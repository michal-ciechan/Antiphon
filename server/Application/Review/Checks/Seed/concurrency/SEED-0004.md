# @model: Selector
Does this change involve concurrent or asynchronous code: tasks, threads, locks, background work, or state shared between requests?
# @model: Prompt
Look for shared mutable state read and written from more than one thread or request without a
lock or an atomic operation, a lock released before the work it protects completes (an await
outside the lock), an async call that is not awaited, check-then-act races, and blocking waits on
async code. Anchor the finding on the unsynchronised access.
# @model: Examples
Bad: `_lock.Release(); await _db.SaveChangesAsync(ct);`
Good: `await _db.SaveChangesAsync(ct); _lock.Release();`
# @humans: Why this check exists
Races pass tests and fail in production under load.
