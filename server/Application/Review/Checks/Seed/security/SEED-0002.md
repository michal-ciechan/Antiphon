# @model: Selector
Does this change handle input from users, requests, files, environment or other systems, build queries, commands or file paths, or touch credentials, tokens or keys?
# @model: Prompt
Look for untrusted data that reaches an interpreter without validation or parameterisation: SQL
or shell built by concatenation, a path joined from user input without normalising and checking
it stays under its root, deserialisation of untrusted types, HTML rendered without encoding. Look
for secrets: a key, token or password written to a log, an exception message, a URL, a response
or a committed file. Anchor the finding on the line where the untrusted value is used.
# @model: Examples
Bad: `cmd.CommandText = "SELECT * FROM t WHERE id = " + id;`
Good: `cmd.CommandText = "SELECT * FROM t WHERE id = @id"; cmd.Parameters.AddWithValue("@id", id);`
# @humans: Why this check exists
Injection and leaked secrets are the most common severe defects in reviewed code; this check is a
bypass category, so it is posted in every round.
