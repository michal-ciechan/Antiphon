# @model: Selector
Does this change alter an API, message schema, public type, CLI flag or configuration key that other teams, systems or users rely on?
# @model: Prompt
Look for incompatible contract changes: a removed or renamed field, endpoint, flag or config key,
a changed type or meaning of a field, a new required field, or changed error codes, without a
version, a deprecation period or a fallback for old clients. Anchor the finding on the changed
contract line and name the consumers that break.
# @model: Examples
Bad: renaming `userId` to `accountId` in a response that mobile clients read.
Good: add `accountId`, keep `userId` until the clients have moved.
# @humans: Why this check exists
A contract break is felt by teams who did not see the change.
