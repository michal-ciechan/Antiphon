# @model: Selector
Does this change alter a database schema, a migration, stored data, or a persisted file or message format?
# @model: Prompt
Look for changes that can destroy or corrupt data that already exists: a dropped or renamed
column or table, a narrowed type, a NOT NULL added without a default or backfill, a migration
whose Down step silently drops data, a serialised format changed without reading the old one, or
a bulk update or delete without a precise filter. Anchor the finding on the destructive line.
# @model: Examples
Bad: `migrationBuilder.DropColumn(name: "Email", table: "Users");` with no copy of the values.
Good: add the new column, backfill it, and drop the old one in a later release.
# @humans: Why this check exists
Data loss is hard or impossible to undo after release; this check is a bypass category and needs a
human approval.
