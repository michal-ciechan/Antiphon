# @model: Selector
Does this change catch, translate, ignore or default around errors or missing values?
# @model: Prompt
Look for failures that are hidden: an empty catch, a catch that logs and continues as if the work
succeeded, a broad catch that turns a defect into a default value, a missing value replaced with a
plausible-looking default, or an error returned without the context needed to act on it. A
failure should be loud where the caller cannot recover. Anchor the finding on the catch or default.
# @model: Examples
Bad: `catch (Exception) { return 0; }`
Good: let it propagate, or catch the specific exception and say what failed.
# @humans: Why this check exists
Silent failures become data problems that are found weeks later.
