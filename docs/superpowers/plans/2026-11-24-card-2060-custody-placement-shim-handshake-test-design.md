# CARD-2060 verification of Linux custody placement

## Verification design

The short Code pass must demonstrate that the original process is still held when the host validates placement, and that its detached descendant can subsequently exit naturally. Two native checkpoint rows cover this. Qualification separately exercises refusal, lost delivery, immutable storage and recovery. A passing polling test cannot establish the ordering of two processes. The implementation slices and protocol decisions are in the [landed plan](2026-11-24-card-2060-custody-placement-shim-handshake-plan.md).

### Proves it works now

- **V-1** · Native v1 · `LinuxCgroupCustodyTests.C2060_Preexec_placement_identifies_the_first_root` (CP-1/CP-2). Commit the compiling S1 witness on the assigned Code branch from master, with an inert pre-change hook. A validated-offer callback holds GO. The parked/master payload reaches the marker without the callback. Assert “validated hold reached before first payload marker” there. Signal through an inherited fixture pipe or atomic marker publication with level checks across watcher registration. A timeout reaching neither is a fixture failure. In the held branch sample the kernel peer, parent, PID, self generation and both exact singleton trees. Verify marker absent, then release GO. Require the same PID/boot/ticks reported across exec by a small payload reading its **own** stat. Avoid a shell utility reading its own PID on behalf of the root. Let the descendant go naturally and validate the host's bound producer receipt. Q11 covers runner acceptance.
