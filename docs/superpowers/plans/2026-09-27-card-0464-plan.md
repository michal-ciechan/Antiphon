# CARD-0464: preserve PTY escape and UTF-8 state across reads

## Verified findings (master a56c3a7e, 2026-09-27)

- The card is **still valid**. `TerminalScreen.Feed` begins each call in ground state and hands an escape to span-local handlers (`src/Antiphon.Agents.Pty/TerminalScreen.cs:71-81`). A trailing ESC is discarded (`:228-230`); an incomplete CSI is discarded (`:256-287`); OSC and ST-terminated strings are skipped only to the end of the current span (`:424-442`). A following call therefore renders their remaining bytes as text or interprets them separately. There is no carry field for parser state (`:32-38`).
- The UTF-8 claim is also live, but the card's name for the location is stale after the pty-host split. The actual PTY byte read and per-read `Encoding.UTF8.GetString` are in `src/Antiphon.Agents.Pty/PtyAgentRunner.cs:241-259`, running inside the detached host (`src/Antiphon.PtyHost/HostSession.cs:49-55,112-114`). The host logs and relays those already decoded strings (`HostSession.cs:343-370`); the session runner only feeds them into its screen (`src/Antiphon.SessionRunner/SessionRunnerRuntime.cs:3191-3205`). A decoder added only to `SessionRunnerRuntime` would be too late.
- CARD-0449 deliberately avoids this defect: `tests/Antiphon.Agents.Pty.Tests/ClaudeEffortDismissalReplayTests.cs:97-121` extends every 256-character piece to the end of its escape token, and `:146-164` compares only those safe pieces and frame cuts. It does not prove arbitrary read-boundary invariance. The single-call fixture decode at `:51-52` also bypasses split UTF-8.
- Direct byte inspection of `tests/Antiphon.Agents.Pty.Tests/golden/card-0449/effort-dismissal-23b5663c.ansi` confirms the card's sample cuts: byte 256 is a UTF-8 continuation; bytes 1024 and 2560 follow ESC; 2048 and 3840 fall inside CSI. These are byte offsets in the fixture, not assumptions about a live OS read size.
- The adoption path reconstructs a fresh screen from an ANSI log tail (`SessionRunnerRuntime.cs:2398-2401,2831-2842`), then feeds future host chunks. `ReadAnsiLog` uses `StreamReader` for its bounded UTF-8 window (`:3462-3501`), so it is not the per-read decoder named by the card. A tail that starts inside an ANSI token may still lack historical parser context; full-screen reconstruction from an arbitrary tail is a separate limitation.
- Preserve the existing delivery path: `docs/session-runtime-invariants.md:468` requires LF normalization, bracketed paste, and a separate Enter. This work is receive-side only. The modern ConPTY ADR records why the host and input path matter (`docs/adr/0002-modern-conpty-backend.md:10-30,43-72`).

## Smallest fix

**S1 — screen parser.** Make `TerminalScreen` retain its escape substate across `Feed` calls. Use a bounded-state incremental parser for ground, ESC, CSI, OSC (BEL or ST), other ST-terminated strings, and ESC character-set designation. Carry CSI private/intermediate/parameter state until the final byte, then call the existing cursor/erase/scroll action logic once. Keep existing handling of unsupported sequences, deferred wrap, and ordinary controls. A parser that merely concatenates an unbounded unfinished OSC/DCS string is unsuitable for a long-lived session. No public `Feed(string)` contract change.

**S2 — PTY byte decoder.** Give `PtyAgentRunner` one small instance-owned UTF-8 decoder wrapper using `Decoder.GetChars`/`Convert` for each nonempty read without flushing at read boundaries. This wrapper is the deterministic seam for the byte tests and the real-fixture replay; production must use it too. Emit only decoded chars into the existing `Output`, live buffer, screen, audit, and `OnData` path; no empty output frame or sequence increment for a read containing only a partial code point. Flush once at clean EOF to handle an incomplete final code point consistently; do not invent an output event during cancellation. Keep the decoder instance private to that session. No input/write change.

**S3 — verification only.** Add focused `TerminalScreenTests` that split supported CSI, OSC BEL, OSC ST, DCS ST, character-set designation, and a standalone ESC at every character boundary, comparing grid and cursor state with one feed. Replace CARD-0449's escape-safe `pieces` coverage with an additional arbitrary **byte** chunk replay of a real fixture through the same incremental UTF-8 decoder used by the host; compare rows, cursor and dialog dismissal with one-piece replay. Add `PtyUtf8DecoderTests` covering every byte boundary of 2-, 3-, and 4-byte characters, consecutive partial reads, malformed bytes, and clean EOF. The new tests must fail on the current stateless production path; a self-comparison or a test helper that independently repairs bytes is not evidence.

## Risks and boundaries

- A split `ESC \\` terminator must not leak `\\` or leave the parser stuck; OSC content must stay hidden even across many calls. The parser must continue after a malformed/unsupported escape without losing later printable text.
- Parser state belongs to each screen instance, including the runner's replay-created screen. A bounded log tail may begin inside a token, so the replay test should feed from a complete fixture; this change does not assert reconstruction from a truncated historical prefix.
- The screen stores one UTF-16 `char` per cell. Supplementary Unicode display width and grapheme clusters are pre-existing limitations; verify their UTF-8 decoding without making cell-width behavior part of this card.
- Host `OnData`/ring sequence numbers may no longer correspond one-for-one to OS reads when one read has only a partial code point. Preserve ordered lossless concatenation and attach/replay continuity.
- Do not alter typed input, LF normalization, bracketed paste markers, or the separate Enter delivery contract.

### Harness and observable contract

Use production `TerminalScreen`, the new instance-owned UTF-8 decoder, and the actual `PtyAgentRunner` read/publish path. A test-local decoder, token reassembler or escape-safe splitter cannot stand in for any of those. Add only a narrow internal seam to drive the runner's existing read loop with a scripted `Stream`/`IPtySession`, initialize its real screen, and await reader completion without spawning a child. Production must invoke that same loop and decoder. The script controls exact read sizes, EOF, cancellation and `IOException`; it does not decode bytes. Synchronize intermediate observations with an explicit read barrier, not a sleep. `Exited` is the child exit signal, not proof that the read task has drained.

For every valid short byte vector of length N, run all two-piece cuts `k = 1..N-1`, one byte per read, and the whole vector. Include empty **decoder input/Feed calls** before, between and after nonempty pieces; do not simulate an empty stream read in the middle, because a zero read means EOF. For ASCII escape vectors, every character boundary is also every byte boundary. For mixed Unicode/control vectors, drive bytes through the production decoder before feeding the screen. Label assertions with vector, cut and phase. Compare full rows and both cursor coordinates, and assert literal expected content independently of the whole-feed reference. Equality between two wrong screens is insufficient.

Observe `Output.Snapshot()`, `SnapshotText()`, `SnapshotScreen()` and both `OnData` subscribers on a small stream that cannot evict the 4096-entry ring. Their concatenated decoded text must agree in order (screen content is interpreted, so compare it to the expected rendered grid). No empty output event or ring entry is permitted. A read containing only a UTF-8 prefix produces no publication; it must neither update the live screen nor generate an audit chunk. Completed text and clean-EOF fallback use the same publication path, including `_audit.RecordChunk`. Inspect that single fan-out in Review; where audit is enabled in the harness, use an isolated temporary audit and assert its decoded marker order without matching timestamps. Do not enable the global audit/pruning path just for these tests.

`HostSession.OnData` already rejects empty strings before incrementing `_lastSeq`. Preserve that code: host sequence numbers count published chunks, not OS reads. The deterministic runner test proves empty-prefix suppression and ordered content at its upstream boundary; it is not a native host reconnect/sequence test. No host/runner protocol, adoption, custody or input-path change is required by this design.
