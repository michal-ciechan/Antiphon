# CARD-2103 — Where the time goes

Give the operator one answer for a slow task or qualification run. Show elapsed time, the longest measured phases, the test entry points and classes responsible for the most execution cost, and the amount of time the evidence cannot explain. Preserve failed, refused, canceled and incomplete attempts. The measurement must survive routine worktree retirement.

Source audit is against `b5b349d968b5c5ae28a66c73201f1ab06a540aa5`. Card descriptions and placement were read from the Antiphon board and API on 2026-11-27. For the incident see [Debug a6eed88b at 1b31e85df33964326edf684bb0e7013e233aa069](https://github.com/michal-ciechan/Antiphon/blob/1b31e85df33964326edf684bb0e7013e233aa069/docs/investigations/2026-11-27-server2-verification-latency.md). The review cited on CARD-2103 spent 62m14s in admission and 16m23s in finalization out of 100m56s. The Debug sample paired 118 client-side lease intervals, with builds using 74% of sampled hold time. Its longest completed build hold was 21m05s. One 9.3-second row waited 540 seconds. Another run spent 570.852 seconds in output cleanup after releasing its last lease. These figures motivate three separate measurements and have different denominators.

## Decisions

**D-1. Start with a task view and prioritize broker restoration alongside it.** S1 explains tasks with existing facts while adding the highest-value missing boundaries. Begin S3 design in parallel with S2 where ownership permits. The shared-authority repair is the first operational follow-up when a drained window is available. A dashboard or capacity tuning first would depend on a biased client sample. This plan dispatch uses retained evidence and read-only API metadata. Activation belongs to later slices.

**D-2. Record per producer and persist a compact task summary in PostgreSQL.** Each task has a `timing/` evidence subdirectory keyed by canonical task ID, with separate append-only JSONL shards per producer and attempt. The dispatcher uses a persistent server evidence root, and checkpoints use the assigned owned evidence root through their existing custody APIs. Reuse the same task/run IDs in default and explicitly retained checkpoint results. A bounded summary table, keyed by task ID with an indexed project/time projection, is the cross-runner query surface. Persist the task ID even if the operational task row is later pruned. Load server milestones when available and preserve their reduced summary for the timing retention period. The timing journal/summary have independent custody from canonical report bytes and checkpoint receipt schemas. A shared file mount adds cross-host deployment and locking coupling, storing every event or test case in the database creates avoidable write volume, and putting task phases into `TestTimings.WriteEvent` would inherit the unbounded mutex/read pattern.

The checkpoint command publishes a compact producer summary once at terminal completion, after lease release and authoritative artifacts are written, over the existing task API client/identity mechanism. Use a small versioned ingest route under the task, with token-bound task/session/attempt validation and a per-producer content digest. Server-owned facts can only be written by the server. Accept old-attempt replay only when binding still proves ownership and accept identical repeats as idempotent. Reject mismatched identities and conflicting finished digests. Merge disjoint producer keys transactionally with bounded optimistic retry. A read can distinguish missing, local-only, expired and truncated sources. An unavailable token, revoked task or server outage leaves owned local evidence. Provide an explicit, bounded operator import from a verified retained bundle for recovery and legacy receipts. Mark imported telemetry by source and keep any unknown identifiers null. A pre-terminal crash can leave readable local spans with a missing terminal summary. Do not upload arbitrary worktree paths or introduce a filesystem crawl, sidecar daemon, or network request per row. Partial timing has no authority over receipt validation, launch, land, task settlement or coverage.

Apply the same writer on standalone and grouped invocations. Buffer bounded events and flush at existing transition or publication boundaries. For tasks without checkpoints the dispatcher and settlement producers still supply their own coverage. Project report timing from accepted receipt observation, sync completion, report-store completion and caller-note enqueue when labelled boundaries exist. Report unavailable for delivery to the caller unless the existing delivery receipt proves it.

**D-3. Give clocks and denominators explicit names.** Schema `antiphon-timing-phase-v1` has `eventId`, `producer`, `sequence`, `taskId`, `attemptId`, nullable `runId`, `rowId` or `chunkId`, `operationId` for land, `buildId` and `leaseId` when present, source SHA, project and entry-point keys, OS/runtime, verified host/authority binding, phase code, UTC start/end and monotonic duration, outcome and coverage/reason codes. Parent or attempt identity qualifies every child ID. Rates and counts describe an explicit population. An unavailable duration is null. Timed-out and refused intervals have their own outcome and may contribute observed cost.

Use application monotonic timestamps for duration and UTC for aligned display. Separate task envelopes from measured child sums. A wall attribution uses the union of compatible intervals inside an envelope, with the remainder labelled unattributed. Only derive exclusive totals from observed interval overlap, with explicit priority for active work over wait in a checkpoint group. An in-flight interval has an age, never a fabricated finish. Across hosts use matching trusted milestones or report phase sums and leave exclusive wall unknown when clocks cannot be aligned. Reuse `admissionOnlySeconds` when the checkpoint already computed the union. Include retry cost in attempted totals and retain attempt boundaries. No phase should inherit the label of its parent without measurement.

**D-4. Keep qualification history in configured timing roots.** Publish one immutable, atomically created run-attempt summary with qualified coverage and per-class/per-chunk rows in the existing timing history root family. Reuse `TestTimings` comparison identity and existing artifact retention paths, while using a bounded terminal/offline importer for full class evidence. Index by fixed UTC date partitions and an atomic per-attempt manifest, with explicit operator-authorized roots or mounted retained artifacts. A lookup reports the roots represented and can run locally on any host with those retained artifacts. No implicit SSH or fleet crawl. Defer central class ingestion until local coverage and operator use justify it. No auto changes to the planner, estimator, exclusions or qualification outcomes.

**D-5. Treat broker and Git scope as coverage data.** Cohort slot observations by authority, activity and outcome. Join the nearest already retained host sample within 10 seconds on the same binding revision, expose sample age, and use unknown for missing CPU, I/O or disk values. Git totals come from supervised and tooling-owned seams. Measure one logical operation and its attempts, then show logical count, backend attempts and elapsed cost separately. Carry instrumentation alongside existing spans. Never use free-form Git arguments or recurse into unsupported interactive shell calls via a PATH shim.

The qualification chunk wrapper's “not-used” slot field refers to that wrapper. If its launcher holds an enclosing lease, assign that hold to the invocation when the lease ID is known. Standalone builds through `scripts/lib/Antiphon.Nightly/BuildSlot.cs` and land verification should pass an allowlisted invocation kind to correlate to the broker. A broker-side request without trusted task or run context is fleet-only. Add an internal broker cursor keyed by authority generation and sequence for the existing server polling/ingest lane to consume batched transitions and expose bounded authorized reads to the CLI. Deduplicate after interrupted reads and show a gap on restart, expired cursor or drops. For runner-owned Git calls use the task/request context before a worker session exists and aggregate across that existing runner reply or owned task evidence; report a missing binding on older replies. These joins keep the number of remote requests independent of the number of Git calls or slot polls.

**D-6. Use a small read-only operator surface.** `scripts/antiphon timing task <id>` takes an unambiguous task ID or supported short ID. `timing run <id>` takes an exact run ID and groups sibling attempts visibly. `timing top --classes|--suites|--phases|--git|--slots --since <UTC instant or Nd> [--project <key>] [--json]` selects one grouping and a bounded window. All three support `--json` and a configured evidence root list, with explicit `--roots` for retained run artifacts. Project filters resolve a recorded project key (board slug/ID for task data, registered test project key for run data), and surface a mismatch instead of guessing. Version JSON; use pagination/coverage for larger scans and a default top 10 in text. Read access uses the underlying project/task and evidence custody. The default Markdown view caps output at about 20 lines with elapsed, outcome, phase wall and unattributed time, the top three contributors by appropriate metric, one comparison, coverage and a short provenance ID. A missing source shows “unknown” and a reason. Report text is rendered from the same projection as JSON.

```text
Review 13129357 · 42m58s · 161 passed
Admission only 17m38s · build producers 12m49s summed
Test hosts 2m42s summed · output cleanup 9m31s
Slowest build hold and class rankings available in detail
Coverage: checkpoint receipt and executor · broker history unavailable
```

**D-7. Cap retention and work at each producer boundary.** Initial ceilings for TestDesign to exercise are 1 MiB and 2,048 phase records per task per owned evidence root (at most 16 producer shards of 64 KiB and 128 records each, with one writer per shard). Keep diagnostic shards 14 days with a 512 MiB ceiling per managed root and task summaries 90 days, at most 10,000 summaries and 64 KiB each. Distributed writers have local limits and the server separately caps the merged summary. Reserve a fixed record or manifest bit for truncation, drops and terminal coverage. History stores at most 64 run attempts per configured root, 90 days and 256 MiB total, at most 4 MiB per attempt. Both full and partial runs count. Broker transition spool starts at seven days or 64 MiB per authority, rotated by day/size. Prune oldest finalized timing artifacts in bounded batches, and refuse further timing writes when no safe prune is available. Exhaustion leaves a coverage reason and preserves active attempts, existing receipts, source and raw qualification history. Use parser size, count and time limits, anchored regular-file reads and atomic summary writes. Allow only typed fields such as IDs, enumerated labels and numeric counters. Exclude tokens, URLs, command lines, stdout, raw case display/parameter values, environment dumps and absolute paths. Stable test/class/method identities come from verified result definitions or are marked unavailable.

## Performance budget

Apply the [plan format and performance standards](../../testing-and-build.md#performance-standards). This documentation slice has no build or test run. Build stages use one warranted red witness and its narrow green plus the named/impacted contract scope assigned to them. For exact selections TestDesign should start with one pure witness per slice and add only the native and contract rows the diff requires.
