# CARD-2069 P2 integrity for candidate selection evidence

**Decision.** Have the qualification consumer recompute the selection evidence from independently pinned inputs. Compare the entire proposed selection with that result before permitting any carry consideration. An unverifiable envelope gives effective **Full**, zero carry credit and a recorded reason. P2 delivers a callable adapter and fixtures. CARD-1836 owns scheduling and activation.

At source `7da5f1377a0681f26498f0d02ff1c6aebded6afd`, CARD-2069 is InProgress and asks for a separate TestDesign. The A-2 advisory is available with `git show d00fb72eb7cba56cdf07b45060adf211fc561d2f:docs/investigations/2026-11-24-card-1866-advisories.md`. Its open question is whether a consumer could distinguish a genuine proposal from a replacement carrying its own valid checksum. The [CARD-1820 P2 contract](2026-11-12-card-1820-selector-v2-trustworthy-for-skipping-plan.md#card-1836-handoff-contract), [CARD-1836 Windows plan](2026-11-25-card-1836-incremental-windows-qualification-plan.md) and [its test design](2026-11-25-card-1836-incremental-windows-qualification-test-design.md) supply the selection and execution obligations.

## Decisions

**D-1. Trust the request, the consumer and its evidence custody.** Treat the proposal, its adjacent hashes, candidate-controlled files and caches as replaceable. Protect against accidental truncation, a different candidate/attempt, stale replay, omitted dependencies and a self-consistent replacement. The caller supplies repository identity, exact B/A and target independently of the envelope. The verifier runs reviewed tooling from a separately pinned installation. It reads Git objects as data. Candidate build steps, analyzers and test processes cannot write the verifier, its policy, its accepted snapshot or the authoritative history of executions. Resolve historical run/attempt IDs and artifact digests from a qualification-owned, write-isolated inventory recorded when the run closed. The same boundary must cover later failures, withdrawals and attempt order. A copied TRX, an editable comparison file, a self-declared producer ID or a candidate-supplied path cannot create such authority. If this custody or target-specific discovery is unavailable, select Full. Compromise of the trusted recorder or verifier is outside both designs' guarantee.

| Candidate design | Attack model and evidence | Cost | Failure behaviour and decision |
|---|---|---|---|
| Consumer recomputes | Using independent roots, rebuild both input closures, derive the full reasoned selection and compare it byte for byte. Read original execution evidence from custody once. The submitted payload supplies no source of expected truth. | Two pinned tree/index reads, graph evaluation and one discovery/receipt pass per distinct target and attempt. No signing service. | Any incomplete derivation or mismatch gives Full. **Recommended** for P2 because local checks can be tested now and the absence of trusted evidence has a useful safe outcome. |
| Consumer verifies an authenticated producer artifact | An isolated, reviewed producer performs the same full derivation and signs a domain-separated canonical root. A candidate cannot choose the key, request signatures on arbitrary output, or write its inputs. The consumer independently checks repository, candidate, target, attempt, roster, input pins, revocation and live obligations. | One expensive derivation amortized across consumers. Requires issuer provisioning, protected signing, key ID and algorithm policy, rotation, revocation, replay control and retained verification history. | Missing, expired, revoked or unknown issuer, wrong context or unverifiable signature gives Full. Defer until an independent issuer exists and measurements justify it. A valid signature only attests what that producer evaluated. |

Reject Git trees alone as the binding. They cannot identify discovery, runtime bytes or a historical observation. A checksum delivered by the proposing party is useful for transport diagnostics in either design.

**D-2. Bind the complete inventory at both endpoints.** B is the resolved comparison and A is the requested candidate. Every root below has a named role and a fixed derivation. The consumer enumerates its expected inputs independently, validates referenced lengths, counts and bytes, and requires exact set equality. Replacing the manifest along with its digest cannot remove an expected member.

**D-3. Use a versioned canonical byte projection.** Transport is strict UTF-8 JSON with discriminator `antiphon-p2-integrity-v1`. Reject duplicate, unknown or missing fields at every level, wrong types, malformed UTF-8/Unicode and unsupported versions. Parse JSON as data. Property order, indentation, and LF versus CRLF used as *JSON whitespace* do not change the root. Checksummed source, index, policy, receipt and evidence blobs use their exact bytes, including BOM and line endings. Existing LF-normalized semantic hashes keep their own role.

Use the following ordered root tuple. The wire carries these named fields and `rootDigest`. Hash the tuple **without** `rootDigest`. Include the discriminator first.

```text
format, repositoryId, line, baselineSha, baselineTree, candidateSha, candidateTree,
runId, attempt, revision, targetDigest, algorithmSha, algorithmDigest,
baselineManifestDigest, candidateManifestDigest, compatibilityDigest,
baselineIndexDigest, candidateIndexDigest, baselineGraphDigest, candidateGraphDigest,
diffDigest, universeDigest, rosterDigest, inventoryDigest, receiptsDigest,
obligationsDigest, trustDigest, selectionDigest
```

Use SHA-256, emitted as 64 lowercase hex digits. Git object IDs are separate typed 40-lowercase-hex fields for this repository. Encode text, enum tags, IDs and lowercase hex digest strings as strict UTF-8 without BOM, prefixed by uint32 big-endian **byte** length using `RcBoundary.AddString/AddU32`. Counts, attempts and revisions are uint32 big-endian. Booleans are single bytes 0 or 1. Optional values use a one-byte presence tag followed by the typed value only when present. Required values cannot be null, and absent, empty and zero have distinct encodings. The root has no separators or terminal newline. A field addition, reordering, change in meaning or encoding requires a new discriminator.

Each structured digest uses the same framing, beginning with `antiphon-p2-integrity-v1/` plus the exact role name (root member name without `Digest`), followed by the typed record or counted sequence. Fix each record's field order in a shared versioned schema and independent golden vectors in S1. For example each endpoint manifest has ordered rows `(path, gitMode, blobId, rawByteCount, rawSha256)`. Encode an index's side/commit/path/blob/byte digest, metadata and counted edge pairs `(path, class)`. Encode graph endpoints as qualified identities with edge kind, source and destination. Raw byte lengths use unsigned 64-bit big-endian. Set/map keys sort by tuple of case-sensitive ordinal strings (numeric fields by numeric value), independent of locale. Reject duplicate keys or equivalent paths, invalid repository-relative paths, conflicting aliases and normalization collisions on the target. Preserve meaningful order in command arguments, dependency chains and the actual planned launch sequence. Stream bounded counts and bytes, rejecting truncation, overflow and oversized evidence before allocating. Pin format-specific limits with real-size fixtures in TestDesign. Exclude local checkout roots, diagnostic timestamps and the envelope itself from recomputed semantic manifests. Time and revision used for freshness checks come from independent custody and participate in the obligations binding.

The four legacy compatibility fields occur in the fixed order `catalogHash, policyHash, runtimeHash, selectorHash` at B and then A. Read `tests/test-selection-policy.json` and `tests/test-execution-policy.json` at each pin. Bind observed external inputs using the six `RcChunkDigest.RequiredReceipts` roles and each chunk's complete `NewManifest` input digest. Keep a raw inventory's byte SHA inside the structured inventory projection. Apply the same rule to raw evidence and policy blobs so an independently computed file SHA can be compared directly with its published seal. Canonical transport members include the root tuple and one typed projection per structured digest, either inline or by verified content address. A verified address identifies bytes only. Participation and meaning come from the consumer's expected inventory.

**D-4. Verify before selection, recheck before credit.**

1. Take one read-only snapshot of the independently supplied context. Read B/A by immutable object ID, acquire the target discovery and evidence inventory from the qualification owner, and restrict artifact resolution to that inventory's controlled root. Verify bytes on the same handles used to parse them. Use the current approval, age and open-obligation revision. Do not let the envelope choose a root, an executable or a source of authority.
2. Strictly decode and verify the proposed root and every referenced object. Independently rebuild the expected manifests, typed edges, trust decision and complete selection from the context. Compare canonical expected and submitted content, including classes, reasons and decisions. Raw hashes alone never discharge completeness. If an evaluator, P1 compatibility proof or source of authority is unavailable, return Full even when two hashes match.
3. Return either a verified, immutable proposal bound to the attempt, or effective Full with a stable reason and the entire current roster owed. Sample reason families are `p2-format`, `p2-context`, `p2-input`, `p2-receipt`, `p2-incomplete` and `p2-selection`. Record component and side without payloads. A resolved execute or unresolved hold remains owed. An empty roster requires reconciliation against independent discovery.
4. At CARD-1836 integration, validate at cut/discovery and before the first carry. At launch/resume and closure recheck the bound revision, receipt bytes or immutable custody handles, current roster, approvals and later obligations. Reuse one consumer-owned derived snapshot within a verified revision only. A same-candidate retry is idempotent. Conflicting revisions, changed context, withdrawn authority, unsupported formats or partial previous plans select Full. If work already launched or was carried, close the old attempt as incomplete, preserve its audit trail and open a distinct Full attempt at A. Grant zero carry credit from that attempt. Full still requires its own successful execution evidence.

## Rollout and rollback

Land the document on master and commission TestDesign. Ship the adapter as diagnostic alongside v1. Preserve Full at all public entry points. Record expected and proposed root, effective mode, refusal reason, input counts/bytes and phase timings in the qualification evidence. Compare observed Full outcomes with predicted eligible carries. Historical unbound receipts remain ineligible. P2 acceptance needs the bounded positive and refusal fixtures. Activation additionally needs the CARD-1836 independently scored five-run replay, two prospective Full shadows, native target evidence and explicit qualification-only approval bound to selector and trust-policy identities. P2 grants no publication authority.

Roll back by withdrawing the relevant admission approval and requesting Full on the exact candidate. Reject any pending or resumed proposal using the withdrawn version. Preserve envelopes, hashes, previous receipts and refusal reasons, mark dependent carry chains ineligible, and obtain fresh Full evidence before granting credit. A repaired verifier gets a new approval after the applicable replay and shadow gates.

## Performance budget

Apply the [performance standards](../../testing-and-build.md#performance-standards). The CARD-1866 advisory measured a 9m24s isolated Linux build and 6.4s execution for six related fixture cases. This is one comparison sample. There is no measured p95 for P2 or its new tests. For one cold row budget 10 minutes for build and startup and up to 2 minutes for the small fixture. CP-3 adds up to 5 minutes for the guard roster. Keep slot admission on its own clock (45-minute tool limit). Run each committed slice separately, including the Plan guard. A red and its corrected green reference different SHAs.

Use one owned small Git fixture and read-only receipt snapshot per selection, fresh per-case overlays, and the assembly process limiter for Git children. No DB, container or AppHost setup is required. Provisionally budget 2s setup, 10s for blob reads, evaluation and digest comparison, 2s teardown per small case. For shadow qualification load each distinct blob and receipt once per verified context, record cold/warm cost and cache invalidation, and stream hashes. Record slot wait, build, discovery, Git/process, file I/O, regeneration/evaluation, receipt verification, comparison, body and teardown separately in ignored checkpoint reports/TRX and run sidecars. Include counts, bytes, SHA, target, run/revision, per-test duration and unattributed remainder.

Under CARD-2069 collect the first five comparable executions from commissioned work per new row and target. Report sample size, nearest-rank p95 and maximum. Set finite operation/test and row timeouts near twice the measured p95 and refresh as samples accrue. Until measured, use provisional 30s fixture and 24-minute cold implementation row limits (30 minutes for a cold guard), distinct from slot wait. Split or send Debug any selection, row or run forecast or observed above 30 minutes before repeating it. Measure full-scale recomputation on the Full shadows before considering producer signing.
