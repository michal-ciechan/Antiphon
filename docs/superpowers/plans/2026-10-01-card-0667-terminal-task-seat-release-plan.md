## Outcome and scope

Make release an independently recoverable consequence of every completed runner-bound attempt: Succeeded, Failed, Canceled, and **Blocked after a completed report**. Discover the same debt when settlement missed its fast path, including a runner seat whose session row is absent from the server. A successful release confirms process exit, removes that generation's runner custody, stops the corresponding server row when it exists, and produces visible attention naming runner, full session ID, task/attempt when known, and reason.

Release follows the existing invariant: killed, deliberately pooled warm, or owned by a standing agent. Deliberate Shared warm pools and standing ownership remain valid dispositions; they are not free physical capacity and must not be counted as such. Worktree terminal tasks are not turned into reusable warm agents. A Working or unknown session remains owned with visible release debt. No age, stall, terminal task status, missing server row, or failed kill alone authorizes stopping it. CARD-0079 remains the sole special automatic stop of a Working session.

Scope includes server settlement and sweep integration, a conditional runner release protocol with fresh transcript evidence, safe Blocked reply continuation, and attention. It excludes workspace/branch deletion, changing task verdicts, changing host budgets/capacity arithmetic, provider launches during development verification, stall escalation, native Codex resume enablement, deployment, and checkpoint-tool or instruction-bundle edits.

## Decisions

### D-1: release debt is keyed to an attempt and runner generation

Add concrete `TerminalRunnerSeatReleaseService` and pure `TerminalRunnerSeatReleasePolicy`. A durable `RunnerSeatRelease` row identifies runner ID, runner store ID, session UUID, accepted-start generation, task ID/attempt and settlement event where available. Rowless discovery uses that runner/store/session/generation tuple without a session FK. Include state, observation identity/revisions, first stable observation time, last observation time, action ID, bounded reason code, outcome and timestamps. Use a unique tuple/index and conditional state transitions, not process-local deduplication. Persist no transcript text, argv, cwd, native provider paths or secrets in the release ledger.

Eligibility requires a committed terminal attempt: Succeeded/Failed/Canceled with CompletedAt, or Blocked with CompletedAt and durable report/settlement evidence. A bare Blocked status used for quota/capacity/routing hold, or a Blocked row with no completed report, is **not** terminal release authority. Explicit marked blocked and runner-sync-blocked completed reports qualify. The classifier must not change the global `IsSettled` definition; Blocked remains answerable on the board.

Check all task ownership by both session ID and agent ID. Queued, Dispatched, Working, a newer attempt, or an unsettled Blocked task veto release. A report-completed Blocked task supplies release authority for its own generation but does not authorize removing its report/worktree. Standing/AlwaysOn/board-owned/specialist owners veto this automatic path. Verification/SourceLanding custody stays with its existing receipt-based owner; never route it through generic release.

Every terminal writer is covered by state recovery, even if its fast hook fails. Add fast observation after ordinary reply settlement and cancellation commit; dispatcher sweep supplies coverage for other terminal writers, including land/helper settlement, without adding a new kill call to every writer. In `ReleaseDelegateAsync`, intercept the runner-bound destructive-release arm before its existing stopper call and register/advance this conditional service instead. Otherwise the old Succeeded/Failed fast path could kill before the new guard ran. Keep existing local release and intentional warm pooling. Explicit operator cancellation still owns its existing requested stop; the post-commit hook reconciles the resulting seat and must not send another unconditional stop. Do not edit landing mechanics to arrange release.

Rejected: only widening `shouldRelease`; treating every Blocked as finished; equating `AgentId == null` with abandoned; deleting a pool agent before confirmed exit; changing host counters without ending or deliberately owning the process.

### D-2: prove not Working with fresh evidence and a 120-second safety margin

Introduce capability `terminalSeatReleaseV1`, a read-only idle observation, and a conditional release command. Append protocol operation numbers; never renumber old operations. Both HTTP and phone-home transports use the same runtime methods.

For a **live** process, eligibility requires all of the following:

1. A current runner/store/accepted-start identity from an available runner, not a stale heartbeat. Pending adoption, unknown liveness, unsupported capability or missing generation defers.
2. A fresh read to the complete-record end of the **currently bound** provider transcript, using that format's existing parser and claim rules. Return binding identity, consumed-file revision, file-order transcript revision, `TranscriptWorkingState` verdict, last qualifying end and runner input/output revisions. Empty, unbound, unreadable, partial trailing record, replaced/truncated file, ambiguous claim or budget-exhausted read is Unknown. An old idle turn from before this accepted generation's delivered task prompt is insufficient.
3. Explicit Idle after a turn-end for the current work, and no later activity. Working always vetoes, however long silent. Server committed Working state is an additional veto after catch-up; server missing/unavailable state is never affirmative idle evidence. Rowless candidates instead rely on the stronger fresh runner observation and independent ownership checks.
4. Two successful observations of the same generation, binding, transcript revision, runner input revision and output revision, at least **120 seconds apart**, and at least 120 seconds since the terminal settlement when one exists. For a rowless seat, the first fully qualified observation starts the margin; an ancient `StartedAt` cannot backdate it. Use injected `TimeProvider` wall/monotonic time in the server and runner; compare elapsed times within each clock, never subtract timestamps from different machines. A change resets the stable interval; unavailable observations discard qualification. Restart resets runner-local qualification and requires a new window.
5. No pending/attempted delivery, held composer-body uncertainty, queue mutation in progress, pending launch/resume, or active execution custody. This includes unsent brief, answer, channel, mention, completion/continuation and recovery delivery addressed **to this seat**; the parent's completion outbox is a different recipient. Do not cancel messages merely to make a seat eligible. Existing terminal-brief cancellation runs under its own rules before reevaluation.

An already exited generation may be evicted without waiting for transcript idleness, after identity/ownership revalidation and positive exit evidence. A missing session in a **fresh authoritative runner lookup** is already absent; failure to contact the runner is Unknown. Server-row absence and runner-process absence are different facts.

Extend `ITranscriptTailer` with a generic fresh idle observation, implemented for Claude, Grok and Codex. Reuse the real normalization/claim machinery; do not copy the server fold or infer progress from screens. Fresh observation must serialize with the tailer's polling/read state without emitting duplicate transcript entries or invoking server queue callbacks. Use bounded streaming reads; exceeding the bound refuses rather than accepting a prefix. CARD-0079's compaction observation and authorization remain unchanged.

The two-minute interval absorbs delayed ingestion and settlement callbacks; **it is not proof by silence**. The final fresh read and conditional checks are still mandatory. The external CLI/file writer is not transactionally locked by Antiphon: do not claim protection from arbitrary out-of-band human keystrokes after the final native observation. For backends that cannot account for independent input/launch custody, return Unknown and expose the hold. Antiphon-routed input and replacement races are fenced by D-3.

Rejected: `Status == Running` meaning Working or idle; timeout/age meaning idle; cached transcript GET; stale Herdr labels; checking only the server database; applying the compaction Working-stop exception to ordinary tasks; short real-time test sleeps.

### D-3: conditional runner mutation and server ownership fencing

Request includes action ID, exact runner store/generation and the qualified observation token. Runner issues opaque observation tokens bound to its current process epoch, session object and evidence; callers cannot manufacture an old stable interval. A token is authority only for conditional reinspection, not permission to bypass it.

Under the existing per-session launch gate, re-read current identity, fresh transcript, input/output revisions and custody, then decide. All externally callable normal and conditional input entry points must participate in the same gate; use an internal already-locked writer to avoid recursive semaphore waits. Preserve the LF/bracketed-paste/separate-Enter contract. Mark release-in-progress before signaling; later input either wins before qualification and invalidates it, or receives a typed refusal after release owns the generation. Output/tailer revisions are checked again at the last pre-signal boundary. New launch generations cannot inherit old release tokens.

Use an injected clock and a test barrier just before final reinspection. Eligible release reuses the existing kill/verify/forget logic through an already-locked helper, not by calling the public lock-taking `ReleaseSlotAsync` recursively. Confirm exit before forgetting in-memory state, PTY manifest or Herdr sidecar. On kill throw, cancellation or non-exit, retain custody and return unresolved; never stamp server Stopped. Duplicate action IDs report the prior result only for the same generation; a different generation refuses. Durable generation history must not be erased by seat release.

Server serializes automatic release with its singleton per-session queue gate. Use short DB transactions to reserve/revalidate the release identity; hold no DB transaction over runner I/O. Task reply/requeue and claiming this session participate in the same ordering. Recheck task attempt, status, settlement identity, owner, queues and runner binding immediately before dispatch, and before applying the response. Lock order is queue gate, then short task/release-row transaction; never acquire the queue gate while holding a transcript-state gate or SQL row lock. `AgentTask.ConcurrencyToken` is not an EF concurrency token: use a row lock or explicit conditional update that compares the expected revision/attempt, and assert one affected row. A read followed by ordinary SaveChanges is insufficient. The release ledger is the recoverable reservation, not a lock held in SQL over the network. A racing claim either invalidates an unsent reservation or waits for an in-flight outcome; it never writes input into a seat whose release is unresolved. Observe current rows from a fresh context, not a dirty settlement tracker.

Transport outcomes are typed: Released/AlreadyExited/AlreadyAbsent, Working, Unknown, PendingDelivery, StaleObservation, GenerationMismatch, Owned, Unsupported, or Unresolved. Automatic callers never fall back to unconditional force release or generation kill. Keep the operator's explicit single-seat force-release API and its token requirement unchanged. `release-orphans` is a selection sweep and uses the safe conditional protocol; its response must distinguish candidates, deferred and released, with `Released` counting only confirmed dispositions.

Rejected: a TOCTOU Boolean check followed by operator force release; a new independent input lock; holding the queue's lock and reentering queue flush; a database transaction across RPC; retrying an ambiguous command with a new identity; silently weakening old-runner behavior.

### D-4: reuse existing sweeps; reconcile the result before retrying

Dispatcher's existing pool-release pass first applies the new service to runner-bound completed attempts. Existing local Shared pooling/standing behavior stays intact. Route remote worktree retirement in the pool janitor through the same safe coordinator so a deferred Working/unknown release cannot later be killed by a less strict TTL arm. Do not make the stall detector destructive.

Extend the existing slot-reconcile job with a separately named conditional-discovery phase after its existing audit reconciliation. Enumerate current configured runner inventories in bounded per-runner pages/batches; isolate unavailable runners and failed candidates. Compare each runner seat with server sessions, task references and agents; a missing server row creates a rowless candidate. Never synthesize a session row to make the normal kill API work. Include desktop's rowless runner inventory through the local client; phone-home-only `Resolve(runnerId)` is not a desktop transport. Known local sessions remain with their existing pool/standing/task owner; do not route an owned local Blocked conversation through the new remote completed-attempt policy. The card's “desktop row Running” case is also covered when that server row belongs to a remote runner. Read-only slot lists may report `orphanCandidate`, `releaseDisposition`, `holdReason` and observation age without performing release.

Persist a release reservation before sending. Lost reply => Unknown/pending, not success and not a blind second kill. Reconcile by exact generation inventory/action result; only confirmed exit/absence finishes the audit. The action result may be cached within a runner process; after restart its absence is not evidence of failure. Wait for adoption/recovery to complete and read authoritative inventory before concluding absence. If the seat remains, obtain fresh qualification before a new conditional action. Current ownership/replacement invalidates old action authority. One candidate failure must not stop later candidates. Old `pending:orphan:` and `pending:kill-generation:` incidents retain their current semantics; this new typed ledger must not accidentally turn old reconciliation into a fresh unconditional kill loop.

For confirmed removal, stop the matching server row with `SessionTerminationSource.SystemRequest` (first writer wins), set ended/last-seen timestamps, and retain task/report/worktree records. A replacement row/generation is untouched. Retire a disposable agent only after the existing confirmed-exit/incident-retention rule; keep a Blocked task's logical continuation record. Audit exactly once per release identity, including rowless seats. A deferred release is not a fourth successful process disposition: retain its existing owner, and describe a pre-existing rowless live process as unresolved orphan custody until it can safely be released or an operator assigns ownership.

Rejected: another periodic timer; scanning only agents; dropping Unknown rows to make rollout counters zero; routing a rowless release through `/api/sessions/{id}/kill`; allowing an automatic sweep to inherit an operator force token.

### D-5: Blocked reply remains usable after physical release

This is an intentional distinction between **a live conversation** and **a completed report whose seat has been reclaimed**. Existing local and deliberately warm Shared Blocked conversations keep today's same-session `AnswerAsync` behavior. For a runner worktree Blocked report whose release is confirmed, retain its task ID, card, root, runner preference, report, report artifact, branch/workspace evidence and question round.

An explicit answer to that released attempt becomes a **queued continuation attempt**, through the existing task requeue/admission machinery. Persist the answer and source release/round identity atomically with the new attempt; include the complete answer once in its normal task brief, alongside the existing retained-report handoff and link to the full old transcript/report. Display the event as “seat was released; answer queued for a new attempt.” It is not a claim of native provider resume. Keep existing auth/quota/capacity/commit-recovery/workspace admission gates; do not silently change kind or host, abandon commit obligations, discard the answer or start a provider from the HTTP reply handler. The requeue helper may bypass its old-session stop only when this exact attempt/generation has a confirmed release receipt; a missing row alone does not grant that bypass. Preserve the branch/workspace and reacquire its existing use reservation; do not create a new base checkout or discard unlanded work to answer a question.

Use nullable attempt-scoped fields on `AgentTask` for the accepted released-seat answer, its ID and target attempt (included in the migration below); new explicit retry clears/supersedes them under the existing task mutation gate. `DelegationReportFormatter.BuildBrief` includes them only for that attempt. They are ordinary authorized task input, not release-ledger diagnostics. Do not truncate the accepted answer to the 4,000-character previous-report excerpt. Existing spill delivery handles long briefs. The task marker and complete normalized UserPrompt remain the delivery evidence; enqueue/Working status alone is insufficient.

Concurrent answers for the same round cannot create two attempts; use current task revision plus release identity inside the task transaction. A racing answer before release dispatch cancels release eligibility and uses the live path. An answer during an ambiguous release waits visibly for reconciliation with its text persisted; it must not enqueue to an uncertain corpse. Restart recovers that accepted answer. Admission refusal preserves it without charging a new provider launch; a later explicit retry consumes the same recorded input according to its attempt identity.

**Compatibility limit:** a reclaimed runner task continues from persisted Antiphon report/transcript/workspace context, not a guaranteed native model conversation. That is the specified continuation behavior for this newly released case; do not globally enable Codex resume or claim it has been measured. Existing live/local/warm reply behavior is unchanged. TestDesign must exercise this branch and make the change explicit in Code's acceptance report; simply returning 200 with an undeliverable old-session queue row is a regression.

Rejected: killing Blocked and leaving `AnswerAsync` untouched; guessing `codex resume` support; transparently starting a fresh provider from the reply endpoint; treating a Blocked routing hold as a completed report; silently losing pending input.

### D-6: attention is a recipient contract, not a log line

Project the typed release ledger into attention using existing `SessionDisagreement` presentation and a distinct `ConditionKey=runner-seat-release:<release-id>`; completed rows have an explicit “Runner seat released” headline and Warning severity, unresolved rows name the exact hold reason. Include runner/store/session/generation, terminal task status/attempt when known, time and confirmed outcome. Rowless entries do not require an Agent or AgentSession join. Preserve task/card linkage when it exists; do not attribute unknown seats to a guessed board. Existing attention scoping/filtering must remain in force.

Include successful notes in the existing recent window (24 hours); unresolved debt remains visible while unresolved. Deduplicate by release identity rather than collapsing every null-Agent incident into one row. The existing Warning force-release audit can remain; do not inflate its severity to Error solely to get it through `BuildRecentIncidentItemsAsync`. Publish the existing attention-invalidating event only after commit; persist recovery state for a missed invalidation or use the existing scheduled reconciliation to republish the same identity. An authenticated attention GET after recovery must contain the same release ID and reason. No chat/email/channel message is added.

Rejected: raw exception text or transcript in an attention note; incident-save-only acceptance; new alert sink; hiding a deferred Working seat or reporting it as released.
