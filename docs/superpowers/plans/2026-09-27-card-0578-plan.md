## Smallest fix

### S1 — persist evidence from the existing one-row runner

Extend `scripts/run-checkpoint.ps1` so `Invoke-Dotnet` creates a per-phase
`build.log` or `run.log` in its already-fresh results directory **before**
starting the child, streams and flushes stdout/stderr into it while the child runs, and
appends an exit marker only after `WaitForExit` returns. Keep the existing
`CHECKPOINT` line, exit-code meanings, slot custody, forward-slash output-path
guard, TRX parsing, and console output. A killed or detached wrapper then
leaves a partial log with no exit marker; a completed failing build leaves its
actual error and exit code. Do not treat mere creation of a log as proof of a
successful build. Use one writer or synchronization for both streams; avoid
buffering the whole build in memory. Add three offline shim cases to
`scripts/test-run-checkpoint.ps1` and corresponding methods in
`tests/Antiphon.Tests/Scripts/RunCheckpointScriptTests.cs`:

- `C578_BuildLogVisibleBeforeExit`: hold a fake build after one output line;
  require a readable `build.log` while the process is still live and require the
  checkpoint wrapper to remain live too.
- `C578_FailedBuildKeepsLogAndExit`: fake a nonzero build; require the error,
  exit marker and existing exit-2 verdict, with no test invocation.
- `C578_NoSuccessReceiptForInterruptedBuild`: stop the owned fake build/wrapper
  at a controlled boundary; require the partial log to remain and no completed
  exit marker or green checkpoint line.

The first case must go red if streaming is replaced by today's end-of-process
buffer. The second must go red if exit handling is discarded. The third must go
red if an incomplete process is reported green. Keep the process-spawning test
class's existing `ParallelLimiter<ProcessSpawnLimit>`.

### Delivery inventory

There is no new agent/session/queue delivery path. The local evidence path is
`dotnet stdout/stderr -> Invoke-Dotnet writer -> fresh phase log -> independent
reader`, joined by checkpoint name, results-directory stamp, phase and owned
child PID/start time. A log's existence is not its completion receipt.

The persistence boundary is flushed, readable bytes in `build.log`/`run.log`.
The completion receipt is one final standalone line
`DOTNET build EXIT CODE: <actual integer>` or
`DOTNET run EXIT CODE: <actual integer>`, respectively, written only after
`WaitForExit` and both stream drains complete. Pin this spelling in the new
assertions; it need not become an extra console line. The observer uses shared
read access while the writer is open. Loss of the wrapper before completion
leaves partial bytes and **no receipt**; report that phase as incomplete, never
as a successful build. An actual nonzero child exit observed by a surviving
wrapper is a completed failure, a different outcome.

The shim substitutes deterministic child output and TRX for MSBuild/TUnit. It
proves the real PowerShell wrapper's logging and gating, not a historical
Windows compiler failure, provider causation, real TRX parameter discovery, or
power-loss durability. No live runner, Postgres, broker or agent is used inside
these fixtures. The outer ordinary checkpoint still takes its host build slot.
