# CARD-2062 · Checkpoint cleanup verification

**Exclusive access cannot be established on the assigned Linux worktree. Keep CARD-2052 parked.** The checkpoint executor has creation records and a driver-exit observation. It has no provider that closes filesystem access to the checkout, its Git inputs and its outputs until the final unlink returns. Accept the current cleanup cost. The conditional tests below are the acceptance criteria if a provider is later proposed. This document completes the verification appendix to the [landed plan](2026-11-24-card-2062-checkpoint-output-cleanup-plan.md).

### Delivery inventory

Cleanup and report publication complete in the executor. This plan introduces zero asynchronous product delivery paths, queues or session inputs. The native fixture uses joined local children. A child request, a gate acknowledgement or a cleanup log line does not establish an attempt, a denied write or an unlink. The observations required from the OS, the independent reader and the terminal report are specified below.

### Proves it works now

- **V-1, native admission and release.** Proposed method `CheckpointCleanupAuthorityWindowTests.linux_finalization_holds_exclusive_custody` (CP-2). Both named parameters must execute on the proposed Linux provider. On today's lane the prerequisite is unavailable. A skip, a timeout or a refusal in both cases cannot qualify it.
- **V-2, admitted product operation.** Proposed method `CheckpointCleanupAuthorityWindowTests.owned_cleanup_preserves_authority` (CP-1). In its plain-owned case require the root physically absent, one complete authoritative removal query, zero per-entry listings, the expected removed counts and the same run/build/output in the terminal receipt. Require the tracked checkout and outside sentinels byte-identical. A separate owned root is a positive removal companion for each refusal family. The ordinary master route and the proposed exclusive route have separate expectations.

#### Native competing writer (CP-2, W5)

Use a disposable full checkout supplied by the **actual proposed supervisor**. The checkpoint executor owns the root and registry from creation. Use the same production handover and anchored unlink as a checkpoint finalizer, with an independent trusted supervisor observation of the syscall. Keep evidence, rendezvous pipes and the observer outside the removable root. Give each run a nonce and each actor a PID/start identity, credential and group identity. Capture the checkout, Git backing and root identities, provider policy, holder membership, actual path attempted, OS return/errno, monotonic event order and final bytes. The supervisor must account for possible writers from admission, including pre-opened descriptors, mounts/aliases and consumers outside the driver tree. If it cannot account for one, qualification ends at refusal.

| Native parameter | Operation and decisive result |
|---|---|
| `holder` | A normally admitted writer first proves reachability by editing harmless checkout metadata and its own output canary. Hold a writable file or directory descriptor across driver exit. Exercise a surviving descendant after the parent exits and a registered consumer outside the build group in separate subfixtures. Wait for a read-back of its nonce before asking for handover. While either holder remains, expect a bounded named refusal, zero destructive calls and unchanged protected bytes. Exercise attempted handoff of a descriptor outside the boundary using a disposable recipient: the provider must prevent that transfer or refuse the grant while the recipient can write. Join and drain every actor. Unknown membership, shared backing and unenforceable admission each retain the whole output. |
| `last-root` | Drain the legal writer, observe empty containment and all consumer releases, close admission and acquire the real finalizer grant. Use a fresh eligible output, with the positive cleanup control in a separate run. An independent probe outside the drained group attempts both harmless checkout/Git writes and an output write. Also ask the real supervisor to admit a new producer. Test identical operations before handover and after release under normal producer authority. Inside the window require an actual kernel refusal for the direct attempts and a named closed-admission result for the admission request. The outside probe uses deployment-equivalent untrusted credentials and namespace. Give it no privileged observer handles. Exercise relevant access routes, including the root's parent name, so permission denial at just one alias cannot qualify the provider. |

**The last-root barrier.** Observe entry and exit of the real finalizer's directory `unlinkat` for this particular output root. A trusted test supervisor may stop **its own disposable child** at syscall entry/exit. Bind the dirfd to the admitted parent object, basename to this root, flags to `AT_REMOVEDIR`, and both stops to the same thread and operation. Also observe an earlier file unlink. A checkpoint callback above the native call, an artificial IO return and a trace of the ledger file are insufficient. If this observer is unavailable on a provider, the native case remains unqualified.

1. Establish independent ready acknowledgements. Hold the finalizer at entry to the root syscall after the last authority and identity checks. The root exists and is empty at this instant. Obtain the competitor's actual operation results while the finalizer is held. Use a create-new canary inside the still-existing root and a harmless write in the still-existing checkout. A successful write fails the case immediately and preserves the fixture. An absent path, an unscheduled child, or a request waiting without evidence of exclusion is inconclusive.
2. Resume the same syscall and require the kernel return value zero. Hold the finalizer after return and before join/release. Check exclusion again using the surviving checkout and an attempted create at the now-empty root **name in its parent**. Verify the protected checkout bytes and the absent root independently. For the revocation subfixture, request cancellation or expire the lease while the syscall is outstanding. Drive the supervisor independently while the executor is stopped. It may stop new operations but must keep admission closed until acknowledged join. A separate cancellation just before a new unlink must leave that entry present.
3. Release only after return, join and acknowledgement. Admit the normal writer on the same workspace again, demonstrate the same checkout and parent/output write operations succeed, and read back the fresh nonce. Record the production admission transition history across the *entire* interval, including new admission and recovery attempts. The required order is grant → authoritative query → native child removals → diagnostic ledger removal → root syscall entry → competitor denial → root syscall success → join → release → successful re-admission. Continuous enforcement comes from the provider's single closed admission interval and filesystem isolation. Samples at two stops alone cannot establish it.

The capability test also needs the trusted provider's assurance that its worker identity cannot escape containment, share writable backing/handles outside the boundary, or access privileged executor/control handles. A permanently unprivileged bystander that can never write is an inadequate competitor. Where deployment assigns different credentials to a new admitted worker, record both identities, demonstrate admission and direct-write reachability on the same fixture when the window is open, and independently exercise the outside principal on a writable matched control. Do not switch the probe to root. A stuck child or missing post-release success fails the fixture. Always release a test stop in teardown, cancel and join owned children, and drain both pipes before any scratch disposal.
