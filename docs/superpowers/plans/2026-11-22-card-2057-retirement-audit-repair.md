# CARD-2057 retirement audit repair after Review round 2

The retirement audit protects indexed content independently of Git status. Only the exact tracked relative path `scripts/antiphon.cmd` can pass with different bytes, and only when a regular checkout file exactly matches the indexed blob with each bare LF expanded to CRLF. The exception reads no attributes, uses no filters and caps both the working file and the indexed blob at 16 MiB. Preview and apply share the read-only audit.

- V-1 requires Git to produce the launcher checkout in a fixture-owned linked worktree. Edited, mixed, extended, truncated, emptied and extra-CR bytes must refuse at the independent audit. Symlink and directory replacements must also refuse. CP-1 requires the linked diagnosis and zero removals on every refusal.
- V-2 requires CRLF edits on other paths to refuse in CP-1. Cover an undeclared path, the same basename with a committed CRLF rule, and common-local, linked-local and staged attribute rules. The Review round 2 implementation must fail the same-basename case before the allowlist fix.
- V-3 requires the launcher checkout to refuse when the indexed blob is exactly 16 MiB and the CRLF working file is one byte larger. Verify both caps independently in V-5.
- V-4 requires C1210 source-roster closure and portable siblings in CP-6. Retain the existing Windows Linux-only outcome row in CP-35.
- V-5 requires Bash syntax checks of the entry script, generated helper and spliced audit, and all 13 byte cases from Review. Exercise the additional CR, both size caps, and the launcher conversion without attributes on owned fixtures.
- R-1 requires the five historical C1008 audit methods in CP-2 and the three Git encoding methods in CP-3.
- R-2 requires the Final policy, mechanical, platform, layering and fixture guards in CP-4.
- R-3 requires the entire matching impact selector across CP-1, CP-4 through CP-20, CP-22 and CP-23. CP-30 through CP-35 belong to the native Windows lane. Run with `--after final` on Linux or `--after native-windows` on Windows and the exact committed `--expected-source-sha`. Use fresh TRX for class and method counts. CP-13 uses only its owned test database on the nested test Docker daemon. No production volume or container is involved.

The Linux witness uses the real Bash retirement audit and Git with fixture-owned linked checkout pointers. Git status alone is forced clean in refusal cases to exercise the independent content check. No optional input controls the exception. Startup impact is none.
