- D-5: Route portable work by live runner defaults, native Job Object evidence by Windows platform. Read runner-defaults and session-runners on 2026-10-29; both portable and Windows lanes are available. Do not pin a fleet location.
- D-6: Reject changing `nativeActiveMax` as though it were a setting. It is a measured output and `>1` currently fails coverage. Prefer the existing in-process limiter for the first diagnostic trial; retain native serialization.
- D-7: Pack only proven-compatible exact methods within the same class; retain separate processes between resulting chunks. Reject whole-class widening, cross-namespace path OR, prefix collisions and combining startup/isolation-sensitive leaves merely to hit a savings target.
- D-8: Use existing assembly setup sharing and immutable schema caching before designing a run-wide live database. A live mutable fixture shared across processes is not a cheap change and is outside this implementation round.
- D-9: Trial `ProcessSpawnLimit=2` in a non-credit Debug harness, with normal execution still 1. Reject concurrent native chunks in this round: they need a new scheduler, per-process DB/resource admission and an explicit change to the native-overlap contract. - D-10: Reject a population-wide shortened watchdog. A per-launch cap must cover the admitted estimate and its measured error; retain existing policy until the planner/cap pair is changed and validated atomically. A speed target cannot justify killing an admissible healthy launch.
- D-11: S6 is a Windows Debug trial (`-Platform Windows`, no host pin). The 657.5 min opportunity is Windows evidence; Linux runs and Windows-only skips earn no trial credit. The candidate rule in seconds is `W(P) = ceil-to-60(max(600, 2*E95*P, Emax*P + M))`, where M is the separately measured cleanup/observation safety margin (not a second counted saving). This follows approximately twice the conditional predicted p95, with an explicit measured tail exception. The suite maximum must satisfy `Wmax >= W(C)` for C=2400 ordinary or C=1800 E2E; the launch validator refuses NaN/nonpositive costs, P>C, missing budget provenance, or W(P)>Wmax **before any child starts**. Missing group estimates in legacy/nightly paths retain the existing watchdog, not the 600 s floor.

Proof: W is monotone in P and W(P) >= Emax*P+M > P, so every admitted estimate through C fits its assigned cap including the recorded worst estimate error.
