## Decisions

- D-1: Measure first. The process responsible for 114.2 minutes of post-session delay is unknown; telemetry is only a hypothesis.
- D-2: Preserve Full coverage, exclusion rules, process custody and frozen candidate identity. Speed is not gate credit.
- D-3: Keep native and in-process concurrency at 1 until an independent Debug comparison supports one change at a time.
- D-4: Implement reviewed changes on both master and the active rc line before a new Full run; do not mutate an existing sealed attempt.
- D-5: Route portable work by live runner defaults, native Job Object evidence by Windows platform. Read runner-defaults and session-runners on 2026-10-29; both portable and Windows lanes are available. Do not pin a fleet location.
- D-6: Reject changing `nativeActiveMax` as though it were a setting. It is a measured output and `>1` currently fails coverage. Prefer the existing in-process limiter for the first diagnostic trial; retain native serialization.
- D-7: Pack only proven-compatible exact methods within the same class; retain separate processes between resulting chunks. Reject whole-class widening, cross-namespace path OR, prefix collisions and combining startup/isolation-sensitive leaves merely to hit a savings target.
- D-8: Use existing assembly setup sharing and immutable schema caching before designing a run-wide live database. A live mutable fixture shared across processes is not a cheap change and is outside this implementation round.
- D-9: Trial `ProcessSpawnLimit=2` in a non-credit Debug harness, with normal execution still 1. Reject concurrent native chunks in this round: they need a new scheduler, per-process DB/resource admission and an explicit change to the native-overlap contract. Neither a trial pass nor lower CPU grants that policy change.
- D-10: Reject a population-wide shortened watchdog. A per-launch cap must cover the admitted estimate and its measured error, including completed failed-test walls; retain existing policy until the planner/cap pair is changed and validated atomically. A speed target cannot justify discarding completed failure evidence through an early kill.
- D-11: S6 is a Windows Debug trial (`-Platform Windows`, no host pin). The 657.5 min opportunity is Windows evidence; Linux runs and Windows-only skips earn no trial credit. Live defaults and runners were read again on 2026-10-29; both portable and Windows dispatch are available, subject to a fresh check at dispatch.
- D-12: Treat missing production authority/ledger wiring as an explicit S4 integration prerequisite, not an uncertainty or an optional follow-up. Reject diagnostic manifest promotion and post-execution rewriting.
- D-13: Limit the first parallelism experiment to two audited synthetic planner tests. Keep one shared strict limiter at 1 in every ordinary run, exclude all other timing/wait tests from the diagnostic process, and report this narrow inference honestly; broader concurrency adoption requires a new reviewed roster and reliability budget.
- D-14: Co-locate CP-1/2/3/5 on the Windows S1 build because CP-2 needs native Windows; this saves three builds without transferring binaries or evidence between OSes. Other reusable groups stay on their actual host/SHA. Reject cross-lane/cross-commit reuse.
- D-15: S3 reductions require 20 independent complete launches in an exact measured stratum. Default, pace, conservative/observed-bound and unknown cost rows retain the existing suite watchdog. Reject pooling a new class with measured siblings or ignoring failed outcomes to obtain a smaller cap. Exact matching may leave S3 inactive after code changes; that is the chosen fail-closed default, not permission to relax comparability.

**S3 budget procedure (round-3 D-1).** Change `Get-NightlyProfileLaunchPlan`, cost provenance propagation, the native launch timeout handoff and the policy validator together. The exact stratum key is `(suite, expanded-UID-multiset digest, cost-table digest, execution-input digest, assembly digest, OS/version/architecture, .NET runtime version, host identity/core count, load-band id, fixture/cache mode, effective concurrency)`. This is a provisional minimum for an empirical nearest-rank p95, not a reliability guarantee.

For an eligible stratum compute E95 = max(1, nearest-rank p95(wall/P)) and Emax = max(E95, max(wall/P)); retain every ratio and outcome. Propagate a reason such as `unmeasured-cost` into the launch receipt. Missing legacy estimates also retain that watchdog. No 600 s fallback for these paths.

The candidate rule in seconds is `W(P) = ceil-to-60(max(600, 2*E95*P, Emax*P + M))`, where M>=0 is the separately measured cleanup/observation safety margin (not a second counted saving). This follows approximately twice the conditional predicted p95, with an explicit measured tail exception. The suite maximum must satisfy `Wmax >= W(C)` for C=2400 ordinary or C=1800 E2E; the launch validator refuses NaN/nonpositive costs, P>C, missing budget provenance, or W(P)>Wmax **before any child starts**. Do not clamp W downward to a suite maximum. If retaining a smaller Wmax, lower C in the same reviewed slice and reprice/split the affected launches; never launch then discover the cap mismatch. Missing group estimates in legacy/nightly paths retain the existing watchdog, not the 600 s floor.

Proof for an eligible stratum: W is monotone in P, W(P) >= Emax*P+M, and W(P) >= 2*E95*P > P, so every admitted estimate through C fits its assigned cap including the recorded worst estimate error **across passing and failing complete launches**. At E95=Emax=1 and M<=P, the boundary budgets are 4800 s ordinary and 3600 s E2E: a uniform 31-35 min cap is impossible; retaining the ordinary 3600 s maximum would require C<=1800 s and any tighter measured margin constraint. Larger measured error raises the required cap or lowers admission. This is conditional empirical protection, not proof that all future walls are bounded.
