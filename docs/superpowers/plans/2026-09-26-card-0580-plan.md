## Smallest fix

**S1 — test request and oracle repair.** In the four durable land scenarios and the already-landed scenario, remove the direct `LandRequestedAt` assignments. After committing the source, publish `HEAD` to its exact `refs/heads/<task.WorktreeBranch>` on the source push URL and call `land.RequestAsync(task.Id, new LandAgentTaskRequest(ExpectedSourceSha: sourceSha), ...)`, following the request shape in `AgentTaskLandStageOutcomeTests.RequestHeadAsync` (`:623-630`). Resolve the URL with `git remote get-url --push origin`, matching the production source observer. Keep the conflict and moved-base setup before requesting. For push rejection, publish the source and request **before** installing the rejecting hook, so the setup push succeeds. Keep the original assertions for clean publication, upstream cleanup, conflict preservation and rejected target push. Add request/operation reason assertions so a pre-operation refusal cannot pass as the intended branch behavior. Rename the already-landed test for its current contract and assert `target_local_ahead`, no operation or target push, unchanged local and remote SHAs, and retained worktree. The analogous CARD-0688 test is a useful expected-outcome reference (`AgentTaskLandPublicationTests.cs:720-739`).

**S2 — portable hook fixtures in this class.** Use one private test helper to write hook text and set `UserExecute` (and read/write) mode on non-Windows, following `ScratchGitRepo.InstallFailingPreCommitHookAsync`; use it for the two `post-checkout` fixture writes and the `pre-receive` hook. This closes the three additional baseline failures and keeps the rejection scenario meaningful on Linux. No server code or shared fixture behavior needs to change.

## Risks and decisions

- Do not restore implicit legacy landing or make a no-SHA request land: `RequestAsync` requires a full expected SHA (`AgentTaskLandService.cs:138-164`), and the resolver intentionally refuses schema 1.
- The source push must use the configured **push** URL (`git remote get-url --push origin`) and an explicit full ref. Production reads this endpoint (`LandingGit.cs:464`); a plain `git push` can use a different upstream or fail under `push.default`.
- A failing target `pre-receive` hook must be armed after publishing the source. Assert the hook actually rejects the target push; otherwise the test could report a false green from a different refusal.
- CARD-0688's `target_local_ahead` refusal has separate coverage already. Retaining the repaired real-Git scenario in this class checks the public request/runner path; TestDesign can consolidate it only if that class-level evidence remains.
