### Receipt implementation stop

The brief requires stopping if the existing mechanism cannot express conditional
skips. At this base `WindowsUnitSkipRoster.Conditional` is consumed only by the
hand-written child audit. S1's 68 native skips are inside its child TRX; its outer
checkpoint has zero skips and therefore passes strict validation. CP-20 exposes
its two conditional skips in the outer TRX and cannot use that arrangement.

`CheckpointSpec` has no skip declaration or capability field. `PlanTableImporter`
accepts only EstimatedMinutesWindows, Serial, Environment and Repeat optional
columns; Expect is descriptive text, not an executable skip contract.
`ReportValidator.Validate` rejects `row.Skipped != 0`; the PowerShell validator
does the same. The unrelated checkpoint-usage OS roster only validates the fixed
checkpoint-namespace census and cannot declare conditional per-row skip reasons.

Missing: a bound per-row declaration of exact class/method identities, counts and
reasons; independent capability evidence distinguishing unavailable from available;
producer serialization of that declaration/evidence; and both strict validators
checking it against fresh TRX (including rejecting extra/wrong skips and requiring
zero skips when privilege is available). Implementing that contract is a separate
checkpoint infrastructure change, rather than using an existing mechanism.
No validator is loosened here. Receipt declaration tests and a clean CP-20 receipt
remain blocked pending caller commissioning of that change.
