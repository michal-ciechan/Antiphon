# CARD-1493 S1: import-time duplicate-build warning

Source: CARD-1493 (remainder of CARD-1489), origin
`docs/investigations/2026-10-22-server2-build-slot-throughput.md`: 45 `Antiphon.Tests` build
attempts in three hours, five of them avoidable second builds of the same project in the same
`After` group (18.7 slot-minutes plus 10.5 minutes of queue). No budget, setting, slot, node or
memory value changes.

## Slice choice

Item 1 of the card (same-group build reuse in `PlanTableImporter`), as a **non-fatal warning** only.
It is confined to one pure function of the plan text, adds no I/O, and cannot change what a run
executes: the manifest, builds, rows and exit codes are produced exactly as before and the
warning is appended to the existing `ImportResult.Warnings` list, which `import` prints to stdout
and `run`/`start --plan` print to stderr as `WARNING ...` (the same channel as the derived-row
timeout advisory). Item 2 (Hosts page reading `ANTIPHON_BUILD_SLOTS_URL`) touches the server's
host-stats store, runner discovery and deployment configuration on two hosts; it stays on the card
with items 3 and 4.

## How the importer derives builds (Step 1, read-only trace)

- A Build cell is `<project> -> bin-<x>/`, `CP-n` (optionally `(-NoBuild)`), or `n/a`.
  `bin-<x>/` is the output path; the build id is the output without the trailing `/`.
  A repeated `bin-<x>/` cell with the same project reuses that build; a different project under
  one id is refused. `CP-n` reuses the build of an earlier row and is refused across different
  `After` groups; a build reused with a different `Repeat` is refused.
- `After` is expanded by `AfterSelector.Expand` and keyed as the comma-joined list.
- What reaches the compiler (`RunScheduler.BuildOneAsync`): `dotnet build <project>` with
  `--property:OutputPath=<bin-x/>`, the manifest-wide `build.properties` (one set for every build
  of a plan; a plan table cannot set them per row), the host platform, the shared-layout
  properties derived from the project and output path, and the RepeatHost properties when the
  build's `Repeat` > 1 (the first row using a build sets it). Row `Environment` does not reach the
  build: the scheduler build takes no row environment and rows then run with `NoBuild`.
  Configuration and target framework are not plan-table inputs.

## The rule

Two Build definitions in one plan are **equivalent** when they have different build ids and

1. the same normalised project: backticks trimmed, `\` -> `/`, leading `./` and trailing `/`
   removed, and a final `/<Name>.csproj` segment removed when `<Name>` equals its parent
   directory's name (`tests/Antiphon.Tests/Antiphon.Tests.csproj` == `tests/Antiphon.Tests`);
   compared ordinal-ignore-case. No filesystem access;
2. the same `After` key (the comma-joined expanded selector); builds in different `After`
   groups are never equivalent, matching the existing refusal to reuse across groups;
3. the same `Repeat` (the defining row's).

At the row that first defines a build equivalent to an earlier one, the importer adds exactly
one warning:

`<CP>: Build '<bin-y>' duplicates '<bin-x>' from <CP-first> (same project '<project>', After '<after>', Repeat <n>); write '<CP-first>' in the Build cell to reuse it and save one build`

where `<bin-x>` is the earliest equivalent build. The warning never changes the exit code, the
error, the manifest, the build list or any row.

## Verification design

All in `tests/Antiphon.Tests/Checkpoints/CheckpointImportTests.cs` (Unit).

- **V-1 `C1493_DuplicateBuild_second_equivalent_build_warns_once`**: CP-1 `bin-a/`, CP-2 `bin-b/`
  (same project, After, Repeat), CP-3 `bin-b/` again and CP-4 `CP-2`: exactly one warning, the
  exact text above for CP-2; exit 0; both builds kept and every row's build unchanged.
- **V-2 `C1493_DuplicateBuild_project_spellings_normalise`**: `tests\Antiphon.Tests\Antiphon.Tests.csproj`
  then `` `./tests/Antiphon.Tests/` ``: one warning naming the first build.
- **V-3 `C1493_distinct_after_repeat_or_project_do_not_warn`** (negative control): a different
  `After`, a different `Repeat`, a different project, a `CP-n` reuse and a repeated `bin-x/`
  produce no warning.
- **V-4 `C1493_warning_keeps_import_exit_and_output`**: `import --plan` of a plan with an
  equivalent duplicate exits 0 and writes the manifest; a plan that is otherwise refused keeps its
  original exit code 2 and error.
- **R-1** the rest of `CheckpointImportTests` (exact warning lists for the derived-timeout
  advisory and committed plans) and the `Antiphon.Tests` Unit lane, which contains every
  checkpoint test class that imports plans (`CheckpointRepeatConfigurationTests`,
  `CheckpointStampSafetyTests`, `CheckpointTaskOwnershipTests`, `PlanCoverageCommandTests`).
- **M-1 (manual, disclosed)**: run `import --plan` over every plan in `docs/superpowers/plans`
  with the tool built at the base and at the tip; every exit code identical, and the number of
  plans gaining the new warning reported.

Red: V-1 and V-2 fail at the S1-test commit (no warning; `ShouldBe` on the warning list).
V-3 and V-4 pass there by design (controls against a fatal or over-eager rule).

Pending for SourceLanding Mutation (method-scoped): PC-1 drop `After` from the key (V-3 red);
PC-2 drop `Repeat` from the key (V-3 red); PC-3 skip project normalisation (V-2 red); PC-4 turn
the warning into a refusal (V-1, V-4 red); PC-5 warn for every reuse of the same id (V-1/V-3 red).
