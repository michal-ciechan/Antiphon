# CARD-0989: pin the Grok CLI download by SHA-256

Date: 2026-10-12. Card: Antiphon `38e7ebb4-8265-46e5-9e12-3532606c4296`.
Inspected source: `d8188da496b2369e9ee688f8977c4888510fbb9f` (`runtime-base` still pipes `https://x.ai/cli/install.sh`).

## Decision

`docker/session-runner-grok/Dockerfile` `runtime-base` downloads `https://x.ai/cli/grok-${GROK_VERSION}-linux-x86_64` to a file, checks a reviewed SHA-256 with `sha256sum --check --strict`, and only then installs and runs `grok --version`. The unchecked `install.sh` pipe is removed. There is no fallback to that script. This slice does not build or push an image and does not touch the server2 stack.

## Pin supply and rotation

The reviewed pair lives as ARG defaults inside `runtime-base`, same shape as Claude Code:

- `GROK_VERSION=1.0.41`
- `GROK_SHA256=9ce03ed23e16ea01072b4496263d6213a27899e1e3e107f008d36edf82e70407`

Measured 2026-10-12 without executing the download: `HEAD` of that URL returned `content-length: 165967424` (the size CARD-0989 recorded on 2026-10-02). The fetched file's SHA-256 is the value above, and the bytes match the host `/usr/local/bin/grok` that prints `grok 1.0.41 (4220f3b224a6) [stable]`. The temporary download was deleted after the hash.

A normal image build uses those defaults and needs no extra build-arg. Raising the pin means editing both defaults together after hashing the new raw artifact. A re-published file fails at `sha256sum --check --strict`. The remedy is a new reviewed pair. Dropping the check or returning to `install.sh` is not a remedy.

An operator who must override the pair passes `--build-arg GROK_VERSION=<version>` and `--build-arg GROK_SHA256=<64 lowercase hex>`. The whole value must be exactly 64 lowercase hex characters. An empty pin, any other length, or any character outside `0-9a-f` (including a newline, CR, space, or uppercase hex) fails the `RUN` before `curl`.

## Failure behaviour

In the same `runtime-base` `RUN`, in order:

1. `test -n "${GROK_SHA256}"`, `[ "${#GROK_SHA256}" -eq 64 ]`, and `case "${GROK_SHA256}" in *[!0-9a-f]*) false ;; esac`. The length and `case` tests see the whole value, not one line of it. Failure stops the build before any fetch.
2. `curl` writes the artifact to `/tmp/grok-download/grok` and does not execute it. `[ -s /tmp/grok-download/grok ]` rejects an empty file before the checksum.
3. `printf '%s  %s\n' "${GROK_SHA256}" /tmp/grok-download/grok | sha256sum --check --strict`, then `[ "${grok_checksum_status}" = "/tmp/grok-download/grok: OK" ]`. A mismatch, an improperly formatted line, or any verified name other than that artifact stops the build before `install` and before `grok --version`.
4. `install -m 0755` to `/usr/local/bin/grok`, `ln -sf grok /usr/local/bin/agent`, then `/usr/local/bin/grok --version | grep -F "${GROK_VERSION}"`.
5. `rm -rf /tmp/grok-download`.

## Verification design

Ordinary scope is these two methods. The binding house rule for this dispatch forbids the broad Unit lane. `DockerStackContractTests` has many unrelated contract methods; only the new method is in scope. `VerifyPhoneHomeGrokScriptTests` is the affected integration class; the closed filter is the one dockerfile assertion. Its other methods spawn `pwsh` and do not guard this pin.

V-1. `runtime-base` pins Grok 1.0.41 to the reviewed digest, rejects a missing or non-whole-string pin before fetch, verifies with `sha256sum --check --strict` and an exact `<artifact>: OK` line before install and before `grok --version`, and the Dockerfile does not name `x.ai/cli/install.sh`. Test: `DockerStackContractTests.Runner_pins_grok_cli_by_version_and_digest`.

V-2. The phone-home dockerfile read still requires `1.0.41`, requires `https://x.ai/cli/grok-${GROK_VERSION}-linux-x86_64`, and rejects `x.ai/cli/install.sh`. Test: `VerifyPhoneHomeGrokScriptTests.Compose_and_dockerfile_do_not_hardcode_server_origin`.

V-3. The same `runtime-base` shell is executed. A multiline pin, a trailing newline, a second line that verifies `/dev/null`, an embedded newline inside a 64-character value, uppercase hex, 63 characters, 65 characters, and an empty pin all fail before `curl`. An empty download and a tampered file fail after the fetch and before install. A pin that matches the file passes. Tests: `GrokSha256PinTests.Runner_grok_sha_rejects_multiline_pin`, `Runner_grok_sha_rejects_trailing_newline`, `Runner_grok_sha_rejects_devnull_second_line`, `Runner_grok_sha_rejects_embedded_newline`, `Runner_grok_sha_rejects_uppercase_pin`, `Runner_grok_sha_rejects_short_pin`, `Runner_grok_sha_rejects_long_pin`, `Runner_grok_sha_rejects_empty_pin`, `Runner_grok_sha_rejects_tampered_file`, `Runner_grok_sha_rejects_empty_download`, `Runner_grok_sha_accepts_matching_file`.
