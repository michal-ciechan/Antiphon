# CARD-1614: Linux custody and PtyHost test repairs

Status: complete design for independent plan review by a different company's model; no product repair or native qualification performed by this Plan.
Round-2 source base: `8b6b23b1a469893b5355ff42aa666230b8a125e8` (round-1 plan and design review). Scope: a written repair plan only. Round-2 revisions resolve review defects D-1 through D-5; product code remains unchanged.
Evidence: [full investigation](../../investigations/2026-10-29-ptyhost-linux-reds-classification.md).

## Decisions

- D-1: Keep the three confirmed product defects distinct from fixture/build defects; a Linux test exclusion cannot repair custody.
- D-2: Root exit with live descendants keeps custody open. Observation must not initiate termination. Explicit release remains available; no new automatic kill or stall deadline.
- D-3: Complete the six missing baseline reruns before implementation. Preserve expected reds as baseline evidence, never as a passing gate.
- D-4: The finished artifact goes to independent plan review by a different company's model before implementation.
- D-5: Use the existing direct-exec sudo design, with the missing credential setting and native proof; reject post-launch PID guessing and a new privileged broker unless this minimal repair is disproved.
- D-6: Stage the native PtyHost once at test build time. Reject a per-test `dotnet build`, global `UseAppHost=true` (shared-output collisions), and skipping Linux launcher tests to hide missing artifacts.
- D-7: Keep Windows inbox semantics explicitly Windows-only, and separately test host OS/backend rejection. Reject changing the Unix backend selector to make a Windows fixture pass.
- D-8: Treat v1 and v2 as separate native lanes, and Windows as a separate regression lane. An unavailable lane is incomplete verification, not a skip credited as green. No default fleet pin.
- D-9 (review D-1): The verification consumer owns explicit release through `VerificationCleanupService.CleanupAsync`, requested by the task's orchestrator after terminal settlement. Root exit and elapsed time are not release authority. Linux custody remains unadvertised until native qualification and this operational owner are established; do not enable it merely because repaired helper probes pass.
- D-10 (review D-2): Natural zero requires successful accounting from an existing owned tree, including the post-drain re-read. Reject missing-tree-as-zero and helper-exit-as-accounting. Retain empty execution cgroups through receipt creation; only probe trees may be removed immediately by helpers.
- D-11 (review D-3): All helper population decisions use successfully read PID content, never pseudo-file size. Read errors and a still-populated deadline are nonzero outcomes. Preserve the production 30-second drain bound, not its broken implementation.

## Product repair design

Line references below are to the base above. Each product fix follows a committed failing witness; build/fixture failure or zero selected tests is not that witness.

### P-1: wrong tracked root identity

`PtyAgentRunner.cs:193-200` records Porta's PID; `IPtyCustodyContainment.cs:94-98` has replaced the payload with `sudo`. The enter helper places its own PID before `exec setpriv` (`antiphon-custody-enter.sh:96-100,163`). Investigation observed the recorded outer sudo outside the tree, with its shell and sleep inside. The image policy (`docker/session-runner-grok/sudoers-antiphon-custody:18-23`) disables `use_pty` and `pam_session` but omits PAM credential teardown, which can retain a sudo supervisor.

Smallest candidate: add `!pam_setcred` to that existing uid-scoped policy, keep the two-command allowlist and the helper's uid/gid, supplementary-group drop and `no_new_privs` boundaries. Validate with `visudo -c`, the effective policy and native PID evidence in a separately provisioned candidate image. The [upstream sudoers manual](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) also requires no I/O logging or configured log server for direct execution; verify those conditions rather than weakening audit policy globally. This is a candidate policy repair, not a proven no-fork guarantee on every sudo build. Do not install it into the running delegate's container. If the actual shipped sudo still supervises, stop this slice for focused investigation of the launch identity protocol; do not substitute the first cgroup member or a process-name/parent-PID census as identity authority.

RED V-7: extend `LinuxCgroupCustodyTests.Tracked_launch_places_child_in_tree` through `HostSession.LaunchAsync -> StartTrackedAsync -> Porta -> installed enter helper`. The payload writes its own PID and a readiness nonce, then holds. Require equality of payload PID, `LaunchedMessage.ChildPid`, running manifest child PID and `tracking.json` PID/start time, and membership in every active hierarchy. Current code already fails membership. Retain `/proc` identity/start and helper/policy/image digests, not command arguments or environment. GREEN must also retain the existing child privilege/containment witness. This fixes the tracked **payload** root; `VerificationHostIdentity.HostPid` separately identifies the observing PtyHost and is not to be replaced.

### P-2: helper exits before termination

Under `set -u`, Bash expands all arguments of `local` before its assignments: `antiphon-custody-kill.sh:91` references `id` in the same statement that initializes it. `:72` and `antiphon-custody-enter.sh:57` repeat the shape for v2. Split each into an `id` declaration/assignment followed by dependent paths. These are the three confirmed dependent-local defects; retain the guarded positional arguments and initialized APP_UID/APP_GID. Correct the misleading no-kill comment on `PtyAgentRunner.cs:503` when separating observation below.

Replace **all four** `-s cgroup.procs` population decisions with checked content reads. Distinguish empty, populated and unreadable; a failed `cat` cannot become an empty string accepted as zero. Enter refuses a populated tree in either v1 hierarchy or v2. Kill retries successful reads until empty or the unchanged 30-second deadline; missing/unreadable data exits nonzero, and `C604_CUSTODY_KILL_OK` is emitted only after observed drain. Remove the `tree_pids ... || true` read-error suppression in the v1 kill loop. Preserve GUID/path validation, privilege drop and freeze/kill/thaw ordering; a missing v1 freezer or failed freeze/read is a refusal, and a failure after freezing must attempt owned thaw while preserving the original failure. Never silently fall back to an unfrozen PID sweep.

To make the failed-drain assertion deterministic, factor the content-read/drain functions into a root-owned, non-writable `docker/session-runner-grok/antiphon-custody-common.sh`, installed alongside both helpers by the Dockerfile. Helpers source only that fixed absolute path; the sudo allowlist stays exactly two commands. Add native `LinuxCgroupCustodyTests.C1614_Populated_tree_refuses_entry_and_drain_success`: an isolated fixture holds a real live cgroup member, confirms pseudo-file size zero plus nonempty contents, asks the installed enter helper to reuse the container (must refuse before a second payload marker), then invokes the **same installed drain function** from an unprivileged test shell without a preceding kill. A test-call deadline of one second is a parameter of the shared function; production main always passes 30 and accepts no caller/environment override. Require nonzero drain result while the independently observed member remains alive and no success marker. Separately the full installed kill path in V-8 must terminate that fixture and read back zero. Missing/unreadable accounting cases use a private filesystem fixture for the shared reader and require nonzero; they do not qualify a native kernel lane. No test replaces helpers in a standing container.

This native witness must fail on the original `-s` implementation after only the mechanical function extraction and dependent-local fixes; commit it before the population repair. Its post-land PC restores `-s` in that shared function and must fail the live-member drain assertion. V-8 additionally tests the failed-drain observation through the managed termination seam: failure plus live population cannot persist a terminal receipt. Zero tests, helper launch failures or `id: unbound variable` are not the failed-drain RED.

RED V-8/V-9: the first two checkpoint methods call `HostSession.GetCustodyAsync(seal:true) -> HostCustodyJournal -> PtyAgentRunner -> LinuxCustodyOperations.Kill -> installed helper` with a live contained payload. Require zero accounting, drained output, terminal receipt and successful termination; a second explicit seal returns identical durable bytes. The existing first-seal assertion fails on current code; the old second-seal run never exercised idempotency. Keep helper stderr/exit separate from accounting. Add a real candidate-image probe witness invoking `LinuxCgroupCustodyProbe.Detect()` and require both installed helpers' probes to succeed. v2 must exercise its native branch; a script text assertion is not native qualification.

### P-3: root exit implicitly authorizes termination

There are **two** seal escalations: `HostSession.cs:332` uses `seal || Status == Exited`, and `SessionRunnerRuntime.cs:4477` uses `HasExited || runner-seal-present`. The host's exit observer (`HostSession.cs:402,405,433`) starts ordinary reads. `HostCustodyJournal.cs:97-101` maps those to `SealAndObserveCustodyAsync`; `PtyAgentRunner.cs:512-529` writes the irreversible producer seal and terminates Linux containment. The unused three-argument `HostCustodyJournal.ObserveAsync` also defaults to `seal:true`; remove that overload. Fixing P-2 alone therefore makes this path more destructive. Ship P-2 and P-3 together.

Smallest coherent change spans `src/Antiphon.PtyHost/HostSession.cs`, `HostCustodyJournal.cs`, `src/Antiphon.Agents.Pty/PtyAgentRunner.cs`, and `src/Antiphon.SessionRunner/SessionRunnerRuntime.cs`:

- Carry explicit release intent from the persisted runner seal at runner ingress (or the explicit `seal:true` host protocol request); root exit and the producer seal are observations/fences, never that intent. Remove both automatic escalations. A later ordinary read after a natural producer seal or failed receipt write must never call `Terminate`.
- Split nonterminating accounting/finalization from explicit Linux seal-and-terminate. A running unsealed root remains Tracking. Root exited with live members is Draining without a producer seal or receipt. Read/identity/output errors are Unknown, never zero. The same retained container observer remains authoritative.
- On natural descendant-zero, under the existing admission/write serialization, fence further input, persist the producer seal, drain output, re-read zero and persist the receipt without invoking termination. A mere root exit or helper exit code cannot certify zero. Reuse the owned drain task and immutable receipt ordering; do not create a replacement container.
- Explicit Linux release persists its fence before termination, then requires observed zero and drained output. Failed termination with live/unknown accounting stays nonterminal. Windows explicit seal remains nonterminating, as `Live_job_seals_without_killing_and_late_input_and_launch_are_refused` requires.
- `StartLingerExpiry` (`HostSession.cs:445`) currently requests host exit on a timer even for tracked descendants. Withhold automatic linger disposal while tracked custody lacks an accepted final receipt, in **both** root-exit (`:402`) and launch-failure (`:174`) paths; retain the observer and explicit-release path. Ordinary untracked linger behavior is unchanged. Once custody is terminal, use the existing acceptance/shutdown contract.

**Release ownership and failure disposition (review D-1).** `VerificationCleanupService.CleanupAsync` is the existing consumer: its terminal-task admission seals further launches, then asks the bound runner to seal every unresolved execution before importing receipts or removing a snapshot. The task's orchestrator must invoke that cleanup operation after Succeeded/Failed/Canceled settlement and retain/retry unresolved residue. It is an explicit operation, not a periodic or age-triggered releaser. There is no automatic release deadline. Do not claim bounded process lifetime from a bounded observation call. Until that operational obligation and native qualification are fulfilled, keep Linux admission/capability off as specified below. Windows already advertises custody; its existing explicit cleanup owner remains responsible for release.

For a missing/dead host, add recovery to `SessionRunnerRuntime.ReadCustodyAsync` and `RunnerSession.CollectCustodyAsync`, sharing one ledger-bound operation in `RunnerCustodyLedger.cs`. Require the exact persisted binding, store identity, `host-identity.json` ContainerId, matching root namespace and persisted `runner-seal.json`. Confirm the recorded host PID/start identity is gone; a disconnected pipe alone does not authorize a second observer. Only then call the installed kill helper for that recorded container, read back its disposition, and retain recovery evidence. Never guess a GUID from a directory scan or PID census. Recovery is cleanup only: the response remains **Unknown**, no producer/accepted receipt is manufactured, and snapshot removal remains refused even after processes are confirmed gone. Missing/mismatched records or namespace keep Unknown and perform no kill. Repeated explicit releases are idempotent. Ordinary reads, adoption and elapsed time never invoke this recovery kill.

When `_failure` is set after native start intent, an explicit release must still reach termination of the retained, known containment before returning Unknown. This covers `RecordTracking` racing a fast root exit: missing root identity forbids a receipt, but must not prevent release of the recorded container. Pre-native/unsupported failures retain their existing NeverStarted/UnsupportedBackend rules. No automatic linger expiry may abandon a possibly started tracked tree.

Expose prolonged Draining through existing runner structured diagnostics: execution/container identity, first observed Draining UTC, duration and a Warning after 30 minutes (test with the clock seam). This is detection only, with no seal, kill, shutdown or parking side effect; the orchestrator owns explicit resolution. Do not add a timer that stops a Working session.

Witness obligations: extend `Lost_host_leaves_unknown_not_receipt` with no-release survival and exact-container recovery semantics; add runner `C1614_Lost_host_explicit_release_kills_but_stays_unknown` (including restart/adoption and mismatched-identity refusal), host `C1614_Failed_tracking_explicit_release_terminates_without_receipt` (fault after native intent, short linger elapsed), and portable runner `C1614_Draining_age_reports_without_releasing`. Each needs committed red-first evidence and final green in the revised roster. The native recovery case must demonstrate a surviving descendant before explicit release and absent process afterwards, not merely helper exit zero.

**Fail-closed natural zero (review D-2).** Change `LinuxCustodyOperations.ReadTreePids` in `IPtyCustodyContainment.cs` to throw on a missing tree/procs file, permission failure or malformed PID data, including errors from a direct open/read (existence probes can hide access failures). Natural completion requires successful reads from the same root namespace/container before and after output drain, validated tracking/native intent, and an observed root exit. A refused placement is Unknown with no receipt even if the outer sudo process exits. `producer-seal.json` is only a write fence; its presence never enables termination on an ordinary retry after failed persistence.

Keep the execution tree after successful explicit helper termination so the host can actually re-read zero instead of inferring it from deletion. Restrict `remove_tree` to `--probe`; empty execution directories become retained accounting residue, eligible only for the separate provenance-checked nonrecursive cleanup procedure after accepted receipt (or operator reconciliation of Unknown). This intentionally trades small empty-directory residue for truthful accounting. Lost-host release still kills the recorded container and stays Unknown; missing accounting cannot be promoted to a clean receipt even there.

Add `LinuxCgroupCustodyTests.C1614_Missing_tree_never_finalizes_naturally`: use a fresh never-created container / refused placement in an isolated native root, observe root exit, assert Unknown, no receipt, no termination call. Add portable `LinuxCgroupContainmentTests.C1614_Missing_tree_throws_before_termination`, exercising the real read implementation with an owned path-resolution seam, not a fake pre-thrown operations error; also cover unreadable/malformed accounting in that method. Add the native red-first witness after S2 to isolate this defect from broken helper prerequisites, and its final native green; run the portable red before S3 and green in the containment contracts row. Natural completion is cross-platform: retain `HostCustodyTests.Producer_store_failure_never_acknowledges_exited_and_can_retry_same_job` and `Durable_receipt_precedes_reply_and_shutdown_requires_runner_acceptance` in CP-22. Their ordinary-read retry/finalization must work on the retained Windows job without an automatic exit-to-seal escalation.

RED V-10: synchronize the existing root-exit daemon fixture, then require actual root exit, living detached child in the real cgroup, Draining on repeated ordinary reads, no seal/receipt and child still alive before explicit release. Exercise both direct host reads and the real runner's `ReadCustodyAsync(seal:false)` path; a host-only test would miss the second trigger. Add `LinuxRunnerCustodyLifecycleTests.C1614_Root_exit_read_does_not_seal_live_descendant` in SessionRunner.Tests using an isolated runtime/runner and real staged PtyHost/helpers, never the production runner.

Add native `LinuxCgroupCustodyTests.C1614_Natural_descendant_exit_finalizes_without_release` and `C1614_Root_exit_retains_observer_past_linger`: use controlled child release/readiness, a short test-only linger duration, receipt absence while alive, then natural exit/zero/drain and durable final receipt. These expose the otherwise tempting incomplete fixes (remove the force-seal but never finalize; keep the timer and abandon custody). An independently observed descendant survival before explicit release is mandatory. Retain receipt-before-ack, lost-host, cancellation/output-error and Windows nonterminating-seal regressions.

This changes custody observation, not an input-waiting session policy. A release still leaves the process killed, pooled warm or owned by a standing agent. A stall never authorizes kill. No automatic release deadline is introduced; with parking disabled, input-waiting sessions have none (CARD-1083).
