# FT-5 checkpoints (Code task 4710f43d)

Closed list for regenerating `tests/derived-impact-index.json` when a land rebase conflicts only in that file, and for the docs-skip receipt naming the matched graph. The first row's cold build uses `EstimatedMinutes` 15. Later test rows reuse that build. The output is `bin-ft5b/`. Positive controls stay pending. Mutation is waived (operator 2026-11-12). Windows is unobserved: `WindowsUnitPlatformAdmissionTests` is not in this list, and the generator child is `pwsh` on this Linux landing host.

The branch was fast-forwarded onto current `origin/master` before any task commit. The named base `4b2299e8b54103c847241ec9d0fe81b2ebb45573` is an ancestor of that master tip, so `check-evidence-diff` over that base includes those already-landed commits plus this task.

A clean rebase that leaves the index stale is unchanged. Verification still runs `DerivedImpactIndexTests.committed_index_matches_the_builder` when the land builds. A docs-only skip does not run that test. This slice does not regenerate on a clean rebase.

These stay a replay or a Code task. Each needs a Review-approved decision, so this land path does not rewrite them:

- `PinnedInputDigest` in `scripts/test-live-lane-run.ps1` is the nightly input census. A land that recomputes it would publish a pin the nightly gate has not accepted.
- `policyHash` in `tests/test-execution-policy.json` is the same nightly reseal. `NightlyPolicy.Read` refuses a stale hash; changing it here would move the gate.
- `LegacyExclusionDigest` keeps Linux-only rows out of the shared registry. Regenerating it on a land would admit or drop rows without that decision.
- The land-graph manifest (`server/Application/Services/LandVerificationBuildGraph.manifest.txt`) is what a docs-only land trusts. A regenerated digest could skip a build that should run. FT-9 owns that file. `scripts/audit-land-verification-graph.ps1 -Check` is warn-only for an inherited mismatch; this plan does not pass `-Update`.

Adversarial risks:

- A wrong regeneration would land a wrong index. The guard is the generator's own second run, which must print `derived-impact-index unchanged`, then one commit whose tree differs only in `tests/derived-impact-index.json`. The witness compares that blob with `DerivedImpactIndexBuilder.Build` on the merged tree.
- A path that resolves any other conflict would silently drop work. The guard is `IsOnlyIndex`: exactly one unmerged path, and it is the index. A later commit that conflicts anywhere else aborts the rebase and returns today's `rebase_conflict` with those paths and no `index-regen-failed` detail. The success witness also keeps a non-conflicting `notes.md` edit from the same commit. A candidate with merge commits stays `merge_branch_needs_merge_role`.

The production regenerator holds one `land-index-regen` build slot around `dotnet build` of `scripts/regenerate-derived-impact-index/Antiphon.DerivedImpactIndex.csproj` (`-p:UseAppHost=false`, no alternate output) and at most two `scripts/regenerate-derived-impact-index.ps1 -NoBuild` runs. A missing slot, timeout, unleased hold, or a still-changed second run refuses with `index-regen-failed:<why>` on the existing `rebase_conflict` / NeedsResolution path. The log line is `generated_artifact regenerated=<true|false> ms=<n>`.
