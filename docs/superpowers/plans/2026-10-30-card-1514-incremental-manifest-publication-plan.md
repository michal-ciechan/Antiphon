With roughly fixed row sizes and r[k], B[k] grows linearly in k and total publication is quadratic. No repeated hashing of previous TRX is in this call. ## Candidate decision (completed)

- D-4: Use immutable, atomic per-publication journal records and materialize the legacy `groups-executed.json` once at finalization or on an explicit snapshot request. This removes historical-row work from each chunk while retaining recoverable evidence and exact final serialization. An ordinary write must touch only the current TRX/result plus constant-size journal metadata.
- D-5: A single JSONL append is rejected for this slice: an append is not a portable transactional record boundary; a kill can leave a partial tail, and concurrent/read recovery needs a framing/commit protocol. One temp-file-to-final-name rename per record gives the needed process-kill commit boundary with the existing filesystem pattern.
- D-6: Faster serialization alone is rejected as the primary fix: it may improve the coefficient but leaves whole-prefix parse/write work quadratic. Incremental hashing is rejected because old evidence is not rehashed here. In-memory-only caching/end-only publication is rejected because a killed harness loses completed evidence.
- D-7: Keep publication diagnostic and preserve the existing verdict/failure-marker contract. A journal or projection error must never manufacture success, conceal missing evidence, modify release custody, or overwrite a valid old snapshot with a falsely complete view. No new release authority is derived from timing files.
- D-8: Do not change tests.log stamping, heartbeat thresholds, watchdogs, process owner, exclusions, timing quality joins, receipt schema or policy hash as part of this fix. The known final-summary cost is not moved into each chunk.

## Publication and recovery protocol

Keep this inside `scripts/lib/test-phase-evidence.ps1`, with production lifecycle calls in `scripts/lib/nightly-tests-impl.ps1`. No new service, database, package, project, global cache or qualification mode.

1. **Initialize once per invocation/timing root.** Open a run-scoped writer context with an exclusive OS file handle; another writer refuses, never steals a lease by PID/mtime. Release it in finally; process death releases the handle. Bind the context to canonical root, journal generation, run/attempt and the supplied source identity; do not reuse it across roots or invocation identities. Existing raw TRX remains the evidence authority. Fresh roots need no prefix scan. On a supported restart, scan/validate committed records once to find the next sequence; this O(prefix) recovery is outside steady-state per-chunk publication and is separately measured. No per-chunk directory enumeration, preceding-file hash, or cumulative-size cache reload.
2. **Legacy seed.** If only a v1 cumulative/single-chunk document exists, retain it unchanged and normalize it once into an immutable seed in `groups-executed.journal/`; atomically publish versioned journal metadata only after the seed is complete. Seed and metadata bind each other's digest/generation. Interrupted initialization leaves the legacy file usable; uncommitted temp files confer no completion. A present but invalid committed journal must not silently fall back to the older JSON. No migration of a sealed historical attempt in place: native replay uses scratch copies.
3. **Commit one result.** Preserve current TRX parsing/hash, `ConvertTo-TestPhaseExecutedChunk` fields and S1's `Write-TestPhaseOwnerObservation`. Serialize only the new normalized row into a versioned envelope containing generation and monotonically increasing sequence. Use fixed numeric filenames, not suite/chunk strings as paths. Write UTF-8 without BOM to a unique sibling temp with exclusive create, flush/close it, and rename without overwrite to its final record name. Returning success means the final record is readable. A conflicting final sequence refuses. Flush(true) is required where available, but this contract promises process-kill recovery, not power-loss durability of directory metadata. Metadata is immutable; the in-memory next sequence changes only after successful rename. A publication exception invalidates the writer context until recovery rather than allowing a gap or silently continuing with stale sequence state.
4. **Read a committed prefix.** The read accessor takes a directory snapshot of final record names, sorts by sequence, and validates a contiguous prefix and generation. It ignores only temp/uncommitted names; malformed committed JSON, gaps, duplicate sequence, digest/identity mismatch, unsupported path or read failure are explicit incomplete/refusal states. Existing path-identity/no-follow rules apply to root, seed, records and projection; no traversal or symlink fallback. Readers may see a valid earlier prefix while a new rename occurs, never a half-record. They return the observed last sequence/quality separately from the v1 projection so a live prefix is not labelled terminal. Restart replays all committed records exactly once and does not skip tests or authorize release reuse.
5. **Linear reduction and exact compatibility.** Seed plus records reduce in one pass using an indexed ordered set. Match replacements by `(suite, chunk)` with the existing PowerShell comparison semantics; remove the old entry and append the new one, retaining cross-suite homonyms. Attempt is deliberately NOT added to that replacement key. Preserve the old header rules (first nonblank run/suite and retained attempt), nullable verdict fields, array shapes, field order, UTF-8 escaping and `manufacturedPassed=false`. Normalize legacy defaults once; never replay the old whole-prefix writer for every record. The existing serializer writes the resulting v1 document once. Equal controlled inputs must produce exactly the old bytes, including one-element/empty arrays, Unicode/control escaping and legacy defaults.
6. **Finalization and explicit reads.** The qualification finalization path flushes/projects after success, failed chunk, timeout and caught orchestration error, before final timing summary/receipt composition, even when no planned manifest exists. An abrupt kill may leave no fresh projection; restart or explicit recovery reconstructs it from the journal. `ConvertTo-TestPhaseSummaryRows` uses the accessor when a journal exists and supports legacy-only input; live `summarize-test-phases.ps1` can summarize a stable prefix without rewriting the projection or taking writer ownership. `Complete-TestPhaseLaunch`, whose explicit contract asks for a full snapshot/summary, materializes before returning, preserving its existing callers. It is NOT introduced into the qualification per-chunk loop. Projection failure leaves the previous valid file and journal intact plus the existing diagnostic failure marker; it does not erase or reinterpret the actual test verdict. A partial journal cannot produce a terminal-complete diagnostic claim.

Do not garbage-collect committed records in this slice. Disk growth is O(total result bytes); the compatibility snapshot duplicates that payload once. Orphan temp files stay diagnostic residue until explicit owned cleanup. Resume/recovery tests must launch a new process, not reuse an in-memory context. Killing between TRX creation and journal commit leaves that chunk uncommitted; recovery may report it incomplete or rerun it under existing run custody, never infer pass from a stale sibling. An acknowledged journal commit before a crash is recoverable even if flat projection/final summary never ran.
