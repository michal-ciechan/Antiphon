## Candidate decision

- D-4: Use immutable, atomic per-publication journal records and materialize the legacy `groups-executed.json` once at finalization or on an explicit snapshot request. This removes historical-row work from each chunk while retaining recoverable evidence and exact final serialization. An ordinary write must touch only the current TRX/result plus constant-size journal metadata.
- D-5: A single JSONL append is rejected for this slice: an append is not a portable transactional record boundary; a kill can leave a partial tail, and concurrent/read recovery needs a framing/commit protocol. One temp-file-to-final-name rename per record gives the needed process-kill commit boundary with the existing filesystem pattern.
- D-6: Faster serialization alone is rejected as the primary fix: it may improve the coefficient but leaves whole-prefix parse/write work quadratic. Incremental hashing is rejected because old evidence is not rehashed here. In-memory-only caching/end-only publication is rejected because a killed harness loses completed evidence.
- D-7: Keep publication diagnostic and preserve the existing verdict/failure-marker contract. A journal or projection error must never manufacture success, conceal missing evidence, modify release custody, or overwrite a valid old snapshot with a falsely complete view. No new release authority is derived from timing files.
- D-8: Do not change tests.log stamping, heartbeat thresholds, watchdogs, process owner, exclusions, timing quality joins, receipt schema or policy hash as part of this fix. The known final-summary cost is not moved into each chunk.

## Publication and recovery protocol

Keep this inside `scripts/lib/test-phase-evidence.ps1`, with production lifecycle calls in `scripts/lib/nightly-tests-impl.ps1`. No new service, database, package, project, global cache or qualification mode.

1. **Initialize once per invocation/timing root under D-14 below.** Open a run-scoped writer context with an exclusive OS file handle; another writer refuses, never steals a lease by PID/mtime. Release it in finally; process death releases the handle. Bind the context to canonical root, journal generation, run/attempt and the supplied source identity; do not reuse it across roots or invocation identities. Existing raw TRX remains the evidence authority. Fresh roots need no prefix scan. On a supported restart, scan/validate committed records once to find the next sequence; this O(prefix) recovery is outside steady-state per-chunk publication and is separately measured. No per-chunk directory enumeration, preceding-file hash, or cumulative-size cache reload.
2. **Legacy seed.** If only a v1 cumulative/single-chunk document exists, retain it unchanged and normalize it once into an immutable seed in `groups-executed.journal/`; atomically publish versioned journal metadata only after the seed is complete. Immutable generation metadata binds the seed digest and parent generation/terminal state; the seed records its generation identity. Interrupted initialization leaves the legacy file usable; uncommitted temp files confer no completion. A present but invalid committed journal must not silently fall back to the older JSON. Never mutate a predecessor generation or sealed historical release evidence. A new authorized invocation may reuse a diagnostic timing root by creating a successor under D-14; native replay uses scratch copies.
3. **Commit one result.** Preserve current TRX parsing/hash, `ConvertTo-TestPhaseExecutedChunk` fields and S1's `Write-TestPhaseOwnerObservation`. Serialize only the new normalized row into a versioned envelope containing generation and monotonically increasing sequence. Use fixed numeric filenames, not suite/chunk strings as paths. Write UTF-8 without BOM to a unique sibling temp with exclusive create, flush/close it, and rename without overwrite to its final record name. Returning success means the final record is readable. A conflicting final sequence refuses. Flush(true) is required where available, but this contract promises process-kill recovery, not power-loss durability of directory metadata. Metadata is immutable; the in-memory next sequence changes only after successful rename. A publication exception invalidates the writer context until recovery rather than allowing a gap or silently continuing with stale sequence state.
4. **Read a committed prefix.** The read accessor takes a directory snapshot of final record names, sorts by sequence, and validates a contiguous prefix and generation. It ignores only temp/uncommitted names; malformed committed JSON, gaps, duplicate sequence, digest/identity mismatch, unsupported path or read failure are explicit incomplete/refusal states. Existing path-identity/no-follow rules apply to root, seed, records and projection; no traversal or symlink fallback. Readers may see a valid earlier prefix while a new rename occurs, never a half-record. They return the observed last sequence/quality separately from the v1 projection so a live prefix is not labelled terminal. Restart replays all committed records exactly once and does not skip tests or authorize release reuse.
5. **Linear reduction under D-15 compatibility.** Seed plus records reduce in one pass using an indexed ordered set. Match replacements by `(suite, chunk)` with the existing PowerShell comparison semantics; remove the old entry and append the new one, retaining cross-suite homonyms. Attempt is deliberately NOT added to that replacement key. Preserve the old header rules (first nonblank run/suite and retained attempt), nullable verdict fields, array shapes, field order, UTF-8 escaping and `manufacturedPassed=false`. Normalize legacy defaults once; never replay the old whole-prefix writer for every record. The existing serializer writes the resulting v1 document once. Use the fresh/prior transition and runtime-specific equivalence below; an unconditional ConvertFrom-Json of every row is incorrect.
6. **Finalization and explicit reads.** The qualification finalization path flushes/projects once for each terminal outcome category (success, failed run, terminal timeout or caught orchestration error), before final timing summary/receipt composition, even when no planned manifest exists. An abrupt kill may leave no fresh projection; restart or explicit recovery reconstructs it from the journal. `ConvertTo-TestPhaseSummaryRows` uses the accessor when a journal exists and supports legacy-only input; live `summarize-test-phases.ps1` can summarize a stable prefix without rewriting the projection or taking writer ownership. `Complete-TestPhaseLaunch`, whose explicit contract asks for a full snapshot/summary, materializes before returning, preserving its existing callers. It is NOT introduced into the qualification per-chunk loop. Projection failure leaves the previous valid file and journal intact plus the existing diagnostic failure marker; it does not erase or reinterpret the actual test verdict. A partial journal cannot produce a terminal-complete diagnostic claim.

Only the qualification's terminal finalizer writes an atomic constant-size seal binding generation, last committed sequence, projection digest and actual terminal outcome. Explicit live snapshots do not seal the run. A sealed generation is read-only; a later authorized invocation creates a new generation, even for the same run/attempt strings. The old seal remains intact and applies only to its generation. Existing release-attempt custody still controls whether execution itself is admitted. A kill before seal publication leaves recoverable records with terminal state unknown. This new journal terminal metadata is separate from the legacy timing-summary `complete` field (join quality), whose semantics stay unchanged. Test failure or partial coverage is retained in the seal; a seal is never release authority.

### D-14: generation and invocation contract

A generation is one journal history with immutable metadata/seed, numbered records and an optional terminal seal. The directory layout is `groups-executed.journal/<opaque-generation>/`; an atomically replaced `current.json` binds canonical timing-root identity, generation and metadata digest. Numeric record names are local to that generation. The root's exclusive writer handle serializes initialization, pointer replacement, writing and projection across every generation; a pointer is not a lease. Readers pin one pointer value and retain access to its immutable predecessor directory if it changes. No old directories are deleted.

| State on opening | Required action |
|---|---|
| No committed journal; no legacy projection | Create a generation once before the invocation's first chunk; sequence starts at 1. |
| Legacy projection only | Copy the exact v1 bytes as the immutable seed, bind digest, then publish metadata/current pointer. Do not reinterpret strings merely by copying. |
| Unsealed generation, same canonical root/run/attempt/source binding, owner absent | Validate once and resume that generation at its committed boundary. This is restart recovery; process ID is never the invocation identity. |
| Sealed generation, even with the same run/attempt/source strings | Create a successor with a fresh opaque ID and a seed of the validated predecessor reduction, retaining its first-header and merge semantics. A second invocation must be able to publish. |
| Unsealed generation with different run, attempt or source identity | Create a successor after validating the old prefix; seed its rows, carry its unresolved gaps/unknown terminal state as provenance, and never manufacture a predecessor seal. This permits a legitimate new attempt while exposing interrupted evidence. |
| Invalid committed state or another owner holds the root | Refuse diagnostic initialization with a reason and failure marker; retain evidence and test verdict. Never adopt an old flat snapshot as a substitute. |

Finish seed and metadata in the new directory before atomic pointer replacement. A kill before that commit leaves the old generation authoritative; a kill afterwards leaves the new empty/seeded generation recoverable. Reconstruct from the predecessor journal if its flat projection is absent/stale; only a digest-bound current projection can be used as an optimization. Read and normalize once at this boundary, outside the steady-state budget. A successor seed carries the exact predecessor v1 representation, last successful publication provenance and diagnostic gaps, so the equivalence transition below occurs only when the next successful chunk arrives. Generation IDs never enter v1 output, and attempt/source binding never enters the legacy replacement key.

The qualification loop owns one explicit context for its whole invocation (all suites). Direct `Write-TestPhaseExecutedManifest` callers without a context use a bounded one-shot context, commit and project before returning, then release ownership without a seal. `Complete-TestPhaseLaunch` shares that context and requests its explicit snapshot/summary once. These compatibility paths may cost O(prefix) per call; the qualification loop must always pass its persistent context, and V-1/V-2 measure that path. A later one-shot call resumes an unsealed matching generation or creates the specified successor. It cannot borrow or terminate another live writer. Normal summary/recovery never creates a successor or seals a generation. A stale context, including one from the predecessor generation, refuses after release/pointer change.

Rejected: refusing a sealed root for every later chunk loses evidence that the old writer merged; silently unsealing changes historical terminal evidence; using attempt as the replacement key changes existing row order. New generations preserve both immutable history and the old merge behavior. Diagnostic seed inheritance does not authorize release reuse or skip any tests.

### D-15: exact equivalence and parse transitions

| Artifact/comparison | Required rule |
|---|---|
| Frozen authority, execution plan, ledger and receipt | Identical UTF-8 bytes/digests for controlled identical source/IDs/clock/measurements and original TRX; diagnostic publication supplies no authority input. Real runs with different timing/source are not compared byte-for-byte. |
| v1 groups-executed.json, candidate versus pinned old writer on the same pwsh 7 runtime/culture | Whole-file byte equality: property and chunk order, escaping, header strings, all row fields including hostWallSeconds, exact null/bool/int/array shapes, outcome order and values. Exclude injected publication gaps from this legacy byte oracle; the old writer has no gap artifact. |
| PS5.1 projection | Parse-compatible, tested on actual Windows PowerShell 5.1 against that edition's pinned old writer. Exact property order/schema, row order, strings, UID/outcome multiset, booleans/nulls/integers and array shapes. Only finite hostWallSeconds is numeric-semantic: absolute error <= 1e-14 * max(1, abs(reference)); differences in decimal spelling/last double digits are permitted. No blanket byte equality between .NET Framework and pwsh 7. |
| Journal metadata, progress, gaps and seal | New diagnostic schema with no legacy byte counterpart. Validate version, identity, sequences/digests, gaps and terminal state literally; never strip these to claim full-run completeness. |

The old writer parses the previous JSON **before** matching replacements. All retained earlier rows and the header have therefore made at least one production `ConvertFrom-Json` round trip; the last successfully published row is fresh. The reducer must model that transition without replaying cumulative serialization. Keep each envelope's original serialized row as an opaque `rowJson` string (not an implicitly parsed nested object), with the current input's exact strings available losslessly. On reduction, settle the previous fresh row once when a subsequent successful chunk is encountered: parse with the production typing and normalize with `ConvertTo-TestPhaseExecutedChunk -Item`. Index its settled suite/chunk strings using the existing case-insensitive PowerShell equality. Compare the incoming **fresh** suite/chunk to those settled keys, remove a match, and append the new fresh row. A date-shaped chunk may intentionally cease to match its earlier ISO input after parsing; the old oracle, not a proposed cleaner identity rule, decides this case. Attempt never joins the key.

Apply the same one-time transition to the header, retaining its first nonblank run/suite and existing attempt; while a header remains blank, a later successful input may supply the old fallback values. Seed bytes are the already-published representation: parse them once for the first subsequent successful publication, not just because a reader requests a snapshot. With no new successful row, repeated snapshots/recovery preserve the seed bytes. Failed commits/gap records do not age the last successful row or header. The final fresh row is emitted from its original serialized representation, without accidental date conversion on reading the envelope. Keep metadata parsing separate from v1 payload parsing. A summary accessor may apply its legacy reader typing, but must not mutate stored projection state.

For the supported scalar schema, settlement reaches a fixed point under the same runtime/culture (date-shaped strings become the legacy display string, doubles retain their parsed numeric value). V-3 must demonstrate idempotence on its date/numeric edge corpus. If a counterexample appears, stop for plan revision; never assume it away or introduce per-chunk prefix work. Record writer/runtime/culture provenance; the exact byte guarantee is for homogeneous runtime/culture sequences. A cross-edition recovery/read must preserve stored strings/order/UIDs and satisfy the numeric-semantic bound, reporting its runtime, without claiming a same-runtime byte receipt. It grants no qualification credit by itself.

The round-2 read-only probe on pwsh 7.5.4/invariant culture confirmed that `2026-10-30T03:02:00Z` parses to System.DateTime and casts to `10/30/2026 03:02:00`; the production double serializer emits `0.3333333333333333`. Windows/PS5.1 was not available. Rejected: lossless-JSON assumptions, serializing every row as parsed (corrupts the final fresh row), or claiming cross-runtime exact doubles.

Recovery is concrete: add an explicit `-RecoverExecutedManifest` switch to `scripts/summarize-test-phases.ps1`. It acquires writer ownership with the same bounded refusal if a writer is live, validates/reduces committed records, and atomically regenerates the v1 projection before summarizing. It does not create a terminal seal, skip tests, mutate TRX, or infer a successful run. The default summary call remains a live prefix read. Exercise this command in V-5/V-10, including absence of planned metadata (projection recovery still runs, ordinary summary remains a no-op). Preserve its existing script-census disposition, adding this argument consumer to the existing wrapper inventory.

Do not garbage-collect committed records in this slice. Disk growth is O(total result bytes); the compatibility snapshot duplicates that payload once. Orphan temp files stay diagnostic residue until explicit owned cleanup. Resume/recovery tests must launch a new process, not reuse an in-memory context. Killing between TRX creation and journal commit leaves that chunk uncommitted; recovery may report it incomplete or rerun it under existing run custody, never infer pass from a stale sibling. An acknowledged journal commit before a crash is recoverable even if flat projection/final summary never ran.
