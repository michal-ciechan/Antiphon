## Publication and recovery protocol

Keep this inside `scripts/lib/test-phase-evidence.ps1`, with production lifecycle calls in `scripts/lib/nightly-tests-impl.ps1`. No new service, database, package, project, global cache or qualification mode.

1. **Initialize once per invocation/timing root under D-14 below.** Open a run-scoped writer context with an exclusive OS file handle; another writer refuses, never steals a lease by PID/mtime. Release it in finally; process death releases the handle. Bind the context to canonical root, journal generation, run/attempt and the supplied source identity (record explicit unknown when a legacy caller supplies none, never infer a qualifying SHA); do not reuse it across roots or invocation identities. Existing raw TRX remains the evidence authority. Fresh roots need no prefix scan. On a supported restart, scan/validate committed records once to find the next sequence; this O(prefix) recovery is outside steady-state per-chunk publication and is separately measured. No per-chunk directory enumeration, preceding-file hash, or cumulative-size cache reload.
2. **Legacy seed.** If only a valid v1 cumulative/single-chunk document exists, retain it unchanged and normalize it once into an immutable seed in `groups-executed.journal/`; atomically publish versioned journal metadata only after the seed is complete. Immutable generation metadata binds the seed digest and parent generation/terminal state; the seed records its generation identity. Interrupted initialization leaves the legacy file usable; uncommitted temp files confer no completion. Malformed legacy bytes are preserved as corrupt predecessor evidence with an empty seed and unresolved provenance under D-14. A present but invalid committed journal must not silently fall back to the older JSON. Never mutate a predecessor generation or sealed historical release evidence. A new authorized invocation may reuse a diagnostic timing root by creating a successor under D-14; native replay uses scratch copies.
3. **Commit one result.** Preserve current TRX parsing/hash, `ConvertTo-TestPhaseExecutedChunk` fields and S1's `Write-TestPhaseOwnerObservation`. Serialize only the new normalized row plus constant-size header state into a versioned envelope containing generation and monotonically increasing sequence. Under D-15 store both fresh and writer-settled forms and their keys before rename: one intentional production parse of the current row/header package, never of historical rows. Use fixed numeric filenames, not suite/chunk strings as paths. Write UTF-8 without BOM to a unique sibling temp with exclusive create, flush/close it, and rename without overwrite to its final record name. Returning success means the final record is readable. A conflicting final sequence refuses. Flush(true) is required where available, but this contract promises process-kill recovery, not power-loss durability of directory metadata. Metadata is immutable; the in-memory next sequence changes only after successful rename. A publication exception marks the context NeedsRecovery, retains the publication identity and invokes D-16; it never permanently disables later publication.
4. **Read a committed prefix.** The read accessor takes a directory snapshot of final record names, sorts by sequence, and validates a contiguous prefix and generation. It ignores only temp/uncommitted names; malformed committed JSON, missing physical sequence numbers, duplicate sequence, digest/identity mismatch, unsupported path or read failure are explicit incomplete/refusal states. Stop at the first invalid boundary; never accept later records across a hole. A safe validated prefix may be returned with unresolved corruption quality, never as complete. Existing path-identity/no-follow rules apply to root, seed, records and projection; no traversal or symlink fallback. Unsafe root/ownership refuses access; content corruption inside a safely bound root allows the successor rule below. Readers may see a valid earlier prefix while a new rename occurs, never a half-record. They return observed last sequence/quality separately from v1 output. Restart recovers only validated evidence and does not skip tests or authorize release reuse.
5. **Linear reduction under D-15 compatibility.** Seed plus records reduce in one pass using an indexed ordered multimap (retain all prior entries when settled keys collide; a replacement removes every matching entry, as the old loop does). Compare both components of `(suite, chunk)` with `StringComparer.InvariantCultureIgnoreCase`, matching the old string `-eq`; never use a PowerShell `@{}` default comparer, ordinal comparison or delimiter-concatenated keys. Remove matching entries and append the new one, retaining cross-suite homonyms. Attempt is deliberately NOT added to that replacement key. Preserve the old header rules (first nonblank run/suite and retained attempt), nullable verdict fields, array shapes, field order, UTF-8 escaping and `manufacturedPassed=false`. Normalize legacy defaults once; never replay the old whole-prefix writer for every record. Assemble the final v1 document once from the selected opaque row/header representations, retaining the existing serializer's layout. Reduction selects stored fresh/settled forms; it never invokes ConvertFrom-Json on their payload strings.
6. **Finalization and explicit reads.** The qualification finalization path flushes/projects once for each terminal outcome category (success, failed run, terminal timeout or caught orchestration error), before final timing summary/receipt composition, even when no planned manifest exists. An abrupt kill may leave no fresh projection; restart or explicit recovery reconstructs it from the journal. `ConvertTo-TestPhaseSummaryRows` uses the accessor when a journal exists and supports legacy-only input; live `summarize-test-phases.ps1` can summarize a stable prefix without rewriting the projection or taking writer ownership. `Complete-TestPhaseLaunch`, whose explicit contract asks for a full snapshot/summary, materializes before returning, preserving its existing callers. It is NOT introduced into the qualification per-chunk loop. Projection failure leaves the previous valid file and journal intact plus the existing diagnostic failure marker; it does not erase or reinterpret the actual test verdict. A partial journal cannot produce a terminal-complete diagnostic claim.

Only the qualification's terminal finalizer writes an atomic constant-size seal binding generation, last committed sequence, projection digest and actual terminal outcome. Explicit live snapshots do not seal the run. A sealed generation is read-only; a later authorized invocation creates a new generation, even for the same run/attempt strings. The old seal remains intact and applies only to its generation. Existing release-attempt custody still controls whether execution itself is admitted. A kill before seal publication leaves recoverable records with terminal state unknown. Journal terminal metadata is separate from timing-summary `complete`: the existing formula (no quality entries and no incomplete test rows) remains, but publication faults now add quality entries and therefore make `complete=false`. A true timing-summary flag is never a terminal seal or qualification verdict. Test failure/partial coverage is retained in the seal; a seal is never release authority.

### D-14: generation and invocation contract

A generation is one journal history with immutable metadata/seed, numbered records and an optional terminal seal. The directory layout is `groups-executed.journal/<opaque-generation>/`; an atomically replaced `current.json` binds canonical timing-root identity, generation and metadata digest. Numeric record names are local to that generation. The root's exclusive writer handle serializes initialization, pointer replacement, writing and projection across every generation; a pointer is not a lease. Readers pin one pointer value and retain access to its immutable predecessor directory if it changes. No old directories are deleted.

| State on opening | Required action |
|---|---|
| No committed journal; no legacy projection | Create a generation once before the invocation's first chunk; sequence starts at 1. |
| Valid legacy projection only | Copy the exact v1 bytes as the immutable seed, bind digest and writer-settled cache, then publish metadata/current pointer. Copying alone does not select the settled form. |
| Malformed old-format projection, safe root | Preserve exact malformed bytes/digest in predecessor evidence, use an empty seed, record `publication-corruption` unresolved, then publish the new generation. Do not try to salvage individual objects from malformed JSON. |
| Valid unsealed generation, same canonical root/run/attempt/source and writer-environment binding, owner absent | Validate once and resume that generation at its committed boundary. This is restart recovery; process ID is never the invocation identity. |
| Sealed generation, even with the same run/attempt/source strings | Create a successor with a fresh opaque ID and a seed of the validated predecessor reduction, retaining its first-header and merge semantics. A second invocation must be able to publish. |
| Unsealed generation with different run, attempt, source or writer environment | Create a successor after validating the old prefix; seed its rows, carry its unresolved gaps/unknown terminal state as provenance, and never manufacture a predecessor seal. This permits a legitimate new attempt while exposing interrupted evidence. |
| Torn/corrupt committed state in a safely bound root, including a continued RunId | Create a successor from the longest valid contiguous prefix, or empty if none is trustworthy. Preserve predecessor files/seal; record unresolved corruption identity, digest/reason and boundary. A second process must be able to journal its new chunks. Never append to or seal the corrupt predecessor. |
| Another owner holds the root, unsafe root identity or path | Refuse diagnostic initialization with a reason and failure marker; retain evidence and test verdict. Never steal ownership, follow unsafe links or import another root's rows. |

Finish seed and metadata in the new directory before atomic pointer replacement. A kill before that commit leaves the old generation authoritative; a kill afterwards leaves the new empty/seeded generation recoverable. Reconstruct from the predecessor journal if its flat projection is absent/stale; only a digest-bound current projection can be used as an optimization. Read and normalize once at this boundary, outside the steady-state budget. A successor seed carries the exact predecessor v1 representation, last successful publication provenance and diagnostic gaps, so the equivalence transition below occurs only when the next successful chunk arrives. Generation IDs never enter v1 output, and attempt/source binding never enters the legacy replacement key.

For corruption, the prefix includes a validated seed plus records 1..k before the first invalid/missing record; a torn last record loses only that record, and a missing middle record excludes its entire suffix. If seed/metadata/current-pointer binding itself is invalid, seed empty instead of searching other generations or importing the old flat snapshot. Record the predecessor generation where known, metadata/record digests where safely readable, first invalid sequence/reason, last valid boundary and `unresolved=true`; unavailable identity/digests are explicit unknowns, never invented values. Carry this provenance through every successor and into state and summary quality as `publication-corruption`, with `publicationComplete=false` and summary `complete=false`, even if all new chunks succeed. Do not erase it because a later same-key row replaces one. Preserve malformed legacy bytes in an immutable predecessor artifact before any later projection can replace the flat path; inability to preserve them refuses that transition. Unsafe individual records are never followed or copied through links. Successor creation is itself atomic under the root lock; IO failure leaves the predecessor current and reports incomplete, but a later authorized invocation can try again. No manual deletion or new permission is needed to recover diagnostic publication.

The qualification loop owns one explicit context for its whole invocation (all suites). Direct `Write-TestPhaseExecutedManifest` callers without a context use a bounded one-shot context, commit and project before returning, then release ownership without a seal. `Complete-TestPhaseLaunch` shares that context and requests its explicit snapshot/summary once. These compatibility paths may cost O(prefix) per call; the qualification loop must always pass its persistent context, and V-1/V-2 measure that path. A later one-shot call resumes an unsealed matching generation or creates the specified successor. It cannot borrow or terminate another live writer. Default read-only summary never creates a successor or seals a generation. Explicit `-RecoverExecutedManifest` may create a corruption successor under the same ownership/provenance rules; it never seals one. A stale context, including one from the predecessor generation, refuses after release/pointer change.

Rejected: refusing a sealed root for every later chunk loses evidence that the old writer merged; silently unsealing changes historical terminal evidence; using attempt as the replacement key changes existing row order. New generations preserve both immutable history and the old merge behavior. Diagnostic seed inheritance does not authorize release reuse or skip any tests.

### D-15: exact equivalence and parse transitions

| Artifact/comparison | Required rule |
|---|---|
| Frozen authority, execution plan, ledger and receipt | Identical UTF-8 bytes/digests for controlled identical source/IDs/clock/measurements and original TRX; diagnostic publication supplies no authority input. Real runs with different timing/source are not compared byte-for-byte. |

Recovery/reducer timezone may differ: stored settled payloads/keys are authoritative and must give identical bytes. Exclude injected publication gaps/corrupt predecessor loss from this legacy byte oracle; the old writer has no gap artifact. |
| PS5.1 projection | Parse-compatible, tested on actual Windows PowerShell 5.1 against that edition's pinned old writer. Exact property order/schema, row order, strings, UID/outcome multiset, booleans/nulls/integers and array shapes. Only finite hostWallSeconds is numeric-semantic: absolute error <= 1e-14 * max(1, abs(reference)); differences in decimal spelling/last double digits are permitted. No blanket byte equality between .NET Framework and pwsh 7. |
| Journal metadata, progress, gaps and seal | New diagnostic schema with no legacy byte counterpart. Validate version, identity, sequences/digests, gaps and terminal state literally; never strip these to claim full-run completeness. |

The old writer parses the previous JSON **before** matching replacements. All retained earlier rows and the header have therefore made at least one production `ConvertFrom-Json` round trip; the last successfully published row is fresh. Capture both representations **at commit time in the writer process**: original serialized `rowJson`, `settledRowJson` produced by one deliberate production parse and `ConvertTo-TestPhaseExecutedChunk -Item`, and fresh/settled suite and chunk keys. Store payloads as opaque JSON strings and keys as explicitly tagged base64 UTF-8 strings; decode keys without JSON date coercion. Use the same encoding for header strings. Parsing an envelope must never implicitly parse nested v1 payloads. Package current row and constant-size header state in one parse so the cost remains O(current outcomes), independent of prefix size. The settled form is prepared now but becomes effective only on the next successful chunk; gap records do not trigger that transition.

The reducer selects the previous row's **stored** settled form and keys, compares them with the incoming **fresh** keys using `StringComparer.InvariantCultureIgnoreCase` for each component, removes every matching entry and appends the new fresh row. Retain all collided seed entries until a matching replacement removes them. A date-shaped chunk may intentionally cease to match its earlier ISO input after parsing; the old oracle, not a proposed cleaner identity rule, decides this case. A soft hyphen or composed/decomposed accent can compare equal under `-eq` while a default PowerShell hashtable retains both; ordinal indexing is therefore rejected. Attempt never joins the key. Persist comparison/runtime provenance; an unsupported comparer/runtime combination fails diagnostic projection explicitly rather than substituting ordinal semantics.

Commit the same fresh/settled choice for the effective header, retaining its first nonblank run/suite and existing attempt; while a header remains blank, later successful input may supply the old fallback values. For a legacy/successor seed, preserve exact v1 bytes and prepare the seed's settled rows/keys/header once in the initializing writer process, durably bound in immutable seed metadata. Select that cache only upon the first subsequent successful chunk. A snapshot before any new successful row emits the exact seed bytes; it must not settle them in the reader. Failed commits/gap records do not age the last successful row or header. The final fresh row is emitted from its original serialized representation, without accidental date conversion on reading the envelope. Keep metadata parsing separate from v1 payload parsing. A summary accessor may apply its legacy reader typing, but must not mutate stored projection state.

For the supported scalar schema, settlement reaches a fixed point under a homogeneous writer runtime/culture/timezone (date-shaped strings become the legacy display string, doubles retain their parsed numeric value). V-3 demonstrates idempotence on its edge corpus. A counterexample refuses the affected diagnostic projection with explicit quality; never introduce per-chunk prefix work or silently claim equivalence. Record writer PowerShell edition/version, .NET/JSON runtime, culture/UI culture, timezone ID and effective offset, serializer/oracle source digest with each fixture output digest and generation/record provenance. Keep the exact-byte claim scoped to homogeneous writer environments, because the old writer itself changes bytes across writer timezones; recovery on another timezone is supported without resettlement. A new writer with a different environment creates a successor, records that boundary and any unresolved provenance, and makes no byte-equivalence claim for a mixed-writer legacy sequence. A cross-edition read preserves the stored opaque representations; any necessary numeric reserialization is subject to the PS5.1 numeric-semantic bound, with no cross-edition exact-byte receipt. It grants no qualification credit by itself.

The round-2 read-only probe on pwsh 7.5.4/invariant culture confirmed that `2026-10-30T03:02:00Z` parses to System.DateTime and casts to `10/30/2026 03:02:00`; the production double serializer emits `0.3333333333333333`. Windows/PS5.1 was not available. Rejected: lossless-JSON assumptions, serializing every row as parsed (corrupts the final fresh row), or claiming cross-runtime exact doubles.

### D-16: failure continuity and explicit gaps

One immutable envelope is either `chunk` (successful publication) or `gap` (a completed chunk whose diagnostic publication exhausted its retry). Both consume one contiguous sequence and carry a unique publication ID, root/generation binding and checksum. A gap carries exact run/attempt/suite/chunk, failure stage/reason and original TRX reference/digest when already known; it carries no outcomes, pass count or invented test verdict. A physical missing sequence is corruption; a valid gap envelope is explicit incomplete evidence that the reducer can continue past.

Each record gets at most **two commit attempts total** (initial plus one retry), with a provisional 2-second elapsed retry-admission budget; no new attempt starts after that deadline. Individual filesystem calls are measured, and the owned harness driver has the finite outer deadline below; synchronous OS IO is not falsely claimed to be cancellable at exactly two seconds. No unbounded retry/backoff loop. Before retry, probe the intended final name: a readable record with this publication ID and digest counts as committed (rename succeeded but acknowledgement failed), a different record is a conflict, and absence allows retry. Never overwrite a conflicting committed name. A transient sharing violation that clears on the second attempt preserves the chunk; an exhausted failure emits the existing marker and attempts a small gap envelope at that sequence under the same bounded policy. The context tracks whether the chunk or gap actually committed, never just whether an exception was thrown.

On the **next write after an unresolved IO failure**, still holding the root lock, perform at most one measured validation/rescan of the committed prefix for that outage, reconcile publication IDs/sequence, commit pending gap metadata first, then the current chunk. Do not replay a failed chunk as a successful observation implicitly. The next independent chunk must not be refused solely because the preceding chunk failed. Define an outage as unresolved publication IO without an acknowledged commit since its start; retain `rescanAttempted` and the last validated boundary in memory. A failed rescan spends that one allowance too: use only a previously validated boundary, never infer new committed evidence. Known malformed/mismatched committed content takes D-14's corruption successor path, not blind retry or stale-flat fallback.

If the directory remains unwritable, keep pending gap metadata in order, continue test execution/verdict handling, and at each later boundary/finalizer probe only the **next intended final name** under the bounded commit policy. Never rescan the prefix or rewalk the whole pending queue on every failed chunk. After an acknowledged commit clears the outage, drain pending gap entries once in order before new chunk records; a new IO failure begins a new episode. A fresh process gets its separately charged initialization scan, not a fictional in-memory recovery receipt. Never acknowledge pending gaps as durable. If the process dies first, restart can recover only the committed prefix; unknown work is not inferred from stale snapshots and no absent seal proves completion. Terminal finalization cannot seal publication-complete with pending gaps. Report refusal even when the best-effort marker cannot be written. V-11 holds an outage across at least 32 chunks, asserts at most one prefix-rescan attempt and O(N) next-name probes, restores IO, and verifies all durable gaps plus a later chunk; one scan per failed chunk is RED.

Finalization reduces all valid chunk/gap envelopes once. Keep v1 rows for successful publications only, preserving prior successful rows for a failed replacement as the old writer did. Report **every** gap (even one later superseded by the same suite/chunk) in `groups-executed.state.json`, with `publicationComplete=false`, identities/reasons, observed sequence, generation and v1 digest. Add `publication-gap` to the timing summary's actual `quality` list, which makes `complete=false`. D-14 unresolved provenance similarly adds `publication-corruption`. These flags never change the coverage ledger, receipt or qualification verdict. This companion is part of the projection result, not release authority. The terminal seal binds both projection and state digests; terminal-finished-with-gaps is distinct from publication-complete. All new readers validate the pair against the journal; if a crash interrupts the two atomic replacements, digest mismatch yields incomplete/recoverable, never a complete claim. A prior seal is immutable and cannot certify a newer projection.

When executed-publication input exists, a missing companion contributes `publication-state-missing`; invalid schema, wrong generation/sequence/root, stale projection/state or a digest mismatch contributes `publication-state-mismatch`. Both enter `quality` and force `complete=false`, including a legacy-only v1 input with no state. Legacy-only rows/joins remain supported, but a lone `groups-executed.json` never proves publication completeness. No publication input at all keeps the pre-existing summary behavior. A valid live accessor may supply newer rows without mutating files, but it cannot silently clear missing/stale companion quality. Explicit projection/recovery can restore a consistent pair and remove the missing/mismatch condition on a later read; unresolved gaps/corruption remain. Do not derive release or test success from any of these diagnostic flags. Existing consumer tests retain their row/join assertions and explicitly adopt only the newly required publication-quality/complete expectations for legacy fixtures without state.

V-11 injects (a) one transient rename failure that succeeds on retry, (b) both chunk commit attempts failing so a gap is required, (c) gap publication also failing until the next chunk, and (d) rename success followed by acknowledgement failure. For a k=2 failure in five chunks, assert k+1..5 committed, exactly one gap in cases b/c, no duplicate chunk in d, unchanged verdict, marker and prior rows. In b/c assert state `publicationComplete=false`, summary `quality` contains `publication-gap` and summary `complete=false`; a fresh process reads the same durable result. Cases a/d add no spurious publication quality. Mutation that leaves the context invalid forever, drops the gap, aborts reduction at a valid gap or keeps summary `complete=true` despite it is RED. Windows V-15 adds real sharing/rename refusal and release; deterministic portable injection calls the real helper around the failed boundary, not a fake reducer.

Rejected: poisoning the writer for the rest of the run loses hundreds of later chunks; silently skipping a record makes a complete projection untrustworthy; indefinite retries can stall the qualification. Permanent IO loss cannot promise durable missing data and remains visibly incomplete.
