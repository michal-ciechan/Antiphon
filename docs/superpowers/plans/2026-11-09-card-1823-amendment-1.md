## Defect

`scripts/merge-nightly-seeds.ps1` marked an identity proven when a later seed was green and that seed's source contained a decision SHA, including when the last-failing run's source already contained the same SHA. A same-tip re-run and a later green on the older fix commit both cleared the identity. An incomplete later chunk on that same source became `fixed-pending-proof`.

## Rule

When `-Repo` is set, each decision SHA already contained in the last-failing run's `sourceSha` is ignored for `proven` and for `fixed-pending-proof`. Containment stays the existing check: `git merge-base --is-ancestor`, or a commit body line that is exactly `(cherry picked from commit <sha>)`. With no remaining SHA the identity stays `open` and the report sets `fixPresentAtFailure` true. `--Proven` remains the manual override. Proof requires the later green source to contain a decision SHA the last-failing source did not already contain. The report still lists every supplied decision SHA. Without `-Repo`, git proof stays off and only `--Proven` clears an identity.

## Advisories taken with this repair

A-1. The script comment help and the run stdout include this sentence: `A test skipped inside a completed chunk looks green; that is an accepted seed-schema limit.`

A-2. After the merged file is written, the script prints `digest=` plus `Get-NightlyHistoryDigest` of that file. That value is what `-PriorFailuresDigest` takes.
