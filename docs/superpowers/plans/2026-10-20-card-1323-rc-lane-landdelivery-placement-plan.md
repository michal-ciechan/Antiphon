## Decisions

- **D-1 — choose platform-scoped exclusions.** Add an optional scalar `platform: "windows" | "linux"`; omission retains an all-platform exclusion. Validate types/values and reason/owner before filtering. Add only three `platform: "linux"`, suite `e2e`, class exclusions owned by CARD-1323, explaining their Windows ConPTY/native FakeGrok requirement. Do not add skips or change the fixtures. This keeps one suite inventory and one profile identity.
- **D-2 — version the changed exclusion semantics as schema 4.** Older readers otherwise ignore the new field and globally exclude these classes. Admit v4 in all three readers (`nightly-policy.ps1`, `release-authority.ps1`, `test-selection.ps1`); keep supported historical schemas. Preserve v3's project/catalog rules for v4. Reuse the canonical hash algorithm. Start from master's JSON, append the rows, and recompute its hash; never replace it with the older RC policy.
- **D-3 — freeze release authority for Windows explicitly.** `ConvertFrom-ReleaseAuthorityPolicyBytes` must resolve exclusions with `-Platform windows` on both creation and validation, independent of the coordinator OS. Its resolved exclusion format and pinned blob/digest chain remain intact. The executor resolves its actual OS once. Linux RC execution is a **platform diagnostic**, with `coverageComplete=false`, `coverageScope=PlatformDiagnostic`, and a named `windows-rc-obligations-outstanding` reason even when every selected case passes. Propagate that scope/reason through summary and run state. The existing credit predicate rejects non-Full scope (`scripts/lib/release-gate.ps1:158`); false coverage also prevents green-file advancement. No cross-host receipt merger or Linux release qualification is introduced.
- **D-4 — reject the larger alternatives.** A new Linux RC profile needs a second inventory plus new profile admission, lane/state-root routing and credit semantics: the current run core explicitly branches on `rc` (`scripts/lib/nightly-run-impl.ps1:187`, `:194`), and credit uses a fixed profile set (`scripts/lib/release-gate.ps1:16`, `:114`). Merely adding its name risks treating it as master or giving it RC credit. Windows-only documentation alone is smaller but leaves the requested Linux diagnostic placement unresolved. Unconditional exclusions repeat CARD-1305's rejected repair.
- **D-5 — D-3 leftover: admit default full Aspire smoke only on Windows.** Refuse a non-Windows full/default invocation before Docker jobs, imports with side effects, network creation or HTTP. Keep `-ProbeListeningPorts` portable and retain explicit `-SimpleMode` behavior, which already avoids the desktop Postgres check. Document the distinction; do not create a fake desktop database on a runner or report skipped checks as healthy.
- **D-6 — D-5 leftover: install Chromium OS dependencies in the `session-testing` stage.** Use the Debian package set for the pinned Playwright driver's Chromium target, including glib and its other required libraries/fonts. Derive it from that version's bundled dependency manifest; do not use an unpinned `npx latest`. Keep browser download a matching-version prerequisite. This limits the change to the image that owns tests. Production activation remains a separately commissioned operator rollout after ordinary review and an approved release-line inclusion; a master-only land does not authorize deploying master.

These are implementation decisions, not unresolved defaults requiring a Decide stage. Neither this work nor its Code verification may invoke `publish-release.ps1` or `promote-release.ps1`, create/push/move/delete tags, run a whole lane, or claim release/readiness credit.

## Verification design

**V-1 / S1:** `C1323_PlatformPolicy` exercises production readers with real JSON files and a scratch Git policy blob, without publication calls. Before the fix, an explicit Windows resolution of a Linux-only exclusion still excludes its node (or schema 4 is refused): that is the red witness. Green checks exact required UID sets for synthetic 52/12/5 expanded rows, Linux exclusion with reason/owner, Windows retention, unclassified/sibling-method retention, all-platform legacy rows, malformed/unknown/null/array platform rejection, stale hash, and platform-only hash change. Prove v3 compatibility, v4 nine-suite/catalog preservation and selector admission. Frozen authority creation and validation must resolve Windows even when the diagnostic host is Linux; removing one of those required UIDs from an otherwise valid scratch plan/ledger must refuse. Call authority readers/validators directly, never a publisher. Synthetic UIDs prove selection mechanics, not execution of the real 69 tests.

**V-2 / S2:** `C1323_PlatformExecution` drives the production executor/run-core through bounded offline command seams. Record the exact launched class list and emitted summary/state. Linux omits only the three added classes, while Windows retains them; other exclusions keep their prior semantics. An unclassified OptIn case remains selected. An all-passing Linux fixture must still emit incomplete diagnostic scope/reason and leave candidate/master green files byte-identical. A Windows fixture preserves the existing Full behavior. Unknown host OS refuses before a build/test command. Before the fix, the Linux list contains the Windows classes and the all-passing result can still be Full: this is the red witness. Seams supply child results, not policy/census/credit decisions; all filesystem effects stay under the harness root.

**V-3 / S3:** `Linux_full_smoke_refuses_before_desktop_side_effects` invokes the real script on Linux with owned child-process sentinels for jobs, Docker and HTTP. Assert the stable desktop-platform refusal and zero sentinel calls. Baseline touches an external-command sentinel instead: a meaningful red without probing the live stack. The existing loopback listener test is the narrow regression control. Preserve nonzero refusal; no automatic retries.

**V-4 / S4:** `Chromium_launches_and_renders_local_content` creates Playwright, launches headless Chromium, sets a local HTML document, asserts its DOM text, and closes browser/processes. No app, provider, broker or external web request. Red must be a browser loader/dependency failure with the matching browser present in the baseline image; missing browser, build, fixture or slot failures are incomplete prerequisites. Green must run the identical method in the candidate image and report one passed, zero skipped. This demonstrates dependency repair only, not the historical 35-case lane or fleet activation.

Read-only placement observations were taken from **GET `/api/runner-defaults`** and **GET `/api/session-runners`** on 2026-10-20: defaults revision 2; eligible Windows and Linux capacity existed, while another Linux entry was draining/stale. This is not a reservation. Re-read before dispatch. CP-1..CP-4 use the portable script-contract lane (omit `-Platform` and `-Runner`); CP-5..CP-8 require the Linux lane (`-Platform Linux`, no host pin). The Windows branches in V-1/V-2 are offline policy inputs, not native Windows qualification.

Run only the commissioned row through the checkpoint tool (`run --plan docs/superpowers/plans/2026-10-20-card-1323-rc-lane-landdelivery-placement-plan.md --rows CP-n`), wait until its result is not 75, and retain its unedited CHECKPOINT lines, source SHA, counts and build provenance. Every driver takes the host build slot, including image prerequisites. Red rows intentionally return failure; expect exactly the described behavioral failure, then stop and implement the fix before running the green row. Green rows form one narrow filter per slice. No Unit/Integration/full assembly or RC/nightly lane runs. Generated receipts remain ignored; remove task-owned alternate outputs after completion.
