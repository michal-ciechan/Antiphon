Independently observe the exact management menu, persist its episode and recovery receipt, and surface it even when the transcript still says working. Automatically dismiss only after fresh idle evidence; a working-session modal requires operator intervention and remains visible in Attention.

The retained PTY contains the Remote Control / Disconnect / Show QR / Continue menu. The paint has **no wall-clock timestamp**. `RcReArmed` at 16:37:02Z and the 16:43:23Z policy-refresh relaunch are context, not proof that either specific operation opened the retained menu.

## Decisions

These are the design choices authorized by this brief's instruction to decide safe suppression/dismissal. No caller answer is needed to proceed to TestDesign.

**D-1 — Suppress an automatic arm whenever the current child is already armed.** Apply this both at scheduling and immediately before the write, on every launch mode. Positive current menu evidence also suppresses arming, but does not certify connection health. Explicit Unarmed means a readable current-child state file with no bridge ID; missing PID/file, probe exception, unknown generation or unavailable guarded transport means Unknown. Unknown withholds automatic RC input, records degradation and leaves the session available for its work. Keep the existing bounded startup probe window/setup budget; a fresh launch may use the same short window rather than paying the entire setup timeout.

Rejected: treating zero TCP connections or a read failure as permission to rearm; a resume-only check; lengthening sleeps to mask the race. The CLI can still arm between probe and submit: detection/dismissal remains an independent backstop, not a claim of atomicity with Claude's own bridge.

**D-2 — Automatic arming is identified maintenance, delivered at most once after an ambiguous write.** Keep WhenIdle scheduling for a positively unarmed established session, including requests scheduled while it is busy. Stamp a dedicated maintenance discriminator and the accepted generation on the queue row, with Supervision origin for health requests. Recheck generation, current bridge state, pending modal and fresh transcript idle under the existing per-session queue lock immediately before bytes. Startup uses the same RC policy/executor under launch ownership and the same delivery exclusion; it must not recursively enqueue or acquire a lock it already holds.

An automatic RC attempt uses the existing composer-evidence contract and **one submitting Enter**. It does not use the generic three-whole-submit boot retry or generic interrupted-message retyping. Persist `SubmissionStarted` before the first possible write. After a timeout/crash with possible bytes, reconcile bridge/menu evidence and retain `ArmUnconfirmed`; never infer that retry is safe from missing evidence. One unresolved/possibly written request blocks another automatic arm in that generation. A positively refused, zero-byte conditional write may be reconsidered at the next ordinary watch pass. `/rename` retains its own existing behavior and only runs after armed evidence plus a clear menu.

Use the same durable maintenance-row reservation for boot (System origin) and health (Supervision origin). Reserve/coalesce under the queue lock with a database uniqueness constraint for the active automatic arm of a generation, then execute through a helper whose caller already owns that lock. Health cannot execute while launch ownership is active or the session is Stopping; a Running status alone is insufficient because current launch code stamps Running before RC setup finishes. Preserve a terminal possibly-written result as a generation-level rearm veto even after the active-row slot closes.

Rejected: bare Ui-origin command rows, timing recovery from enqueue, classifying a local command as a delivered work prompt, or using a new general-purpose job subsystem. Request rows already provide ordering, persistence and queue ownership; RC-specific outcomes must stay distinct from `DeliveryVerdict.Delivered`.

**D-3 — A stale armed connection produces degradation, not an RC-only process restart.** Delete the armed/zero-connection rearm and `RcRestart` kill branches from health repair. Preserve the observation thresholds for connection warnings and healthy-reset behavior. Never-armed scheduling remains, subject to D-2. Keep old enum values and historical incidents readable; deprecate the RC restart-attempt setting rather than repurposing it. No change to operator Stop, genuine process-exit recovery, policy refresh, or other independently justified supervisor actions.

Reason: opening a known management dialog cannot repair a bridge merely because TCP inference reports zero, and monitoring is not the session's purpose. Rejected: automated Disconnect/reconnect, restarting to clear a modal, or routing the modal through a generic delivery-kill ladder.

**D-4 — Detect the exact modal regardless of working/idle and regardless of who opened it.** Run a passive rendered-screen sweep for live RC-capable sessions, including card sessions and non-AlwaysOn sessions. It must not depend on `PendingMenuCheck`, a prior health request, `RemoteControlEnabled`, queued-message origin, an idle output sequence, or the generic watchdog's age gate. Use the existing watch cadence (60 seconds by default) with bounded runner reads; observe at startup and before/after an automatic arm as well. RC connection-watch disablement must not silently disable modal observation; give the modal watch a separate enabled setting, default true. Global supervision shutdown still stops background work.

Strengthen the shared matcher using a coherent ordered block: Remote Control heading, Disconnect row, Show QR row, Continue choice and documented Esc footer. Whitespace/border/selected-row normalization is permitted; arbitrary prose containing the words, old scrollback, help text and partial paints are not active-menu proof. Keep a weaker `HasRemnant` result separate from actionable `IsPresent`: a partial remnant cannot authorize Esc or certify a clean composer. Use rendered grids, not substring matches against append-only ANSI history. Full-screen passive observations record first-observed time, never invented paint time.

Rejected: globally removing the generic watchdog's working gate, interpreting a spinner as progress, or matching any dialog heading. A legitimate long turn with queued input and no modal remains healthy under the existing generic detector.

**D-5 — Automatic Esc is narrowly idle-gated and has a receipt.** A live modal produces an immediate Warning episode (Critical when channel-bound), even with an in-flight fork or no queued input. Detection never waits three minutes. Attempt automatic dismissal only after acquiring the queue delivery lock, pulling the transcript with `CatchUpTranscriptAsync`, proving it bound/current and idle, and obtaining a fresh actionable modal snapshot from the same accepted generation. A matching generation/sequence conditional write sends exactly one Esc with `trackManualTurn: false`. Never Enter, navigation or a work-body replay. The runner rejects stale generation/sequence; output changes cause re-observation, not blind retries.

For working, unavailable transcript, stale/partial screen or unsupported conditional transport, record the reason and keep the episode open for the next passive observation. In particular, the recorded mid-fork CARD-0514 shape is **detected and surfaced, not automatically interrupted**. A fresh observation after a later TurnEnd may become eligible. If one Esc might have been sent, no second automatic Esc in that episode, including after server restart. Re-read after the existing 500ms settle, bounded by the existing 3-second dismissal budget; require two clear observations separated by a settle interval, the same generation, and no menu/remnant before recording verified dismissal. A read failure or deadline leaves `DismissUnverified`, not success. No disappearance claim from write acknowledgment alone.

Rejected: removing the working guard because the footer says Esc, assuming Esc is harmless during an active model turn, or clearing the episode's latch before checking. The existing idle-composer canary does not establish busy-turn Esc safety. Future busy dismissal would require a separately approved design and provider measurement.

**D-6 — Persist modal episodes separately from generic queue symptoms.** Add a small `RemoteControlModalEpisode` entity, with one open episode per `(SessionId, AcceptedStartedAt)` enforced by a unique filtered index. It contains an immutable episode ID, first/last observation UTC, child PID, before/after output sequence, transcript catch-up watermark/working observation, optional related maintenance queue ID, dismissal intent/sent/verified times and typed result, and resolution/time. Associate a maintenance request only when actually known; otherwise source is Unknown. No inference tying the September 13 paint to a specific request.

Commit detection and Esc intent before side effects. Persist/update the episode and emit linked `AgentIncident` receipts only on meaningful transitions, using `FailureReason` as a versioned episode reference, not free-form state parsing. Expose typed evidence in the existing incident/session detail path. Keep prompt bodies, full screens, bridge URLs, state-file contents and credentials out of these receipts. Unknown/failed post-observation is explicit. Open episode state is not lost when ordinary incident retention prunes history; Attention reads the durable episode without the recent-incidents `since` cutoff. Resolved episodes follow normal configured retention.

Modal clear and input delivery are **different outcomes**. Persist `DismissedVerified`, `ObservedClear` (no attributable automatic Esc) or `GenerationEnded` as appropriate. None means queued input was delivered. Record observed enqueue/drain/prompt sequence watermarks for diagnosis. A queue dequeue/remove or unrelated prompt may show movement, but cannot certify each of the three inputs. Existing per-message identity/completeness confirmation remains authoritative; no new synthetic `UserPrompt`, TurnEnd or successful task receipt.

**D-7 — Preserve queued work while a modal is known open.** Integrate an open-modal barrier under the queue lock before ordinary local commands, Now/WhenIdle delivery, boot work prompts, Enter retries, and failure cleanup can touch this generation. Catch up transcript and permit existing late confirmation first. Known open or dismissal-unverified episodes withhold additional automated bytes, publish a blocked reason, and do not consume ordinary delivery attempts, park as a delivery failure, or kill. The passive screen watch and operator raw terminal access remain available to clear it. Once a fresh observation proves clear, release the modal barrier and use existing late-confirm-before-redelivery rules. Do not automatically resend inputs held inside Claude's own queue; they have no new Antiphon queue identity to replay.

If RC setup merely fails without positive modal evidence, retain CARD-0056's best-effort launch/work behavior. If a modal is positively known and remains open, keep the process alive but explicitly defer the work prompt and skip rename, rather than reporting the TUI usable. An unrelated task's normal deadline may still report incomplete work; modal detection itself is not kill authority.

For the direct card-run boot path, persist the deferred original prompt once with its RunAttempt and accepted-generation identity before yielding launch ownership. Resume its delivery/first-output observation through that durable continuation after modal clearance; do not run the existing first-output timeout before any work was submitted, return a successful run, or lose the prompt in a local variable. Reuse the existing queue/launch continuation machinery and add the narrow missing linkage if necessary. A server restart while deferred must recover that same work identity exactly once. Interactive launch notes already routed through the queue keep their identities and simply wait at the barrier.

**D-8 — Respect generation identity at the runner input boundary.** Add generation-bearing snapshot metadata and a capability-advertised conditional maintenance-input operation carrying accepted generation and expected screen sequence. Resolve and write the same session object under the runner's existing launch gate, analogous to `KillGenerationAsync`; return Written, StaleObservation, GenerationMismatch, Missing/Exited, or Unsupported distinctly. A lost HTTP response is Unknown. All automatic RC command/body/Enter and Esc writes use the guarded path; each phase stops on mismatch. Do not extend the scope into rewriting ordinary human raw input.

Older runners may ignore additive input fields, so a field on the old request alone is insufficient. Advertise a distinct capability and route/contract; no fallback to `/input`. A compatible server with an older runner continues passive detection and records monitoring degradation while withholding automated RC. Preserve UTC microsecond-normalized `AcceptedStartedAt` equality, not runner `StartedAt`, wall-clock tolerances or PID identity alone.

An old-runner screen without generation metadata is explicitly `ObservationGenerationUnproven`: retain a diagnostic against the expected DB generation with the observed generation null, without claiming a current-generation match or authorizing Esc. A later compatible observation must establish identity afresh. On proven generation replacement, close the old episode as GenerationEnded; no old intent, barrier or successful receipt transfers to the replacement.
