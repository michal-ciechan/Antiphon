## Summary

S2 gives the runner kernel-attested proof that the process behind a session's pipe is the host it expects.
It adds two things, each behind a default-off flag:

1. **Owned rendezvous (Linux).** New sockets live in `<PtyHostDir>/sock`. That directory must be owned by
   the runner's euid, mode 0700, not a symlink, and reached through safe ancestors. Unsafe means fail
   closed, never a fallback to `/tmp`.
2. **Peer check (both platforms).** The client runs it after `connect` and **before the hello is written**:
   - Linux: the socket file's owner and type, then `SO_PEERCRED`.
   - Windows: a `CurrentUserOnly` client under Enforce, then `GetNamedPipeServerProcessId`.
   - The peer pid must equal the host pid we spawned (fresh launch) or `manifest.HostPid` at its recorded
     start (adoption).

   A refused adoption becomes a held pending row (`pty_host_peer_unproven`) with no kill, released by the
   S1 vanish sweep. Off is today's behaviour, byte for byte.

**What S2 leaves for S3:** the per-session key, `LaunchMessage.HelloKey`, the nonce and HMAC hello proof,
protocol v2 and the key store. S2 changes **no protocol message, no host code and no manifest schema**.

**S3 recommendation:** hold S3 until S2 has run under Enforce on server2. S3 still does not defend
against a same-uid agent child (overall §3.4).

## 2. Invariants (S2)

These are carried from the overall plan (I-1, I-2, I-4, I-7, I-8) and narrowed to S2, plus four new
compatibility invariants.

- **I-1 (S2 form).** Under `PtyHostPeerCheck=Enforce`, the client writes **nothing**, not even the hello, to
  a peer whose kernel-reported pid is not the expected host. On Linux the peer's uid must also equal the
  runner's euid. Unreadable credentials (getsockopt failure, pid 0, or `GetNamedPipeServerProcessId` false)
  are unproven, never accepted.
- **I-2 (S2 form).** A peer refusal never stops or signals `manifest.HostPid` and never deletes its manifest.
  The kill branch stays reachable only for (a) failures before any peer answered (connect timeout, as
  today) and (b) failures after the peer was proven to be the manifest host.
- **I-3.** A peer refusal is a held pending row (`pty_host_peer_unproven`) that the server raises as its
  pending incident. It is released by evidence only: the S1 vanish sweep once the host pid is dead at its
  start, a restart that proves the host, or an operator stop. There is no timer.
- **I-4.** Under `PtyHostSocketDirMode=Owned`, new non-custody sockets are created only in a directory that
  meets all of:
  - owned by the euid, mode exactly 0700, and not a symlink;
  - every ancestor is owned by the euid or root and is not group- or other-writable unless sticky;
  - the full socket path fits in 107 UTF-8 bytes.

  Any failure is `pty_host_socket_dir_unsafe` or `pty_host_socket_path_too_long`. The launch fails before a
  host is spawned. There is no `/tmp` fallback.
- **I-7.** Refusal and observe logs carry the session id and a fixed token only:
  `pty_host_peer_mismatch`, `pty_host_peer_mismatch (observe)`, `pty_host_socket_dir_unsafe`,
  `pty_host_socket_path_too_long` and `pty_host_legacy_socket_path`. They never carry a claimed pid, uid
  or path.
- **I-8.** A host launched before the flag change, on `/tmp/antiphon-pty-<id>`, keeps being adopted. Under
  Enforce it is adopted through the socket-file check and the peer check. It is never refused for being on
  the legacy path.
- **I-S2-a (flags off are inert).** With `PtyHostSocketDirMode=Legacy` and `PtyHostPeerCheck=Off` (the
  defaults), every observable is unchanged from `907edaebb`:
  - the pipe names and client `PipeOptions`;
  - the frame order;
  - the catch routing, kill path and log lines.

  No statx, getsockopt or `GetNamedPipeServerProcessId` call runs.
- **I-S2-b (Windows pipe name).** On Windows the pipe name is `antiphon-pty-<id:N>` in every mode.
  `PtyHostSocketDirMode` is ignored, with one startup information line.
- **I-S2-c (custody pipe name).** A launch with a `VerificationBinding` always uses
  `PtyHostProtocol.PipeNameFor(id)`, so `RunnerCustodyLedger.RecoverManifests`'s identity check still holds.
  The peer check still applies to custody launches and adoptions (I-1). A custody refusal keeps the custody
  failure path, which already never kills.
- **I-S2-d (no host or protocol change).** S2 touches no file under `src/Antiphon.PtyHost/` or
  `src/Antiphon.PtyHost.Protocol/`. Mixed host versions therefore cannot disagree.

## 3. Design

### 3.1 Settings (`SessionRunnerSettings.cs`)

| Setting | Type | Default | Meaning |
|---|---|---|---|
| `PtyHostSocketDirMode` | enum `PtyHostSocketDirMode { Legacy, Owned }` | `Legacy` | Owned puts new non-custody Linux sockets in the owned directory |
| `PtyHostSocketDir` | `string?` | null | Overrides `<ResolvedPtyHostDir>/sock` |
| `PtyHostPeerCheck` | enum `PtyHostPeerCheckMode { Off, Observe, Enforce }` | `Off` | The peer check |
| `ResolvedPtyHostSocketDir` | computed | `Path.GetFullPath(PtyHostSocketDir ?? Path.Combine(ResolvedPtyHostDir, "sock"))` | |

An unknown enum value fails options binding, so the runner refuses to start (fail closed).
`docker-compose*.yml` is **not** edited in S2 (rollout §6).

### 3.2 Rendezvous (new `src/Antiphon.SessionRunner/PtyHostRendezvous.cs`, internal)

- `string PipeNameFor(SessionRunnerSettings s, Guid id, bool custody, bool isWindows)`:
  - Windows, custody, or Legacy: `PtyHostProtocol.PipeNameFor(id)`;
  - otherwise: `ResolvedPtyHostSocketDir + "/" + id:N`.

  This is a pure function, so it is portable-testable on both lanes (V-18a).
- `SessionRunnerRuntime.StartAsync` decides the name **once**, before the pre-launch Grok manifest (`:736`
  writes it) and before `session.StartAsync`. Under Owned on Linux it first calls
  `PtyHostSocketDirectory.EnsureSafe(dir, euid, probe)`. A refusal throws `PtyHostSocketDirUnsafeException`
  (fixed code) before `LaunchDetachedAsync`, so no host is spawned and no `/tmp` socket is created.
- `RunnerSession.StartAsync` gains `string pipeName`. It passes `pipeName:` to `LaunchDetachedAsync`, which
  already emits `--pipe`, and connects to that same value. The host records it in its manifest as today.

### 3.3 Socket directory (new `src/Antiphon.PtyHost.Client/PtyHostSocketDirectory.cs`, public)

- `IUnixFileProbe` has two methods:
  - `UnixFileFacts? Lstat(string path)`, returning `{ Kind (Directory|Socket|Symlink|Other), Uid, Mode }`
    or null when absent;
  - `uint Euid()`.

  The default implementation copies `CheckpointNativeIo`'s `statx(AT_FDCWD=-100, path,
  AT_SYMLINK_NOFOLLOW=0x100, mask)` and `geteuid` declarations: the 256-byte explicit layout, Uid at
  offset 20, Mode at offset 28 (D-7 copy, about 40 lines).
- `EnsureSafe(path, probe)`:
  1. `Directory.CreateDirectory(path, UserRead|UserWrite|UserExecute)`.
  2. Lstat the path. A symlink, a non-directory, or `Uid != Euid` is unsafe.
  3. `(Mode & 0777) != 0700` with the owner equal to the euid: `File.SetUnixFileMode(path, 0700)`, then
     Lstat again. Still wrong is unsafe.
  4. Walk the ancestors up to `/`. Each must be a directory (`Lstat`; a symlinked ancestor is resolved
     through `Directory.ResolveLinkTarget(returnFinalTarget: true)` and the target is checked, D-S2-5) with
     `Uid ∈ {euid, 0}`, and `(Mode & 0022) == 0 || (Mode & 01000) != 0`.
  5. `UTF8(path) + 1 + 32 > 107` is `pty_host_socket_path_too_long`.
- `CheckSocketFile(path, probe)`: Lstat the path.
  - null: `Absent`, which keeps retrying.
  - `Kind == Socket && Uid == Euid`: `Ok`.
  - Otherwise: `Refused`.

### 3.4 Client peer check (`PtyHostClient.cs`)

- New public types:
  - `PtyHostPeerCredentials(int Pid, uint? Uid)`;
  - `PtyHostPeerCredentials.Read(SafePipeHandle)`: Linux `SO_PEERCRED`, Windows
    `GetNamedPipeServerProcessId` with a null Uid, otherwise null; never throws;
  - `PtyHostPeerRefusedException(string code) : UnauthorizedAccessException`;
  - `PtyHostConnectPolicy` with these members:
    - `bool CurrentUserOnly`;
    - `Func<string, SocketFileVerdict>? CheckSocketFile`;
    - `Func<SafePipeHandle, PtyHostPeerCredentials?> ReadPeer` (default `Read`);
    - `Func<PtyHostPeerCredentials?, bool> AcceptPeer`;
    - `bool Observe`;
    - `Action<string>? OnObserved`.
- `ConnectAsync(string pipeName, TimeSpan timeout, CancellationToken ct, PtyHostConnectPolicy? policy = null)`.
  A null policy is today's code path exactly (I-S2-a). With a policy, each attempt runs:
  1. Linux, when `CheckSocketFile` is set: `Absent` falls through to `Connect`, which fails into the
     existing retry. `Refused` under Enforce throws `PtyHostPeerRefusedException("pty_host_peer_mismatch")`,
     which is not retried. Under Observe it calls `OnObserved` once per `ConnectAsync`, then continues.
  2. `new NamedPipeClientStream(".", name, InOut, Asynchronous | (CurrentUserOnly ? PipeOptions.CurrentUserOnly : 0))`,
     then `Connect`. On Windows, a `CurrentUserOnly` owner mismatch (`UnauthorizedAccessException`) is
     rethrown as `PtyHostPeerRefusedException("pty_host_peer_mismatch")`.
  3. `ReadPeer(pipe.SafePipeHandle)` and `AcceptPeer`. A false result under Enforce disposes the pipe and
     throws the refusal before **any** write. Under Observe it calls `OnObserved` and continues.
  4. Then the existing hello write and read.

### 3.5 Runtime wiring (`SessionRunnerRuntime.cs`)

- **Policy factory** (`RunnerSession.PeerPolicy(int expectedPid, DateTime? expectedStart, IProcessLivenessProbe probe)`).
  It returns null under Off. Otherwise it sets:
  - `CurrentUserOnly = IsWindows && Enforce`;
  - `CheckSocketFile = IsLinux ? path => PtyHostSocketDirectory.CheckSocketFile(path, FileProbe) : null`;
  - `ReadPeer = PeerReaderOverride.Value ?? PtyHostPeerCredentials.Read`;
  - `AcceptPeer = c => c is { Pid: > 0 } && c.Pid == expectedPid
    && (!IsLinux || c.Uid == FileProbe.Euid())
    && (expectedStart is null || probe.IsAlive(c.Pid, expectedStart.Value))`;
  - `Observe = mode == Observe`;
  - `OnObserved = _ => log "pty_host_peer_mismatch (observe): session {SessionId}"`.

  `PeerReaderOverride` and `FileProbeOverride` are `internal static AsyncLocal<…>` test seams on the
  `HerdrPeerIdentity` pattern.
- **Fresh launch.** `expectedPid = _hostPid` and `expectedStart = _hostStartTimeUtc`, both captured before
  connect. A refusal is caught by the existing launch catch, so `TearDownFailedLaunch` kills **our**
  spawned host (proven by spawn, I-2). `LaunchMessage` is never sent.
- **Adoption.** `expectedPid = manifest.HostPid` and `expectedStart = manifest.HostStartTimeUtc`, using the
  sweep's probe, which is now passed into `AdoptAsync`. When the mode is Owned, the path is not under
  `ResolvedPtyHostSocketDir` and the platform is Linux, log `pty_host_legacy_socket_path` once per
  session.
- **Sweep catch.** A new arm `catch (PtyHostPeerRefusedException)` sits beside S1's identity arm and ahead
  of the generic arm. For a non-custody manifest it disposes without Shutdown and registers
  `CreatePendingConflict(manifest, …, "pty_host_peer_unproven")`. It keeps the manifest, does not kill and
  continues. A custody manifest keeps the custody path (I-S2-c). The generic arm is unchanged: it is reached
  only by pre-peer failures or by a proven peer under Enforce, and by anything under Off or Observe.
- **Release.** `ReleaseUnprovenHostIfDead` accepts both unproven reasons (GT-S2-6).
- **Adoption-sweep diagnostic.** Under Owned on Linux, the sweep runs `EnsureSafe` once and only logs the
  fixed token on failure. It never gates adoption, because adoption proof is per path (socket file plus
  peer, D-S2-4).

### 3.6 Windows vs Linux

| Aspect | Linux | Windows |
|---|---|---|
| Rendezvous | `/tmp/antiphon-pty-<id>` (Legacy) or `<sock>/<id>` (Owned) | `antiphon-pty-<id>` always (I-S2-b) |
| Pre-connect file check | statx: socket type and owner == euid | none (the named-pipe namespace has no file) |
| Owner proof | statx owner plus `SO_PEERCRED` uid == euid | `PipeOptions.CurrentUserOnly` (owner SID), Enforce only |
| Pid proof | `SO_PEERCRED` pid (the listener at `listen(2)`) | `GetNamedPipeServerProcessId` |
| Start-time proof | `probe.IsAlive(pid, start)` (`/proc` start ticks) | `probe.IsAlive(pid, start)` (process StartTime) |
| Observe | all checks, log only | pid check, log only; **no** `CurrentUserOnly` (GT-S2-12) |
| Off | today's code | today's code: `PipeOptions.Asynchronous`, the same name |
| Witness lane | linux-native (CP-4) plus portable on server2 (CP-5, CP-6) | windows-native (CP-7, CP-8, CP-19) |
| Cross-account witness | not possible (one uid on server2; the probe seam stands in) | not possible (one account; R-3, review item) |

### 3.7 Compatibility with the live Windows qualification

- **rc does not carry S2.** `rc/2026-11-01` lacks CARD-1636 and S1 (overall plan header), so the running
  Windows qualification executes none of this code. S2 is master-first. An rc port needs CARD-1636 and S1
  ported first.
- **Off is inert on Windows.** The defaults leave the Windows client's `PipeOptions` and pipe name
  byte-identical (I-S2-a, I-S2-b), and the desktop runner's configuration sets neither flag. Even after a
  future rc port, the qualification's named-pipe path changes only when an operator sets
  `PtyHostPeerCheck`. G-63 and PC-63 pin this.
- **The Windows checkpoint rows cannot collide with the qualification.** They run on the desktop under the
  build-slot gate, build to the checkpoint tool's own output, and create in-process runtimes whose pipes are
  per-test session GUIDs. They never touch the production runner (17204) or the AppHost. If the
  qualification holds the slot, the row waits. Exit 4 is reported as not run, never retried unleased.
- **The new tests are green on Windows before they join a Windows roster.** The new portable class
  joins the session-runner suite, so it enters the Windows qualification roster only through a later rc
  port. CP-7 proves it green on Windows first. The Linux-only class carries a `platform: windows` policy
  row, so it is excluded from Windows suites.

## 6. Flags and rollout

1. Land with Legacy/Off (I-S2-a). Nothing changes on any host.
2. server2 precheck (orchestrator): `stat -c '%U %a' / /tmp /tmp/antiphon-pty-hosts` inside the runner
   container. All must pass the ancestor rule (they do today, GT-S2-9).
3. server2 canary: `SessionRunner__PtyHostSocketDirMode=Owned` and `SessionRunner__PtyHostPeerCheck=Observe`
   for 48 h. Grep the runner log for `pty_host_peer_mismatch (observe)`, `pty_host_socket_dir_unsafe` and
   `pty_host_socket_path_too_long`. All three should be zero. `pty_host_legacy_socket_path` is expected once
   per pre-canary host.
4. server2 Enforce.
5. Desktop (Windows): `PtyHostPeerCheck=Observe`, then Enforce, only after CP-7/CP-8/CP-19 are green, and
   never during an active rc qualification on that host.

A flag back to Off or Legacy is a runner restart. No host is involved.

## 7. Decisions (D-S2-n, stated defaults)

- **D-S2-1. Peer check before hello.**
  - Why: I-1. The hello is cheap, but writing it already tells a squatter that this session is being
    adopted.
  - Rejected: after the hello (the overall plan's "before the hello write" kept; PC-51).
- **D-S2-2. A public `PtyHostConnectPolicy` parameter, with the seams kept in SessionRunner.**
  - Rejected: `InternalsVisibleTo` additions, which change a csproj and the land-graph digest.
  - Rejected: a client-global static, which would leak between parallel tests.
- **D-S2-3. Custody launches keep the well-known name.**
  - Why: `RecoverManifests` pins `PipeNameFor` (GT-S2-3), and widening a custody identity check is its own
    review.
  - Rejected: teaching the ledger the owned path in S2. That is F-5 if wanted. Custody still gets the peer
    check.
- **D-S2-4. `EnsureSafe` gates launches, not adoption.**
  - Why: adoption's proof is per path (socket owner plus peer), and refusing adoption on a directory fault
    would hold every live host.
  - Rejected: gating the sweep.
- **D-S2-5. An ancestor rule, added to the overall plan's I-4.**
  - Why: an attacker who owns an ancestor can rename `sock/` after the check.
  - Rejected: checking only the directory itself (the overall plan). The peer check would still catch the
    swap, but the directory proof would be hollow.
- **D-S2-6. The runner checks the 107-byte bound itself.**
  - Rejected: relying on .NET's 108 check, which fires after spawn inside the host's bind.
- **D-S2-7. One portable peer class instead of a separate Windows class.**
  - Why: the in-process fake's pid is the test process on both platforms, so V-11 is M-13's witness on
    Windows for free.
  - Rejected: `Card1653WindowsPeerTests` (overall plan), which would duplicate the class.
- **D-S2-8. Windows Observe does not set `CurrentUserOnly`** (GT-S2-12).
  - Rejected: a manual owner-SID read in S2. That is about 60 lines for a log line.
- **D-S2-9. `PtyHostPeerRefusedException : UnauthorizedAccessException`.**
  - Why: it takes the existing non-retry arm of `ConnectAsync` without touching the CARD-1632/1634 retry
    predicate.
- **D-S2-10. No change to compose files or to the runner configuration in S2.** The rollout is
  operational (§6).

## 8. Risks and follow-ups

- **R-3** (kept): there is no cross-account witness on either platform. The probe seam stands in for a
  foreign uid on Linux. Windows `CurrentUserOnly` is a review item.
- **R-5:** `SO_PEERCRED` across pid namespaces gives pid 0. That is unproven, so a refusal under Enforce.
  Runner and hosts share the container, so this does not arise on server2. Observe measures it first.
- **R-6:** the probe flip in V-11e depends on the sweep passing its probe to `AdoptAsync`. TestDesign
  confirms the seam. Otherwise G-49 becomes a review item, recorded as such.
- **F-4:** stale socket files accumulate (1253 in server2 `/tmp`, GT-S2-9). A cleanup that unlinks
  `sock/<id>` for sessions without a manifest belongs on a separate card.
- **F-5:** owned rendezvous for custody launches (D-S2-3).

## 9. Waiting-input checklist

S2 adds no session that waits for input. It adds a second reason for S1's held pending row,
`pty_host_peer_unproven`. Input to that row is refused by the existing pending guards. It is released by:

1. the vanish sweep, once the manifest host pid is dead at its start (G-59);
2. a runner restart whose adoption proves the host;
3. an operator stopping the verified pid, after which (1) applies.

There is no timer. With `BlockedTaskParking:Enabled=false` there is **no automatic release deadline**
(CARD-1083), and S2 adds none. The server raises its pending incident after `HerdrPendingAlertMinutes`
(default 5), reason-agnostic (S1 V-8).

## Performance budget

Sources:

- **S1 Code, measured** (server2 Linux, loaded): per-test TRX p95 2.78 s across `Card1653RefusalRetainsHostTests`
  and `Card1653FreshLaunchIdentityTests`. `Card1636AdoptionIdentityTests` p95 1.42 s (S1 TestDesign, n=3).

- **Overall plan (cf8b6982 receipts):** build p95 135 s, n=11.
- **Unmeasured, provisional:** the Windows SessionRunner.Tests build and the four `Card1619RunnerExitTests`
  retry methods. TestDesign or the first Code run records them.

Budget:

- **Selections.** Each row is one exact class, or one OR of whole classes with a trailing `*` on every
  operand, or one OR of method prefixes inside one class. No AppHost, Postgres, container or browser.
  Antiphon.Tests is not built: S2 changes no server code, and the server's pending handling is
  reason-agnostic (S1 V-8 and PC-26/27).
- **Per-test bodies.**
  - Fake-world tests: about 1 to 2.5 s (S1 p95 2.78 s).
  - Real-host tests (V-13, V-14): about 3 s (launch, restart, adopt; CARD-1636 real host 1.42 s plus a
    second sweep).
  - V-9 and V-9b: at most 1.5 s, because the tests set a 5 s connect budget and assert < 1 s for a refusal.
- **`[Timeout]`.** 10 000 ms per test on both new classes. The formula is S1's:
  max(10 s, 2x p95, largest internal bound + 5 s). The largest internal bound is the 5 s adoption connect.
  Code resets each class from the first green TRX and records it.
- **Fixtures.** No shared setup is needed. Each test owns one stand-in, or one real host, and one
  `TestSessionLogRoot` (`c1653-sock`/`c1653-peer`). Every class takes `[ParallelLimiter<ProcessSpawnLimit>]`
  and `[Category("Integration")]`.
- **Teardown.** At most 2 s: `TestSessionTeardown` plus stand-in disposal.
- **Phases.** `TestTiming.BeginPhase(ProcessWait, …)` around each sweep and launch (the
  `PtyHostStrangerWorld` pattern) and around the connect in V-9/V-9b. Slot wait is reported separately
  (45 to 211 s observed).
- **Rows** (EstimatedMinutes):
  - Linux build row (CP-4): 5, which is the 2.3 min p95 build plus about 30 s of class plus margin.
  - Reuse rows: 1 to 2.
  - Windows build row (CP-7): 8, provisional.
- **Runs.**
  - Run L (server2, `--rows CP-4,CP-5,CP-6,CP-17,CP-18,CP-20`): about 11 min.
  - Run W (desktop, `--rows CP-7,CP-8,CP-19`): about 10 min.

  No row or run is near 30 min (R1).
- **Mutation floor.** 35 PCs at about 2.3 min each (incremental build twice, two method runs) is about
  80 min serial on Linux, plus PC-64 on Windows at about 10 min. Two Linux shards give about 45 min of
  wall time.
- **Production cost.** At most one statx per ancestor (about 4) per launch. One statx and one getsockopt
  (or one `GetNamedPipeServerProcessId`) and one `IsAlive` per connect attempt. All are microseconds,
  inside the existing 15 s and 5 s connect budgets. S2 adds no new production timeout.
