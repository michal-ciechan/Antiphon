# CARD-0573 disposition: card completion and leftover tasks

Date: 2026-09-27. Investigated at `2f050e3d2b1cc36a3440d5914089aaded7c68a12` (the task checkout; CARD-0738's landed `4bb48ff4` is an ancestor). No production code or tests changed.

## Verified findings

1. **The card's main diagnosis is stale.** A terminal `CardService.MoveAsync` first commits the card write, then calls `CardTaskSettlement.SettleClosedCardAsync` (`server/Application/Services/CardService.cs:476-490`). `card.ps1 close` uses that PATCH result and prints canceled or still-working task IDs (`scripts/card.ps1:705-719`, `:446-462`). Tracker closes call the same settlement after saving (`server/Application/Services/ExternalTrackerSyncService.cs:136-140`). Archive calls it too (`server/Application/Services/CardService.cs:965-978`). CARD-0738 is Done on the board and its implementation is present here.
2. **The concrete CARD-0573 bound-Blocked failure is handled.** Settlement selects open, non-specialist tasks by exact `CardId` (`server/Application/Services/CardTaskSettlement.cs:75-83`). Blocked and Queued count as unstarted (`:240-245`) and are canceled through `AgentTaskService.CancelAsync` with a reason naming the card and its close reason (`:85-102`, `:280-285`). The existing integration test pins a Blocked task's Canceled state, reason, session stop, event, and move summary (`tests/Antiphon.Tests/Application/CardTaskSettlementTests.cs:21-46`). Thus the two bound markdown-package tasks described on CARD-0573 would be canceled on a new close.
3. **Started work remains visible for a decision.** A Working task, or a Dispatched task whose brief was Sent or whose transcript has a turn prompt, stays open and gets a Warning (`server/Application/Services/CardTaskSettlement.cs:240-277`). The close response reports its ID; `/api/attention` projects one `CardClosedWhileWorking` Warning with Cancel/OpenCard actions for a task older than the card close (`server/Application/Services/AttentionService.cs:947-975`; `tests/Antiphon.Tests/Application/CardClosedAttentionTests.cs:23-44`). This is a deliberate safety boundary, not the old silent leftover.
4. **Existing leftovers have an explicit repair path.** `POST /api/agent-tasks/closed-card-sweep` previews by default; `apply: true` cancels unstarted bound tasks created before the close and leaves started or later-created tasks alone (`server/Api/Endpoints/AgentTaskEndpoints.cs:93-99`; `server/Application/Services/CardTaskSettlement.cs:132-232`; `tests/Antiphon.Tests/Application/ClosedCardSweepTests.cs:21-62`). The endpoint can repair old CARD-0573-shaped data without a new scheduled job.
5. **The remaining unbound example is outside what a card can prove.** The three gym-stat Deploy tasks in CARD-0573 had no card binding. Exact `CardId` settlement cannot see them (`server/Application/Services/CardTaskSettlement.cs:77-80`). Title or working-directory resemblance is not a durable relation: a directory can contain several cards, and a task title can name a problem without being superseded. Automatic cancellation or demotion from that heuristic could hide real work. The card's proposed `GET /api/agent-tasks?...&cardId=...` query is also stale: the list route accepts `projectId`, `boardId`, `unscoped`, `status`, `since`, and `rootId`, but no `cardId` (`server/Api/Endpoints/AgentTaskEndpoints.cs:32-51`). Inspect a scoped task list and filter returned `cardId` or `workingDirectory` client-side, then cancel a verified obsolete row with a reason. `docs/ops-http.md:95,104` and `docs/agent-card-lifecycle.md:24` document the bound-task close and sweep paths.

## Smallest fix and disposition

Close CARD-0573 as superseded by CARD-0738. No new production change is justified for its bound-task symptom. For unbound tasks, use the existing scoped task list and attention feed as a manual close review, recording why an identified task was superseded before cancellation. If repeated unbound cases warrant automation, create a separate card for an explicit task-to-card binding or a review-only candidate list with evidence; do not infer completion from title or path alone.

The CARD-0738 board record separately notes an archive-after-Done edge: the immediate archive call does not check whether an unstarted task was created after Done (`server/Application/Services/CardService.cs:965-978`; `server/Application/Services/CardTaskSettlement.cs:75-102`). The preview sweep and attention projection use `CreatedAt < CompletedAt` (`CardTaskSettlement.cs:159-185`; `AttentionService.cs:950-953`). Resolve that CARD-0738 edge in its own follow-up; it does not change the CARD-0573 terminal-move disposition.
