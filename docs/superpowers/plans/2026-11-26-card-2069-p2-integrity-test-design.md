# CARD-2069 P2 integrity verification appendix

A bounded proposal can make one unaffected chunk eligible for later carry checks. Replacing any bound evidence and resealing the proposal must return **Full, zero carry candidates and the entire independently discovered roster owed**. Run these two outcomes through the same admission entry point. The [P2 plan, D-1 through D-4](2026-11-26-card-2069-p2-integrity-plan.md) and its [investigation](../../investigations/2026-11-26-card-2069.md) own the design. ### Delivery inventory

S1/S2 add a synchronous encoded proposal and a synchronous consumer decision. The producer writes bytes, the qualification consumer opens them and the returned decision identifies the attempt, owed chunks and eligible origins. The independent custody store supplies inputs to that call. No new or changed queue, session input, background delivery, retry worker or recipient receipt exists in these slices. A saved file or matching digest proves only that those bytes exist. The tests observe the adapter's returned partition. Actual launch receipts, recovery after partial execution and publication are owned by CARD-1836.

#### T — one bounded decision and its resealed replacements for S2

**Setup.** Use one private temp Git repository and fixed line, run, attempt, revision and clock. B and A are two real commits with distinct trees and B ancestor of A. Commit the minimal category, owner/reader, project, policy, catalog, SDK, selector sources, discovery and index inputs at both endpoints. Use `core.autocrlf=false` and raw Git blob handles. Create a separate reviewed tool source, an independent request and a read-only qualification snapshot. The fixture owns the latter two. Never derive their roots, pins, catalog of artifacts or history from a proposal. Give the proposing side a separate writable copy. Use in-process receipts for a declared fixture Linux x64 `rc` target, with TFM/RID/configuration and six independently observed input roles. Keep one second target/attempt available for substitution.

The two test projects are `tests/Hot/Hot.csproj` and `tests/Quiet/Quiet.csproj`. One changed private Hot input selects `Probe.HotTests` (chunk H, case `h1`), while `Probe.QuietTests` (Q, cases `q1`,`q2`) has equivalent inputs on both sides. Key each case by suite/assembly, qualified class, method and stable data-case identity. Place a v2 original execution row and its exact clean TRX under the authority's relative artifact ID for each B chunk. Pin inventory and artifact digests when creating that authority. Record Q's origin as `(B, run-b, attempt 1, inventory seal, q.trx byte SHA)`. Build the expected H/Q partition and reasons from the fixture facts by hand. Count nonempty, distinct content digests. Observe the actual adapter output and reconcile against these named cases.

Use production contract, content/input comparison, receipt/TRX and trust logic through the adapter. For missing S1R6/P1 services, the bounded fixture can supply independently recorded **source inputs** to a small, reviewed evaluator of the admitted fixture grammar, a pinned target discovery observation and an in-memory qualification recorder. Require a real read of B and A, regeneration from the two source closures and comparison against their committed indexes. No seam may supply a preapproved bit, a precomputed final partition, the proposal's own root as an expectation, or `Reusable=true`. Exercise the ordinary provider with an unavailable proof too.
