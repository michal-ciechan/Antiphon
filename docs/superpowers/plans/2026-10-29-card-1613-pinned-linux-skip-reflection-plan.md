## Decisions

- **D-1 — One source, exact per-suite type identity.** Add `tests/Shared/NativeLinuxOnlyAttribute.cs`, namespace `Antiphon.TestSupport`, linked into the four suite projects. Declare `public sealed class NativeLinuxOnlyAttribute : TUnit.Core.SkipAttribute`, `[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, AllowMultiple = false, Inherited = false)]`. A constructor accepts a nonempty compile-time reason string and calls `base(reason)`; its only predicate is `public override Task<bool> ShouldSkip(TestRegisteredContext context) => Task.FromResult(!OperatingSystem.IsLinux());`. No environment override, helper call, Conditional attribute, clock or injected OS. Sealed overrides follow from the sealed class. This also skips macOS: the two existing Windows-only guards become explicitly Linux-only, as the card requests; record that narrowing rather than claiming all non-Windows behavior is unchanged.
- **D-2 — Additive, byte-exact migration.** Each marker reason must equal that node's **current effective Windows skip reason byte for byte** (UTF-8 of the decoded string, with no trim, newline or Unicode normalization). A policy exclusion's explanation is not a runtime skip reason. For each of the 25 class rows, use a class attribute only if every expanded test has the same Windows reason; otherwise mark every selected method with its own reason. SafeDeleteProcessBoundaryTests and CheckpointFixtureProcessTests require two method markers each. Also mark exactly the 95 names in the 20 method rows, resolving every matching overload/type. Retain all current gates and reasons. Reject replacing/removing gates in this change: it would entangle the migration with C1210/C1050, direct helper callers and prerequisite semantics. Reject class attributes on the 20 mixed classes: that would skip their portable siblings. D-10 makes Windows outcome/reason equality executable across all four suites.
- **D-3 — Pin bytes and compiled origin.** Add an exact LF rule for the attribute in `.gitattributes`. Embed the same Compile input as a named resource in each suite. Pin its SHA-256 as an independently reviewed literal in `tests/Shared/NativeLinuxPolicyWitness.cs`; do not compute the expected hash from the input under test. Verify embedded bytes, checkout bytes, sealed/base type/method/AttributeUsage shape, and that the expected attribute belongs to this built suite module. Match `CustomAttributeData.AttributeType == typeof(NativeLinuxOnlyAttribute)`, never Name, FullName, suffix or assignability. A look-alike in another namespace/assembly fails. Build/source receipts bind source to DLL; the hash alone cannot authenticate an unrelated prebuilt binary. Reject a new shared production library: linked test-only support follows the existing classification model and avoids product dependencies.
- **D-4 — Explicit inheritance.** Only the concrete test class's **direct** marker or the effective test MethodInfo's **direct** marker is evidence. An inherited base test carrying that exact method marker is covered. A marked derived concrete class covers its inherited tests. A marker on a base class alone or on an enclosing nested type is not evidence; require an explicit marker on each concrete derived/nested test type or method. This deliberately conservative rule avoids depending on TUnit's differences between generated and reflection attribute collection. It may refuse a runtime-skipped future shape, but cannot borrow a decoy's gate.
- **D-5 — No policy generation from markers.** Keep reviewed policy rows as the authority and check them in both directions. Auto-generating exclusions from annotations could turn an accidental marker on a portable test into an approved exclusion. Pin the canonical **88 legacy exclusion records**, including suite/class/methods/platform/owner/reason, as a baseline digest in the witness. Every other rc row must resolve to the pinned marker; require the existing Linux reason prefix and `platform: windows`, rather than using the prefix to decide whether to validate. An unknown suite or changed/new legacy-shaped record fails until explicitly reviewed. This does not claim the 88 legacy records are proved by the new marker.
- **D-6 — Reflection in the owning host.** Link `NativeLinuxPolicyWitness.cs` and `NativeLinuxPolicyWitnessTests.cs` into each of the four assemblies. Each host checks its own `typeof(NativeLinuxPolicyWitnessTests).Assembly`, its suite ID from an explicit assembly-name map, and the current policy file. No loading another test DLL into PowerShell, no ambient AppDomain enumeration and no probing default bin directories. Aggregate four clean checkpoint receipts to prove all 45 rows. This avoids test-project references, dependency-version collisions and constructor execution during inspection.
- **D-7 — Retire the source-only shell verdict.** Delete the lexer and its Add-Type/synthetic-source logic. Rename the remaining policy-only case to `LinuxOnlyWindowsExclusionPolicy`; update the ReleaseGatePlatformTests adapter to that name. The old `-Case LinuxOnlyWindowsExclusions` must refuse with a diagnostic directing callers to the compiled witness selection, not silently downgrade to a policy-only success. The harness's complete gate is the checkpoint selection below: it launches each built TUnit assembly through the existing driver, then validates all four receipts. No script or TUnit test recursively builds/runs its own suite. Preserve the independent policy/census/gap checks in the renamed case.
- **D-8 — Native probe, not OS emulation.** Add a small child-only TUnit executable under `tests/Antiphon.NativeLinuxPolicy.Probe/`, built once with the Antiphon.Tests graph, staged like existing child hosts. It links the pinned attribute, not the production witness tests. A parent `NativeLinuxPolicyExecutionTests` runs it under existing owned-child process custody and the assembly-local ProcessSpawnLimit. Windows and Linux receipts are both required. Reject a fake IsLinux seam as proof of the actual attribute.
- **D-9 — Placement and scope.** GET `/api/runner-defaults` and GET `/api/session-runners` were read on 2026-10-29: default revision 2; a Linux default and Windows runner are advertised. No fleet address or host is a plan constant. Omit `-Runner`; use `-Platform Windows` only for native Windows rows and `-Platform Linux` for native Linux rows. Portable metadata rows follow defaults. No session waiting/release behavior changes, deployment, tags, qualification publication or rc rebases are part of this work.
- **D-10 — Static Windows preservation proof, with explicit limits.** Add `tests/Shared/NativeLinuxWindowsBaseline.json` (reviewed test input, not generated execution evidence) and `tests/Shared/NativeLinuxWindowsReasonAudit.cs`, linked/embedded in the four suites. Before annotation, extract and review every migrated node's Windows outcome/reason from the immutable pre-S1 source; after annotation each suite's existing `Policy_rows_require_pinned_attribute` compares its marker metadata to that baseline and revalidates the retained gate source. This needs no native Windows run for all 45 rows. Keep CP-9/10/11 as native checks of the framework and existing roster subsets; they do not stand in for full-roster equality. Reject using Linux runtime reasons, policy reasons, an automatically refreshed baseline, or a blanket class string as the oracle. The detailed fail-closed procedure below is a migration compatibility check; only the pinned compiled marker establishes admission.
- **D-11 — Fail closed on custom test sources.** Enumerate candidate method attributes using `typeof(TUnit.Core.BaseTestAttribute).IsAssignableFrom(attribute.AttributeType)` with framework identity, without constructing attributes. Support ordinary exact TestAttribute nodes. Refuse every other BaseTestAttribute subclass on a policy-matched type or a marked type/member as `unsupported-test-attribute`, naming the attribute and method, even if another ordinary test resolves the same row or the custom member has a marker. This deliberate refusal avoids pretending that static reflection can enumerate a dynamic builder's generated tests. Reject exact-TestAttribute-only discovery and string-name ancestry. A later request to support builders needs its own discovery design; this card cannot hide them behind an exclusion.
- **D-12 — Isolate expected red.** Run the pre-annotation real-policy proof from a separate ignored one-row manifest; its failed receipt is required RED evidence, never part of final checkpoint validation. All 13 ordinary checkpoint rows below run green at S1-S3. CP-1/2/3 share one final main-suite build and partition the shared witnesses, negative-fixture parents and native/parity parents. Reject accepting an expected-red row as a clean run or counting CP-2 from a failed combined run as final evidence.

## Reflection algorithm and harness boundary

1. Parse the complete policy strictly, check schema/hash with a C# implementation of the existing canonical JSON contract (cross-checked against Get-NightlyPolicyHash in the parity test), validate every exclusion's suite/platform/owner/reason/method shape, and compare the canonical legacy set with D-5. Unknown or omitted suite mappings fail even when encountered by another suite's host. Each of the four expected hosts must report its suite ID, policyHash, full source SHA, module MVID, assembly path/hash and matched row/method counts. A missing host receipt is not success for an empty local subset.
2. Enumerate **all** types in the owning compiled assembly. Never recover a partial list from ReflectionTypeLoadException. Keep all namespaces, nested types and generic definitions; skip non-runnable abstract declarations as concrete nodes, but inspect their inherited methods on concrete types. Inspect public/nonpublic instance **and static** methods for **any framework BaseTestAttribute subtype**, applying D-11's explicit refusal to unsupported subclasses before row resolution can succeed. Honor exact InheritsTestsAttribute on the concrete class (including framework-supported inheritance); retain effective overrides and every overload. Walk hierarchy where needed so a hidden base test is never silently lost. Refuse an unsupported or ambiguous discovery mapping rather than guessing it away.
3. For each concrete test node retain `(suite, concrete type, declaring type, module MVID, method metadata token, generic arity, parameter types)`. Do not DistinctBy method name. Construct its TUnit ClassName and Type spelling using the pinned framework contract: namespace plus containing types separated by `+`, name including backtick arity, constructor-argument suffix only in the runtime ClassName. Generic instantiations share attribute metadata but retain all discovered cases. The comparison is the **same** OrdinalIgnoreCase predicate as Test-NightlyProfileNodeExcluded, including full ClassName fallback and constructor suffix handling. A plain Foo row must not borrow Foo<T>'s marker; a nested row explicitly naming Outer+Foo must be checked too.
4. A class row selects every matching runnable test, across namespaces/case twins. A method row selects every matching method name across **all** matching classes/overloads. Require at least one concrete test for a class row and at least one test for **each listed method name** in a method row; one resolved method cannot hide a typo in its sibling. Each selected node independently needs the exact direct marker defined in D-4. On error list suite, row, fully qualified concrete/declaring type and signature. Sort diagnostics ordinally.
5. Read marker CustomAttributeData without instantiating user attributes or tests. Check that its string reason is nonempty and its constructor is the pinned constructor. The admission proof never infers a marker from method IL/source or an old gate call. Separately run D-10's static compatibility comparison of the retained gates and compiled marker reasons for migrated nodes. A Conditional helper, unawaited Task, iterator or alias is irrelevant without the marker. Marker shape/hash and the native predicate are tested independently; a fixture's fake attribute never becomes the expected type.
6. Check reverse coverage in each primary suite: marked concrete test nodes must be selected by witnessed Windows exclusion rows; unselected mixed-class siblings remain unmarked. On the current migration require the same 45 normalized row keys/95 named method entries and identical existing TUnit node identities/argument multiplicities before and after. The witness's own new tests are required on both platforms and never receive the marker.
7. TUnit invokes this code within each built test host; the checkpoint harness starts the explicit isolated output using its verified build stamp and validates the fresh TRX. This is how the harness reaches the compiled assembly. Do not Add-Type or Assembly.LoadFrom a test executable into pwsh, copy a DLL from another checkout, or run a build from inside a test. Standalone policy-only PowerShell assertions are supplementary, never a replacement for the four compiled receipts.

Parity is an independent integration test, `NativeLinuxPolicyMatcherParityTests.Matcher_agrees_with_nightly_exclusion_predicate`: pass a fixed matrix of node identities/rows to the **real** PowerShell functions and compare selected signature sets with the C# matcher. Cover full and simple identities, different namespaces, Unicode identifiers, case twins, all overloads, `Outer+Inner`, ``Type`1``, constructed generic cases and constructor-argument suffixes. The native probe supplies actual TUnit diagnostic/TRX names for nested/generic/inherited cases; if those disagree with the projected names, repair the projection and rerun parity before migration approval. Do not change the production PowerShell matcher to fit the witness.
