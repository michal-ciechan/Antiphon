## Decisions

- **D-1 — One source, exact per-suite type identity.** Add `tests/Shared/NativeLinuxOnlyAttribute.cs`, namespace `Antiphon.TestSupport`, linked into the four suite projects. Declare `public sealed class NativeLinuxOnlyAttribute : TUnit.Core.SkipAttribute`, `[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, AllowMultiple = false, Inherited = false)]`. A constructor accepts a nonempty compile-time reason string and calls `base(reason)`; its only predicate is `public override Task<bool> ShouldSkip(TestRegisteredContext context) => Task.FromResult(!OperatingSystem.IsLinux());`. No environment override, helper call, Conditional attribute, clock or injected OS. Sealed overrides follow from the sealed class. This also skips macOS: existing Windows-only guards (including UnixPtyArgvTests, UnixDelegateLaunchArgvTests and the selected CompletedCardWorkspaceInspectionR3 executable-bit method) become explicitly Linux-only, as the card requests. Record that narrowing rather than claiming all non-Windows behavior is unchanged.
- **D-2 — Additive, byte-exact migration.** Each marker reason must equal that node's **current effective Windows skip reason byte for byte** (UTF-8 of the decoded string, with no trim, newline or Unicode normalization). A policy exclusion's explanation is not a runtime skip reason. For each of the 25 class rows, use a class attribute only if every expanded test has the same Windows reason; otherwise mark every selected method with its own reason. SafeDeleteProcessBoundaryTests and CheckpointFixtureProcessTests require two method markers each. Also mark exactly the 95 names in the 20 method rows, resolving every matching overload/type. Retain all current gates and reasons. Reject replacing/removing gates in this change: it would entangle the migration with C1210/C1050, direct helper callers and prerequisite semantics. Reject class attributes on the 20 mixed classes: that would skip their portable siblings. D-10 makes Windows outcome/reason equality executable across all four suites.
- **D-3 — Pin bytes and compiled origin.** Add an exact LF rule for the attribute in `.gitattributes`. Embed the same Compile input as a named resource in each suite. Pin its SHA-256 as an independently reviewed literal in `tests/Shared/NativeLinuxPolicyWitness.cs`; do not compute the expected hash from the input under test. Verify embedded bytes, checkout bytes, sealed/base type/method/AttributeUsage shape, and that the expected attribute belongs to this built suite module. Match `CustomAttributeData.AttributeType == typeof(NativeLinuxOnlyAttribute)`, never Name, FullName, suffix or assignability. A look-alike in another namespace/assembly fails. Build/source receipts bind source to DLL; the hash alone cannot authenticate an unrelated prebuilt binary. Reject a new shared production library: linked test-only support follows the existing classification model and avoids product dependencies.
- **D-4 — Explicit inheritance.** Only the concrete test class's **direct** marker or the effective test MethodInfo's **direct** marker is evidence. An inherited base test carrying that exact method marker is covered. A marked derived concrete class covers its inherited tests. A marker on a base class alone or on an enclosing nested type is not evidence; require an explicit marker on each concrete derived/nested test type or method. This deliberately conservative rule avoids depending on TUnit's differences between generated and reflection attribute collection. It may refuse a runtime-skipped future shape, but cannot borrow a decoy's gate.
- **D-5 — No policy generation from markers.** Keep reviewed policy rows as the authority and check them in both directions. Auto-generating exclusions from annotations could turn an accidental marker on a portable test into an approved exclusion. Pin the canonical **88 legacy exclusion records**, including suite/class/methods/platform/owner/reason, as a baseline digest in the witness. Every other rc row must resolve to the pinned marker; require the existing Linux reason prefix and `platform: windows`, rather than using the prefix to decide whether to validate. An unknown suite or changed/new legacy-shaped record fails until explicitly reviewed. This does not claim the 88 legacy records are proved by the new marker.
- **D-6 — Reflection in the owning host.** Link `NativeLinuxPolicyWitness.cs` and `NativeLinuxPolicyWitnessTests.cs` into each of the four assemblies. Each host checks its own `typeof(NativeLinuxPolicyWitnessTests).Assembly`, its suite ID from an explicit assembly-name map, and the current policy file. No loading another test DLL into PowerShell, no ambient AppDomain enumeration and no probing default bin directories. Aggregate four clean checkpoint receipts to prove all 45 rows. ## Reflection algorithm and harness boundary

1. Parse the complete policy strictly, check schema/hash with a C# implementation of the existing canonical JSON contract (cross-checked against Get-NightlyPolicyHash in the parity test), validate every exclusion's suite/platform/owner/reason/method shape, and compare the canonical legacy set with D-5. Unknown or omitted suite mappings fail even when encountered by another suite's host. Each of the four expected hosts must report its suite ID, policyHash, full source SHA, module MVID, assembly path/hash and matched row/method counts. A missing host receipt is not success for an empty local subset.
2. Enumerate **all** types in the owning compiled assembly. Never recover a partial list from ReflectionTypeLoadException. Keep all namespaces, nested types and generic definitions; skip non-runnable abstract declarations as concrete nodes, but inspect their inherited methods on concrete types. Inspect public/nonpublic instance **and static** methods for **any framework BaseTestAttribute subtype**, applying D-11's explicit refusal to unsupported subclasses before row resolution can succeed. Honor exact InheritsTestsAttribute on the concrete class (including framework-supported inheritance); retain effective overrides and every overload. Walk hierarchy where needed so a hidden base test is never silently lost. Refuse an unsupported or ambiguous discovery mapping rather than guessing it away.
3. For each concrete test node retain `(suite, concrete type, declaring type, module MVID, method metadata token, generic arity, parameter types)`. Do not DistinctBy method name. Construct its TUnit ClassName and Type spelling using the pinned framework contract: namespace plus containing types separated by `+`, name including backtick arity, constructor-argument suffix only in the runtime ClassName. Generic instantiations share attribute metadata but retain all discovered cases. The comparison is the **same** OrdinalIgnoreCase predicate as Test-NightlyProfileNodeExcluded, including full ClassName fallback and constructor suffix handling. A plain Foo row must not borrow Foo<T>'s marker; a nested row explicitly naming Outer+Foo must be checked too.
4. A class row selects every matching runnable test, across namespaces/case twins. A method row selects every matching method name across **all** matching classes/overloads. Require at least one concrete test for a class row and at least one test for **each listed method name** in a method row; one resolved method cannot hide a typo in its sibling. Each selected node independently needs the exact direct marker defined in D-4. On error list suite, row, fully qualified concrete/declaring type and signature. Sort diagnostics ordinally.
5. Read marker CustomAttributeData without instantiating attributes/tests; check its nonempty reason and pinned constructor. For frozen migrated signatures only, byte-compare the reason with the baseline; new marked nodes need no historical entry (D-16). Never digest inventory source or re-extract old gates in this permanent algorithm. A Conditional helper, unawaited Task, iterator or alias is irrelevant without the marker.
