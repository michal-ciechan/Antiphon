## Routing data and execution ownership

Use three bounded records rather than grow `AgentSupervisionState` with provider policy:

- `StandingSpecialistRouting`: unique `AgentId` of the logical owner, `CandidatesJson`, configuration revision/concurrency token and enabled state. Reuse enum-name JSON and `RoutingCandidate` validation; require both fields here even though task pins permit partial pairs. Reject duplicate/unsupported pairs and lists over three. A configuration update changes future admission, never an in-flight task's identity.
- `StandingSpecialistCandidateState`: unique logical owner + pair, physical agent id, resolved kind/level/alias, effective profile revision, session id + StartedAt generation, contract/launch/tool-policy/transport fingerprints, qualification evidence task ids, state/reason, next probe time and failure episode. Store references/stamps, never launch secrets. A change to alias resolution, profile, executable version, backend, composed instructions, tool policy or session generation invalidates qualification. Reordering an unchanged pair does not duplicate its physical seat.
- `StandingSpecialistHealth`: unique logical owner, active candidate, first unresolved failure/last valid real Check times, consecutive failed request count, last evidence/run ids, outage start/resolution and durable status. Add a request/attempt relation (separate table if needed) keyed by checked task + check number to claim attempts and a single winning result atomically. Health counts logical requests, not polling passes or failed candidates followed by success.

Keep logical ownership typed, e.g. a managed-candidate relation, rather than detecting slug prefixes. Provisioner, supervisor, startup notes, policy refresh, liveness and deletion must recognize managed specialist seats. No workspace-reading bootstrap or refocus compact may be sent to them. All remain non-pool agents; alternate tasks stay Role=Check, ReplyTo=None, no CardId, and never enter the worker cascade/check-check loop. Every process remains owned until the ordinary authorized stop/cleanup path ends it.

The primary preserves its current profile, exact model and working directory during compatibility rollout. Its configured head pair must match its kind/tier; an exact ModelId remains authoritative through `DispatchModelAlias.Resolve` and the normal launch resolver. Reject a contradictory head configuration. Alternate pairs resolve from the existing definition/model ladder; do not inherit a Claude profile, environment overrides or Herdr tab label into Codex. V1 supports registry-defined alternate launches in isolated PtyHost scratch seats. Custom alternate profiles or Herdr seats without explicit placement are rejected with an actionable validation reason, not silently relocated. This keeps the initial configuration API pair-compatible with CARD-0322.

Provide `GET/PUT /api/agents/{id}/specialist-routing` with fresh concurrency-token writes, configured candidates, effective identities, readiness and reasons. Restrict it to supported specialist owners. Add a small Agents settings section and a PowerShell helper (`scripts/specialist-routing.ps1`) accepting `Kind/Level,...`, with inspect/set/revalidate operations. Revalidate is an explicit bounded request, respects holds/human barriers, and cannot mark a candidate qualified directly. Saving a declared chain authorizes its bounded qualification work and listed models; it does not activate an unqualified route. Ordinary agent PATCH of a managed execution identity must invalidate qualification and be rejected while that seat has active work.

Alternates are warm standing seats only while their owner/feature/configuration authorizes them. Reconciliation must honor suspension, liveness latch, Herdr hold, authentication, global feature switches and model holds before starting anything. Removing/disabling a candidate stops admitting work, cancels only unclaimed queued probes/check attempts, and drains owned active work. Do not turn suspension into a hidden cleanup mechanism or let an AlwaysOn supervisor immediately resurrect a disabled alternate. Retire an idle removed seat through normal stop ownership rules; retain history. CheckInterpreterEnabled=false suppresses new probes, starts and outage alerts while preserving audit state.

## Capability and interpretation gates

### G-1: provider execution contract

Before a kind/backend combination is admitted, prove all of these through its actual launch composer and queue:

1. The effective instruction text contains the current interpreter bundle and per-task format reminder. Codex uses `developer_instructions`, not the inert `instructions` key. Details and attachment presence are irrelevant to this assertion. The launch has the requested tier/exact model, no competing model flag, and no workspace ritual.
2. The complete deterministic facts reach a transcript-confirmed UserPrompt with the current Check marker. Use LF, bracketed paste and a separate Enter through `SessionMessageQueueService`, with its established confirmation/retry rules. Test non-ASCII text, embedded task/report markers, head/middle/tail facts, near-limit input, CRLF normalization and warm reuse. A matching screen, Sent flag or TurnEnd without prompt evidence does not pass.
3. Tool execution is denied before it runs, including file reads, shell/edit tools, MCP and network/search. Claude's owned deny hook must fail qualification if it cannot be armed; the current log-and-continue workspace preparation is insufficient. Codex needs a verified provider-specific restrictive launch configuration and isolated specialist home/settings; never inherit a general coding profile with permission bypass and call it no-tools. Do not guess a Codex flag or claim read-only sandboxing disables reads. If the installed CLI cannot enforce the required tool policy, mark that candidate Unsupported and return the capability finding for implementation/design follow-up. It cannot become a live fallback.

Add an explicit specialist capability entry/transport policy beside the provider contract catalog, not a general `ForAgentKind` exception. Establish its maximum UTF-8 input size from current production-path canaries; no number is declared safe by this plan. The queue must carry this typed policy through enqueue and retries so both `FitBriefForTyping` and queue spill cannot replace the facts. Oversize is a typed `InputUnsupported` outcome before any submit. Keep the raw digest complete for the existing caller fallback. Unknown/inbox/Herdr combinations remain ineligible unless independently certified. Server/runner feature compatibility must fail closed where the implementation adds protocol fields.

The ordinary Codex delegate pointer policy stays as documented. A one-line encoded full-fact payload is acceptable only if the model/transport fixtures prove semantic preservation; it is not permission to discard evidence to fit a ceiling. No broad transport redesign is implied.

### G-2: model qualification before production selection

Use representative synthetic `DelegateCheckProbe.CheckFacts` through `CheckInterpretation.BuildGoal`, real Check task creation, standing dispatch, queue, transcript ingestion, report settlement and result validation. They must not publish caller notifications, create cards, or use a live broker. The suite covers doing/produced, stuck boot turn, ambiguous evidence, shared-checkout authorship, and settled-at-capture. Include a fixture where the checked delegate's brief is a pointer: the interpreter receives the facts inline and must correctly describe that pointer as delivery to the other delegate. Include instruction-looking text in the facts; it must remain data.

Release acceptance requires all five semantic fixtures on the real primary and real alternate, plus repeated checks in the same warm session and a fresh launch. Assert fixture-specific evidence and classification, current Check done token, one line <=240 characters after token extraction, no fabricated completion/authorship, and zero tool attempts. `ready`, empty output, copied fact dump, wrong token, blocked token or a valid-looking answer unrelated to the fixture fails. A fake provider proves plumbing only and cannot satisfy this gate.

Runtime qualification uses two small deterministic fact fixtures with fresh evidence nonces per new launch fingerprint. It records input/answer hashes, transcript sequence boundaries, settlement task ids, actual model/CLI/profile/backend, validation version and time. Qualifying requests are allowed onto the candidate's session, but production requests cannot select it until qualification passes; keep the two task purposes typed to avoid a circular gate. A runtime probe never recursively invokes fallback to qualify itself.

At most one qualification batch per candidate generation. A failed batch quarantines it; a hold-clear recovery, changed configuration/fingerprint or explicit revalidate can schedule one later batch. No periodic paid liveness loop. On a warm seat, a meaningful compaction/instruction-refresh boundary invalidates the behavioral qualification and schedules requalification at idle; do not force compaction to test production. Real CLI transport canaries use `RealCliStubEnv` and its dual-hit oracle where applicable; authenticated model tests use the dedicated test home and explicit headed opt-in under the testing owner. Never copy the user's credentials/home or use production runner 17204.

### G-3: each returned reading

Introduce a pure `CheckInterpretationValidator` after normal report-token extraction. Require the matching report/turn correlation, terminal success, one nonempty physical line <=240 characters, one of the four current prefixes, and no leftover report/task markers or generic ready response. Validate text before formatting or truncation; presentation truncation must not manufacture a pass. Preserve `Settled at capture` and legitimate evidence language; do not ban the word complete indiscriminately. Semantic correctness is proven by the fixture suite, not falsely guaranteed by the prefix parser.

Record typed outcomes: held/quota/auth unavailable, identity mismatch, input unsupported, delivery unconfirmed, expired before dispatch, timed out after dispatch, task failed (with original bounded FailureReason), empty, invalid reading and valid reading. Keep transport evidence distinct from model/output failures. This removes the current information loss behind `the interpretation failed` without logging credentials or full sensitive bundles.

## Selection, failure and recovery

Claim a logical interpretation request before candidate admission. Snapshot selected kind, tier, effective alias/exact model, physical seat, session generation and configuration revision onto its attempt/task. Apply this identity fix to both `RunAsync` and `RunWithPolicyAsync`; do not regress Distill's deadline behavior. Dispatcher admission rechecks actual session identity and generation. A conflict returns a typed refusal to the bounded chain; it must not silently retag a task already dispatched or remove `PlaceOnStandingAgentAsync`'s guard.

Walk declared candidates in order, filtering support, current qualification, holds (including kind wildcard and Manual), subscription gate, authentication, supervision barriers and session occupancy. Preserve the existing explicit internal primary quota-override policy only where already authorized; alternate selection defaults to the quota gate, with any override explicitly configured/audited. Failures of the availability reader are not evidence of availability. Model holds remain owned by `ModelAvailability`/API-error recovery; invalid output only quarantines the specialist candidate and never disables that model for the whole fleet.

Use one absolute request deadline (`CheckInterpreterWaitSeconds`, default 60) from before eligibility/provision work. Prepare/qualify alternates outside this request in a bounded supervisor reconciliation hook; the check worker remains free to drain. A known held primary is skipped before enqueue, allowing the same check to complete on the warm alternate. Unknown failure can consume the first 30-second attempt allocation if a second ready candidate exists; then attempt that second candidate with the remaining time. A single candidate can use the remaining full budget. At most two submitted attempts per logical request; a third configured candidate is future coverage, not an unbounded latency multiplier. Honor global concurrency/cost limits without inventing implicit expensive-tier escalation.

On expiry, atomically cancel only still-queued task/message work; queued rows need an execution deadline so they cannot start after the caller left. If dispatch won the race, leave the active session owned and mark that attempt expired for this request. Its eventual report settles its own task but cannot win the request, update the current candidate's health or emit a second caller note. At most one attempt result wins by compare-and-swap; preserve all attempt ids/costs for audit. A failed first candidate followed by a valid second result counts as a successful request with failover, not a consecutive outage failure.

Retrying the immutable, scrubbed fact snapshot on another no-tool seat is safe, bounded optional work. It is not another prompt to the timed-out session. Busy alone does not kill, fail or quarantine a model. Attempt a ready alternate when the preferred seat is occupied; if all are transiently busy, preserve the existing busy digest. Persist the oldest blocked/expired outstanding attempt so five minutes of starvation is visible even when new requests keep reporting Busy. No rewrite of the checked delegate's lifecycle, check backoff schedule or successful/deterministic digest wording is needed.

CARD-0412 owns hold expiry/clear, capacity-wait episodes, paced admission and guarded automatic starts/continuations. Register the affected specialist physical seat/current authorized pending qualification as its consumer. An available alternate is ordinary authorized Check execution; the held seat's later wake must use the shared admission gate. Coalesce startup liveness with the qualification task where possible; do not add a second continuation beside a capacity recovery prompt. An old expired Check is never the work to resume. If it remains an owned active task, let existing recovery settle it and discard the late result for caller/health purposes before qualification.

Before implementing that integration, re-read CARD-0412's actual landed symbols and record the base SHA. If only the plan exists, implement independent identity/gate/Attention slices first and keep automatic recovery activation pending. Do not add a private hold-expiry timer, fresh-start override or second resume budget. A specialist output/delivery failure not caused by capacity is quarantined once and requires explicit revalidation; retain Attention until real service recovery. This prevents replacing a sixteen-hour silent outage with a restart/spend loop.

## Durable Attention and operator behavior

The health reconciliation hook runs at least every 30 seconds in the existing supervisor loop and does no provider work inline. It projects one row per logical interpreter, with stable identity and these transitions:

| State | Trigger / surface | Exit |
|---|---|---|
| Healthy | Valid real Check on preferred candidate; no unresolved service failure | Failed request, failover or loss of qualifying candidates |
| UsingFallback | Primary held/quarantined, qualified alternate selected; durable Warning Attention names primary reason, active alternate and last valid interpretation | Preferred candidate requalified and a real Check succeeds there, or outage begins |
| Suspect | First unexplained failed request; persist first failure and counter immediately | Valid real Check, third failure, five-minute timer, or definitive unavailable chain |
| Unavailable | No eligible/qualifiable route because all candidates held/unsupported/quarantined, or three consecutive failed requests, or first unresolved failure/starvation age >=5 minutes; durable Error Attention | A real Check succeeds; qualified-only recovery remains visible as awaiting real Check |
| Disabled / intentionally suspended | Feature/operator intent prevents service; status/configuration visible, no new outage paging/counts | Re-enabled service requalifies; keep prior outage history |

Definitive exhaustion raises Attention on its first observation, even if only one check ran. A known primary hold with no qualified alternate must not wait for N more checks. Timer escalation after an unexplained failed request does not require another request. Short, healthy backlog does not start a failure episode; stuck backlog has its own evidence. Qualified standby status alone is never described as successful interpretation.

Persist state and its bounded incident/task audit in the same database transaction, then publish existing AgentChanged/AgentTaskChanged events for query invalidation. Attention is derived from the persistent state even with alerts disabled, server restart, a 24-hour lookback or deleted incidents. Exclude the transition incident from the generic recent-incident projection to prevent duplicate rows. Existing Attention badge/count and broken/suspect groups must include the new kind; provide OpenAgent and inspect-last-attempt navigation. No card move, alert sink or chat send is part of the design.

The row states: first failure/time unavailable, current candidate, original reason (e.g. kind mismatch), last successful real interpretation, consecutive failures, per-candidate skip/qualification reasons and next recovery eligibility. During fallback, example: `Check interpreter using Codex/Low; ClaudeCode/haiku held until ...; last valid check ...`. During outage: `Check interpretation unavailable since ...; 3 failed requests; no qualified alternate; inspect candidate qualification`. Acknowledge, if offered, marks seen only; it does not clear the outage, qualify a candidate, clear a provider hold or reset a human start barrier. Recovery writes one resolved audit event, rather than a new row on every tick.

**Race placement.** V-14/V-15/V-19/V-21 must pause at these actual boundaries, not merely invoke a pure policy twice: request-claim before/after commit; task claim before queue insertion; queued-message delivery-start intent; external input accepted before acknowledgement save; candidate/config replacement before winner CAS; winner+health persisted before notification; hold clear before consumption; recovery admission before side effect; accepted launch before asynchronous callback. Force both competing orders. Before-commit failure leaves no partial row/claim; after-commit uncertainty reconciles the same receipt. A transcript-unavailable action remains visibly unconfirmed; do not claim exactly-once delivery or manufacture a new request to conceal it. Blocked external fakes must not hold database transactions open or block independent health/clear writes.

**Threshold and validator conventions.** For the existing C# one-line contract, count UTF-16 string characters for the 240 limit (239/240/241 ASCII controls plus surrogate-pair controls); this is distinct from the transport's UTF-8 byte limit. Accept the usual terminal newline after extracting the done-token line; reject extra nonempty physical reading lines before formatting. The four prefixes come from current v5. A short grammatical copied claim or unrelated reading is rejected by qualification's semantic oracle, not falsely promised detectable by syntax alone. The 60s deadline is exclusive for winner admission: receipt before the deadline but winner commit at/after it cannot win. External caller-note transport time is measured separately from the bounded interpretation result; cleanup/publish work must not renew that model budget. Immediate Attention means committed with the first definitive-unavailable observation and visible on the next GET; five-minute escalation means the first normal maintenance tick at/after the threshold, without requiring another Check.
