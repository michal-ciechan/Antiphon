# CARD-2117 S1 verification design

Companion to the [landed scheduling plan](2026-11-27-card-2117-resource-aware-scheduling-plan.md) at `7e10da45ffe696dbdd5c7893432185b943d3cbd4`. This design prices and selects S1 only. S2a, S2b and S3–S5 each need their own closed manifest before Code. The two current dependencies are the shared producer contracts in [CARD-2103](https://github.com/michal-ciechan/Antiphon/blob/499a66f0d9228cc06f1fa931be4890b8339a83f4/docs/superpowers/plans/2026-11-27-card-2103-where-the-time-goes-plan.md) and the production claim change on CARD-2118. The S1 workspace still has a plain `FOR UPDATE` at the queued task claim. The workspace-admission advisory-lock fix at `75f1fea498d422d3f532bb0beb5f1b1eac26168f` addresses a different lock.

Sideband buffering in the first Code slice uses the shared writer's existing boundary. A new asynchronously delivered sideband, receipt or session input requires an inventory and a real-queue row before it joins S1.

| ID | Behavior, layer and decisive expected result |
|---|---|

### Guards the regression

| ID | Regression and assertion |
|---|---|
| R-1 | Duplicate contribution or inferred complete data. CP-2/4 require exact per-generation owner vectors, aligned peaks, null unresolved counters and one joined lease with no implicit second charge. |
| R-2 | Off-slot cleanup is omitted, assigned to the ended lease or announced as measured zero. CP-3 checks the retained phase, known bytes and null/unassigned companion through terminal readback. |
| R-3 | A v1 peer is held, contacted with a new operation or treated as reporting zero. CP-6 checks live data, durable admission and capability/coverage on the shared path. |
| R-4 | Observe steers queue order, caps, session eligibility or delivery. CP-1 requires the ordered live bytes and recipient transcript on both sides, even when shadow disagrees, the sink fills or a recorder call fails. |
| R-5 | A locked queue head blocks the successor, is marked failed, or consumes a claim. CP-1 locks only the first eligible row using a separate PostgreSQL transaction. The second task claims and receives its prompt while that exact transaction is still open. The first stays queued with original token, no launch/terminal failure, and runs once after release. |
| R-6 | Shadow steers broker FIFO, memory-floor or worker arguments, changes a grant count, or mislabels counterfactual events. CP-7 compares broker projections, and CP-4 pins actual RowVerb argv and lease order. |
| R-7 | Queue refusal/partial commit erases a durable sample/summary or acknowledges it early. CP-5/6 compare exact immutable receipts after recreation, a same-identity replay and, separately, a conflicting replay. |
| R-8 | A missing, incorrect or 405 broker route is accepted as zero/healthy. CP-7/12 and LP-1 require the intended physical authority and both endpoints. |
| R-9 | A successful history HTTP request with zero eligible samples is accepted. CP-6 and LP-2 require matched nonempty durable history plus an explicit empty diagnostic. |
| R-10 | Wrong boot, PID reuse, missing exit or device ambiguity trains the cohort. CP-2/12/13 check that invalid generations, stale/mismatched samples and missing capability are excluded and separately reported. |
| R-11 | CLI output suppresses missing coverage or turns it into apparently measured data. CP-14 requires the same explicit empty-history diagnosis and missing numeric value in both formats. |
