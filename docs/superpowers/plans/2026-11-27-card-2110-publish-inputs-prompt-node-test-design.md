- Use the GH-62 step capability descriptor and the execution-aware embedded graph clone in `ReviewWorkflowValidatorTests`. Reuse GH-62's `WorkflowEditor.test.tsx` draft and deferred-validation harness in `WorkflowTab.test.tsx` and `NodeSidePanel.test.tsx`. No new editor or save abstraction. GH-62's unsupported-binding negative must still use a deliberately unregistered capability after the positive capability lands.
- In PostgreSQL use one test-run container and the existing scoped migrated host fixture, with owned DB isolation, unique run/revision/iteration/PR IDs and independent fresh reader scopes. `ResetAsync` also clears in-memory state. Before any case beginning mid-walk, seed through a pinned revision and commit the typed producer rows, run and iteration in that DB. Then call the real hosted executor's `RunPendingAsync`. Use the host's refusing session runner and the scripted reviewer/decision/completion fixtures. For busy and crash cuts use isolated claimant scopes, callback or EF interceptor barriers, and a controlled clock. Always release and join participants. Drive cancellation inside the provider or at the specific database boundary, according to the case.
- Base the recipient on `ScriptedCodeHost` and `ScriptedPr`. For queue proofs, extend the substitute with a test-owned PR review store that retains full bodies and inline payloads by returned review ID, repository, PR and commit, independently of the executor instance. Use a fixture-only loopback endpoint or independent store read to retrieve the posted record. A request spy, the `PostReviewAsync` return value and an Antiphon `Posted` flag are supplemental. Link the recipient object to fresh PostgreSQL rows by publish output review ID and check path, line, comment/thread IDs and body. Use this same receipt for S1 post parity. Record commit and iteration identity explicitly to disambiguate retries.
- Wire witnesses run actual chat and Messages serializers against the `CompletionModelTests` capturing HTTP handler. CLI witnesses run the production `ClaudeCliCompletionModel` against a capturing `IClaudeCli` like `ClaudeCliTransportTests`, then inspect the actual argument builder output. They exercise the real formatting and launch configuration. They substitute the model/process and carry no live account. The executor tests use real dispatch and chain selection with scripted transport results. Use deterministic unique synthetic markers for every provenance source and dangerous-looking input. Normalize expected legacy newlines with `Environment.NewLine`. Compare the full body and inline payload, including final newline, within each platform.
- All new .NET witnesses below are single `[Test]` cases. Unit tests invoke the actual production resolver, renderer, validator, adapter or chain used by the feature. When a row names a matrix, run the arms inside the method with distinct case labels and collect observations before asserting the decisive arm, so a failure names the exact guard. Assert valid companions and prerequisite observations even when a named negative fails. Use local JSON with synthetic inputs. Provider exception messages and synthetic response bodies are separate markers.
