## Decisions

- **D-1 — Scope:** include R1–R6, L1–L8, F1–F9, I1–I14 and I18. This closes the named remaining fixture census instead of leaving analogous bypasses hidden. L7 is a request factory, not another launch. Preserve L9 and I15–I17 as intentional lifetime exceptions: no established normal-path defect justifies converting them to completion runners.
- **D-2 — File reads:** hash `Read-CheckpointBytes` results and use those same bounded bytes for ASCII validation: existing three-second deadline, 64 MiB cap, native regular-file/link/containment admission. Preserve digest casing and ASCII error outcomes. Reject `Test-Path` plus an unbounded open. The harness currently advertises PowerShell 5.1 while its runner and shared reader require 7; update its requirement to 7 when importing that helper, retaining ASCII source. This is a test-harness runtime declaration, not a daemon change.
- **D-3 — Git bytes:** add an additive `RunBytes` result/API to `CheckpointProcessRunner`, sharing its existing deadline, hardening, stdout/stderr concurrency and cleanup with `Run`. Read `StandardOutput.BaseStream`; retain text stderr for diagnostics. R5/R6 retain 30,000 ms per Git operation and `git_start/git_timeout/git_exit` semantics; L1/L2 adopt the same limit. Caller cancellation remains distinct from deadline expiry. Never pass bytes through a string, silently truncate, or change source fingerprint framing/version.
- **D-4 — Execution custody:** extract a reusable owned-process lifetime inside the same standalone `CheckpointProcessRunner.cs` compilation unit, using only dependencies available to its PowerShell `Add-Type` consumer. Buffered readers, fixture helpers and the real `ProcessDriver` use it; keep the driver's streaming `OnOutput`, log, `Exited`, confinement settlement, fake factory seam and `RowTimeout` results. The owner retains Linux process-group/Windows job custody after direct-child exit and has bounded disposal. Reject replacing row execution with a synchronous text-returning helper. Preserve a test factory seam around native start/assignment so R-2 can coordinate a child-before-assignment barrier. Native Windows pre-assignment containment remains a measured R-2 obligation, not a claimed consequence of this refactor.
- **D-5 — Git policies:** retain hardened read-only Git for R5/R6/L1/L2 and baseline `rev-parse`. Baseline fetch/worktree mutations keep the installed Git/credential/remote behavior under the shared lifetime and cancellation budget; fixture Git keeps `git:false`. Do not apply read-only configuration suppression to mutating Git or scratch-repository setup. Recompute baseline time remaining after slot acquisition/prelaunch, while preserving the separate one-minute worktree-removal allowance.
- **D-6 — Lifetimes and exclusions:** L3's owner is explicitly stopped after readiness (three-minute readiness limit); L4 stays live through the sweep and is stopped at cleanup, with a two-second join cap. Use the owned lifetime for these phases, not `Run` until completion. Keep L9's holder and intentional detach tests unchanged. CARD-0830 owns the full usage/progress loop; legacy `Invoke-Dotnet`, harness `Invoke-Checkpoint`/C578, diagnostic Git/host collectors, known-created scratch reads and metadata/staging remain excluded. No claim of universal boundedness. No agent session/input-wait policy changes.
- **D-7 — Evidence and cost:** one red invocation and one narrow green invocation per slice, with the same CP filter; no Unit, namespace or whole-lane runs. Existing source pins establish wiring only. Behavioral assertions establish deadlines and custody. PC-1–PC-11 Mutation remains a separate post-land obligation; this ordinary red/green work does not relabel it complete.

## Verification design

All new process-spawning classes use the existing assembly `ParallelLimiter<ProcessSpawnLimit>`, `CheckpointTestBase` sandbox ownership and a cancellable outer test timeout. Add named slow allowlist entries only where required by the owner guide. Do not co-schedule Pty tests. Tests may expose an internal callable fixture method or extract a script function **without changing its behavior** in the red commit; call the actual migrated entry point, not a duplicate implementation or the shared helper alone.

Common probe contract: record exact owned PID/start identity and a nonce readiness signal, and time the whole operation from invocation; readiness controls fault release, not the start of the measured budget. Use a 2 s child budget + at most 1 s reap, assert return before 4 s and descendant death within another 2 s, with an independent 8 s watchdog and bounded emergency cleanup. Watchdog rescue/survivor is a failed assertion. Retain 3 s file admission, assert refusal before 4 s, outer watchdog 8 s. W9 retains its real 4 s child budget: allow at most 1 s reap, assert completion before 6 s, watchdog 8 s. For production 30 s Git entry points use their real budget: assert before 32 s, watchdog 35 s, rather than adding a public timeout solely for tests. ProcessDriver retains its existing at-most-10 s cleanup ceiling: with a 2 s test row budget assert completion before 13 s and independently check death, outer watchdog 16 s. No sleeps stand in for readiness.

Parameter counts below are separately reported TUnit cases; each case includes a healthy control. Existing large fixture scenarios are not rerun wholesale. Invoke their launcher seam with a small payload that tests the same output/result assertions. Test-only Git/PATH substitutions belong in private scratch trees; no real repository config, network fetch, live runner or daemon is changed. Shims emulate config inspection as well as the requested Git verb.
