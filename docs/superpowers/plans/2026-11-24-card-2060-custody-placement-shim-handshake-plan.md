# CARD-2060 Linux custody placement at the shim boundary

The Linux shim can establish which process entered the custody tree while it still controls that process. Have it hold the original PID before payload exec, answer a challenge from the spawning PtyHost, and wait for release. The host can then certify placement even when the payload forks on its first instruction. A natural-exit receipt still requires the original host to observe root exit, a drained output stream and a fenced zero population.

Scope is new tracked launches using `linux-cgroup-v1`. CARD-2060 is InProgress. CARD-1931 is parked in Review. Start from master, leaving both rejected polling branches with their historical results. Ground truth below is from `2e31a995bdd10b1570df586a29f4356bf34980c5`.

## Ground truth

| What the card assumes | What the source and reviews establish |
|---|---|
| Placement is a server or session-runner decision. | The runner selects the backend and reserves the binding. `HostSession.LaunchAsync` owns admission and the host manifest. `PtyAgentRunner.LaunchCoreAsync` records native intent, spawns Porta, records tracking, then calls `ReadActive()` once. It accepts the numeric PID anywhere in the returned population. A missing tree or placement I/O failure leaves tracking in place. |
| The argument called execution ID identifies the attempt. | `LinuxCgroupContainment.Place` actually supplies the host-generated **container ID**. The cgroup path contains the runtime namespace and container ID. The ledger has a separate store ID, binding execution ID, session generation and host instance ID. Preserve those distinctions. |
| The tracked PID is the shim PID. | The installed enter helper writes its own shell PID to the unified tree on v2 or to both pids and freezer on v1. It execs `setpriv` to drop uid/gid, supplementary groups and set `no_new_privs`. The uid-scoped sudo policy disables its extra PTY, PAM session and credential supervisor. Direct exec and identity equality are native acceptance conditions. |
| Seeing a PID proves a live placed generation. | `PortaPtySession` captures a best-effort UTC start and replays native exit. `RecordTracking(int)` independently opens the numeric PID. `RecordLinuxPlacement(bool)` copies the tracking start into revision 1 of `linux-placement.json`. The Linux ordinary reader also calls `RootAlive(pid)`. Agreement between copied values does not establish the generation present at placement. |
| More samples solved the missing receipt. | Review b72ac3e7 found mixed/reused PID acceptance, an over-deadline read and placement I/O incorrectly turning a successful spawn into failure at `8d4ebba6034b61f57dce0561f230226c0eadc22a`. Review 45bfbc5f found ambiguous liveness, uncapped admission and a missing pre-fork boundary at `b39cf6d0de425473c8b4ddfa2ad941b1d396784c`. | The request's 30 s timer cancels work on the host. | `PtyHostClient.RequestAsync` starts its reply timeout after sending. `PtyHostServer` awaits dispatch on the pipe read loop. The connection token and the waiting-for-first-launch watchdog cannot enforce that client deadline inside the handler. |
| Zero in the cgroup is sufficient. | `HostCustodyJournal.ObserveLinuxOrdinaryAsync` requires placement, identity, tracking, intent, a second fenced zero and output drain. An explicit seal uses a different termination path. `RunnerCustodyLedger` binds accepted bytes to the same host/generation. Dead-host cleanup can stay Unknown even after helper success. |

An early read can see empty, a late read can see the root plus a detached descendant, and a PID sampled again can denote another process. More frequent reads add cgroupfs and procfs calls per active launch without establishing ordering. A longer settle window holds admission longer on missing evidence. `Task.Run` moves the first sample behind a scheduler decision, and cancelling a delay cannot interrupt a synchronous read already in progress. An empty tree observed *after* root exit remains a legitimate accounting input. It does not repair missing placement.

## Decisions

| ID | Choice and reason | Rejected alternative |
|---|---|---|
| D-1 | Use a private Linux Unix-domain stream, bound and listening before spawn. Derive a short abstract address from a fixed prefix and the fresh container GUID. Kernel peer credentials and a fresh challenge bind a single exchange. The abstract name is public and disappears when its last socket closes. | PTY output can contain arbitrary payload bytes. A shared marker needs filesystem ownership, stale-file cleanup and a wakeup protocol. Passing an inherited FD through Porta and sudo would change both launch and descriptor policy. [Linux Unix sockets](https://man7.org/linux/man-pages/man7/unix.7.html) |
| D-2 | After both v1 placements the shell execs a small image-owned native stage **in the same PID**. Use its live self stat, membership and kernel-authenticated connection under a pre-exec barrier. Use boot ID and field 22 in kernel ticks for identity, and retain UTC for the existing receipt. | Forking a notifier authenticates the notifier. Separate PID lookups or a negative hangup predicate leave identity ambiguous. A mandatory pidfd would exclude the supported 4.15 kernel. [Process stat](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html) and [pidfd availability](https://man7.org/linux/man-pages/man2/pidfd_open.2.html) |
| D-3 | Make the time-limited decision in the original host's memory. Materialize only a successfully committed decision on the ordinary custody path. This keeps optional journal I/O off launch admission and gives cancellation a single point at which it can invalidate an offer. | Timing out a background writer that already has permission to publish allows a late file. Waiting for fsync under launch admission has no enforceable upper bound. |
| D-4 | Version the local helper exchange and placement record. Qualify runner, host and image together for new launches. Preserve exact historical terminal receipts and the explicit-release path for unresolved attempts. | Reconstructing placement after restart, backfilling revision 1 or silently selecting a polling helper gives a new process authority over an earlier launch. |

## Protocol and ordering

1. **Prepare.** For a new Linux tracked launch only, the runner requires a private host hello feature `linuxPlacementV1` alongside custody support. Send an optional absolute deadline in CLOCK_MONOTONIC nanoseconds on the private launch frame. Stamp it immediately before the write, using the shared Linux time namespace of runner, host and shim. A new host requires this extension on that path. Verify the binding, reserve one attempt and prepare the socket before native intent and spawn. Preserve the existing order for host identity, namespace, manifest, runner/native intents and tracking. The helper argv is `<container-guid> --placement-v1 <deadline> -- <exe> <args...>` after the existing sudo/enter prefix. The address is derived by both peers. Only validated scalar metadata precedes the separator.
2. **Enter.** The helper reads its trusted runtime namespace, claims the fresh container once, checks empty trees, and completes the required kernel membership writes. For real v1 entries make creation of the primary pids execution directory an exclusive claim shared by both helper syntaxes. A second entrant cannot pass an emptiness check concurrently. Refuse existing or partial execution trees, retain the populated-tree refusal for live members, and leave a partial claim to the existing owned cleanup path. Keep the reserved probe ID on its existing locked create/remove path. Exec the fixed native stage in place before any payload instruction.
3. **Challenge.** The native stage connects as root and waits. The host checks `SO_PEERCRED` on the accepted stream for uid 0 and the exact PID returned by its sole Porta spawn. The stage checks the listener's kernel uid and PID against the runner account and its own direct parent. Require this direct-parent relationship on the packaged image. A sudo monitor or a crossed host cannot complete this proof. The host issues `PROVE` only after mandatory tracking succeeded for that connection. It contains the version, a fresh 128-bit challenge, store, execution, host-instance, container and namespace GUIDs, and the capped deadline. The host retains the full generation binding locally.
4. **Prove.** Without forking, the stage reads its own `/proc/self/stat` for PID, parent, positively live state and start ticks in one parse, and reads the boot ID. Verify self-membership in the exact namespaced tree of **both** v1 hierarchies, each containing solely this PID, while this process holds the pre-exec barrier. Bound each input and refuse incomplete, mixed, foreign or malformed evidence. The self process executing both the reads and the send is the generation whose membership is attested. `PLACED` echoes the challenge and tuple and supplies these observed values and the hierarchy mask. Namespace and membership are independently observed by the shim. Echoing the challenge alone proves neither.
5. **Bind and release.** At Porta attachment capture the spawn-owned PID, boot ID and raw start ticks once, bracketed by replayable exit checks on the original connection. A missing capture or exit before a valid challenge closes the attempt. Use the same capture for Linux tracking, UTC projection and manifest child start. Compare the attestation to that capture, the private peer credentials, host parent, binding, durable tracking and namespace. Supplying a fresh `Process.GetProcessById` result after the exchange is invalid. The authenticated direct child is still held at this step. The host checks the remaining time and cancellation before sending `GO` on the same stream. On timely GO the stage sends `RELEASING` with the challenge, closes the control FD and execs the fixed privilege drop. EOF, a failed send or expiry before release makes the stage exit. The acknowledgement attests to this release boundary. Provider exec can still fail normally. Only that branch can invoke the payload. The stage owns the absolute path to `setpriv`, the fixed uid/gid 1654, clear-groups and no-new-privileges flags. User argv starts after its own literal separator. No command is interpreted by a privileged shell at this boundary.
6. **Commit.** GO can start a child even if its reply is lost. After timely `RELEASING` and successful required running-manifest publication, the original host commits the validated offer under a single per-launch decision gate before returning its launch reply. Under that gate arbitrate cancellation, absolute expiry, teardown and successful admission. Recheck monotonic time there. A cancellation or expiry that wins discards the offer permanently. A cancellation after commit cannot rewrite history. A rapid normal exit after release is valid. The positively live proof belongs to the earlier pre-exec instant.
7. **Persist and finalize.** The first serialized ordinary custody observation of the committed launch materializes the exact immutable `linux-placement.json` revision 2. Use the store's no-overwrite publisher and byte-identical replay. Include the bound IDs, boot ID, PID, raw ticks, tracked UTC start and controller mask. Associate the file with the live accepted attempt and its matching tracking and native-intent records. Keep the random challenge on the channel only. A raw, staged, unsupported or conflicting file grants no authority. Check native root exit via the original runner's `Completion`, then retain ordinary population, fence, seal, drain and exact producer/accepted receipt checks. A live descendant yields Draining. A natural receipt has zero active processes and null termination fields. Re-reading an accepted terminal receipt returns its original bytes.

Use a fixed-size, versioned binary frame per message, with explicit type and length, fixed byte order and one GUID representation on both ends. Cap a frame at 256 bytes. Read exactly the specified frame, reject wrong size/type/order, truncation, repeated challenge or incompatible version. One connected exchange per attempt, backlog one, no reconnect or buffering across launches. Use close-on-exec descriptors and cancellable nonblocking socket I/O. No control bytes go through the PTY, stdout, transcript or provider environment.

## Deadlines, failures and restart

Use a provisional **5 s total placement budget**, capped by the remaining client request deadline with 1 s reserved for the reply. The client stamp includes time before host admission. The host also clamps it against its own receipt time before `_admission.WaitAsync`. Pass the same absolute cutoff through queueing, required setup, identity capture, shim reads, socket operations, GO and final commit. Each side rejects equality with the cutoff. The helper independently expires even if the host disappears. Keep the existing 30 s client reply limit. If the caller cancels a sent, outstanding tracked Linux launch, close that request connection before another request can acquire it. While dispatch awaits the launch, arm one event-driven Unix peer-hangup watch on the existing pipe socket. It feeds the same decision gate, consumes no frame and is disposed with the request. The runner reconciles an uncertain reply by reconnecting to the recorded host. The absolute cutoff covers a lost cancellation signal. The ordering authority is the original host observing cancellation versus committing the offer.

Only the original host can decide or write a placement. Bound the read-only capture to one per tracked PtyHost, ignore any result after the gate closes, and never hold admission while joining it on disposal. If a best-effort spawn identity read needs a blocking syscall, use at most one host-owned read returning inert data. Race only its result against remaining time and cancellation, give it no socket, journal or release capability, and retain ownership through completion and teardown. Close the channel on expiry. A blocked kernel read in the helper may return late, at which point it must recheck the cutoff before continuing. The host never waits for that read under admission after expiry. Existing mandatory manifest/intent/tracking writes have their own I/O cost. Record those phases separately. Moving a synchronous optional write onto a worker with access to the journal would reintroduce the review defect.

| Interruption or observation | Host and shim outcome |
|---|---|
| Unsupported helper/protocol, admission cancelled before native intent | Refuse the new tracked launch before spawn where detectable. Ordinary sessions use their existing backend. NeverStarted requires the existing durable pre-intent proof. |
| Kernel placement failure, invalid peer, identity discrepancy, unreadable live stat, missing controller, mixed members, or timeout before any GO | Withhold GO, close, and have the shim exit without payload exec. After native intent, retain the Porta connection, ledger and container for reconciliation. Report the tracked start failure and Unknown. No placement or natural receipt. |
| GO write may have reached the shim, missing RELEASING, or cancellation/expiry after observation but before commit | A possibly running child keeps its tracked handle and exit/output subscription. Preserve launch success when the spawn and required tracking succeeded and GO may have been delivered. Suppress placement and natural finality. A lost client reply never authorizes a second spawn. |
| Placement-only namespace read, file write or flush fails | The prior `LaunchedMessage` and tracking remain valid. Mark natural proof unavailable for this attempt. No launch-failure record or natural receipt. A conflicting immutable file is an integrity fault. Ordinary observation cannot terminate the tree. |
| Runner reconnects while the original host lives | Reattach to the exact recorded host, binding and pipe. Query the committed decision or accepted bytes. Retry neither the handshake nor the launch. Duplicate requests use the existing single-launch guard. |
| Host dies before GO / after GO / after proof / after producer receipt | Before GO the shim exits on EOF/deadline. After GO it may run inside the cgroup. Without the original observer, outstanding or on-disk placement alone cannot issue a receipt. Use existing exact producer-receipt validation/replay when available. Otherwise retain Unknown and the bound explicit-release/recovery path, including the live-host refusal and dead-host namespace/identity checks. |

The shim's wait is a bounded native startup exchange. It introduces no session or task waiting for operator input.

## Rollout and rollback

1. Land the design on master through the Plan owner's settlement/land operation. TestDesign then fixes the short verification roster and separate qualification cases. Keep CARD-1930/1932 and the landed CARD-1929 fixture change distinct from the natural-exit verdict.
2. Build a disposable, isolated `session-testing` candidate from the implementation SHA with its own delegated v1 pids/freezer roots and namespace. Record helper and image digests, effective direct-exec policy, managed source SHA and matching host features. Keep global qualification off. Validate the old helper/new client refusal, and that only a matched runner/host/helper can use the new launch form. An old runner understands the legacy probe, so mixing an old qualified launcher with a new helper is an operationally disallowed rollout order.
3. After ordinary review and native qualification, drain new tracked admissions, roll the matched image as a unit and opt in only on a qualified v1 canary via the existing `SessionRunner:LinuxCustodyQualified` setting. Check advertised capability, verified placement rate, deadline/identity/storage refusal counts, phase latency, and one genuine natural-exit receipt accepted byte-for-byte. A failed native witness, unexpected GO, late proof, mismatched bytes or unexplained Unknown holds promotion. Windows continues to establish membership in the kernel job during suspended spawn. v2 and unqualified Linux stay unadvertised.
4. To roll back, stop new tracked admissions, restore qualification to false, and retain the original hosts for existing generations until their receipts are accepted or they receive an owned explicit disposition. Record unresolved binding, namespace and container IDs. Restore the previous matched image with qualification off and recheck ordinary launch and advertised backend. Retain immutable store contents and existing cgroups under their recorded ownership. Legacy terminal receipts remain replayable. An older reader rejects revision 2 for natural finalization, and a new host cannot upgrade an incomplete revision-1 execution.
