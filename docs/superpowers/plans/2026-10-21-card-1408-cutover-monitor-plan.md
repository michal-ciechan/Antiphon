# CARD-1408: post-cutover Postgres monitor and latency rollback trigger

Stage C3 of CARD-1401. Parent plan: `docs/superpowers/plans/2026-10-21-card-1401-postgres-to-server2-plan.md`, decision D-11 and phase 5. Base `13048a2eb356446f4f14960249d7fde2ce5c51e8` (origin/master). Script only. No Antiphon.Tests project, no database, no Docker, no live HTTP in tests.

## Scope

- `scripts/postgres-cutover-monitor.ps1`: read-only monitor. Modes `Plan` (default), `Baseline`, `PreWindow`, `Watch`. Every mode is a dry plan until `-Execute`. Endpoints are parameters. The measurement seams (`-HttpGet`, `-TcpConnectMs`, `-Now`) take scriptblocks so the harness needs no server.
- `scripts/test-postgres-cutover-monitor.ps1`: `-Case` harness in the repo's script-test pattern.
- Baseline and result files default to `.antiphon/postgres-cutover/`, which `.gitignore` already ignores.

## Decisions

- **D-1 - Exit codes.** 0 `OK`, 1 `WARN`, 2 `ROLLBACK`, 3 `ABORT` (pre-window), 4 `INVALID` (bad input, missing, older-schema or non-finite baseline, unmeasurable, an unreadable failure count, or an unexpected error). `ROLLBACK` and `ABORT` are also printed as their own line so a runbook or scheduled job can grep for them.
- **D-2 - Rollback rule (D-11).** `Watch` rolls back when the fresh pipeline median is above both `-MedianFloorMs` (1000) and `-MedianRatio` (3) times the baseline median, or when the window's dispatch plus land failure count exceeds the baseline count by more than `-FailureSlack` (2). A median above the ratio but under the floor exits 0 with a `NOTE` line.
- **D-3 - Pre-window abort.** `PreWindow` aborts when the TCP connect median to `-Server2Host:-Server2Port` (the Tailscale address) is above `-ConnectAbortMs` (20). `-LanHost` is measured as evidence only and never decides.
- **D-4 - Warn.** Exit 1 when the fresh window had sample errors, a failure count above baseline by one to `-FailureSlack`, a health code other than 200, or a version SHA that differs from the baseline. None of these is a rollback trigger.
- **D-5 - Read-only.** GET only. The script never calls `restart-apphost.ps1`, `docker`, `user-secrets`, `psql`, or a `POST`/`PUT`/`DELETE`. The only file it writes is its own JSON. Diagnostics properties whose name or value looks like a credential (password, pwd, token, dsn, connection string, URL userinfo) are dropped or masked. URL userinfo and secret-looking query values (token, access_token, key, apikey, password, pwd, secret, sig, signature, auth) are masked in every printed line, error message and recorded JSON; the request itself uses the unmasked URL. After Review 2f1f73a5: userinfo is masked to the last `@` before the path, query or fragment (a literal `@` in a password), key names are compared after percent-decoding (`access%5Ftoken` is sent as `access_token`), `#` starts a new pair so fragment pairs are masked like query pairs, and a request error is masked where it is caught because a `[uri]` conversion error quotes the whole URL. The monitor sends no delegation token: `GET /api/agent-tasks/{id}` writes poll bookkeeping (`LastPolledResult*`, `FullReadAt`) only for a caller with a delegation token for the parent session, so auth headers must never be added. Out of contract (Review 2f1f73a5 A3): secrets in path segments and keys outside the listed set.
- **D-6 - Failure count (repaired after Review 39af9e8d).** One `GET /api/agent-tasks?projectId=<id>&since=<window start>` list per measurement; `since` is the list's window key (`AgentTaskScope.SupportedListQueryKeys`) and any other key is a 400. Failed tasks are items with `status` `Failed`. List items are `AgentTaskSummaryDto` and carry no land outcome, so each item with `landAttempt > 0`, `landRequestedAt` or `landStartedAt` is read from `GET /api/agent-tasks/{id}` (at most `-MaxLandDetailRequests`, default 50); a failed land is a detail whose `landing.phase` or `landing.publication` is `Refused` or whose `landRequest.state` is `NeedsResolution`. After Review 2f1f73a5 D1 a land also failed when `landRequest.terminalFailureCode` is set and the landing did not publish (a land that threw: `AgentTaskLandService.PersistFailureAsync` completes the request with a `LandRefused` event and never moves the op to `Refused`; a code after publication, `landing_interrupted_after_publication`, ends in a Landed event and is not a failure), or when `events` carry a `LandRefused` event at or after the window start (an unreadable event time counts). A refusal before the attempt counter moved (`landing_protocol_unavailable`) leaves `landAttempt` 0 and, after `ClearPending`, no `landRequestedAt`/`landStartedAt`; the only land-eligible shape left is a `Succeeded` task with `workspace` `Worktree` (`LandApproval.RequestStatusEligible`), so every such item is also a detail candidate. Remaining gap: a pre-protocol refusal of a recovery land on a `Blocked` or `Failed` task with no earlier attempt is not read (a `Failed` task is already counted as a failed task). Known window effects (Review 2f1f73a5 A1), equal in Baseline and Watch so they cancel in the delta: a land that fails in the window on a task completed before it is not listed, and an unresolved `NeedsResolution` is counted in every window whatever its age. A non-200, non-JSON or envelope-less list, an unreadable detail, or more candidates than the cap makes Baseline `INVALID` (no baseline written) and Watch `INVALID` unless a rollback already fired. The baseline is schema 2; Watch refuses an older or incomplete one. `-TaskListUrl` overrides the list URL. After the Final Review at 2324f10d (CARD-1423 A3, A4; plan `docs/superpowers/plans/2026-10-22-card-1423-monitor-followups-plan.md`): the detail cap is sized for the default 30-minute window and at the observed dispatch rate only bites with `-WindowMinutes` around 8 hours or more; the `INVALID` reason names that and the remedy (raise `-MaxLandDetailRequests` or shorten the window). A `Blocked` task whose land threw before the window carries `landRequest.terminalFailureCode` without a publication, so the failure-code rule counts it in every window the list returns it in; it counts equally in Baseline and Watch, so the delta is unaffected.

## Verification design

- V-1 median above both the 1 s floor and 3x baseline exits 2 and prints `ROLLBACK`; above 3x a tiny baseline but under 1 s exits 0; above the floor but under 3x exits 0.
- V-2 failures more than 2 above baseline exit 2; exactly 2 above is not a rollback.
- V-3 TCP connect median above 20 ms exits 3 and prints `ABORT`; a reading near 7 ms exits 0.
- V-4 the default dry plan calls no seam and writes no file; `Watch -Execute` without a baseline exits 4; credential-looking properties are absent from the recorded JSON.
- V-6 (D1) the fake list refuses unknown keys with 400 like the server; ten failed tasks exit 2; the list URL carries `since=`; a non-200 list, a non-JSON body and a body without `items` each exit 4; an empty `items` list exits 0; a latency rollback still exits 2 with an unreadable list; Baseline with an unreadable list exits 4 and writes no baseline.
- V-7 (D2) fake list items have the `AgentTaskSummaryDto` shape with no `landing`/`landRequest`; three failed lands are counted from the detail route and exit 2; detail is fetched only for the four land candidates (the two plain items are `Shared`, which cannot land); more candidates than the cap and an unreadable detail each exit 4. V-7b (Review 2f1f73a5 D1) from the real `AgentTaskDetailDto`/`LandRequestStatusDto`/`AgentTaskEventDto` shape: an exception-ended land (landing `Prepared`/`Unconfirmed`, request `Completed` with `terminalFailureCode`, a `LandRefused` event) counts 1; a pre-protocol refusal (list item with no land hint, request `Completed` without a code, a `LandRefused` event) is read from detail and counts 1; a `LandRefused` before the window followed by a landed land counts 0; three LandRefused-only lands exit 2.
- V-8 (D3 and advisories) sentinels in URL userinfo and an `access_token` query value appear in no Plan/Baseline/Watch line, no recorded JSON, and no child `pwsh` stdout or stderr including request errors; dsn and connection-string-shaped values are dropped by shape; an unexpected error exits 4; a NaN baseline median exits 4. V-8b (Review 2f1f73a5 D2) one sentinel per form, a literal `@` in the password, `access%5Ftoken=` and a `#access_token=`/`#token=` fragment, appears nowhere in the masked exception text, child `pwsh` stdout or stderr (Plan, Baseline, Watch), or the recorded JSON; the fake request converts the URL to `[uri]` first, so the real conversion error is the exception text.
- V-5 the script source has no `restart-apphost`, `docker`, `user-secrets`, `psql`, or non-GET HTTP verb; a child `pwsh` process returns exit code 2 with `ROLLBACK` on stdout.
