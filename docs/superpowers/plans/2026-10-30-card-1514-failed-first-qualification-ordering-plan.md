## Decisions

- **D-1 — Global stable priority.** Only when a nonempty validated history is supplied, prepare the same complete suite plans once, flatten references in existing suite/chunk order, stable-partition references into priority and ordinary work, then execute serially. All chunks intersecting a listed class precede every ordinary chunk across all suites. Within each partition retain old order. Reject per-suite sorting because session-runner, agents-pty and E2E failures would remain behind ordinary antiphon work (`:1174`, `:1319`). Reject repricing or repacking Full: it changes grouping, timing strata and ledger obligations.
- **D-2 — Immutable Full plan, separate schedule.** `antiphon-nightly-dispatch-v1` records `(suite, chunk, canonicalOrdinal, dispatchOrdinal, priorFailure)` plus history digest, canonical plan digest, `preparationComplete`, and loud header `unresolved[]` with suite/class/old-chunk/reason. Never renumber IDs or reorder an already sealed authority document. Absent or empty valid history means exactly today's lazy per-suite prepare-then-run sequence (D-17), not just the same flattened order. Full canonical plan, membership, exclusion census, filters, cost/watchdog fields and ledger row identities remain unchanged. Schedule is diagnostic and grants no authority.
- **D-3 — Class-level selection.** Input is suite + fully qualified bare class identity, using `Get-NightlyBareClassIdentity` for constructor display suffixes. No method selectors, globs, prefixes, display names or manual aliases. Every required expansion and split of a matching class is selected. Full prioritizes whole existing chunks, including their other classes. Partial replans only selected classes using the same production planner and full discovery universe for prefix-collision safety; it does not drag unrelated co-packed classes into the sweep. Full keeps its run-profile/category exclusion behavior; Partial uses the history-profile exclusions and current execution platform under D-21.
- **D-4 — Versioned failure-history JSON.** Add `scripts/export-nightly-prior-failures.ps1` and `scripts/lib/nightly-failure-history.ps1`. The explicit exporter runs on a closed retained run directory and writes a new immutable file outside that run. It reads existing TRX, summary, pinned diagnostic evidence and per-suite planned/discovery artifacts. It does not scrape Markdown investigation tables or consult live services. History is a scheduling hint, never a receipt. See its exact schema and fallback below.
- **D-5 — Conservative fallback with explicit uncertainty.** Use whole historical chunk membership only when exactly bound. If it cannot be reconstructed, retain every observed class and record the unresolved historical chunk plus missing membership; never invent co-packed classes. Full ordering accepts this diagnostic uncertainty and prints it prominently in the schedule header; Partial refuses before launching because an incomplete fallback cannot define the sweep. A named class does not need its old numeric chunk: resolve it against the current complete discovery and prioritize every current intersecting chunk. Reject TRX-only extraction, which loses seven Error observations and the hang.
- **S1 round-2 accounting clarification (D-5).** Ordinary nonzero/FAIL chunks with a complete Failed/Passed TRX are accounted failures, with or without retained plans: select the failed class and report no unresolved entries. Reconcile summary failure only after reading test identities. Independent short-TRX, missing/unreadable TRX, detail and timeout checks remain active. A missing TRX with exactly bound whole-chunk membership may still use D-5 fallback (including an accounted diagnostic failure/hang); a crash with missing-terminal-accounting and an all-Passed TRX is explicitly unaccounted, remains unresolved even with bound membership, and Partial refuses. This asymmetry is intentional: a bound roster repairs missing membership, not contradictory terminal accounting. Missing Partial exclusion context emits a loud warning; S4a/S5 must supply context at every receiving hop. CP-2 retains both crash shapes and the bound missing-TRX control, plus the ordinary-failure witness in both modes and plan shapes.
- **D-6 — Mode-specific resolution.** Deduplicate ordinally by suite/bare-class; malformed schema, conflicting provenance, unsupported version, mismatch between history and its own retained source evidence, path escape or digest mismatch refuse both modes. Unknown/renamed/removed/entirely-excluded classes and zero current required UIDs are resolution failures: Full records each as `unresolved` with reason in the schedule header, emits a loud warning and continues the complete canonical roster; Partial refuses clearly before any chunk. This includes CARD-1613/1618 renames and conservative fallback members. No fuzzy aliases or manual trimming. Empty valid history is a lazy Full no-op and Partial refusal. History `sourceSha` and `policyHash` are provenance of the old run and are **not compared for equality to the current candidate SHA or policy hash**. S1 changes the script census/policy hash, so such a comparison would reject the motivating history. Validate those fields against the bound old evidence only, then resolve identities against current candidate discovery/costs and mode-specific exclusions (Partial: D-21 history-profile rows in the current committed policy); old results never earn new credit. CP-2 accepts valid history with both values differing from the candidate and refuses disagreement within historical evidence.
