## Decisions

- **D-1 Phase 0 changes no namespace and no public type name.** Every production move is a
  `git mv` with identical bytes, provable with `git diff -M100% --stat <base>..<tip>`; the only
  content edits are the file splits and port introductions named per slice. Reason: decision 5 of
  the spec, 700 files of `using` churn avoided, and rename-only commits rebase cleanly over the
  in-flight branches that edit the same files. Rejected: re-namespacing the moved types now
  (`:66`, `:78`), which the spec's own decision 5 forbids and which would conflict with every
  in-flight server task.
- **D-2 The guard is path-based, not namespace-based.** `C1729LayeringGuardTests` reads a
  committed map `tests/Antiphon.Tests/Layering/layers.txt` (ordered path-glob to layer rules,
  first match wins, plus the allowed edges) and an allowlist
  `tests/Antiphon.Tests/Layering/allowlist.txt`. It parses every `server/**/*.cs` outside
  `server/Migrations/` with `Microsoft.CodeAnalysis.CSharp` (already referenced,
  `Antiphon.Tests.csproj:23`) at syntax level only: declared top-level type names index to their
  file and layer; identifiers in each file, excluding trivia and the file's own declarations,
  resolve by simple name; a simple name declared in more than one layer resolves through the file's
  `using` directives and namespace, and is otherwise reported as ambiguous and listed. Reason:
  namespaces no longer say where a type lives after D-1; the map is also the file-to-project list
  that Phases 2-8 will execute, and Phase 4's path rules. Rejected: reflection over the built
  assembly (no file information, needs IL decoding for the static back-references), a full Roslyn
  compilation (slow, needs references) and a `using`-directive scan (too coarse once a Core file
  and an Application file share a namespace).
- **D-3 The ratchet is a two-mode allowlist.** The allowlist header carries `strict: false` at
  first landing: the test fails only on map or parse errors and prints every current violation and
  every stale row. A one-line commit flips `strict: true` once the first mechanical wave has landed
  (P0-G2); from then on a violation absent from the allowlist fails, and a row that no longer
  matches a violation fails. Rows are grouped under `# slice <id>` headers with blank lines so that
  two slices deleting their own rows rebase without a textual conflict. Reason: the brief asks for
  warn-first-then-ratchet, and strict-from-day-one would turn the race between a landing fix and a
  seeded row into a land refusal. Rejected: a count-only ratchet (cannot name the regression) and
  an environment-variable switch (not reproducible).
- **D-4 Core-bound files stage under `server/Application/Core/`**, new ports go to
  `server/Application/Interfaces/`, runner drivers and inverted hosted services go to
  `server/Application/Services/`, host-only misplacements to `server/Infrastructure/Security/` or
  `server/Infrastructure/Agents/SessionRunner/`. The map pre-declares every destination folder so
  move slices never edit the map. Reason: one folder equals one future project; Phase 2 is then
  `git mv server/Application/Core src/Antiphon.Server.Core` plus the Core-tier folders. Rejected:
  `server/Domain/ValueObjects/` for the value types (their namespace stays
  `Application.Services`, which would mislead there).
- **D-5 Digest-changing items leave Phase 0 and ride the Phase 1 re-record.** The staged-helper
  `.targets` move and the `PtyBackend`/`PtyInputEncoding` move each need a csproj edit. Phase 1
  already re-records the digest for the Support and Checkpoints csproj and already pays one
  `P-BUILD` full run; adding these two there costs nothing extra. The brief's rule that Phase 0
  keeps the land graph untouched holds for all 20 slices below.
- **D-6 Ports are extract-interface over used members, registered beside the concrete.**
  `IGitWorkspace`, `ICardFileBoardLookup`, `IPhoneHomeRunnerDirectory`, `IPhoneHomeRunnerClient`,
  `IOrchestratorWorkspaceProbe`, `IAuditService` and `ILandGit` are new interfaces implemented by
  the existing classes; consumers change a constructor parameter type; `Program.cs` adds one
  `AddScoped<IX>(sp => sp.GetRequiredService<X>())` line per port, and
  `tests/Antiphon.Tests/TestHelpers/DelegationTestServices.cs` registers the same alias so the
  hand-built graphs keep resolving. Tests that `new` a consumer with the concrete still compile.
  Rejected: mocking-oriented full-surface interfaces (52 members for `IGitWorkspace`) and widening
  `ISessionRunnerDirectory` (34 files already use it with a narrower meaning).
- **D-7 The Program.cs split is a verbatim cut that keeps global registration order.** Each
  `AddAntiphon<Layer>()` receives the existing lines in their current relative order; the 52
  `AddHostedService` lines keep their positions in the overall sequence, which means the hosted
  services stay in `AddAntiphonHost()` in original order rather than being distributed by layer.
  Reason: `IHostedService` start order and `IEnumerable<T>` resolution order are registration
  order; nothing in the spec requires reordering. Review verifies the cut by diff; a count witness
  is optional (slice P0-I).
- **D-8 Back-references are inverted by moving the driver, not by adding a callback.**
  `LandingVerifier` (78 lines, calls the static `AgentTaskLandService.VerifyWithObserverAsync`,
  `Infrastructure/Git/LandingVerifier.cs:17-34`) and `WorktreeHealthHostedService`
  (`:52` resolves `WorktreeHealthService`) are drivers of application services and move to
  `Services/`. `LocalTaskParkPublisher` keeps its place; the one static it uses,
  `BlockedTaskParkingService.Digest` (`LocalTaskParkPublisher.cs:161,174`), moves into a small
  Core helper that both callers use. Rejected: callback interfaces for all three (more types, no
  layering gain).
- **D-9 Test-count parity is measured only where tests change.** A slice that touches nothing
  under `tests/` proves parity by `git diff --stat <base>..<tip> -- tests/` being empty. A slice
  that touches tests runs `--list-tests` twice on the worktree's native build, at the start
  commit before edits and at the tip, and diffs the sorted output. `--list-tests` ignores
  `--treenode-filter` on this runner (CARD-0403) and is discovery only, so it is complete and
  cheap. Rejected: committing a 21.9k-line roster (conflicts on every test addition).
- **D-10 Slices land one at a time; coding runs in parallel.** The shared files are
  `allowlist.txt` (grouped rows, D-3), `Program.cs` (touched only by the port slices, one line
  each, and by P0-I last) and `DelegationTestServices.cs` (one line per port). Everything else is
  disjoint by construction. Landing order is the wave order below; the orchestrator defers a
  slice whose files are in an in-flight branch (orchestration-loop rule 5).
