# CARD-0491: interrupt a running delegate to deliver a refinement

## Verified findings (master `2f050e3d2b1cc36a3440d5914089aaded7c68a12`)

- The card is **open, not already fixed**. `scripts/delegate.ps1:263-271,857-869` accepts `-Refine` and promises delivery between turns. `server/Application/Services/AgentTaskReplyService.cs:556-628` records the refinement, then enqueues it as `MessageSendMode.WhenIdle`; `server/Application/Services/SessionMessageQueueService.cs:767-782,1371-1397` delivers only after idle/turn end. A long agentic turn can therefore keep it Pending indefinitely. `tests/Antiphon.Tests/Application/AgentTaskRefineTests.cs:29-65` explicitly pins that behavior.
- The Grok file constraint is already handled. `AgentTaskReplyService.cs:612-627,642-677` uses the Grok composer ceiling and a file pointer; `AgentTaskRefineTests.cs:148-180` pins oversized spill. Do not change body transport to solve timing.
- The runner already accepts raw input and a generation/sequence-conditional write: `src/Antiphon.SessionRunner/Program.cs:318-326,394-403`, `src/Antiphon.SessionRunner/SessionRunnerRuntime.cs:795-801,938-995`, `src/Antiphon.SessionRunner.Contracts/ConditionalInput.cs:20-29`. A new runner transport or ACP client is unnecessary for a TUI keystroke. The server must still gate the write against the active task, queue row, session, and composer state; the low-level runner route provides none of those checks.
- `tests/Antiphon.Agents.Pty.Tests/GrokCanaryTests.cs:334-393` measured Grok **1.0.5** accepting Esc and writing `turn_completed stop_reason=cancelled`. This is stale as a universal key claim: [current xAI Grok Build shortcuts](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/03-keyboard-shortcuts.md) say Esc does **not** cancel, and Ctrl+C on an empty draft cancels the turn without quitting. The local binary reports `grok 1.0.40`; its actual Ctrl+C behavior still needs the headed canary. The same xAI guide documents a native `follow_up_behavior="steer"` safe-gap mode, but Antiphon does not type `WhenIdle` refinements into a working composer, so that setting alone cannot deliver this queue row.
- ACP `session/cancel` is a client-to-agent notification, not a command to the already-running TUI. Antiphon reads Grok's ACP-shaped `updates.jsonl` (`docs/agent-kinds.md:301-343`) and drives its TUI through PTY input. Replacing that launch/control architecture is out of scope. xAI's [hook documentation](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/10-hooks.md) identifies Ctrl+C and ACP cancel as turn cancellation, leaving the session alive.
- This is not solely Grok's scheduling gap: every `-Refine` uses `WhenIdle` (`AgentTaskReplyService.cs:624-627`). Claude Esc interruption has a measured marker/no-marker split (`docs/session-runtime-invariants.md:496`; `ClaudeInterruptCanaryTests.cs:37-52,146-152`). Codex's screen advertises Esc, but this checkout does not establish a corresponding safe mid-turn delivery contract. Start with Grok; do not broadcast a generic key to other kinds.
- `CARD-0472` is Done for a separate test-fixture defect; its secondary refine observation remains consistent with this card. It did not add mid-turn steering.

## Smallest fix

**S1 — explicit Grok interrupt.** Extend `delegate.ps1 -Refine <task> <message>` with an opt-in `-Interrupt` switch and the existing `/api/agent-tasks/{id}/refine` request with `interruptCurrentTurn: true`. Preserve the default `WhenIdle` behavior. Reject the option for Queued, Blocked, settled, non-Grok, or unowned sessions with an explicit result; no silent fallback that claims an interrupt. After persisting one marked refinement queue row, use its exact ID and the session's current generation to request one conditional `Ctrl+C` (`\x03`) write through the runner. Serialize the pending-row check with the per-session queue lock. Catch up the transcript first, require the same live Running Grok session and a working turn, and refuse if an overlay/question or existing draft may consume Ctrl+C. If the row has already been sent at a natural boundary, report that outcome and send no key. A stale generation/sequence, unknown runner state, or failed write leaves the refinement Pending and reports `queued; interrupt not confirmed`; never retry the key blindly. Do not create a second refinement on a retry of the interrupt request; make the operation idempotent with the queue-row ID or a request ID.

**S2 — completion semantics.** On `turn_completed stop_reason=cancelled`, keep the delegate Working (`AgentTaskReplyService.cs:680-703,2573-2644` already excludes cancelled turns as reports) and let `OnTurnEndAsync` flush the queued refinement. Declare success only after the existing full `UserPrompt` delivery verdict, never after the keystroke or a redraw. Expose separate `interruptWritten` and `refinementDelivered` statuses so the CLI cannot say a message landed when only a key was written. Document that Ctrl+C stops the current *turn/tool*, not the session, and can leave partial tool output or files. The original `-Refine` remains the non-interruptive choice.

Do **not** add a timer that automatically cancels any busy turn in this slice. A pending message may be a normal completion note or low-priority reminder, and current code has no approved age/priority policy for destroying in-flight tool work. Once explicit interruption is measured, a later policy can opt selected urgent refinements in using the same gated primitive. Do not change Grok's user `config.toml` or switch Antiphon to ACP.

## Risks and decisions

- The xAI key contract has changed since the 1.0.5 canary. If Grok 1.0.40 does not cancel on a single Ctrl+C with an empty composer, keep the opt-in path disabled and return an explicit unsupported result; do not substitute Esc on documentary evidence alone. The canary establishes the actual provider/version contract.
- An interrupt may cancel a tool command mid-write. The caller must explicitly request it. A session being alive does not prove the tool work completed.
- Runner sequence/generation fencing cannot by itself prove an empty composer or protect a terminal overlay. Use the existing screen and modal evidence; an ambiguous observation refuses the key. Transcript pull precedes absence-based decisions.
- A queue row can be persisted before a runner failure. Keep it Pending, report the split outcome, and preserve the existing recovery/delivery attempts. An HTTP retry must not duplicate the row or press Ctrl+C twice.
- If Windows headed credentials or the real binary are unavailable, CP-3 is blocked rather than skipped as green. CP-1/2 alone prove server logic, not the Grok TUI response.
