## Design

1. **Keep the build error.** A real verification failure stores the failing step and the last 40 lines on the land operation. `-Status` prints that step and that output. The event detail keeps the same text, clipped at the existing event cap, with the end retained.
2. **Show the phase.** `-Status` names the current phase (`queue`, `admission`, `git`, `build`, `push`, `confirm`) and the UTC instant it started. A Completed request reports `noProgressSeconds` as 0 and does not print the no-progress counter.
3. **Fail fast on a known-broken target.** The land build compiles the candidate rebased onto the target, so a `build` failure is recorded against the target SHA only when the failing land's own diff could not have caused it: only `CS` compiler errors name a project (an `MSB` error never does), and that diff changes none of the failing projects, the projects they reference (transitively, read from the target SHA), or a build input (`*.props`, `*.targets`, `*.rsp`, `*.sln*`, `global.json`, `nuget.config`, `.editorconfig`, `*.globalconfig`). Changing a project includes its csproj, files under its directory, and every item include and import it names, including links. A glob, an MSBuild expression, an unreadable project, or a diff that cannot be listed records nothing. Within `Landing:KnownBrokenTargetMaxAgeMinutes` (default 30) of the failed land's last write, a land of the same target SHA whose diff changes none of that closure is refused in-process with `target_build_broken`; the detail names the failing operation, task, projects and age, both overrides, then the saved output. A refused land records nothing, so it never renews the record. A later passing build or a `tests` failure is not a broken target. A docs-only skip does not consult this record. Overrides: `Landing:RefuseKnownBrokenTarget=false` (default true), `Landing:ForceVerificationBuild`, and the land body field `ignoreKnownBrokenTarget` (`delegate.ps1 -IgnoreKnownBrokenTarget`), which clears the records when the request is accepted.
4. **The server build stays the gate.** A plain `-Land` with no review evidence is valid. A review does not skip the build.

No timeout or assertion is loosened. `LandingVerifier` still marks a generation ready when the build child exits 0 or 1.
