## Receipt and observation contract

Every row receipt identifies `runId, after, checkpoint, sourceSha, buildSourceSha, buildOutput, hostId, os, sdkVersion, gitVersion, intendedBackend, actualBackend, storage, startedAt, finishedAt, outerNoBuildSeconds, trxElapsedSeconds, buildSeconds, slotWaitSeconds, dbBootstrapSeconds, failed, skipped, reruns`. Missing fields are unknown, never zeros. The test process timer brackets launch through awaited exit/drained output of that no-build test process only. Store all artifacts outside disposable repositories.

Each case records `namespace, class, method, arguments, outcome, observedGitLaunches, launchObserverPresent, fixtureFailureLedger, observations, commands`. Case identity uses the exact declared argument tuple (including whitespace, booleans, enum values and the order of arguments), not just the display name or count. CancellationToken injected by TUnit adds no case. Parameterized Mutation filters use the exact method plus `*`; read the individual argument results from fresh TRX.

Use deterministic fixture scenario IDs/ref names and fixture-owner file bytes for paired runs (derived from class/method/argument key); fresh roots and isolated DB schemas remain unique. Do not erase random GUIDs from compared bytes. Persist actual IDs and join DB rows by them within each run. The observer exports:

| Observation | Required externally visible content |
|---|---|
| Git graph | Symbolic vs detached HEAD; full ref names/targets; ordered commit parents; committed path/blob bytes; explicit missing/error results; source, target, tag and remote identities separately. |
| Index/worktree | Per-checkout staged and unstaged states, ignored/untracked paths and exact byte digests; distinct admin/index paths and shared common directory; clean client reads the same chosen store. Native index-byte cases remain real. |
| Worktrees | Complete registration identity/path/ref/HEAD/locked state; actual file/admin/set-aside/journal existence; bytes before/after deletion and rollback. |
| Service/DB | Fresh-context task base/branch/SHA/source/owner, task status/attempt/session, warning-intent/event/note identity, operation id/schema/phase/pins/source/prepared/target, publication receipt and cleanup/canonical outcome/reason. |
| Fault/ordering | Exact command or durable phase/cut, hit count, before/after disposition, mutation visibility, owned callback/journal receipt and barrier reached/released; verifier count; order of publication, cleanup, canonical advancement. |
| Commands | Sequence, setup/service/observer role, cwd, complete argv, stdout/stderr or production diagnostic category, exit code and actual launch count. Preserve fault scopes and observer independence. |

Only the plan's normalization is allowed: owned-root prefixes, permitted platform separators/newlines, timestamps and a **single bijection per scenario** between fake/real OIDs. Short OIDs must resolve unambiguously through that same mapping. Preserve ref case, parent order/count, tree bytes, index/worktree distinction, exits, production-consumed diagnostics and deletion/sequence outcomes. Never normalize all errors, all missing refs or all OIDs to a common token.

Pilot observation commands needed for its discriminators are explicitly part of S1's narrow read vocabulary: `show <ref>:<path>`, `rev-list --parents -n 1 <ref>`, `rev-parse <ref>`, `branch --show-current`, and index/status observations in addition to the originally named service/setup vectors. S3 already needs blob-tag/`hash-object`, `commit-tree`, `update-ref`, `cherry-pick` and `commit --amend` from its current bodies; do not defer those setup vectors to S5. Contract extensions below precede their first migrated consumer in the same slice.

A fake migrated case has **zero actual Git launches including setup, observers, evidence capture, disposal and rollback**. Actual Git launches in the deliberately native `GitCommandExecutorTests` inside CP-1 are separately tagged `transport-canary`; they cannot be attributed to a FakeGit scenario or excluded to hide an escape. Pure naming/selection cases have zero launches in either mode. Real operational cases must have positive launch counts. Fake contract cases requiring genuine leases/journals use physical storage; S1 pilot/model-only cases use mock storage. Storage is recorded, never mislabeled as process elimination.

Lifecycle setup for `OwnedMutationPreservesLifecycleCallback`: hold an identifiable real Git child using a private fixture-owned synchronization hook until the started callback is observed; the fake fixture uses its before-dispatch latch. These are setup adapters for the same callback/result assertions, not fake certification of native hooks. Do not claim that native Git cannot mutate after launch but before acknowledgment. Early-exit/unknown-process identity, actual stream ownership and worker death remain covered by the unchanged real lease suite.

## Delivery inventory

This migration creates no new asynchronous user-delivery path. S5 preserves existing dispatcher -> committed `AgentTaskDispatchWarningIntent` -> materializer -> `AgentTaskEvent`/`AgentTaskLandNotification` -> `SessionQueuedMessage`, joined by task id, intent id, notification id and `SourceEventId`. Claim rollback and claim-loser bodies retain real transaction failure tests and no-intent/no-session outcomes. `MaterializeAndDeliverAsync` reconciles into the real fixture queue; its name is not proof of terminal delivery. The fixture starts no live session/launch worker. The warning/queue assertions certify persistence and routing, **not complete UserPrompt receipt**. Existing recipient, busy/eligible and crash-delivery suites stay unchanged in their ordinary lanes; no new delivery feature or substitute receipt is claimed or authorized here.

## Proves it works now and guards the regression

The parent plan's V-1–V-11 and R-1–R-5 map to the roster bindings below. Each roster row's assertion is required in both backends without backend-conditioned expectations. New checks strengthen existing bodies; setup preconditions must make alternative outcomes distinguishable (different branch tips, different file bytes, a genuinely moved ref, an actual competing lease). A trace-only assertion is supplementary to ref/file/DB outcomes. Every specified fault/barrier must demonstrably fire. Each retained real case keeps its original native assertions.

No copied fake/real test body is permitted. New class names/methods in the next table are **implementation obligations**, not claims that they already exist. `TestGitBackendTests` is Unit (16 cases); `FakeGitContractTests`, `GitCommandExecutorTests` and `FakeGitMeasurementTests` are Integration and carry this assembly's ProcessSpawnLimit. Any additional process-capable class also carries the limiter. The script tests execute only fixture inputs and never launch checkpoint tests/builds. Existing Slow registrations stay.
