## Verified findings

1. The card describes `Investigate -> Plan -> TestDesign -> design-Review -> Code -> Review`, but the documented cycle is `Investigate -> Plan -> TestDesign -> Code -> Review -> Mutation`; TestDesign hands directly to Code, and only Code hands to Review (`docs/orchestration-loop.md:151-181`). The executable stage predicate has the same six stages and only one Review role (`server/Domain/Enums/AgentTaskEnums.cs:26-78,419-436`). The bundle map also has one Review bundle (`server/Application/Services/InstructionBundles.cs:223-233`). Thus there is no current design-review role or dispatch gate to split. The board's Review *column* is a separate card-state concept (`docs/agent-card-lifecycle.md:5-18`).
2. The create gate counts open tasks in the same project and same role, using `RolePolicy[role].RecommendedInFlight`; it checks the absolute count separately (`server/Application/Services/DelegationOpenGate.cs:43-54,112-132`). Current defaults are `MaxOpenTasks = 6`, `Code = 2`, `Review = 2`, other named stage roles = 1, and desktop `MaxConcurrentTasks = 2` (`server/Application/Settings/DelegationSettings.cs:21-33,334-339`). The pipeline status test asserts those current values and already represents two Working Review rows (`tests/Antiphon.Tests/Application/AgentTaskPipelineStatusTests.cs:112-127,597-619`). The old one-Review-slot observation was valid for its date, but is stale now. The create gate can admit two Reviews in a project if the absolute cap has room; a third Review still meets the Review-role ceiling.
3. The `next: review` token maps to the existing Review role (`server/Application/Services/PipelineHandoff.cs:24-43,75-99`). Both PowerShell surfaces accept that same role (`scripts/delegate.ps1:20-24`; `scripts/routing-pin.ps1:30-36`). Retaining it means existing Review routing pins continue to govern post-Code Review without migration. A new role would require enum, handoff, stage predicate, bundles, scripts, routing pin policy, UI and tests for a stage that is absent from the intended cycle.
4. `MaxConcurrentTasks = 2` is a separate desktop dispatch ceiling (`server/Application/Settings/DelegationSettings.cs:21-25`). Two admitted Reviews may still wait behind other dispatched work; the global `MaxOpenTasks = 6` can also refuse creation. These are fleet/project capacity controls, not evidence that design and post-Code reviews share a role slot (`server/Application/Services/AgentTaskPipelineStatusService.cs:358-365`). Current source defaults are verified here; an operator override or live config could differ and should be read from the running environment before diagnosing a specific live refusal.
