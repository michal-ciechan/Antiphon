# CARD-1974 and CARD-1975 cutover verification checkpoints

Script-only repair of phase 3 sequence verification (CARD-1974, F-1) and rollback stop gate 6 (CARD-1975, F-2) in `scripts/cutover-postgres-server2.ps1`. No production cutover, no desktop run, and no named Docker volume.

## Verification design

- V-1. F1-mismatch. A source whose identity sequence is ahead of a target restored from an older dump fails phase 3. The probe text contains `REFUSED: phase 3 mismatch for sequences`.
- V-2. F1-unreadable. A sequence the probe role cannot read fails closed. The probe text contains `query failed for sequence` and `hidden_seq`.
- V-3. F1-match. An identical pair passes. The probe prints `PHASE 3 match: sequences` and the SHA-256 of the real `last_value` and `is_called` lines.
- V-4. F2-delete-insert. One delete plus one insert keeps the row count and the primary-key high-water mark equal. Stop gate 6 still contains `REFUSED: stop gate 6: the new database has rows the old desktop volume lacks.`
- V-5. F2-identical. A quiescent identical pair passes and prints `ROLLBACK CONTENT fingerprint:` for the content checksum.
- V-6. F2-unreadable. A table the probe role cannot read fails closed with `REFUSED: stop gate 6: row comparison failed. Neither data directory is removed.`

The round 1 review (4f199f91, B-1) found that gate 6 used `max("<pk>")`, and PostgreSQL 16 has no `max(uuid)`. The V-7 to V-10 witnesses use an EF-shaped schema: `Cards` (uuid key, jsonb, timestamptz), `AuditEntries` (no key, duplicate rows, jsonb, timestamptz), `Counters` (identity integer key) and `Legacy` (serial key). Each case after V-7 first runs a control probe on the identical pair and requires it to be clean.

- V-7. F2-ef-identical. A quiescent identical EF-shaped pair passes: `ROLLBACK ROWS clean` and `ROLLBACK CONTENT compared: 4`. Red at 4b33cb6dc with `row comparison failed`.
- V-8. F2-ef-update. An in-place UPDATE of one row refuses with `the new database has rows the old desktop volume lacks.` for each of these: the uuid table jsonb column, the uuid table timestamptz column (+1 microsecond), the keyless table, the identity table and the serial table. After every edit is reverted, the pair is clean again.
- V-9. F2-ef-delete-insert. Deleting one uuid row and inserting another with the same count refuses with `the new database has rows the old desktop volume lacks.`
- V-10. F2-ef-unreadable. A uuid table the probe role cannot read on the target refuses with `REFUSED: stop gate 6: row comparison failed. Neither data directory is removed.`
- R-1. `scripts/test-cutover-postgres-server2.ps1` stays green: W-1 through W-30, including `count(*)` in the phase 3 WhatIf text and the exact stop-gate 6 refusal sentence.

No PC-n is named. Mutation execution is waived (operator 2026-11-12) and is not discharged. A real cutover window is operator-only and is not performed here.
