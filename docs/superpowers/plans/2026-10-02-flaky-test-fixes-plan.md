## Design decisions

### D-1: observe completed readiness decisions under a stopped clock

Authorized narrow seam: append optional `TimeProvider? timeProvider = null` to `RunnerCodexAdapter`'s constructor, store System by default, and pass it only into readiness and, later, submit options. No DI registration, settings, launch, turn-completion or terminal-input change. This existing direct constructor is used by the fake-backed tests; the adapter-level contract requires the seam rather than moving its assertion to another class.

Add test-only `ControlledTimeProvider` wrapping FakeTimeProvider, exposing registered/changed timers through numbered asynchronous signals and explicit `AdvanceTo`. Registration must precede advancement; `CreateTimer` and `ITimer.Change` must both be observed. Do not implement automatic real-time pumping. Add per-call snapshot hooks to ScriptedCodexRunnerClient, separate attempted and completed reads, with asynchronous continuations and unconditional releases.

S1 sequence: start at virtual t=0; let snapshot one finish; wait until the **50 ms poll timer is registered**, then assert exactly one completed snapshot (`snapshot-one-before-first-poll`). Freeze time while installing the second-read barrier. Advance exactly 50 ms, wait for read two to enter, assert two attempts/one completion (`snapshot-two-held`), release it, await ready and assert two completed reads (`snapshot-one-per-decision`). Identify the poll timer by its due time and phase, not merely the first timer (bounded read timers also exist). An extra snapshot within a loop must reach the named count assertion, not hang behind an unannounced third barrier. Dispose the adapter and cancel/drain pending work in finally.

Rejected: longer sleeps, accepting SnapshotReads <= 2 at an arbitrary instant, a global no-parallel fixture, moving all proof below the adapter, or a second production snapshot callback. The authorized seam changes scheduling dependency only; production remains on system time by default.

### D-2: exact resilience boundaries, shared test driver

Add `AdvanceAfterAsync`/boundary-driver support in ResilienceTestSupport, accepting the controlled TimeProvider and **explicit phase signals**. Broaden only test `Build`/`Clock` arguments from FakeTimeProvider to TimeProvider where needed. Preserve old Pump for unrelated callers in this slice; the two named tests must no longer call it. Its eventual wider migration is not claimed here.

For slow-first: pin start; await first handler entry and registered attempt cancellation; advance to just before 10 s and assert cancellation has not fired; advance to exactly 10 s, await cancellation plus first task completion **without advancing further**; assert exact 10 s and one send. Stamp the second request with the same budget, signal its entry instead of polling sends, observe retry/total timer registration, and advance through explicit registered boundaries up to absolute t=30 s. Never advance beyond t=30 while waiting for completion. Assert exact total elapsed and independently observed original deadline. Preserve non-overlap and terminal attempt-timeout semantics.

For short owners: signal runner-list and git handler entry and timer installation separately; check token state immediately below the deadline, advance to exactly 3 s/10 s relative to each request's start, then await the exception/failed result. Cancellation callbacks record the virtual instant and their own phase number before the result continuation is allowed to finish. Hold that result continuation while inspecting the recorded instant; no real delay advances virtual time. Other timer callbacks must be drained/acknowledged before the next requested boundary. Retain existing outer safety cancellation solely to diagnose missing progress; never raise a deadline or use it as a timing tolerance or successful assertion.

Rejected: increasing 12/15 s ceilings, a longer Task.Delay(1), `Task.Yield` as a claim that all continuations drained, manually throwing cancellation instead of exercising production timers, or modifying the retry policy. The second operation's total timer/remaining budget assertion must fail before a missing timeout turns into a watchdog failure.

Linux has three applicable tests plus two explicit skips in diagnostic whole-class runs; final Linux checkpoint selects the three applicable methods. Run GrokRulesArgvPolicyTests on both OSes, including its explicit `isWindows: false` positive control.

Rejected: skipping the whole class, accepting generic conflict, fabricating cmd.exe on Linux, or widening Windows policy to all platforms. No bundle composition is changed despite this class exercising bundles.

### D-4: one worker migration slice, three callers

Keep S4 **one slice**: one worker registry/launch change should not leave one caller on the old host between independently landed migrations. Add `LandProtocolCrashWorker.cs` and `WorktreeRetirementCrashWorker.cs` under TestHelpers, each with an owned marker and typed `{Root, TaskId, Cut, Ready}` payload. Follow LandingRemovalCrashWorker's root/task owner validation, confine Ready directly to that root, and whitelist the seven land cuts plus resume and thirteen retirement cuts plus resume. Supply the existing parent connection only through the child environment, never argv/log/JSON report. Keep TestDbFixture/SharedStoreWarmup unchanged: mode dispatch must occur before test execution and before child database initialization. Migrate C448_V15, post-land PublicationCommitCrashAsync and StartRetirementWorker. Replace the fragile `start.ArgumentList[6] = "resume"` with a new typed resume request. Preserve the parent-owned repository/database, all durable-phase assertions, notification identity/receipt checks, and the intentionally root-only kill at the crash cut (its recovery semantics are not a reason to tree-kill earlier). ### D-5: one clock for submit deadlines and delays

Append the authorized optional TimeProvider to CodexSubmitOptions in `CodexSubmitConfirmation.cs`; use it for every global/poll deadline, poll Task.Delay and blind two-look settle. System remains default for all existing callers, including the direct Pty adapter. RunnerCodexAdapter passes the D-1 clock. Do not alter attempt count, matching, blind policy, total budget, cancellation handling, body send or separate Enter transport.

Drive the **existing eight** submit tests with explicit timer-registration and per-Enter progress signals, using the shared controlled test clock where required. For the two four-Enter cases, establish the first-Enter signal before driving the confirm clock, then advance each registered 250 ms poll only after the previous continuation reached its next timer/Enter barrier. Assert Enter counts 2/3/4 at 250/500/750 ms while the global deadline remains 2 s; thereafter advance to the deadline. For the blind body case, separately drive the existing AbsentSettle delay and require both screen looks. The terminal's existing pre-Enter real delay is outside the confirmation budget; await the first-Enter signal rather than changing transport. All sends use ScriptedCodexRunnerClient, never a model.

Rejected: a 10 s fixture budget as the sole fix, requiring four presses even after the actual production deadline expires, screen redraw as transcript proof, or fake success bypassing the confirmation helper. The old loop may legitimately stop at three presses when 2 s is consumed; the fixture must control consumption rather than redefine that product behavior.

### D-6: hold failed-build child until readiness is observed

Use the existing `New-C578Case -Hold build -FailBuild` mechanism. Child publishes entry identity, both flushed stream markers and build.ready, then waits for its owned build.release. Parent observes matching live identity and readiness, waits for both markers in the wrapper's build.log, and only then releases. Await wrapper completion and preserve actual build exit 37/checkpoint exit 2/no test run. Keep all five exact existing assertion labels.

Wait-C578Ready reports elapsed time, readiness/entry/log state, wrapper/child exit and phase on failure. TestDesign supersedes the proposed deadline increase: use readiness/release/exit events under unchanged outer harness cancellation, without a local elapsed-time success rule. Controlled schedules cover a ready signal delayed past the old ten-second gate and a parent observation deferred until after the old unheld child would exit. Code implements the frozen S6 wait-clock/readiness release in the **test script**, so the deterministic late schedule does not sleep eleven real seconds in every run. Finally releases gates and joins only captured children even if the first assertion fails. Preserve ASCII script encoding.

Rejected: timeout increase alone, treating existing log text as live child ownership, swallowing premature exit, broad process cleanup or editing the production checkpoint driver.

### D-7: inject the underlying clock into the test-only scaled clock

Append optional `TimeProvider? source = null` to ScaledTimeProvider; default System. Obtain initial UTC/timestamp, frequency, elapsed timestamp delta and timer creation from that same source. Scale due/period as today (ceil to milliseconds, minimum one for positive values, unchanged zero/infinite); forward the source timer's behavior without inventing a new production timer implementation. Preserve Advance as an offset change that never fires pending timers.

Rewrite all six tests with FakeTimeProvider as source. Advance source exactly 100 ms -> scaled UTC and timestamp elapsed exactly 1 s at speed 10. Check pending timer before source due and completion at due; offset Advance alone leaves it pending; speed one preserves exact offset; cancellation fires at the scaled due. Invalid speed assertions remain. Timer disposal/cancelled task observation belongs in finally. No upper/lower wall-clock ratio remains.

Rejected: injecting timestamp only while leaving System timers, weakening ratio tolerances, changing production clocks or changing helper defaults for existing consumers.
