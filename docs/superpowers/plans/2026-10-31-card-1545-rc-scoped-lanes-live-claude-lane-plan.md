The current policy does not admit composition of unrelated scoped receipts into Full. S3's live requirement is additive; S4's eventual replacement of any Full obligation requires an independent scoped-coverage policy, complete census and production ledger qualification. No script in this plan is executed against a real cut/publish operation.

Guard details:

- CLI auto-update: disable it process-locally where supported; all rows use the single attested executable seam and immutable owned copy, never arbitrary PATH cl resolution. Attest launched images and the installed source target before/after and at cut/publish. Installed drift invalidates compatibility even if the copy stayed stable; unresolved wrappers or executed-image mismatch are inconclusive.
- Cut race: hold a bounded qualification-input lease that coordinates executable/config updates, freshly challenge the enrolled host, and recheck at the publication boundary. If there is no update interlock, a point-in-time hash cannot guarantee stability across that boundary; enforce no-reuse/fresh-run policy and record that limit. Never claim “hash once” closes TOCTOU.
- Branch reuse: require exact repository/ref, ancestor source and recomputed candidate closure. Receipt hashes alone do not establish branch lineage.
- Clock/host: publisher time is authority for freshness; reject future stamps outside the existing 120-second skew policy, negative durations, impossible order, unknown host/key and stale challenge. Use monotonic timing for durations; a hostname string is not identity.
- Tamper/replay: signature plus enrolled issuer, immutable no-overwrite storage, nonce/run/candidate binding, revocation index and artifact digests. Reject duplicate contradictory receipts and a newer red for the same key. Private evidence retention must survive worktree cleanup.
- Configuration: mechanically attest allowlisted non-secret values and their loaded sources; unknown/unobservable behavior inputs disable reuse. Opaque account identity never masks settings/hook changes or replaces this projection. Do not hash/log secrets.
