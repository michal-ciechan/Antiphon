## Decisions

**D-1 — One test fixture contract, production remains real.** Add an external-I/O command seam in `server/Application/Interfaces/IGitCommandExecutor.cs`, its CLI implementation in `server/Infrastructure/Git/`, and test-only `TestGitBackend`/`FakeGit` under `tests/Antiphon.Tests/TestHelpers/FakeGit/`. Production composition selects the CLI and real `IFileSystem`; only the test fixture factory reads the test switch. Unset or `0` means fake, exactly `1` means real, other values fail configuration. Freeze the choice once per test host; never mutate process-global environment during parallel tests. No production dependency on test types, static backend singleton, PATH substitution, or fake executable.

The executor takes argument vectors, working directory, cancellation and the caller's timeout; it returns stdout, stderr and exit code. Convert the pilot's existing string commands carefully, including the commit message and trailer. Preserve cancellation, simultaneous stream draining, process-tree termination and existing caller error translation. Keep `ILandingGit` as the landing API, and keep its mutation ownership/journaling wrapper. Do not reduce `RunOwnedAsync` to an unowned executor call. S1 changes only the pilot's paths; extend the seam to worktrees and landing in their own slices. The real test backend gives each fixture its own HOME/config, identity, local remote and noninteractive Git settings; never read a developer's credentials or global Git configuration.

**D-2 — A model with explicit supported vectors, not a canned response map.** Model repositories, immutable commits/parents/trees, index, working files, HEAD, branches/tags, separate linked-worktree indexes/admin paths, remote refs and fetch observations. Use stable synthetic OIDs with real-shaped formatting, but compare graph identity rather than expecting real Git to create the same hash. Update refs only on successful commands. An unsupported command/option/quoting form throws and records a fixture failure; teardown fails even if application error handling swallowed that exception. Never return default success or fall back to Git. Cancellation and injected faults must not leave an acknowledged state transition that never happened.

S1 implements only its measured command vocabulary: `init`, fixture `config`, `add`, `commit` (including trailers), `checkout`/branch creation and listing, `rev-parse HEAD`, `rev-list -n 1`, tags/listing, `log -1 --format=%B`, `merge --no-ff`, and the two-tag text diff. Later slices add only their observed vectors: ancestry/patch-equivalence, worktree registration, fetch/push, ref compare-and-swap and recovery. Setup commands count too. Do not implement an arbitrary Git parser or general merge engine up front.

**D-3 — Shared Git rules over a chosen `IFileSystem`.** Use `MockFileSystem` for the pilot and model contract tests. Inject it at `GitService`'s file/directory reads and writes. The same model can use a fixture-owned real `FileSystem` for worktree/landing tests that retain native lease and journal I/O. That deliberately preserves the existing real lock implementation without a broad storage rewrite; log `storage=mock|physical` separately from `git=fake|real`. All consumers of one repository see the same storage and command model; do not mirror two divergent filesystem states. The real backend always uses physical storage.

This narrows the investigation's blanket MockFileSystem proposal: landing savings primarily come from eliminating Git subprocesses, not pretending an in-memory filesystem has OS locking or crash persistence. Never replace `RepositoryMutationLease`, database transactions, or the native child journal with an always-success fake to get a green comparison. Real PostgreSQL remains real. Tests whose purpose is native Git index bytes, hooks, submodules, symlink/junction resolution, OS sharing, or actual worker death stay on the original real fixtures.

**D-4 — Preserve the body, assertions and independent observations.** Fixtures expose the same paths, filesystem, `RequiredAsync` result checks, clean observation client and before/after command fault hooks. Observers do not inherit the service's injected faults. A fake observer is still model evidence; the real run with its independent remote/clone is the external oracle. Never replace file/ref assertions with inspection of FakeGit's private dictionaries or a trace-only assertion. Record fault hooks actually firing, persisted service outcomes, content, refs, registrations and remote containment.

Normalize only fixture-root prefixes, platform separators/newlines where the contract allows them, timestamps and a bijective OID-to-scenario mapping. Preserve parent order/count, ref targets and ancestry, tree bytes, staged/unstaged distinctions, command exit codes, diagnostic categories consumed by production, sequencing and deletion outcomes. In particular, preserve the missing-tag diagnostic recognized by `GitService.TagStageAsync`. Unexpected diagnostics are failures, not normalization candidates.

**D-5 — Two gates, no automatic expansion.** G1 requires pilot parity and measured benefit before **any** S3+ migration. G2 compares each later slice's exact fake and real selection; do not start the next slice if parity, escape detection or timing regresses. A failed/inconclusive gate returns to the caller with evidence; revise and recommit the plan before authorizing more work. Keep the small pilot and existing real tests independently reviewable. Thresholds below are proposed acceptance decisions, not observations.

**D-6 — Partial migration is deliberate.** Existing real-only fixtures keep their defaults. Only named migrated methods opt into the new factory. This allows a mixed class to retain native methods without a silent fake-to-real fallback: the checkpoint selection and per-case backend receipt identify which contract is under test. Unselected methods remain real and retain their existing nightly/CI coverage. Do not globally change `ScratchGitRepo` or `LandingGitFixture` defaults for their other callers.

Rejected alternatives: a fake `git` executable still pays process startup; LibGit2Sharp introduces another real Git implementation and does not certify CLI behavior; replacing all landing tests at once risks modelling the same mistake as production; separate copied fake/real test bodies drift; removing Slow/limiter metadata before new evidence hides cost or weakens isolation; an unconditional full-suite run obscures this controlled experiment.

## Measurement and expansion gates

In S1 provide per-case JSON receipts from the test fixture, outside any disposable repository: sample row, backend/storage, class/method/arguments, outcome, normalized final observations, command trace and actual Git-launch count. Count setup and observer launches as well as service calls. A missing launch observer or a missing receipt is unknown evidence, not zero. For migrated paths, a fixture guard rejects accidental construction/use of the real executor in fake mode; contract tests prove it fires. Audit direct `Process.Start` and `new LandingGit` paths in the changed dependency graph as well.

CP-3–CP-8 are three paired runs of the exact `GitServiceTests` filter at the same S1 commit and host. Alternate order R/F, F/R, R/F. All reuse CP-1's isolated build in one checkpoint invocation. Each test case gets a new repository; no cache/state carries between backend runs. No benchmark warmup or hidden rerun is authorized. Record first-run effects separately. Keep Git version, SDK, OS, storage, host/load, slot wait, complete roster, failed/skipped/rerun counts and command counts.

Use outer **no-build test-process wall time**, plus TRX start/finish elapsed and per-case durations; exclude build and slot wait from the comparison and report them separately. Do not sum overlapping durations and call that wall time. The pilot does not boot a DB; broader slices report DB bootstrap separately but include it in end-to-end class wall time. If checkpoint artifacts cannot isolate a metric, add a narrow timing/export hook to the fixture/driver interface in S1 with verification; do not manufacture wall time from case sums. Prefer existing checkpoint timing/log data, and avoid changing scheduling.

After the S1 invocation terminates, write a local `.antiphon/fakegit-pilot-source.json` pointer containing its exact run directory/id, manifest hash, tested S1 SHA and CP-3–CP-8 row paths. Do not select the newest run by glob. CP-9 reads this explicit pointer, verifies all paths/receipts belong to that run, and writes immutable comparison JSON/Markdown under `.antiphon/fakegit-evidence/<tested-sha>/<run-id>/`. S2 changes only the results document and evidence pointer; it may not change the pilot/executor/model/comparer sources after sampling; otherwise resample the S1 group as a reported rerun. The comparison script rejects stale, mixed-host, mixed-SHA, duplicate or missing sample evidence. Export a small class-duration record keyed by commit, host, run, row, class, backend, outcome and rerun reason; no central telemetry service is part of this work.

**G1 (CP-9):** all six pilot rows execute the same complete twelve-method roster with zero failed/skipped; all semantic parity observations agree; all required negative contract cases pass; every fake sample has zero Git launches and real operational samples have positive launch counts. Let R and F be the medians of the three real and fake outer no-build durations. Pass only if `F <= 0.70 * R`, `R - F >= 1.0 second`, and each of the three paired fake runs is faster. Report medians, min/max, absolute and percentage changes for outer wall and the operational subset. This is a go/no-go experiment, not a statistical claim about the suite. Noise, invalid isolation, failure, no material gain or parity drift holds S3+. Record why; retain real default for any unproven migration.

**G2 (each S3–S10):** compare the exact paired checkpoint rosters and observations at that slice's SHA, zero failed/skipped, zero fake Git launches, and a lower fake outer no-build wall time. Report the remaining physical I/O and DB costs. Each slice's first fake row includes a build, so compare its test-process portion only, never the whole build+test row against a reused real row. Capture the real/fake per-class saving even for grouped S5. Commit the comparison/coverage ledger before the next slice. A noisy one-pair result is inconclusive: it authorizes no unlisted reruns or further migration; bring a revised, bounded measurement group to TestDesign. No class loses native assertions to satisfy G2.

## Handoff and boundaries

TestDesign pins the exact current case roster and discriminating assertions for these closed selections. Class- and method-segment OR syntax follows the documented TUnit 1.44 form. A changed requirement or newly discovered seam needs a reviewed manifest revision before Code; there is no implied extra test lane. The full native removal matrix runs on Windows because one existing argument deliberately skips on Linux; no native skip counts as qualification.

No implementation, build, benchmark, card mutation, activation or deployment is authorized by this Plan deliverable itself. Later Code is bounded by the accepted TestDesign manifest. No changes to CARD-0792, CARD-0793, queue clocks, PostgreSQL design, checkpoint scheduler, provider fakes, automatic cleanup rules or live stack belong in these slices. A central test-history service and migration of every Git fixture are future work.

Plan publication requires an actual push to the task branch and literal matching local/remote SHA proof. Task success alone is not publication evidence.
