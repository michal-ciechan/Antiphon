# CARD-0494: close the landing recovery coverage gaps

Baseline: `2f050e3d2b1cc36a3440d5914089aaded7c68a12` (this worktree's starting HEAD and the remote `refs/heads/master` observed with `git ls-remote`, 2026-09-27). The local `master` ref at `25564530c` and local `origin/master` tracking ref are older; neither is used as the code baseline. CARD-0488 shipped in `e6826120`; its landing safety fix is present. This plan changes no production or test code during Investigate.

## Verified findings

1. **The two old regressions still do not isolate the two guards.** `AgentTaskLandService.cs:545-571` allows an unpublished operation to resume only with a complete source snapshot bound to the same request, and otherwise refuses a schema-1 request before resolution. `AgentTaskLandingProtocol.cs:622-640` independently refuses an unpublished operation without reviewed identity, approval request, or remote snapshot. `AgentTaskLandApprovalRecoveryTests.cs:514-590` reaches both through `LandingProtocolHarness.RunAsync`, which calls the service (`tests/Antiphon.Tests/TestHelpers/LandingProtocolHarness.cs:108-145`). The legacy case asserts the exact `legacy_review_binding_required` reason; that gives some service-side margin, but neither case directly exercises the protocol guard without the service. A separate protocol-entry probe and an explicit no-Git-mutation service probe are still warranted. CARD-0688 added another schema-1 refusal for unpublished pre-push phases (`AgentTaskLandingProtocol.cs:73-80`); design the protocol probe with a schema-3 operation missing one source snapshot field, or with a retained schema-1 `PushStarted` operation, so that the probe actually reaches the guard.
2. **Successful push with lost confirmation is still blocked by later source movement.** A durable `PushStarted` operation hits source-remote and local-source rechecks at protocol entry (`AgentTaskLandingProtocol.cs:163-168`) and again before target observation (`:261-267`); source movement throws `source_remote_changed` (`:622-640`), although the later `ObserveAsync`/`ConfirmAsync` path (`:266-296`) could establish that the saved `VerifiedSourceSha` is already on the target. `C488_PublishedPayloadSurvivesSourceMovement` (`AgentTaskLandApprovalRecoveryTests.cs:706-727`) only checks operation ID and SHA, not publication or caller outcome. `docs/superpowers/plans/2026-09-11-card-0488-land-source-freshness-plan.md:146,150` explicitly calls for read-only reconciliation of a saved publication intent before classifying source change.
3. **The drawer bug is fixed.** `client/src/features/delegations/TaskDetailBody.test.tsx:180-182` expects both `Approved original` labels and checks both SHAs (CARD-0697 commit `1bd8dc1f4`). No drawer edit or checkpoint is needed.
4. **The deferred V/R claims are narrower under today's code.** `AgentTaskLandApprovalRecoveryTests.cs:819-882` matrix methods call selected existing methods, not every crash cut in CARD-0488 V-6/V-7. The `C488_ReviewToLandReceiptMatrix`, `C488_ReviewDeliveryCrashMatrix`, and `C488_ReviewEvidenceCrashRecovers` methods in `tests/Antiphon.E2E/AgentTaskLandDeliveryE2ETests.cs:275-296` delegate to land-outcome tests and do not produce and deliver a real Review report. `AgentTaskLandSourceFreshnessTests.cs:80-132` verifies the detached nonce by Git `show` while the harness uses a controlled verifier; it does not compile and run the detached fix through the real landing verifier. These remain evidence gaps. The proposed schema-1 Prepared late-bind **success** case is obsolete: `AgentTaskLandingProtocol.cs:73-80` now refuses that unpublished legacy phase as `landing_schema_superseded`. Retain a precise refusal/repair-path test, not a success assertion for retired behavior. The original CARD-0488 plan lists 158 PCs (`:276-627`) and a 795-minute mutation budget (`:683-700`); CARD-0488 records only two independently run PCs. There is no complete PC evidence ledger in this tree for the other roughly 156. Treat them as a separate post-land Mutation obligation, with each current control revalidated against schema 3 rather than blindly replaying schema-2 mutations.

## Smallest fix and handoff to TestDesign

### S1 — independent guard tests

Add focused tests in `AgentTaskLandApprovalRecoveryTests`: (a) schema-1 unpublished operation/request through the service, with exact refusal, unchanged operation and request identity, and no source-resolution, rebase, verifier, or push trace; (b) call `AgentTaskLandingProtocol.RunAsync` directly under the existing repository lease with a deliberately incomplete **schema-3** source snapshot and otherwise valid operation/request, then require `source_resolution_required`, no mutation/push, and unchanged approval. A test that is green after removal of its intended guard is a stub. TestDesign must demonstrate each single-hunk mutant separately; if a second guard masks it, adjust the fixture rather than weakening the assertion. Keep the normal schema-3 recovery success control.

### S2 — publication reconciliation after push intent

In `AgentTaskLandingProtocol`, for a saved `PushStarted` operation only, validate the immutable operation/request/destination, pin and child-journal evidence, then **observe the target read-only before both source guard sites**. If the exact saved verified commit is contained at the same destination, confirm the same operation and continue guarded cleanup; source movement cannot erase the historical publication. If containment is absent, retain the current source-remote and local-source checks before any retry push; a moved source refuses with publication unconfirmed, while an unchanged source may retry the saved push. An unreadable target also remains unconfirmed. Report an actionable moved-source reason saying the operator must inspect the target and seek a newly reviewed source/task if necessary. Do not adopt a new source tip, rebase, force-push, or replace a post-intent operation. Add controlled interrupted-ACK cases for contained and absent target with source moved, plus an unchanged-source retry control, then one real-Git target-containment case in `AgentTaskLandPublicationTests`. Require target SHA/ancestry, operation ID, publication/receipt, no second push in the contained case, and retained source when cleanup cannot safely remove it. TestDesign should specify the exact refusal and operator action before Code.

### S3 — close the highest-value deferred V/R evidence

Replace the `C488_ReviewToLandReceiptMatrix`/Review crash aliases with one genuine Review settlement → durable evidence → native caller `UserPrompt` → exact approved SHA land request flow in `AgentTaskLandDeliveryE2ETests`. Cover idle and busy recipient plus one crash cut, with complete body/ID/SHA and no duplicate delivery. Add a real landing-verifier/content assertion to the detached B fix path in `AgentTaskLandSourceFreshnessTests`; the published target must retain B's behavior and the independent target commit. Add focused schema-3 crash/boundary variants only where a named cut lacks an executed case; document the V/R coverage map in TestDesign instead of treating wrapper names as full matrices. Preserve the legacy late-bind refusal control.

### S4 — post-land Mutation inventory

After Code, ordinary Review, and confirmed land, commission a fresh SourceLanding Mutation task for the remaining CARD-0488 PC IDs. Map each PC to today's guard and exact test, mark retired schema-2 controls with the replacement schema-3 invariant and evidence, execute a red/restore/rebuild/green cycle for each applicable control, and record the independent single-hunk kills from S1. This is not part of the Code checkpoint list. A surviving mutant or new safety defect returns to Code.

## Risks and cost

- Reconciliation must distinguish observed target containment from push exit, local branch state, an old tracking ref, or screen/log evidence. An unreadable target remains unconfirmed. Git does not atomically lock source and target refs; the saved approved payload and last source observation remain the safety boundary.
- Direct protocol tests must use a held repository lease and a fixture that reaches the intended guard. Real-Git and native tests may be slow; keep their existing process limiter/isolated runner and report counts from fresh TRX, not wrapper aliases.
