# CARD-0266 — a canceled-but-typed queue row can fuse into the next delivery

**Date:** 2026-10-22 · **Stage:** Plan (task a5950745) · **Base:** origin/master `3f54023d6`
· **rc:** `0714a9a89` carries the same code (see rc applicability).

## Outcome in one line

The defect is live. Cancellation of a queue row is bookkeeping only. The one composer guard that
protects later deliveries, the CARD-0501 F1 hold, reads only **Pending** rows, so a row that was
typed in this generation, never confirmed and then **Canceled** is invisible to it. The next flush
then types its body on top of the orphan, and one Enter submits both. Fix: extend the hold to
canceled typed rows. Reuse the CARD-0650 composer judgement (transcript first, then Claude's
composer box, then the whole head on screen) and send no clearing keystrokes.

## Failure shape, in words

1. Row X (any origin) is typed into the composer in generation G. Enter is withheld (`NoComposerEvidence`) or swallowed, so X stays Pending with `DeliveryAttempts ≥ 1`, `LastDeliveryGeneration = G` and `SentAt = null`.
2. Row X becomes Canceled through any unguarded site in A2. The body still stands in the composer.
3. Row Y is enqueued. The flush loads Pending rows only, so the F1 hold sees no held-back row and the CARD-0650 hold sees no expectation nudge.
4. Y is typed after X's text, and Enter submits `X + Y` as one `UserPrompt`. Head-window verification of Y fails, and the contains-match late-confirm marks Y Sent for a prompt it does not own.

In the harness this is: `PrimeComposer(X)`, cancel X, seed Y, flush. `FakeAgentProtocolAdapter`
appends typed input to `_composer` (`:492`), so `SubmittedBodies == [X+Y]`. That is red today.

## Decisions (stated defaults; the caller may override)

- **D-1: hold, don't clear.** A canceled typed row of the current generation holds new typing until
  the composer is shown clear, exactly as F1 does for Pending rows. *Rejected:* a Ctrl+U or Ctrl+C
  clear before typing. It is unproven on multi-line and collapsed pastes, Ctrl+C interrupts a
  working turn, and it can eat operator text (A4). *Rejected:* Enter-only submit of the canceled
  orphan. It delivers content the queue decided not to deliver, and with a collapsed paste the
  head check that authorizes Enter-only cannot pass anyway.
- **D-2: one queue-level predicate, not per-site guards.** Patching around fifteen cancel sites to
  refuse typed rows is whack-a-mole, and a human Drop of a parked row is a legitimate cancel.
  The hold lives where typing happens, so every present and future cancel site is covered.
  *Rejected:* adding a `DeliveryAttempts == 0` guard to the supersession cancel only. That fixes one
  site, and the row it leaves Pending gets a CARD-0501 re-type when its head is not visible, which is
  the same fusion.
- **D-3: the orphan predicate.** A row is an orphan when `Status == Canceled`, `DeliveryAttempts > 0`,
  `SentAt == null`, `!DeliveryGenerationChanged(row, G)` (the existing helper, including its
  legacy-null arm), and there is **no `UserPrompt` record of any text** above its typing floor:
  `LastDeliveryBaselineSequence`, or the `LastDeliveryStartedAt − tolerance` arm, the same two
  floors `LateConfirmAttemptedMessagesAsync` uses. Any submitted prompt after the typing proves the
  composer was emptied since, so the orphan is resolved permanently. This is transcript-confirmed
  evidence, and it stops a long-dead orphan from holding every later non-empty composer.
  *Rejected:* matching the orphan's own body text. A fused submit makes the record start with X,
  and an operator who submitted their own text also emptied X; both still resolve under "any
  UserPrompt".
- **D-4: screen judgement reuses CARD-0650's.** Extract the snapshot half of
  `ExpectationBodyBlocksComposerAsync` into one private helper. It holds when there is no snapshot.
  For Claude: a readable box that is empty on two snapshots releases, a non-empty box holds, and an
  unreadable box holds. For other kinds, the whole head on screen holds. The expectation hold and
  the new orphan hold both call it. This catches the collapsed-paste incident shape that
  head-visible alone misses.
- **D-5: a defer, never a park or kill.** No attempt is charged and no row status changes, including
  the orphan's (it stays Canceled). The log line names the orphan id, and the release is a cleared
  composer, any later `UserPrompt` or a new generation.
- **D-6: scope.** This covers the queue flush (`FlushAsync` after the F1 hold) and the
  expectation direct send (`SendExpectationNowAsync`, whose composer-safety list names F1 rows
  but not orphans). Human Send-now keeps its operator-intent semantics and is not gated. That is
  recorded, not changed.
- **D-7: no new attention row in this card.** The hold is visible in logs only, the same as F1
  today. The aging-undelivered-note attention row is CARD-0264's secondary finding 2 and belongs to
  its own card. The handoff names it as a follow-up if none exists.

## Failure modes of the fix

- **F-1 strand:** an orphan whose composer the operator never clears holds that session's queue
  (the incident orchestrator would hold until a human clears its composer). This is accepted
  as the lesser harm versus a fused prompt (D-1). It releases by itself on any later `UserPrompt`,
  for example when the operator types and submits anything, or on a relaunch.
- **F-2 Claude-box ghost frame:** handled by `ComposerStaysEmptyAsync` (two empty reads).
- **F-3 orphan typed but never rendered** (the write died in transit): the Claude box reads empty
  twice and releases correctly. For other kinds, no head on screen means release, as in F1.
- **F-4 snapshot unavailable:** holds (F1/0650 parity). This changes
  `AgentTaskCheckSweepTests.the_flush_cancels_a_settled_check_already_typed_once_before_it_retypes`,
  which pins the defect ("the next completion note is typed after the canceled check"). S1 rewrites
  it to the corrected contract (see the slices).
- **F-5 query cost:** one extra indexed read per flush (Canceled ∧ attempts > 0 ∧ SentAt null ∧ this
  session), bounded by generation. It runs only when F1 did not already hold.
- **Out of scope, recorded:** a Pending typed row whose head is not visible is re-typed by the
  CARD-0501 retry path, so a collapsed paste could be doubled. That is a separate pre-existing gap,
  worth a follow-up card.

## Verification design

The red witnesses are R1 and R2, plus the rewritten sweep test. Each one fails at base on the
specific assertion `SubmittedBodies`/`Runner.Writes` (a fused or written body), never on setup.
A test that cannot go red is a stub. If R2 passes at base, the harness is not modelling the
composer, so stop and report. The guards are G1–G4, the twin, and the existing F1 cases
`Parked_head_*` and `Cleared_composer_*`. They pass at base and after the fix, and they bound the
predicate on generation, typedness, transcript resolution and cleared composer. The CARD-0650
regression is `ExpectationDirectDeliveryTests` plus `ExpectationHoldReleaseEndpointTests`: the
extract-method refactor must leave them all green. Platform: everything is Antiphon.Tests on the
shared Postgres fixture, so it runs on Linux. The lane is the default runner (`server2` per
`GET /api/runner-defaults`). No `-Runner` or `-Platform` pin is needed.
