## Decisions

- **D-1 - Userinfo runs to the last `@` on the same line (A1, amended by DEF-1).** `http://u:1234/S3@h/...` parses in .NET as host `u`, port `1234`, path `/S3@h/...`, so no credential is sent; but a value meant as userinfo whose password holds `/` printed unmasked in `PLAN`, `MEASURED`, `UNREADABLE`, `SAMPLE-ERROR` lines and the JSON. The first cut masked from `://` to the last `@` before whitespace, a quote or an angle bracket (`[^\s"'<>]*@`); the Final Review (3a27a954) found DEF-1: .NET keeps `'`, `"`, a space, `<` and `>` as part of the password (`[uri]"http://u:SENT'q@h/x"` has userinfo `u:SENT'q`, the apostrophe raw in `AbsoluteUri` too; the others are escaped there and raw in `OriginalString`), so such a password printed unmasked in `PLAN` lines, the result JSON `server`/`url` fields and the recorded request error. `Hide-CutoverText` now masks from `://` to the last `@` on the same line: a newline is the only terminator and the password may hold any other character. `Test-CutoverSecretValue` classifies a value by the same rule. Additionally the raw and escaped userinfo forms of the given `-ServerBaseUrl`, `-PipelineUrl` and `-TaskListUrl` (and of each requested URL in its request error) are replaced wherever they appear on every surface (`PLAN` lines, result JSON, request errors, exception text), so a message that quotes the credential without its URL is covered. Over-masking is accepted: a literal `@` in a path or query, and a URL followed by whitespace and then an `@` elsewhere on the same line (`http://h/x and mail a@b` becomes `http://<redacted>@b`); the request itself still uses the unmasked URL. The D-11 rollback reasons, verdict lines and measured numbers stay readable (the forms carry the `user:` part, so they never match a bare number).
- **D-2 - A plain value that decodes to a secret is a secret (A2, amended by DEF-1).** `x=y%26token%3DS` reaches the server as `x=y&token=S`; the key `x` is not secret-looking, so the value printed whole. For a non-secret key the value is percent-decoded (repeatedly while it changes, so a double-encoded pair is found) and, when the decoded text would itself be masked (an embedded secret pair or a URL with userinfo), the whole value is `<redacted>`. A benign encoded value (`redirect=%2Fhome%3Ftab%3D1`) is kept. DEF-1 alongside: (a) the server reads `+` in a value as a space exactly as it reads `%20`, so every decoding round is also checked with `+` as a space (`x=y+token%3DS` and `x=y+token=S` are masked like `x=y%20token%3DS`); (b) a value still percent-encoded after the four decoding rounds is masked whole whatever it hides (a pair encoded five times passed before; a benign value encoded five times is now over-masked); (c) a quoted connection-string value, `Password="..."` or `Password='...'`, raw or inside an encoded value, is masked whole with its quotes, and a plain value is searched for pairs of its own (a URL inside a value). Quoted values are not looked for in serialized JSON text, where a raw quote is structure and a quote inside a value is escaped.
- **D-3 - The detail cap names its remedy (A3).** `-MaxLandDetailRequests` (50) is sized for the default 30-minute window; at the observed dispatch rate it only bites with `-WindowMinutes` around 8 hours or more. The `INVALID` reason now says so and names the remedy (raise the cap or shorten the window); the script help documents it. The cap and its `INVALID`, never a partial count, are unchanged.
- **D-4 - Known window effect, documented not changed (A4).** A `Blocked` task whose land threw before the window carries `landRequest.terminalFailureCode` without a publication, so the failure-code rule counts it in every window the list returns it in. It counts equally in Baseline and Watch, so the delta is unaffected. Added to the script header's known-gaps text and to CARD-1408 plan D-6; no counting change.
- **D-5 - Scratch sweep (A5).** The harness records every scratch root it creates and removes any that remain in a `finally` after the cases, with one assertion that every case removed its own root. The five `/tmp/c1408-*` folders on server2 (each holding one result JSON from 2026-10-21 18:32) are removed by hand in this task.

## Verification design

- V-1 (D-1) a userinfo password containing `/` (`http://u:12/SENTSLASH1423@fake.invalid`) appears in no Plan, Baseline or Watch line, no recorded JSON, and no child `pwsh` stdout or stderr including the request's exception text, which quotes the URL .NET would send; the fake still routes the request by path. After DEF-1, `Hide-CutoverText` masks `http://h/x and mail a@b` to `http://<redacted>@b` (newline is the only terminator) and leaves an `@` on a later line alone.
- V-2 (D-2) one sentinel per form appears nowhere on the same surfaces: an encoded secret pair inside a plain value (`x=y%26token%3DSENT`), a double-encoded one (`x=y%2526token%253DSENT`), and an encoded URL with userinfo inside a plain value (`next=http%3A%2F%2Fu%3ASENT%40h%2Fdb`). A benign encoded value (`redirect=%2Fhome%3Ftab%3D1`) and `projectId=p1` are kept.
- V-6 (D-1, D-2 as amended by DEF-1; cases `C1423_ApostropheInUserinfoMasked`, `C1423_DoubleQuoteInUserinfoMasked`, `C1423_SpaceInUserinfoMasked`, `C1423_LessThanInUserinfoMasked`, `C1423_GreaterThanInUserinfoMasked`, `C1423_QuotedConnectionStringPasswordMasked`, `C1423_PlusAsSpaceInEncodedValueMasked`, `C1423_FiveTimesEncodedValueMasked`, `C1423_VerdictLinesReadableWithMaskedUserinfo`) one case per character `'`, `"`, space, `<`, `>` in a userinfo password (`http://u:SENT<char>q@fake.invalid`): the sentinel appears in no Plan, Baseline or Watch line, no in-process or child recorded JSON (the pool-diagnostics string value included), no child stdout or stderr including the request error that quotes `AbsoluteUri` and `OriginalString`, and `Test-CutoverSecretValue` classifies the URL as a secret; the request still routes and measures. Quoted `Password="..."` and `Password='...'` values are masked whole with their quotes, raw in a query, inside an encoded value and alone in a line, while a plain key's quoted value is kept. `x=y+token%3DSENT` and `x=y+token=SENT` are masked like `x=y%20token%3DSENT`; `q=a+b%20c` is kept. A secret pair encoded one to six times inside a plain value is masked and its neighbours kept; a benign value encoded twice is kept. Readability witness: with a credentialed server URL whose password holds all five characters, a Watch that trips D-11 still prints `REASON median 5000 ms is above the 1000 ms floor and above 3x the baseline median 100 ms (300 ms)`, `ROLLBACK`, the `CUTOVER-MONITOR ... medianMs=5000 baselineMedianMs=100 ...` line, a `MEASURED pipeline http://<redacted>@fake.invalid/... medianMs=5000 ...` line and the JSON `"server": "http://<redacted>@fake.invalid"` beside `"medianMs": 5000`, and a request error keeps `request failed for http://<redacted>@fake.invalid/api/x`.
- V-3 (D-3) more land candidates than the cap still exits 4; the `UNREADABLE` line and the recorded `failures.unreadable` name `-WindowMinutes` and the cap; the script help has a `Detail cap:` paragraph naming when it bites.
- V-4 (D-4) a `Blocked` task whose land threw with every event before the window counts one failed land in Baseline and one in Watch, the delta is 0 and Watch exits 0 `OK`; the script header's known-gaps text names the Blocked case.
- V-5 (D-5) the harness's final assertion finds no scratch root left by a case; the sweep removes any that remain. The server2 `/tmp/c1408-*` removal is reported with the count, not tested.

Red witnesses: each `C1423_*` case is committed before its fix and run alone (`-Case`) against the unfixed monitor; these `-Case` runs are the unlisted runs of this task. The green run is CP-1 on the final tip.
