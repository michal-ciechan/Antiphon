## Decisions (stated defaults)

- **D-1 (operator): turn on away paging or not.** The default is to keep it inert, as documented. If the operator wants it, they set `Digest:Enabled=true` and mark one channel `DigestEnabled` (their DM). That one config change activates the Blocked, Decision and Incident pages the card's A2 asks about, with no code. A Code task must not flip it, because it sends real traffic to a real channel.
- **D-2 (operator): where "tell the human about a peer's result" belongs.** The default is the **receiving session**: the standing orchestrator's own instructions. A Claude Code session with remote control can raise a push itself (Claude Code's PushNotification / remote-control surface). Antiphon cannot see the triggering message (G1). It can see only that the session went idle. Recommended action: add a line to the Gym Stat / standing-orchestrator instructions telling the session to push-notify the operator when a peer reports a result. That is an instruction edit, not an Antiphon change.
- **D-3: no `QueuedMessageOrigin.CrossSession`.** Rejected. Antiphon never enqueues these messages (G1), so the origin would never be written. Raw API callers that want completion should use delegate tasks (A4).
- **D-4: no long-poll `/wait` endpoint or webhook.** Rejected for this card. Delegate completion notes already deliver completion to an orchestrator session. A wait or webhook surface is a new public API, which needs its own card if a non-session caller ever appears.
- **D-5: close or park the card.** The default recommendation is to close it, linking this plan as the resolution: A1/A3 rest on a wrong premise (G1), A2 is config (D-1), and A4 is covered (delegate tasks). Park instead only if the operator wants S1-optional.

## S1-optional (not recommended, not authorized by this plan): page on standing-session idle

Build this only if D-1 is turned on **and** the operator asks for Antiphon-side pages in addition to D-2.

- **Seam:** a new `StandingIdlePageNotifier` beside `IncidentPageNotifier` (`server/Application/Services/`), registered with the other notifiers and swept in `AwayDigestHostedService`. It pages each `DigestEnabled` channel once per idle episode of an `AlwaysOn` agent that is not bound to a channel, when that agent's session has gone idle after a turn and no human prompt has followed. Text: the agent name plus the first line of the last assistant text. Dedup works the same as `IncidentPageNotifier`'s per-state marker.
- **Data:** one nullable marker column (for example `Agents.IdlePageSentForTurnEndAt`, timestamptz). The migration is additive only and must be timestamped after `20261022110953_AddPoolProviderProjection`.
- **Red witness:** `StandingIdlePageNotifierTests.Idle_standing_unbound_agent_pages_once`. Seed an AlwaysOn agent with a channel set to DigestEnabled and a stored TurnEnd, sweep twice, and expect exactly one send. Guards: a channel-bound agent gets no page, a non-AlwaysOn agent gets no page, no DigestEnabled channel means nothing is sent, and a new human prompt resets the marker.
- **Risk:** noise. Every orchestrator idle becomes a phone ping. It is inert until D-1. It does not apply to rc as a fix; it is a feature for master only.
- **Size:** 45-60 minutes. If chosen, a Plan amendment adds the closed `### Checkpoints` table. This plan has no table because it authorizes no Code slice, so there is nothing for `import --plan` to validate.
