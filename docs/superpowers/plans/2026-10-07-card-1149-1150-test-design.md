### Delivery inventory

No new producer is added by this design. The producers under test are the existing dispatcher claim, `SessionMessageQueueService.EnqueueAsync`, and `FlushSessionAsync`.

| Path | Producer | Destination | Persistence | Recovery | Receipt |
|---|---|---|---|---|---|
| Refused launch | Dispatcher claim, then launch enqueue throws | One Pending delegation brief | Brief row and goal spill committed before the refusal returns | V-1 / V-16 hold that same row | The row stays Pending. No UserPrompt is required, because nothing was typed. Bytes compared from a fresh scope. |
| Missing brief after Running | Real dispatch `INSERT ... RETURNING` fault, then `SessionStarted` after the Running commit | No brief row | Running is committed; the brief is not | V-10 discovery backfill | One complete UserPrompt after the real flush. A second scan does not backfill. |
| Insert committed, flush cut | Backfill INSERT commits, then the next command throws | That same Pending row | Row id and body already durable | V-11 rediscovery | The same row becomes the one UserPrompt. No second row. |
| Follow-up during the gap | Ui enqueue on either side of the missing brief | Two queue rows | Both bodies durable | V-12 | First flush sends only the original head. Later idle advancement confirms both full bodies once. |
| Concurrent producers | Post-claim enqueue plus two recovery calls | One row | Insertion lock | V-6 | One payload. A delivery, if it happens, is one attributable UserPrompt. |

Substitutes that do not prove delivery: a queue insert, a Sent flag, an ack, a runner list entry, or a screen redraw. Session input is proved only by a complete UserPrompt. V-6, V-10, and V-12 use the real queue flush. The launch sink refusal leaves the fake runner empty. The brief INSERT fault is injected on the reader arm. The Running cut is an `OperationCanceledException` on `SessionStarted` after the Running save. The pre-flush cut is a committed insert. The missing brief is not seeded as setup. Clocks advance 89/91 seconds, the three-minute dead grace, and +11 minutes without sleeping.

### D-7 inherited boot-stall kill

Reproduced on `9ee6d46d3` by `Aged_prompt_only_Working_tick_stops_the_session_and_requeues_once` (filter `/*/*/BootStallWorkingTickCharacterizationTests/*`, 3 succeeded, 0 failed, 46.6s). This is a defect against the session rule that CARD-0079 is the only automatic stop of a Working session. CARD-1149/1150 do not fix it.

What the path does. `TickAsync` runs the overdue sweep at `:373`. `TryFailOverdueAsync` (`:2735`) calls `TaskDeadlinePolicy.EvaluateAsync`. The cheap gate (`:145-146`) returns before any phase query until elapsed reaches the smallest armed limit times `PreviewFraction` (0.8). The smallest armed limit is the boot deadline, 8 minutes (`DelegationSettings.cs:452`), so the preview starts at 6.4 minutes. A 1-minute task never enters. A 9-minute task does. Phase evaluation requires `IsWorkingAsync` (`:164-168`). `LoadBootTurnAsync` (`BootReplyWatch.cs:171-207`) selects `DeadlineKind.BootModelWait` when a real UserPrompt or QueuedUserPrompt exists since `max(DispatchedAt, LaunchResumedAt)` and no AssistantText, Thinking, ToolCall, ToolResult, or TurnEnd exists since that clock (`HasModelReplySinceAsync`, `:86-99`). At 9 minutes the boot fraction 9/8 beats the Code ceiling 9/240 (`RolePolicy` Code still defaults its timeout to 240). `TryFailOverdueAsync` (`:2803`) then calls `TryFailBootStallAsync` (`:2859`). The workspace guard (`:2865-2869`) allows the kill unless the probe is Available and `LastFileChangeAt` or `LastCommitAt` is set. A null probe also allows it. The tail writes `ProviderUnresponsive` through `FailAndNotifyAsync` (`:2890`) and, because attempt 1 is under `MaxAttempts` 2, calls `RetryAsync` (`:2939`). `RetryAsync` calls `StopDelegateAsync` (`:3953-3960`) before it clears `AgentSessionId`, so the stopper records the old session. The runner list is not an input. Dead-session `IsDeadSession` (`AgentTaskLiveness.cs:60-64`) is false for Running and for Starting. The delivery watchdog is a different arm and only selects Dispatched tasks. Stall detection does not kill. CARD-0079 compaction is not registered in this harness, and the runner's compaction-stop count stayed 0.

The aged companion with AssistantText does not select boot, and the 1-minute prompt-only tick does not pass the preview gate. Both stayed Working with an empty stopper.

S1 (dead-sweep hold), S2 (queue identity), S3 (Running discovery), and S4 (watchdog arbitration) do not edit `TryFailBootStallAsync`. They neither extend nor narrow this kill, provided a recovery error is not routed into that tail. S1 and S5 still re-run the characterization because S1 edits the same file.

`C1149_C1150_Working_full_tick_safety` (V-20) asserts the future no-stop result. It is not committed. Disabling boot wait to make it green is forbidden. Title: Boot-stall tail stops a Working session

On master, `TryFailBootStallAsync` (`AgentTaskDispatcher.cs:2859-2959`) fails the task with `ProviderUnresponsive` and `RetryAsync` (`AgentTaskService.cs:3484`) stops the delegate when `TaskDeadlinePolicy` classifies `BootModelWait` (`TaskDeadlinePolicy.cs:172-183`), the session is Working, the workspace is quiet or unavailable, and elapsed has reached `BootModelWaitDeadlineMinutes` (8, `DelegationSettings.cs:452`). A runner that still lists a matching generation is not an input. CARD-0079 is the only automatic stop the session contract allows. Reproduced by `BootStallWorkingTickCharacterizationTests.Aged_prompt_only_Working_tick_stops_the_session_and_requeues_once` at `9ee6d46d3`. Stop killing and retrying Working sessions from this arm. Leave CARD-1149 and CARD-1150 unblocked; their recovery must not edit this tail.

The fifth S2 Final Review (task 818f247a, at 066b302d) found one defect.

- F10: the interrupted-launch backfill (`ResumeInterruptedLaunchAsync`) now
  calls the queue-owned ensure, which inserts the brief and types it at once.
  The resume then saved its "brief re-queued" event. When that save failed,

save detaches its event. Before any input, the resume keeps today's
kill-and-fail path. The boot-stall tail, the CARD-0340 order (attach, ready,
Running, flush) and the dispatcher's ensure are unchanged. No migration.

| Step | Before | After |
|---|---|---|
| "brief re-queued" event save | kill + Failed | logged, event detached |
| `FlushSessionAsync` | kill + Failed | logged |
| "launch resumed" event save | kill + Failed | logged, event detached |
| `RecordLaunchInterruptedByRestartAsync` | already best-effort (own scope, try/catch) | unchanged |

When the ensure typed nothing but the flush delivered, the "launch resumed"
save is also after input; it is non-destructive too. That case was already
destructive before S2; it is fixed by the same flag.

Known limits, unchanged from base. A throw inside a delivery, after typing,
