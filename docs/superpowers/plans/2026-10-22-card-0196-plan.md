# CARD-0196 — Configurable agent/model presets per task type and difficulty, global and per project — plan

**Date:** 2026-10-22 · **Card:** CARD-0196 (`8ddceaa0-dfc1-49e5-bb5b-458a6be2c9a9`) ·
**Status:** plan. **Recommendation: close the card as delivered by CARD-0090, CARD-0332, CARD-0097
and CARD-1275** (D-1). The only part not built is the per-project override. If the operator wants it
anyway, three slices are planned below, and S1 is ready to hand to Code.
**Verified against:** `origin/master` @ `44a0c36d7`. Live facts were read from
`https://antiphon.desktop.codeperf.net` on 2026-10-22.

## Verdict

The card asks for five things. Four of them already exist.

1. **A lookup table from task type × difficulty to (AgentKind, ModelLevel).** Built: this is the
   Role × complexity matrix.
2. **Global defaults.** Built.
3. **An API that reads and writes the table.** Built.
4. **Programmatic resolution, so nobody has to remember a prose table.** Built.
5. **Per-project overrides with "following global" and reset, plus a Global tab in the project
   view.** Not built.

Item 4 goes further than the card asked. The **server** resolves the cell for every ordinary Worker
create. The caller only passes the role, and optionally `-Complexity`.

On the remaining gap (item 5), the data argues against building it:

- **97.5 % of delegated work is on one project.** In the last 30 days the Antiphon project created
  4,356 tasks. Every other project together created 113: markdown-package 68, slides 35, gym-stat 8
  and school-revision 2. The other 10 projects created none. Source: `GET /api/agent-tasks?projectId=…&since=…`
  for every project returned by `GET /api/projects`.
- **The operator does not differentiate even inside the global matrix.** All 45 live cells (3
  any-role rows and 14 roles × 3 tiers) have the same Human chain, `[ClaudeCode/High, Codex/Frontier]`
  (`GET /api/complexity-chains`). `GET /api/routing-pins` is empty. The card's premise was "Design →
  fable, Build → Grok, cleanup → Codex Low". The operator has since chosen one uniform chain for
  every cell, so a second scope would only hold copies of that chain.
- **There are cheaper escape hatches for a one-off project need.** A card pin (`delegate.ps1 -Pin`,
  `routing-pin.ps1`) or an explicit `-Kind/-Level` on the dispatch already overrides the matrix for
  a particular piece of work.

**Recommend closing CARD-0196** with a pointer to this plan. Reopen it with this plan as the design
the first time a second project needs routing that differs from Antiphon's. If the operator keeps it,
S1–S3 below deliver the per-project scope in about 2.5 hours of Code.

## Decisions

- **D-1 (recommended): close the card without building.** Reason: A1–A7 and A11 are delivered.
  A8–A10 would serve 2.5 % of tasks, and today they would hold copies of one uniform chain.
  Rejected alternative: build S1–S3 now. That adds a scope dimension to the walk, the role view,
  the token rules, the expiry sweep and the UI (the CARD-1275 contract alone has 9 test rows) for
  no observed need. Reopen trigger: a second project needs routing different from Antiphon's.
- **D-2 (if kept): resolution order is per level, project first.** The role cell resolves from the
  project's role cell, then the global role cell. If neither exists, the any-role row resolves from
  the project's any-role row, then the global any-role row. If neither exists, config applies. So a
  project override replaces exactly its global counterpart, and nothing else, which matches the
  card's "anything it does not override follows global". Rejected alternative: project any-role
  outranks global role cells. Then one project row would silently shadow 14 global cells, and
  "following global" could not be shown per row.
- **D-3 (if kept): no board-level scope.** A board with no project falls straight back to global.
  Reason: `AgentTask.ProjectId` is the existing concurrency and API-key scope, and no board-level
  routing need has been reported.
- **D-4 (if kept): same table, nullable `ProjectId`.** Rejected alternative: a separate
  `ProjectComplexityChains` table. That would duplicate the token, the expiry sweep and the
  provenance code paths. The existing unique active index becomes
  `(ProjectId, Role, Complexity) NULLS NOT DISTINCT WHERE ClearedAt IS NULL`. Existing rows keep
  `ProjectId = NULL` (global), so the migration is additive in data. The index is dropped and
  recreated, and no rows change.
- **D-5 (if kept): "reset row" is the existing DELETE at project scope, and "reset all" is a new
  scope-wide DELETE.** Both record a reason. "Reset all" sends no per-row token and is
  last-writer-wins, as documented for a no-token write.
- **D-6: rc applicability.** Master only. This is a feature, not a defect fix on the rc.

## Slices (only if D-1 is overruled)

### S1 — `ProjectId` on `ComplexityChain` and project-first walk (~50 min)

- **Files:** `server/Domain/Entities/ComplexityChain.cs` (`Guid? ProjectId`);
  `server/Infrastructure/Data/AppDbContext.cs` (index replaced per D-4; FK to `Projects` with
  cascade delete); a migration timestamped after `20261022110953_AddPoolProviderProjection`;
  `ComplexityRoutingService.LoadChainAsync`/`FindActiveAsync`/`WalkAsync` take `Guid? projectId` and
  apply D-2. `ResolvedFrom` adds `projectRole` and `projectAny`.
- **Callers:** the six call sites (`AgentTaskService` ~960/967/996/3457/4052/4074,
  `AgentTaskDispatcher` ~1866, `ComplexityChainService` ~148) pass the task's project. In
  `CreateAsync`, hoist the `DeriveCallerProjectAsync`/parent project derivation above the default-tier
  routing block.
- **Red witness:** `ProjectComplexityChainResolutionTests`:
  `A_project_role_cell_outranks_the_global_role_cell`,
  `A_project_with_no_rows_follows_global_exactly`,
  `A_project_any_row_does_not_shadow_a_global_role_cell`,
  `A_task_with_no_project_never_reads_a_project_row`,
  `A_plain_create_on_a_project_board_walks_the_project_cell` (the last one goes red until the hoist
  is done).
- **Risk:** reordering the project derivation in `CreateAsync`, which is a hot path. The regression
  rows run `MatrixDefaultComplexityCreateTests` and `ComplexityCreateTests` whole.

### S2 — project API and script (~50 min)

- **Routes:** `GET /api/projects/{projectId}/complexity-chains` returns every cell with
  `effective`, `resolvedFrom` and `followingGlobal: bool`, plus `concurrencyToken` for the project's
  own row. `PUT`/`DELETE /api/projects/{projectId}/complexity-chains/{role}/{complexity}` reuse the
  CARD-1275 token rules. `DELETE /api/projects/{projectId}/complexity-chains?reason=` is reset all.
  An unknown project is 404 and writes nothing.
- **Files:** `ComplexityChainEndpoints.cs`, `ComplexityChainService.cs`, `ComplexityChainDtos.cs`,
  `scripts/complexity-chain.ps1` (`-Project <name|id>`), `docs/antiphon-api.md` (routes and the D-2
  rule), `docs/orchestration-loop.md` §2 (one paragraph).
- **Red witness:** `ProjectComplexityChainHttpTests`:
  `Put_then_get_shows_the_row_overridden_and_others_following_global`,
  `Delete_row_resets_it_to_global`, `Reset_all_clears_only_that_project`,
  `Stale_project_put_is_409_with_the_current_row`, `Unknown_project_is_404_and_writes_nothing`.

### S3 — project view UI (~60 min)

- **Files:** `client/src/features/settings/RoutingSettingsTab.tsx` and `routingSettingsModel.ts`
  (scope switcher Global | project, an "Overridden / Following global" badge per row, Reset and
  Reset all), `ProjectConfig.tsx` (a "Routing" link that opens the tab scoped to the project, with a
  Global tab beside it), `client/src/api/complexityChains*.ts`.
- **Red witness:** `RoutingSettingsTab.test.tsx` cases `C0196 project scope shows following-global
  badges`, `C0196 reset row sends DELETE at project scope`, and `C0196 reset all asks to confirm and
  sends the scope DELETE`.

### Dropped (with reasons)

- Board-level scope (D-3).
- New cell names (`Build-Easy`, `Cleanup`): the role enum already covers them (A2), and adding
  aliases would fork the vocabulary.
- An AGENTS.md row: AGENTS.md already routes "Cards, delegates…" to orchestration-loop.md, which
  owns the matrix rule.

## Verification design

Applies only if D-1 is overruled. Each red witness above is committed failing before its fix. S1's
`A_plain_create_on_a_project_board_walks_the_project_cell` is the end-to-end witness that the hoist
happened. Without the hoist, `projectId` is null at walk time and the test reads the global cell.
