## Decisions

- **D-1 — Preserve custody.** An abort ends a turn, not its task, session or workspace. Keep the cancelled idle boundary and existing queue delivery fences. Reject automatic kill, retry, synthesized continuation, blocking the task to make parking applicable, and new timers: none follows from an interrupted turn.
- **D-2 — Preserve narrow compatibility.** Use exact `TranscriptKinds.StopReasons.Cancelled` / `IsReportBoundary`, not an `end_turn` allowlist. Null/other stop reasons keep their current semantics. Capacity recovery still rejects API errors; boot response detection still accepts them. Adapter API-error policy is unchanged in this card.
- **D-3 — Stamp only observed usage.** Consume the most recent cumulative snapshot at each boundary. No usage since the last boundary means null token fields, not invented zeros. Abort error metadata stays ignored. Reject a new ledger, historical rewrites and a second usage algorithm. Late counts and overlapping replacement turns remain an explicit measurement limit.
- **D-4 — Distinguish interruption from timeout.** Extend `AgentTurnResult` with optional StopReason. A cancelled result is `TurnCompleted=false`, retains diagnostic text/snapshot, and is handled before the caller's success/timeout branches. Retain the existing unfinished run attempt in nonterminal AwaitingInput and the session Running; return control without after-run hooks, disposal or kill. The S4 refinement below supersedes S3's original StreamingTurn retention, which left an automatic stall kill armed. Reject mapping abort to success, timeout, or a new terminal phase. S3 must precede S4.
- **D-5 — Publication is window-specific.** A cancelled owning turn cannot start a reply or append further text/attachments. Keep its correlation, unreserved text and existing delivery receipts. Do not retract already published text or replay an uncertain send. Reject filtering cancelled rows out of the global boundary/window queries: that can join two turns or fall back to an older successful answer.
- **D-6 — Use the attention already present.** The immediate task warning plus PastExpectedIdle is sufficient notification machinery. Improve its evidence for a current interrupted turn, preserving the existing age threshold, kind and UI. Reject another attention kind, scheduler, alert-sink message or automatic prompt. Boot-stall attention retains precedence for an abort before any model response.
- **D-7 — Placement is live policy.** GET `/api/runner-defaults` (revision 2) and GET `/api/session-runners` were read; the catalogue included an eligible Linux runner, an eligible Windows runner and a stale/draining runner. Re-read at dispatch. These ordinary checkpoints need no particular OS: omit `-Runner` and `-Platform`; a reused explicit platform pin can be cleared with `-Platform Any`. Lane names below describe test categories, never a request for a whole-lane run.

### Input-wait / release checklist

The task may remain Working while its process is idle; the card state is separate. The planned adapter outcome also returns while retaining the live session. An already queued message or explicit operator reply can start another turn through the existing input path; that does **not** release its physical seat. An explicit cancel/stop or actual process exit can end the process; ordinary eventual task settlement follows its existing ownership/pooling/release rules. No new release deadline is introduced.

With `BlockedTaskParking:Enabled=false`, **there is no automatic input-wait release deadline** (CARD-1083). Parking never stops a Working task. A stall remains detection/decision only. The configurable 240-minute default task ceiling is not a guaranteed physical release, and an unresolved boot episode is protected even past that ceiling. S5 must preserve that protection. See `docs/session-runtime-invariants.md:169` and `server/Application/Services/AgentTaskDispatcher.cs:3733`.
