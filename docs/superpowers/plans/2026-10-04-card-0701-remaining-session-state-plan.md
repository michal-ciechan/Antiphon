## Decisions

These are implementation decisions within the previously commissioned cache/event direction, not defaults awaiting operator approval.

- **D-1 — Preserve the commit boundary.** PostgreSQL remains authoritative. Extend the existing DI-owned store and its leases; do not replace the fold, read barrier, startup service, synthetic restart append, deletion repair, or disabled-cache rollback. Reject a second working-state cache and TTL working bits: both introduce conflicting freshness rules.
- **D-2 — One consumer read boundary.** Add a concrete `SessionStateReader` for enabled-store versus existing indexed SQL fallback selection. Production consumers use it, including explicit arguments to static policy helpers. Keep the old static SQL helper as an oracle/fallback implementation, with an audited allowlist. Do not use optional null injection that silently leaves production on SQL. Preserve callers' batching and live/unknown/gone gates.
- **D-3 — Cache binding identity, resolve liveness now.** A separate bounded singleton caches `Missing`, `Local`, or `Remote(RunnerId, RunnerStoreId, RunnerCwd)`. Positive binding identity has no TTL; missing entries expire five seconds after load completion. Versioned single-flight loading and post-commit invalidation prevent late missing loads overwriting creates. Resolve connection, store/epoch, lease, socket and recovery on every RPC. Reject caching a runner client, active inventory or permission to deliver.
- **D-4 — Positive replay evidence only.** Keep a bounded identity sidecar under the session lease, keyed by `(Uuid, Kind)` and separate TurnEnd `ApiCallId` membership. Fill it only from durable query results or confirmed persisted representations. Misses retain 512-UUID SQL chunks; null-UUID sequence checks retain their existing behavior. Use the leased `LastSequence` only while valid. Reject negative dedup entries, pre-commit insertion, all-history retention and treating a uniqueness error as proof that our proposed row landed.
- **D-5 — Bound memory and expose misses.** Use typed initial limits of 16,384 positive identities per session (UUID/kind and API-call keys combined), 262,144 process-wide entries and 64 MiB of accounted identity storage; stop admission at whichever limit is reached first. Charge retained strings plus a conservative per-entry overhead, report the accounting separately from measured heap, and bypass caching for a key over 2,048 characters. Derived facts have a 4 MiB per-session and 64 MiB process-wide accounted budget; binding entries use R1's 4,096-session bound. These are tunable capacity limits, not correctness thresholds. Reject admission/evict evidence and use the durable fallback, never truncate evidence or infer novelty. Eviction of identity evidence must not evict a held R1 lease. Large replay churn is a measured residual, not a zero-query claim. Whole-history RPC/watermark redesign is outside this work.
- **D-6 — Separate state change from delivery.** Every committed revision can wake in-process waiters, even if Working is unchanged. A wake means recheck durable state. UI metadata events are coalesced and sent through `IEventBus`; they contain no transcript text or runner path. Reject callbacks under the state gate and one database/API refresh per transcript token.
- **D-7 — Cache input facts, keep clocks.** Revision-keyed facts may replace repeated content derivation; time-dependent verdicts cannot be cached by revision alone. Deadline, stall, retention, quota, screen/Enter, external file/git, runner recovery and final-pull clocks stay. Reject replacing every dispatcher/supervisor tick with transcript events.
- **D-8 — Keep ownership boundaries.** CARD-0720 owns parent board/card locking for cascade membership. R2/R3 only attach identity/fact/binding invalidation to the existing committed deletion boundary and preserve its gates. CARD-0699 owns completion stamps and CARD-0700 owns Boards amplification. R6 Unknown remains distinct from idle and Gone. No additional automatic session stop is authorized.
- **D-9 — Compare the running configuration, do not tune it.** Capture actual sanitized pool flags and resolved driver/provider versions. Unchanged `noResetOnClose=true` is acceptable for an attribution comparison, not a new qualification of that setting. A pool/driver/settings change invalidates the pair. No pool switch, reset experiment, automatic statistics reset or new read-retry policy belongs in this implementation.
- **D-10 — Separate publication, activation and acceptance.** Ordinary Review precedes landing. Independent Mutation controls run against the landed source. A desktop acceptance task captures an R1 baseline before any R2 activation, then matched R2/R3 after windows with confirmed served SHA. A green query-budget test, push or land cannot close the full card.

## Implementation design

### R2: metadata reader, binding identity, replay evidence

`SessionStateReader` routes a batch through `SessionStateStore` when enabled and the old indexed oracle otherwise. Existing R1 queue/agent calls should converge on this selector without weakening their tests. Keep R1's distinction between empty/missing/faulted; a failed load never becomes idle. An enabled read after a completed ingest must observe its committed state through the same gate. Static helpers receive the reader explicitly; no static service locator or mutable global state.

For each SQL metadata replacement record the old projection, ordering, timestamp fallback and tie-breaking beside the new snapshot field. In particular, last-by-sequence, maximum native timestamp, and maximum `Timestamp ?? CreatedAt` are different facts. A deadline asking for the row with greatest timestamp cannot use `LastKind` paired with an unrelated timestamp. Extend snapshot/loader/fold together when an exact small projection is possible; otherwise use the fact cache or retain the targeted query. Do not move report bodies into `SessionStateSnapshot`.

The binding cache belongs behind `PhoneHomeRunnerDirectory.GetBindingAsync`; its database loader uses a fresh scope and a `session-state.binding` tag. Keep `BindingLookups` as request count if existing tests rely on it, and expose actual loads separately. Publish/invalidate after committed creation in `AgentControlService`, both dispatcher creation/resume paths, and direct `AgentSessionService` creation as applicable. Audit all session creation/deletion paths, including retention and board/project cascades. Invalidation must be tied to the same durable success/rollback outcome as R1; never invalidate on an uncommitted delete. A version fence rejects an in-flight stale loader. No global directory lock spans SQL, state leases or subscriber execution.

Keep `PendingRunnerSessionInventory` and `PhoneHomeRecoveryPump`'s runner/store provenance checks. Recovery may reuse binding identity, but never its cached presence as proof of current inventory. Current connection replacement, socket closure, lease expiry, failed List and generation tombstones preserve their R6 outcomes. A Missing binding is not Local; preserve the current interpretation of incomplete stored remote fields unless a separately justified schema change is commissioned.

Pass the held R1 lease into the ingest core to obtain positive identity hits and the committed sequence floor without reentering the gate. Query only uncached UUIDs; each SQL query may return several kinds for one UUID. Cache those actual returned identities, and publish successful inserted/stub representations after commit. A skipped original that became a stub must not be admitted under an identity or classification the database lacks. Reload/uncertain outcomes clear or reconcile the sidecar before another reader can trust it. Retention/reset/deletion clears affected identities; process restart starts cold; a resumed tailer still rebases new low source sequences.

`ObserveTranscriptAsync` currently checks boundary novelty **before** `PersistTranscriptAsync`. Preserve that semantic when optimizing: the same entry's post-commit cache hit must not suppress its first flush. Capture boundary novelty under the serialized operation before inserting, return it with the persistence outcome, then perform actions after releasing the lease. Keep existing fail-open behavior on a boundary-check failure; do not invent a cached negative. Two TurnEnd records sharing an API-call ID may persist as separate UUID/kind rows but must not trigger two completed-turn effects. Catch-up persists evidence without recursively flushing the queue.

Repeated in-capacity positive replay must produce zero UUID membership queries and no redundant maximum-sequence query. Null-UUID misses, unknown identities, cold seeds and a replay larger than the configured cache remain explicit durable work. Test both a fitting replay and a replay exceeding capacity; inspect actual retained key/byte counts. The investigation's mean 22.38 probes per ingest suggests full snapshots, but does not establish their cardinality or a safe cache capacity. Capture replay size, admitted hits, misses and evictions before claiming the live budget is met.

### R3: facts, wakeups and consumers

Add `SessionStateChanges` as a DI-owned coordinator. Snapshot publication under a session lease records its revision/change flags; release precedes executing subscriber work. `WaitForChangeAsync(session, epoch, resetEpoch, revision, ct)` registers and rechecks atomically enough to prevent the read/register lost wake. Cancellation unregisters; deletion returns a deleted/reset result; restart/new epoch requires a new snapshot. Held waiters must not be silently evicted. A bounded dirty-session queue coalesces repeated wakes; overflow marks a recovery rescan of outstanding durable work, and handler failure leaves work recoverable. No callback may acquire the queue lock while holding the state gate.

The existing raw `SessionTranscript` stream remains useful for rendering. Its delivery before commit cannot advance the new committed revision or prove receipt. New internal notifications cover append, retention/reset and deletion; runner availability and queue/task changes retain their separate lifecycle owners. Use one scheduling owner per action: migrate an existing callback or make duplicate scheduling harmless under its durable claim/queue lock. A new broadcaster alongside the old flush path must not send twice.

Introduce bounded `SessionStateDerivedFacts` for deterministic transcript inputs. Keys include session epoch/reset/revision and applicable task identity/dispatch floor, generation, model/provider accounting and settings revision. Load and publish facts under the same session lease, or reject/retry a load whose captured revision changed; never label older facts with a newer revision. Avoid recursively acquiring a held lease. Preserve `SessionContextUsage.Compute` as the independent calculation contract. Progress inputs must retain novelty since dispatch as well as the rolling time window; pruning to the lookback alone changes long-stall escalation. Cache sufficient compact facts, or fall back on an oversized case. Re-evaluate `now`, files/git and due-time predicates on their original clocks even when transcript revision is unchanged.

Convert queue delivery/late-confirm waits to query durable matching evidence once per relevant committed revision, plus an initial query and required recovery/final-pull checks. Continue checking screen evidence and retry-Enter on their own cadence; wait until the earliest notification, deadline or mandatory pull. A pull shared across callers must start after each caller's freshness floor. Never accept a cached pre-send negative as the post-send final check. Preserve complete prompt matching, original attempt sequence/generation/time fences, immediate-refusal restoration, and existing provider-specific behavior. Do not expand degraded screen-only success into a transcript-confirmed success; full-inline/channel receipts retain their stricter complete UserPrompt contract.

Apply the same wake/fact pattern to `GrokRulesRefreshService`, `AgentTaskLandNotificationService`, deferred report discovery in `AgentTaskReplyService`/dispatcher, specialist qualification, boot/queued-input facts, context/policy refresh, check continuation, expectations and API-error/capacity facts listed in the old census. Timers remain recovery/deadline clocks, but do not repeatedly issue unchanged transcript queries. Land-note/task/note state changes also wake the matching owner; a session event alone cannot replace durable discovery of newly created work. Keep `AgentTaskLandMonitorService`, completion stamp selection and card-file policy outside the transcript rewrite.

### R3: API and UI

Add `GET /api/sessions/{id}/state` to `SessionEndpoints.cs` with a small typed DTO: session/correlation IDs where authorized, epoch/reset/revision, last stored sequence, readiness and working state. Report availability through its existing authoritative source if included; do not derive it from Working. Reads must avoid loading the entire message queue. Use the endpoint's existing access rules and `HttpException` errors.

Publish `SessionStateChanged` through `IEventBus.PublishToAllAsync`, the existing metadata lane used by `AgentChanged`, with only the small DTO above and no content. This reaches badges without requiring them to join a transcript group; TestDesign must verify the actual event destination and existing connection access boundary. Working/readiness transitions invalidate promptly; usage/progress invalidations coalesce to at most one per second per session. Unchanged Working still wakes server receipt waiters independently of this UI throttle.

Use `client/src/api/sessions.ts` and TanStack Query's `['session', id, 'state']`. Update `useSignalRInvalidation.ts`, `SessionWorkingBadge.tsx`, queue consumers and the existing connection store/hook. Subscribe before fetching the initial snapshot; reconnect refetches, same-epoch older events cannot overwrite newer state, and a new epoch resets the watermark. Remove the badge's three-second connected polling. Preserve the older plan's agent safety refresh of 60 s connected and 30 s disconnected, and badge fallback of 30 s disconnected. Keep task/attention age clocks and `SessionQueueChanged` for queue contents. The transcript panel remains event-driven and does not refetch history per token.

### Diagnostics, acceptance tooling and rollback

Extend current metrics with binding loads, UUID hit/miss/eviction and replay size, null-sequence/boundary probes, maximum-sequence fallback, fact-cache fallback, waiter/dirty backlog and handler latency. Labels must be bounded categories, not session IDs or arbitrary caller text. Retain the distinction between EF attempts (including retries), PostgreSQL completed calls, ingests, inserted rows, and content queries. Tag actual binding SQL and recognize that tag in the collector before adding a leading comment breaks its current untagged binding regex.

Extend the existing collector rather than replacing its immutable evidence format silently. Its current hard-coded reset-enabled test must become a comparison of sanitized effective settings and resolved versions across every point in the pair. Missing fields or changed settings make attribution invalid. Preserve schema-1 evidence readability where fields suffice; version additional provenance explicitly. Add intermediate live/workload observations so two endpoints alone cannot certify the ten-live-session requirement. Record observed workload rather than calling the first 180-second window idle and the next active without evidence. Keep natural production activity; no synthetic session prompts.

Update `docs/session-runtime-invariants.md` to describe remaining-round semantics and replace the stale deployed-reset assertion with the no-pool-change contract and observed-setting requirement. Keep `SessionState:Enabled=false` as a complete escape to SQL reads and bounded polling for the migrated consumers. Binding/identity/fact accelerators and notifications must have documented startup-configured disable behavior; ingestion serialization and durable records remain intact in every mode. Deployment/rollback is through the canonical runbook with served SHA verification, never from this task worktree.
