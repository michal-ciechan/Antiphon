The deployed server reports `4e873cf20a61b0475f9a013b57168e6ecdd7aea5`; the relevant dispatcher, producer, Check selector and identity test files have no diff between that SHA and this checkout. CARD-0758 has no content revisions after creation.
- The production Check is on the **legacy** path: `AgentTaskCheckService.cs:474-487` activates the request graph only for an enabled declared routing with a qualified candidate; otherwise `:493-510` calls `SpecialistTaskRunner.RunAsync`. Live `GET /api/agents/be5d4502-89df-4412-8ebb-26c1e9171021/specialist-routing` has no enabled declaration or qualified candidate. The card's claim that one permanent specialist task remains pinned is stale: `SpecialistTaskRunner.cs:309-350` creates a fresh task per Check and snapshots the agent's current persistent session ID, `StartedAt`, effective model and profile revision.
- Live task `19f001a5` was **created at 14:53:33Z**, but its Created event recorded session `cea73d57` with `StartedAt=11:24:07Z`. It was held behind another Check and then for no live session; at 14:54:30Z it failed when the same session ID had `StartedAt=14:54:22Z`. Thus the runner/server recovery changed the generation while the task was queued. This supports a race, not a permanent pin. `AgentTaskDispatcher.cs:7257-7266` determines live status from the database row, and `:6562-6572` resolves the current standing session at dispatch.
- `AgentTaskDispatcher.cs:6587-6609` first checks kind, tier, exact model, effective model and alias, then rejects any session ID, start time **or** profile revision difference as `SpecialistIdentityMismatchException`. `:904-913` turns it into a terminal failure before session assignment, and `SpecialistTaskRunner.cs:273-281` returns the reason to the degraded Check. This guard was intentional for CARD-0415 (`docs/agent-kinds.md:556-563`) and must remain for routed/typed attempts: `SpecialistRequestService.cs:225-243` and `SpecialistInputPolicy.cs:60` bind those to an authorized generation.
- The exact failure text does **not** distinguish a generation change from a profile change. The observed old and new `StartedAt` values prove a generation change; no evidence here proves profile revision drift. `SpecialistExecutionIdentityTests.cs:23-41,96-145` currently expects **all** generation drift to fail, including legacy tasks. That expectation needs a Check-specific amendment, not a broad removal of identity protection.
- The outage is no longer active at inspection time. Live agent `be5d4502` is Running on `cea73d57`, now started at `15:28:45Z`. The 25 Check tasks created after that start through `16:52Z` all Succeeded; the latest, `dae94df4`, has a nonempty reading. The card's “every check digest” statement is stale. No live restart is warranted now. The server SHA is older than current master, so verify deployment SHA separately when assessing future incidents.

## Smallest fix

**S1 — dispatch-time re-resolution of a queued legacy Check.** In `PlaceOnStandingAgentAsync` (`AgentTaskDispatcher.cs:6555-6634`), retain the existing kind/model/alias checks and the terminal profile-drift guard. When the sole mismatch is session ID or `StartedAt`, allow a queued **legacy Check** on the configured primary interpreter (`Role=Check`, `SpecialistInputPolicyJson == null`, owned standing seat) to adopt the current Running session only if its profile revision still equals the task's snapshot, its effective model and seat identity still match, and the optional deadline has not expired. Under the existing claimed-task transaction, refresh `SpecialistSessionId` and `SpecialistSessionStartedAt`, record a Warning event with old/new generation, and continue through the existing occupancy and delivery path. A changed profile revision, model, kind, tier or alias still fails loudly. Do not rebind a task with `SpecialistInputPolicyJson`: routed attempts also bind an authorization, fingerprint and complete-input transport policy to the original generation; they need their own request-graph retry design.

**S2 — focused regression.** Extend `SpecialistExecutionIdentityTests` with three argument cases for a legacy Check: same session ID/new `StartedAt`, replacement session ID/same approved profile, and changed profile revision. The first two must dispatch and create exactly one queued message on the current session, with none on the old generation; the third must fail before input. Keep existing Codex, model, tier, live-model and public-kind refusals. Exercise both the no-deadline `RunAsync` and deadline policy as appropriate; a terminal or expired task must never be rebound. A new test is useful only if its first two cases go red on the current guard and green after S1.

## Risks and cost

- A database Running row can lag the runner during restart. Keep the present queue's generation check at delivery; if the session changes again after dispatch, typed delivery must refuse or retry safely, never write into an unverified composer. This plan does not claim a native-process end-to-end proof from the database fixture.
- A profile revision may encode changed instructions, tool access or transport. It is not safe to treat it as a cosmetic restart stamp. The observed incident establishes only generation drift; profile drift retains the typed refusal until equivalence or fresh-work semantics are designed.
- Rebinding must occur once under the existing task lock and before any dispatch/message intent; re-evaluate deadline and seat occupancy. Do not resurrect terminal Checks, create another task, reset a routed candidate's qualification, or alter the old digest.

Ordinary cost: **26 minutes** implementation and test authoring + **12 minutes** CP-1/CP-2 + **6 minutes** Review = **44 minutes**. Positive-control floor: **3 controls**, each one red and one restored-green exact-method execution, **6 method executions / about 9 minutes**, separate from ordinary Code. PC-1 remove the new re-resolution branch: same-ID restart must fail its Dispatched/current-message assertion. PC-2 permit profile drift: profile-refusal case must fail its no-input assertion. PC-3 bypass the existing model guard: the retained model-drift case must fail its identity-refusal assertion. Total planned work floor **53 minutes**; measurements supersede estimates.
