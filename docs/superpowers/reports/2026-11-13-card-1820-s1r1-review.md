## Safety questions from the brief

1. **A release request never returns complete/skippable.** `New-ReleaseImpactEnvelope` emits constants:
   `complete=$false`, `fallback='Full'`, `classes=@()` and `incompleteReasons=@('release-graph-unavailable')`. Every graph/input/universe
   digest is null. `ConvertTo-ReleaseImpactJson` acts as an independent gate. It refuses complete=true, a missing or empty reasons list, any class,
   a non-Full fallback, `target.verified` other than false, and any non-null graph digest. When it refuses, the request takes the exit-2
   `invalid-release-request` incomplete/Full path. Nothing reads an index, a cap, the working tree or policy, so missing, stale, capped,
   truncated or mismatched evidence cannot change the outcome. Direct CLI probes on the real repo returned these results:
   - Candidate f14441056 or master 586be574b: exit 0, complete=false, Full, 0 classes.
   - A tree SHA as candidate: exit 2, refused, Full.
   - An uppercase SHA: exit 2, refused, Full.
2. **Binding.** `baselineSha` and `candidateSha` must be full lowercase 40-hex values, and `rev-parse --verify <sha>^{commit}` must return exactly that SHA. A tree, a short SHA or an unknown commit is refused (witnessed; mutant M4). `algorithmSha` is the source checkout's HEAD. `algorithmDigest` hashes the path and blob pairs of both scripts, and the check refuses when the on-disk blobs drift from that HEAD. In S1R1 the binding proves the commits exist but hashes no candidate content. The tree, policy and input-manifest digests are null by design and are owned by S1R2–S1R6. No consumer exists yet, so there is no tamper surface (see A-2).
3. **Ordinary selection is byte-identical.** I ran the base (`cc48c7005`) and tip selector scripts against the same repo tree for 9 invocations: `-Range` over branch, master and historical cut ranges, with and without `-Json`; `-Path`; `-MergeSubset`; and `-Audit`. All 9 had identical stdout+stderr bytes and identical exit codes. CP-101 `ImpactedClassesSelectorTests` passed 42/42.
4. **Nothing consumes the envelope.** `git grep` finds `ReleaseEvidence`, `release-impact` and `antiphon-release-impact` only in the two scripts, the new test and the report. The only other script that calls `impacted-classes.ps1` is `scripts/lib/post-land-early-warning.ps1`, which uses ordinary mode and is unchanged. Nightly, qualification and Full are untouched. Incremental qualification stays inactive.
