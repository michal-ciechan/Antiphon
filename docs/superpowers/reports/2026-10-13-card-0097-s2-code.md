### Root cause

The test awaited a control behind a two-step data chain (complexity list, then the Mutation row's effective query)
with a whole-document `findByRole`. `findBy*` polls with a 1 s budget; each whole-document role scan computes
accessibility and styles for every node (`css: true`), costing up to ~1 s on its first evaluation under load.
The query's own evaluation cost spends the budget before the data arrives. S2 widened the window: it adds the role-policy
request and a ~200-node table (437 → 633 nodes), making each scan more expensive and adding render work.
The race is present before S2, so this is a test defect that S2 makes more likely, not a product
render-order defect. The matrix already renders independently of the role-policy query (separate sections, own queries).
