## Scope and verification design

S1R1 adds the release-only CLI envelope. It admits no complete release graph:
missing schema-1 indices, stale working inputs and candidate/tree mismatches all
remain incomplete/Full. Unverified graph, input, universe and compatibility identities
are explicit nulls. Exact requested baseline/candidate commits and a separately
source-checked algorithm identity are recorded. Ordinary mode retains its payload.
No scheduler, ledger, delivery, landing, lease, persistence, migration or activation
behavior changes. Release mode requires PowerShell 7; ordinary mode retains 5.1.

V-1 has exactly four executions: MissingIndexIsIncomplete, StaleInputIsIncomplete,
CandidateMismatchIsIncomplete and OrdinaryModeRemainsAdvisory. Each runs the real
selector against an isolated Git fixture. The red-first adapter invokes ordinary
mode only while the release module is absent; the resulting successful advisory
payload must fail the missing-completeness assertion. After implementation it
invokes the release CLI and also verifies invalid-switch/endpoint refusal,
ordinary field/value compatibility, and a Windows-target request remaining unverified.
These are outcome assertions, not comparison against the serializer implementation.

## Performance and platform

repositories under ignored evidence. Each Git call has a 60s deadline, selector
process 120s, stream drain 10s and teardown 30s, matching the provisional upstream
budget (CARD-1820/CARD-1404), not a measured p95. Per-process phase durations are
printed as C1820 records; TRX retains per-test duration. All processes are joined.

reported separately. No timeout or assertion is relaxed. No proof repetitions are
required after green. Mutation execution is waived by the operator (2026-11-12);
positive controls remain pending, and ordinary red assertions are still required.
