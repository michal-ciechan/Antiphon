## Round-1 blocker

`Repeated_hot_reads_do_not_add_transcript_sequential_scans` at `cd222da3c` saw Sequential 2 → 4 on the class run and Sequential 4 → 4 on an isolated retry. Round 1 read that as two parallel workers publishing late. The fix commits correct that account, and PostgreSQL 16.15 source agrees with the correction.

`pgstat_shutdown_hook` calls `pgstat_report_stat(true)` at process exit, so each parallel worker force-flushes before it exits. The leader's Gather waits for that exit before the statement completes. The late packet is the leader client backend. `pgstat_report_stat(false)` on the idle path refuses a flush inside `PGSTAT_MIN_INTERVAL` (1000 ms) and returns `PGSTAT_IDLE_INTERVAL` (10000 ms), which arms `IDLE_STATS_UPDATE_TIMEOUT`. That timer can fire inside the window. The red shape before `{2,0}` after `{4,…}` is that deferred leader packet, on top of the two worker increments already visible.
