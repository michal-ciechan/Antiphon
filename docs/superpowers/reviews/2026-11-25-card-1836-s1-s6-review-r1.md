## Blockers

Owner for every item: the Code landing owner `5dbd583f-0040-4afc-a9f3-35bce1516a13`.

**D-1 The derived impact index is stale at the tip.**
- **Where:** `tests/derived-impact-index.json`, not regenerated after S1-S6.
- **Failure:** `DerivedImpactIndexTests.committed_index_matches_the_builder` is red (run `20261125-204451-1fb7`, RV-8). It regenerates clean at the base.
- **Why:** the guard batch is part of Final. The selector this card builds reads this file.
- **Fix:** run `scripts/regenerate-derived-impact-index` and commit the result, then rerun that method. At land, master `457a8efe1` also regenerated the file. Resolution order: rebase; on a conflict in the index take `origin/master`'s blob; regenerate on the rebased tree; commit; rerun `committed_index_matches_the_builder`. The merged tree needs regeneration today too (16+/8-).

**D-2 The S1 reuse predicate misses operator-named non-clean states and fails open on a missing case roster.**
- **Where:** `RcChunkReceipt.Reusable` (lines 186-224), and its use in `RcIncrementalCut.Execute` (line 170: `chunk?.Cases ?? Array.Empty<string>()`).
- **Failure:**
  - M1, M2 and M3 survive. No CP-1 row covers row `skipped=true`, `timedOut=true`, non-empty `evidenceReasons`, or a nonzero exit under a pass label. `s1-tolerated-exit` uses exit 0 and the flag.
  - A row with `coverageComplete=false` or a freshness `detail` (both are written by `NightlyChunkRunner` lines 616-623, 697-702 and 735 while `result` stays `pass`) is not read.
  - An empty `requiredCases` turns off the exact-coverage check. A TRX with one passed case then admits a ten-case roster.
- **Why:** this breaks the operator rule to rerun every chunk that is not a clean pass, including skipped, timed out and evidenceReasons set. It also breaks D-3.1's exact case coverage and highest-risk area 5 (fail open on missing input).
- **Fix:**
  - Refuse `coverageComplete==false` and a non-empty `detail`.
  - Treat a null or empty required roster as `no-case-roster`, never as "no cases required".
  - Add CP-1 rows `s1-row-skipped`, `s1-timed-out`, `s1-evidence-reasons`, `s1-nonzero-exit-pass-label`, `s1-coverage-incomplete` and `s1-no-case-roster`.

**D-3 Carried provenance is unbound: no platform, no origin SHA, no later-open obligations, and a constant Full verdict.**
- **Where:** `RcChunkReceipt.Stamp`/`Reusable`, `RcIncrementalCut.Admit` (lines 98-116) and `Execute` (lines 145-232).
- **Failure:**
  - A v2 row records no platform, architecture, repository or profile, so a Linux or other-repository receipt is admitted for a Windows qualification.
  - `Admit` never compares the inventory's `sha` with `comparison.json`'s `sha`, and `Execute` never checks a carried row's `sha`. An inventory sealed at X but named by a comparison at A carries X's rows into A.
  - D-1's later-open obligations (`RcComparisonBaseline.Choose().Owed`) are consumed nowhere. A later FAIL attempt at the same SHA is hidden by an earlier clean inventory: the group 136 intermittent shape.
  - M4 survives, so no row exercises the cross-source branch.
  - The Full branch of `Execute` sets `AllGreen = true` without reading any launch outcome. This constant cannot go red.
- **Why:** this is highest-risk area 1 (a carried origin from another candidate or platform; Windows chunks need Windows receipts) and D-1/D-2.
- **Fix:**
  - Stamp the platform (OS/architecture), repository, profile and runId.
  - `Reusable` takes the expected platform and refuses one that is absent or different.
  - `Admit` requires `inventory.Sha == comparison.sha`, plus ancestry and line, and binds the `Choose` choice and its owed set by digest.
  - `Execute` refuses a carried row whose `sha` differs from the bound baseline, and executes every owed content.
  - Compute `AllGreen` from the returned rows.
  - Add CP-6 rows `s6-cross-source-executes`, `s6-foreign-platform-owed`, `s6-inventory-sha-mismatch`, `s6-later-fail-same-sha` and `s6-full-red-is-red`.

**D-4 S2 selection skips in three ways.**
- **Where:** `RcChunkSelection.Select` (line 127) and `ReadIndex` (lines 195-223).
- **Failure:**
  - (a) A path matched by any census glob is added to `discharged`, and line 127 then skips its project closure. A census glob such as `scripts/lib/**` narrows a change to a compiled `Antiphon.Nightly` source to the reader chunk, and every consumer of `Antiphon.Nightly` carries.
  - (b) An index blob without an `edges` or `cappedPaths` array, or with another `schema`, reads as zero edges and gives no fallback.
  - (c) A change to the index blob selects only the classes on changed edges. D-3.3 ("include the index's actual readers") is missing, and a change to `cap`, `allowlist`, `windowsOnly` or `linuxOnly` selects nothing. M5 survives.
- **Why:** the operator rule (a harness change reruns its dependents through the project graph), D-3.4 and D-3.5, and highest-risk area 5.
- **Fix:**
  - Compute the closure for every changed path, and use discharge only to clear `unknown-path`/`shared-input` fallbacks. At most, narrow non-compiled data under a test project to its declared readers.
  - Require `schema==1` and both arrays; otherwise report `index-malformed:<side>`, which forces Full.
  - On an index change, hit its declared readers, and force Full (or reader hits) for non-edge field changes.
  - Add CP-2 rows `s2-census-keeps-closure`, `s2-index-schema-unknown` and `s2-index-readers`.

**D-5 The S3 trust gate trusts undeclared edges and package changes.**
- **Where:** `RcTrustedProjectGate.Decide` (lines 178-199) and the `GlobalInput` regex (line 86).
- **Failure:**
  - (a) `RcTrustEntry.Downstream` is parsed and never read. Any consumer of a trusted project is held, and on a gate pass it carries even when its edge is not declared.
  - (b) This repository has no `Directory.Packages.props`; versions live in each `.csproj`. A `PackageReference` version bump inside a trusted project is treated as a private change and released by an equal contract hash.
  - (c) M6 survives.
- **Why:** this breaks the operator rule (SDK and packages are never trusted) and D-4 (downstream edges the entry may satisfy).
- **Fix:**
  - Hold only consumers whose project is in `Downstream`. Others execute with `consumer:<p>:undeclared-edge`.
  - A changed `*.csproj`, `*.props`, `*.targets` or `packages.lock.json` owned by or imported into a trusted project voids trust for that decision.
  - Add CP-3 rows `s3-undeclared-consumer`, `s3-csproj-package-bump` and `s3-own-case-missing`.

**D-6 The S4 queue cannot express several influencing gates.**
- **Where:** `RcImpactObligation.Gate` (a single string) and `RcImpactQueue.Dispatch` (lines 109-120).
- **Failure:** a consumer held by two changed trusted projects names one gate and carries when that gate passes, even if the other gate is red. A gate is released on the launcher string `pass` rather than on the strict own-gate predicate.
- **Why:** D-4 requires that every influencing gate must pass.
- **Fix:** use `Gates[]`. Release only when every gate passed with equal contracts; expand when any gate fails. Add the CP-4 row `s4-two-gates-one-red`.

## Default-off, cut path and trust-gate questions from the brief

- **Default-off (3), held.**
  - `ReleaseCutOptions.Parse` refuses `--selection-mode Incremental`.
  - `release-cut.ps1` and `nightly-run.ps1` keep `ValidateSet('Full','Shadow','ChangeAware')`.
  - No environment variable sets the mode.
  - `NightlyChunkRunner.ChunkReceiptVersion` defaults to 0 and nothing in production sets it.
  - The `Incremental*` hop fields are read only by `RcIncrementalCut.Execute`, which production `NightlyTests` never calls.
  - A programmatic Incremental request seals and runs `effectiveMode = Full`.
- **Cut path (4), held for the in-process cut.** An Incremental request returns before `ReleasePublish.Run` on every branch: not green returns first, WhatIf skips admission and still returns, and the exception path is red. Advisory A-1 covers the durability gap.
- **Trust gate (2):**
  - Policy is read from B only, and a B/A difference voids trust, so self-authorization is closed.
  - The shipped `entries: []` admits nothing.
  - A null or empty hash is `contract-absent`, never equal.
  - Package and undeclared-edge trust is open (D-5).
- **Fail-open (5).** An unbound index, malformed JSON, an unreadable inventory, a missing outcome or a project-planner fallback all fail closed, as Full, execute or unsafe. The exceptions are D-2 (empty roster) and D-4(b).

## Advisories

- **A-1** An admitted request reports `CoverageScope=Incremental` while Full executes. Requested-Incremental is not recorded in the sealed attempt or summary, so once `Execute` is wired, a later standalone `publish-release` could publish a carried ledger. Make the qualification-only scope durable before wiring.
- **A-2** `RcIndexBinding.Sha256` hashes decoded and re-encoded text, not the blob bytes. `s2-index-binding` computes it the same way, so it is a self-compare.
