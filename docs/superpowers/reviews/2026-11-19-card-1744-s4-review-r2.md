## D-2 (autostart fails closed): fixed

I read `scripts/autostart-session-runner.ps1` at the tip branch by branch:

- **Helper load (`:42-57`):** the dot-source runs under `Stop` inside `try`. A missing file or a parse
  error is terminating, so the script logs `helper-load-failed` and exits 2.
- **Config present (`:62-80`):** the read, the parse and the secret `Test-Path` run under `Stop` in
  `try`. Any throw logs `config-unreadable` and exits 2. An empty file is `""`, not `$null`. The
  untyped `$ConfigText` keeps that, so it parses as `config-malformed` (refused), never `direct`.
- **Plan (`:89-109`):** a throwing `Resolve-...` logs `plan-resolve-failed` and exits 2. A null plan, or
  a mode other than exactly `refused`, `direct` or `phone-home` (`-ceq`/`-cne`), logs
  `plan-mode-invalid` and exits 2. A `refused` plan logs its own reason and exits 2.
- **Phone-home without env:** the helper returns `phone-home` only together with the 19+ key `$built`
  dictionary, and `$mode -ceq 'phone-home'` sets each key. I found no input that gets to `run-daemon`
  in phone-home mode with no environment. (An empty value, for example no `pwsh` on PATH, still removes
  that one variable. That is round 1 code and does not block.)
- **Direct while the file exists:** `Resolve-...` returns `direct` only for `$null` text. Text is `$null`
  only when `Test-Path` reports the file absent. The one way left is a `Test-Path` false negative on an
  existing file, which is A-2. It is not reachable through the config content.

**Helper-load exit 2 with no config file.** This is acceptable as fail-closed, and consistent with the
rest of S4. `dev-aspire.ps1:31` and `restart-apphost.ps1:104` also dot-source the helper with no
fallback. With a broken helper the desktop gets no logon runner, and the AppHost launch also fails, with
a console error. The logon task prefers pwsh 7 (`install-autostart.ps1:133-149`), so the Windows
PowerShell 5.1 parse risk exists only where pwsh 7 is missing. The helper is a tracked file beside the
script, so "missing" means a broken checkout. Not every fallback here is safe: round 1 showed that a
null plan started the runner on Kestrel's default URL. The cost is visibility. The only signals are a
log line that says `phone-home config refused: helper-load-failed` when no config exists, and Last
Run Result 0x2. See A-1.
