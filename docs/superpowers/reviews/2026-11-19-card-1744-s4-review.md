## Blockers

### D-1 The AppHost refusal prints an unconditional delete, `-Hard`, retry recovery

- **Where:** `scripts/lib/windows-phone-home-env.ps1:291`, `Get-WindowsPhoneHomeLaunchRefusal`. Both
  `scripts/restart-apphost.ps1:103-111` and `dev-aspire.ps1:31-37` print its text as is. The harness pins
  that wording: `scripts/test-windows-phone-home-runner.ps1:325` (`apphost-guard.present` requires
  `Delete `, `restart-session-runner.ps1 -Hard` and `retry`).
- **Failure:** the printed text is exactly:

  ```
  REFUSED: phone-home-config-present
  Delete C:\Antiphon\runner\phone-home.json, run restart-session-runner.ps1 -Hard, then retry.
  ```

  The file exists only in the window or in rehearsal RH-3, which is when the Linux server may be the
  writer. Suppose an operator, or an orchestrator under standing restart autonomy, runs
  `restart-apphost.ps1` mid-window and follows the message. They delete the file, run `-Hard` and retry.
  The retry passes the guard. `restart-apphost.ps1` has no maintenance-marker check. With the
  user-secret removed (parent step 1.7), the AppHost falls back to `DefaultConnection`, the desktop
  `localhost:17280` database, while the Linux server still serves the public origin. That gives two
  control planes, the outcome this guard exists to prevent. The S5a runbook review (`9681fa98`, D-1)
  found this. It moved the condition into the docs because "the S4 refusal text ... also says Delete ...
  retry". The refusal text is the one line that is always in front of the operator, and it still
  advises the unsafe sequence with no condition.
- **Why:** the brief lists an unconditional delete-and-retry message as blocker-grade. Plan D-15 does
  specify this wording. The finding is against the plan text as well: the S5a review result came
  later and the plan was not amended.
- **Fix:** make the printed recovery conditional, and change the `apphost-guard.present` assertion to
  pin the condition in place of the bare `Delete`/`retry` tokens. A suggested wording:
  `REFUSED: phone-home-config-present` / `desktop-win is in phone-home mode. If the Linux server is
  serving (cutover window), this refusal is correct: stop, do not delete the file. Only during rollback,
  after the Linux server is stopped and pg_stat_activity shows no production-compose client: delete
  <path>, run restart-session-runner.ps1 -Hard, then retry.` It must still not contain
  `restart-linux-server` (T-21). Optionally amend D-15 in a separate plan-amendment file.

### D-2 Autostart fails open to the direct runner when the config cannot be read or the helper cannot load

- **Where:** `scripts/autostart-session-runner.ps1:24` (`$ErrorActionPreference = 'Continue'`), `:36`
  (dot-source of the helper), `:38-41` (`[System.IO.File]::ReadAllText`), and `:61-94` (`$plan`
  consumed with no null or mode check).
- **Failure:** reproduced on Linux pwsh against a `git archive` copy of the subject, with `run-daemon.ps1`
  replaced by a stub that prints its arguments:
  1. `phone-home.json` exists but cannot be read (chmod 000, or a directory with that name). `Test-Path`
     is true, and `ReadAllText` throws a statement-terminating `MethodInvocationException`. Under
     `Continue`, the script goes on with `$configText = $null`. `Resolve-SessionRunnerAutostartPlan`
     returns `direct`, and the stub prints `exeArgs=[--urls http://localhost:17204]` with no
     `PhoneHome__*` set. Autostart exits 0, with no `config refused` log line. That is the **direct
     runner on 17204**, the outcome D-14 forbids ("no fallback to the direct runner"). On the desktop
     the triggers are a sharing violation from an editor or AV scanner at logon, or an ACL copied from
     the restricted `secrets` tree. The AppHost would then adopt 17204 as `local` beside the server2
     server (T-14).
  2. The helper fails to dot-source, for example a Windows PowerShell 5.1 parse failure in the
     UNOBSERVED T-18 fallback, or a missing file. Then `ConvertFrom-WindowsPhoneHomeConfig` and
     `Resolve-SessionRunnerAutostartPlan` are "not recognized" (non-terminating), and `$plan` is `$null`.
     Neither `refused` nor `phone-home` matches, and `run-daemon.ps1` runs with `-ExeArgs $null`. The stub
     printed `exeArgs=[]`. The runner starts with no phone-home env, on Kestrel's default URL. This holds
     whether or not the phase 2 file is present, and the config-absent direct runner also loses its
     17204 binding.
- **Why:** "a bad config that falls back to the direct runner" is blocker-grade. No witness can see
  either path. W-10 to W-12 call the helper functions only. Nothing exercises
  `autostart-session-runner.ps1` as a whole, so a mutation in the autostart wiring survives every
  CP-11 test. Examples are dropping the `exit 2` branch, or reading the file inside a swallowed error.
  This is the producer-to-recipient gap, from config file through autostart to the run-daemon arguments.
- **Fix:**
  - Make the config section fail closed. Use `-ErrorAction Stop` on the dot-source, and put the read
    and parse in `try { ... } catch { log '[autostart] phone-home config refused: config-unreadable';
    exit 2 }`.
  - After `Resolve-...`, refuse (exit 2) unless `$plan` is non-null and `$plan.mode` is exactly
    `direct` or `phone-home`.
  - Add a witness case that runs the real autostart script against a stub `run-daemon.ps1`, the same
    way this review did. It needs three rows: unreadable config, helper load failure, and a refused
    config. Each must exit 2, write the log line and never reach the stub.

## Advisories (to cards, do not hold the land)

- **A-1:** D-14 says the logon task's `RestartCount 3` "retries and then stops". Task Scheduler's
  restart-on-failure normally fires on a launch failure, not on a non-zero exit code. Exit 2 is then
  likely a single silent failure: a `Last Run Result 0x2` plus the log line, then unleased builds after
  grace. That is fail-closed but quiet. Verify on the desktop and fix the plan sentence.
- **A-2:** PS7 `ConvertFrom-Json` enumerates a one-element top-level array, so `[{...valid...}]` is
  accepted on pwsh 7 and refused on 5.1. Not dangerous. Use `-NoEnumerate` when available, or check
  that the text starts with `{`.
- **A-3:** `Test-StopOnlyExempt` accepts any enclosing `if` clause whose text contains `-not` and
  `StopOnly`, for example `if (-not $StopOnly -or $true)`. This is a weak pin of the exemption.
- **A-4:** while the phase 2 file exists, the AppHost watchdog (every 2 minutes) will log one exit 3
  per fire if its task is still enabled. The window runbook disables it; say so next to the D-15 text.
