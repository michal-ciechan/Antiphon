## Epoch filter

`RegisterAsync` returns `PhoneHomeRegistrationResponse.Epoch`. `PhoneHomeRunnerDirectory` mints that value with `++slot.Epoch` at registration and puts the same value on the ticket. `AcceptConnect` stamps `ticket.Epoch` onto the connection it installs, and `ValidateTicket` rejects the ticket when `ticket.Epoch != slot.Epoch`. A later registration increments `slot.Epoch`, so the earlier ticket cannot become the live connection. `slot.Epoch` is only incremented.

`ConnectPeerAsync` waits with `WaitLiveAsync(runnerId: id, epoch: ticket.Epoch)`. The match is exact equality. A later epoch does not match. The deadline stays 2 seconds of wall clock, so the wait cannot run forever. If a second replacement supersedes the minted epoch before a 20 ms poll sees it, the wait times out instead of returning that later connection.

`AfterHandshake` exists only on `PhoneHomeTestHost`. The test host wraps `IHttpWebSocketFeature` and awaits the hold inside `AcceptAsync`, after the 101 and before `AcceptWebSocketAsync` returns. Production `SessionRunnerEndpoints` still calls `AcceptWebSocketAsync` and then `AcceptConnect`.
