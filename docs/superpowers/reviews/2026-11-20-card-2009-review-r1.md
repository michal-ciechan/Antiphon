### D-1. The E2E identity parser fails open. Some E2E edits still defer.

- **Where:** `scripts/lib/rc-input-manifest.ps1` `Get-RcTestIdentities` (method regex and the `\[Arguments\((.*?)\)\]` capture) and `Test-RcTestIdentityChange`.
- **Failure:** I fed before/after texts directly to `Get-RcTestIdentities`/`Test-RcCountMapsEqual` at the tip. These returned *equal* identities, so the file defers:
  - An added multi-line `[Arguments(\n "b")]` row on an existing method. `.` does not cross a newline, so the row is captured as nothing. The repository uses this form in 46 places outside E2E today.
  - A method rename when its attribute holds `]`, e.g. `[Arguments(new[] { "a" })]` or `[Arguments("x]")]`. `\[[^\]]+\]` stops early, the method is never matched, and it has no identity on either side.
  - Renaming a generic test method `Task A<T>()`. The name must be followed by `(`.
  - A rename with a qualified return type `System.Threading.Tasks.Task M()`.
  - Moving a `[Test]` from an outer class into a nested class declared above it. The method is attributed to the last `class` token before it.
  These cases were correctly SELECTED: a single-line rename, a rename in a file with two classes, a class rename (file-scoped namespace, `partial`), a namespace change, an `#if`-wrapped added row, an uncommented block-comment test, and `record` beside `class`.
- **Why:** A-1 claims "an added `[Arguments]` row SELECTs" and says E2E identity changes fail closed. When the parser does not recognise a form, it drops it silently. It should treat an unparsed form as a change. On the real tree today every E2E `[Test]` is parsed (143 `[Test]` attributes, every file's identity count at or above its attribute count, no multi-line or array `[Arguments]` in `tests/Antiphon.E2E`). So this gap is latent, not live.
- **Fix:** Make the parse fail closed. In `Test-RcTestIdentityChange`, return `$true` when either side has more non-comment `[Test` attributes than matched `[Test]` methods, or more `[Arguments(` openers than captured rows. Capture `[Arguments(...)]` with Singleline/balanced parentheses. Allow `<...>` after the method name and a qualified `Task` return type. Add harness cases to `E2EIdentityChangeSelectsSuites` for the multi-line added row, the `new[]` rename and the generic rename. Each must be red at `30e42ec5`.
