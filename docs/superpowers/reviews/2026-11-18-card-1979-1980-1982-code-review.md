## Code findings

- Phase 3 key probe: `min(("Id")::text)` and `max(("Id")::text)` cast before the aggregate. The rest of the script has no other `min(`/`max(` aggregate. Both sides use the same cast, so the comparison stays like with like. uuid text is fixed-format lowercase hex, so collation cannot reorder it differently between the two sides.
- Gate 6 bound: `SET statement_timeout TO '<n>s';` is semicolon-terminated and sent in the same psql stdin script as the fingerprint SELECT, so it applies to the session that runs the fingerprint. The bound includes lock wait, which is what V-12 witnesses. `[ValidateRange(1, 7200)]`, default 1200. On a timeout, `Fail-Cutover` names the table and the elapsed seconds and exits 3 before any data directory change. Any other psql failure still returns null, and the caller refuses with "row comparison failed". The `SET` command tag is removed before the result is compared.
- Session pins: every SQL read goes through `Invoke-CutoverPsqlOutcome`: the probe containers, the desktop `antiphon-postgres` container, and server2 over ssh with `docker compose exec -T -e PGOPTIONS='...'`. `Invoke-CutoverPsql` is a thin wrapper around it. The only other database client is `pg_dump -Fc` for the transfer, which is not a comparison read. The canonical fingerprint lives only for one run, so no unpinned value from an earlier run is compared.
- Windows PowerShell 5.1: I found no PS7-only syntax (`??`, `?.`, ternary, pipeline `&&`/`||`, `-Parallel`). `[pscustomobject]`, the generic `List[string]`, `TryParse([ref])` and the culture-qualified `ToString` all work on 5.1.
