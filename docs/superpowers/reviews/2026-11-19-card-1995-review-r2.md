## Judgements

**(a) Can a remaining path refuse an unrelated land?**
- A breaks P, B lands outside P: A's own diff touches P, so `TargetBreakAsync` stores no project list. The later row is the latest `build` row and has a null list, so B builds. Witness `C1995_CandidatesOwnBreakDoesNotRefuseAnUnrelatedLand`.
- A touches P and fails in P: not recorded. Correct, because A may be the cause.
- A fails in Q, which it did not touch, because an earlier master push broke Q: `TargetBeforeSha` is the broken tip A rebased onto, so the failure is recorded. That is a real broken master. Correct.
- Two candidates fail at once: each is keyed by its own `TargetBeforeSha` and its own diff. The newest row wins. A row with a null list never refuses, so concurrency only makes the gate more lenient.
- A refused land, then a successful build of the same SHA: a refused row has step `target_build_broken`, which the "latest" query ignores. The successful build comes from a diff that touches the closure. It is `VerificationPassed` and the newest row, so the refusals stop.
- Renewal: refused rows store no project list, and a failed verification row has no publication, so cleanup retries do not keep re-stamping it. The 30-minute bound holds.
- One residual is advisory A-1 below. In this repo it is masked, and it is bounded by the age-out and the overrides.

**(b) Clearing on `ignoreKnownBrokenTarget`.**
- Clearing every record is what an operator wants at 3 am. The only cost of a cleared record is one extra build per land until a fresh failure is recorded. The clear runs inside `RequestAsync`'s transaction, so a refused request rolls it back.
- Auth: the field arrives through the same handler (`QueueLandAsync`) and the same body as `recoverReviewedSource`, `verify` and the other land flags. It adds no auth surface, and it can only make a land build, never skip one.

**(c) Closure walk safety.**
- Project files are read with `git show <sha>:<path>`, so nothing is read from the filesystem.
- `NormalizeRepoPath` returns null on `..` above the root, on `:` and on control characters, so `..\..\..\` records nothing.
- A symlinked csproj is shown as its target text, fails to parse as XML and records nothing.
- `<tree>:<path>` does not follow symlinked directories. The argument starts with the SHA, so it cannot inject an option.
- The walk stops at 256 projects.
- Bounded to the repo.

## Advisories (cards; they do not hold the land)

- **A-1. Items injected by imports are outside the closure.**
  - Where: `LandVerificationFailure.ProjectInputs` adds an `<Import>` path but never reads that file's items. `Directory.Build.*` is not read at all.
  - Failure: `Directory.Build.targets` compiles `src/Antiphon.Hosting/PwshPrivateCache.cs` into every project directly under `tests/`, and `tests/Shared/CheckpointRepeat.targets` compiles `CheckpointRepeatEvidenceAttribute.cs` the same way. Suppose a candidate's edit to one of those files raises CS errors in only some test projects, or the globs in `Antiphon.E2E.csproj` (`$(_LandFakeGrokDir)**\*`) and `Antiphon.Messaging.Tests.csproj` (`Fixtures\*`) are removed. The candidate's own break is then recorded, and unrelated lands are refused for up to 30 minutes.
  - Why it is advisory: today a plain error also fails E2E and Messaging.Tests, whose globs make the closure null. The age-out and the overrides also bound the damage.
  - Fix: walk the item includes of imported files and `Directory.Build.*`, or treat any changed `.cs` outside every project directory as doubt.
- **A-2. The override is not carried to the run.**
  - Where: `AgentTaskLandService.RequestAsync`. `ignoreKnownBrokenTarget` acts only at request time and is not stored on the land request.
  - Failure 1: a build failure recorded between acceptance and the queued run refuses that same land again.
  - Failure 2: the clear nulls `VerificationFailingProjects` on every historical `build` row, not only the rows inside the age window, so the project-list diagnostic is lost permanently.
  - Fix: persist the flag on the request and honour it in `RefuseKnownBrokenTargetAsync`, and limit the clear to rows inside the window.
- **A-3. The setting overrides need a restart.**
  - Where: `AgentTaskLandingProtocol` reads `IOptions<LandingSettings>`.
  - Effect: `Landing:RefuseKnownBrokenTarget` and `Landing:ForceVerificationBuild` take effect only after a server restart. The docs say "no code change", which is true, but they could mention the restart.
