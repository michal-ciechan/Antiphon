## Deletion safety

- **What the new code deletes.** `ClearRejectedIgnoredAsync` runs only on a warm reset. It runs after
  the D-1 ownership re-proof, the forced checkout and the normal keep-list clean, all inside
  `ResetForFreeAsync`. The slot is in the Releasing state, so no lease can race it.
- **Which paths it clears.** Status entries go through the same `ForeignEntries` selection that
  `CheckFreeAsync` uses. Every `!!` entry outside the keep-list gets
  `git --literal-pathspecs clean -ffdx -- <path>`, and every other code is skipped.
  - Tracked files are never deleted by git clean.
  - Untracked files that are not ignored were already refused by `DirtAsync` before any clean.
    W-B2 pins this: the slot is quarantined as custody/dirty and the residue and `work.txt`
    bytes are unchanged.
  - Keep-list paths (`**/obj/`, `**/bin/`, `**/node_modules/`, `/client/dist/`) are filtered out
    by `IsKeepListPath`. W-B1 asserts both the keep-list literal and that native obj/bin files keep
    their bytes and mtime.
- **No new deletion primitive.** The scoped command is the same `git clean -ffdx` the cold reset
  already runs over the whole worktree, with a narrower pathspec. Everything it removes is a
  foreign `!!` entry that made `CheckFreeAsync` quarantine the slot at base. So the change cannot
  remove warm output from a slot that base would have freed.
- **Path handling.**
  - `-z` porcelain output is unquoted.
  - `--` stops a path from being read as an option.
  - `--literal-pathspecs` stops globs and pathspec magic.
  - git rejects a pathspec outside the repository with a nonzero exit, which leads to quarantine.
- **Scratch probe (Linux git).** I ran it on these inputs:
  - an ignored `.antiphon/` holding a symlink to an outside directory, a literal `*` directory and a
    nested `bin/`
  - `tests/X/bin-row/` holding a symlink to an outside directory that contains `bin/`
  - a `-n/bin/` directory

  Result: the scoped cleans removed only the two rejected parents and unlinked the symlinks without
  following them. The outside targets, native `src/P/obj/` and the keep-list `-n/bin/` survived.
- **Windows.** The Windows junction and reparse-point behaviour is the git clean behaviour the base
  whole-tree warm and cold cleans already depend on. This change adds no new exposure. The change
  makes no path comparison of its own: git status prints `/` separators and `IsKeepListPath`
  normalises `\`.

## Fail-safe

- Any nonzero exit from the status call or a scoped clean returns an error string.
  `SettleAsync` then quarantines the slot as filesystem/reset and never reports it free. The retry
  loop is unchanged.
- An entry that is not `!!` is skipped, so `CheckFreeAsync` still quarantines it.
- The loop is bounded by the finite status output: one git process per rejected parent, in each of
  at most two reset passes.
