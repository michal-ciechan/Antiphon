## B-1 (blocker): widening HostJq exposes an in-process ETXTBSY race (reproduced 2 of 10)

- **Where:** `tests/Antiphon.Tests/Scripts/HostJqPrerequisiteScriptTests.cs:1412-1416` (`HostJqFixture.Identity`)
  writes `Control + "/replacement"` with `File.WriteAllText`, chmods it 755, and then `Process.Start`s that file
  directly (`:1586`). Every one of the 40 methods now carries `[ParallelLimiter<ScriptModelSpawnLimit>]` (6-wide).
- **Failure:** HostJq alone at width 6 (`ANTIPHON_TEST_SCRIPT_MODEL_SPAWN_LIMIT=6`, 10 consecutive leased runs at
  the reviewed SHA, `--timeout 570s`, load 4-5) gave **8 runs 40/40 and 2 runs 39/40**:
  - run 6: `C1058_Observation_failures_are_invalid`
  - run 8: `C1058_Metadata_syntax_refuses`

  Both failed with `Win32Exception: An error occurred trying to start process '/tmp/c1025-<guid>/control/replacement' ...
  Text file busy` at `HostJqFixture.Identity` `:1416`.
- **Why:** this is the classic Linux write-then-exec race, and the resource is shared by the whole process: the test
  process's own fd table. Another test's `Process.Start` forks while this test's write fd is still open. The forked
  child holds a copy of that fd until its own `exec` (O_CLOEXEC closes it only then), so this test's `execve` of the
  inode returns ETXTBSY. At width 1 only one HostJq test forks at a time, so a HostJq-only run cannot hit it. The
  per-class census (temp roots, ports, docker names, git config, HOME) and the W-5 fixed-temp lint do not model it.
  Any widened method whose fixture writes an executable and then has it exec'd is exposed. In this fixture that
  includes `WriteTool`, `Payload`, `Existing(fault)` and `IdentityExisting`, not just `Identity`.
- **Fix (Code chooses one):**
  - (a) Run fixture-written scripts through an interpreter (`/usr/bin/bash <file>`) wherever the test process starts
    them directly. The exec target is then bash, which is never write-open.
  - (b) Write the whole executable set before any concurrent window, for example under a process-wide lock that
    `Start` also takes, so no fork overlaps an open write fd.
  - (c) Keep the write-then-exec methods on `ProcessSpawnLimit`.

  Then add a witness that can go red: a lint or compiled-code walk refusing `File.Write*` followed by a direct
  `Process.Start` of the same path in a wide-lane method. Also extend the census rule in `docs/testing-and-build.md`
  and `ScriptModelSpawnLimit.cs` with "no fixture-written file is exec'd". Re-census the 11 + 12 + 1 widened Rolling
  methods for the same pattern. They were 5/5 green here, but the hazard class is the same.
