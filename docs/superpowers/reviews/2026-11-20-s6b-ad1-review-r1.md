## Q3: PowerShell coercion classes in the new code

I probed the tip library directly with pwsh, without a build. None of the results lets the shadow say Passed where the real check would fail, because the JSON branch has no production caller and is reachable only from the harness. The C# port must keep or tighten each item below. Task 3a5b76f5 does not own this file, so record these on the port card.

1. **Case-variant duplicate keys.** PowerShell 7 ConvertFrom-Json throws on `executed` together with `Executed`, which gives NotRun results-unparseable. System.Text.Json accepts duplicates (last wins). The port must refuse duplicate and case-variant keys explicitly.
2. **Case-insensitive keys.** Upper-case keys such as `EXECUTED` and `ROWS` are accepted, because PowerShell `-notcontains` and member access ignore case. A case-sensitive port is stricter, which is acceptable, but should be a deliberate choice.
3. **Unrolled single-element values.** A row Outcome given as `["Passed"]` becomes "Passed" through `[string]` and is accepted. A `rows` value given as an object instead of an array is accepted as one row. The port should refuse non-string Outcome and Identity values and non-array rows.
4. **Counters.** Test-NightlyRcWholeNumber rejects bools and arrays, and accepts the string "1" and the double 1.0. The port must keep the bool and array rejection.
5. **ISO strings becoming DateTime.** ConvertFrom-Json turns an ISO-looking Identity into a DateTime. `[string]` then reformats it, so it no longer matches the roster. This only moves rows to unexecuted, so the effect is stricter. The port should read raw strings.
6. **$null versus empty.**
   - `rows` set to null, `[]` or `[null]` all give NotRun.
   - A null roster gives @(). The port must keep this: ConvertTo-NightlyCoverageVerdict loads the production roster when the roster is null and Platform is not empty, and that must never happen here.
   - A roster with Platform '' matches nothing, which is stricter.
7. **Duplicate JSON row identities are not refused.** The TRX path refuses duplicate testIds. The port should refuse duplicates on the JSON path too.
8. **Outcome case.** A lower-case row outcome `passed` is accepted through ClassifyOutcomes. The summary outcome is compared case-sensitively, so `completed` gives Failed summary-outcome. Keep both.
