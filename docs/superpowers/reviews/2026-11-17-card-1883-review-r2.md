## Advisories (non-blocking; for the caller to file)

- **A-1: inherited over-flag.** It is not new in this diff, and it is conservative and fail-closed.
  `ReflectionBindings.Expand` prefixes every namespace using to an undotted name. Under `using System.Reflection;`,
  a receiver such as `string`, or a local typed `int`, therefore expands to `System.Reflection.<name>`, which
  counts as reflective. At the tip every uninvoked member access in such a file is classified, so any property
  read flags the file. The census shows 0 newly flagged files, because those files were already flagged by the
  base rules. Fixing it would add precision only.
- **A-2: blanket flag under a reflective static using.** A file with a reflective static using, for example
  `using static System.Reflection.BindingFlags;`, is now flagged by any uninvoked identifier. Before, only a bare
  invocation flagged it. This is conservative and gave 0 newly flagged files on the real tree. It is a
  precision follow-up only.
