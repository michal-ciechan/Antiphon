## Comment truth (4e88fc3bd)

`RunGitInputAsync` starts git and then attaches it to the job on Windows. `AssignedBeforeSpawn` is never set to true. On cancel or timeout, `TryKill` runs `owned?.TerminateMembers` first and then `if (!process.HasExited) process.Kill(entireProcessTree: true)`. The new comment's main claims are true:

- the attach happens after start;
- a grandchild started before the assignment is outside the job;
- the fallback walk is gated on `HasExited`;
- the old sentence "Kill(true) stays as the fallback for a process outside the job" was an overclaim, and it is removed.

On Linux, `owned` is null and the walk always runs while git is alive, so Linux is unaffected.

### A-1 (advisory): two wordings are stated more firmly than the code guarantees

- **Where:** `server/Infrastructure/Git/CardFileRepository.cs:416-420`.
- **Failure:**
  - "or the job kill threw": `TerminateMembers` does not throw when `TerminateJobObject` returns false. It only logs `terminated=False`. The realistic case where git is still alive is a false return, and the comment does not name it.
  - "A successful job kill has already exited git, HasExited is true, and this walk is skipped": `TerminateJobObject` starts termination and does not wait for it, in the same way as `TerminateProcess`. If `HasExited` is read before git's handle is signalled, the walk does run. It then finds the pre-assignment child, whose parent pid is still git's, and kills it. In that window the comment's "It does not collect that grandchild" is wrong in the safe direction.
  - "Same attach-after-start limit as LandingGit" is true of the attach. But `LandingGit.ReleaseChildAsync` runs the tree walk BEFORE the job kill, so LandingGit does collect a pre-assignment child of a live git. CardFileRepository does not.
- **Why:** this does not change behaviour, and it is no worse than the overclaim the card set out to remove. The g82 Review graded that original overclaim as an advisory.
- **Fix:** reword the comment to say the walk is usually, not always, skipped, and to name the false-return case. Alternatively, run the walk before the job kill, as LandingGit does. Better still, let the CARD-1850/1852 containment design remove the limit. Filed as CARD-1859.
