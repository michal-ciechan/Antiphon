### D-1 (blocker): `GET /api/session-runners` still reads the shadow load by the raw runner id

- **Where:** `server/Api/Endpoints/SessionRunnerEndpoints.cs:44`
  (`Load = load?.Get(r.RunnerId)`) and `:64` (`Load = ...?.Status(runnerId)`).
- **Failure:** `HostLoadHistoryService.CurrentAsync` stores the shadow under the canonical key
  (`shadows.Set(runner, advice)` with `runner = Known(hostId) = _keys.Canonical(hostId)`, `:28`,
  `:50`). With `DirectRunnerKey=server2-direct`, the key S1's compose sets for the cutover, the
  shadow lives at `server2-direct`. The catalogue's direct row (`RunnerPlatformWire.DesktopId` =
  `desktop`) and `/api/session-runners/desktop/status` then read `desktop`, which nobody writes.
  Their `load` becomes null. Today, at the default key, these readers are populated.
- **Why:** D-3 says readers map the direct ids through `Canonical`. The pipeline readers were
  converted but these two equivalent readers of the same shadow were not. After cutover, the
  documented runner listing loses the direct runner's load signal.
- **Fix:** resolve `HostLoadRunnerKeys` (registered singleton) in both handlers. Read
  `Get(keys.Canonical(r.RunnerId))` and `Status(keys.Canonical(runnerId))`. In `Status`, index
  `_values` by the same key it read. Add a witness beside W-7: shadow `desktop`=X and
  `server2-direct`=Y; with the key set to `server2-direct`, the endpoint's `desktop` row load is
  Y. It is red at this tip. Add the class to the CP-6 row.
