## Defects

### B-1. Stop gate 6 refuses every rollback on the production schema (uuid primary keys)

- Where: `scripts/cutover-postgres-server2.ps1`, `Get-CutoverContentFingerprintSql` (`COALESCE(max("<pk>")::text, '')`), reached from `Test-CutoverNewHasExtraRows`, which `Invoke-CutoverRollback` calls.
- Failure: 118 of the 140 entities in `server/Migrations/AppDbContextModelSnapshot.cs` have a Guid `Id` (Postgres `uuid`). PostgreSQL 16 has no `max(uuid)`. On a throwaway postgres:16 container, `SELECT ... max("Id")::text ...` on a uuid-keyed table fails with `ERROR: function max(uuid) does not exist` (exit 3). I ran the script's own probe path (`-VerificationProbe rollback-rows`) against two IDENTICAL, quiescent throwaway containers, each with one uuid-keyed table. It printed `REFUSED: stop gate 6: row comparison failed. Neither data directory is removed.` (exit 3). `Invoke-CutoverRollback` refuses a null result before it checks `-AcceptDataLossRollback`, so the operator has no override either.
- Why it blocks: the pre-change count gate worked on this schema. After this change the rollback can never pass, so the production emergency path is dead. All witnesses use `integer` primary keys, so CP-1 cannot see it. The card's acceptance says a quiescent identical pair passes, and on the real schema it does not.
- Fix: make the high-water mark type-independent. Either use `max("<pk>"::text)`, or drop the high-water mark: the md5 over `row_to_json` already covers every column. Then add an EF-shaped witness to `scripts/test-cutover-postgres-verify.ps1` (uuid PK, jsonb, timestamptz, a table with no key) that must pass for an identical pair and must refuse after an in-place update. Landing owner stays Code ab41aa31.
