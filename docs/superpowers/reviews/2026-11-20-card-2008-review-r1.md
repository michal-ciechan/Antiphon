The process exit is stricter in the shadow: `exit-N` Fails even where the native check tolerates the exit. `discovery-produce-failed` reaches the verdict as missing discovery. Client and scripts never set the record flag. The booleans are strict `-is [bool]`, so a string, an int, null or a missing field is NotRun. **One native input is not in the chunk shadow:** the suite-level union check in `Complete-NightlySuiteExecution` (`missing-expanded-row union`). It is a suite verdict, not a chunk verdict, so chunk parity holds. This is advisory AD-2.
2. **Ordering.** The record now runs after the verdict and freshness. Each one is recorded once (V-8 checks that `Register-NightlyRcChunkRevision` appears exactly once), and the later timeout and completed-hang code never rewrites it. If the code throws between the run and the record, no revision is written. The old code wrote one built from the TRX alone. That fails closed, since a missing revision is never Passed (AD-1). Revisions are append-only, so a retry can append Passed after Failed; that is unchanged by this diff (AD-5). The interrupt path is unused by the implementation.
3. **The A-2 witness calls the real `ConvertTo-NightlyNativeSuiteVerdict` and `Test-NightlyFreshEvidence`, not a stand-in.** It does not run `Invoke-NightlyScheduledChunk`. The wiring check is source-position only (AD-3). The red commit was red for every stated reason (see the table).

No real verdict variable, exit code, `summary.json` field or log line changes. The record functions are not newly wrapped and are not newly throwing: `Get-NightlyRcChunkOutcome` was already unwrapped, and Register is non-strict.
