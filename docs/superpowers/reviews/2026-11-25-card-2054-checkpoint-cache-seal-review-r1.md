## Findings

1. **Standalone no-build replay rejects its producing binary.** The scheduler writes the three warm-layout properties into the binding and passes them to its own rows. The standalone command reconstructs the private layout. On the first Review run’s actual stamp, the production binding check returned `verified` with the six producer properties and `mismatch` with the three standalone properties. The project, output, source SHA and fingerprint were identical. A strict `row --no-build` therefore returns `build_source_mismatch` before slot acquisition. The generated failure rerun command also omits the warm properties. Carry a validated producing layout through standalone replay and protect the shared partition for the reader’s lifetime. Cover a retained warm output and a cold-fallback output through the public row command. [Standalone admission](../../../tools/Antiphon.Checkpoints/Execution/RowCommand.cs#L94) · [Scheduled publication](../../../tools/Antiphon.Checkpoints/Execution/RunScheduler.cs#L649) · [Generated rerun](../../../tools/Antiphon.Checkpoints/Evidence/EvidenceFolder.cs#L80)

2. **Cache hashing delays cancellation while holding the worktree gate.** The scheduler calls `Prepare` before slot admission. Both eligibility and publication traverse the partition with `Digest`, which takes no cancellation token. Each member read receives the default token. Cancellation during a scan can leave the executor reading the remaining files while another executor waits or falls back cold. The duration grows with the partition, even after the run’s deadline. Pass the run token into enumeration and bounded member reads, preserve the cancellation outcome, and cover cancellation during preparation and publication. This finding follows the production control flow. [Preparation](../../../tools/Antiphon.Checkpoints/Execution/RunScheduler.cs#L438) · [Digest](../../../tools/Antiphon.Checkpoints/Execution/CheckpointIntermediateCache.cs#L345) · [Publication](../../../tools/Antiphon.Checkpoints/Execution/CheckpointIntermediateCache.cs#L428)

3. **The Linux FIFO witness has a second reason to pass.** The fixture creates the seal’s parent and a FIFO but never creates the keyed partition directory. `Prepare` rejects a partial pair. The test can therefore stay green if an existing partition loses its nonregular-seal protection. Create the keyed directory, assert it exists, and assert the file-type refusal within the bound. Keep the partial-pair case distinct. [Fixture](../../../tests/Antiphon.Tests/Checkpoints/CheckpointWarmBuildTests.cs#L242) · [Eligibility](../../../tools/Antiphon.Checkpoints/Execution/CheckpointIntermediateCache.cs#L146)

The warm replay and digest behavior entered the candidate with the cache port. The partial-pair rule added by the seal repair weakens the existing FIFO witness. The standalone mismatch was observed on a real stamp. The cancellation and FIFO findings follow from the paths and assertions above.
