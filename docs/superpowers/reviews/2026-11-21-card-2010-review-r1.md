## Advisories (cards, do not hold the land)

- **A-R1 (wrapper rewrites passthrough data).** `ConvertTo-RcCamelCase` rebuilds the caller's
  `-SampleFailure` when it returns it as `preservedSampleFailure`. The pre-port code returned the
  caller's own object unchanged.
  - Observed: `[pscustomobject]@{ Kind='sample-outcome'; chunkId='c1' }` comes back as a new object,
    `{"kind":"sample-outcome","chunkId":"c1"}`, with ReferenceEquals false.
  - It would also drop script and alias properties.
  - Hashtables pass through unchanged, so the current test comparisons still hold.
  - Impact: none today, since there is no production consumer. A later JSON digest or identity
    check on that field in the S6c/S6d wiring would diverge from the pre-port behavior.
  - Fix: convert only the result-class properties, and return caller-supplied values verbatim.
- **R-1 (plan row CP-13 is stale for the replay).** Its `-BaseRef 8af57860` is not an ancestor of
  the replay tip, so the row always exits 2. The plan's Base line ("origin/master does not contain
  that port commit") is stale too. The replacement run on `328eafa3` is green.
- **R-2 (plan row CP-14 cannot go red for policyHash).** It dot-sources
  `scripts/lib/nightly-policy.ps1`, which master removed in 47dd2f06c. Read-NightlyExecutionPolicy
  is therefore undefined, the row prints an empty `policyHash` and exits 0. The pin is established
  above by byte identity with master.

## Windows: unobserved

- `RcPortWrapperCasingTests` starts `pwsh` by name. On Windows that resolves to the MSIX alias, and

  LF, so `-Prove` would report `BYTES differ` there. The C# replay parses JSON and is unaffected.
