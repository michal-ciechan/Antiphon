## Fail-closed analysis (false skip)

The new branch is reached only after the unchanged `OnlyDocumentation` classifier passes, and only
when the embedded-manifest comparison has already failed. So it fires only on a diff that the old code
would also have treated as docs-only, and that the old code built for one reason:
`unrecognized-build-graph`, because the embedded manifest did not match. It cannot be reached with a
diff that the old code built as `diff-requires-build`.

| Vector | Result |
|---|---|
| Diff touches docs and a build-definition path | `diff-requires-build` (`C_FT2_BuildDefinitionByteStillBuilds`, killed by mutant) |
| Rename or move into or out of `docs/` | Both rename sides must be `README.md` or `docs/**.md`, so the diff builds |
| Delete or add of a docs path | Allowed only as mode `100644` with a zero oid on the correct side |
| Symlink, gitlink, executable, or mode change | Builds: old and new mode must be `100644` |
| Case variants (`Docs/`, `.MD`) or backslash or `..` paths | Not documentation (ordinal `SafePath`), so it builds |
| Path that is both docs and graph (`docs/Directory.Build.md`) | The candidate graph then differs from the target graph, so `unrecognized-build-graph` |
| Candidate supplies its own manifest | Not possible. The manifest is read with `git show <TargetBeforeSha>:<path>` from the target tree. Changing the manifest path is a non-docs diff, so it builds |
| Stale committed manifest | Builds unless the manifest equals the target graph exactly (SHA-256 over mode, oid and path rows, plus the count). An equal digest means the graph bytes are the ones the audit wrote it for |
| Missing, malformed, U+FFFD, BOM-prefixed, or unreadable manifest | Builds (tests for stale, malformed, missing and unreadable; BOM gives a 65-character line, so `ParseManifest` returns null) |
| Target moves between the decision and the push | Unchanged. The decision uses `op.TargetBeforeSha` and the pinned `op.RebasedSourceSha`. The push is a CAS against `RemoteBeforeSha ?? TargetBeforeSha` (`remote_changed_before_push`). A retry is a new operation that rebases again and decides again |
| Embedded match | Still returns `non-code` before the target tree is read (`C_FT2_EmbeddedManifestSkipUnchanged`, missing and stale) |

**Trust.** The committed manifest is written only by `scripts/audit-land-verification-graph.ps1 -Update`,
which requires the emulation pre-check and a real MSBuild evaluation. It is the same file the
embedded path trusts. The embedded copy is that file at the running server's commit; the new path
reads it at the target tip. What changes is timing: a reviewed master manifest now takes effect at the
next land, instead of after an rc port and a restart. Land verification is a build only (FT-0 G2), so
the skip drops no test coverage that the land had before.

`EA552D85…/80`. At `f997d3f06` (master moved during this review) both are `9147CEA0…/80`. Both were
recomputed with the production selector and hash. So the new skip **would fire on master today**.
`DA2C126C` was the stale manifest at the older base `8a89aa0e5`. The skip stops firing after any
code land that changes a graph file, until the next land-graph refresh commit. That commit is not
docs-only, so it builds.

## Advisories (do not hold the land; file as cards)

- **A-1 Misleading receipt.** `AgentTaskLandingProtocol.cs:337` still writes `Skipped(non-code); …; graph=<embedded digest>`.
  For a target-manifest skip, that digest does not equal the candidate graph. Nothing downstream parses
  it: only `BuildSlotNote` reads `VerificationCommand`, and the Verify stage detail and the log use
  `VerificationSkipReason` or `decision.Reason`, which are correct. The plan promised `trust=` at that
  line and dropped it. Minimal fix: return the matched digest in `Decision`, and write
  `Skipped({decision.Reason}); …; graph=<matched>`.
- **A-2 Rollback strands an in-flight land.** A pre-FT-2 server's `HasVerification` rejects
  `docs-skip-target-manifest`. If an operation reaches Verified or PushStarted under an FT-2 server and
  is then resumed by an older one, the transition is refused (`landing_transition_refused`). This fails
  closed and loses nothing, but the land has to be retried. When porting to rc, move the policy and the
  state literal together, and roll back only while no land sits between Verified and PublicationConfirmed.
- **A-3 Duplicate oracle.** The test helper `SelectGraph` copies `TryReadGraph` line for line. Keeping an
  independent oracle is defensible. If the selector changes, update both.
- **A-4 Activation.** The change takes effect only after an AppHost restart on a build that contains it,
  which means an rc carrying FT-2. A master land is not activation.
