# CARD-0048 — Answer OpenConsole's DA1 query so the modern pty stops freezing every child for 3 s

**Status:** Plan (not implemented). 2026-08-16.
**Card:** CARD-0048 "Modern pty: a child is silent for 2-5s on first typed input, and production runs modern" (`a7c1d9b2-cf2e-4724-8916-65a652f69a56`). CARD-0049 closed as its duplicate and rides on this fix.
**Root cause:** PROVEN, do not re-derive — `docs/investigations/2026-08-16-modern-conpty-da1-stall-CARD-0048.md` (a7bf42f). `OpenConsole.exe` emits `ESC[c` (DA1) at startup and holds the console **client** until a DA1 response arrives or ~3.0 s elapses. Nothing in our stack answers; the inbox conhost never asks.
**Relates to:** CARD-0037 (modern backend, ADR `docs/adr/0002-modern-conpty-backend.md`), CARD-0045 (backend test equivalence, spec `2026-08-15-card-0045-pty-backend-test-equivalence.md` — its slice 2 guard is why nothing in the default suite currently exercises modern-only code unless the test pins `"modern"` explicitly).

**The deliverable in one sentence:** on the modern backend a child's first output arrives in tens of milliseconds instead of ~3 s, the fix is owned by `ModernConPtyConnection`, it is pinned by modern-declaring tests that run in the default suite on any machine with the redistributable, and the inbox path is byte-identical to today.

---

## 1. Decision 1 — the response string: `ESC[?1;0c`, kept from the probe, with an explicit escalation gate

**Production answer: `\x1b[?1;0c`** — DA1 response "VT101 with no options".

Why this one and not something richer:

- **It is proven.** It is the only string measured to unblock the client (43 ms vs 3061 ms); a plain byte, a CPR (`ESC[1;1R`), and a mangled reply all leave the stall intact (investigation §2). The full casualty suite went 0F with it, twice each (§6), and the reply is consumed by OpenConsole's input state machine and never reaches the child (§5) — so it provably cannot change what Claude or Codex negotiate. The only remaining channel for behavioural change is OpenConsole itself adapting its **output translation toward us** or **input translation toward the child** based on what we claim.
- **It is accurate, not just conservative.** The DA1 response describes the *hosting terminal* — and our hosting terminal is `PtyAgentRunner`'s scraper (`TerminalScreen` + string detectors). It genuinely is a minimal terminal: no sixel, no soft fonts, no rectangular editing, no horizontal scroll margins, and it ignores the `ESC[?9001h` win32-input-mode request. Claiming the VT101-no-options profile tells OpenConsole the truth. It is also the same string legacy conhost's own VT engine historically returns to a client DA1, so it is a reply every console codebase already tolerates.
- **The risk is asymmetric.** Claiming too much invites OpenConsole to emit sequences `TerminalScreen` cannot parse, silently degrading every snapshot-based detector. Claiming too little risks only that OpenConsole withholds a passthrough feature we depend on — and we depend on exactly one, bracketed-paste/DECSET-2004 marker delivery, which is **directly pinned by an existing test** and becomes this slice's acceptance gate.

**The gate (the card's required re-check):** with the responder active, `PtyBackendContractTests` (especially `The_production_write_path_delivers_the_markers_on_the_modern_backend`), `PtyBracketedPasteContractTests` (inbox arm untouched), and the modern paste arm of `FakeClaudeContractTests` (`LaunchClippingFakeOnModernPtyAsync` tests, incl. `A_collapsed_paste_still_produces_composer_evidence`) must all pass. The §6 probe runs did **not** include the marker tests, so this is genuinely unverified — it is the one experiment slice 2 must run before merging.

**Escalation path if the gate fails** (recorded now so the fallback is a decision, not a scramble): claim what a real Windows Terminal claims, since ConPTY is designed to sit inside one. Do not guess the string — capture it: run the existing `NodeStdinProbe` (or a 10-line probe) *inside* Windows Terminal and record WT's actual DA1 reply, or read it out of the `microsoft/terminal` source at the tag matching `ConPtyRedistributable.PackageVersion` (1.24.260710001). Then re-run the same gate. Under no circumstances include sixel (`4`) in the claim — `TerminalScreen` cannot parse sixel output.

**Scope: answer the FIRST DA1 only, per session.** The startup query is guaranteed to be the first `ESC[c` on the pipe *because of the defect itself* — the child is frozen until it is answered, so nothing else can have written output. Answering only that one is exactly the case §5 proved safe (consumed, never reaches the child). A *later* DA1 could in principle be a child query forwarded by OpenConsole; answering it might route our reply to the child and change TUI negotiation — the precise risk the card warns about. So: first query answered, subsequent `ESC[c` occurrences counted and surfaced (`Da1QueriesSeen`), not answered. If field counters ever show a second query, that evidence reopens the scope question with data.

## 2. Decision 2 — where the fix lives, and how modern-only code gets default-suite coverage at all

### 2.1 Ownership: `ModernConPtyConnection`, via a wrapped reader stream

`ModernConPtyConnection` introduced the query; it answers it. The inbox path (`PortaPtySession`) is untouched — not "guarded off", structurally absent. `PtyAgentRunner.ReadLoopAsync` (shared by both backends, and the probe's re-entry-into-`WriteAsync` concern) is untouched.

Mechanics:

- New `src/Antiphon.Agents.Pty/Da1StartupResponder.cs` — a pure byte-level state machine: scan passing output bytes for `ESC [ c` / `ESC [ 0 c` **across read-chunk boundaries** (the init burst arrived as one read in every measurement, but a split query must not defeat the fix), invoke a reply callback exactly once, count further queries. Holds the response constant with the §1 justification as its doc comment. No I/O — unit-testable without a pty.
- `ModernConPtyConnection` wraps its `ReaderStream` in a thin internal pass-through decorator (override `Read`/`ReadAsync(Memory<byte>)`; every byte passes unmodified — snapshots, audit, and the visible `ESC[c` in output all stay exactly as today). On first match it writes `\x1b[?1;0c` as **one write on a dedicated non-owning `FileStream` over `_inWrite`** — not `WriterStream`, so there is no shared-instance thread-safety question with `PtyAgentRunner`'s writes, and no interaction with the write gate. A pipe write is one `WriteFile`; it cannot split a concurrent runner write, so the SINGLE-WRITE delivery ceilings are unaffected (and in practice the reply lands ~31 ms after spawn, before any adapter writes — the child is frozen until then). Swallow `IOException`/`ObjectDisposedException` on the reply write (child may have died).
- Expose `internal DateTimeOffset? Da1AnsweredAt` and `internal int Da1QueriesSeen` on the connection (`InternalsVisibleTo Antiphon.Agents.Pty.Tests` already exists). Optionally surface "DA1 answered at +Nms" as a `PtySessionAudit` note if the audit type has a cheap seam; do not build one for it.

### 2.2 Coverage: modern-declaring tests are exempt from the CARD-0045 guard by design — use that

CARD-0045 slice 2's `PtyBackendEnvGuard` clears the inherited env var, so the **default** backend in every test host is inbox and an env-driven modern sweep no longer exists. But the guard never touched the per-instance override: `new PtyAgentRunner("modern")` and `SessionRunnerSettings.PtyBackend = "modern"` (the slice-3 `--pty-backend` seam, commit 59fdb4e) outrank the environment. `PtyBackendContractTests` already runs modern this way in the default suite today.

So the answer to "a modern-only fix would be exercised by NOTHING" is: **every regression test for this fix declares `"modern"` explicitly**, lives in the normal (non-headed, non-Explicit) suite, and skips via the existing pattern — `ConPtyRedistributable.TryLocate` failing ⇒ `SkipTestException` (`RequireShippedDll()` in `PtyBackendContractTests` is the template). On any machine that builds the repo the redistributable is staged into test output by `Antiphon.Agents.Pty.csproj`, so in practice these tests RUN everywhere and the skip only fires on a genuinely bare machine — which is the CARD-0045 §2 design ("a modern-asserting test SKIPS when the redistributable is absent"), i.e. this is CARD-0045's optional slice 4 finally paid, scoped to the facts this fix creates.

## 3. Decision 3 — the quiet-window constants do NOT move; the soundness gap gets its own card

**No production constant changes in this card.** `CodexReadyQuietPeriodMs` 1000, `CodexDoneQuietPeriodMs` 3000, `ClaudeReadyQuietPeriodMs` 5000 / `MinTotalWait` 9 s, `RunnerRawAdapter`/`RawPtyAdapter` `ReadyGrace` 500 ms / `TurnQuietPeriod` 2 s all stay. Reasoning:

- With DA1 answered there is **no configuration that exhibits the stall**: fixed modern starts the child in ~40 ms, inbox never stalled, and a modern request that *falls back* runs inbox. The constants' assumption ("a pty starts its child promptly") is true again everywhere.
- Widening them was explicitly rejected by the investigation — it hides the exposure instead of fixing it, and taxes every turn forever.
- "Enforce that a readiness quiet window exceeds the known worst-case stall" is not implementable as a settings validator once the stall is fixed — there is no runtime constant to compare against, and post-fix the honest bound is ~0. The enforcement that IS implementable is empirical, and this plan ships it: **the slice-3 latency pin** (`first child output < 2.5 s` on modern, against a stall floor of 3.0 s) keeps the worst-case startup stall measured near zero on the exact hash-pinned binary. If a future `Microsoft.Windows.Console.ConPTY` bump introduces a new handshake, that test goes red before any quiet window silently becomes a coin flip — and the bump itself already requires deliberate re-measurement (`The_shipped_binaries_are_the_ones_with_recorded_provenance`).

**What deserves its own card (file it, do not ride it here):** the structural gap the stall exposed is backend-agnostic — *readiness and turn-completion accept pure silence as evidence.* `CodexReadyDetector` is quiet-only; `RunnerRawAdapter.WaitForReadyAsync` is a 500 ms grace, full stop; `WaitForTurnCompleteAsync` will report `TurnCompleted: true` with empty `ResponseText` whenever the child is slow for ANY reason (cold AV scan, WSL start, loaded box — not just DA1). Requiring "evidence of life" (≥1 byte of child output beyond the console host's own init burst) before quiet can count, and refusing to settle a turn on an empty snapshot, is a real behaviour change to production adapters with its own failure modes (what counts as init burst?) and its own test surface. New card, referencing investigation §9; suggested title: "Ready/done detectors accept silence as evidence — a slow child start reads as a completed empty turn." Riding it here would couple a proven 7-byte fix to an open-ended adapter redesign.

## 4. Slices

Each slice lands and verifies independently. Build with `--property:OutputPath=bin-<name>/` (forward slash), foreground, and delete the ~12 `bin-<name>` dirs afterwards. TUnit: `dotnet run --project tests/<X> ... -- --treenode-filter "/*/*/<Class>/*"`.

### Slice 1 — the responder, pure and unit-pinned

**Files:**
- NEW `src/Antiphon.Agents.Pty/Da1StartupResponder.cs`: byte state machine (`Scan(ReadOnlySpan<byte>)` → fires reply callback on first complete `ESC[c`/`ESC[0c`; `QueriesSeen` counter; `AnsweredAt`), plus `public const string Response = "\x1b[?1;0c"` carrying the §1 justification and the escalation note.
- NEW `tests/Antiphon.Agents.Pty.Tests/Da1StartupResponderTests.cs`.

**Tests that prove it (all deterministic, no pty):** query in one chunk fires once; query split at every byte boundary (`ESC` | `[c`, `ESC[` | `c`, `ESC[0` | `c`) fires once; `ESC[0c` variant fires; second query increments `QueriesSeen` but does NOT fire; lookalikes never fire (`ESC[?1004h`, `ESC[?9001h`, `ESC[201~`, literal text `[c` with no ESC, `ESC[1t`); interleaved noise around a split query still fires.

Dead code until slice 2 — safe to land alone.

### Slice 2 — `ModernConPtyConnection` answers, and the response string passes the contract gate

**Files:**
- `src/Antiphon.Agents.Pty/ModernConPtyConnection.cs`: wrap `ReaderStream` per §2.1; dedicated one-shot reply `FileStream` over `_inWrite`; expose `Da1AnsweredAt` / `Da1QueriesSeen`; dispose the wrap in `Dispose`.
- NEW tests in `tests/Antiphon.Agents.Pty.Tests/` (class `ModernPtyDa1Tests`, `[NotInParallel("Headed")]`, `[Category("Pty")]`, `RequireShippedDll()`-style skip; every runner constructed with `"modern"` explicitly — the env guard is irrelevant to it):
  1. `Modern_child_first_output_arrives_without_the_da1_stall` — `new PtyAgentRunner("modern")`, `cmd /d /c echo DA1-FIX-MARKER`, assert marker within **2.5 s** (healthy ≈ 43 ms, stall floor ≈ 3.0 s; margin is wide both ways, and a load-induced red is a visible false alarm, never a silent pass). This is the fix's direct pin and the §3 enforcement test.
  2. `The_da1_reply_is_consumed_and_does_not_leak_to_the_child` — interactive `cmd /d /q /k` on modern, send `echo leak-check-ok`, assert the echo lands and the snapshot contains neither `?1;0c` as child-visible text nor `is not recognized` (the investigation's measured leak signature).
  3. `The_connection_answers_exactly_one_da1` — internals: after start + settle, `Da1AnsweredAt` is set and `Da1QueriesSeen == 1` (doubles as the field probe for the §1 second-query question).
- Inbox non-regression is structural (Porta path has no responder) and already pinned by the inbox suite; no new inbox test.

**The gate (must run before merge, all foreground):** `PtyBackendContractTests` full class (markers still delivered through the production write path with the responder active), `PtyBracketedPasteContractTests` (inbox still strips), `FakeClaudeContractTests` modern-paste arm incl. `A_collapsed_paste_still_produces_composer_evidence`, and `PtyDeliveryCeilingsTests`. Any red here reopens §1's escalation path — do not merge a response string the gate rejects, and do not weaken the gate.

### Slice 3 — regression coverage for the casualty shape (CARD-0045's slice-4 debt, scoped to this fix)

**Files:**
- `tests/Antiphon.Agents.Pty.Tests/ModernPtyDa1Tests.cs` (same class as slice 2): add `WaitForQuiet_on_modern_returns_false_from_launch_under_continuous_output` — modern runner, the investigation's continuous-echo bat, `WaitForQuietAsync(quiet 2 s, max 3 s)` started **immediately after `StartAsync`** (the window must cover the launch, or the test cannot see a stall) asserting `false`. This is the exact original casualty (`PtyAgentRunnerTests.WaitForQuiet_returns_false_under_continuous_output`) re-stated with a declared backend; red without the fix (3/3 measured), green with it.
- `tests/Antiphon.SessionRunner.Tests/PtyHostAdoptionTests.cs`: add `Exit_while_runner_down_is_collected_on_adoption_on_the_modern_backend` — the existing CARD-0049 test body with `BuildSettings()` setting `PtyBackend = "modern"` (the slice-3 seam threads it to the detached host via `--pty-backend`) + skip-if-no-redistributable. This pins the fix **through the detached pty-host and the shadow-copy path** — the fix ships inside `Antiphon.Agents.Pty.dll`, an ordinary deps.json assembly, so `ShadowCopyStore` carries it with no change (the CARD-0037 Content-item trap applies only to the conpty pair) — and it is CARD-0049's regression lock: red without the fix (child exits at ~5 s > the 4 s adoption point), green with it (~2 s).

**Verify:** run both new tests with the fix present (green) and — once, as a scratch check, not committed — with the responder disabled, confirming both go red for the documented reason. Then the CARD-0045 equivalence check on the touched projects: full run of `Antiphon.Agents.Pty.Tests` and `Antiphon.SessionRunner.Tests` with `ANTIPHON_PTY_BACKEND` unset and exported=`modern` — identical results (the guard still clears env; the new tests pin `"modern"` themselves so they run in both arms).

### Slice 4 — file the detector-soundness card; record the docs

**Files:**
- New card (board API, per §3): silence-as-evidence in `CodexReadyDetector` / `RunnerRawAdapter.WaitForReadyAsync` / `WaitForTurnCompleteAsync`-empty-`ResponseText`; cite investigation §8–9; state explicitly that the DA1 fix removed the known 3 s instance and this card is about the class.
- `docs/adr/0002-modern-conpty-backend.md`: append the DA1 handshake fact and the fix (the ADR owns "what the modern backend is"; a startup handshake the connection must answer is part of that contract now).
- `CLAUDE.md` gotcha bullet (short): modern OpenConsole demands a DA1 answer at startup; `ModernConPtyConnection` answers `ESC[?1;0c` once per session; any new code path that creates a modern pseudoconsole without going through it re-inherits a 3 s frozen client; pinned by `ModernPtyDa1Tests`.
- CARD-0048 resolution: proven cause → fix → the three decisions above → pointer to the new card; note CARD-0049 stays closed and is now regression-locked by the modern adoption test.

**Deployment note (goes in the resolution):** already-running detached pty-hosts keep their old shadow-copied binaries until the session ends — the fix applies to sessions launched after deploy. Restart the runner with `scripts/restart-session-runner.ps1` (sessions survive) and the server via `scripts/restart-apphost.ps1` so the in-process server adapters (`RawPtyAdapter`/`CodexAdapter`) pick it up.

**Landing order:** 1 → 2 → 3 → 4. Slice 2 is the fix; 2's gate is the card's mandated re-check; 3 is what keeps it from rotting.

## 5. What I could not determine, and what would settle it

1. **Whether marker passthrough survives an `ESC[?1;0c` claim.** The §6 probe runs never exercised the marker tests. Settled by the slice-2 gate, before merge. Fallback documented in §1.
2. **Whether OpenConsole ever emits a second DA1** (post-resize, or forwarding a child's query). Never observed; first-only scope is provably safe regardless. Settled over time by `Da1QueriesSeen` (test 3 asserts ==1; if a live session or future run ever shows >1, that datum reopens the scope decision).
3. **Windows Terminal's exact DA1 reply at package 1.24.260710001** — only needed if (1) fails; settled by capturing it empirically inside WT or reading the pinned terminal source. Deliberately not guessed here.
4. **Whether the 2.5 s latency bound is flake-free under full-suite load.** Healthy is ~43 ms and the class is `[NotInParallel("Headed")]`, but this repo documents PTY-timing flakes under parallel load; a red here is a visible false alarm (rerun in isolation per CLAUDE.md), never a silent pass. Evidence accumulates for free from suite runs.
5. **Real-TUI behaviour on the fixed backend** (Claude/Codex headed). By construction nothing the child sees changes except starting 3 s sooner, and the reply never reaches it; a headed confirmation (`FakeVsRealClipParityTests`, `[Explicit]`, costs no model turns) is available if wanted, not required.
