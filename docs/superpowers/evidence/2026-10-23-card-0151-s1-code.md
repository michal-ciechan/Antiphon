## Implementation

Card creation accepts a nullable decimal effort estimate. Content edits can set or clear it;
omission/null preserves it. The existing content-edit revision captures the superseded
estimate before mutation. Both DTOs omit the property when null. Shared create/edit validation
requires `0 < estimateDays <= 365` with at most two decimal places, rejects value-plus-clear,
and runs before writes. Estimate-only edits count as content changes. Existing concurrency,
bounded reason and transition logging behavior remains in use.

The change touches Card, CardRevision, AppDbContext, request/response DTOs, CardService,
BoardService mappings, CardRevisionLog, the API documentation and CardEstimateTests.
No new audit table, ledger route, CLI/UI feature or backfill was added. No private-notes
route or production card-note body was read, copied or exported.

The HTTP tests use the existing isolated PostgreSQL WebApplicationFactory with production
runner launches refused and the card-file publication tick disabled. They exercise fresh
request scopes, persisted GET values, revision values, unset JSON omission, legal boundaries
0.01/365, title-only preservation, clear, all four invalid numeric inputs and value-plus-clear.
Rejected edits preserve the token, revision count and title; rejected creates leave no card.
