## Causes found (base, under a CPU stressor)

Stressor: `nice 19` busy loops (48) beside a `nice 19` vitest over the six files named by the card and
the CARD-1256 inventory (`AgentHerdrPlacement`, `AgentsPage`, `hostStatsHubReceipt`,
`AgentAttachHerdr`, `AgentCreateModal`, board `SessionTabs`). Script: scratch `stress.sh`, run through
`scripts/build-slot.ps1` (not committed). Load averages are the `uptime` lines printed per repetition.

1. **Per-key typing.** `userEvent.type` on long strings in large Mantine forms ran into the 20 s hang
   detector. The timed-out test's typing kept running and landed in the next test's field: base
   failures `expected 'hOrch2' to be 'Orch2'`, `'src\aOprpch2'`, `expected 'redi' to be ''`.
2. **findBy/waitFor windows after fetch-driven renders.** Under load the MSW reply plus the render
   outlasted the 1 000 ms window (`Unable to find role="button" and name "Attach…"`, `"Start"`,
   `"Add Card"`). In `AgentCreateModal` the Phone radio was clicked before the preset reads settled,
   and the preset then reset it (`creates an explicitly Phone agent`: radio not checked).
3. **Receipt test anchor.** Node start-up and the SignalR `require` counted against
   `hostStatsHubReceipt`'s 2 300 ms test limit (timeout plus 2 s), measured from process spawn
   (`receipt exceeded timeout plus 2 seconds`). The script arms its own 0.3 s timer after the
   `require`.

## Change (tests, test utilities, and the production SessionTabs terminal loader)

- `client/src/test/utils.ts`: `settleQueries(queryClient)` waits inside `act` on the query and mutation
  caches' idle events, one zero-delay tick per round, looping while a flush leaves work in flight.
  While settling, React Query's notify scheduler is `queueMicrotask` (restored after): with the
  default `setTimeout 0`, `useQuery`'s second notify hop landed after the tick and the round ended
  with data cached but not rendered (seen in `AgentsPage › offers Stop…` during this task).
  `pasteInto(element, text)` focuses and pastes.
- Agents tests named in the base failures: `settleQueries` after render and after each
  fetch-triggering action, then synchronous `getBy*`/`expect`; per-key typing replaced by
  `pasteInto`. Asserted request bodies and values are unchanged. Two `AgentAttachHerdr` text lookups
  became roster-button lookups, because after settling the detail panel repeats the agent name.
- `hostStatsHubReceipt.test.ts`: the same 2 300 ms limit now starts at the fake hub's first accepted
  socket. The script arms its timeout before `connection.start()`, so a hang after connecting still
  fails the test. **Decision for Review:** this removes process start-up from the bounded interval;
  it is a changed anchor, not a changed number.

- `SessionTabs` (second round, CARD-1256 pattern): `client/src/features/board/sessionTerminalLoader.ts`
  owns one memoised `loadSessionTerminal()`; `SessionTabs` builds its lazy terminal from it. The
  test awaits that promise, renders inside one async `act`, then asserts with `getByTestId`.
  `SessionTabs.tsx` and `sessionTerminalLoader.ts` ship in the client bundle; a server restart is
  needed after landing to serve the updated bundle.

No `testTimeout`, `asyncUtilTimeout` or per-file timeout was changed; no test was skipped.

## Modal render cost (one bounded measured step)

Scratch probe (not committed): a copy of `AgentCreateModal.test.tsx` › `defaults to Standing
orchestrator…` with phase timers and a counting wrapper around `window.getComputedStyle`, run
through `build-slot.ps1` at host load average 8–30 (`uptime` beside the runs).

- Per phase, cold test (runs `idle1`–`idle5`, `gcs6`, `gcs7`): render 905–1 326 ms, first settle
  1 117–1 736 ms, each paste 132–552 ms, Create click 205–262 ms. A second, warm run of the same test
  in the file: render 411–618 ms, settle 937–1 522 ms. The modal is 307 DOM elements.
- `getComputedStyle`: 1 564 calls per test, 1 106–1 515 ms cold and 730 ms / 764 ms warm
  (`gcs6`, `gcs7` cumulative minus cold). By first non-wrapper stack frame (run `callers`):
  1 403 from `@floating-ui/utils` `getComputedStyle` (Mantine popover/combobox positioning), 64
  `getViewportRect`, 25 + 22 `dom-accessibility-api`, 23 Testing Library `isSubtreeInaccessible`.

So the fixture data is not the cost: floating-ui positioning in jsdom is roughly a third of the test
at idle. Changing it (stubbing positioning in the test environment, or lighter popovers) touches
the shared test setup and is left to CARD-1280, the floating-ui `getComputedStyle` follow-up for
modal render cost under load; no change was made from this step.
