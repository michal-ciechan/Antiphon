## Root cause (measured)

`React.lazy` suspends on its first render even when the module is cached, so clicking "Edit card"
commits the Suspense fallback and the dialog renders later as a time-sliced retry. That render costs
0.7–2.1 s of CPU alone in jsdom (author's `probe.log`: standalone `CardEditModal` renders 2 089,
685 and 1 224 ms). `findByRole` polls with React's act environment off and the default 1 000 ms
window (`client/src/test/setup.ts` sets no `asyncUtilTimeout`), so its timer fires between render
slices. Pre-importing the module (the S5 author fix) cannot help: React 19.2.4 `lazyInitializer`
(`react/cjs/react.development.js:460-496`) attaches `.then` and marks the payload pending on the
first render, so the lazy payload still suspends once.
