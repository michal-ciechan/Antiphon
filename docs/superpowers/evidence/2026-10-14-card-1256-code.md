## Root cause (measured)

`React.lazy` suspends on its first render even when the module is cached, so clicking "Edit card"
commits the Suspense fallback and the dialog renders later as a time-sliced retry. That render costs
1–2.5 s of CPU alone in jsdom (cold standalone `CardEditModal` render 2 089 ms). `findByRole` polls
with React's act environment off and a 1 000 ms window, so its timer fires between render slices.
Pre-importing the module (the S5 author fix) cannot help: the lazy payload still suspends once.
