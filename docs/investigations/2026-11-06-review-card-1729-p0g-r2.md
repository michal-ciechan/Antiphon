## Blocker

### B-3: a value declared anywhere in a file still hides that file's unqualified expression-position type references

- **Where:** `tests/Antiphon.Tests/Layering/LayeringGuardEngine.cs:228-229`. `declaredNames` (`:194`) is
  still a set built for the whole file. For a bare name outside a type-only context, a hit in that
  set drops the candidate, whatever scope the declaration is in: another method's parameter, a
  property of another class, an enum member, or a positional parameter of another record.
- **Failure on the real tree:** `server/Application/Exceptions/ModelDisabledException.cs` (Core,
  `layers.txt:13`) has `using Antiphon.Server.Application.Services;` and, at `:47` inside
  `ModelDisabledException.FormatRefusal`, the expression `ModelAlias.KindWide`. That is the
  Application static class `server/Application/Services/ModelAlias.cs:10`. The only `ModelAlias`
  declaration in the file is the positional parameter `string ModelAlias` of the separate record
  `ModelAvailabilityProblemDto` (`:85`), which is not in scope at `:47`. So this is a real
  Core-to-Application reference. It is **not in the allowlist and not reported**.
- **Synthetic proof** (strict, `core/V.cs` with `using X.App;`). Each of these produces zero findings
  at the tip:
  - `class V { void M(int Svc) {} int N() => Svc.Run(); }`
  - `class A { int Svc { get; } } class V { int N() => Svc.Run(); }`
  - `enum E { Svc } class V { int N() => Svc.K; }`
  - `class A { int Svc; } class V { string N = nameof(Svc); }`
  - `… => o is not Svc`, `o is Svc or string` and `o switch { Svc => 1, _ => 0 }` with the shadow in
    another class
  - the ModelDisabledException shape:
    `class V { static string M(Holder h) => h.Kind == Svc.K ? "a" : "b"; } record Dto(string Svc);`
- **Why it blocks:** this is the same fail-open class as round-1 B-2 (the guard silently approves a
  wrong-way reference), and it happens on the current tree. Like round 1's `LandWorkspace` case, it
  means the seeded inventory is not the real inventory: a Core-origin row is missing.
- **Smallest fix:**
  1. Make the value-name exclusion scope-aware. Drop a bare expression-position name only when it is
     declared in a scope that encloses the use:
     - a field, property, method, event or positional/primary-constructor parameter of an enclosing
       type;
     - a member of an enclosing enum;
     - a parameter, type parameter, local, designation, foreach or catch variable of an enclosing
       member, accessor, local function or lambda;
     - a top-level-statement local.
  2. Keep the `own` type-name check and the type-only-context rule as they are.
  3. Add L5 in-body variants `static-call-shadow-elsewhere-fires`, `nameof-shadow-elsewhere-fires` and
     `positional-parameter-of-other-record-fires`.
  4. Add L6 variants `findings=0:same-scope-value-member` and `findings=0:same-scope-parameter` so the
     scoped check still drops real values.
  5. Reseed by adding exactly
     `server/Application/Exceptions/ModelDisabledException.cs -> ModelAlias @ server/Application/Services/ModelAlias.cs`
     under the slice that owns the other Core `Exceptions -> Services` policy rows (`# slice P0-A1`
     per the seed, or the plan owner's choice).
- **Review trial of that fix (scratch only, mutant `SCOPED` in `.antiphon/review-d5fd03f4/engine-mutants.diff`):**
  - All 9 frozen methods stay green.
  - All 6 same-scope value probes still give 0 findings: field, local, parameter, lambda parameter,
    pattern designation and primary-constructor parameter. The Color Color static call still fires.
  - Every out-of-scope probe above fires.
  - On the real tree the inventory changes by exactly one row: `VIOLATIONS 1 LISTED 223 STALE 0 AMBIGUOUS 3`,
