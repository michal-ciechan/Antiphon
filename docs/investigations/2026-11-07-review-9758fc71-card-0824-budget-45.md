## Verdict: ACCEPT 45

The extra statement is the CARD-0824 RefOnly owner read in
`WorkspaceReservationJournal.OverlapAsync` (commit `43d819da7189349c548b07ebd2677e6be086d95b`,
on master since 2026-11-06, the only journal change since 2026-10-04). It is a deliberate,
bounded, batched fence read; the pin records the current product truthfully. No defect.

### 1. Intended and necessary

`OverlapAsync` must know whether the requesting owner (`command.TaskId`) or any candidate
reservation row's owner is recorded `DesktopWorkspaceKind.RefOnly`. That fact lives only on
`AgentTasks`; neither the reservation row nor `WorkspaceReservationCommand` carries it. The
read is what makes a RefOnly identity's exact full ref unwritable by a second identity
(`C0824RefOnlyConsumerTests` same-ref-fenced / same-ref-owner-visible-across-identities,
added by the same commit). Reading the DB-recorded flag inside the admission transaction
(`pg_advisory_xact_lock(1017, 459)`) is the right custody; a caller-supplied flag would
trust a possibly stale in-memory entity.

Folding: the rows' owners could be folded into the existing `WorkspaceUseReservations`
SELECT as a correlated subquery, but the requester's own flag would still need a read or a
command DTO change at five call sites. Not worth it for one indexed PK lookup.

Skipping: the read is provably dead when the normalized key has no ref
(`normalized.SourceFullRef.Length == 0`, the RefOnly disjunct requires a nonempty ref) or when
`ids` is empty. The refused-dispatch fixture is exactly that case: a Shared-workspace task with
no `WorktreeBranch`, so `WorkspaceReservationKey.ForTask(null, workingDirectory, null, null)`
normalizes to `SourceFullRef == ""`. `ids` is not empty there (`[taskId]`), so only the ref
guard would skip it. See A-1.

### 2. Scaling

Constant +1 per `OverlapAsync` call. All candidate owner ids are batched into one
`"Id" = ANY (@__ids_0)` predicate; there is no per-row query. The dispatch path calls
`RequireConsumerAsync -> TryAdmitConsumerAsync -> OverlapAsync` once per claimed task, so the
cost is +1 per task admission, not N+1. `ReadActiveAsync` (both overloads) and
`TryClaimRetirementAsync` gain exactly +1 each. The SQL the Debug quoted
(`... AND a."DesktopWorkspaceKind" = 1`) is the EF translation of that query (`RefOnly = 1`).

### 4. Advisory (D-2, non-blocking, no rerun)

A-1. `OverlapAsync` could return `rows.Where(r => Same(r, normalized)).ToList()` before the
`AgentTasks` read when `normalized.SourceFullRef.Length == 0 || ids.Length == 0`. That removes
a dead round-trip from inside the serialized admission section for every ref-less Shared
dispatch and every empty-set `ReadActiveAsync`, and would return this fixture to 44. Follow-up
card material, not a landing condition; if adopted, the pin moves back with that change.
