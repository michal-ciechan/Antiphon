# CARD-0805: `c723-*` checkpoint test roots fill server2

## Finding

Confirmed from source and CARD-0804's recorded filesystem inspection. The measured `/tmp/c723-<32-hex>` paths are created by the **checkpoint tests**, not by the checkpoint tool's production `ShadowCopy` path. `CheckpointFixtures.TempDir()` creates a new temp directory with that exact name and returns a plain string; it has no owner, disposal, or cleanup (`tests/Antiphon.Tests/Checkpoints/CheckpointTestSupport.cs:154-159`). There are 73 calls across 18 checkpoint test files. No checkpoint test deletes one of these roots. CARD-0804 records 20,541 such roots, 189 GB, and a sampled root with three 385 MB tool copies. CARD-0805 records the later 20,600+ roots / ~233 GB incident and one manual age-based deletion. Those measurements are incident evidence, not a fresh disk census in this investigation.

The amplification path is concrete: tests pass a `c723-*` root as `repo` to `CheckpointApp.StartAsync` (for example `CheckpointTaskOwnershipTests.cs:433-444`). `CreateRun` places results beneath that repo (`CheckpointApp.cs:297-314`); `StartAsync` copies all tool output from `AppContext.BaseDirectory` to `<root>/.antiphon/checkpoints/<run>/tool` (`CheckpointApp.cs:321-340`). `ShadowCopy.CopyFiles` recursively copies output directories except `src` and `obj`, excluding only `.cs` and `.csproj` files (`Execution/ShadowCopy.cs:3-38`). In a test host, `AppContext.BaseDirectory` is its large build output. Several test runs can therefore multiply one `c723-*` root.

The tool's existing cleanup cannot reclaim those roots. `WaitCommand` removes a completed run's `<run>/tool` after the executor pid is gone, regardless of green/red (`Commands/WaitCommand.cs:39-52`), and `CreateRun` sweeps finished `tool/` directories only inside **that run's results root** (`CheckpointApp.cs:299-304`; `Evidence/EvidenceFolder.cs:61-82`). Tests often call `StartAsync`/`ExecuteAsync` directly without `WaitCommand`; each new `TempDir()` also gets a distinct results root that later tests never revisit. `ExecuteAsync` intentionally cannot delete its own in-use image (`EvidenceFolder.cs:84-119`); `KeepOutputs` also bypasses its green cleanup (`CheckpointApp.cs:237-248`). A red production run that reaches `wait` does remove the copy, so red retention is not the reason for the measured `c723-*` accumulation. `OutputCleanup.RemoveOlderRuns` only targets the selected results root and is an explicit `clean` command (`Cleanup/OutputCleanup.cs:24-46`; `Program.cs:242-250`).

There are separate production recovery gaps worth fixing, but they do not explain the `c723-*` name: `StartAsync` leaves a partial run/tool copy if copying or launching fails before state is written (`CheckpointApp.cs:335-347`); `WaitCommand` reports an executor that dies before `phase=done` without removing its copy (`WaitCommand.cs:55-61`); `SweepFinishedToolCopies` skips `starting`/`running` state even when the executor has died (`EvidenceFolder.cs:61-82`). A completed run whose caller never waits is swept on a later start in the same results root.

## Scope reconciliation

CARD-0804 already owns the direct cause: lifecycle of test temp roots, reducing repeated whole-output copies, and marker-gated orphan cleanup. Implement that work once. Treat CARD-0805 as the disk incident and acceptance gate for that shared fix, plus the distinct production `tool/` recovery gaps above. A generic checkpoint-tool sweep of `/tmp/c723-*` would target a test-only namespace and could delete another active worktree's fixture. CARD-0773 shared `obj` collisions and CARD-0774 escaped row grandchildren do not create these named roots in the inspected code; a live process can still be a cleanup veto.

## Fix plan for the Plan stage

1. Give each checkpoint test an owned temp-root lifetime. Register every `TempDir()` root with the current test and remove it in a guaranteed per-test teardown, including assertion failure and cancellation. A test using a real child must await/stop that child before teardown; do not rely on class/assembly completion. Cover the 73 call sites, including multiple roots in one test. Use disposable fixture scopes where a TUnit teardown hook cannot express the lifetime. Keep test evidence needed for a failed assertion in the normal test output, outside the temporary root.
2. Remove amplification: tests that only validate imports, state, or round trips should use a tiny purpose-built tool directory or `CreateRun`, not `StartAsync` copying the entire test host output. Keep a limited integration case that checks the real shadow-copy behavior. The production copy still belongs under `<resultsRoot>/<run>/tool` for detached execution.
3. Complete tool-run cleanup. Keep `WaitCommand`'s after-pid-exit deletion on both green and red, independent of `KeepOutputs`; make the no-`phase=done` crash path and `stop`/next-start recovery delete only a proven dead executor's `tool/`. If `StartAsync` fails before launch, remove its partial run; if launch may have succeeded, do not remove a possibly executing image. Preserve reports, TRX, and logs. Account for PID reuse and process-start identity before classifying a `starting`/`running` run as dead. Check a timeout or failed deletion is reported and retried, not silently treated as success.
4. Add a bounded orphan safety net for **test-owned** `c723-*` roots: write an ownership marker at creation containing a version, run/test identity, host identity, pid and process start time. Sweep at test assembly startup and rate-limit subsequent sweeps during long runs. Only consider direct children of the OS temp root with the exact name shape and valid marker. After a short grace period, remove an old root only when the owner identity is gone and no nested checkpoint executor is live; use oldest verified orphan first above an explicit count/byte budget, and log failures. Never sweep unmarked legacy roots automatically. Provide a dry-run operator path for reviewing legacy cleanup; age or name alone is not deletion authority.
5. Verify with small deterministic tests: green/red/cancelled test teardown leaves zero owned roots; a `StartAsync` copy failure, launch failure, executor crash before `done`, and a normal wait leave no eligible tool copy; a live executor, reused pid, foreign/unmarked root, and concurrent worktree remain intact. Measure peak and residual `/tmp/c723-*` count/bytes across two repeated checkpoint-class/full-suite runs. Acceptance for CARD-0805 is no retained GB-scale growth and a bounded, audited orphan backlog after simulated process death.

## Not done, noted

No source fix, test, build, or live `/tmp` deletion was performed in this investigation. The plan needs one explicit owner for the shared CARD-0804/CARD-0805 fixture work; production run recovery can be a separate slice of the same plan.
