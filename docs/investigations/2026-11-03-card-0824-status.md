## 2. Is the slot pool enabled anywhere? No.

The pool needs both halves on (`server/Application/Services/RemoteWorkspaceService.cs:217-221`):

- **Server flag:** `_workspaceSlots = configured.WorkspaceSlotsEnabled` (`:67`), defined at
  `server/Application/Settings/DelegationSettings.cs:703`. It is a C# `bool` with default false, and
  there is no `WorkspaceSlots` key in `server/appsettings*.json`.
- **Runner flag:** the runner must advertise `workspaceSlotV1`.
  - Settings: `PhoneHomeWorkspaceSlotSettings.Enabled` (`src/Antiphon.SessionRunner/PhoneHomeWorkspaceSlotSettings.cs:9`),
    default false.
  - The pool object is created only when the flag is true
    (`src/Antiphon.SessionRunner/PhoneHomeCommandDispatcher.cs:165-167`).
  - The feature is advertised only with the flag on (`:142-144`).
  - There is no `WorkspaceSlots` key in `src/Antiphon.SessionRunner/appsettings.json`, and no
    `PhoneHome__WorkspaceSlots__*` in any `docker-compose*.yml`. `docker-compose.server2-runner.yml:52-89`
    sets only `Enabled`, `RunnerId`, `Capacity "10"`, the homes and the paths.

**Live state, 2026-11-03 20:32Z.**

- `GET /api/session-runners`: no runner advertises `workspaceSlotV1`. These runners were checked:
  - desktop (capacity 2);
  - server2 (capacity 10, 7 occupied);
  - server2-temp (retired).
- The running server `919d8d42f14d1b11ae5dcba8dafd1e1b2a8d90cd` (from `GET /api/version`; it is on the
  rc/2026-11-03 and rc/2026-11-04 lineage) contains S1 up to `7ab9aa36c`.

**Dispatch today.** Every Worktree task gets a fresh desktop worktree
(`AgentTaskDispatcher.cs:6000`, `DelegationWorktreeService.CreateForTaskAsync`). A runner task also
gets a fresh `task-<8hex>` mirror, sent in the legacy request shape (`RemoteWorkspaceService.cs:216`).
Even with both flags on, S1 would bound only the server2 mirror. The desktop half needs S5.

## 3. Interaction with CARD-1677 retention (and the CARD-1677 temp sweep)

**CARD-1677 is landed and shipped on by default** for server2 (operator decision 2026-11-03):

- Commits `1b6aaf36b` and `292195764` (the on-by-default flip).
- `server/appsettings.json:230-250` sets `RunnerWorktreeRetention:Enabled=true`, `Execute=true`,
  `Runners=["server2"]`, `MinTerminalHours=12`, `MaxRemovalsPerTick=25`, cron `*/30`.

**It is not active on the running build yet.**

- Running server `919d8d42f` does not contain `1b6aaf36b`, `292195764` or `bb0947982`
  (`git merge-base --is-ancestor`, all three no).
- server2's live feature list lacks `workspaceRetentionV1`. A Linux runner with the CARD-1677 code
  advertises it unconditionally (`src/Antiphon.SessionRunner/PhoneHomeRuntimeAdapter.cs:36-38`), so
  the live runner build predates it too.
- All three commits are on master and on `rc/2026-11-04`. Activation is the rc/2026-11-04 rollout,
  which the operator owns.

**Does retention ever select a slot worktree? No. There are three guards, and each has a witness.**

1. **Server selection.** The path leaf must match `^task-[0-9a-f]{8}$` and equal the task id
   (`server/Application/Services/RunnerWorktreeRetentionService.cs:39,259`). A task with
   `RemoteWorkspaceSlotId` set is skipped as `slot_managed` (`:263`). The inventory marks a slot leaf
   and does not report it as unmatched (`:375`).
   - Witness: `C1677RetentionServerTests` case `slot-bound` (`tests/Antiphon.Tests/Application/C1677RetentionServerTests.cs:139,180,231`).
2. **Runner confinement.** `RunnerWorkspaceSlotPool.IsSlotLeaf(leaf)` returns `Kept(SlotManaged)`
   before the leaf pattern is checked (`src/Antiphon.SessionRunner/RunnerWorkspaceRetention.cs:220-223`).
3. **Runner ledger check.** A path listed in `/work/workspace-slots/ledger.json` is kept as
   `slot_managed`. An *unreadable* ledger also keeps the tree (fails closed) (`RunnerWorkspaceRetention.cs:243-245,449-451`).
   - Witness for guards 2 and 3: `C1677RetentionEngineTests.Slot_paths_are_refused`, with cases
     `ws-leaf` and `ledger-path` (`tests/Antiphon.SessionRunner.Tests/C1677RetentionEngineTests.cs:100-122`).

The reverse direction also holds. The slot pool's `RemoveAsync` refuses `ws-*` paths and ledger paths
(`RunnerWorkspaceService.cs:546-547`).

**CARD-1677 temp sweep.** Only settings exist, and they default off:
`RunnerWorktreeRetention:TempSweep:Enabled=false`, `Execute=false` (`server/appsettings.json:243-249`,
`server/Application/Settings/RunnerWorktreeRetentionSettings.cs:69-77`). A grep for `TempSweep` finds
only the settings class, with no sweeper consumer. It targets `/tmp` families, not `/work/worktrees`,
so it has no slot interaction.

**Does retention make slots less urgent?** For **disk on server2**, yes, once it is activated: it
removes finished, clean, published mirrors 12 h after they become terminal, at up to 25 per 30-minute
tick. CARD-1677 also adds the `WorkspaceDiskLow` attention at 85 % (`bb0947982`), which covers the
disk-alarm part of S4's watchdog.

Retention does **not** deliver what slots are for:

- **Desktop registrations.** Retention is server2-only; the desktop half needs S5.
- **The cold-checkout and cold-build cost** per task.
- **Bounded-by-construction counts.** Dirty, unpushed or held mirrors are kept indefinitely.

**Risks.**

- **S1 review gate.** The round-3 review scope was Interim (`ordinaryScopeCompleted: Interim`) and no
  Mutation ran.
- **Warm output.** Stale outputs in a warm native `bin/` (plan risk 6) are mitigated only by the
  weekly, explicit and pre-rc cold reset.
- **Blocked tasks.** A Blocked task holds its slot with no deadline while parking is off (plan §9).
- **Windows (S3/S5), long paths.** The 2026-11-01 `Filename too long` left `card-task-a7b2b64a-rc` on
  disk unregistered. The design answer is `core.longpaths=true`, the `\\?\` prefix, and re-homing.
- **Windows (S3/S5), file locks.** testhost, node, PtyHost and MCP children can hold `bin/`/`obj/`
  locks (CARD-0308). A cold reset is where native `bin/` locks bite hardest. The design answer is a
  Restart Manager probe, deferral, then quarantine and re-home.
- **Windows (S3/S5), side effects.** Quarantined directories consume disk until an operator clears them,
  and Defender inflates the first checkout.
- **Branch deletion (S2).** Deleting branches before legacy mirrors drain turns them into CARD-1008
  recycle refusals.
