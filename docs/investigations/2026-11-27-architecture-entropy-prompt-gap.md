## Verbatim `/goal` prompt

Paste the block after `/goal`. It uses 2,924 UTF-16 units with LF line endings.

```text
Reduce architectural entropy in Antiphon through small, verifiable worktree batches. Start from current requirements, callers, data compatibility and production constraints. Read AGENTS.md and the owner docs for the selected area. Reuse the normal Investigate, Plan, TestDesign, Code, Review and landing flow.

Aim for one authoritative source per rule, state, contract and setting, and one implementation for equivalent semantics. Favor deep modules with small stable interfaces, cohesive owners, explicit dependency direction and local changes. Preserve real compatibility paths. Delete replaced paths after migrating their callers. Enforce critical invariants with targeted types, reference rules, lint or contract tests.

For one area from antiphon.areas.json, record the base SHA, module boundaries, dependency directions, state owners and writers, duplicate candidates, deviations and actual callers. Reuse repository maps and ADRs. Record exclusions and uncertainties. Let Investigate gather evidence and Plan compare keeping, deleting or consolidating where viable. Choose the lowest overall complexity that meets current needs and list caller migrations, deletions, guards and acceptance.

Apply the Deletion Test: if this layer goes away, does complexity disappear or spread to callers? Keep seams that hide real complexity or preserve a named contract. Reuse existing abstractions. Require current callers for a new abstraction and an ownership benefit for moves. Preserve different semantics and readable code.

Establish a narrow behavior baseline and use the existing checkpoint and positive-control rules. Migrate all callers of the replaced path and delete it in the same slice once safe. Give any required bridge an owner, removal condition and follow-up. Review the changed scope for parallel paths, shallow wrappers, leaked internals, cross-layer dependencies, duplicated rules and missed deletions. Accept only with clear owners and public interfaces, explained compatibility and dependency exceptions, local changes, guarded critical rules and preserved behavior, data and contracts. Follow the current verification profile, minimal testing and Review round limits.

Orchestrators delegate implementation and use live limits. Put GitHub issues, rc failures and operator requests first. Admit one governance Code task at a time, defer it during native rc on its host and use a branch owned only by that task. Commit and push each coherent slice through the normal contract. Keep docs/architecture/progress.md, durable decisions in docs/adr/, and independent follow-ups as board cards labeled architecture. Put product choices, major boundary changes or breaking migrations in pending confirmation through the existing card decision path. Continue independent authorized work without per-round approval. Stop when high-value work converges, the budget expires, or further work needs evidence or authority.
```
