## Root cause and repair

Production calls `ILandingGit.RunAsync(repository, ["worktree", "remove", "--", source], ct)` on both platforms in `GuardedWorktreeRemoval.RemoveDirectoryAsync`.
The fixture's `AfterCommand` hook is reached after successful Git removal. `WorktreeGuardedCleanup.RemoveAsync` catches ordinary exceptions and returns `cleanup_evidence_storage_unavailable`; `AgentTaskLandingProtocol.CleanupAsync` has another ordinary-exception boundary. Both propagate `OperationCanceledException`.

The test now separately asserts the hook fired and the exact injected exception escaped. It verifies the actual directory/registration disappeared while the local branch remains at the source SHA, the operation is still `CleanupStarted`, and the durable cleanup attempt has a command intent but no acknowledgement. A new service graph must recover the same operation, preserve publication, finish cleanup, and avoid another removal, push or rebase.

The fix belongs to the test's interruption model. V16 uses a dedicated `SimulatedServerInterruption : OperationCanceledException`, caught directly to retain the exact instance. Other tests retain their original `SimulatedServerCrash : Exception`. Production cleanup remains unchanged. Paths and real Git operations remain portable.

Final code commit: `882394871e1f9de4910bedec44d75c7a22d4ca90`.
