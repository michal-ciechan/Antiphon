## Defect

Where: `scripts/lib/rc-ledger.ps1` `Read-RcLedger` (lines 660-667) and `Test-RcLedgerDocument` (lines 383-454). `ConvertFrom-Json` keeps the last duplicate property. The validator reads known names only.

Failure: A file that contains both `"outcome":"failed"` and `"outcome":"passed"` on the same identity is accepted. `Read-RcLedger` returns `outcome=passed`, and `Get-RcIdentityCarryDecision` returns `decision=carry reason=carry carried=True`. An unknown property (`doNotCarry: true`) is ignored and that document also carries. A newer format string `antiphon-rc-ledger-v2` throws `ledger-invalid: format`. Truncated JSON throws from `ConvertFrom-Json`.

Why: A recorded failure can be overwritten by a second key in the same object and then carried. The review brief required extra fields and a newer schema to fail closed and never be ignored. The newer format and a truncated file already fail closed. Duplicate property names and unknown properties do not. `Write-RcLedger` itself emits one key per field, so this is the reader, not the writer.

Fix: Reject duplicate property names and unknown properties before any carry decision, so `Read-RcLedger` throws `ledger-invalid` and no carry is produced. One witness: the failed-then-passed file must not read as carry. Do not change the D-4 result for a well-formed row.
