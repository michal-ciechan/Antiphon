## Outcome

**23 mutants were run. 14 were killed and 9 survived.**

- 3 survivors are equivalent: C1 by construction, C3 and F8 on Linux.
- The other 6 survivors are coverage gaps. Four of them are in the SAFETY direction, listed first below.
- Every survivor is unreachable from the three witnesses for one of these reasons:
  - the fixture has no file with `.git` inside a longer name;
  - every case passes `-ResultsDirectory`;
  - every case makes exactly one fixture root, which is still there when the `finally` runs;
  - no case fails before `New-Fx`.

## Method

- **Mutant application.**
  - Each mutant was a throwaway one-literal-match edit applied by a node script, which refused any match count other than 1. The edit was made in this task worktree's script file. The test host resolves `scripts/` from `DelegateScriptRunner.RepoRoot` (it walks up from the test dll), so the worktree file is the one under test.
  - After each run the file was restored with `git checkout -- <exact path>`, and `git status --porcelain --untracked-files=no` was checked to be empty (RESTORED 0) before the next mutant.
  - No environment gates were used, and production bytes were not changed.
- **Batching.** One mutant per file per run. When a round held both an FF mutant and a CA mutant, those mutants were in different files with distinct witnesses. The H mutants each ran alone.
- **Combined runs.**
  - r14 (C8+C4+C3+C1) was invalid as a survivor check: C1's early delete plus C4's unguarded delete interact. Its result is used only as evidence that C4 masks the original failure.
  - It was replaced by r15 (C8+C3+C1 on CAp+CAf, green 2/2) and r16 (C4 alone on all three witnesses, green 3/3).
  - C12 ran on CAf only. That it is equivalent on CAp follows from the single `New-Fx` call in `Test-C1313_BaselineAuthority`.
- **Build.**
  - One `dotnet build tests/Antiphon.Tests -p:UseAppHost=false` at L, with native default output, under its own build-slot lease. It took 166 s.
  - No rebuilds: every mutant is a PowerShell script that the test reads at run time.
- **Runs.**
  - Every run was `dotnet run --no-build --project tests/Antiphon.Tests -p:UseAppHost=false -- --treenode-filter <F> --report-trx --timeout 25m`, one build-slot lease per run, with `TEMP=/tmp`.
  - The filters:
    - all three: `/*/*/(RcFailedFirstExecutionTests*)|(ChangeAwareReleaseTests*)/(C1590_*)`
    - FF and CAf (fast rounds): `…/(C1590_ArchiveHoldsNoGitRepository*)|(C1590_FailedRunRemovesFixtureRoots*)`
    - CA only: `/*/*/(ChangeAwareReleaseTests*)/(C1590_*)`
  - `ProcessSpawnLimit` serialises the tests.
  - Slot waits were 0-105 s, and the load average was 8-21.
- **Baseline at L (r00):** 3/3 green. FF took 138 s, CAf 9 s and CAp 271 s.
- **Restored green at L:**
  - FF 1/1 in r16 (the FF file was at L)
  - CAp and CAf 2/2 in r99 at 17:55 UTC
  - the final `git status` shows tracked source clean at L
- **Outputs.**
  - Each FF run writes `.antiphon/failfirst/<L>/portable/ConservationDiagnostics-<guid>/` into the worktree. The archives from mutants F2, F3, F7 and F9 contain copied `.git` admin files, which are nested repositories.
  - Each CA run writes `.antiphon/test-output/c1313-s6a/<guid>/`.
  - This session created both directories. Both were deleted at the end by their literal paths, along with the build's `bin/` and `obj/` outputs.
  - No `/tmp/c1313-nightly-*` or `/tmp/ff-nightly-*` directories were left: ScriptHarness removed them.
