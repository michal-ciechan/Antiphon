## Finding: bind background work to its accepted generation (P1)

Locations: `server/Application/Services/AgentControlService.cs:412` and `:612`; `server/Application/Services/AgentSessionLaunchQueue.cs:45`; `server/Application/Services/AgentSessionService.cs:340` and `:525`.

The Fresh reservation takes queue locks for the source/current session, but its new `chosenSessionId` is absent from `involved`. It commits before registering launch ownership. The background work carries a session ID, spec and resume flag, but does not carry the accepted `StartedAt` generation. `LaunchInteractiveAsync` reads whatever generation exists when it begins and uses that as its expected generation. Consequently its subsequent authority checks can validate an obsolete Fresh spec against a later accepted resume generation.

Deterministic reproduction against unchanged production code:

1. Start Fresh from stopped B, creating C. Gate immediately after the reservation transaction commits and before enqueue. C has no launch-queue owner; only B's queue lock is held.
2. Stop the standing agent through `AgentControlService.StopAsync`.
3. Select C through `StartAsync(resumeSessionId: C)`. This takes C's queue lock, accepts a later generation, starts with `--resume`, and completes its worker.
4. Release the original Fresh call. It registers C again and starts a second adapter with the obsolete create-mode spec. Its authority check reads the later generation and accepts it.

The test fails specifically at `obsolete.Started.ShouldBeFalse`: actual value is `True`. This proves an unauthorized obsolete create launch reaches the adapter after Stop and a subsequent resume. The test uses the existing fake adapters and isolated database; it does not claim to demonstrate native history loss or a live provider accepting a resume of newly created C. Provider-side missing/duplicate-session refusals are not a substitute for the server's generation/Stop contract.

Reserve ownership of the chosen target across the commit-to-enqueue boundary (including Fresh/new-row targets), and carry/validate the immutable accepted generation into the worker before adapter creation or side effects. A rejected obsolete worker must not write failure evidence into a newer generation. Preserve rollback cleanup and the rule against holding database transactions across runner I/O. Extend V-21/V-22 to gate after commit but before queue registration; existing tests gate after registration and miss this interval.
