## Normaliser

The existing `WorkingDirectoryIdentity` (CARD-0558, project readiness and setup's reverse
lookup) is the single rule: a path is Windows when spelled with a drive letter or UNC prefix
(case-insensitive, `/` equals `\`), otherwise POSIX (ordinal, `\` is a file-name character);
trailing separators drop above the root. `PathsMatch` now delegates to
`WorkingDirectoryIdentity.Same`; `IsWorktreeCwd` splits a Windows-spelled path on `\` and `/`
and a POSIX path on `/` only. The answer depends only on the spelling, so the Windows server
and Linux runners agree.

Behaviour change worth knowing: POSIX paths in `PathsMatch` are now case-sensitive on every
host (the Linux filesystem is), and `C:\` no longer equals `C:`. On Windows,
`GetRepoToplevelAsync` returns `Path.GetFullPath` of git's output, so a UNC toplevel that git
prints as `//host/share` is still compared as `\\host\share`.

Not in scope, left as follow-up candidates: `AgentTaskDispatcher` (lines ~4513, ~9763,
~9904, ~10254, ~10292) and `SharedWriterLeaseProjection` (~165) also compare through
`NormalizeSeparators`. They were not named by the advisory and were not changed here.
