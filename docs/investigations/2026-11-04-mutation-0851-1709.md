# Mutation sweep: CARD-0851 build-slot broker and CARD-1709 completion recovery (2026-11-04)

Mutation task e24018e3. Subject base `240231e86c90707cd6e0d0c88affcd5bddfb4247` (master, batch 68).
Sources: Code 1ee29680 (CARD-0851, PC-a..PC-f), Review 9602645b (CARD-0851), Review 459edfef (CARD-1709).
Linux server2, one build-slot lease per build and per run, `UseAppHost=false`, native default output.

**Outcome.** 16 CARD-0851 mutants: 15 killed by their assertions, 1 survives. The survivor is
equivalent, and the landed code cannot have it. 19 CARD-1709 mutants: 14 killed by assertion, 1
killed only by a hang, 4 survive. Of the four survivors, two have missing witnesses with a
correctness effect (B6a, B6b) and two are constructed timer alternatives (B10, B11). B5
(unconditional retry) is confirmed killed only incidentally, by C1360. Every edited file was
restored with `git checkout --` and rebuilt, and the restored tree ran green.

## Method

- Each subject was mutated in one tree. Every mutant sits behind an environment gate (`E24_MUT=<id>`;
  for the scanner run, a comma list) in the product file, so one mutant build serves every
  mutant. Subject A ran in the task worktree. Subject B ran in a detached shard worktree at the same SHA.
- Per subject: a green baseline on the pristine build, then the mutant build, then a gate-off control
  run on the mutant build (must be green), then one run per mutant. After that, `git checkout --` of
  each edited file, a rebuild, and a restored-green run.
- Subject A witness set: `/*/*/(BuildSlot*)|(HostStatsProbeParseTests*)/*` (44 tests,
  Antiphon.SessionRunner.Tests). Subject B witness set:
  `/*/*/(TaskSupervisionReceiptTests*)|(CompletionNoteDurableSweepTests*)|(CompletionNoteWorkQueueTests*)/*`
  (43 tests, Antiphon.Tests). That set holds the four C1709 witnesses, C1360 and the work-queue unit tests.
- A mutant is **killed** only when a named test fails on a test assertion in a run with nonzero
  counts. A hang is reported separately.

`Lease.KeptPastTtl`, a property of the private `Lease` record. `_leases.Remove(lease)` drops the

## Survivors and gaps

- **B5 (Review A-2 confirmed): a missing C1709 witness.** C1360's startup-timer assertion is the
  only thing that kills "retry even when nothing was skipped". The missing case: in
  `C1709_Busy_pass_retries_skipped_work_before_the_backstop`, after the retry pass enqueues the
  skipped note (nothing busy any more), the next armed timer must be the 15-minute backstop. Assert
  that `DueTimes` gains 00:15:00 after the retry pass, and that no further 00:00:05 entry appears.
- **B6a: a missing witness with a correctness effect.** The commit says the busy set is "shared by
  both phases". With separate sets, two things go wrong:
  1. A recipient whose supervision notice timed out has its completion note tried again in the same
     pass. That costs another 1 s, and if the lock frees in between, the completion note is
     enqueued ahead of the supervision notice left for the next pass (cross-kind reorder).
  2. A pass whose only busy item is a supervision notice adds nothing to the loop's set, so no 5 s
     retry is armed and the notice waits for the 15-minute backstop.

  Held keeps the lock for the whole pass, so the second attempt also times out, and no witness
  seeds a supervision-only busy pass. Missing cases:
  - (a) Cross-kind order: hold the recipient's lock, let its supervision notice time out, then
    release the lock from the `completion-scan` boundary for the same recipient's owed completion
    note. Expect 0 rows for that recipient after pass 1, and the supervision notice's row before the
    completion note's after pass 2.
  - (b) Supervision-only retry: run the hosted service with a pending supervision notice
    (TaskCeilingHarness `role: Deploy` + `SweepAsync`) and no owed completion note for that
    recipient, with the recipient's lock held. Expect `DueTimes.First()` to be 00:00:05.
- **B6b: a missing witness with a correctness effect.** The retry witness covers only the startup
  sweep pass. A `Recovery.Check(taskId)` pass (the non-sweep branch) that hits a held lock would,
  with a per-task set, arm no 5 s retry and fall back to the 15-minute backstop. Within one Check
  batch, a busy caller's later task would also be retried (another 1 s, and a reorder if the lock
  frees). The missing case: start the worker with nothing owed so the startup sweep passes clean,
  then seed the busy-parent note and call `Recovery.Check(taskId)` with the lock held. Expect a
  00:00:05 timer armed after the 15-minute backstop timer, and the note enqueued after release
  plus `Advance(5 s)`. Optionally seed A1 < B < A2 through one Check batch for the order half.
- **B10: survived, low severity. It is a constructed alternative that the landed code cannot
  exhibit.** The landed code folds every busy outcome into one `nextSweep` deadline with `Min`. A
  stacking refactor would create one timer per busy session per pass. Their `RequestSweep` calls
  coalesce on `_sweep` and the one-slot wake channel, so passes do not multiply, but timers pile up
  while locks stay held. The missing case: hold two sessions' locks in one pass, and assert exactly
  one 00:00:05 entry in `TimerClock.DueTimes`. The current retry witness holds only one session.
- **B11: survived. It is equivalent in observable behaviour, and the landed code cannot exhibit
  it.** A retry timer that ignores shutdown fires `RequestSweep` after `StopAsync`. That writes a
  flag on the singleton `CompletionNoteRecoveryQueue` that nothing reads once the loop has exited,
  so no state, row or delivery changes. The landed code has no separate timer. Its only retry wait
  is the loop's `WaitAsync(nextSweep, clock, ct)`, which is linked to `ct` (see B11b).
- **B11b: killed only by a hang.** The test that hangs is C1360, not a C1709 witness. The missing
  case: bound the stop in the C1709 retry witness (and C1360). For example, use
  `await worker.StopAsync(default).WaitAsync(TimeSpan.FromSeconds(10))`, so a shutdown-ignoring
  wait becomes an assertion red instead of a session hang. The mutated line predates CARD-1709.

No unmutated-L defect was found: every baseline, gate-off control and restored run was green. There
were no infrastructure failures. B11b's missing TRX is the expected effect of a hang plus
`--timeout`, and its attribution run is above.
