## How a card was classified

Exactly one state. A non-terminal task (Queued, Dispatched, Working, Blocked) is IN-FLIGHT even when older commits are already on master.

A master commit counts as this card's code only when the subject names it as a primary subject (conventional `card-N` scope, the first `CARD-N`/`card-N` in the subject, or a merge-batch subject) and the subject is not `docs` or `plan`. Later mentions in the same subject are weak and do not count as this card's land. Body-only mentions are recorded and do not by themselves count as a land. `plan(...)` subjects are plans, not code.

CODE-UNLANDED means an unmerged remote branch tied to this card by name or task id, excluding a branch that belongs only to a Plan, Investigate, TestDesign, or Docs task. LANDED-OPEN-ITEMS means primary code is on master and at least one of these is true: latest Review outcome is Found, `reviewedSourceClean` is false, there is no Review outcome row, or a Mutation task is not Succeeded. LANDED-REOPEN-QUESTION means primary code is on master, the latest Review is Clean, `reviewedSourceClean` is not false, and every Mutation task that exists is Succeeded. A card with no Mutation task stays in that state. Review text was also searched for native checks owed, positive controls owed, and advisories remaining. No detail in this set matched those patterns.

PLANNED-ONLY means a subject plan or investigation doc, a plan-family task, or a docs/plan commit on master, and no primary code commit, no code branch, and no succeeded Code, Debug, Deploy, Review, Test, Merge, or Mutation task. A citation inside another card's doc is not a subject doc. NO-WORK means none of those artifacts. UNSURE is used where the artifacts do not fit one of those states. CARD-0038 is forced to UNSURE from its own description: it is the Linux/Docker epic tracker and the text says to keep it open until the named checklist is Done.
