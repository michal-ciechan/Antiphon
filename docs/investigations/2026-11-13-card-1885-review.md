## What the change does

`ANTIPHON_LINUX_COMPILER_POLICY` must be exactly `1`, and the process must not
be Windows, before `BuildDriverEnvironment.Apply` prepares a compiler.
`GetOverrides` still returns an empty dictionary on Linux. `0`, empty, absent,
`true`, and `01` stay off. Nothing in `Directory.Build` or the default
build-slot path sets the variable.

When it is on, preparation copies SDK `10.0.404` Roslyn under the user cache
and replaces only `bincore/VBCSCompiler` with a launcher. The launcher runs
`taskset` against its own pid, then execs the original SDK `VBCSCompiler.dll`
with `-timeout:120`. Compiler-only environment is `DOTNET_PROCESSOR_COUNT` and
`DOTNET_GCHeapHardLimit=100000000` (hex, 4 GiB managed heap). Affinity or
preparation failure restores the caller's original command and logs
`LINUX COMPILER fallback=stock`. The build is not failed.

Identity is the SDK content, uid, cgroup, mount namespace, isolation, idle,
the capped flag, the chosen CPU list, and the literal `c1885-v1`. It is not
per lease or per worktree. The same grant shares one pipe. A different
`-maxcpucount` selects another CPU subset and a second compiler. Policy-off
clients keep the stock shared compiler. Turning the switch on does not cap or
stop a compiler that is already running.

The trusted exec path is the SDK DLL recorded from `dotnet --info` when the
cache entry is created. A cache hit trusts the manifest already sitting in
that cache. A same-user rewrite of the launcher and its manifest is not
detected. That is an advisory for any later default-on slice. It does not
hold an opt-in land: a repository that can rewrite the build user's cache
already runs as that user, and `Directory.Build.props` cannot override the
global Roslyn properties this path sets.

`taskset` is applied to the launcher pid that is about to exec, or to a
`true` probe. There is no cgroup write and no `pkill` or `killall`. Shutdown
of a private compiler is `dotnet exec` of the SDK DLL with `-shutdown` and
the exact pipe. The pipe name is `ac1885-` plus the identity hash.

on the wrong pid, and a dropped idle exit go red. `Enabled` rejects every
value other than exact `1`. The adapter asserts stock argv, stock exit status,
and `fallback=stock`. The native case asserts the compiler pid's threads stay
inside the granted set, the driver affinity is unchanged, and the fixture
compiler exits inside 15 seconds.

the happy-path cleanup would also not go red, because the idle exit already
clears the pipe before `Stop-C1885PrivateCompiler`. Those two are advisories,
not product defects.
