### Existing ghost sweep backlog

The old sweep could produce 17,280 rows per continuously eligible seat per day at
a five-second interval, or 518,400 in the old 30-day retention window. A five-attempt
budget per tick limits fleet-wide production. The actual backlog depends on outage
duration, eligibility, reconciliation and when pruning last ran.

An operator can get the current count from this read-only server-side query.
`RunnerSlotReleaseIntent` is incident kind 75. The message predicate identifies the
ghost producer among direct releases that share its marker.

```sql
SELECT "FailureReason" AS runner_marker,
       count(*) AS pending_rows,
       count(DISTINCT "SessionId") AS affected_seats,
       min("CreatedAt") AS oldest,
       max("CreatedAt") AS newest
FROM "AgentIncidents"
WHERE "Kind" = 75
  AND "FailureReason" LIKE 'pending:%'
  AND "FailureReason" NOT LIKE 'pending:orphan:%'
  AND "FailureReason" NOT LIKE 'pending:kill-generation:%'
  AND "Message" LIKE 'Failed task % mirror clean and equal to origin, idle since %'
GROUP BY "FailureReason"
ORDER BY pending_rows DESC;
```

For a retired runner such as `server2-temp`, use its exact marker
`pending:server2-temp` to count the ghost backlog for that runner. Existing rows
remain pending until settled. The operator can preview and bulk close verified
retirement obligations through the existing per-intent audited close path.
Save those receipts because old terminal rows can be pruned on the next sweep.
