# CARD-2078 review advisories

The incident-cap witness seeds an older null-agent `HostBudgetChanged` row with a
`pending:` reason. Pruning must delete that row along with other capped history and
retain both pending runner slot release intents.

The migration pins read declared IDs from the existing migration fingerprint,
which preserves duplicates before EF keys its migration list by ID. Each pin
requires strict ordinal increase from the last ID in its pinned window. Both
tests reject a duplicate and a reversed pair in temporary copies of the ID list.
The existing positive witnesses still accept a new migration appended to the chain.

At red witness commit `e0691dbfd324119d8b2b846a68f8cc3c73b486ce`, the build-slot
run in a disposable checkout executed five cases. It failed three at their
intended assertions. Removing the incident-kind check kept the fleet notice.
Both migration pins accepted a duplicate ID, so the expected exceptions were
absent. The two reversed-pair cases passed. The disposable checkout's product
mutation was restored after the run.

## Pending intent retention

Recommend retaining pending runner slot release intents until reconciliation
records a terminal outcome or an operator closes the obligation with evidence.
The age sweep currently removes the only record the reconciler uses to retry an
owed deferred kill. A runner outage past 30 days can therefore erase both the
obligation and the intent-based attention item for kills pending over five minutes.
Apply the 30-day history limit to completed and failed intents and keep the existing
stuck-kill attention visible while the obligation is open. The retention decision
belongs to the owner.
