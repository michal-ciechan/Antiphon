## Exact first-seed proof and remaining races

**INFERRED — Minimum safe exception:** under the existing host maintenance lock, before `c849_prepare yes` can create anything, accept only `-SavedDonor`, absent ready marker, a retired/no-container temp, and a live exact-ID main container whose filtered mounts omit all three cache names and destinations. Check `docker ps -aq --filter volume=<exact-name>` for *all* containers (including stopped) before preparation, after archive copy, before each import, after helper removal, and before marker publication. Continue to reject any attachment, changed main container ID/mount set, foreign/partially populated volume, or missing/unknown Docker result. **INFERRED — An absolute claim that the seed “physically cannot touch any consumer” is too strong.** The host daemon is shared with other host clients; the maintenance lock serializes this deployment script, not arbitrary `docker run`. Repeated attachment/identity checks close the practical race for controlled deployments, and no external cache mount should be published before the ready marker and verified `deploy-temp`. A host operator outside this lane could attach a cache volume between checks. Refuse on observed change; never make this exception available to Reset, Prune, a rerun against populated volumes, or any donor-container path. The main runner's nested Docker uses its own `dind-data` volume and no host Docker socket in the deployment contract [docs/superpowers/plans/2026-09-30-card-0849-shared-runner-caches-plan.md:48-55, 156-164](../superpowers/plans/2026-09-30-card-0849-shared-runner-caches-plan.md); [scripts/c590-remote.sh:3323-3329](../../scripts/c590-remote.sh).

**INFERRED — Resource fence:** require a known broker budget and available memory, plus enough free host Docker filesystem space for the approximately 2.8-GB staged tree and 2.8-GB imported volume data while retaining the documented 20-GiB floor; recheck before publication.
