## Review questions

1. **Live holder before the cap.** The new branch fires only when grant age is at least the cap.
   Below the cap, every lease follows exactly the pre-change chain, so a live, matching pid-mode
   holder is still kept past TTL. V1 holds the lease to 48 h minus one tick (sweep reaps 0). V5 does
   the same with a real process. The unit-swap mutant U1 (TotalMinutes) is red: that is the dangerous
   direction, because it would reap a live 45-minute build after 48 minutes. 48 h is about 64 times
   the measured longest lease (2,702 s) and above the documented 17-30 h qualifications.

   **At the cap** the broker logs one Warning (V1 asserts exactly one, with the lease id and
   `held 172800s`), counts a metrics reap, and frees the slot. The holder is not told; see A-1. The
   freed slot can be granted to the next waiter while the old driver still runs, so the host
   transiently runs MaxConcurrent+1 drivers; see A-2. That is the card's chosen trade-off, the same
   as a manual DELETE, and the broker never kills anything. There is no double grant of the *same*
   lease id: a re-POST from the reaped holder becomes a new waiter with a new grant age.

2. **Clock.** Age uses `TimeProvider.GetUtcNow()`, the wall clock, the same as TTL, renew grace and
   waiter silence before this change. Leases live only in memory. A runner or broker restart drops
   every lease (this predates the change and the card names it as an escape). So age neither
   survives nor resets across a restart, and the cap cannot release everything at once after one.
   Only a wall-clock step of at least 48 h forward could mass-reap kept leases; see A-3.

3. **Configuration.** Absent: the property initializer gives 48. Zero: `Validate()` sets 48 (V7).
   Negative: `PostConfigure` throws and `ValidateOnStart` stops host startup (V4), the same as every
   other `BuildSlots` setting. That fails closed: it never silently picks a default. A non-integer
   fails binding at startup. The name follows `LeaseTtlMinutes`; the section and binding are
   unchanged. The compose files need no entry, because the default applies.

4. **Dead holders unchanged.** The dead/recycled/unreadable-start and renew-silent branches are
   unchanged below the cap. The existing `A_wrapper_killed_mid_hold_is_reaped_and_the_waiter_is_granted`,
   Broker (17), Endpoint (7) and Metrics (5) cases pass. At or past the cap a dead holder is reaped
   with the max-hold reason instead of the liveness reason. Only the log text differs, and it can
   happen only if no sweep ran for 48 h.

5. **Witnesses.** Fake clock throughout; no test sleeps to age a lease. V5's wrapper sleeps for real
   only as a live holder, under the existing 90 s fixture deadlines. See the evidence below.

6. **Runs, check-evidence-diff, merge-tree.** See the evidence below.

## Advisories (non-blocking)

- **A-1 The holder never learns its lease was reaped.**
  Where: `scripts/lib/build-slot.ps1:172-176`, and the renewer at `:116`.
  Failure: after a max-hold reap, a pid-mode wrapper's exit DELETE gets 404 and prints
  `BUILD SLOT release failed ... status=404; the runner reaps it when this process exits`, which is
  wrong after a reap. A renew-mode renewer stops silently on 404.
  Why: the transcript gives no sign that the slot was taken away; only the broker Warning does.
  Fix (optional): print a distinct line on 404 ("lease no longer held: reaped by broker") and say so
  in the Build slots docs.
- **A-2 Overshoot after a cap reap is not stated in the docs.**
  Where: `docs/testing-and-build.md`, Build slots.
  Failure: the doc says the reap "kills no process" but not that the slot is re-granted while the old
  driver may still run, which can push the host to MaxConcurrent+1 drivers and over the memory
  floor's assumptions.
  Fix: one sentence in the docs.
- **A-3 Wall-clock age.**
  Where: `BuildSlotBroker.cs:202`.
  Failure: a forward clock step of at least 48 h reaps every kept lease at once. A backward step
  delays the cap by the size of the step.
  Why: this is the same exposure TTL has always had. The risk is negligible at 48 h.
  Fix (optional): record a `Stopwatch.GetTimestamp`/`TimeProvider.GetTimestamp` at grant and measure
  elapsed time with it.
- **A-4 Test name.**
  Where: `tests/Antiphon.SessionRunner.Tests/BuildSlotMaxHoldTests.cs:79`.
  `V4_Nonpositive_bound_is_rejected...` now covers only `-1`, since zero is accepted (V7). A rename
  to `Negative` would be cosmetic.
- **A-5 Final gate still open.**
  R-3 (the whole Unit lane; plan CP-3 timed out at 25 min with no TRX, and CP-7 never ran) has no
  receipt. The brief commissioned Interim and says the operator accepts Interim for master-only work.
  The standing rule says an Interim Review cannot approve a land. The caller should record which one
  governs this land.
