## Blockers

### D-1: S3b refuses every case-keyed S2 chunk on current master

- **Where:** `scripts/lib/rc-chunk-digest.ps1:41-42` re-derives the chunk ID as `Get-RcBoundaryChunkId $Chunk.suite $Chunk.boundary @($Chunk.identityKeys)`. Line 79 does `$methods.Add($key,...)` once for each identityKey.
- **Failure:** the branch was cherry-picked onto `ab67e69b7` in a scratch tree, and New-RcBoundaryChunk built the chunk from master's S2 membership with case keys:
  - method-level chunk, every caseKey empty: OK.
  - `Example.Queue/Check` with `row:a`, `row:b` plus `Example.Queue/Other` with `singleton`: THROW `boundary-chunk: invalid/duplicate identity`.
  - one case for each method (`row:a`, `singleton`): THROW `chunk-membership-mismatch`.
- **Why:** master commits `3b1771357` and `a4af3cc32` (CARD-1836 S2 hardening) made the chunk membership `(class, method, caseKey)`. `identityKeys` now repeats a method once for each case, and the ID is computed over `caseKeys`. S3b omits `$Chunk.caseKeys`, so it cannot consume S2a membership, which the plan names as its input ("Convert S3a inventories and S2a membership"). Every harness fixture uses a chunk with no case keys, so all 4 cases are green on master as well. The failure is closed (it throws, so there is no false clean), but the slice does not work on the target.
- **Fix:**
  - Pass `@($Chunk.caseKeys)` to Get-RcBoundaryChunkId, or verify `$Chunk.fullDigest` with Get-RcBoundaryCanonicalDigest.
  - Deduplicate method keys before building `$methods`.
  - Require the chunk's `(identityKey, caseKey)` membership to equal the case manifest wherever case keys are present.
  - Add a harness case that uses a case-keyed New-RcBoundaryChunk with at least two cases of one method.

### D-2: second identity, digest and sort implementation beside the S2 canonical library

- **Where:**
  - `rc-chunk-digest.ps1:128-131`: `membershipDigest` hashes `('antiphon-rc-membership','1',suite,boundary)` plus the sorted identityKeys only. It does not use S2's `fullDigest`, which is Get-RcBoundaryCanonicalDigest over Sort-RcBoundaryIdentities and includes caseKey.
  - Lines 88 and 103: cases are keyed and sorted by `ConvertTo-Json` strings instead of Sort-RcBoundaryIdentities.
  - Lines 5-26: Get-RcManifestDigest is a separate length-delimited encoder. It uses strict UTF-8 (`throwOnInvalidBytes`), while S2's Add-RcBoundaryString uses replacing `[Text.Encoding]::UTF8`, so the two encodings differ on a lone surrogate.
- **Failure:** two chunks whose membership differs only in case keys get the same S3b `membershipDigest`, but different S2 `chunkId` and `fullDigest` values. The persisted membership identity therefore diverges from S2's. This is the S4a-class conflict this week's Merge found.
- **Why:** the brief rules that any S3b-owned digest, identity or sort is a blocker. Ledger and admission joins (S5b) would compare two non-equivalent membership identities.
- **Fix:**
  - Take the membership identity from `$Chunk.fullDigest`, recomputed through Get-RcBoundaryCanonicalDigest and Sort-RcBoundaryIdentities.
  - Order cases with Sort-RcBoundaryIdentities.
  - Build the input-record row encoder on the shared Add-RcBoundaryU32 and Add-RcBoundaryString primitives in `rc-boundary.ps1`, or hoist one row encoder into that library, so there is one UTF-8 and length-prefix rule.
