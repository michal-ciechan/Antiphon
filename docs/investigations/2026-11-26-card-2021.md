# CARD-2021 derived impact index publication

The server's landing regenerator builds and runs the same driver as
`scripts/antiphon regenerate-derived-impact-index`. That driver called
`File.WriteAllBytes` on the published index, so a write could expose a
truncated file. The shared writer now stages the bytes in a uniquely named
sibling and closes it before replacing the index with one rename. On a
handled write or rename failure it attempts to remove its staging file and
preserves the original error.

The real-driver test runs the CLI against a scratch Git repository. It
checks the generated bytes, the changed and unchanged reports, and the old
bytes through a hard link that survives replacement. Removing a tracked
input forces a generation failure and the test checks that the published
index survives. The existing fake-child test checks one slot hold and one
build followed by changed and unchanged driver results on the server path.

The original in-place writer served as the red control. At
`b77a1e9ebf543a55bc7912850befdb0e944cc10a`, server2 checkpoint
`20261126-025125-a6d4` ran one test and failed the old-file assertion.
The source was clean and the build source verified. The test body took
2.6 seconds. Slot admission took 675 seconds across the build and row.
The checkpoint report captures the final run's timings and receipt at the
verified source SHA.
