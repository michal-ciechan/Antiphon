## Method

- **Env-gated mutants.** Every production mutant was compiled in behind `C1653MutCli.On(id)` or `C1653MutRt.On(id)`. The gate reads
  `C1653_MUTANT` (comma-separated). The helpers were untracked files, deleted afterwards:
  `src/Antiphon.PtyHost.Client/C1653Mutant.cs` and `src/Antiphon.SessionRunner/C1653Mutant.cs`. With the variable unset, the gated code is L.
- **Builds.** All builds were of `tests/Antiphon.SessionRunner.Tests`, each under its own build-slot lease, with native output, `-p:UseAppHost=false` and `TEMP=/tmp`:
  - the gated build: held 54 s
  - the PC-66 build, with `[NativeLinuxOnly]` removed from the test file: held 22 s
  - the restore build at L: held 19 s
- **No PtyHost.Tests build.** No S2 PC or witness is in PtyHost.Tests, because every S2 witness is in SessionRunner.Tests. So no PtyHost.Tests build was made.
- **Rounds.** Every round was `dotnet run --no-build --project tests/Antiphon.SessionRunner.Tests -p:UseAppHost=false -- --treenode-filter <F> --report-trx --timeout 30m`, under its own lease.
  - Two lanes ran at once.
  - Slot waits were 15-150 s.
- **Filter F:** `/*/*/(Card1653SocketDirTests*)|(Card1653PeerCheckTests*)|(Card1636AdoptionIdentity*)|(Card1653RefusalRetainsHost*)|(Card1653FreshLaunchIdentity*)|(Card1619RunnerExit*)/*`.
  - That is 85 executions: CP-4 28, CP-5 29, CP-6 18, and the whole Card1619RunnerExit class 10, which contains CP-20's 4.
  - No other class shares those prefixes; checked with a grep of class names.
  - Every round's TRX lists all 85.
- **Round grouping.** Each wide mutant got its own round, paired only with mutants whose witnesses it does not touch. Typical wide mutants are any change to the adoption-refusal arm, since every refusal test asserts kill, manifest, pending, event and log. Pairings were checked against each round's red list.
- **Restore.** Files were restored with `git checkout -- <exact path>`, and the helpers were deleted by literal path.

## Masking: PC-80 and the 15 s teardown in the Linux real-host adoption witnesses

Under PC-80, the sweep returns 0 before it reads any manifest. In both witnesses, the first assertion that the
mutant changes is `adopted.ShouldBe(1)`:

- `Legacy_real_host_is_adopted_after_owned_enforce`
- `Unusable_socket_dir_setting_never_kills_a_live_host_at_adoption(nul)`

**Why the assertion never shows.** That assertion throws, and then the `finally` calls
`TestSessionTeardown.KillAndAwaitHostExitAsync(runtimeB, id, hostPid)` (`PtyHostLeakSweep.cs:42`):

1. `KillAsync` finds no session in runtimeB, because it adopted nothing.
2. The helper then polls up to 15 s for the live host to die.
3. That is past the class `[Timeout(10_000)]`, so TUnit reports a `TimeoutException` and the assertion is never shown.

**Effect.** The mutant is killed, because the test is red only under it. But the recorded red is the timeout, not the
assertion.

- The same masking appears for any adoption failure in these methods: PC-77 in r06, PC-46 in r10 and PC-51/PC-80 in r12.
- r20 also leaked the real host its test spawned: pid 7725, plus its `/bin/sh` child 7781. This sweep killed both after the run, by literal pid.

**Proposed fix (caller's choice; not written):** make the teardown pid fallback kill the host at once when
`runtimeB.Get(id)` is null (no adoption), or bound the poll below the class timeout. Then an adoption-failure
mutant goes red at `adopted.ShouldBe(1)` and leaks no host. This is a test-quality advisory, not a coverage gap.
