# Astra 6.2 selectability, confirmed by tests

Tip under test: `bd34a7ff6da9db1a3fa3690f824890ef9b7cc2c0` (`feat/card-task-53eaeb09`, the live rc tip at the start of this run). Linux runner. No deploy, no restart, no production Postgres. `ANTIPHON_LINUX_COMPILER_POLICY=0`. Native `bin/` and `obj/`. Each class had its own build-slot lease. Every `dotnet run` passed `--timeout 570s`.

## Verdict

In-process selectability holds at this tip. Creating a Codex High task with model `gpt-6.2-astra` stores `RequestedModelAlias` and composes `--model gpt-6.2-astra` plus `model_reasoning_effort=high`. An unknown alias, a conflict with the standing agent's model, a model without kind and level, and a hold on that alias are refused. Reroute, dispatch re-walk, blocked-chain resume, and wall requeue clear the alias. A warm pool row that carried the alias is not reused.

Nothing in this run starts a real `codex` process. The headed and real-CLI canaries skip on Linux before launch. `NamedCodexAgentLaunchTests` is red on this host because `cmd.exe` is not on `PATH`. That class does not assert `gpt-6.2-astra`, and its source matches `origin/master` (`3f01ab24968b29de65549ec5f502bdcf39702936`).
