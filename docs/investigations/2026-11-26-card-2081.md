# CARD-2081 native custody fixture teardown

The runner's `NativeHold` fixture starts a detached native PtyHost for
`LinuxRunnerCustodyLifecycleTests` and `Card1619LinuxCustodyStopIntentTests`.
Its teardown wrote a release marker, detached the runtime, and deleted the
fixture directory without waiting for the host or the payload. The marker
could disappear before the held descendant read it. The separate
`LinuxCgroupCustodyTests` fixture uses an in-process `HostHarness` and already
waits for its payload root and cgroup to empty.

The Linux red witness at `1715a216421c4f01c30dfcb69dff8914ee3f2a85` ran
`C1614_Root_exit_read_does_not_seal_live_descendant` and found one native host
alive after fixture disposal. The dedicated
`C2081_Native_fixture_disposes_its_detached_host` witness checks the same
fixture before launch, while its native host is live, and after disposal.
The expected counts are 0, 1, and 0. It waits for the held descendant and root
exit without asking the runner to read a custody receipt, which keeps the
teardown witness independent of the host-generation mismatch tracked by
CARD-2067.

Teardown gives the release marker time to drain the recorded cgroup and uses
the custody helper on that exact cgroup if needed. It then stops and joins
the fixture's detached host before removing its files. The census scopes
ownership to the fixture's shadow directory, manifest directory, and session
argument, and the stop rechecks the kernel generation.

Run the witness through `scripts/run-checkpoint.ps1` for
`tests/Antiphon.SessionRunner.Tests` with filter
`/*/*/LinuxRunnerCustodyLifecycleTests/C2081_Native_fixture_disposes_its_detached_host`
and a minimum of one executed test. Use a session-testing Linux image with
working placement and kill probes and its own initialized custody namespace.
The CARD-2081 runs used the image from the CARD-2067 review
(`sha256:f492654cbdf681978d869a5f1bce0762e42b5577d39ff8db4cda94acb08a22bc`).
