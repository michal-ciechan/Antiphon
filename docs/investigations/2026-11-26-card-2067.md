# CARD-2067 Linux custody host identity

The SessionRunner and PtyHost recorded the same PID and host instance ID but projected
the start tick against separate boot-time estimates. CARD-2060's five failing pairs
had UTC deltas of 0.65 to 1.53 ms. The .NET Linux implementation caches one estimate
per process, from separate readings of `CLOCK_BOOTTIME` and `CLOCK_REALTIME_COARSE`.
Each observer adds the same kernel start ticks to its own estimate.
[Managed implementation](https://github.com/dotnet/runtime/blob/v9.0.15/src/libraries/System.Diagnostics.Process/src/System/Diagnostics/Process.Linux.cs#L53-L90)
[Native clock readings](https://github.com/dotnet/runtime/blob/v9.0.15/src/native/libs/System.Native/pal_time.c#L90-L107)

Both Linux custody writers now read the kernel boot ID and field 22 of
`/proc/<pid>/stat`. The ledger requires the same PID, instance ID, boot ID and
start tick. Server2 reports `CLK_TCK=100`, or 10 ms per tick. Exact kernel
comparison rejects adjacent generations and works independently of differences in
UTC projection. The instance ID also distinguishes host launches within one tick.
The ledger still compares the complete host record with the stored record. Pairs
written before this change use exact UTC equality, as do Windows pairs. A pair
with one kernel identity fails closed.
