# CARD-1705 mutation sweep: scanner bounded queue-lock wait

Task 801ad6c3 (Mutation, High). The mutated source is master `1ef88240b3c5ee2c759db958e5fb0b635b1248cc`, which contains CARD-1705 (`52ea63da8`, `b48989fa6`, `f26179c6f`, `d4c88ddde`). The Code tasks were 37b01055 and 449c541d, and the Reviews were bdaa665c (round 1) and c8274f67 (round 2, clean). Runs were on Linux server2, with one build-slot lease per build and per run, `UseAppHost=false`, native default output and `TEMP=/tmp`.

**Outcome: 12 of 19 mutants were killed, 1 was killed only intermittently, and 6 survived.** Of the six, 3 are equivalent, 1 is near-equivalent and 2 need a witness. Every pending PC from the Reviews was killed: the 1 s bound, the busy-set skip, the busy catch's position and the semaphore count. The one PC the Reviews named that survived is "the clear on busy", and it is equivalent (M16 and M16b below).

## Method

- I added an env-gated switch file (`server/Application/Services/M1705.cs`, `ANTIPHON_M1705=<id>[,<id>...]`) and edits at each site. There was one mutant build of `tests/Antiphon.Tests` (2m21s), then a rebuild (2m03s) that let the switch take a comma list for the packed survivor run.
- Every mutant ran the three C1705 witnesses with `/*/*/AgentTaskLandNotificationRecoveryTests/C1705_*`. The baseline on the mutant build with no switch set was 3/3 green in 42 s.
- The survivors (M8, M12, M13, M14, M15, M16, M16b) then ran packed in one process per lane over the Review's 19 scanner classes (group A has 10 classes, group B has 9). A third lane ran `LegacyCheckNotePublicationTests` and `AgentTaskLandNotificationPersistenceTests`. That came to 437 tests, 1 of them red, which was M13 (below). Group A now has 251 tests, not the 250 Round 2 counted, because master has moved since then.
- I restored all four edited files with `git checkout -- <path>`, deleted the switch file and rebuilt (4m28s). The restored build contains no `ANTIPHON_M1705` string. The restored run of `C1705_*` was 3/3 green, and the tracked source and index are clean at `1ef88240b`.

## Survivors

### M8: phase-local busy set (witness missing)

Order and loss are unchanged. With a fresh set in the land phase, a caller that timed out in the captured phase waits another bound on its first land-phase notice. If its lock has freed by then, all of its notices are enqueued in id order in this pass rather than the next. The produced note is itself an `AgentTaskLandNotification` row, so the land phase still orders by id. The only effect is cost: each held caller costs up to 2 s per pass instead of 1 s. That breaks the claim Code 449c541d made: "the land phase skips that caller's other notices at once instead of waiting another 1 s".

Missing witness, deterministic and with no timing: seed one due Captured publication for held caller A and one older Queued land notice for A, plus a free caller B's notice, and hold A's lock for the whole scan. Assert that `LandDeliveryBoundary` `before-enqueue` fires for B's notice but never for A's land notice in scan 1. The busy skip at `:151` runs before that boundary, and under M8 A's notice reaches it.

### M12: cancelled wait treated as busy (equivalent)

The `ct` given to the bounded `EnqueueAsync` is always the hosted `stoppingToken`. `ReconcileAsync(id, stoppingToken, busySessions)` passes it at `AgentTaskLandNotificationHostedService.cs:110`. `RecoverCapturedAsync` and `ProduceAsync` thread the same token at `:79`, and the producer path passes a null set, so it never has a bound.

- Base: the OCE propagates and nothing is written.
- Mutant: the busy catch clears the tracker, adds the caller to the busy set and writes nothing. The next operation on the cancelled token then throws an OCE, which the general catch excludes. That operation is the next row's `SingleAsync` or `ToListAsync`, the `while (!stoppingToken.IsCancellationRequested)` loop check, or `Task.Delay`. The hosted catches are filtered on `!stoppingToken.IsCancellationRequested`.

No persisted state differs, and the loop ends at the next awaited call.

### M13: skip only the first busy notice (witness is probabilistic)

W3 seeds A notices until at least one is below B's id and one is above it. That leaves k ≥ 1 earlier A notices and usually exactly one later notice. Under M13, the earlier notices alternate between being skipped (which removes A from the set) and waiting 1 s (which times out and adds A back). So A2 is skipped when k is odd and enqueued when k is even. That is a reorder, and W3 catches it only then, which matches the 3 kills in 8 runs.

Missing witness, deterministic: exactly one A notice before B and at least two after it (A1 < B < A2 < A3), with A's lock freed at B's `before-enqueue`. Assert that neither A2 nor A3 has a `QueueMessageId` after scan 1, and that A's queue rows are in order A1, A2, A3 after scan 2. Equivalently, fix k = 1 and seed two later notices. The current seeding loop cannot fix k.

### M14: producer given a busy set (witness missing)

`PublishAsync` commits the publication as Produced and the land notice as Queued before the inline reconcile. Under M14, a caller lock held for more than 1 s makes the inline enqueue throw busy, and the note waits for the next scan, about 5 s later. Nothing is lost and nothing is reordered. What changes is the stated producer contract ("Producers pass null and wait for the lock as before", `AgentTaskLandNotificationService.cs:50-55`): the inline handoff no longer completes when the publish returns.

Missing witness: hold caller A's queue lock and call `LegacyCheckNotePublicationService.PublishAsync` for A's Check. Release the lock after 1.5 s. Assert that the publish completed only after the release, and that on return the note has a `QueueMessageId` and is `AwaitingReceipt`. Under M14 it returns after 1 s with the note still Queued and no queue row.

### M15: per-pass lock budget (near-equivalent; a design choice)

Once 1 s has passed in a pass, every later wait has a zero timeout. A free semaphore is still acquired at once, so only a caller whose lock is contended at that moment is skipped, and it is retried in the next pass. Order and loss are unchanged, and the scan's worst case falls from 1 s per held caller to 1 s per pass. Neither Review nor Code names "each caller gets its own 1 s" as a requirement.

If the caller wants per-call semantics pinned, the witness is: held caller A for the whole pass, then caller C whose lock is held and released 0.5 s into C's own wait. Assert that C's notice is enqueued in the same pass.

### M16 and M16b: no `ChangeTracker.Clear()` on the busy paths (equivalent)

Both paths return from `ReconcileAsync`, and nothing runs after the catch. Both of its busy-set callers save nothing on that `DbContext` afterwards:

- The hosted land phase disposes `rowScope` right away (`AgentTaskLandNotificationHostedService.cs:108-111`).
- `ProduceAsync` returns right after `ReconcileAsync` (`LegacyCheckNotePublicationService.cs:227-228`), `RecoverCapturedAsync` returns right after `ProduceAsync` (`:336`, `:344`), and the hosted captured phase disposes its `rowScope`.

The unsaved `EnqueueAttempts++` and `ConcurrencyToken` changes are discarded with the scope. The Clear is defensive. It becomes load-bearing only if a future caller saves on the same context after a busy return.

## Notes

- **M6b, W3 precondition failure.** In the parallel witness sweep (three mutants at once), W3 under M6b failed at its fixture precondition `earlier.ShouldNotBeEmpty("A1 precedes B")`. That assert runs before the hosted worker starts, so the mutant cannot have caused it. W3 alone with M6b afterwards was green, and the baseline and restored runs are green. The seeding loop should always produce an A notice before B, so a single failure here points to a possible fragility in W3's fixture under load. I did not investigate it further.
- **Interim scope.** This sweep did not run the whole Unit lane, and did not run the direct `ReconcileAsync` callers that pass no busy set (AgentTaskLandReceipt*, AgentTaskLandQueue* and similar). With a null set the diff leaves those paths unchanged, and every mutant except M14 is gated on a non-null set or on the scan call site.
- **Logs.** Logs and TRX files are outside the repo (the session scratchpad `ev/`) and are not committed.
