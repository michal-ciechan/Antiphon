# Flaky test root causes, 2026-10-02

Eight named failures resolve to seven fix groups. The two resilience cases share an unsynchronised fake-clock pump; the other six have different mechanisms. CPU pressure exposes several assumptions, but it is not evidence of a product race. CARD-0820 also discusses checkpoint temp-root contention; no evidence connects that separate issue to either resilience case here.

## Evidence and scope

- Failure wording from the cards/review evidence: CARD-0742 says "`SnapshotReads` is 2 and the test expects 1"; CARD-0889 records "expected four Enter writes but observed three" in two named cases; CARD-0890 records "`File.Exists(ready)` should be True but was False" in all seven cases. CARD-0900's failed assertion is "`C578 FailedBuild retains stdout and stderr`" even though both markers were in the log. CARD-0820 lists `ResilienceBudgetTests` as inherited under load; the CARD-0802 review records that its timing assertion "exceeded its 12 s ceiling." CARD-0751 reports a failed full lane, followed by "3/3 alone" and a passing second full lane; the CARD-0418 evidence recorded 18 s against a 15 s threshold. CARD-0757 reports "4 of the 6" failed in a full lane and "6/6" passed alone. CARD-0882 records actual `conflict` versus expected `grok_rules_argv_unsafe` for both Linux rows.
- Read `card.ps1 get` and `history` for all eight supplied cards, and searched the board with `-All` for each test name before assigning a fix card. No new card was needed because each root already has a record. CARD-0820 is the canonical shared-clock fix; CARD-0751 remains its linked symptom record. CARD-0889 is already InProgress for this investigation, so it was not duplicated as a new Backlog card.
- The only scratch test run was the Linux C448_V15 filter under `scripts/build-slot.ps1 -Label flakes`: seven executed, zero passed, seven failed. An owned PowerShell reflection probe under a second build slot exposed the inner `System.Text.Json` load failure. No product/test file was edited or runner restarted.
- For loaded repros, use an isolated output path and a build slot. A 24-burner run should retain every burner PID and kill only those PIDs in a `trap`; repeat the exact class filter 20 times. Such a stress run is supporting evidence, not the final deterministic clock/barrier test. Do not run `Antiphon.Tests` alongside `Antiphon.Agents.Pty.Tests`.
- The current eight do not support a shared-global-port/file or general test-parallelism diagnosis. A process limiter already decorates `RunCheckpointScriptTests`; C448 has a child-host mismatch, not an unbounded wait.
