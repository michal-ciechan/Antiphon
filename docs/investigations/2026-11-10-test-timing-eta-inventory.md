## 2. Gaps against the operator ask

- No `[ExpectedDuration]` (or any duration attribute) on a test class. `tests/Shared/PlatformTaxonomy.cs` lines 10-170 declare `LinuxOnly`, `WindowsOnly`, `HasLinuxSpecifics`, and `HasWindowsSpecifics` only.
- No host identity on a class duration. The class-cost file has one `platform` string, rewritten from the refresher's directory separator. Supervisor `platform` is `Windows`/`Unix` on the identity file, not on the heartbeat, and not joined to a class row.
- No per-OS split. One `seconds` number per class. A second OS cannot be stored beside the first without a schema change, and a refresh from the other OS would overwrite `platform`.
- No outstanding-batch view and no ETA. `plannedSeconds` is the current chunk's hang budget and the launch watchdog input. `watch-qual.ps1` prints failures, `RUN-ENDED`, `HANG-SUSPECTED`, and `HEARTBEAT-STALE`. `rc-qualification-status.ps1` reads `last-run.json`, the two locks, and optional `candidate.json` (`scripts/lib/rc-qualification-status.ps1` lines 134-149). `docs/release-gates.md` lines 156-159 say `lastActivityAt` does not supply an ETA. The heartbeat fields listed above have no remaining-chunk count and no finish time.
- Class-cost `seconds` is a serial sum of test `duration` attributes. Chunk wall is `runWallSeconds` (stopwatch around the chunk process) or TRX `Times` start to finish. Those are different numbers. The cost file header says the measured rows are not a p95 (`nightly-class-costs.json` line 4).
- The ledger can carry a duration and a platform. It cannot carry the host, and it rejects a new field until the closed schema changes.

## 4. Smallest design that reuses the current stores

Keep `plannedSeconds` as the batch estimate. It is already the sum the packer computed from class costs or the node model. Keep `nightly-class-costs.json` as the class number. Keep the timing sidecar as the actual. Do not add a second duration store.

**Attribute.** A generated roster beside `tests/Shared/PlatformTaxonomy.cs`, not an `[ExpectedDuration]` on each class. Hand attributes would drift from the measured file, and `PlatformTaxonomy.Derive` stays a platform function. The roster is a projection of the class-cost rows: class name, `seconds`, `basis`, `hostId`, `os`, `measuredRunId`. CARD-1832 is the neighbor directory only.

**Refresh.** Extend `scripts/refresh-nightly-class-costs.ps1` so a row keeps `source`, and so `platform` is no longer inferred only from the refresher's separator. New columns on the row: `hostId` (the measurement machine's name, passed in, never guessed), `os` (`windows` or `linux`), `measuredRunId`. One `seconds` remains the number the packer reads.

**When to split OS.** Store `secondsByOs` only after a second OS has a sample for that class and the two seconds differ by more than both 30 s and 25% of the larger. Otherwise keep the single `seconds` and record the host and OS it came from. That tolerance is a Plan choice; these two numbers are the proposed default.

**Estimator.** A read-only script, inputs the timing root's `groups-planned-*.json`, `active-chunk.json`, and `*.timing.json` (optional class-cost file only to explain a chunk that has no `plannedSeconds`). Outputs, per chunk: `plannedSeconds`, state (`complete` / `timeout` / `cancelled` / `teardown` from `lastPhase` or `completedAt`, otherwise `running` if it is the active chunk, otherwise `outstanding`), and `runWallSeconds` when the sidecar has it. Outstanding list is the plan rows still outstanding. ETA is the sum of outstanding `plannedSeconds` added to now. p50 of that sum is the same point estimate; the class file has no p95, so the script prints p95 as unavailable until chunk-wall history exists. It does not write inside the run directory.

**Where it shows.** `watch-qual.ps1` prints one outstanding count and that ETA, still writing only its caller-owned state file. The supervisor heartbeat already publishes the current chunk's idle budget; leave it unchanged so a live qualification does not gain a new writer. `rc-qualification-status.ps1` stays on its four records; `docs/release-gates.md` lines 156-159 already refuse an ETA from `lastActivityAt`, and widening that reader would mix a log-dir walk into a 1 MiB record check.

**Ledger.** CARD-1836 S1 can store `durationSeconds` and `platform` today. Filling `durationSeconds` from sidecar `runWallSeconds` (chunk) and TRX result duration (method) fits the current schema. Host id does not. New names throw `ledger-invalid`, so host and OS wait for a schema revision of `scripts/lib/rc-ledger.ps1`. Do not put them in v1.

## Root cause

The batch estimate is already computed and stored as `plannedSeconds`, and the actual is already stored on the timing sidecar and the TRX. The missing piece is a reader that lists plan rows the sidecar has not finished and sums their `plannedSeconds`. Class expected duration is the cost file, one Windows-leaning number, with no host and no second OS. The ledger's duration field is empty of a writer and closed against a host column.
