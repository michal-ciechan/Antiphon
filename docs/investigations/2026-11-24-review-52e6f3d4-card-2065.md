- Where: `scripts/lib/desktop-postgres.ps1` (new), `scripts/deploy-local.ps1`,
  `scripts/pg-qps.ps1`. No test file references `desktop-postgres.ps1`, `pg-qps` or
  `deploy-local.ps1 -Report`. The new `DesktopPostgresTests` cover only the C# copy
  (`DesktopPostgres.cs`).
- Failure: two of the five helpers named on the card can lose their highest-risk
  checks with every test still green. These checks are the endpoint match against the
  AppHost secret, the pinned 64-hex container ID, `PGOPTIONS=-c default_transaction_read_only=on`,
  hiding stderr, and refusing with exit 3 when the secret is missing. For example,
  deleting `-not $matchesEndpoint` from `Resolve-DesktopPostgresTarget`, or dropping
  the `PGOPTIONS` element, fails no test. The C# file says "Keep the resolution
  contract in sync with scripts/lib/desktop-postgres.ps1", but nothing enforces that.
- Why: the first attempt's witness for these paths, `scripts/test-reap-zombie-agents.ps1`
  (54/0 there, with a mutant on the pg-qps endpoint match), was deleted on master. It
  was not ported. Review c951b45e D-1 asked for the witnesses to be ported. The brief
  names fail-closed resolution and keeping the credential out of argv and output as the
  highest risk. A behaviour that is changed but not witnessed is not acceptable evidence.
- Fix: add an in-process test in `tests/Antiphon.Tests/Scripts`, committed red first,
  that runs `scripts/pg-qps.ps1 -Seconds 10` and `scripts/deploy-local.ps1 -Report`
  through pwsh with these fixtures:
  - a fake `docker` first on PATH that records its argv and its stdin, and writes a
    password-bearing line to stderr;
  - `APPDATA` pointing at a temporary `Microsoft/UserSecrets/aspire-antiphon-apphost/secrets.json`
    whose connection string includes `Password=`.

  The test must assert:
  - for a matching endpoint: `--context antiphon-server2 inspect`, then `exec -e PGOPTIONS=-c default_transaction_read_only=on -i <pinned id> psql ... -w ... -h /var/run/postgresql`,
    using the secret's user and database;
  - for an endpoint mismatch, a stopped container or a missing secret: exit 3 for
    pg-qps, a failed or refused verdict for deploy-local, and no `psql` launch;
  - for a psql failure: exit 3 and no stderr text in the output;
  - no `Password`/secret text in any recorded argv or in the output;
  - for `-Container`/`-PgContainer`: no `--context`.

  The reviewer's scratch probe below is this test in shell form. It needs a `.cmd` shim
  on Windows.
