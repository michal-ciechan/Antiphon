# CARD-1680 mutation sweep: restart-apphost health window (2026-11-03)

Task c389a57b (Mutation, waived ordinary-worktree sweep). Subject: master
`e56e4d1b6a727b3127b473307b860b7117980f09` (CARD-1680, landed batch 31).
**This is not CARD-0478 evidence.** Merge-role lands have no land operation id, so this
sweep ran in an ordinary task worktree with no SourceLanding identity.

Result: **28 mutants. 16 killed, 1 equivalent, 11 survived.** Eight survivors are in the
lock or launch-ownership direction. None of the 11 can turn an unhealthy or stale stack into
exit 0, and no survivor makes the wait unbounded.

## Method

- Each mutant is one literal edit of `scripts/restart-apphost.ps1` or
  `scripts/apphost-common.ps1`. The edit was applied in place in a worktree at the subject SHA,
  with the find text checked to occur exactly once. Each mutant was parse-checked, its harnesses
  were run, and the file was then restored with `git checkout --` of the exact path. All 28
  restores printed `RESTORED <id> clean e56e4d1b6…`. Three worktrees ran in parallel: the task
  worktree and two detached scratch worktrees at the same SHA, both removed afterwards. No source
  edits were made.
- Every harness run had its own build slot:
  `scripts/build-slot.ps1 -Label c1680-mut-<id>-<h> -- pwsh -NoProfile -File scripts/test-apphost-<h>.ps1 [-Case X]`.
  A mutant stopped at its first red harness.
- Green baselines at the subject SHA: health-window 30/30, graceful-stop 11/11, server-version
  131/131, dead-launch Launcher 3, Recovery 4, Alert 12 and Guards 49, all failed=0.
- Harness reach. dead-launch runs `restart-apphost.ps1 -TimeoutSec 0`, so it never enters the
  wait loop. It only reaches the post-loop launcher check and `Remove-AppHostLock`, so it was run
  only for M19, M20, M21 and M13b. Slot contention (4/4 occupied, queue position up to 7) used up
  the 100-minute budget. Late survivors therefore ran only the harnesses that reach the mutated
  code (see the "ran" column). graceful-stop never checks rotation, the progress signals or the
  pid file.
- Labels: hw = test-apphost-health-window, sv = test-apphost-server-version,
  gs = test-apphost-graceful-stop, dlL/dlR = test-apphost-dead-launch -Case Launcher/Recovery.

## Notes

- Not reproduced by name: "a stale launcher output file from the previous launch counted as
  progress". The launcher output paths carry a fresh GUID per launch (restart-apphost.ps1:282),
  so a previous launch's file is never in `$progressFiles`. M18 is the nearest real form, where
  pre-launch state is credited at the first poll.
- Not separately reproduced: "losing the current log on a failed move". The designed fallback
  already empties `apphost.log` when a move fails. No harness provokes a failed move, so that
  fallback path is unwitnessed too. M15c covers the order of the history shift.
- Evidence was kept outside the repo, in this session's scratchpad (`ev/<id>-<harness>.log`,
  `ev/shard*.log`). The mutation driver was `scratchpad/mutants.js` plus `run-mutant.sh`.
