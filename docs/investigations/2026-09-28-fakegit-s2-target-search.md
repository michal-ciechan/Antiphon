# FakeGit S2 target search: no Git-dominated class found

Investigation task `21fd71fe`, source `7ca550cec42852b9659078420707b6bda0128cc3` on Debian 12, .NET SDK 10.0.401, Git 2.47.3. **Recommendation: do not commission a third FakeGit pilot from the current test suite.** The strongest measured classes spend about one fifth of no-build wall time inside real Git. A fake cannot recover the database/test-host setup and the non-Git work in their bodies. This is a negative target finding, not an executed fake/real G1 comparison.

The earlier design (`c599994fc`, `docs/investigations/2026-09-28-test-reruns-and-fakegit-design.md`) ranked classes by cumulative duration. The qualified Boundary pilot trace on `feat/card-task-2aa8cd10` (`docs/investigations/2026-09-28-fakegit-pilot-results.md`, source `e0d450f9`) found 3,632 direct Git children occupying 10.921 of 76.373 no-build seconds (14.3%); PostgreSQL bootstrap took 40.411 seconds. Its 19 case bodies totaled 30.247 seconds, of which Git occupied 10.921 (36.1%). The other failed pilot, `GitServiceTests`, had about 15% Git share. These numbers motivated a search for a class with more Git per unit of *outer* wall time.

## Real-only measurements, ranked by Git fraction

One successful isolated `Antiphon.Tests` build was reused for two exact class filters; a separate `Antiphon.SessionRunner.Tests` checkpoint built and ran its class. All runs used the host build slot. Slot waits and builds are excluded below. A temporary `PATH` wrapper invoked the real `/usr/local/bin/git`, recording native Git entry/exit times and argv. The union of completed intervals was clipped to the fresh `run.log` birth-to-last-write interval, which closely brackets the no-build `dotnet run`; the TRX supplies the executed roster and body durations. No child intervals overlapped. This wrapper measures time *inside native Git*, excluding its own shell startup; the ratios are directional research evidence, not the pilot trace validator's full child-lifetime receipt or a formal G1 verdict. The [raw archive](2026-09-28-fakegit-s2-target-traces.tar.gz), SHA-256 `e46f20284a0fe0c03b7ff230bb2361854d5b79ac6bb3cfa5c7a70a9440cb4214`, contains the wrapper, per-run Git TSV, run logs, and TRXs.

The first case began 29.2 seconds after the checkpoint-matrix log opened and 44.0 seconds after the removal-matrix log opened. Both use `LandingSafetyHarness` and its real isolated PostgreSQL database. The Runner class avoids that database, yet its 15-case process spent about 5.5 seconds before the TUnit run began and only 3.1 seconds inside Git. Even among the checkpoint rows, `C448_V15_ResumeUsesOnlyAcknowledgedCheckpoints` is the most favorable related group: 11 rows, 18.481 Git seconds / 46.846 body seconds (39.5%). Paying about 32 seconds of this run's non-body overhead for that group alone gives roughly 23% outer Git share. One `C15` argument row reached 4.576 / 8.119 body seconds (56.4%), but its isolated process would pay the same startup and is not a viable small pilot by itself.

## Source coverage and remaining candidates

- [RunnerWorkspaceService](../../src/Antiphon.SessionRunner/RunnerWorkspaceService.cs) executes `clone`, `fetch`, `rev-parse`, `worktree add`, `status`, `worktree remove`, and `prune`; [RunnerWorkspaceServiceTests](../../tests/Antiphon.SessionRunner.Tests/RunnerWorkspaceServiceTests.cs) covers the real mirror and removal path with a scratch repository. This was the best database-free candidate found.
- [LandingGit](../../server/Infrastructure/Git/LandingGit.cs) owns the landing CLI child; [LandWorkspace](../../server/Infrastructure/Git/LandWorkspace.cs) adds/locks/resets the persistent land worktree. The measured [checkpoint](../../tests/Antiphon.Tests/Application/AgentTaskLandCheckpointMatrixTests.cs) and [removal](../../tests/Antiphon.Tests/Application/AgentTaskLandRemovalMatrixTests.cs) matrices exercise repeated recovery, ref, branch, checkout, and guarded removal paths. Even 9,633–11,002 launches per class leave more than three quarters of outer time elsewhere.
- [WorktreeManager](../../server/Infrastructure/Git/WorktreeManager.cs) calls `worktree add/list/remove` through its own child path. [WorktreeManagerGitIntegrationTests](../../tests/Antiphon.Tests/Infrastructure/WorktreeManagerTests.cs) had only 15 cases / 22.15 body seconds in the earlier profile, and pays the `Antiphon.Tests` assembly startup. [DelegationWorktreeTests](../../tests/Antiphon.Tests/Application/DelegationWorktreeTests.cs) also cover checkout, rebase, and removal through `ScratchGitRepo` and `GitWorkspaceService`, with mixed database/service work. Neither offers evidence of a better outer ratio than the two measured large landing matrices.
- [GitService](../../server/Infrastructure/Git/GitService.cs) has its own `Process.Start` route and was the failed first pilot. [LandingGitTests](../../tests/Antiphon.Tests/Infrastructure/LandingGitTests.cs) is a narrower direct-Git class; it still pays the assembly's database startup. `GitDiffSpikeTests` tests real Git diff timing, and index-lock/hook/process-custody cases assert physical Git/OS behavior; a fake would change the thing being tested.

No exhaustive Git-child census of every class was run. The measured no-database runner class and two high-volume landing/recovery classes, together with the qualified Boundary trace, leave no credible class-level target where Git *dominates* current wall time. Combining the two landing classes would amortize one `Antiphon.Tests` startup but also combine bodies whose measured Git shares are only 25.8–29.1%; it would not turn them into a Git-dominated selection. Reconsider FakeGit only after a distinct class or harness change produces a fresh real-only trace above the feasibility threshold; otherwise address PostgreSQL/test-host startup and non-Git case work directly.

## Verification notes

The qualified checkpoint runs were `run-checkpoint.ps1` with the exact filters `/*/*/RunnerWorkspaceServiceTests/*`, `/*/*/AgentTaskLandRemovalMatrixTests/*`, and `/*/*/AgentTaskLandCheckpointMatrixTests/*`; the last two used `-NoBuild` and `bin-fakegit-investigation-2/`, and the runner class built into `bin-fakegit-runner/`. Their fresh TRXs are in the archive. An initial `Antiphon.Tests` build failed with ten copy errors because the Linux `fakeclaude` apphost file collided with the staged `fakeclaude/` directory; a fresh `UseAppHost=false` build succeeded with zero errors. An initial `LandingGitTests` trace was discarded: its wrapper mistakenly called absent `/usr/bin/git`, causing 47 setup failures among 55 rows (8 pure rows passed). The wrapper was corrected and directly checked against Git 2.47.3 before the three qualified runs. No FakeGit pilot or product/test source change was made.
