## A-1 behavior

The old check uses `@($rows[0].methods).Count`. `@($null)` has count 1, so a missing `methods` property falls through to `$rows[0].methods[0]` and throws `Cannot index into a null array` before the assertion can fail.

The fix, `scripts/test-rc-coverage-admission.ps1` lines 88-96, keeps only non-null method values and then requires exactly one value equal to the obligated method. A class-scoped row (no methods) makes `manualWrong` contain that class. The new assertion requires that result for each of the two manual classes and records an exception text if the check still throws. Shipped rows have no `platform` property; a platform property still fails the exact-scope check.

The null hole does not exclude any extra test. Production `Get-NightlyProfileExclusions` already drops null and whitespace before matching, and a remaining single method excludes only that method. Piping the real method value does not split a string: a one-element policy array stays one element, and a scalar string also stays one element on this PowerShell 7.

The green assertion name is `CoverageAdmission class-scope-rejected-by-assertion`. On the red tree the detail names both classes and the null-index exception. That is a refusal with a clear message, not a silent admit.
