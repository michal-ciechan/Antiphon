# CARD-2071: plan checkpoint rows that select retired test classes

Group 113 of rc run `b8cbfb24` failed in `PlanCoverageBindingTests` because unit 20
(`3937ffdb7`) deleted `RunCheckpointScriptTests` and `CheckpointNamespaceCensusUsageTests`
while the CARD-1035 and CARD-1005 checkpoint rows still selected them. The Debug that traced
it (`114bddd4`, note `2026-11-25-why-missed-group-113-plan-coverage-binding.md` on
`feat/card-task-114bddd4`) found the same stale selector pattern in other archived plans.

## Why short verification missed it

A plan names its classes in Markdown, so the deletion compiled. Only
`PlanCoverageBindingTests` resolves plan rows against the tests tree, and it reads seven
plans. `impacted-classes --merge-subset` unions the fixed subset with the hand table
(`tests/impacted-classes.json`) only. It never reads `tests/derived-impact-index.json`, which
is where the plan-to-`PlanCoverageBindingTests` edge lives, so the Merge for unit 20 did not
select that class. In `ImpactedClasses.cs`, `Run` resolves the derived selection but calls
`Merge(matched, kinds, windowsWhole, windowsMethods)` without it.

## Guard

`tests/Antiphon.Tests/Infrastructure/PlanCheckpointClassSelectionGuardTests.cs` (Unit, no
process spawn) reads the first table of the `### Checkpoints` section of
every `docs/superpowers/plans/**/*.md`. It uses the importer's escaped-pipe split and its
first-backticked-filter rule, but not its row rules, so legacy tables are checked too. Every
OR operand of a treenode filter's class segment must match, as a glob, a class, record or
struct declared in `tests/**/*.cs` (build output, `.cs.txt` fixtures and dot directories
excluded). A namespace segment other than `*` must match a namespace declared in the same
file. Property filters and bare `*` are not checked.

A historical row is retired in `tests/checkpoint-retired-selections.json` (plan path, CP id,
operand). A ledger entry that resolves again, or whose row no longer selects that operand,
fails the guard, so the ledger cannot outlive a repair. An entry for a plan that is absent
from the checkout, such as on a pruned line, is ignored. The second test builds a synthetic
tree that covers a deleted class, a moved namespace, an excluded fixture or `bin` copy, a
retired entry, a stale entry and an unknown ledger property.

The guard joins the standing guard batch in `docs/testing-and-build.md`, which Code,
Review and Merge run whatever the diff. It is not a hand-table kind: a `tests/**/*.cs` kind
would change the exact kind and class pins in `ImpactedClassesSelectorTests` and
`MergeHighRadiusSubsetTests` (about ten assertions) for no extra coverage.

## Census and repair

At `6f5b24b75`, 576 operands in 156 plans named no declared class. 61 of them, in 32 plans,
are the classes unit 20 deleted; the 29 plans in the 114bddd4 note were counted at an
earlier pin with a narrower parser. The other operands name classes that were renamed or
never written. The CARD-1035 CP-2 repair is copied byte for byte from `114bddd4`, so the
two branches merge cleanly in either order. The other 575 operands in 155 plans are
retired in the ledger. They are historical receipts and replay only at their own pins.
CARD-1005 CP-1 stays retired because `114bddd4` keeps that row and binds it through a
fixture. No plan text other than CARD-1035 changed.
