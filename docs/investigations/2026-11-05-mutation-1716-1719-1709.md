## Findings for caller triage

### G07: missing independent open-owner witness

**Where:** `AgentTaskDispatcher.PoolSupervision.cs`, `ReleaseCleanGhostSeatsAsync`, the `busyAgentIds.Contains(row.Agent.Id)` gate. **Failure:** deleting it passed the visibility method's 22 cases and the complete 31-test ghost/visibility pack. **Why:** the visibility fixture does not seed a clean/equal completion mirror for this ownership combination, and the ghost fixture never seeds a second open owner. Later-owner cases can also be stopped by `FailedTaskSessionOwnership.CurrentOwnersAsync` before this guard is reached.

**Missing case / suggested witness:** bind an older Queued, Dispatched, Working or Blocked task to the same agent while a newer Failed task remains the current proved-generation session owner; make that Failed task's mirror clean/equal, completion at least ten minutes old, agent idle, and transcript proved idle. Assert that no slot release occurs while the older task remains open. This must fail when only the busy-agent guard is removed. Coverage gap, not a reproduced unmutated product regression; suggested priority medium.

### G05: static Blocked result masked by the ownership query

**Where:** the same method's freshly materialized `task.Status != Failed` check. **Failure:** its deletion passed the static Blocked witness and all 31 class-pack cases. **Why:** `FailedTaskSessionOwnership.CurrentOwnersAsync` already excludes a statically Blocked owner, so the candidate never reaches the deleted check.

**Missing case / suggested witness:** use a deterministic boundary after the Failed-owner snapshot but before the subsequent full task load; change that task to Blocked (or another open status), keeping the earlier busy-agent snapshot unchanged. Assert no runner release. The local check reads a later database snapshot, so this mutation is not proven equivalent under concurrency. The observed static case is classified **blocked by second guard**, with a missing race witness; suggested priority medium.

### B11b: the notice-only shutdown witness can pass before parking

The first isolated `C1709_Pass_whose_only_busy_item_is_a_supervision_notice_retries_before_the_backstop` run passed 1/1 with B11b enabled. The same witness failed in the B11b class pack, which produced all five expected StopAsync timeouts. Its final `UntilEnqueuedAsync` observes the queue row, not that the recovery loop has entered its next wait. Shutdown can cancel the pass before it calls the mutated wait, leaving nothing for this control to detect.

The supplemental isolated `C1709_Busy_pass_retries_skipped_work_before_the_backstop` run killed B11b with the intended bounded StopAsync timeout. It already waits for the backstop timer and `SettledAsync` before stopping. Use that method for the shutdown PC. If all other shutdown tests are intended to be independently reliable mutation witnesses, give them an explicit parked-loop boundary before StopAsync; a longer stop timeout does not fix the race. Mutant B11b is killed overall; retain the initial green as a witness-reliability finding rather than erasing it. Suggested priority medium. This is a witness-reliability finding; restored-source runtime behavior remains unverified.
