## Implementation and compatibility

Accounting uses an idempotent queued reservation, raw UTF-8 payload JSON bytes,
64-bit received totals, one accounting snapshot for end text/properties and a
separate immutable overflow trigger. Fixed diagnostic buckets, a 16-producer sample
and active phases exclude payloads. Output observation exposes typed phase metadata.

Registration negotiates `phoneHomeEventWindowV1`, binding both limits and epoch to
the ticket. A supporting runner reserves count/bytes before the socket writer gate.
A single connection-owned server writer coalesces cumulative observation releases.
Heartbeats/RPC replies do not consume credits. Malformed bounds/updates and oversize
events fail explicitly. Owned runner loops and request sends join before disposal.

Four fixed workers preserve per-session FIFO and return nonempty sessions to the
ready queue tail. Queues/active work retain the same global reservation. Catch-up
precedes live observation; replacement waits for old observers to join while
supervision remains active. Existing owner, generation, replay and failure semantics
remain in place. Sustained overload retains bounded runner overflow and durable
transcript catch-up, without claiming lossless transient-output recovery.

New runner + new server: `window-v1`. Old runner + new server: no capability means
no window and legacy desktop overflow/reconnect. New runner + old server: absent
response field means the new runner sends in legacy mode; old server limits can
still close it. Both server restart and runner rollout are required for activation,
through the reviewed rc process. No deployment/restart/settings change was performed.
