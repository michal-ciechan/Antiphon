**Verdict: two blockers.** Most of the guard is correct. The map, the ratchet modes, the nine frozen

reference exists today and is missing from the seed.

## Blockers

### B-1: object-initializer, named-argument and pattern member names are counted as type references

- **Where:** `tests/Antiphon.Tests/Layering/LayeringGuardEngine.cs:193-199`. Every `SimpleNameSyntax`
  is a candidate. That includes the left side of an assignment inside an `InitializerExpressionSyntax`
  (`new X { Kind = … }`, `with { Status = … }`), names inside `NameColonSyntax` (`F(Active: …)` and
  `{ Active: true }`), and names inside `NameEqualsSyntax`. These names are members, not types, but
  each one resolves to whichever indexed type has the same simple name.
- **Failure on the real tree:** 67 of the 289 seeded rows are not type references. A review probe
  that skips those three contexts leaves the same tree at `LISTED 222 STALE 67 AMBIGUOUS 3`:
  - 57 rows of `-> Kind @ server/Application/Services/GitIndexLock.cs`. The nested enum `GitIndexLock.Kind`
    is the only indexed `Kind`.
  - 6 rows of `-> Active @ …/PhoneHomeEventDiagnostics.cs`.
  - 2 rows of `-> Generation @ …/LandVerificationArtifacts.cs`.
  - 2 rows of `-> Status @ …/BootReplyWatch.cs`.

  59 of the 68 `P0-C5` rows are false, so P0-C5 cannot "remove the GitIndexLock rows": those rows
  have nothing to do with the GitIndexLock port. The same fix also clears 29 of the 32 ambiguities,
  which are named-argument artefacts such as `Outcome:` and `Stage:`. The full list is in
  `.antiphon/review-5960094e/stale67.txt`.
- **Why it blocks:** after P0-G2 sets `strict: true`, any new `Kind = …`, `Active: …` or `{ Status: … }`
  in an Application, Persistence, Integrations or Runners file is an unlisted violation, so strict
  mode fails on unrelated work. Witness R-4: appending
  `new Antiphon.Server.Domain.Entities.AgentTask { Kind = default }` to
  `server/Application/Services/RunnerState.cs` with `strict: true` turns L4 red with
  `server/Application/Services/RunnerState.cs -> Kind @ server/Application/Services/GitIndexLock.cs`.
  The seeded rows also break the "a row is a real current violation" contract, which the slice
  plans rely on when they count removed rows.
- **Smallest fix:**
  1. Skip a candidate when it is the left side of an assignment whose parent is an
     `InitializerExpressionSyntax`, or when its parent is a `NameColonSyntax`, `NameEqualsSyntax` or
     `ExpressionColonSyntax`.
  2. Add L6 in-body variants `findings=0:initializer-member`, `findings=0:named-argument` and
     `findings=0:property-pattern`.
  3. Reseed: delete the 67 rows that turn stale.

### B-2: a member, parameter or local with a type's name hides every reference to that type in the file, even fully qualified ones (the guard fails open)

- **Where:** `LayeringGuardEngine.cs:192,197`. `declaredNames` is a file-wide set of every
  property, method, parameter, local, enum-member and label name. Line 197 drops any candidate in
  that set before any qualification check. `own` (`:191`) does the same for the file's own type names.
  The TestDesign accepted false rows from this approximation ("a local or property that shares a
  type's PascalCase name can produce a false row"). It did not accept dropped references.
- **Failure on the real tree:** `server/Application/Services/AgentTaskLandingProtocol.cs` declares the
  property `LandWorkspace` (`:33`). It also contains `new LandWorkspace(git, gitSettings, clock)`
  (`:34`) and `Infrastructure.Git.LandWorkspace.Scan` / `.LockReason` (`:588`, `:696`). That is a real
  Application-to-Git reference to a P0-C5 concrete, and it is **not in the allowlist and not reported
  as unlisted**. A review probe that keeps type-only-context references (`SyntaxFacts.IsInTypeOnlyContext`)
  finds exactly this row: `VIOLATIONS 1`. Synthetic probes: `Svc Svc { get; }`, `void M(Svc Svc)`,
  `Svc Svc = null;` and an own nested `class Svc {}` beside `X.App.Svc foreign;` each produce **zero**
  findings from a Core file. In the first probe even the fully qualified `X.App.Svc Other;` vanishes.
- **Why it blocks:** the guard silently approves wrong-way references. This is the C# "Color Color"
  idiom, and positional record parameters named after their types are common in this codebase.
  Witness R-3: with `strict: true`, appending
  `Antiphon.Server.Application.Services.AgentTaskService? AgentTaskService { get; }` to
  `server/Domain/Entities/AgentTask.cs` (Core) leaves all nine methods GREEN.
- **Smallest fix:**
  1. Apply the `declaredNames` and `own` exclusion only to an unqualified identifier in expression
     position. Never apply it when `SyntaxFacts.IsInTypeOnlyContext(node)` is true, and never when the
     qualified-owner match at `:203-216` already matched an indexed identity.
  2. Add L5 variants `color-color-fires` and `qualified-with-shadowing-member-fires`.
  3. Reseed: the `AgentTaskLandingProtocol.cs -> LandWorkspace @ server/Infrastructure/Git/LandWorkspace.cs`
     row joins `# slice P0-C5`.

Both fixes stay inside the frozen nine methods as in-body variants. They change no grammar and
no layer.

## Advisories

- **A-1: a dead glob is not detected.** `dead-rule` is checked per line (`:89-90`), but a line holds
  several globs. Today `server/Composition/**` and `server/Application/Core/**` are forward
  declarations, and `server/Migrations/**` is never in the census, so none of the three matches a file.
  A mistyped glob inside a multi-glob line goes unnoticed: a `*Job.cs` typo would silently move Job
  files to Integrations. The TestDesign grammar was one glob per line.
  Suggested fix: a per-glob check that names its expected exemptions, or more L2 pins.
- **A-2: the census walks directories, not git.** `RepositoryPaths` (`C1729LayeringGuardTests.cs:226`)
  enumerates `server/` and excludes `bin`, `obj` and `bin-*`, as the TestDesign specified. An untracked
  `.cs` file under `server/` still enters the verdict. Land verification uses a clean tree, so the risk
  is local noise only. `git ls-files` would be exact; this is the TestDesign owner's call.
- **A-3: resolution gaps.**
  - Duplicate-name preference ignores enclosing namespaces. C# finds a type in an enclosing namespace
    before a compilation-unit `using`; probe `enclosing-namespace` produced a false row.
  - Other gaps are inherent to syntax-only analysis: an alias with a different name
    (`using S = X.App.Svc`), `using static`, extension-method-only dependencies, and
    nested-generic-qualified owners (`:211` strips one level).
  - On the real tree today these cost nothing. There are 2 aliases, both same-named or legal; the
    2 `using static` directives are Application-to-Application.
  - Suggested fix: record these gaps in the project-context paragraph.
- **A-4: the repository test is over the duration tripwire.** L4 took 7.9 s cold in this review's
  CP-1 (TRX). The Code run took 21.0 s at load 12. That is above the 5 s tripwire
  (`scripts/test-duration-tripwire.ps1`, manual), and the class is Unit, not Slow or allowlisted.
  - Within that time, `Analyze` takes 4.6 s for the whole tree (1,349 files, 11.8 M chars) and the
    file reads take 126 ms. Parsing dominates.
  - Analysing half the tree took 4.95 s, so there is no superlinear growth at this size.
  - The only quadratic term is `declarations.Where(d => d.Path == path)` at `:191`, which a single
    `GroupBy` would remove.
  - This is within "seconds, not minutes".
- **A-5: warn mode cannot ratchet yet.** This is by design. R-1 (a wrong-way reference added to a
  Core file) and R-2 (an allowlist row deleted) are both GREEN while the header is `strict: false`.
  Both go red under strict. Until P0-G2, each slice's "rows removed" claim is checked only by
  reading the printout.
