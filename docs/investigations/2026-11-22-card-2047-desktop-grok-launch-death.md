# CARD-2047 — Desktop Grok launch death

The stored exit shows a Windows PTY child kill while the Grok delegate's first message was still pending. The 60-second Grok readiness deadline and the server's launch cleanup are the leading explanation. The available records do not identify the kill caller or show which condition prevented readiness. The restart reported on the card was about 28 minutes after the session ended.

## Mechanism and alternatives

- **Readiness cleanup is the leading explanation.** The dispatcher queues launch before the message ([AgentTaskDispatcher.cs, line 6534](../../server/Application/Services/AgentTaskDispatcher.cs#L6534)). The service waits for readiness before setting Running or flushing that message ([AgentSessionService.cs, lines 605 and 725](../../server/Application/Services/AgentSessionService.cs#L605)). The Grok adapter uses the 60,000 ms setting ([RunnerGrokAdapter.cs, line 185](../../server/Infrastructure/Agents/SessionRunner/RunnerGrokAdapter.cs#L185), [appsettings.json, line 161](../../server/appsettings.json#L161)). A false verdict throws, and the launch catch issues the generation-scoped cleanup kill ([AgentSessionService.cs, lines 2775, 751 and 873](../../server/Application/Services/AgentSessionService.cs#L2775)). On Windows the PTY stamps `KilledByRequest` before calling the backend kill ([PtyAgentRunner.cs, line 586](../../src/Antiphon.Agents.Pty/PtyAgentRunner.cs#L586)). `ProcessExit` is the server's observation category and carries no caller identity ([SessionTermination.cs, line 30](../../server/Application/Services/SessionTermination.cs#L30), [AgentTaskLiveness.cs, line 155](../../server/Application/Services/AgentTaskLiveness.cs#L155)). The launch catch preserves an already-recorded exit if it cannot bind that exit to its own kill. One way this can happen is if the observer stored code 1 before the adapter's completion was available, leaving the cleanup's observed code null. This is a source-level possibility, with no matching kill receipt for this incident. [AgentSessionService.cs, lines 465, 917 and 946](../../server/Application/Services/AgentSessionService.cs#L946)
- **Reported restart and launch race.** The session had already ended and the task had settled at the reported restart time. The normal restart preserves detached PTY hosts. Killing their sessions requires the explicit `-KillSessions` branch, which calls `/sessions/kill-all` ([session-runner-restart-health.ps1, lines 123 and 228](../../scripts/session-runner-restart-health.ps1#L228), [SessionRunnerRuntime.cs, line 2677](../../src/Antiphon.SessionRunner/SessionRunnerRuntime.cs#L2677)). There is no evidence of an earlier restart or drain overlap in the task history. The card's report that the runner was stale by 24–25 source changes lacks a historical runner build SHA in the retrieved evidence. Staleness is unproven as either the cause of the readiness failure or the reason the task was admitted.
- **Pool release, stall and cancellation.** The normal unowned-pool sweep excludes a Dispatched owner, and the stall detector selects a streaming run attempt. The retained task events and message show no started turn. Task cancellation ordinarily writes Canceled after stopping the delegate, and there is no such event. These checks leave a separate session stop or an interrupted cancel unverified without a caller log. [AgentTaskDispatcher.cs, line 9607](../../server/Application/Services/AgentTaskDispatcher.cs#L9607), [RunAttemptStallDetector.cs, line 38](../../server/Application/Services/RunAttemptStallDetector.cs#L38), [AgentTaskService.cs, line 3172](../../server/Application/Services/AgentTaskService.cs#L3172)
- **Auth, native CLI exit and PTY host crash.** The recognized sign-in screen has a typed launch block and a task failure-code path. Neither that code nor an auth incident was retrieved. An unrecognized screen or profile condition remains possible. An ordinary spontaneous child exit would select `ProcessExited`, and the cold-host disappearance path records `ProcessVanished`. The stored `KilledByRequest` observation supports a kill path, with no affirmative crash evidence. [RunnerGrokAdapter.cs, line 199](../../server/Infrastructure/Agents/SessionRunner/RunnerGrokAdapter.cs#L199), [AgentTaskLiveness.cs, line 101](../../server/Application/Services/AgentTaskLiveness.cs#L101), [PtyAgentRunner.cs, line 266](../../src/Antiphon.Agents.Pty/PtyAgentRunner.cs#L266), [SessionRunnerRuntime.cs, line 4763](../../src/Antiphon.SessionRunner/SessionRunnerRuntime.cs#L4763)
