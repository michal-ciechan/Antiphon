# Mutation sweep: CARD-1617 custody kill bound and CARD-1681 EIO end of output

Task b9b25805 (Mutation, waived). This was an ordinary-worktree sweep on master
`6a4f522962ba6c7598fbad9d4e8439298a035370` (L). It covers two things:

- **CARD-1617:** the Linux custody kill bound in `PtyAgentRunner.SealAndObserveCustodyAsync`.
- **CARD-1681:** EIO is end of output only after root exit (`IsHangupAfterRootExit`, `RootExited`, `ProcStatShowsExit`, `ProcStatReader`).

Both landed in batch 29 (picks `09a41371f..b2ea37b4d`). The sweep ran on this task's Linux x64 runner container (kernel 4.15, load
average about 8-16) on 2026-11-03 from 11:29 to 11:42 UTC, inside the 120-minute budget.

**These results are NOT CARD-0478 evidence.** The Merge-role land has no land operation id, so there is no
SourceLanding. This sweep was waived to an ordinary worktree. No product or test code was changed, and nothing
was landed. The only commit is this report.

## Outcome

**43 single mutants plus 2 layer pairs and 1 diagnostic combination were run (57 mutant runs, plus 9 baseline and restored-green runs). 33 single mutants were killed and 10 survived.**

- **Pending positive controls.** Every pending PC was killed at its planned assertion: PC-1..PC-19, including the named variants PC-12a/b, PC-14a/b and PC-19a/b, plus PC-10.
- **One plan-variant survivor:** PC-8b (see below).
- **PC-19a was not a survivor here.** It is the null `/proc` reader at the production call site. Review r2 expected it to survive CP-3, but on this host it is killed race-dependently in **7 of 8** CP-3 runs (details below).
- **Survivors by kind.**
  - 3 are single layers of a guard with more than one layer, or equivalent by construction (S01, S03, S04). Their pairs are killed.
  - 1 is masked by a host-level lock (S14).
  - 5 are coverage gaps: S08 and S02 (safety direction), plus PC-8b, S11 and S15.
  - S09 is a near-equivalent low gap.

### Equivalent or redundant (pairs killed)

- **S01.** The runner drops `if (population.Count != 0) return` (:656). The journal (S03 layer) and the store validation catch it. The pairs S01+S02 and S01+S03 are both killed:
  - S01+S02 at W1-W4 `ShouldDrainAsync` :438, `Draining -> Exited`;
  - S01+S03 at :437, `verification_custody_invalid_receipt`.
- **S03.** The journal drops `observation.ActiveProcesses != 0` (`HostCustodyJournal.cs:244`). It is redundant with the runner's early return, which also sets `OutputDrained=false`. The pair S01+S03 is killed.
- **S04.** The journal drops `!observation.OutputDrained` (`HostCustodyJournal.cs:244`). This is equivalent by construction: on the Linux explicit path, `OutputDrained` is false only together with `Count != 0`.
- **S14.** `SealAndObserveCustodyAsync` drops `_writeGate` (:607/:670). It is masked: `HostSession.GetCustodyAsync` serialises every custody read on `_admission` (`HostSession.cs:383`), and the tests are sequential. Only a runner-level concurrent witness could kill it. That would be two `SealAndObserveCustodyAsync` calls with a blocking fake `Terminate`, expecting `Terminations == 1` while the first call is in flight. No production Linux caller bypasses `_admission`.

### PC-19a (review r2 note): killed race-dependently, not a survivor here

PC-19a makes `RootExitedForHangup` pass `null` as the reader (`PtyAgentRunner.cs:365`), so only the runner's exit observation counts.

- **Runs.** It ran eight times on the host lane: **7 red, 1 green.**
  - The red runs failed on W3 `C1617_Bounded_release_still_finalizes` :290 and/or W2 `C1617_Failed_termination_retries_on_capped_backoff` :257.
  - The assertion was `final.State` `Exited` but was `Unknown`/`observation_failed`.
  - `C1681_Eio_after_root_exit_drains_to_receipt` was never red.
- **Baselines.** Five switched-off baselines (h00, h00-r1..r3 and h99) were green 9/9, and so was every unrelated mutant run.
- **Meaning.** On this host, the pty master's EIO often arrives before `HandleExit` completes `_exitTcs`, so the `/proc/<pid>/stat` signal (a zombie or PF_EXITING) is what lets the drain succeed. The stat path carries real load. It is not belt-and-braces.
- **The kill is not deterministic.** Which test dies varies, and one run in eight survived.
- **A deterministic witness would need a seam:**
  - Drive the Linux custody read path with `ReadStreamForTestAsync` (or a fake `IPtySession`), using a stream that throws `IOException("Input/output error", 5)` while `_exitTcs` is **not** completed. Make `_conn.Pid` the pid of a reaped child (stat missing, so gone) or a zombie.
  - Assert that the drain succeeds (`_custodyReadFailure` stays null), and that it fails when the pid is live.
  - That needs runner seams for `_custody`/`_containment`/`_conn` on the scripted-stream path. Without them, the race-based host kill is the only one.
- **The combination PC-16+PC-19a** (both root-exit signals dropped) is killed deterministically: W2 :257, W3 :290 and C1681 after-exit :370, all `Unknown`/`observation_failed`.
- **PC-15 and PC-19b on the host lane:** green 9/9. PC-15 drops the stat signal at the static `RootExited`, so it differs from PC-19a only in where the cut is made. Its host run was green once, which fits the 1-in-8 survival rate above. The unit lane kills it deterministically.

## Method

- **Gate.**
  - Every mutant was compiled in behind `M1617.On(id)`, which reads `M1617_MUTANT` (a comma-separated list).
  - The gate is in the untracked file `src/Antiphon.Agents.Pty/M1617.cs` (public, so `HostCustodyJournal` in Antiphon.PtyHost could use it). It was deleted afterwards.
  - Mutant edits were in `PtyAgentRunner.cs` and `HostCustodyJournal.cs` only. With the variable unset, the gated code is L.
- **Builds.** One build-slot lease per build, native default output, `-p:UseAppHost=false`, `TEMP=/tmp`. No slot wait.
  - gated `tests/Antiphon.PtyHost.Tests`: 43 s (cold)
  - gated `tests/Antiphon.Agents.Pty.Tests`: 10 s
  - restore builds at L: 14 s and 10 s
  - After the restore, the rebuilt `Antiphon.Agents.Pty.dll` (in both test bins) and `Antiphon.PtyHost.dll` contain no `M1617_` string, so no stale gated DLL.
- **Runs.** Every run was `dotnet run --no-build --project <P> -p:UseAppHost=false -- --treenode-filter <F> --report-trx --timeout 20m`, each under its own lease, one at a time, never concurrent, with lanes run separately.
  - host lane: `/*/*/(LinuxCustodyReleaseHostTests*)/*` (9 tests, about 7 s)
  - unit lane: `/*/*/(Card1681PtyHangupTests*)/*` (30 tests)
  - floor: `/*/*/(HostCustodyPlatformTests*)|(CustodyReceiptBackendTests*)/*` (6 tests)
  - The class-scoped lane filter contains each PC's planned methods exactly. It also shows any extra witness that dies.
- **Isolation.** One mutant per run. The exceptions are the declared pairs S01+S02 and S01+S03 and the diagnostic PC-16+PC-19a.
- **Baselines** (gate compiled in and off): u00 30/30, h00 9/9 (plus h00-r1..r3 9/9), f00 6/6.
- **Restored green at L:** u99 30/30, h99 9/9, f99 6/6.
- **Load.** There were no load flakes. The only nondeterministic result is PC-19a, which is explained above and backed by the five green baselines.
