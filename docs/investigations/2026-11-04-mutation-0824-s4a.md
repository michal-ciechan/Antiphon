    the reopened attempt. Missing test: `Reopened_attempt_re_proves_a_tree_dirtied_after_the_refusal`.

## Method

- Every mutant is an exact-string edit of the production source at L, gated by `Mut.On("<id>")` in an untracked
  `server/MutationSwitch.cs` (deleted after the sweep). Inert with no environment; the `base2` run proves it
  (174/175 green, the one red is PC-64).
- Build 1 (lease 13 min) ran PC-1..PC-4 one per process (`ANTIPHON_MUT=<id>`). Slot waits of ~4 min per run made
  95 single-mutant processes too slow, so builds 3/4 select the mutant **per running test**:
  `ANTIPHON_MUT_MAP="Class.Method=<id>;..."` read through TUnit `TestContext.Current` (reflection). 24 packed rounds
  carry one mutant per test method; a mutant spanning two methods (X-2, X-3, X-22, X-27) is mapped to both in the
  same round. PC-1 re-killed in round R00 as the mechanism check. Builds 2 and 3 and their runs were discarded: build 2 threw
  `AmbiguousMatchException` on `TestContext.Current`; build 3's first rounds showed the mutants inactive
  (`TestDetails` is non-public), both fixed before build 4. Only build-1 and build-4 evidence is counted.
- PC-64 (an attribute, not gatable) was an exact edit in builds 2-4; its red is `base2`'s and `X-26`'s single red.
- M-7 ran process-wide over CP-24's two classes; X-26 over CP-23 + CP-24 (all four classes).
- One build-slot lease per build and per run; three runs at a time; `TEMP=/tmp`, `-p:UseAppHost=false`, native
  output.
