## Group 74 — slow phone-home observer

`PhoneHomeBackpressureTests.Slow_observer_is_attributed_without_payload` throws `TimeoutException`: "The operation has timed out." at line 220, `h.Activity.Entered.Task.WaitAsync(LoadTimeoutBounds.PhoneHomeSignalWait)`. Linux red: the same exception, 49s. The first half of the method (the held `output.publish` phase) had already passed, so this is the activity hold.

`HeldActivity` is a `SaveChangesInterceptor` that signals `Entered` only when `AgentSession.LastSeenAt` is modified through the change tracker. CARD-1987 writes that stamp with one raw command tagged `-- rt.activity.write` (`AgentSessionRuntime.RecordActivityAsync`). The phase `output.activity` is entered immediately before that command. The SaveChanges interceptor never runs, so `Entered` never completes and the 20-second `PhoneHomeSignalWait` expires. This is a missed signal. It is not a Windows timer and it is not desktop Full-run load. A 20-run load loop was not required: the old interceptor cannot observe that command.

The repair keeps the SaveChanges path and adds a command interceptor on `rt.activity.write`, registered beside it. The command is held while the phase is still active, the fake clock advances 10 seconds, and the existing pump cycle logs the slow observer. `PhoneHomeSignalWait` stays 20 seconds. No sleep was added. Linux green after the fix: 32s, one run.

Why the gates missed it: the short Final and the Linux selection that landed CARD-1987 proved the write is one tagged command. They did not run this Integration method, whose hold still assumed SaveChanges.

## Group 84 — task-input HTTP 500

`AgentTaskInputFallbackTests.Input_body_is_absent_from_task_summary_events_and_logs` asserts `publicResponse.StatusCode` is OK and gets InternalServerError at line 326. Linux red: the same assertion, 37s. `ExceptionMiddleware` replaces an unexpected exception with the body "An unexpected error occurred." and logs the exception, and the test asserts status before it reads that body, so the red log does not print the type name.

The cause is in the test host. `GET /api/agent-tasks/{id}` takes `AgentTaskGetPollMetrics` (`AgentTaskEndpoints`). `TaskInputHttpHost.StartAsync` registers every concrete type in `AgentTaskService`'s namespace with a factory that throws "Unmounted endpoint attempted to resolve {name}." `AgentTaskGetPollMetrics` is in that namespace. `AgentTaskService` is registered again after the loop. The poll counter was not, and the last registration wins, so the GET resolves the throwing factory. The repair registers the real singleton after the loop. The throwing placeholders stay. Linux green: 43s. That registration is the only change in the file.

Why the gates missed it: CARD-1972 / CARD-2004 added the parameter and covered it with `AgentTaskGetPollMetricsTests`, which reads `Program.cs` and the endpoint text. The minimal host that maps `MapAgentTaskEndpoints` and then keeps only the detail route was outside that selection. The failure is the same on Windows and Linux.
