## What a sync debt is

`AgentTaskSyncDebt` is one settled attempt's owed desktop fast-forward. States are Pending, Ready, Held, and Superseded. `SettlementSyncRecoveryService.SaveAsync` writes Ready only from Pending, and only when the desktop-after SHA, the remote SHA, and the full ref all equal the debt's `SourceSha` by ordinal compare. It then sets `ConfirmedSha` to that same `SourceSha`. That proves one recorded SHA was on the desktop checkout and on the remote ref at confirmation time. It does not prove that every later commit on the task branch was published.

The only other Ready writer is `MarkExhaustedReadyAsync`. It runs only for Held reason `settlement_sync_attempts_exhausted`, and only when the desktop worktree HEAD matches the recorded `SourceSha` and the episode still matches. It does not fetch or fast-forward. Every other Held reason, including `settlement_sync_source_changed`, is restamped hourly and does not read the worktree.

`GitObjectId.IsFull` accepts only length 40 or 64 lowercase hex. Settlement refuses a short or uppercase source as `settlement_sync_source_changed` before Ready.

## The new rule cannot skip a live recheck

`SyncDebtRetentionPolicy.Unpaid` is one EF expression: Pending, or Held, or Ready whose `SourceSha` is null or whitespace, or whose `ConfirmedSha` is not ordinally equal to `SourceSha`. `RunnerWorktreeRetentionService.ClassifyAsync` and `DesktopLegacyReleasePolicyService` both filter with that expression. Any unpaid debt for the task blocks. Newest does not win. Superseded does not block. A paid Ready beside a separate Held debt still blocks.

Classify is not the deletion. The runner service calls it again immediately before each send. Other server holds remain: not terminal, still inside `MinTerminalHours`, leaf or branch or slot or landing or repair or mutation, land pending, the path shared with an open other task, a live session, an unpreserved report. Only then is a retain request sent. `RunnerWorkspaceRetention.CheckAsync` then requires a confined registered worktree, HEAD on the request branch, `git status --porcelain --untracked-files=all` clean, `rev-list --count HEAD --not --remotes=origin` equal to 0, a live `ls-remote` of that exact branch, and `merge-base --is-ancestor` of HEAD into that live tip. It also refuses a live process and an ignored secret. Phase B is `git worktree remove` without `--force`. The server clears the mirror path only when the runner says Removed, or AlreadyAbsent with no retiring residue.

Desktop `ActAsync` reloads the row and runs `PrecheckAsync` before filing. Precheck refuses a dirty status, a HEAD that is not the branch, an `ls-remote` failure, and a HEAD that is not an ancestor of the live origin tip. The release is filed with that live HEAD, not the debt SHA. Guarded removal matches the inspection HEAD to the requested SHA and rechecks ignored content and late untracked files.

Counter-example: Ready for SHA A with `ConfirmedSha == SourceSha == A`, then a local commit B that never got a new debt. The server now sends. If B is not an ancestor of live origin, the runner returns unpushed or origin-does-not-contain-HEAD and the tree stays. If a new Pending or Held debt was recorded for B, `Any` blocks on the server and the runner is never asked. If B was pushed, the commits are published and removal is allowed; the desktop may still be at A. That is a missing new debt, not an unpublished-only-in-tree deletion.

The status check includes untracked files. It does not list stashes. A stash ref in the common git directory survives `git worktree remove`, so this path does not delete stash contents. The unpushed check is HEAD against remotes, not every local branch. Both limits are pre-existing. They do not let an unpublished HEAD through.

Equality is ordinal. A different case or an abbreviation does not match, so those rows stay unpaid. There is no mixed-case or abbreviated fixture. Production Ready rows are written only after an ordinal match, and an uppercase source is refused before Ready. This fails closed. It is an advisory coverage gap, not a land blocker, and it does not need a repair card: the contract's "equals" is the same ordinal compare the writer already uses.

The debt filter is by task id. Another task's debt does not block this task. `path_shared` still blocks an open other task on the same path. Task leaves are `task-<id8>`, and task ids are not reused. An older unpaid debt of the same task still blocks, which is stricter than sibling inventory. Sibling inventory still treats every Ready as paid and keeps only the current attempt whose full ref matches and whose source is a full id. The plan leaves that selection outside this change. `AntiphonRefProtection` already treats only Pending and Held as open (CARD-1446). `WorkspaceSlotReleaseService.EligibleAsync` likewise blocks only Pending and Held. Neither of those paths deletes a worktree. Retention is the stricter deletion gate.
