# CARD-2068 Windows session launcher tests

The CARD-2060 review found three failures in a Linux run of `SessionRunnerRuntimeTests`.
The same three reproduced at `ef381ddf1b57c08e045b7e3f6d38fe197e468c3a` in
checkpoint run `20261126-024515-5556` on Debian 12. The source was clean and the
build source was verified. The row executed five tests. Two passed and three failed.

| Method | Linux baseline failure |
|---|---|
| `Session_runner_starts_shell_accepts_input_and_keeps_buffer` | Sending input to the exited `cmd.exe` session threw `InputRefusedException`. |
| `Session_id_can_be_relaunched_after_exit_but_not_while_running` | The second start did not throw `InvalidOperationException` because the first launch had exited. |
| `StartAsync_that_fails_after_the_host_exists_leaves_no_pty_host` | The missing executable did not cause `StartAsync` to throw. |

The three methods now call the existing Windows-only gate before fixture setup.
Their placement roster entries allow the checkpoint validator to recognize the
three Linux skips. The Linux rc policy excludes just these methods.
`WindowsUnitPlatformAdmissionTests` uses the shipped policy reader and selection
logic to check that Windows selects the whole class and Linux selects its two
remaining methods. Native Windows execution belongs to the Windows qualification.

The new Linux row adds one record to the pinned legacy exclusion set (98 to 99).
The 109 witnessed records remain intact. The live-lane input digest was regenerated
after the policy hash.
