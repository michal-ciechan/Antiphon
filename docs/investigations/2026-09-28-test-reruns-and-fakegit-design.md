# Test rerun cost and FakeGit design (2026-09-28)

Investigation for task `9ad681e2`. No product or test code was changed. All durations below are observations on the stated host/selection, not a current full-suite benchmark. The current full-suite duration is unknown: [testing-and-build.md](../testing-and-build.md) §Gotcha 74 says the 3,893-case/25.5-minute figure is obsolete; a 7,072-case discovery, 1,992-case Unit selection (70.29 s outer wall), and a 492-case broad slice (94m23s raw, with interference) were measured on 2026-09-10.

Flake-driven reruns are separately evidenced by CARD-0776 (two 5 s gate waits fail under parallel load, pass on rerun), CARD-0761 (accepted TCP client discarded, websocket hang becomes reset), CARD-0687 (20 ms real race), CARD-0625 (client 20 s timeout), CARD-0622 (`RepairSourceSettlementTests` 90 s timeout in class, passed alone), CARD-0568 (37 concurrent `pwsh` tests without limiter, 15 timed out under load), and CARD-0609 (unguarded shared `CLAUDE_CONFIG_DIR`). All were read from full board-card descriptions with `scripts/card.ps1 get CARD-nnnn -Json`; these cards already own their fixes.

**History gap.** `tools/Antiphon.Checkpoints` writes per-run `report.json`, `report.md`, TRX, and slow-class rows under `.antiphon/checkpoints/<run-id>/`; `report --merge` merges only reports with the same manifest hash in one results root ([Program.cs](../../tools/Antiphon.Checkpoints/Program.cs), [ReportWriter.cs](../../tools/Antiphon.Checkpoints/Report/ReportWriter.cs)). Searches of server entities/`AppDbContext`, API routes, and checkpoint code found no central test-class/checkpoint-duration table or endpoint and no cross-worktree historical cost report. Nightly state records suite runs, not a durable per-class duration series. A later plan should emit a small immutable class-duration record keyed by commit, host, run, row, class, outcome, and rerun reason; do not call repeated selected rows “flakes.”

## Real external systems and existing fake convention

`FakeGrok` is a **real local executable** staged by the E2E and PTY test project build targets ([E2E csproj](../../tests/Antiphon.E2E/Antiphon.E2E.csproj), [PTY csproj](../../tests/Antiphon.Agents.Pty.Tests/Antiphon.Agents.Pty.Tests.csproj)). `LandDeliveryOptions.ConfigureHost` selects it through `Agents:Definitions:c467-grok:Exe`, puts `GROK_HOME` under the fixture root, and passes named, non-secret fake controls through `Env`/`NonSecretEnvironmentNames`. `FakeGrokContractTests` drives the staged process through the same PTY runner. E2E `ChannelOutboundIsolatedTests.Composed` selects a staged `f5-grok` executable and `ANTIPHON_FAKE_OUTBOUND_*` knobs for the converter path. The real-vendor checks are separate opt-in canaries: e.g. `GrokCanaryTests`/`FakeVsRealClipParityTests` use `[Explicit]`, headed isolation, and `ANTIPHON_HEADED_TESTS=1`; they compare a documented contract after vendor changes. There is no universal FakeGrok-vs-real switch shared by all E2E bodies.

`FakeSlackServer` is an in-process Kestrel HTTP/WebSocket stand-in for exact Socket Mode and Web API shapes, with recorded sends/acks/uploads and injectable faults ([FakeSlackServer.cs](../../tests/Antiphon.Messaging.Tests/FakeSlack/FakeSlackServer.cs)). E2E links its source file, starts it on an ephemeral loopback port, then constructs the **real** `SlackChannelAdapter` with `SlackSettings.ApiBaseUrl = fakeSlack.ApiBaseUrl` and fixture tokens ([composed E2E](../../tests/Antiphon.E2E/ChannelOutboundIsolatedTests.Composed.cs)). No same-body real-Slack opt-in was found. The reusable convention is explicit boundary injection, fixture-owned roots/endpoints, observable receipts, and separate real canaries; FakeGit should add a stricter same-body backend switch.

Git has several seams already: production `ILandingGit`/`LandingGit` and `ITaskProgressGit`; `ControlledLandingGit` implements an explicit in-memory commit/ref model and throws on unsupported command shapes, but still writes some **real** HEAD/admin/content files for production code that reads `System.IO`; `LandingProtocolHarness` injects it while retaining a real isolated PostgreSQL database. `FakeTaskProgressGit` and `MockGitService` cover narrower policy calls. The real `LandingGitFixture` constructs a bare remote, canonical repo, worktree, and observer clone and overrides `LandingGit` for fault cuts; `ScratchGitRepo` shells out for worktree tests. `WorktreeManager` and `GitService` still have their own `Process.Start("git")` paths, so an `ILandingGit` swap alone cannot make all tests fake. No LibGit2Sharp usage or current `RealGit` switch was found. `System.IO.Abstractions` **22.1.0** is already referenced by the server, and `System.IO.Abstractions.TestingHelpers` **22.1.0** by `Antiphon.Tests`; `MockFileSystem` is already used for directory/slash-command/zombie-census tests. No `FakeSystemIO` or `Testably.Abstractions` reference was found.

A conservative source inventory finds **105 Application/Infrastructure files with direct real-Git fixture/process references**, defining 1,428 `[Test]` methods in those files. That is an **upper bound**, not 1,428 Git executions: partial classes, mixed pure/real tests and argument expansions make static counting imprecise. The earlier timing profile positively identifies about 30 real-Git classes but measured only five large land matrices and three narrow classes. Its narrow examples were `WorktreeManagerGitIntegrationTests` 15/22.15 s, `GitServiceTests` 12/5.20 s, and `GitDiffSpikeTests` 5/10.98–13.74 s. Full-suite Git wall share remains unmeasured; the 122-minute serialized case-time floor shows it can dominate a selection that includes the five matrices.

Other expensive real boundaries: `TestDbFixture` starts one PostgreSQL Testcontainer lazily per relevant `Antiphon.Tests` process, then clones template databases for isolation. The prior profile measured 24.4–25.7 s bootstrap, 140–180 ms clone, 50–60 ms drop; database-specific SQL, locks and migrations require real PostgreSQL. A fake DbContext is appropriate for policy-only cases, not the transcript/query/locking tests. `AntiphonAppFixture` starts a real PostgreSQL container, Kestrel host, isolated runner, and sometimes Chromium; ten E2E source files create browser pages. Child-process script tests are a larger near-term non-Git target: CARD-0734's PowerShell harness (14.2 min per named class selection) and CARD-0733's probe builds, plus the older [full-category profile](2026-09-11-card-0474-full-category-timing-breakdown.md)'s `RunnerRestartHealthTests` 143 s/55 cases. These already have offline shims or fake endpoints; batch/reuse the child process and preflight before building a new fake.

## FakeGit design and migration plan

1. **Unify the command boundary.** Keep `ILandingGit` as the landing API; add an injectable Git command executor to `WorktreeManager` and `GitService` where they currently start processes privately. Fixture builders supply one `TestGitBackend` to setup, production service, and independent assertions, so fake mode cannot accidentally invoke real Git. Preserve production CLI as the default in the application. Do not make production `GitService` depend on test types.
2. **Model Git state over `IFileSystem`.** Extend the explicit `ControlledLandingGit` graph into `FakeGit` with `MockFileSystem`: commits with parent OIDs and tree snapshots, index vs working tree, local refs/HEAD, linked worktree registrations/admin paths, bare remote refs, fetch state, and a deterministic trace. Implement only commands exercised by migrated tests: `init`/`clone`; `worktree add/list/lock/remove/prune`; `branch`/`checkout`/`switch`; `add`/`commit`/`status`/`diff`; `rev-parse`/`show-ref`/`symbolic-ref`/`merge-base`; `fetch`/`push` with fast-forward and force-with-lease checks; `rebase`/`merge` including dirty-tree, divergence, and conflict/sequencer states. Simulate a conflict by overlapping changes from a common ancestor, preserve pre-conflict refs, and implement `--abort`/`--continue` only when a migrated test needs them. Return real-shaped exit codes and normalized stdout for known vectors; throw on every unsupported command (no default success, no fallback to `git`). Model filesystem operations through injected `IFileSystem` at the production readers touched by those tests. The package supplies filesystem state; the Git rules belong in `FakeGit`, not in `MockFileSystem`.
3. **Same test bodies, explicit real opt-in.** A fixture factory chooses fake by default and the real CLI backend only when `ANTIPHON_TEST_REAL_GIT=1`; both expose the same paths, command/result contract and assertion helpers. The same exact TUnit class filter then runs either backend, with real mode logged in the checkpoint report and kept on `ProcessSpawnLimit`. Put a few sampled real parity rows in an explicit Git-upgrade/mismatch lane; compare normalized refs, worktree registration, file content, exit class, and conflict/abort result across backends. Existing real-only capstones for index bytes/locks, hooks, submodules, symlinks/junctions, OS path behavior, and child-journal identity stay real. `MockFileSystem` follows the host OS's path rules, so it must not certify Windows-specific Git behavior on Linux.
4. **Measure before expanding.** For each migrated class, capture fake and real TRX method durations on the same host/commit and the command trace count, keep assertions identical, and add a parity scenario before deleting a real-only assertion. Report per-class wall and process count; preserve class `Slow` registration until a new measurement supports changing it. A later central duration series should include backend (`fake`/`real`) and selection origin.
