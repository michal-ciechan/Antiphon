- **Deferred effects, nine failures:** all four arguments of
  `C0491_CancelledBoundaryKeepsWorkingFlushesTheRowAndConfirmsFromTheUserPrompt` and all
  four of `C1169_AgedScreenOnlyRefinementFollowsInterruptedSentRecovery` in
  AgentTaskMidTurnRefineTests asserted before the action coordinator ran. Its common

  pulling the turn end only commits/hints effects. It now explicitly drains the real
  coordinator before checking queue submission. Complete/head-only/no-prompt and
  transport-failure assertions remain intact.
- **Claude input admission, six failures across two classes:** five seat-release tests
  used recipient adapters without current generation-bound observations:
  Long_answer_keeps_complete_content_and_spill_receipt,
  Settlement_delivery_precedes_release_and_survives_release_fault,
  Parent_receipt_rejects_ack_stale_or_partial_prompt,
  Answer_receipt_rejects_ack_stale_or_partial_prompt, and
  Accepted_answer_after_release_is_delivered_once. AttachRecipientAsync now calls
  the shared EnableClaudeDialogObservationAsync helper against the persisted generation.
  The agent-control remote-control boot test also needed WithClaudeDialogObservation.
  That alone left its modal gate unable to see the launched fake: unlike a production
  runner, its runner client cannot supply a snapshot. Its first boot-prompt callback now
  registers the started adapter with the runtime once, exposing the helper's real dialog
  observation before the work prompt gate. All three ordered prompt assertions remain.
- **Invalid branch setup, one failure:** the seat-release blocked-report test used
  `feat/retained`, which is not an owned delegate branch. Branch validation correctly
  returned runner_sync_branch_mismatch before reaching the missing dependency under test.
  That test now supplies RemoteWorkspaceService.OwnedBranch(taskId), still asserting
  dependency-unavailable, retained branch, report, running session and default-off parking.
- **Fixture race, one failure:** Herdr's
  A_launch_still_owned_by_the_queue_is_consumed_only_after_its_catch_classifies_it
  changed the session to Failed before the worker necessarily entered adapter.StartAsync.
  The standing launch authorization could refuse before the intended detect-timeout cut.
  A completion-source rendezvous now proves entry into StartAsync, and an additional
  queue-ownership assertion precedes the injected terminal state. The existing gate,
  catch classification and consecutive-failure assertions remain. Its new rendezvous has
  a finite 10-second failure bound; no existing deadline was increased. This is fixture
  scheduling, not an unexplained load-only dismissal or a demonstrated product defect.
