### B-4. The printed migrations query loses its identifier quotes under sh

Where: `scripts/deploy-server2-postgres.ps1:280,283`; `docs/docker-stack.md:1381` has the correct escaped form.

Failure: the script prints `psql -U antiphon -d antiphon -At -c "select "MigrationId" from "__EFMigrationsHistory" order by "MigrationId""`. In sh the inner double quotes close and reopen the word, so Postgres receives `select MigrationId from __EFMigrationsHistory order by MigrationId`, folds the identifiers to lower case, and fails with `relation "__efmigrationshistory" does not exist`. The doc block prints `\"MigrationId\"` and `\"__EFMigrationsHistory\"`, so the script and the doc disagree, and the test asserts only the `__EFMigrationsHistory` substring (`drill-commands`), which cannot see the quoting.

Why: a phase 3 acceptance query that errors as printed; doc and script must print the same sequence.

Smallest fix: build `$migrations` with escaped quotes (`select \"MigrationId\" from \"__EFMigrationsHistory\" order by \"MigrationId\"`) so the printed line equals the doc's, and assert in `drill-commands` that the printed line contains `\"__EFMigrationsHistory\"` (or compare the nine printed commands with the doc block line by line, which also closes A-17).
