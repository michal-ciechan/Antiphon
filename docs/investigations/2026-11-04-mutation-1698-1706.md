### Survivors: missing witnesses

1. **A8f/A8g/A8h (version-unreadable message fields).** `Test-C1698_UnreadableVersion` checks
   only `StartsWith('WARNING: the git version could not be read')` and the `floor` property, never
   the message's floor, impact or fix. Missing case: for each unreadable source, assert the
   message contains `the minimum is 2.43`, the impact text (`lands will fail`) and
   `Fix: ` + the host fix, as `Below message carries all five fields` does for the below-floor
   message.
2. **A9pRS (restart-server wrapper removed alone).** Equivalent for every value the shipped lib
   returns: `Write-ToolchainFloorWarnings` and `Get-ToolchainFloorWarnings` catch everything, so
   only a dot-source failure (lib missing, unreadable or unparsable) reaches the caller's
   wrapper. A9rs shows the harness kills an escaping throw. Missing case: `restart-server.ps1`
   (and the runner entry) run from a root whose `scripts/lib/toolchain-floor.ps1` throws at load
   (for example a file containing only `throw 'x'`), asserting exit 0, `Server restarted.` and
   the same stop/build/start calls. The same gap holds for the session-runner and nightly-run
   wrappers.
3. **A11b (summary.json write).** `Test-C1698_SummaryRecordsToolchain` proves the function
   output and finds the call site by source text, so any edit that keeps the text but skips or
   overwrites the assignment survives. The harness comment says Invoke-E cannot reach the summary
   on Linux. Missing case: a run of the nightly-tests preflight block (Windows Invoke-E, or a
   seam that executes the block) that reads the written `summary.json` and asserts
   `preflight.toolchain.tools` and `warnings`.
4. **A12 (non-ASCII in the lib).** `NightlyScriptsTests.The_three_scripts_are_ascii_only`
   lists the nightly scripts and `nightly-run-impl.ps1`/`nightly-tests-impl.ps1` (A12b proves it
   bites there) but not `scripts/lib/toolchain-floor.ps1`, `restart-server.ps1` or
   `scripts/session-runner-restart-health.ps1`, all of which carry the ASCII-only rule. Missing
   case: add those three paths to the ASCII list (or a CARD-1698 ASCII test over them).
5. **A13/A13b (Windows PowerShell 5.1 syntax).** No test guards 5.1 syntax for these files:
   every harness runs pwsh 7, which accepts `?:` and `??`; on 5.1 both are parse errors, so the
   dot-source fails and the caller wrapper prints `check failed` (no exit change, but no
   warning either). Missing case: a 5.1 parse of the lib and its three entry callers, either
   Windows-only with real `powershell.exe` (the CARD-1048 `BuildSlotScriptTests` pattern) or a
   cross-platform AST scan with `[System.Management.Automation.Language.Parser]::ParseFile`
   refusing `TernaryExpressionAst`, `??`/`??=` tokens, `?.`, and pipeline-chain `&&`/`||`.
