## Change

`LandNotificationPayload` reserves **448 UTF-8 bytes for diagnostics before allocating
sibling detail**. This leaves space for a sibling-count summary within the 1,024-byte
envelope even with four distinct 64-character approval SHAs. The sibling allocation
cannot borrow that reservation when diagnostics are short. Unused space can carry
optional cleanup prose and path detail.

`WorktreeCleanupPresentation.NotificationParts` composes capture identity/time,
prior-request provenance, first owner name/PID or diagnostic availability, and Git/native
facts from the committed structured capture. It reserves fixed facts before bounding
the owner display name. Cleanup prose and paths follow separately; no final clipping
operation spans the mandatory block and sibling text. Optional clipping remains
UTF-8 aware and uses `~`.

`AgentTaskLandService` passes the capture reference and separate sibling entries to
the producer. A fitting list retains its existing marker. An oversized list reports
`unlanded-sibling=N siblings, showing first M` and only complete task/branch entries.
It does not parse the publication narrative or split arbitrary branch names to count
siblings. Existing terminal-event formatting, immutable destination/body/digest, queue
identity and complete UserPrompt receipt semantics remain in place.
