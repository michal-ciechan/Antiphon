  (no such pid, access denied) is `Missing` without a throw; an exited-but-openable pid returns an

  `PROCESS_MEMORY_COUNTERS` (DWORD, DWORD, 8 x SIZE_T; 72 bytes on x64). FILETIME and `TimeSpan`

## Blocker

### B-1 The no-snapshot witness guards dead code, not the production reader

- Where: `src/Antiphon.SessionRunner/HostStatsSamplerService.cs` (`internal static long? WorkingSet`),
  `tests/Antiphon.SessionRunner.Tests/HostStatsSamplerTests.cs`
  (`Working_set_reader_does_not_snapshot_the_system_once_per_process`, first block;
  `Production_query_reads_this_process_once`, tick section).
- Failure: `HostStatsRoutes` now wires `processes.WorkingSet` on the `SamplerProcessQuery` singleton.
  The static `HostStatsSamplerService.WorkingSet` has no caller anywhere (src, tests, docs, scripts)
  and allocates a fresh `SamplerProcessQuery` per call. V-1's first block scans that dead method.
  The plan says V-1 "fails if the sampler snapshots with `GetProcessById` / `WorkingSet64` /
  `GetProcesses` / `NtQuerySystemInformation`"; it does not. A regression that adds
  `Process.GetProcessById(pid).WorkingSet64` to `SamplerProcessQuery.WorkingSet` (bypassing `Read`,
  so `Queries` stays at 1) or to `Read` ahead of the OS branch passes V-1 (only the `ReadWindows`
  body is scanned) and V-2. The Code-stage mutant "putting `GetProcessById` back failed V-1" mutated
  the dead method, so it is vacuous for production. The DI wiring of the working-set delegate is
  also unwitnessed: wiring the dead static (new instance per call, cache never hit, two reads per
  process per tick) passes V-1 and V-2, because V-2's tick section builds the sampler with the
  test's own `SamplerProcessQuery`.
- Why: the card's acceptance is "no whole-system snapshot per sampled process"; its witness must
  bind the reader production calls.
- Fix: delete the static `HostStatsSamplerService.WorkingSet`. In V-1 scan `SamplerProcessQuery.cs`
  with the `ReadLinux` body excised (or the `WorkingSet(`, `Read(` and `ReadWindows(` bodies) for the
  four tokens. In V-2 add a production-wired tick: resolve `HostStatsSamplerService` and
  `SamplerProcessQuery` from `HostStatsServices()`, call `SampleOnceAsync()`, and assert exactly one
  query (the self target has no host pid), which proves the CPU probe and the working-set delegate
  share the singleton and the cache is hit through production wiring. Re-run CP-1.
