## Blockers

### B-1. The scratch drill has no scratch compose; reusing the production compose under the drill project name mounts the production volume

Where: `docs/docker-stack.md` section `Scratch restore drill` (new lines 1361-1369); `scripts/deploy-server2-postgres.ps1:178-198` (`Write-Server2PostgresDrillPlan`) and `:332-338`; `docker-compose.server2-postgres.yml:42-44` (explicit `volumes.pgdata.name`) and `:25-26` (`ports`).

Failure: the card's `## Drill` and plan phase 0 step 6 require a restore into scratch project `antiphon-server2-postgres-drill` with its own volume, then removal of only that container and that volume. The delivery names the scratch project and volume `antiphon-server2-postgres-drill_pgdata` but ships no compose definition that produces them, and `-RestoreDrill` prints labels (`drill-project:`, `unread:`, `phase3:`) rather than commands. The only compose file in hand pins the production volume by explicit name, so the obvious operator move `docker compose --env-file <env> -f docker-compose.server2-postgres.yml -p antiphon-server2-postgres-drill up -d` renders (verified with `docker compose config -p antiphon-server2-postgres-drill`) `name: antiphon-server2-postgres-drill` but `volumes.pgdata.name: antiphon-server2-postgres_pgdata` and the same `host_ip: 100.64.0.2` `published: "5432"`. A `pg_restore` into that container writes into the production volume, and a `down -v` of the drill project targets the production volume (Docker refuses only while the production container still holds it; after a stop it deletes). The runbook therefore does not define a safe scratch path, and the natural improvisation is a data-custody hazard.

Why: card `## Drill` ("with its own volume", "remove only the scratch container and the scratch volume"), plan D-3 and phase 0 step 6, brief item (5), decision CARD-1221 risk list ("Production Postgres ... created ... Forbidden"). Missing acceptance behaviour of the card's drill.

Smallest fix: add `docker-compose.server2-postgres-drill.yml` with `name: antiphon-server2-postgres-drill`, the same `${ANTIPHON_POSTGRES_IMAGE:?}`, command preload, healthcheck and `${POSTGRES_PASSWORD:?}`, volume `pgdata` with `name: antiphon-server2-postgres-drill_pgdata`, no `ports:` (phase 3 runs by `docker exec`, never a host connection string), and no shared network name. Make `-RestoreDrill` print the exact commands with that file: `up -d`, decrypt-and-restore (`age -d <dump.age> | docker exec -i <drill container> pg_restore -U antiphon -d antiphon --no-owner --no-acl`), the phase 3 queries via `docker exec`, then `docker compose -p antiphon-server2-postgres-drill -f <drill file> down` and `docker volume rm antiphon-server2-postgres-drill_pgdata` (that exact name only; keep the existing `drill-volume-guard` source assertions). Mirror the commands in the `Scratch restore drill` doc subsection. Add script test cases: the drill compose contains `name: antiphon-server2-postgres-drill_pgdata`, contains neither `antiphon-server2-postgres_pgdata` nor `antiphon_pgdata` nor `ports:`, and `-RestoreDrill` output names the drill file and redacts the password. Red first by committing the test before the compose file.

## Advisories

- A-1. `Test-Server2PostgresBind` (`deploy-server2-postgres.ps1:43-55`) accepts any syntactically valid IPv4 in `-WhatIf`, including LAN or public addresses; only `-Execute` compares against `tailscale ip -4`. Add a `100.64.0.0/10` range check so the dry run refuses a LAN or public bind statically. Execute's equality check remains the authority.
- A-2. The image regex requires `postgres:16@sha256:<64 hex>`. `docker inspect --format '{{index .RepoDigests 0}}' antiphon-postgres` yields `postgres@sha256:...`, which the script refuses with the misleading reason `image-floating`. Document the exact expected value in the doc section and name the reason (for example `image-not-16-digest`).
- A-3. Exit codes (0 plan or ok, 2 refusal, 3 `ambiguous-mode`) are not documented in the script header or the doc section.
- A-4. `Expand-Server2PostgresCompose` (`:157-169`) is called only by the test's `render` case; the `-WhatIf` path never prints a rendered view. Either print the redacted render in `-WhatIf` (complete dry-run output) or drop the function.
- A-5. On Windows `Test-Server2PostgresMode0600` returns false, so `-WhatIf -EnvFile` always refuses `env-mode` on the desktop. Fail-closed, but undocumented; say in the doc that the env-file dry run is Linux-host only.
- A-6. No `shm_size`. Docker's default `/dev/shm` is 64 MiB; Postgres parallel workers on the 794 MB `TranscriptEntries` relation can hit `could not resize shared memory segment`. The desktop file has the same omission, so this is parity, but the compose or the doc should state the choice (`shm_size: 1g` is the usual value).
- A-7. `POSTGRES_PASSWORD` is container environment, visible to `docker inspect` on the host. This is what the card specifies. The CARD-0628 principle in the same doc prefers file secrets; a later card can move to `POSTGRES_PASSWORD_FILE` with a mounted secret.
- A-8. `docs/testing-and-build.md:1028-1029` still says the runner is the only standing Antiphon process on server2 with "no server and no Postgres". Out of this card's documentation scope (one sentence in `docker-stack.md`); fold into the fix round or CARD-1741.
- A-9. No closed `### Checkpoints` manifest exists for slice C1: the plan has `## Proposed checkpoints` (CP-2 is this script) and no TestDesign closed it, so the Code report carries no CP-n rows. This review followed the brief's explicit verification profile instead. C2 and C3 should get a closed table before Code.
- A-10. `Test-Server2PostgresDrillVolume` is called in production only with its own constant (`:260`, self-compare). No committed path removes any volume, so it guards nothing today; the B-1 fix is where the real drill compose's volume name should be validated.
