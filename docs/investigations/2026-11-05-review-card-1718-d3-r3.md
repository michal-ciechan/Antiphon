## B-1r2: closed

`ReadIgnoredSecretAsync` (`src/Antiphon.SessionRunner/RunnerWorkspaceRetention.cs:534-541`) now sends every
listed entry that ends in `/` to `ReadCollapsedIgnoredDirectory` (`:551-596`). That method:

- checks each ancestor segment for a reparse point before entering;
- walks the tree with an explicit stack and `EnumerationOptions { IgnoreInaccessible = false, AttributesToSkip = 0 }`,
  so hidden entries are included and a denied directory throws;
- refuses (keeps the tree) on a reparse point, a control character, an escaping path, any
  `IOException`/`UnauthorizedAccessException`/regex timeout, or more than 10 s of walking;
- applies `IgnoredSecretFloor.Matches` to the root-relative path of every descendant file, so the
  `**/x/**` descendant companions apply too.

One helper serves admission, the locked recheck, phase B and residue recovery. Cancellation throws
before `git worktree remove`, so nothing is deleted on that path.

From the code, without a probe:

- **A directory that changes during the walk.** A vanished entry raises `DirectoryNotFoundException`
  or `FileNotFoundException`, both `IOException`, so the tree is kept. A directory swapped for a
  link after its check can only add names or time; nothing is ever opened. The remaining gap is a
  secret written into an already-walked directory before `git worktree remove`. That is the same
  TOCTOU window as round-2 A-2, and it needs a writer in a tree that passed the holder scan.
- **Windows trailing dot or space.** The walk calls `File.GetAttributes` on a path without the
  `\\?\` prefix, and Win32 normalisation trims a trailing dot or space from the last segment. So
  an entry like `key.pem.` resolves to a missing file, raises `FileNotFoundException`, and the tree
  is kept (fail closed). A `.env ` name matches `.env*` anyway. This is reasoned, not run natively.
  The top-level listing path still name-matches without a stat; that is round-1 A-3, which predates this diff.

## Advisories

- **A-1r3 Over-protection and opaque detail.** Any link, unreadable entry or walk past 10 s in an
  ignored nested repository keeps the whole tree with `inspection_failed` and the detail
  `ignored list unavailable`. The detail does not say which entry, or whether a link, a denied
  directory or the budget caused it. A nested checkout with `node_modules/.bin` symlinks would be
  held forever. Suggest a bounded detail (`collapsed=<dir> cause=link|denied|budget`).
- **A-2r3 The budget is per collapsed entry and the walk is synchronous.** With N collapsed
  repositories, one listing can walk N x 10 s. Execute walks three times: the first check, the
  locked recheck that runs inside the dispatcher's mutation lock, and phase B. Measured cost is
  about 70 microseconds per file (40k files, 2.8 s per DryRun), so about 140k files reach the budget,
  and the tree is then kept. Suggest one total deadline per `ReadIgnoredSecretAsync`.
- **A-3r3** The walk TOCTOU described above (same class as r2 A-2).
- **A-4r3** Native Windows reparse, ACL and trailing-dot behaviour is still unverified (V-Native pending).
- **A-5r3** .NET never sets `FileAttributes.Device` on Unix, so FIFOs and sockets count as files.
  They are only name-matched, never opened, so this is harmless. The `Device` test is effectively Windows-only.
