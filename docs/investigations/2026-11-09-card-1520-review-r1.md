## D-1 (blocker): the witness's JSON assertion is red on Windows

- **Where:** `tests/Antiphon.Tests/Infrastructure/CheckpointPerEntryRefusalReasonTests.cs:84`, in `AssertPersisted`: `ReportWriter.JsonText(model).ShouldContain(reason, ...)`. Both tests call it.
- **Failure:** `HostCleanupCheckpointFixture` builds host-native paths with `Path.GetFullPath(Path.Combine("/c987", ...))`. On Windows the reason is `left in place: C:\c987\<guid>\bin-owned\payload.txt; ...`. JSON escapes each backslash as `\\`, so the serialized text never contains the raw reason. Both tests fail at `:json` on the Windows Unit lane and in the Windows rc qualification.
- **Probe:** I loaded the built `Antiphon.Checkpoints.dll` into pwsh and serialized a `ReportModel` with that refusal. The output has `"reason": "refused: left in place: C:\\c987\\abc\\bin-owned\\payload.txt; ..."`, and `contains-raw=False`. The same check on a `/c987/...` path gives `True`, which is why the test passes on Linux.
- **Why:** this adds a new red test to the Windows lanes. The fixture keeps host-native paths on purpose so that Windows runs these classes.
- **Fix (test only):** compare the parsed value instead of the raw text. For example, `JsonDocument.Parse(ReportWriter.JsonText(model)).RootElement.GetProperty("cleanupRefusals")[0].GetString().ShouldBe(reason)`, or `ShouldContain(JsonSerializer.Serialize(reason, ReportWriter.Json))`. Production code needs no change.
