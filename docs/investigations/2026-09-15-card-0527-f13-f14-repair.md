## Repairs

F13: persist a `CommitRecoveryStarted` event containing the exact settlement digest
in an independent context before the gate can stage or commit. This saves no outer
settlement state. Every retry checks that durable obligation before classifying a
repository-negative result as ordinary non-Git work. Failed history cannot erase it.
The existing settlement identity lookup runs again until history and repository
inspection recover. A failure saving the obligation prevents mutation.

F14: scoped add, commit and reset use `:(literal)` filenames. Scoped staging verifies
the changed index paths against the approved set and restores the captured index
on unexpected changes. Commit trailers store the approved filename manifest;
the shared `InspectCommittedFilesAsync` checks actual files against it for immediate,
operation-recovery and settlement-recovery receipts. Old commits without a manifest
retain legacy recovery; this task's new settlement obligations require the manifest.
Endpoint validation continues accepting legal bracketed names.

The recovery architecture now has durable pre-mutation evidence and a shared
committed-file inspection guard, rather than relying only on ordering individual
inspection calls. The settlement and HTTP operation identity lookups remain distinct:
one permits an inspected empty history before a new attempt, the other requires one
exact completed operation. Their existing unavailable/ambiguous guards remain.

No database schema migration. Restart after eventual landing: **server**, no runner.
This task does not land or deploy.
