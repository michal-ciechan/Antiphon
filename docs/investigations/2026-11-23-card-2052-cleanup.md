# CARD-2052: owned-output cleanup reads the git index once per index version

This note covers CARD-2052 only. The shared rc note `docs/investigations/2026-11-22-rc-run-79d9e6f9-failures.md`
is unchanged.

## Problem

`CheckpointOutputLedger.Remove` asked "is this entry tracked?" once per owned entry. Each answer read and parsed the
whole git index (about 11,500 entries). The checkpoint tool's `output-cleanup` phase took 369 s for a
2,190-file output on server2 (Review ad310231).

## Change (rounds 0-2)

- `TrackedIndexScope` keeps one in-process index listing for each `Remove` call. It reuses the listing only while a
  fresh `TrackedIndexStamp` shows the same version. The stamp covers:
  - the index's inode, size, mtime and ctime;
  - the index length and its SHA-1 trailer;
  - git's 2-second racy-index rule;
  - the text of every config file git or libgit2 consults (repository, global, XDG, system, ProgramData) and the
    variables that move those files.
- Round 1 (Review d1e0f4ca): a listing whose stamp moves while it is being read authorizes nothing. A decision bound
  to an index version may unlink only while the index is still that version.
- Round 2 (Review 2ff6a0bc): a decision bound to no version is asked again after the content hash and the
  creation-identity lookup (`SafeWrite.Preflight` with no scope). Only a fresh untracked answer permits the unlink.

## Round 3 blockers (Review 2b79e113) and the round 4 repair

1. **An included config changed during validation and the bound decision still held.** The stamp observed the
   including file but not the included one. `DecisionBound` was set even when the stamp declined reuse. Repair:
   - A decision now binds only a Reusable stamp, meaning complete and settled.
   - Any of these leaves the decision unbound: an include or includeIf in any consulted file (now including
     user/system files), per-worktree config, or a racy index.
   - The stamp observes every included file, recursively to git's depth of 10, whatever the include's condition.
     A value it cannot resolve is recorded as unresolved.
   - Each entry keeps the stamp its check observed, even when git answered the check.
   - An unbound entry gets a fresh lookup with no reuse after validation, then is kept if a stamp re-read after that
     lookup differs from the observed one.

   git's repository setup reads `.git/config` through `git_config_from_file`, which does not follow includes. So
   git ignores an *included* `core.worktree` and still calls the target untracked. The fresh lookup alone could not
   keep the file. The stamp comparison does.
2. **When the discovered repository disappeared, the fallback recheck reported success.** `PreflightRoots` with no
   owner returned null ("nothing tracked") from the absence of a repository. Repair:
   - `Remove` records a `RepositoryIdentity` at its start: the checkout root, `.git` (kind, ids and gitdir pointer),
     the git directory and the common directory (paths and ids).
   - `requireRepository` (passed when `AllowOutsideRepository` is false) refuses when no repository is found.
   - Each entry re-verifies the identity before its decision and as the last observation before its unlink.
     `repository-unavailable` or `repository-changed` keeps the entry.
   - Outputs deliberately outside every repository keep their policy.

## Measurements (server2, production `CleanOwnedOutputs`, scratch driver outside the repository)

| Round | Files / dirs / bytes | Seconds | In-process index reads | Refusals |
|---|---|---:|---:|---:|
| before CARD-2052 | 2,190 / 40 / 856,657,920 | 369 | one or more per entry | 0 |
| round 2 (Review 2b79e113) | 2,190 / 40 / 856,657,920 | 51.186 | 7 | 0 |
| round 4 (this repair, no include) | 2,190 / 40 / 856,657,920 | 46.941 | 7 | 0 |
| round 4, repository with `include.path` | 200 / 4 / 78,233,600 | 27.038 | 420 | 0 |

The round 4 runs used a `git clone --shared --no-checkout` of the task tip with `git read-tree HEAD`, which gives
11,690 index entries. With an include, every entry reads the index twice: once for its decision and once after
validation. That is about 0.13 s per entry, or roughly 5 minutes for 2,190 entries, close to the pre-CARD-2052 cost.
On server2 the runner mirrors' configs (`/work/repos/antiphon/.git/config`, worktree gitdirs, and global) have no
include and no `config.worktree`, so the fast path applies to them.
