# CARD-2080 Linux placement deadline

The Linux runner now gives tracked placement sixteen seconds. It still clamps the
absolute cutoff to the request's 30-second window with one second for the reply.
The host and native shim share that cutoff. Scaling the budget covers scheduler
delays in each fresh PTY host, including delays that a warm executable cache
cannot remove.

## Server2 measurements

The active runner image predates the placement stage. Measurements used an
isolated cgroup-v1 `session-testing` container on the 24-core server2 host,
image `sha256:f492654cbdf681978d869a5f1bce0762e42b5577d39ff8db4cda94acb08a22bc`.
The installed stage passed the v1 probe and its source matches the assigned
checkout. Each repetition started a fresh test process, and each tracked
launch spawned a fresh PTY host. The kernel page cache was shared. The two
stress profiles used a one-CPU container quota and either two or six CPU
workers running in that container. The native runs used the host build slot.

The host log records elapsed time from receipt to the launch decision and
reply construction, the budget remaining at receipt, admission time and
outcome. Stamp-to-reply time adds `PlacementLimit - receipt_budget_ms` to
the logged elapsed time. It includes request serialization and transport,
host setup, spawn and the handshake. The budget starts after the new PTY
host connects. The measurement includes reply construction after placement.

The five-second full-class run with six workers reproduced
`verification_custody_start_failed`. The host had 4.293 s left at receipt
and logged a broken pipe before returning the error 5.399 s after receipt.
The test driver reached its outer 90-second cap before finishing the class.
That partial run establishes the failure and is excluded from the percentile
table. All eight ten-second replays reached the payload, including the
7.994-second sample. The final 16-second budget is about twice that
provisional stressed p95. The sample is small. CARD-2080 can use the timing
log to collect the first 20 cold placements from the next qualified Linux
run and refine the tail estimate.

The 15 complete class repetitions executed 105 cases. The 30 helper and
namespace cases passed, and the 75 tracked launches returned before their
tests failed a subsequent custody read with the CARD-2067 identity mismatch.
The same mismatch reproduced in the exact base
`0cfc4ac1ffb41f5af159a0c1db423fe119950267` with the root-exit method. The
16 explicit-release tests had the same custody-read failure after launch.

## Verification

The clock-driven fixture at `0bf1403c51d03904c9744d2d1a5408b5df465935`
failed before the fix with `verification_custody_placement_refused`. It
holds a valid PLACED frame until six seconds, then checks GO, acknowledgement
and proof commit. Its silent peer stays pending through the tick before the
deadline, loses the socket at the deadline and leaves no committed proof.
The witness uses real Unix sockets and is listed in the existing Windows
exclusion for Linux placement tests. The compiled policy checks cover the
marker and its roster entry.

Native TRX, stage probe evidence and the timing CSVs are under
`/work/evidence/debug-34fef000/`. The branch's timing baseline is
`0600207be7bb3ff1ff08ab729e92f4da777c038d` and the ten-second native build is
`3dab4a8d5ca96b4fdff88d17a144a846d2edaf78`.
