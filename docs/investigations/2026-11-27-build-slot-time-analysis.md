**Confirmed mechanism.** The server2 checkpoint driver builds the selected project and its references. A one-method row in `Antiphon.Tests` can therefore require a build of 46 projects. Most retained MSBuild traces show a full graph restore and a fresh output tree. Three observed same-checkout builds reused restore state and finished in 27–59 seconds. Different tasks successfully built the same clean SHA and entry project at least 42 times after the first task. The Windows rc run explicitly built `Antiphon.sln` once and shared its prerequisites across suites.

## 2. Project scope and compilation cost

On server2 the project commands resolve to the following shapes. The Linux default adds `UseAppHost=false`. Source-qualified scheduled builds can add the three checkpoint intermediate properties from `AppendSharedLayout`. The grant determines `N`. The filter goes to the test executable after `--`.

```text
dotnet build <project> --property:OutputPath=<owned-bin> --property:ArtifactsPath=<owned-bin>/artifacts --property:UseArtifactsOutput=true --property:UseAppHost=false -nodeReuse:false -maxcpucount:N --nologo
dotnet run --project <project> --no-build --property:OutputPath=<owned-bin> <same-layout-properties> -- --treenode-filter <filter> --report-trx --report-trx-filename run.trx --results-directory <row-directory>
```

For the standalone path, `RowCommand` holds its slot across the `RowRunner` call. In a grouped run the scheduler uses one producer for a build ID and gives each dependent row `NoBuild=true`. The confinement driver additionally evaluates `dotnet msbuild <project> -getItem:ProjectReference -nologo -nodeReuse:false ...` recursively to determine owned paths. That is evaluation work before the SDK build, with the recorded target's references and forwarded properties. A command row executes its own explicit command, and the actual argv determines its scope.
