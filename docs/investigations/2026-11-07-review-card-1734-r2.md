## Diff audit against the brief

1. Truthful terminal receipts. `TerminalReceipt.Publish` (new) is the single producer for stop
   (`Program.Stop`, exit 130 `supported-stop`), caller cancellation (`CheckpointApp.ExecuteAsync`
   catch, exit 130 `caller-requested`) and executor failure (exit 6 or 2). It rereads
   request.json and manifest.resolved.yaml, refuses a state whose owner/runId/commit/fingerprint
   disagree with the request, observes the source again (a failed observation leaves End null,
   state unknown; an earlier `changed`/observed-`unknown` state is kept), marks pending or running
   builds and rows with the terminal state and reason, parses each row's existing TRX (absent or
   malformed is null, never zero) and writes report.md/report.json then state.json with
   `phase=done`, exit and `EndedAt` equal to the report. Row timeout and build failure/timeout stay
   on the ordinary scheduler path; `Finish` now takes the report's `EndedAt` so state and report
   agree. `ReportValidator` and the script both refuse a non-empty `reason` on a green report
   (ordered after cleanup/exit/source checks); green runs never carry a reason. Witnesses:
   CP-5 (all six modes), R-6, R-7, R-8, mutants M2, M5, M6, M7.
2. Executor-to-waiter regression. Stop takes `.terminal-publication.lock` (SafeWrite OpenGate,
   FileShare.None, errno 11/32/33 means held) after identity checks and before `StopAndWait`, and
   holds it through re-read, publication and tool cleanup. Wait tries the same gate only after it
   observes the executor dead; while a stopper holds it the observation is downgraded to unknown
   and the loop continues, so the round-1 race (and advisory A-1 of round 1, the concurrent tool
   cleanup) is closed. The executor's own terminal paths publish before the process exits, so a
   dead observation already implies the receipt. Witnesses: the HeldStop barrier test, M1, M3.

4. Writes and deletions. All new writes go through `CheckpointWrite.Under(runDirectory)` (report
