### Confirmed separate origin defect

The untraced ParameterHops failure is reconstructed from an actual Git-produced fixture config. Windows Git stores the local origin as `C:\\...\\origin.git` in `.git/config`; `git config --get remote.origin.url` decodes it to `C:\...\origin.git`. `Get-NightlyOriginUrl` reads the text with a regex and returns the raw match (`scripts/lib/nightly-common.ps1:182-189`); the ownership guard compares it directly to the decoded `ExpectedOrigin` (`:237-239`). Consequently the correct origin is refused. This is a product config-reader defect exposed by a Windows local-path fixture, not evidence of a foreign checkout and not a selection-worker timeout. The demonstrated scope is a Windows local origin; the default HTTPS origin has no such backslash escaping and is not shown broken here.

`E/origin-reconstruction.json` preserves the raw config, expected string, parser result and equality checks. Its first ownership probe correctly refused the evidence directory as `shared-tree`; that result is retained, not credited as the origin witness. A copy of the same independent fixture clone under the task-owned scratch checkout then passed the earlier location/marker gates and returned **`Field=origin`, `Reason=wrong-origin`**, with **`rawEqual=false`, `gitEqual=true`** (`E/origin-reconstruction-outside-shared-tree.json:3-15`). No config or production reader was changed. This matches the native ParameterHops transcript and the historical group-77 F091 error.

The untraced BaselineAuthority failure is also separate: `ScriptHarnessOptions.Default` sets the whole-case budget to 300s (`tests/Antiphon.Tests/Scripts/ScriptHarnessProcess.cs:16`), and repeat1's retained timeout transcript contains 12 successful assertions through `baseline-ancestor-required`, with the final incompatible/publication checks not completed. Repeat2 subsequently completed in 292.026s without changing the budget. The historical direct 362s/14-row pass is consistent with this cumulative fixture cost; a 300s-censored TUnit duration is not a completed-case p95. No timeout was loosened to conceal it. This is a fixture-performance/budget problem requiring a Debug/Plan follow-up, not evidence that one selection worker stalled.
