## Survivor PC-19 (call-site wiring) and the missing test

The diagnostics show that the only host witness,
`LinuxCustodyReleaseHostTests.C1681_Eio_after_root_exit_drains_to_receipt`, passes with either
signal alone:

- With the stat signal dropped (PC-15), it passes, so the runner has always observed the exit
  before it classifies the EIO.
- With the exit signal dropped (PC-16), it also passes, because the stat then shows the root gone
  or a zombie.

So nothing pins the production wiring of the `/proc/<pid>/stat` reader:

- the `null`-without-pid branch;
- the path string;
- the pid it reads.

The unit tests pin only the static `RootExited` and `ProcStatReader`, and they are given their
inputs directly.

The real case this guards is the EIO that arrives before the runner sees the exit. The kernel
closes the descriptors in `do_exit`, before the parent's wait returns. In that case PC-19a and
PC-19c turn a valid Linux release into `Unknown/observation_failed`, so they fail closed and do not
fail open. They are still coverage survivors, because the plan's stated reason for the stat signal
is not witnessed.

**Missing test:** `Card1681PtyHangupTests.C1681_Eio_before_exit_observed_drains_from_proc_stat`
(or a host twin), in `Antiphon.Agents.Pty.Tests`, where the internal seams are visible.

1. Start a Linux tracked launch with a fake `CustodyContainment`.
2. Hold `ExitHandledForTest`, which runs before `_exitTcs` completes
   (`PtyAgentRunner.cs:276-279`). Release it only after the read loop has handled the EIO, using
   the `ReadProcessedForTest` signal from the catch.
3. Assert that the custody drain succeeds, with an `Exited` receipt and `OutputDrained`.

The test is red under PC-19a (no reader means not exited) and under PC-19c (the reader sees the
live test host, so not exited). It is green at L.
