## Blockers

**B-1. False green: build/shard exit codes and non-`Failed` TRX outcomes are ignored.**
- Where: `scripts/lib/post-land-early-warning.ps1:876` (`$null = Invoke-PostLandSlot $build`), `:891` (shard exit discarded), `:611-626` (only `outcome="Failed"` counts).
- Failure, probe 1: a stub `build-slot.ps1` returns 4 for the build, the slot-timeout code. The lane still ran the shard `--no-build`, and the receipt was `completed`, `slot=true`, `new-reds=0`. On a long-lived worktree (S1 manual, S4 hourly), `--no-build` runs the previous tip's binaries. The green is credited to a tip that may not compile, and that receipt becomes the next tip's ancestor baseline.
- Failure, probe 2: the shard exits 2 and its TRX has `Timeout` and `Error` outcomes. The receipt is `completed new-reds=0`, executed=2 passed=0 failed=0.
- Also: TRX files from an earlier attempt on the same tip are read as fresh when a re-run shard writes none.
- Why: the brief requires exit 4 to be reported. The repo's own parser counts `Failed`, `Error`, `Timeout` and `Aborted` as failures (`tools/Antiphon.Checkpoints/Trx/TrxReport.cs:57`). A hang or a compile break is the regression this card exists to catch.
- Fix: record the build exit and each shard exit in the receipt. A non-zero build (4 = slot timeout) skips the shards, and the summary reads `new-reds=unknown build=<exit>`. A shard that exits non-zero with no fresh TRX is `no-trx`. Remove or refuse a pre-existing `<shard>.trx` before each shard, or require mtime after the shard start. Count `Error`, `Timeout` and `Aborted` as failures. Add a run-mode witness: extend `POST_LAND_WARNING_SLOT_SHIM` to return a chosen exit and optionally write a TRX.

**B-2. `Non_linux_run_refuses_before_a_slot` is red on Windows by construction.**
- Where: `tests/Antiphon.Tests/Scripts/PostLandEarlyWarningTests.cs:183-201`. The absent-seam and empty-seam cases expect exit 2 `refused=head-mismatch` on every OS. With no seam, the script uses `$IsLinux` (`scripts/post-land-early-warning.ps1:26-41`), so a Windows host exits 3 `refused=not-linux`.
- Failure: the simulated Windows host mutant gives `absent.Exit should be 2 but was 3`. The class is `[Category("Unit")]` with no `[NativeLinuxOnly]` and no OS branch, so the Windows Full rc qualification goes red. That is the run this card is meant to protect.
- Why: R2-style Linux-only blindness, and it is a regression in the rc lane.
- Fix: branch on `OperatingSystem.IsLinux()` in the test. On Windows, absent and empty expect exit 3 `refused=not-linux` with no shim file, which also makes the test the real Windows-refusal witness. Alternatively, mark the method `[NativeLinuxOnly(...)]` with its CARD-1613 policy row. The first option is better.

**B-3. The OS-witness checker refuses (exit 2), and the declared production factory is a test-private stand-in.**
- Where: `PostLandEarlyWarningTests.cs:243` and `:245` (interpolated `$"..."` literals). Also `:14-15` and `:393-402`: a private `PostLandEarlyWarningScript.ResolvePostLandPlatform`, called at `:187/:197/:207` with its result discarded. Its doc comment says it "names the production script function ResolvePostLandPlatform", and no such function exists in `scripts/`.
- Failure: `check-os-witnesses.ps1` exits 2 at the tip. In a scratch clone with only those two literals rewritten as concatenation, the checker gets past lexing and lints the witness. It passes only because the fake class supplies the `productionType`/`factory` tokens.
- Why: `docs/testing-and-build.md` "OS branch witnesses" requires Code to run the checker. Exit 2 is invalid input, so OS verification is incomplete under D-2. A seam or mock "cannot replace" the production object.
- Fix: rewrite the two literals. Delete the stand-in class, its three calls and the false comment. Declare the witness against the real script process: the `pwsh -File scripts/post-land-early-warning.ps1` start, with the absent/empty/value `Environment` setup lines as setupAssertions. Rerun the checker to exit 0 and report its lines.

**B-4. The one-lane bound is check-then-act with a window of 20 s or more, so two starts run two lanes.**
- Where: `Get-PostLandDecision` checks `lock.json` (`lib:768`). The child then re-runs the whole decision (selector plus census, about 20 s on the real tree: `-Plan` measured 19.97 s). Only after that does it write the lock (`lib:865`). The parent's `lane-started.json` detach check (`entry:96-101`) is never cleared, so after the first run it passes at once.
- Failure, probe 3: two starts 4 s apart on one tip. Both children leased and ran `dotnet build tests/Antiphon.Tests` (parents 25710 and 25767), then both shards. That is two leases and two concurrent builds in one checkout's native `bin/obj`.
- Why: this breaks D-4/D-5, the card's "bound it to one shard set at a time", and the one-build-per-worktree rule.
- Fix: the child takes the lock atomically first (`FileMode.CreateNew`). If it exists with a live pid, the result is `skipped-busy`. A dead pid is replaced. Hold the lock for the lane and remove it in `finally`. The parent waits for a per-invocation marker (a nonce or child pid), not for a file left by a previous run.
