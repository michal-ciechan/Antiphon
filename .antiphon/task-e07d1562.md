## Changes and failure policy

`server/Infrastructure/Agents/SessionRunner/SessionRunnerEventPump.cs` gives a
held event one offer through the normal dispatcher, with a monotonic deadline and
linked host signal. `SessionRunner:HeldEventDeliveryTimeoutSeconds` defaults to
3 seconds and must be positive (`server/Application/Settings/SessionRunnerSettings.cs`).
An already-stopping host gets that initial offer before its cancellation is
propagated; passing an already-cancelled token first would reject non-replayable
output immediately. Registration observes cancellation racing the offer as well.

When an asynchronous consumer has not completed delivery at host cancellation or
the deadline, the pump stops waiting, warns once with an abandonment count, and
unwinds the iterator for shutdown/reconnect. It retains the callback's separate
service scope until that task settles and observes late faults. There is no held
output replay queue; retrying an uncertain publication can duplicate accepted
output. Therefore this attempt is explicitly abandoned. Durable transcript data
can still recover through the existing later catch-up. This is a bound on the
asynchronous preservation wait, not arbitrary synchronously blocking callback
code, successful-path callbacks, all snapshot persistence, or recipient delivery.

Catch-up checks cancellation after each awaited sync and again at pass completion,
so the runtime's swallowed final-pull cancellation enters this same preservation
path rather than resuming normal dispatch with a cancelled token. Success/throw
paths retain their existing ordered iterator flow. The DTO comment and both plan
documents now qualify delivery claims; normal S0 callback obstruction is unchanged.

New `tests/Antiphon.Tests/Application/SessionRunnerHeldEventDeliveryTests.cs`
uses actual HTTP parsing, runtime and pump, a non-cooperative gated event bus,
FakeTimeProvider and a held final transcript request. It drives cancellation or
fake time with no sleeps. Real-time waits are outer hang guards; the unreleased
consumer gate has no other completion path. Teardown releases and joins retained
delivery scopes before disposing the provider, including baseline-red outcomes.
Existing T01 source is byte-for-byte unchanged from ff561103; no assertion was
weakened and no existing timeout was widened.
