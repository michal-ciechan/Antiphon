## Per defect or finding

- **D1 (P1): stale worktree pointer.**
  - `<common>/worktrees/*` is scanned directly; `git worktree list` is no longer used.
  - Each admin directory is classified, and its refs, HEAD and logs are read. Its common directory must be the audited one (`git-dir-layout`).
  - The checkout's files are inspected only when both pointers name each other. Otherwise the index must equal that directory's HEAD (`diff-index --cached`). Staged bytes refuse `RecycleWorktreeDirty` with `check=stale-index`.
  - A stale or prunable admin directory whose index is clean passes.
  - A registration outside the volume refuses `worktree-confine`.
  - A non-bare common directory with `core.worktree` set refuses `core-worktree`. This is added hardening.
  - Red proof: at c3b0381f, `stale-pointer-staged` (Review's exact shape) passed and `pruned-path-staged` and `stale-linked-published` refused `worktree-path`. Three mutants turn them red: removing the admin loop, making the stale-index check a no-op, and trusting one pointer direction. Removing the confine line turns `linked-outside` red.

  - In a checkout with an index, ignored files are not protected work and are not audited.
  - The ignore rules are the audited repository's own. A file hidden by an ignore rule is accepted by design.
  - Tracked files (also under an ignore pattern), staged entries and untracked files that are not ignored stay protected. Assume-unchanged and skip-worktree entries still refuse.

  - Pins: `ignored-build-output` passes. The `status --ignored` mutant turns it red. `ignored-tracked-modified` refuses dirty; it is a control. Both behaved the same at c3b0381f, so they pin the decision rather than detect a new defect.
