On cancellation, `Settle(null)` runs and then the exception is rethrown. `Settle` enqueues the claim with no liveness stamp (the status filter is unchanged, same as the not-live path), removes completed pending state, stores the remainder, and arms the debounce. The pump still observes the cancellation. `AgentSessionRuntime.ObserveOutputAsync` already catches that exception; that swallow is unchanged.

Any other exception from the read is logged and then takes the same null-stamp enqueue.

Keys are the target only, so releasing the shared key would let the next chunk deliver the first mention again. `ChannelWriter.TryWrite` returns false when the channel is full and still logs `CommandDropped`. That full-channel drop is unchanged.

The suspected version collision after `TryRemove` (a new remainder state at version 1 matching an in-flight debounce that also expects version 1) did not fail a test. The assigned cancellation leaves an empty remainder, so the old debounce sees the state gone. Left as-is.
