## Defects

**D-1 (high, false-green by OS substitution). Where:** schema `capability.platform` enum `Any`; validator rules 4 and 5 ("the agent may choose ... equivalent eligible targets"); `linux-projects` target.
- **Failure:** the catalog marks a portable obligation in a required RC suite (for example `scripts` or `antiphon` Unit) as `Any`. The planner places it on `linux-projects`, where it passes. The validator accepts it because capability is satisfied. The RC graph then reports that leaf green without any Windows execution. Many classes are red only on one OS (see the memory list of Linux-only reds, and the reverse also exists).
- **Why:** the plan's prose says "do not redirect Windows obligations to Linux", but no validator rule ties an obligation to the platform of record for its profile. The plan also never says which obligations a Linux target owns in an RC graph, or which `profiles.rc.exclusions` and platform-limited rows apply there.
- **Fix:**
  - Every required leaf carries `platformOfRecord`, taken from the policy profile, not from the agent. For RC that is Windows.
  - `Any` is legal only for obligations whose profile defines them as platform-agnostic, or for additive diagnostic leaves that are excluded from the RC verdict.
  - The validator rejects a required leaf placed on a target whose bound observed OS differs. Key this on the binding's OS, not the declared capability.
  - State Linux's RC role explicitly: additive and diagnostic, or a named Linux profile with its own exclusions.
  - Add an "Any-placed Windows obligation" arm to V-3.

**D-2 (medium, operator priority (c) not implemented in the default). Where:** "Default smart ordering", step 3.
- **Failure:** the operator's third priority is "Affected lanes only since last rc run". In the default Full mode, step 3 orders all remaining passed work by lane, then frontier, then chunk ordinal. Affected status never influences order. Only the non-credit Affected mode uses it, and it then skips rather than orders. So with the defaults, a lane changed since the last rc run waits behind unchanged lanes.
- **Fix:** in Full, split class 3 into 3a (affected since the source of the selected history run, using `rc-project-selection` closure at both commits) and 3b (unaffected). Skipping unaffected lanes stays non-credit and is the operator's decision (see Q3). Also define "since last rc run" as the selected history run's `sourceSha`, not the last green receipt. Add to V-5.

**D-3 (medium, frontier undefined under repacked membership). Where:** step 2 "contiguous canonical pass frontier", step 3 "position after its proven contiguous frontier (wrapping)", and the A1–A4 example.
- **Failure:** between runs the packer regroups because of cost-table or discovery changes, new tests or prefix-collision splits. Old A2 (failed) is now split across new A2 and A3, and new A2 also holds passed members. The plan says chunks with any never-completed member are class 2, and uses the oldest member completion. It never says how the frontier is computed in current-chunk terms. It also says "contradictory historical membership disables history globally". An implementer could read ordinary repacking as contradictory, which would silently disable failures-first on most candidates.
- **Fix:**
  - Define the frontier only in current membership: the longest prefix of current lane chunks whose every member UID has a bound pass in the selected run.
  - Define "contradictory" narrowly: one historical UID bound to two distinct terminal outcomes, or one old chunk with an unbindable member list. New, renamed or moved UIDs are never contradictory.
  - Add a repacked-membership fixture to V-5 (split, merge and move) that asserts the launch trace.
  - Note that class-3 ordering of already-passed chunks has no safety meaning, so keep it simple, or drop the wrap.

**D-4 (medium, a known failure is demoted below unfinished work). Where:** step 1 ("failed ... in the prior run of this line"), the history table's terminal-aborted row, and "Select the explicit last closed attempt".
- **Failure:** run N fails classes F1 and F2. Run N+1 is cancelled (a common outcome for 15–23 h Fulls) after re-running only F1, which passes. Run N+2 takes N+1 as history. F2 was planned but not started, so it is class 2, sorted by last completion (N's time) behind every never-completed chunk. F2 is a known red that the operator wants first.
- **Separate gap:** if N+1 is dead and unclosed, nobody is named to write the "separately recorded supervisor-aborted terminal observation". The plan doesn't say whether the selector then uses N (dropping N+1's progress) or falls back to Full/Original.
- **Fix:**
  - Class 1 is every obligation whose latest bound terminal outcome across the lineage index is failed, timed-out or errored. Inconclusive goes to class 2. A later bound pass clears it.
  - Define the selector when a newer attempt is unclosed: use the newest closed attempt plus the unclosed attempt's valid committed prefix only as unfinished hints.
  - Name the writer of the aborted observation (the next controller, at admission, from the dead owner's prefix).
  - Add the N/N+1/N+2 trace to V-4/V-5.

**D-5 (high for S14, contract conflict). Where:** "Co-located native targets share one host supervisor ... consume a private graph-bound inherited-lock context ... through the existing continuation contract", and S14's change to CARD-1545's `scripts/run-live-lane.ps1`.
- **Failure:**
  - The existing continuation path at `release-gate.ps1:398-411` requires `existing.lane == $Lane`. The lane is `rc` or `master` (`nightly-run-impl.ps1:208`), along with run ID, PID and start time.
  - A live-claude adapter that presents its own lane gets `shared-hop-identity`. To pass, it has to impersonate the `rc` lane and run ID.
  - CARD-1545 (latest 4e1e6106, D-7 and its Execution section) makes `run-live-lane.ps1` validate "still-held native-lock owner" for its own run, with "busy means deferred". It has no inherited-entry contract, and the 1545 plan never references this graph plan.
  - So S14 changes another in-flight card's admission contract and the lock primitive without either owner's plan saying so. "No public bypass switch is added" while a new private bypass is added is the kind of seam Review would reject.
- **Fix:** for now, keep live-claude out of the RC graph (D-10 too). When it is added, choose one of two approaches:
  - (a) Make it a separate serial phase on the same host that acquires the lock in its own right, as 1545 D-7 intends.
  - (b) A reviewed CARD-1545 amendment plus a `release-gate.ps1` change that defines a typed graph-continuation lane, with its own witnesses.

  S14 must not be commissioned before that amendment exists. Add a V-8/V-17 arm in which a foreign-lane continuation is refused.

**D-6 (medium, contradicts failed-first S1/S2). Where:** "Previous-run source and fallbacks" and "Composition".
- **Failure:**
  - **Two history sources.** Failed-first D-4/D-7 uses an explicit exporter file (`antiphon-nightly-prior-failures-v1`) with `-PriorFailuresPath` and `-PriorFailuresDigest` forwarded across hops. The graph auto-selects from a new lineage run index. That gives two history readers and two trust models for the same failures.
  - **Contradictory unresolved-membership rules.** Failed-first D-5 keeps observed classes and prints `unresolved[]` (the known group-105 case) in Full. The graph's "unresolvable ... membership disables history globally" would turn failures-first off for exactly that real history. S2 and the graph path would then order the same candidate differently.
  - "Do not revive PriorFailureSweep/Partial authority" reads as though Partial were abandoned, but failed-first S4a/S4b (nightly-only, non-credit) are still planned.
- **Fix:**
  - The graph consumes S1's exporter and resolver as its class-1 source, and its lineage index adds only age and unfinished data.
  - Adopt D-5's partial-uncertainty rule: keep resolved classes and display `unresolved`.
  - Say plainly what S2 becomes: the legacy non-graph scheduler, unchanged. S3 is a hard prerequisite of graph S11. S4/S5 stay nightly-only diagnostics, independent of the graph.
  - Re-anchor to S2 at 0f4d90b8.

**D-7 (high, retry-to-green undefined). Where:** D-7/D-8, "allow a new explicit attempt only after joining custody", and the verdict paragraph.
- **Failure:** attempt 1 of chunk X is red. The operator, or an orchestrator acting on "new explicit attempt", submits attempt 2, which passes. The verdict rule ("all required leaves must have verified ... passing execution") does not say which attempt counts. A latest-attempt reading turns a flaky red green inside a Full run. The plan forbids only automatic retry.
- **Fix:** a new attempt is allowed only for inconclusive-without-receipt, never after a bound red. Any red attempt is final red for that leaf in that run. The verdict lists every attempt. Add a red-then-green attempt arm to V-9 (resume) and V-16 (verdict).

**D-8 (medium, one discovery failure blocks every target). Where:** "Preparation before a complete test graph exists" ("Discovery failure yields incomplete qualification with no executable graph").
- **Failure:** the Linux project's discovery, or the Windows E2E prerequisite (Playwright or client build), fails. The run then gets zero test execution on every target for the whole window. Today's legacy path keeps E2E-prerequisite failure per-suite and continues. The barrier couples independent targets, which defeats per-target parallelism.
- **Why:** global conservation does not need it. A failed suite can be a sealed, required, inconclusive group node, and the run stays non-green.
- **Fix:** seal the execute graph with a per-suite `preparation-failed` obligation node. Run every independently prepared suite and target, and keep the run non-green. Keep the S2 barrier semantics only for the legacy opt-in path. Add a V-2/V-11 arm.

**D-9 (medium, commissioning owner unassigned; touches the human-only area). Where:** "Rollout" and the final paragraph ("commission host transport and private supervisor forwarding/readback", "obtain the missing private supervisor source/launch record").
- **Failure:** nothing assigns an owner. An orchestrator could commission a Debug or Code task to read or forward the private supervisor under `C:\Antiphon`, or to enroll SSH host keys and credentials. Agents must not touch either.
- **Fix:** name the operator (human) as the sole owner of:
  - the private supervisor source, launch record and forwarding change;
  - SSH host-key and credential enrollment (agent-credentials custody);
  - worker-entrypoint deployment on the Windows host;
  - the activation window.

  Agents may produce only a recipe and the provider-free native witness S16-W, which uses the Windows-pinned agent worktree and never `C:\Antiphon\releases` or the live supervisor. Q6 below offers a transport-free first step.

**D-10 (low-medium, live-lane reuse inside Full is contradictory). Where:** "Full explicitly ignores lane skips and reuses no results" versus the rendered node "Live Claude: execute or receipt reuse"; also D-6.
- **Failure:** a Full graph with a live node either always re-spends quota, overriding 1545 D-6's pending bounded reuse, or reuses inside Full against its own rule.
- **Fix:** live-claude is not a Full roster leaf. It is a separate additive obligation whose reuse is governed solely by 1545 D-6 and S3, and it is absent from the graph until 1545 S3 activation.

## Advisories

- **A-1:** Add a disappearance census. UIDs in the selected history roster but absent from current discovery must be explained by deleted or renamed source. Otherwise flag them, because validator and planner otherwise share one discovery oracle.
- **A-2:** On an invalid agent proposal, fall back to deterministic Smart (validated) before Original. Original only when deterministic Smart is itself invalid.
- **A-3:** Validator rule 5 plus a total stable key leaves the agent no ordering discretion. Say so plainly (see Q2).
- **A-4:** Strict lineage ancestry is credit-grade strictness applied to an ordering hint. At a new `rc/` cut, the previous line's run is not an ancestor, so the first run of each line loses failures-first. Allow cross-line history for ordering only, never reuse (Q1).
- **A-5:** CP budgets of 7–8 min are under the recorded loaded build. 413 s plus a 210 s body bound is about 10.4 min. Use about 11 min estimates, and run `checkpoint import --plan` on the table in S1.
- **A-6:** The schema location `scripts/schemas/` is new. The repository already uses `docs/schemas/`.
- **A-7:** S11, S12, S13, S16-W and S17-L must carry `testing-and-build.md#os-branch-witnesses` declarations. Windows OpenSSH's default shell quoting is the native argv witness (V-17).
- **A-8:** Linux N=2 on one host shares one Postgres (`127.0.0.1:54329`). Schema isolation does not bound connections; 53300 too-many-clients has occurred. Add a connection-budget resource key.
- **A-9:** Same-run resume after stale-lock recovery must re-verify build output bytes, not just a build-receipt digest. The checkout may have changed under NoSync.
- **A-10:** Daemon or Windows-side entrypoints that might run under Windows PowerShell 5.1 must stay ASCII-only.

## Answers to the brief's questions

1. **False green or dropped node.** Concrete scenarios are D-1 (OS substitution), D-7 (retry-to-green) and A-1 (shrunken discovery). Planner omissions, fingerprint skips in Full, stale history and the overlay are contained by set equality, "Full rejects every skip", ordering-only history and V-16.
2. **Ordering.** (a) is implemented, but undermined by D-4. (b) is finite: one attempt, frozen admission and age carried across cancels, so it does not starve old work. (c) is missing from the default (D-2). Repacked frontier: D-3.
3. **Contention.** Windows=1 is enforced by the validator, runtime counters and the native lock, not by convention. Linux and Windows run on separate physical hosts, so the build slot, runner and DB are host-local and do not contend across targets. Within a host, see A-8. Recovery: controller restart reattaches, and a dead native owner needs explicit stale-lock recovery (sound). A-9 still applies.
4. **Consistency.** D-5 (1545 lock), D-6 (S1/S2) and D-10 (1545 reuse). S2 remains the legacy path. Failed-first S3 gates graph S11.
5. **Slices and checkpoints.** All 17 slices fit 30–60 min. S1–S10 and S12–S15 are portable on server2. S11 waits for failed-first S3. S16-W needs `-Platform Windows`, and S17-L is Linux-native. All 18 CPs use exact single-method filters; namespaces are verified (`Antiphon.Tests.Scripts`, and `Antiphon.Tests.TestHelpers` for CP-12). Every new CP can go red. CP-12 is a regression guard, not a new red. The closed list is fine apart from A-5.
6. **Commissioning:** D-9.
