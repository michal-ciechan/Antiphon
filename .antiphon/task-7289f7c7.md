## D-1: ConflictFileSummary splits a surrogate pair at the name clip

- **Where:** `server/Application/Services/AgentTaskLandingProtocol.cs`, the new `ConflictFileSummary`: `file[..(ConflictNameMaxLength - 3)] + "..."`. The final cut `detail[..MergeRoleDetailMaxLength]` in `MergeRoleDetail` is also a raw char cut. It only fires on a pathological ref, so this part is an advisory.
- **Failure:** take one conflicted path longer than 200 characters with a non-BMP character (an emoji) whose high surrogate sits at index 196. The protocol reads names with `git diff --name-only --diff-filter=U -z`, so non-ASCII is not octal-quoted. The summary then ends that name with a lone `\uD83D` and then `...`. I probed the built `Antiphon.Server.dll`: output len=200, char196=0xD83D, char197=0x002E. Npgsql's `NpgsqlWriteBuffer.UTF8Encoding` has `EncoderExceptionFallback`, and strict UTF-8 encoding of that string throws `EncoderFallbackException`. The Conflicted event (linear path) or the LandRefused/Warning event (Merge-role path) then fails at SaveChanges, the same shape as the 22001 that D-1 fixed. Before this diff the same single path was joined whole and stored fine, so this is a regression in the new lines.
- **Why:** the repo already owns this rule. `ColumnText.Clip` ("Never splits a surrogate pair... handing one to Npgsql trades an oversize failure for an encoding failure") and `ColumnTextTests.A_surrogate_pair_is_never_split` pin it. The new helper clips without it.
- **Fix:** do not cut after a high surrogate in the name clip. Either step the cut back one when `char.IsHighSurrogate(file[cut - 1])`, or reuse `ColumnText.Clip(file, ConflictNameMaxLength)`. Note that Clip uses a one-character ellipsis, so update the existing test's `"..."` expectation. Apply the same guard to the `MergeRoleDetail` hard cut and the `ConflictFileSummary` final cut. Add a red-first unit case with an emoji straddling index 196/197 that asserts no lone surrogate (for example, `new UTF8Encoding(false, true).GetBytes(summary)` does not throw).
