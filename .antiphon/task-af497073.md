## D-1

`WindowsReadStream` derives from `Stream`, holds the caller-owned `SafeFileHandle`, and does not dispose it. It does not construct a `FileStream`, so the handle is not bound to the thread-pool completion port. The hEvent low bit is not set. `OpenStream` is `OperatingSystem.IsWindows() ? new WindowsReadStream(handle) : new LinuxReadStream(handle)`. The Windows type and `WindowsOverlappedRead.Read` are `[SupportedOSPlatform("windows")]`. `LinuxReadStream` stays a `FileStream`.

## D-2

After `CancelIoEx`, `GetOverlappedResult(..., true)` returns before `CloseHandle`, `pin.Free`, and method return. A cancelled token throws `OperationCanceledException` and does not advance the offset. If that wait never returns, the finally block does not run, so the dedicated `checkpoint-file-read` thread keeps the buffer, event, and frame. The 100 ms bound stays only in `ReadBudget.Run`. The 3 s silence window and the overall budget are unchanged. There is no `WaitForSingleObject(ev, 100)` on the I/O thread.

## D-3

A clean EOF is accepted only when the bytes read equal the inspected size and a re-inspect of the retained handle shows that size unchanged. Otherwise both copies throw `InvalidDataException` with `read-truncated: {total} of {metadata.Size} bytes; retained size {observed}`, which `ReceiptFile` wraps as `receipt-read-refused`. An empty file (size 0, total 0) is still accepted. The first stalled zero is still retried once. A prompt zero of a nonempty file is refused. A successful zero-then-bytes retry stays accepted. Accepted clean EOF re-inspects, so those success paths inspect twice. A mid-file stall still inspects once.
