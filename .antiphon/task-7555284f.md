## D-2 (blocker): the CP-merge-subset-e2e row as documented always ends RED exit 2 on Linux and poisons the next E2E build

- **Where:** docs/orchestration-loop.md, Merge process table, row `CP-merge-subset-e2e`. Root cause: `server/appsettings.json:362` has `Delegation:CheckInterpreterWorkingDirectory = C:\logs\antiphon\check-interpreter` (9785c4b1e8, 2026-08-16). The E2E fixture does not override it. On Linux the in-process server boot creates one directory with that literal backslash name inside the test cwd, which is the row's output `bin-merge-e2e/`. It contains CLAUDE.md and .claude/settings.json.
- **Failure:** at the reviewed SHA, `run --plan <extract> --rows CP-merge-subset-e2e` (run 20261108-154318-ff17) gave `CHECKPOINT ... executed=5 passed=5 failed=0`. The verdict was still `RED exit=2 reason=refused: output-ledger-mismatch; left in place: .../bin-merge-e2e/C:/logs/antiphon/check-interpreter`, with outputs `refused/kept`.
  - **Pre-existing:** the same one-row ContractSnapshotTests plan in a detached worktree at master 7624fb682 (run 20261108-155045-496c) gave 5/5 and the identical RED exit 2 refusal.
  - **Worse:** while that residue stays, the next E2E build in the same worktree fails with `MSB3552: Resource file "**/*.resx" cannot be found` (run 20261108-155930-87d5, build=failed).
  - Because of this, a Merge on server2 can never get a green receipt for the row, and validate refuses the whole run. The rc-cut gate ("does not push that ref while the row is red") either blocks every cut or trains operators to ignore red.
- **Fix (minimal, verified):** add an `Environment` column to the table. For `CP-merge-subset-e2e`, set `Delegation__CheckInterpreterWorkingDirectory=<absolute path outside the repo>`. I tested this with a scratch path (run 20261108-160503-ece2 at cfefd4b64): `executed=5 passed=5`, `outputs: deleted bin-merge-e2e-env2/`, `verdict: GREEN exit=0`, and `validate --expected-source-sha cfefd4b64...` gave `CHECKPOINT SOURCE VALID rows=1`, exit 0. The directory was created at the redirected path.
  - Untested alternative: `Delegation__CheckInterpreterEnabled=false`, the same setting DistillerCanaryOptions uses.
  - Pin the Environment cell in MergeHighRadiusSubsetTests.AssertRows, so that dropping it goes red.
  - The real fix is in the fixture. AntiphonAppFixture should set `Delegation:CheckInterpreterWorkingDirectory` to a fixture temp dir. That needs a separate card (pre-existing, affects every Linux E2E checkpoint row).
