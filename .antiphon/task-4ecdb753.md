## R3: an escaped project directory is decoded as a separator (fail-open, reachable at the tip)

- **Where:** `scripts/audit-land-verification-graph.ps1`, `Resolve-ItemPathText`, `-DirectoryPropertiesOnly` branch (lines ~842-852 at e6ac1c606). Repair 8 rewrote `$part = $root + $part.Substring($directory.Length)` and then calls `ConvertFrom-PercentEncoding $part`, so `$projectText` (the repo-relative project directory) is percent-decoded along with the value.
- **Failure:** take a project at `server/a%2Fb/App.csproj` (the folder name is the literal text `a%2Fb`) with `<PackageReadmeFile>x.json;$(MSBuildProjectDirectory)/../../docs/guide.md</PackageReadmeFile>`. That is exactly R2's shape. fd20e8dcc refuses it with `PackageTags/PackageReadmeFile -> docs/guide.md`. f8f3233f3 and the tip return `-Update` exit 0 with count=2. The single-part form `$(MSBuildProjectDirectory)/../../docs/guide.md` and the lower-case `a%2fb` spelling behave the same. The audit reads `server/a/b/../../docs/guide.md`, which is `server/docs/guide.md`. Control: a real `server/ab/c/` directory is approved at all three versions, which is correct.
- **Real MSBuild** (build-slot `dotnet msbuild -getItem`, no SDK, no restore, lease 2526c07a): from `server/a%2Fb/App.proj`, `<P Include="$(MSBuildProjectDirectory)/../../docs/guide.md"/>` (through a property) gives FullPath `<root>/docs/guide.md`, the root docs. MSBuild stores `MSBuildProjectDirectory` escaped and decodes it once at use. `$(MSBuildThisFileDirectory)` is not escaped: the same layout gives `<root>/server/docs/guide.md`, which the audit matches, so the ThisFile form is an over-refusal that was removed, not a finding.
- **Why it is a finding:** fd20e8dcc refuses it, the tip approves it, and real MSBuild selects `docs/guide.md`. Repair 6's D-33 introduced it by decoding after the root is spliced in. Repair 8 leaves it reachable, because it rewrote this splice and kept the decode over the root. For values it is the same consumer class as R2. The item `Include` form still refuses through the markdown-document rule.
- **Fix:** splice `$(MSBuildProjectDirectory)` escaped, as MSBuild does (`%`->`%25`, plus `;`, `*`, `?`, `$`, `@`, `'`), so the one decode restores the literal directory. Leave `$(MSBuildThisFileDirectory)` unescaped, as MSBuild does. Apply the same rule in `Expand-Candidates` (the full expansion) and in the Import consumer. A simpler fail-closed alternative: refuse any definition file whose tracked path contains `%`. No tracked file has one, and `-Check` count=57 would not change. Witness: the three shapes above refuse naming `-> docs/guide.md`, and the `server/ab/c` control and the ThisFile form are approved. Each outcome must be confirmed with real MSBuild first.
- Not checked: whether an `Import Project="$(MSBuildProjectDirectory)/..."` from such a directory follows a different file than MSBuild does. Cover it in the fix.
