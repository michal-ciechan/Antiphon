## Implementation and verification design

`TaskParkPublicationService` atomically stores Pending sync, the exact published
SHA and initial due time when accepting a remote publication. Local publication
remains NotRequired. `BlockedTaskSyncRecoveryService` reads at most 32 due debts,
claims each under the task lock, persists attempts and 1/2/4/5-minute capped due
times, runs Git outside the transaction, and conditionally saves the result against
the unchanged episode/revision. Bad debts cannot end the sweep. A restart reads the
same durable obligation; disabling new parking does not disable debt recovery.

`RemoteWorkspaceService.SyncParkedAsync` uses the desktop endpoint captured in the
progress baseline, the exact park ref and immutable SHA. The runner's publication
endpoint may differ. This recovery never publishes the mirror and tries a busy
repository lease once per due pass. Existing settlement lease budgets are unchanged.
Changed/unknown endpoints, moved/missing refs, dirty/sequenced/divergent desktop
source and changed episodes hold safely. Ready commits before dashboard invalidation.
The service has no settlement, approval, release or provider-launch dependency.

The dispatcher has an independent scoped sync sweep, registered by Program.
Task detail exposes the latest same-attempt `ParkSync` projection; attention includes
sync state/source/readiness alongside release debt and retains Pending/Held debt
beyond the usual release age. The runtime-invariants owner documents this contract.

`BlockedTaskSyncRecoveryTests` uses actual Git repositories, production repository
leases, isolated PostgreSQL, actual publication/release integration and recreated
providers. Its two methods cover:

- V-15: real settlement exhausts the unchanged 120-second budget under a held lease;
  independently published clean source parks once with Pending exact-source debt;
  dirty independent publication still vetoes release. Restart plus parking-disable
  preserves the obligation, future due is skipped, later sync advances the desktop
  exactly once, and task GET/attention reflect Ready while the task stays Blocked.
- V-16: valid source versus advanced tip, changed endpoint, endpoint change between
  validation and exact-ref observation (asserting no fetch), unknown endpoint, dirty
  tree, sequencer, divergence, missing ref and changed episode. Immutable task/report,
  completion evidence, events, outcomes and notifications are compared before/after
  real recovery. Actual held leases demonstrate persisted 1/2/4/5/5-minute backoff
  across recreated services. Crash cuts after claim, Git and saved Ready recover via
  fresh task GET without minting approval. A malformed earlier debt does not starve
  a valid neighbor. The HTTP fixture enforces a test credential around the real
  AgentTaskService projection; it is not a live fleet or production-auth acceptance.

The new class is Integration/Slow, carries ProcessSpawnLimit, shares the MessageQueue
nonparallel lane and has a reason in slow-tests-allowlist.txt. Fixture changes provide
real remote/desktop topology, sync DI, runner park proof and recreated reservation
services. No assertion was loosened, timeout widened, or retry added to mask red.
