### D-3 (Medium): the mapping turns the canaries' own post-control assertions into INCONCLUSIVE
- **Where:** in `ClaudeRemoteControlAtStartupCanaryTests.cs:78-101`, Slash calls `RequireSlash`, which calls `RequireBridge`, which throws `bridge-unestablished`
  (`LiveClaudeStartupEvidence.cs:24-26,79-83`). Off and Slash call `RequireOff`, which calls `RequireSettings`, which throws `settings-unobserved` when the off session
  lacks a marker that the control had (`LiveClaudeStartupEvidence.cs:88-94`). Both are mapped by `LiveClaudeOutcome.cs:11,13`.
- **Failure:** suppose the same run's control established an owned bridge and all three markers. After settings-off, either `/remote-control` fails to arm,
  or `ApplyOff` drops the user setting source. The result is `SkipTestException("20 BridgeNotEstablished")` or `("20 ReadyTimeout")`, and S1b classifies it `20 setup-unclassified`.
  Before this round, both were Failed, which S1b classifies `1 assertion-failed`. CP-6's Slash and the V-22 retained-source check can no longer go red.
- **Why:** plan R-D-6 maps ReadyTimeout/BridgeNotEstablished to 20 "unless typed outage evidence or **independently demonstrated
  contract failure**". A completed control in the same run is that independent demonstration. Test design V-18/V-22 label these cases
  `slash-setup` and `20 settings-unobserved`, so the plan and the test design disagree. If the planner wants 20 here, this becomes an operator decision under D-11.
- **Fix:** once `RequireControl` has passed, raise an assertion (`InvalidOperationException("C1545 startup/...")`) when Slash fails to arm or the observed side
  loses a marker. Keep 20 only when the control itself lacks the bridge or markers. Add witness rows for both cases.
