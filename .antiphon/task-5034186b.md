## Brief items

1. Mutual exclusion. Two live sessions can never both hold `pg_try_advisory_lock(1743,1)`. After the holder's session dies (Postgres restart, `pg_terminate_backend`, host freeze long enough for the server-side keepalive to expire), the old process believes it holds the lease until its next 15 s tick; `EnsureHeld` then re-acquires on a fresh non-pooled session or, when another worker already holds the lock, throws and `OnTick` calls `StopApplication`. The bounded overlap is the tick (≤15 s) plus the Hangfire drain (`BackgroundJobServerHostedService.StopAsync` waits `ShutdownTimeout`, default 15 s) plus host shutdown. A paused-but-alive holder (GC pause, `docker pause`) keeps answering TCP keepalives from the kernel, so Postgres keeps its session and no second holder is admitted; a whole-kernel freeze longer than 60 s expires the session and the resumed process stops at its next tick. Stop-on-failure is enforced at the first failed re-confirm (stricter than the 60 s expiry), see A-1.
2. Shutdown order. `ReleaseWorkerLeaseWhenHostStops` registers `lease.Dispose` on `ApplicationStopped`, which `Host.StopAsync` raises after every hosted service's `StopAsync` returned (Hangfire 1.8.25 waits for the processing server there). Witness `Worker_lease_stays_held_until_hosted_services_finish_stopping` proves a contender is refused inside a hosted service's `StopAsync` and admitted after `StopAsync` returns. Dispose takes `_gate` (only the tick contends, and the tick waits on nothing else), disposes the timer, runs `pg_advisory_unlock`, closes. No deadlock; on a dead link the unlock costs at most Npgsql's 30 s command timeout plus a 5 s cancel connect (A-5). Hard kill: kernel FIN/RST, immediate. Host crash: ≤60 s (30 + 10×3) by the server-side `tcp_keepalives_*` the lease sets on its own backend.
3. Session lock semantics. The lease connection is `Pooling=false; Timeout=5` built from the EF string, so the session is dedicated and `pid = pg_backend_pid()` in the `pg_locks` check names the right backend. Dropping the keepalive `set_config` (Code PC-5, brief PC-4) leaves the backend on OS defaults (idle 7200 s) so a crashed host's lock lingers ~2 h and the successor is refused; `Worker_lease_sets_a_sixty_second_crash_expiry` reads the effective socket values through `current_setting` (the show hook reads the socket, not the GUC) and goes red on that mutant.
4. Error classification. `StartupFailure` walks `InnerException` for `PostgresException`: 28P01/28000 → authentication, 42501 → privilege, 3D000 → database does not exist, else not reachable; the original exception is attached. The message is constant text; Npgsql's connection and Postgres error texts carry host:port, user, database, never the password or connection string. Witnesses assert `ToString()` excludes the password on the unreachable, 28P01 and 42501 paths.
5. Witnesses. ## Advisories

- A-1 (design/doc, introduced) `HangfireWorkerLease.OnTick` stops the host on any `EnsureHeld` exception, including `StartupFailure` from `fresh.Open()` when Postgres is unreachable at a tick (`HangfireConfiguration.cs:484-499, 514-518`). A Postgres restart of a few seconds therefore has a (downtime/15 s) chance of turning into a server restart (docker path `restart: unless-stopped`; startup has no retry, so the container loops until Postgres is back). Safe for mutual exclusion, costly for availability, and undocumented ("When another worker holds the lock, the host stops" is the only stop the doc names). Suggest: retry the re-acquire until `CrashExpirySeconds` since the last confirmed hold before stopping, consider stopping the Hangfire server rather than the host, and document the behaviour either way.
- A-2 (correctness edge, introduced) `ReplaceConnection` takes the lock on the fresh session before the old session is closed (`:504-526`). If `SessionStillHoldsLock` returned false because the check query errored while the old backend is still alive (statement timeout, cancelled command, transient server error), the fresh `pg_try_advisory_lock` sees the process's own old backend and reports "another worker holds it", stopping the host. Close/terminate the old connection first, or compare the holder pid against the old backend pid before declaring another holder.
- A-3 (doc) The documented 15 s "longest without the lock" is the detection bound; the overlap with a successor is 15 s plus the Hangfire drain (15 s default) plus host shutdown. State the full bound in `docs/docker-stack.md`.
- A-4 (verification) The 60 s crash expiry is witnessed as effective socket options only; no test drives a silent peer to expiry. Note `tcp_keepalives_count` is unsupported by a Windows-native Postgres (reads 0); the Testcontainers image is Linux on every lane, so the witness is stable, but say so in the test name or doc.
- A-5 (robustness) `ReleaseConnection` on `Dispose` runs `pg_advisory_unlock` with the default 30 s command timeout; on a dead link `ApplicationStopped` can take ~35 s past the host shutdown timeout. Give the probe connection string a short `Command Timeout` or skip the unlock when the socket is broken.
- A-6 (test timing) `Worker_lease_is_reacquired_after_its_backend_is_terminated` and `Worker_lease_refuses_to_continue_when_another_worker_holds_the_lock` read `pg_locks` or re-acquire immediately after `pg_terminate_backend`; the terminated backend exits asynchronously. Green here (49 s row) but poll with a bound to remove the race under load.
- A-7 (test shape) `Program_releases_the_worker_lease_when_the_host_stops` and `Durable_hangfire_documents_the_lease_the_package_and_renames` pin source and prose text (15 fragments) inside the Unit class, the pattern CARD-1743 A-5 asked to isolate. Acceptable guards; keep them in a documentation test.
