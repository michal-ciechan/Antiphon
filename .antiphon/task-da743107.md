# Debug da743107: rc 0b05506b e2e-all-split-2, C467_V29 Batch2(residue-cleanup) receipt timeout

## Verdict
Harness issue (brief option c), made worse by load on the Windows host. Not a land stall in
residue cleanup. Fixed in test code only.

## Cause
- `ReceiptAsync` waits in `UntilProtocolAsync`. Its quiet window (60 s) renews only when a committed
  `protocol-git-*.json` record appears. `EvidenceGit.RecordAsync` writes one after each completed
  `ILandingGit` command (tests/Antiphon.E2E/Fixtures/LandDeliveryOptions.cs).
- At failure the operation was `Phase=Prepared Publication=Unconfirmed`. The last git command was
  `status`, and the request's LastProgressAt was the same instant. The Prepared branch
  (server/Application/Services/AgentTaskLandingProtocol.cs:294-338) runs `VerifiedLandWorktreeAsync`
  (rev-parse + `status --untracked-files=no` on the land worktree), then hands the work to the verifier.
  `AgentTaskLandService.cs:709-731`: PrepareAsync gives a ticket, R is released, and
  `VerifyPreparedAsync` runs. `VerifyWithObserverAsync` (`AgentTaskLandService.cs:1903`) takes a
  build slot from the owned runner, then runs a real `dotnet build --artifacts-path` of the owned
  repository. The fixture commits `Feature.cs`, so `LandVerificationPolicy` returns
  diff-requires-build.
- Neither the slot wait nor the build runs any protocol git, so the quiet window cannot renew while
  the verifier works. One verify longer than 60 s fails the receipt. This happens whatever the
  outcome arm: landed, already-present, residue-cleanup, retained and operation-refusal all build.
  residue-cleanup was just the case that hit it.
- The residue-cleanup code was never reached. Cleanup runs after PublicationConfirmed, and the
  failure has `Publication=Unconfirmed`. That rules out option (b).
- Measured timing: a cold verify build of the same owned project on server2 takes
  3.4 / 4.0 / 4.2 / 3.8 / 6.4 s (n=5, one lease each). On Windows the verify window ran past 60 s.
  Two possible reasons:
  1. Admission: the owned runner's broker refuses grants while available memory is below 6144 MB
     (`BuildSlotSettings.MinAvailableMemoryMb` default). It retries every 15 s and has no fallback.
     That is plausible on a host running a Full qualification.
  2. Execution: a cold MSBuild build on a loaded host.

  The remote evidence cannot tell these apart. On the desktop, grep
  `<evidence root>\server-logs\*.log` for `Landing verifier` / `BUILD SLOT` between
  08:04:05 and 08:05:05Z.
- The Linux run of the method that was asked for is impossible by construction. `InitializeAsync`
  begins with `OperatingSystem.IsWindows().ShouldBeTrue()` and needs ConPTY and fakegrok.exe
  (LandDeliveryFixture.cs:58-60). Nothing was run on the desktop.
