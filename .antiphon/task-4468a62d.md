## (c) Windows path comparisons (by reading the code)
- `full.StartsWith(_repo + sep, Ordinal)`: `_repo` is `GetFullPath($RepoRoot)`, and every project path and FullPath comes from that same string (`solutionPath = GetFullPath(Combine(repo, sln))`). Normalize already needs the same Ordinal prefix for every row, and the Windows real-repo approval pinned in the evaluation record depends on it. A drive-letter case, `\\?\` or other spelling that differs only fails closed (refuse).
- Copy set: `OrdinalIgnoreCase` on Windows. Git paths are `/`; docs paths are rewritten to `/`; the lookup turns `relative` into `/`. Case variants of copied files are not tolerated. The canary `File.Exists` check is case-insensitive on NTFS, so it backstops the copy-set lookup.
- Trailing dot or space: Windows `GetFullPath` strips it, so the path maps to the copied name and is refused. 8.3 short names are not expanded, but a pass-1-only row only comes from a glob (which returns long names) or a condition. A short-name docs payload is still refused by pass 1 or as a row only pass 2 has.
- On Windows, `tests\Antiphon.E2E\TestOutput\Logs\run.log` is in the repo, ignored, absent from the canary and has no reparse point, so it is tolerated. The gated cases do not depend on these comparisons (they refuse as rows only pass 2 has, or through the pass-1 docs refusal), so they still refuse.
