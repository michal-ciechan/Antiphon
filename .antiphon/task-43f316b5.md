## Defects

### D-1: the census grep misses valid `[NativeLinuxOnly]` spellings, and the fixture pins the miss

- **Where:** `scripts/test-rc-platform.ps1` `Get-C1323LinuxOnlyCensus`. The file prefilter is `$text.Contains('[NativeLinuxOnly(')`. The line match is `'^\s*\[NativeLinuxOnly\('`. In `Test-C1686_LinuxOnlyCensus`, the `$beta` fixture's `[Test, NativeLinuxOnly("not a marker line")]` on `Portable` is asserted not to count, in the `c1686-consistent-census-passes` set.
- **Failure:** I ran probes on the tip against a scratch copy of `tests/` with the shipped policy. Each probe added one marker with no policy row. Every spelling below compiles as a real marker, and for each the census returned `Ok=True` with no problems:
  - `[Category("Unit"), NativeLinuxOnly("x")]` on a class
  - `[Test, NativeLinuxOnly("x")]` on a method
  - `[NativeLinuxOnlyAttribute("x")]`
  - `[Antiphon.TestSupport.NativeLinuxOnly("x")]`
  - `[global::Antiphon.TestSupport.NativeLinuxOnly("x")]`
  - `[ NativeLinuxOnly("x")]`
  - `[NativeLinuxOnly ("x")]`

  The reflection witness (`HasDirectMarker` uses `AttributeType == typeof(...)`) sees all seven as markers, so the two checks disagree. The reverse case also fails: a correctly rowed marker written in one of these forms gets a false `row-without-marker` red from the census while the compiled witness is green.
- **Why:** the brief makes "a marker spelling the grep misses" a defect. The docs added in 4282088c9 say the census "fails on a marker without a row", which is false for these forms.
  - Only the compiled `NativeLinuxPolicyWitnessTests` catches them. That class is in no selection set, so it runs only on Full or remainder selections.
  - Today the practical gap is narrow. All 69 markers in the repo use the canonical line form, and every marker file except two is unnamed (so it selects Full). The two routed docker files hold class rows that cover any new method.
  - The cost is still real: a stacked marker in any narrowly selected file escapes until a Full or Windows run. That is the CARD-1686 failure mode.
- **Fix:** fail closed rather than widen the parser. Any non-`//` line in a scanned `.cs` file that matches `\bNativeLinuxOnly(Attribute)?\s*\(` but is not the canonical line form becomes a problem such as `marker-noncanonical:<rel>:<line>`. Widen the prefilter to `NativeLinuxOnly` to match. Flip the `$beta` `Portable` fixture so it expects that problem, and add fixture rows for the `Attribute`-suffix and qualified forms.

  This leaves the census's job unchanged and only makes it fail on forms it can't parse. It also means the policy, the policy hash and the catalog hash need no re-record. It is a test-harness-only change in `test-rc-platform.ps1` and `ReleaseGatePlatformTests.cs` if the assertion count changes. Re-run `ReleaseGatePlatformTests`.
