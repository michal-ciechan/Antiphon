## Checked and safe (D-1 adversarial)
- **Parse.** `TryParseProcStartTicks` takes everything after the LAST `)` and returns fields[19], which is field 22 (state is index 0 = field 3). Checked on synthetic text: comm `a b) c) d` gives 888 (correct); a short line returns false; a negative value returns false. An independent sed/awk parse of a live process named `a) b) (c` gave starttime 1995897973. That is 19958979.73 s at CLK_TCK 100, against an uptime of 19958980.75 s and etimes 1, so it is field 22.
- **Read race.** There is no separate exists-check. ENOENT on the read maps to Absent, which is correct because the process is gone. EACCES and other IO errors map to Unknown, so the cache is kept. A zombie still has stat and keeps its cache.
- **Runner path.** `AssignOwner(host)` reads `/proc/<hostPid>` itself on Linux and ignores `_hostStartTimeUtc`. If the host dies before that read, the marker is pid-only: dead means swept (correct), and a reused pid means kept (a leak, never a deletion). Before the reassignment, the runner's own `pid@k` marker keeps the cache while the runner lives.
- **Markers and versions.** Old `pid` and `pid@wall` markers on Linux stay while the pid exists. The `k` prefix makes the master and fe5f054b4 parsers read new markers as Garbled, so they keep them.
- **Windows.** `OperatingSystem.IsLinux()` is the only branch selector. Windows still uses StartTime with the 50 ms tolerance. InvalidOperationException and Win32Exception now map to Unknown and keep the cache; before, InvalidOperationException meant dead.
- **D-2.** The stamp is current only when `0 <= age < 10 min`. The one-year-ahead witness is red at b4c07225d and green at the tip.
- **D-3.** Probe children and the checkpoint-tool child strip ROOT, and the class passes 13/13 with ROOT set. See D-1 below for the sibling classes.
- **Unresponsive flake.** That test is not touched by the diff. The supervisor's added work is one `/proc/self/stat` read at Install and one at Release, which `Process.StartTime` already did. Classed as the known load-flake class.

## Defects

### D-1 (blocker; incomplete repair of round-1 D-3): ROOT on the test host turns two D-1 marker witnesses red with no mutant
- **Where:** `tests/Antiphon.Tests/Scripts/ScriptHarnessLinuxOwnershipTests.cs:61`. It globs `Path.GetTempPath()` for the supervisor cache, but the supervisor child inherits the host's `ANTIPHON_PWSH_CACHE_ROOT` and creates the cache there. `tests/Antiphon.SessionRunner.Tests/C1793SessionPwshCacheTests.cs:52` asserts that the session cache's parent is `Path.GetTempPath()`, but `CreateOwned` uses `CacheRoot()`. The new paragraph in `docs/testing-and-build.md` says "a Mutation host may set it as well as the temp variables".
- **Failure:** Both tests were red at the unmutated tip with only ROOT added on the host. Supervisor_removes_... failed 1/1 twice. Each_pty_session_... failed with parent `/tmp/r6008/root3` where `/tmp/r6008` was expected. Both stop at a location assertion, before the `pid@k<ticks>` marker assertion. A Mutation stage that follows the doc would therefore record every marker or owner mutant as "killed" by these witnesses, which is invalid PC evidence. Round-1 D-3 was exactly this failure, in the sibling class.
- **Fix:** In both tests, compute the expected parent the way `PwshPrivateCacheTests` now does: the configured ROOT if it is set, else `Path.GetTempPath()`. Alternatively, strip ROOT in `LinuxSupervisorProbe`'s child environment. The other option is to make the doc recommend TMPDIR/TMP/TEMP only. Then re-run both classes with ROOT set.

## Advisories (cards; never hold the land)
- **A-1:** The L mutant (IndexOf in place of LastIndexOf) survives because no witness has a `)` in comm. The marker witnesses compare against the product's own `TryReadKernelStartTicks`. The parse is correct (see above), but add a pure `TryParseProcStartTicks` row with a comm like `(a) b) (c)`.
- **A-2:** On Linux an unreadable /proc is not "unknown". With no /proc mounted, or with hidepid=2 hiding another user's pid, the read gets ENOENT, which maps to Absent, which means dead, so the sweep tries to delete. Master's `Process.GetProcessById` uses kill(pid,0) and EPERM, so it kept the cache. Exposure is small: server2's /proc is `rw,nosuid,nodev,noexec,relatime` with no hidepid, .NET barely runs without /proc, and deleting another user's cache usually fails EACCES. Hardening: when the read is Absent, confirm with kill(0) or `GetProcessById` and return Unknown if the process is alive.
- **A-3:** A relative ROOT is accepted, resolved against cwd. A missing ROOT is created, which the doc states. The brief listed both as unusable. Deletion stays confined to the `antiphon-pwsh-cache-*` prefix, so this is not a hazard, but the behaviour should be documented or fail closed.
- **A-4:** Windows execution of the new and changed tests is owed to rc qualification and was not run here.
