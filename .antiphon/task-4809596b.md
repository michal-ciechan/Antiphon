## Reading

1. Nothing weakened. Every refusal before the change is still in place and still runs first:
   origin allowlist/scrub/shape, custody (reparse point), clock, `existing` (bundle or proof
   already in the proof dir), previous-proof header + recorded-hash check, ls-remote before vs
   show-ref, required objects, ls-remote after (snapshot), clock skew. The new guard hashes the
   staged copy against `$old[7]`, the EARLIER PROOF's recorded `bundle <sha256>` line, not a
   value worked out from the file. It is strictly stronger than before: the old code unbundled
   from the earlier proof path and later copied that path again, two re-reads after the hash
   check. Now the bytes are read once into scratch, hashed, unbundled and moved, so the bytes
   unpacked are the bytes published.
   - Move: `[IO.File]::Move($staged,$bundle)` (overwrite false). Same volume means an atomic
     rename. Across volumes .NET copies then deletes, and a failed move throws into the catch,
     which deletes the bundle when no proof file exists. A crash mid-copy leaves a bundle with
     no proof header. A later attempt in that directory refuses `existing`. Reuse needs a proof
     file plus a matching recorded hash, so a partial bundle is never trusted. The proof's
     `bundle` hash is taken from the final file in the proof directory after the move, as before.
   - Scratch: `GetTempPath()` + `c1609-host-` + a random GUID, made fresh for each attempt and
     removed in `finally`. On Windows that path is the per-user %TEMP% (about 80 characters for
     the bundle and its .lock). Copy uses overwrite false, so nothing planted can be reused
     silently. Unchanged from before.
2. The proof content is unchanged. The bundle path is not part of the bundle bytes. The reuse
   path copies the identical bytes. The header and file layout are untouched, so the host
   consumers (c1008-retirement.sh, c590-real.ps1) see the same names and content. The test
   asserts that the reused bundle's bytes are identical and that `list-heads` includes main.
3. The red test is real (mutant A). The new hash guard has no test (mutant B, advisory A-1).
4. PowerShell/Windows: `Join-Path` and `IO.File` are separator-neutral. Moving across volumes
   is fine, as above. The script is ASCII-only (grep). It is not a daemon or auto-start script.
