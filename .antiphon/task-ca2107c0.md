## Brief items

1. Buffer route versus session record (runner side). `RunnerSession.GetBuffer()` and `ToDto()`/`LastSequence` read the one `_lastSequence` field under the same `_gate`; pty output advances it in `HandleOutput` under `_gate`, so for pty both routes return the same value at the same instant. For herdr the single-session GET first runs `RefreshHerdrSurfaceAsync` (pane.get plus a pane.read that bumps the CARD-0164 content counter) and then reads; the buffer route reads without that fold, so its value lags until any fold: the `RunnerTerminalSession` exit watcher (`WaitForExitAsync`) issues a session GET every 250 ms for the life of every adapter-owned session, and every snapshot read (`GetSnapshotAsync`, used by `WaitForQuietAfterVisibleAsync`, Grok's `WaitForTurnCompleteAsync`, `VerifiedPromptSubmitter` evidence polls and `TryGetLiveSnapshotAsync`) folds as well. Bound while an adapter owns the session: about 250 ms plus one GET. Lag only delays the observation of a change, so quiet is declared later, not earlier; the post-Enter advance check has a seconds-scale `PostSubmitAdvanceTimeout`. This is exactly the production behaviour before `825296b0e` (CARD-1761 landed 2026-11-07 16:42Z): before that commit both readers were the buffer route on every backend. Delivery verdict: unchanged, transcript-confirmed UserPrompt (`TryGetLiveMetadataAsync`/`GetAsync` for metadata, transcript rows for confirmation). Watchdog: unchanged snapshot route. Behind/readiness: `ReceiptReadiness` uses `lease.Snapshot.LastSequence` from snapshot reads and `SessionHealthService` uses the live metadata GET; neither calls the changed readers. Not a regression; see A-1 for the one narrow caveat.
2. Cached route when a backend changes mid-life. The same session id can change lane only on a relaunch: `StartInteractiveSessionAsync` sets `previous.SessionBackend = agent.SessionBackend` on crash-restart and `AttachHerdrAsync` rewrites an existing row to Herdr. `RunnerTerminalSession._backend` is per adapter instance and re-captured at `StartAsync`/`AttachAsync`, so the terminal route is never stale. The runtime cache is cleared by `DisposeSessionAsync` (stop, kill and stall-detector paths) and process restart; the reconciler's phantom-close path publishes `SessionExited` without disposing, the same lifecycle as the sibling `_lastSequences`/`_manualTurns` caches. Bound of a stale entry: a pty session left on the buffer route pays one bounded ANSI-log read per poll and returns the same value; a herdr session left on the GET route pays the CARD-1761 cost and returns a fresher value. No wrong sequence is possible in either direction. Advisory A-2.

## Advisories (cards; none holds the land)

- A-1 Herdr sessions without an in-process adapter. After a server restart herdr sessions are not re-attached (`AgentSessionService` returns before `AttachAsync` for `SessionBackend.Herdr`), so no 250 ms exit-watcher GET folds the pane into `_lastSequence`; the manual-turn tracker's buffer-route polls then see advances only when some other GET or snapshot folds them (health, corroboration, operator views). First-delta detection can miss within `FirstDeltaTimeoutMs` and complete the manual attempt early, which removes it from the stall detector's `StreamingTurn` selection (the non-killing direction). Same as production before CARD-1761. Candidate fix: let the runner's herdr `GetBuffer()` fold a cheap pane.read, or keep a runner-side herdr sequence poller, and record the bound in `docs/session-runtime-invariants.md`.
- A-2 `_sequenceRouteIsPty` outlives a crash-restart lane change for the same session id (natural exit path does not dispose the runtime entry). Cost only, never a wrong value. Clear it on launch/resume for that id or key it by accepted generation.
- A-3 `CacheSequenceRoute` reads `_sequenceRouteIsPty[sessionId]` after `TryAdd`; a concurrent `TryRemove` throws `KeyNotFoundException`, swallowed by the caller's catch-all (returns the delta default for that poll). Return the local `pty` value instead.
- A-4 The watchdog witness's empty-screen half uses the tail `Press Enter to continue`, which matches the default `press-enter` rule; `SendInputAsync` then throws on the empty service provider and the watchdog's catch swallows it. The assertions are unaffected, but a non-matching tail would keep the witness on the read path only.
- A-5 Two wall-clock-bounded witnesses can flake under heavy load: `Card1766_Herdr_quiet_follows_the_buffer_sequence_not_a_flat_session_record` (80 ms quiet inside a 2 s cap) and the pre-existing `Card1761_Pty_output_wait_snapshots_only_when_the_sequence_moves` (needs two loop iterations inside 250 ms).
