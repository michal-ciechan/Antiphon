## Advisories (cards, not blockers)

- **A-1 Cross-process ticks.** The turn is per process and the cursor insert is not idempotent; before a second server process runs retention against the same runner (server2 server compose ships it on), serialise across processes (a Postgres advisory lock around the tick, or an upsert on `CandidateKey`). Today the phone-home eligibility check and the "do not run both servers" rule keep it to one process.
- **A-2 Run terminal state.** A failed or shutdown-cancelled background tick leaves the run with `FinishedAt` null and no failure row, and the 202 is answered before the row exists (brief 404 window; a kill switch flipped between the route check and the tick body yields a runId with no run at all). The previous request-bound route surfaced the failure as an error reply. Suggest stamping the run in the `catch` (fresh scope: `FinishedAt` plus a Deferred `tick_failed`/`tick_cancelled` row), saving the run before the 202 (or documenting `MaxTickMinutes` + `RequestTimeoutSeconds` as the give-up bound), and a hosted service that awaits `Background` with a bound on stop.
- **A-3 Preview still runs on the request.** `RunPreviewAsync` runs the DryRun tick under `RequestAborted`; a proxy timeout cancels it mid-tick (same shape as before CARD-1796; no deletion effect). Document `curl --max-time` or background it the same way.
- **A-4 Guard batch red.** Nine inherited failures (one lane-xor) at base and tip; land is not held, Debug b73aeb1d owns it.
