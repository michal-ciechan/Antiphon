## Check 2: telemetry wiring and the ReadLinux meaning

Intact. `HostLoad.Authority` named client, `HostAdmissionSnapshotClient` (`TryAddSingleton<IHostAdmissionSnapshotReader>`), `HostLoadCaptureService` singleton + `IHostLoadHistorySource`, both hosted services under `startSampler`, and the sampler constructor's `HostLoadCaptureService` argument are all present at the tip.

`ReadLinux` now returns `Reading(cpu, workingSet)` from `LinuxProcessFacts.TryCpu` and `TryWorkingSet` when trusted. Semantics match the previous `Process` reading:

- CPU: `(utime+stime)/CLK_TCK` from `/proc/<pid>/stat` fields 14/15, which is what `Process.TotalProcessorTime` reads on Linux; the 2-minute pid-reuse tolerance is applied from field 22 + `btime`, and a recycled pid yields `cpu == null` while the working set is still read, exactly as before.
- Working set: second `statm` field (resident pages) x page size. The telemetry original (`64bd6de842`) parsed the first field (virtual size); the integration corrected this to resident, which is the same quantity as `Process.WorkingSet64` (`/proc/<pid>/stat` rss). V-2's tolerance assertion against `WorkingSet64` executed green on this host, so the sampled value's meaning is unchanged.
- Fallback: `TryCpu` false (unreadable `/proc`) falls to `Process.GetProcessById`; a process that disappears between the two reads yields `Reading(cpu, null)` which the sampler reports as working set unknown. No fail-open onto another process.
