## R1 (regression): D-25 property-value check skips the whole value when any part carries `@(`, `%(` or `$([`

- **Where:** `scripts/audit-land-verification-graph.ps1`, `Assert-PropertyValuesAllowed`. This line now sits before the pipeline loop:
  `if (($value.IndexOf('@(') -ge 0) -or ($value.IndexOf('%(') -ge 0) -or ($value.IndexOf('$([') -ge 0)) { continue }`
  At `fd20e8dcc` the same test was applied inside `foreach ($part in $value.Split(';'))`, so it skipped only the part that carried the reference.
- **Failure:** one line is appended to `tests/Antiphon.Tests/Antiphon.Tests.csproj` and committed in a scratch worktree, then `-Update` is run. Each scratch worktree was a detached checkout of the SHA under test, and the change was reset after each run.

  | snippet | `fd20e8dcc` (repair 5) | `ad13d6cd3` (repair 6) |
  |---|---|---|
  | `<PropertyGroup><PackageReadmeFile>../../docs/guide.md</PackageReadmeFile></PropertyGroup>` (control) | exit 1 `PackageReadmeFile -> docs/guide.md` | exit 1, same message |
  | `...<PackageReadmeFile>../../docs/guide.md;@(None)</PackageReadmeFile>...` | exit 1 `-> docs/guide.md` | **exit 0, count=57** |
  | `...<PackageReadmeFile>../../docs/guide.md;$([System.String]::Copy(''))</PackageReadmeFile>...` | exit 1 | **exit 0, count=57** |
  | `...<PackageReadmeFile>../../docs/guide.md;%(None.Identity)</PackageReadmeFile>...` | exit 1 | **exit 0, count=57** |

- **Why it counts as found:**
  - It is a regression of existing behaviour that repair 6 introduced. The previously reviewed tip refuses these values.
  - Plan D-25 states the rule per `;`-part: "A literal `;`-part (no `$(` after the two directory properties, no `@(`, `%(` or `$([`, no wildcard)".
  - It is not among the Code report's five stated behaviour deltas. Delta (2) covers the whole-Exclude drop, which is safe because an Exclude only subtracts. No delta mentions this skip, and a skip in the refusal rule weakens the audit.
  - The CP-1 tests do not catch it.
- **Reachability, stated honestly:** I did not show a real MSBuild read of `docs/` through such a value.
  - Used as `<None Include="$(PackageTags)" />`, the include check still refuses it (`cannot resolve ... docs/guide.md;@(None)`), at both SHAs.
  - What weakens is the D-25 value layer, the cheap guard for values that the SDK consumes without an audited include.
- **Fix:** move the `@(` / `%(` / `$([` test into the `foreach ($spec in (Resolve-ItemPathText $value ...))` loop, applied to `$spec.Source`, so only the referencing part is skipped, as at `fd20e8dcc`. Add a table/C1409 witness, `<PackageReadmeFile>../../docs/guide.md;@(None)</PackageReadmeFile>` refuses with `-> docs/guide.md`, and move CP-1's expect if the method count changes.
