## Defects

### D-1: An empty matching receipt refuses cleanup retries (existing test now red)
- Where: scripts/c590-remote.sh, `c994_lookup_image` tail (`if [ "$saw_empty" = 1 ]; then return 2; fi`),
  reached from `case_retire_temp_containers` (`c994_lookup_image || c994_refuse TempContainerReceiptUnavailable`).
- Failure: RetiredTempContainerHostTests.C994_Absent_cleanup_is_idempotent fails at the tip and passes
  with the base script. The retry exits 2 with `DIAGNOSIS=TempContainerReceiptUnavailable`
  (`C994_TEMP_CONTAINERS removed=0 alreadyAbsent=0 outcome=refused`). The first cleanup of an absent
  temp writes a completed, non-dry-run receipt with `image:""`. The retry treats that receipt as an
  empty-image match and refuses.
- Why: the "empty matching receipt refuses" rule was meant for the retire-temp-runner audit gate. It
  also applies to the cleanup path, where an empty image on an absent temp is the normal result.
  The author's run list did not include RetiredTempContainerHostTests, although this branch edits that class.
- Fix: apply the empty-refusal (and D-2's mismatch refusal) only on the C1008 audit lookup. For
  example, pass a mode argument from `c1008_recycle`, or have the c994 caller keep base semantics.
  Keep C994_Absent_cleanup_is_idempotent green.

### D-2: Any older-retirement receipt on disk refuses a new retirement's first cleanup
- Where: same function, `identity_mismatch=1` on any record whose project, projectId or retiredAt
  differs, then `if [ "$identity_mismatch" = 1 ]; then return 2; fi` when nothing bound.
- Failure: I extracted the function verbatim (base vs tip) and ran it with stubbed
  `sudo`, `docker image inspect` and `require_lane`. Results:
  - Older retirement 2026-10-20 receipt (completed, image) plus this operation's own pending receipt,
    no operation named: base `code=0` (unpinned); tip `code=2`.
  - The same applies with only the older receipt (tip `code=2`).
  - With a named current-SHA empty receipt plus the older one: tip `code=2`.
  Nothing prunes `$SERVER2_ROOT/temp-container-retirement` (only writes; no rm/prune in c590-remote.sh).
  So from the second rollout onwards, `retire-temp-containers` refuses
  TempContainerReceiptUnavailable for every fresh retirement. deploy-server2.ps1:1027 runs it before
  retire-temp-runner. retire-temp-runner without a matching receipt refuses RecycleGitAuditUnknown
  where the docs promise `C994_IMAGE_UNPINNED`.
- Why: receipts from earlier temp generations are expected history, not evidence about this
  retirement. No test seeds an older-retirement receipt beside a fresh cleanup. The C994 roster's
  `unrelated-newest` case always has a matching image beside it.
- Fix: do not refuse on non-matching identity when no file was named. Keep `return 2` only for a
  named file whose identity mismatches (already handled). Add witnesses: cleanup with an
  older-retirement receipt succeeds, and retire-temp-runner with only an older-retirement receipt
  prints `C994_IMAGE_UNPINNED`.

### D-3: The docs misstate the refusal rules
- Where: docs/docker-stack.md, the retire-temp preview paragraph (~l.429) and the gate paragraph (~l.514).
- Failure: the docs say "A matching receipt whose image is empty also refuses" and "When no receipt
  matches, the preview prints C994_IMAGE_UNPINNED". In the code, an empty receipt refuses only when
  no other image binds (the C1594 witness itself names an empty receipt and binds the cross-SHA image).
  A non-matching receipt refuses instead of warning (D-2). Matching partial or dry-run cross-SHA
  receipts are silently treated as "no receipt" and lead to unpinned.
- Fix: restate the rules after the D-1 and D-2 fix.

## Fail-open audit (priority 1/2): clean
- Project, projectId and retiredAt use exact string equality against the normalized 9-digit `%N`
  stamp. I tested a 7-digit stamp `2026-10-27T23:41:00.7094931Z` against a 6-digit truncation: no match.
- Cross-SHA requires `dryRun==false` and `outcome=="completed"`. In the witness, partial and dry-run
  were not bound (they lead to unpinned and, on apply, a current-SHA audit).
- Images must match `^sha256:[0-9a-f]{64}$`. A tag returns 2 (witness: cross-tag code=2).
- `docker image inspect -f {{.Id}}` must equal the candidate. Otherwise `image-absent` refuses
  RecycleGitAuditUnknown before any helper starts (C1594 "missing" case; no `run` traced, Removed empty).
- An empty image is never passed to the helper on a match. Apply on `unpinned` audits with the
  current-SHA image and refuses when that image is absent (C1594 witness, Removed empty).
- "Newest" means file mtime (`stat %Y`) with the operationId as tiebreak. Advisory: unlike same-SHA,
  two cross-SHA receipts of one retirement with different images do not refuse. The newest wins.
- Record fields are schema-validated by jq regexes (operationId, sourceSha, image, outcome enum)
  before use. Every expansion is quoted. There is no new command substitution of record data into
  docker argv beyond the regex-checked image.
- The helper flags are byte-identical: all `c1008_audit*` functions are identical base to tip, and
  no diff line touches docker run, --user or --entrypoint.
