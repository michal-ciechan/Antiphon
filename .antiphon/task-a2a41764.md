## What changed

Runner (`src/Antiphon.SessionRunner`):
- `RunnerSession` gives every tailer it binds a new stream id (`_transcriptStream`, a Guid set in the `Tailer` setter when the reference changes).
- `GetTranscript(since, stream)`: when `since > 0` and `stream` is the current stream, it returns the rows after `since` (`ITranscriptTailer.SnapshotAfter`). A cursor past the stream's `LastSequence`, an unknown or missing stream, or a bad cursor gets the full transcript. Every answer carries `Stream`.
- The three production tailers take `SnapshotAfter` under their own lock (`TranscriptEntries.After`, a binary search over the sequence-ordered list). `Snapshot()` is `SnapshotAfter(0)`, so it returns the same as before.
- HTTP `GET /sessions/{id}/transcript?since=&stream=` and phone-home `Transcript` payload `since`/`stream` are both optional. With no cursor, a request gets the full body it gets today.
- `/capabilities` and `PhoneHomeRuntimeAdapter.StaticFeatures` advertise `transcriptSinceV1`.

Contracts: `RunnerTranscriptDto.Stream` is additive and optional (`JsonIgnore WhenWritingNull`, so today's bytes stay the same when it is null). Also adds `TranscriptSince` (names, query builder, `IsCursor`) and `RunnerCapabilityFeatures.TranscriptSinceV1`.

Server (`server/Infrastructure/Agents/SessionRunner`):
- `TranscriptReadHold` keeps the last whole transcript per session. The HTTP client caps it at 256 sessions and drops the least recently used. On phone-home it lives with the connection's `PhoneHomePtyReads`, so a session that ends drops it (same as the S3 holds).
- `TranscriptSinceRead.ReadAsync` sends a cursor only when it holds a body from a runner that named its stream. Phone-home also needs `transcriptSinceV1` in the connection's capabilities. It applies a delta only when all of these hold: same session, same stream, `SessionGeneration.Equal` generation, rows start at the cursor plus one with no gap, and the rows end at `LastSequence` (an empty delta is allowed only when `LastSequence` equals the cursor). Otherwise it does one full read without a cursor. A full body is held only when it is rows 1..LastSequence with no gap and a known generation.
- Callers still get a whole `SessionRunnerTranscriptDto`. Catch-up, the boot-turn verdicts and the UserPrompt confirm see the same rows a full read returns. A missed row can never come back as "nothing arrived".
- Mixed versions: an old runner returns no stream, so it is never sent a cursor. An old server sends no cursor and gets the full body; it ignores the extra `stream` field.
