## What changed

`TaskReportTurnSelector` treated the next older TurnEnd as a hard floor. When that TurnEnd was a skipped sibling phantom, the newer housekeeping boundary (compaction continuation or local-command record) found no real prompt in the gap, skipped as inert, and the phantom itself was skipped as `sibling-tool`. `SelectAsync` returned `None`. `ReportNudgedAt` stayed null, so the task remained Dispatched.

`PhantomTransparentFloor` walks older boundaries and lets a proven `end_turn` sibling stay transparent. A genuine `end_turn`, `max_tokens`, and `cancelled` stay opaque. The housekeeping owner lookup uses that floor. Housekeeping and notification sibling skips now call `RememberPhantomBarrier` on the real owner, the same barrier the real-prompt path sets. `max_tokens` and `cancelled` stay terminal. The notification token walk was already unbounded by that floor, so a notification phantom followed by a later final was already Selected at `f34da7133`.

Two finals in a row settle the first genuine final (boundary 8, "First final."). That end_turn stays an opaque floor, so a later tokenless housekeeping end_turn cannot steal the report and nudge.
