## Defects

**D-1: the entrypoint's own step-3b guard has no executing witness, and removing it stops the runner.**
- **Where:** `docker/session-runner-grok/dind-entrypoint.sh:169-186`. That is the `[ -r /usr/local/lib/antiphon-custody-common.sh ]` / `if source ... && declare -F custody_namespace_entrypoint_step` wrapper and its two `else` continuations.
- **Failure:** every committed bootstrap test calls `custody_namespace_entrypoint_step` from the library directly. No test reads or executes these entrypoint lines. Replacing the wrapper with a bare `source` keeps CP-41, CP-52 and the census green.
- **Scenario:** under the entrypoint's `set -euo pipefail`, the mutated wrapper exits the entrypoint with 1 (library missing or unreadable) or 2 (library has a syntax error) before dockerd starts. With `unless-stopped`, the container then loops on restart.
  - This is the D-17 "never stop the runner" path that round-1 D-3 asked to be witnessed against the real entrypoint.
  - The current code is correct (my harness: 19/19 continue). The guard is simply unpinned.
- **Fix:** add a portable test in CustodyNamespaceBootstrapTests that:
  - extracts the text between `# --- step 3b` and `# --- step 4` from the real `dind-entrypoint.sh`;
  - runs it under `set -euo pipefail` in `unshare -rm` with tmpfs `/usr/local`, `/var/lib` and `/run`;
  - covers a missing library, a syntax-broken library, a library without the step function, and a read-only stale marker;
  - asserts exit 0, a sentinel line after the block, `qualified=false` and `CustodyNamespaceUnready`.

  Commit it red first, against a bare-`source` copy in scratch, as the round-1 reds were.
