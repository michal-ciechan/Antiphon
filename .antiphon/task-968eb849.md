## Advisories (sizing only; not defects)

**A-1. Cap basis.** The caps are 2x the cost-file mean. `test-performance-standards` asks for about 2x the measured p95, and the mean is a serial sum taken under unlimited contention. The width limit makes the current caps far wider than observed rows (for example, Pipeline's row max is 2.8 s against a 22 s cap). The exception is Specialist: its width-4 Linux row max of 23.2 s is already above its 18 s cap, and its pre-limit max was 36.65 s. Recommended values:
- Specialist: 18 s → **45 s** (the class timeout of 180 s leaves room).
- Pipeline: 22 s → **30 s**, and Land: 23 s → **30 s**, to match Boot and Delegation. A wider cap costs time only on a red run.
- Spill (64 s) and Delegation and Boot (30 s): keep.

**A-2. Shared limiter type.** This is not `TerminalSeatReleaseLimit`'s per-class pattern. The limiter type is shared, so the six classes share four slots in one process; the witness above measured maximum concurrency of 4 across all six. Nightly run 79b742de co-binned Pipeline, Land and Boot in all-group-30. That makes the report's "a nightly chunk of one class only limits that class" incomplete, and the per-class hung-chunk arithmetic does not hold for that bin: ceil(163/4) × 120 s = 4920 s, which is above the 3600 s chunk cap. In practice each capped wait fails at 30 s or less, and before this change there was no timeout at all, so this is not a regression. Recommended fix: one limiter type per class, or correct the comment in `LoadTimeoutParallelLimit` and the report arithmetic.

**A-3. Cost rows: no update needed.**
- The planner prices serial seconds (`Get-NightlyLaunchClassCost`). Walls at width 4 are far below those prices: Pipeline ran in 32 s alone and about 164 s for all six together, against 730 s priced for Pipeline alone.
- The author's 78 s figure for Pipeline is a loaded-host wall. It is still inside the 900 s target bin and the 2400 s and 3600 s ceilings.

**A-4. Witness coverage.** `LoadTimeoutWaitTests` covers the helper's late-hook, test-clock and wall-cap paths. It does not cover the `Open()`/`WallElapsed` swallow path (used by Pipeline and Spill) or the branch that rethrows the operation's own OCE. There is no per-class never-signaled witness; the per-class failure modes above are established by reading the code.
