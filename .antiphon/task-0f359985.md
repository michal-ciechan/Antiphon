# task-0f359985: CARD-1650 Debug report

**Outcome:** none of the 8 Linux reds was a product defect or a load or timing flake. Each test launched a hard-coded `Path.Combine(Environment.SystemDirectory, "cmd.exe")`. On Linux `Environment.SystemDirectory` is `""`, so the child was the bare name `cmd.exe`, which exits at once, and every Running-session precondition failed. Fixed by switching the tests to the suite's existing portable shell (`HerdrTestProcess.ShellPath`/`InteractiveArgs`: identical cmd.exe path and `/d /q /k` args on Windows, `/bin/sh -i` elsewhere). I also added two real-child Linux witnesses, which prove the CPU watchdog works on the Linux runner.

## Decision

Neither (a), (b) nor (c) as written. This is a test portability defect, and the fix makes the tests run on both platforms. I chose this over (a) because the watchdog and conditional stop are runner features that must hold on the Linux runner, and skipping would have left them unproven there. Only the two new real-child witnesses are Linux-only, because a Windows real-busy-child cmd loop could not be verified from server2.

The CPU watchdog works on Linux: the new witnesses use the real `SystemProcessCpuProbe` (`Process.TotalProcessorTime` reading /proc, plus the start-time PID-reuse guard) and the wall clock. A `/bin/sh -c 'while :; do :; done'` child with an idle transcript is killed with `CpuSpinKilled` about 4 s after launch: the window is 3 s at 25% of a core, with a 30 s deadline. An idle `/bin/sh -i` survives 9 s of real sweeps and is sampled (non-null) on every one.

Threshold basis: server2 runs at load average 20 to 40 on 24 cores, so a spinner can get roughly half a core. Hot is therefore set at 25%, against an idle shell's ~0%. In every observed run the kill took about 5 to 7 s total against the 30 s deadline.
