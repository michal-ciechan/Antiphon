## Semantics (check 1)

- **Intended window.** The launch prompt p comes before the cancelled TurnEnd e, and the ceiling is e. So p ≤ e and is not re-armed. A follow-up stored after e is above the ceiling and re-arms, even when it is stored before the query. This matches D-1.
- **Several TurnEnds before the query.** Taking the MAX over cancelled TurnEnds:
  - With e1 cancelled, then f1, then e2 cancelled (f1's own interrupt), f1 is dropped, but its turn was already ended by e2, so it is awaiting input anyway. A later f2 re-arms.
  - With e1 cancelled, then f1, then an end_turn TurnEnd, f1 re-arms on drain and the later TurnEnd returns the attempt to AwaitingInput. That is correct.
- **Stale or earlier cancelled TurnEnd.** `ResolveSessionAsync` either creates a new session or uses a preclaimed one in `Starting`, so there is no earlier turn in the session. The Codex verdict is the first TurnEnd past the prompt baseline. A stale cancelled TurnEnd below the launch prompt would only matter during the D-2 window, which is not reachable in practice (disclosure).
- **Sequence gaps and out-of-order storage.** The code only compares sequences, so gaps do not matter. Out-of-order storage is excluded by the documented "stored sequences only increase" invariant.
- **Restart.** A restart between the cancel and the transition leaves the launch attempt StreamingTurn under the existing reconciliation path, which the change does not touch.
- **D-2 fallback.** It applies only when no cancelled TurnEnd is stored, in which case no follow-up after it is stored either. It cannot reintroduce the CARD-1402 drop. The launch prompt being unstored at query time is a pre-existing CARD-1395 limitation, and it is unchanged.
- **Which adapters report Cancelled.** Grok's `TryBuildTranscriptVerdictAsync` passes no StopReason, so Codex is the only adapter that reports Cancelled. The report's claim holds.
- **Kill assertion.** It is test-only. `RunAttemptStallDetector` is unchanged by this diff, and the assertion pins the StallTimeoutMs kill that CARD-1395 already applies to re-armed StreamingTurn attempts. It adds no kill and does not touch the CARD-0079 rule.
- **Docs diff.** It is accurate: 250 ms `TurnPollInterval`, and a cancelled TurnEnd is an idle boundary in `AgentSessionRuntime.IsTurnBoundary`.
