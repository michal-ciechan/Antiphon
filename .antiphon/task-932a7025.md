## Per test (red at 0096f7c5a, Linux server2, one build, one lease)

### C1338_Retire_temp_dry_run_lists_exactly_the_temp_volumes: STALE

- **Red:** `removes` should be `[work, runner-tmp, dind-data, runner-state]` but was
  `[runner-state, dind-data, runner-tmp, work]`.
- **Why stale:** 8536d74cf (CARD-1609) set the temp delete order to state, dind, tmp, work. This is plan step 5:
  "Keep work last ... so a partial failure preferentially retains repository data". Also, the preview now always
  resolves the current tooling (`c1609_resolve_current_audit`) and audits the content. So a passing preview
  prints `auditPending=false` and `C1609_RETIREMENT state=Ready`, where the test expected pending. The preview
  also legitimately runs the read-only content helper (`docker run`).
- **Fix:**
  - New order.
  - `auditPending=false` and a Ready marker.
  - Only `run` is allowed, with `--rm`, `--cap-drop ALL` and `,readonly` mounts. No stop, rm, create, start
    or volume rm, and no journal.
- **New witness:** after the Ready preview, a gate-off apply (`C1609_FIXTURE_APPLY_GATE=off`) exits 2 with
  `DIAGNOSIS=apply-gate-off`. It has no Docker effect, removes nothing and writes no journal.

### C1008_Recycle_dry_run_never_mutates: STALE

- **Red:** expected `auditPending=true`, but the output had `C1609_TOOLING ...`. The main iteration passed; only
  temp failed.
- **Why stale:** same cause as C1338. A temp preview is now a content-audited Ready preview.
- **Fix:** temp expects `auditPending=false` and Ready. Main keeps `auditPending=true` and must not be Ready. The
  read-only trace checks and the RunnerBusy apply recheck are unchanged.

### C1008_Retire_temp_rechecks_absence_and_retirement: STALE (vacuous vector)

- **Red:** fault `down-retains-volume`: `refused.Exit` should be 2 but was 0.
- **Why stale, not a lost protection:** the fake-docker fault fires only on `compose down -v`. 8536d74cf replaced
  temp's `compose_temp down -v` with exact per-volume `docker volume rm -- <name>`. After each rm,
  c590-remote.sh:9505 confirms absence with `[ "$(c1008_volume "$name")" = null ] || c1008_refuse
  RecycleRemoveFailed`. So the fault became unreachable. The apply removed exactly the four temp volumes, which
  was correct. Owned containers are still stopped and removed explicitly, as before.
- **Fix:** the fake docker gets a new fault, `rm-retains-volume` (scripts/fixtures/c1008-fake-docker.sh): `volume rm`
  exits 0 and keeps the volume. The vector now requires exit 2, `RecycleRemoveFailed`, nothing removed and exactly
  one `volume rm`, so the first retained volume stops the rest.
- **New witnesses:**
  - The accepted apply never calls `compose ... down`.
  - An apply with the token but no Ready preview exits 2 with `reason=preview-required`, with no stop, no rm
    and nothing removed.

### C1105_Git_audit_resume_preserves_proof: STALE (fixture)

- **Red:** fixture c1105-git-audit.cjs:868: `1 !== 2`. Its stderr was `TEMP_PROJECT: unbound variable`.
- **Why stale:** CARD-1609's `c1008_audit_checked` now reads the global `TEMP_PROJECT`, which production defines at
  c590-remote.sh:904. The extracted resume wrapper never set it, and the wrapper runs under `set -u`.
- **Fix:** the wrapper sets `TEMP_PROJECT=antiphon-runner-temp`. The main-only reuse of a saved audit is still the
  path under test.
