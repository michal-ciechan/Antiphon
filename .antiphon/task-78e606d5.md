## Defect and fix (scripts/c1008-content-audit.sh)

Why bash-edit-diff dirs count as evidence: the evidence-name rule is a name-only roster
(plan line 212, meant for evidence directories). It refuses any HEAD-named file outside
`.git/`. A bash-edit-diff dir is a separate Git directory with no `.git` component, so its HEAD
is unknown.

Real shape, from 369 live dirs on this runner, all identical:
- entries {HEAD, config, config.global (empty), index, info/{exclude,attributes}, objects, refs}
- HEAD is `ref: refs/heads/main`
- the only ref is refs/heads/main
- objects/info/alternates points to /work/repos/antiphon/.git/objects
- one parentless commit: `author/committer bash-edit-diff <bash-edit-diff@localhost> 1000000000 +0000`, message `snapshot`

These dirs DO hold one commit and one ref. The brief's assumption of "no commits/no refs" does
not hold. About half the dirs are empty (no HEAD) and are never findings.

New `c1609_tool_snapshot`, called before the evidence finding. It accepts only when every check
below holds:
- role=tmp
- the path relative to the tmp root matches `^claude-[1-9][0-9]{0,9}/bash-edit-diff/[0-9]{1,20}-[0-9]{1,20}-[0-9a-f]{16}$`, with no symlinked component
- top-level entries are a subset of the set above, and HEAD, config, objects and refs are present
- HEAD is exactly 21 bytes of that ref
- refs/ holds only heads/, tags/ and heads/main
- info/ holds only exclude and attributes
- config and config.global, read with `git config --file` (follows no include), have no include*/filter*/fsmonitor*/diff.external/core.hookspath/core.sshcommand/core.worktree/protocol*/remote*/extensions* key
- the commit bytes equal exactly `tree <hex>\nauthor <stamp>\ncommitter <stamp>\n\nsnapshot\n` (no parent, gpgsig, encoding or other header)

The guards keep their strength. A real commit, a second ref, a stash, a reflog, packed-refs,
hooks, a remote, a detached HEAD, a nested or unanchored path, or the same shape in the work
volume still refuses. Unpublished commits, modified files and stashes in /work are untouched.

Policy note, my call under the standing "Clean it up" authority: a snapshot's loose objects can
hold a past copy of uncommitted worktree bytes. The classifier treats that copy as disposable
tool scratch. The live checkout it was taken from is audited where it lives, and plain /tmp
scratch files are already unaudited.
