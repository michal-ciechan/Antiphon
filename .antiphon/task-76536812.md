### 3. The bounded one-second wait after SIGKILL

- `process.WaitForExit(1000)` (`SessionRunnerRuntime.cs:2471`, `HerdrPaneChild.cs:1227`).
- Measured on a real zombie (killed but never reaped): 1254 ms and 1269 ms per attempt, so the wait is bounded.
- `TryRead` is a synchronous read of `/proc/<pid>/stat` and is not itself time-bounded. However, stat does not take mmap_lock, unlike cmdline/environ, so it does not hang on a D-state target.
- Grace limits:
  - The CPU-spin 5 s watchdog and the server's `KillGraceMs` 5000 go through the host route (`PtyAgentRunner`), which has no added wait.
  - The Herdr paths add at most about 1.3 s, under 5 s.
- A zombie still counts as alive to `SystemProcessLivenessProbe` (`probeAlive=True`), so a dead-but-unreaped child keeps Pending until its parent reaps it (A-3).

## Defects

### D-1 (adequacy): nothing tests the Herdr P8 identity refusal

- **Where:** `src/Antiphon.SessionRunner/HerdrPaneChild.cs:1213-1218`, the `KillPidBestEffort` refusal reached from the P8 unexpected-foreground path at `:1153`.
- **Failure:** under mutation M5, a sidecar with no `ChildLinuxIdentity`, or an unreadable `/proc` identity, kills the PID anyway. All 35 tests in HerdrAdoptionSweepTests, HerdrPaneChildKillTests and HerdrPaneSidecarTests still pass. The fix's claim that a missing or unreadable identity refuses the kill is therefore untested on this site. Only the `SessionRunnerRuntime` copy is tested (M4 goes red).
- **Why:** this is a second, independent copy of the refusal guard. A future edit could reopen a PID-reuse kill or a legacy kill there without anything going red.
- **Fix:** test-only. Add HerdrPaneChildKillTests cases on the P8 path with a live dummy child and foreign foreground PIDs:
  - `ChildLinuxIdentity = null` → child alive, `CloseAsync` returns false, sidecar kept, no Exited;
  - mismatched ticks → the same result.
  Both must go red under M5.

## Advisories

- **A-1 (runaway risk; dormant):** a legacy Herdr sidecar has no `childLinuxIdentity`, so its Linux orphan, pending or P8 kill is refused forever. That is a regression against base, which killed by PID within the 2-minute `IsAlive` tolerance. This is acceptable now because `SessionRunner:Herdr:Enabled` is false on all Linux runners. Before enabling Herdr on Linux, either:
  - back-fill the identity at successful R1 adoption, when Herdr lists the PID in our pane; or
  - fall back to the legacy `ChildStartedAtUtc` within a small tolerance. Cross-process drift is milliseconds, and a reused PID would have to start within the same second.

  File it as a follow-up card.
- **A-2:** the CP-9 timing witnesses (100 ms durable record, 250 ms signal latency) went red under concurrent host build load and passed alone. This matches the known overlapping-row flake pattern. Run CP-9 alone, or budget those bounds against measured load p95.
- **A-3:** a SIGKILLed zombie whose parent never reaps it reads as alive to `SystemProcessLivenessProbe`, so a refused-or-unobserved retention persists until the reap. Herdr pane shells reap, so this is low risk.
- **A-4:** a refused orphan kill is logged as `Herdr unreachable while adopting … (Unreachable)` (`SessionRunnerRuntime.cs:2239`). Herdr was reachable; the kill was refused. Use a distinct reason or log line so the operator is not misled.

Input waits: the fix adds no new holds. A refused-kill Pending session has no automatic release deadline: parking is disabled (CARD-1083), and release comes only when the child is observed gone.

Standing authority used: none needed. Everything ran on server2.
