## D-1 (blocker): the supervisor tree kill also ends the driver, so a normal stop exits 3 and keeps the lock

- **Where:** `scripts/qualification/qualification-stop.ps1:243-253`, the kill loop. The driver comes from
  `scripts/qualification/supervise-rc.ps1:64-75`. There, `Start-Process` with `-SameSession` (no setsid on
  Windows) makes the launch child a direct child of the supervisor.
- **Failure:** take the normal case, a live supervisor and a live driver. `taskkill /PID <supervisor> /T /F`
  ends the driver along with the supervisor tree. The driver step then re-observes `absent`. Because
  `$kills.Count -gt 0`, the loop sets `$failed = $true`. The census is skipped. The result is
  `exitCode 3 outcome=incomplete lock=not-attempted`, and the stale `native-run.lock` is never moved.
  The supervisor.log line tells the operator the stop was incomplete when it was complete. Only a second
  invocation (both pids absent by then) reaches the lock move.
  Reproduced with a scratch probe that dot-sources the tip library and injects a StopTree with `/T`
  semantics (supervisor stop also marks the driver absent):
  `exit=3 outcome=incomplete lock=not-attempted calls=4100 lockStill=True`, log
  `STOP reason="probe" outcome=incomplete lock=not-attempted killed=supervisor:4100`.
- **Why:** the card asks for one script that stops the tree and then clears the dead-owner lock.
  `docs/release-gates.md` and the SKILL say the script "performs that kill order ... and step 4's
  stale-lock move". In the main real case it does neither in one call, and it reports a false survivor.
  The fixtures cannot show this: every fake StopTree (`New-C1507Stop`, `$stopSurvivor`, `$stopChange`)
  marks only the pid it was given as absent and never models `/T` descendants. C1507_StopOrder therefore
  asserts two taskkill calls (4100 then 4200), which a real Windows host would not produce.
- **Fix:** in the loop, when a later step's re-observation after an earlier kill is `absent`, treat it as
  gone with the tree and continue to the census. A record that is not kill-eligible is not a failure.
  Keep `reused`/`unknown` after a kill as incomplete. Make the fake tree stop model parent/child membership
  (supervisor 4100 owns driver 4200). Add a witness that the real shape (supervisor alive, driver its child,
  dead lock owner) gives exit 0, `kills=[supervisor]` and `lock=moved`. That witness must go red on the
  current loop. Correct the SKILL/release-gates wording: the second taskkill runs only for a driver that
  outlived the supervisor tree. Add the same shape to the owed Windows sleeper run below.

## Advisories (no land hold; card them)

- A-1: the census watches only the supervisor and driver pids. Manual step 3 also requires
  "any remaining candidate/run descendants". Orphaned descendants whose intermediate parent was already
  gone are outside the `/T` walk and are never censused, so `outcome=stopped` can coexist with surviving
  test hosts. The lock owner is checked separately before the move, so the lock stays safe.
- A-2: without `-Confirm` the script refuses (exit 2), which is safe, but it does not print the planned
  kills or lock action as a dry run.
- A-3: the reason allows `"`, so a reason can forge `outcome=`/`lock=` text in a supervisor.log line.
  A supervisor.log write failure after the kills throws under `Stop`, with no JSON result.
- A-4: identity is pid plus the exact Windows start time (FILETIME, tolerance 0), re-observed immediately
  before each kill. That is adequate against pid reuse. It does not check the command line or markers the
  brief mentioned. `check-os-witnesses.ps1` has no recorded declaration for the platform branch; the D-1
  Code round should run it.

## Checks (identity, order, compatibility, docs)

- Identity/selection: `-TaskRoot`, `-CoordinationRoot`, `-RunId` and `-Reason` are mandatory, and nothing
  picks a "latest" run. The run id must equal both records' `runId`. A reused or unknown supervisor or driver
  refuses with exit 2 before any kill. A generation change at the pre-kill re-observation refuses. A dead
  supervisor stops only the recorded driver. The lock pid is never a kill target. There is no name-based kill.
  `taskkill` takes only `/PID <recorded> /T /F` and refuses pid <= 0 or self.
- Order/failure: supervisor first; a failed supervisor kill stops the loop (driver not killed, exit 3).
  Lock handling: missing -> absent. Unreadable, foreign, alive, unknown, reused or changed -> retained, exit 4.
  A dead owner gets a move, never a delete: unique stamp, same volume, no overwrite, bytes re-verified,
  original path checked absent. The log is append-only and flushed. Exit codes: 0, 2, 3, 4, 5.
- PS 5.1/7: all three files are ASCII (0 non-ASCII bytes). No `??`, `?.`, `&&`, `||` or ternary.
  `[Parameter(Mandatory)]` is valid in 5.1, and `$IsWindows` sits behind the Desktop check. Not executed
  under 5.1 here (pending).
- The harness catch rewrite (92cea07f07) follows the OS-witness scanner rule in
  `docs/testing-and-build.md` (OS branch witnesses): the bounded scanner refuses (exit 2) on PowerShell
  quoted subexpressions `"$(...)"`. Assertions are unchanged (diff 897e5c960e..92cea07f07 is that line only).
- Docs: the SKILL and release-gates name the script, keep the manual steps as the proof when the script
