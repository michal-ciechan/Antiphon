## Windows dictionary

.NET 9 `ProcessStartInfo.Environment` (release/9.0 `ProcessStartInfo.cs`) copies the process environment into a `Dictionary<string, string?>` whose comparer is `StringComparer.OrdinalIgnoreCase` on Windows and `StringComparer.Ordinal` otherwise. `EnvironmentVariables` is a `StringDictionaryWrapper` over that same `DictionaryWrapper` (`StringDictionaryWrapper.cs`, `DictionaryWrapper.cs`). The wrapper's indexer is the dictionary indexer, so a missing key throws `KeyNotFoundException`. `ContainsKey` forwards to `Dictionary.ContainsKey` and does not throw for a missing key. A present null value is found and returned as null.

`GetOverrides` now reads the opt-out only after `ContainsKey`. Absent skips the indexer and applies all six settings. Exact ordinal `"1"` returns no overrides. `"0"`, `""`, and a present null are not `"1"`, so the policy applies. On Windows the key match is ordinal-ignore-case because that is the dictionary comparer; the value check stays exact `"1"`. Linux `Windows=true` does not change that comparer. No production read of `ANTIPHON_BUILD_MEMORY_POLICY_OPTOUT` remains outside this guard.

`Apply` enumerates the new override dictionary and then writes the environment. The PowerShell adapter uses `GetEnvironmentVariable` / `SetEnvironmentVariable` (`NullString` for an absent restore) and does not index an optional key. `build-slot`, checkpoint `ProcessDriver` / `BuildConfinement`, `run-checkpoint`, land `RunProcessAsync`, nightly native/exact, and watched tests call `Apply` or `Set-AntiphonBuildDriverEnvironment`.
