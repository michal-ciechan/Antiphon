## (1) ACL fixture

- **Principal:** the Deny ACE uses `WindowsIdentity.GetCurrent().User` (the current user's SID, `:455-457`), not Everyone. It denies only `ReadData`. ReadPermissions and ChangePermissions are not denied, and the owner keeps implicit READ_CONTROL/WRITE_DAC, so the test can always restore the ACL. Read-denial also applies to an elevated token, because File.ReadAllText does not use backup semantics.
- **Restoration (94b93f85c):** done in `finally` (`:572-585`).
  - It runs when an assertion throws, because `originalRegistrationAcl` is captured before `SetAccessControl`.
  - It opens a new `FileInfo` and does not depend on any test handle.
  - It writes the original DACL binary form into a fresh `FileSecurity`, which marks the section modified. This fixes the "untouched snapshot is not persisted" failure the author observed.
  - It then asserts that the SDDL is exactly the original and that the file is readable again.
  - Ownership and inheritance never change. Only the Access section is touched, and its protected/inherited flags travel in the binary form. Take-ownership or an inheritance reset is therefore unnecessary.
  - `using var scratch` disposes after the `finally`, so the ACL is restored before the scratch is deleted.
- **Killed mid-test:** the leftover is `%TEMP%\c1032-ws-<guid>\runner-store-id` with the Deny ReadData ACE. It is outside the worktree. A ReadData deny does not block DELETE, so the file is not stuck.
