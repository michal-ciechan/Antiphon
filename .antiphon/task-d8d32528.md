## Per defect

**D1 (P1): orphaned checkout content.**
- `consider_linked` resolves the checkout that `<id>/gitdir` records. Only the directory part is resolved; the `.git` entry itself is not followed.
- When that directory exists, it is always inspected:
  - If both pointers agree, through its own `.git`, as before.
  - Otherwise, `consider_dirty` runs with `git -C <checkout> --git-dir=<id> --work-tree=<checkout>`, after the index-equals-HEAD check. It covers status, index flags and raw hashes; the check name is `orphan-status`.
- Only an absent checkout falls back to the index-equals-HEAD check alone.
- These refuse `worktree-path`:
  - a recorded path not ending in `.git`;
  - a checkout that is not a directory;
  - an absent checkout under an unsearchable directory.
- The orphan inspection uses the same parallel queue, with one status and one batched hash per checkout.
- Red proof:
  - At 1ac296dd, orphan-missing-modified and orphan-missing-untracked both passed.
  - The `orphan-queue` mutant turns both red. The `orphan-gitdir` mutant turns modified, clean and ignored red.
  - The prunable cases are the existing rows stale-linked-published and pruned-path-staged. stale-pointer-staged keeps `check=stale-index`, and the `orphan-stale-index` mutant turns it red.

**D2 (P1): non-commit tips.**
- The origin read is now `ls-remote --heads --tags`, still one call.
- One `cat-file` reads each tip's own type. A tag, tree or blob tip is published only when origin advertises that exact object (peeled lines included).
- A tree tip also counts as published when a present head reaches it. That costs one `rev-list --objects --filter=blob:none`, run only when such a tree exists.
- Otherwise it refuses `RecycleUnpublishedWork` with `check=tip-object`.
- An advertised tag's commit is still proven against the heads, consistent with the peeled line in packed-refs. tag-published-off-branch pins this as U `rev-list`.
- Red proof at 1ac296dd:
  - tag-annotated, tag-annotated-packed and tag-of-tag passed.
  - tag-tree, tree-ref-unpublished and blob-ref refused K `tip-commit`, where U is now expected.
  - tree-ref-published refused K, where it should pass.
- Mutants: tip-object refusal, tags not advertised, tree-unreached no-op, tree reach skipped, tag commit uncounted, all-as-tags.

**D3 (P2): symlinks and ignored HEAD files.**
- Symlinks:
  - The symlink pass now runs after every content audit.
  - A dangling or out-of-volume symlink whose nearest owner is a checkout's work tree is that checkout's content. Orphan checkouts count as checkouts here.
  - Such a link is never followed: ignored ones are ignored, tracked ones compare by link text, and unignored untracked ones refuse `status`.
  - Symlinks inside a Git directory, or outside every checkout, keep `link-resolve` and `link-confine`.
- HEAD files:
  - A file named `HEAD` adds an entry only in a Git-shaped directory, meaning one that also holds objects, refs, packed-refs or commondir.
  - A Git directory's own subdirectory (a bare repository's `logs/`) is skipped.
  - A shaped directory that Git does not open refuses `git-dir-shape`.
- The receipt therefore depends only on repositories and their retained tips.
- Red proof at 1ac296dd:
  - ignored-head-equality: the receipts differed.
  - ignored-symlink-outside and tracked-symlink-outside refused K `link-confine`.
  - ignored-symlink-dangling and orphan-symlink-ignored refused K `link-resolve`.
  - untracked-symlink refused K, where D is now expected.
  - damaged-git-dir-ignored passed.
- Controls metadata-symlink-outside and loose-symlink-dangling stay K.
- Mutants: shape skip, subdirectory refusal, git-dir-shape no-op, checkout-owned link skip, owner always tree, status no-op.
