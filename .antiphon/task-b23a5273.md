## Defect (Final Review fe40955b)

scripts/test-postgres-snapshot.ps1 line 1462 used
`Set-Acl -LiteralPath $private -AclObject $acl` on the directory that
`New-SnapshotPrivateDirectory` had just created. On PowerShell 7 Set-Acl writes
every section of the descriptor, so it needs SeSecurityPrivilege for the SACL;
an ordinary desktop session does not hold it, the live section stopped after
34 PASS lines with "The process does not possess the 'SeSecurityPrivilege'
privilege which is required for this operation" and the script exited 1.

## Fix (commit ca5cee46a5e628a39f33f6beaf9315e5ef043169, test file only)

In the live section of `Test-WindowsAclRules`:

- read: `[System.IO.FileSystemAclExtensions]::GetAccessControl($di, Access)`
  (DirectoryInfo instance method on Windows PowerShell) instead of Get-Acl;
- write: `[System.IO.FileSystemAclExtensions]::SetAccessControl($di, $acl)`
  (instance method on Windows PowerShell) instead of Set-Acl. Only the
  modified Access section is persisted, so no privilege beyond the caller's
  ownership is required.

The rest of the live section was checked: no other Get-Acl/Set-Acl use
remains (the production reader `Get-SnapshotWindowsSecurity` still reads with
Get-Acl, which is read-only and unaffected). scripts/postgres-snapshot.ps1 is
unchanged. The Linux path of the test (everything outside
`if ($env:OS -eq 'Windows_NT')`) is untouched; the file parses with 0 errors.
