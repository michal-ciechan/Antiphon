## Advisories (cards, not blockers)

- **A-1 Concurrent ticks.** Execute route plus a scheduled tick (or two execute calls) run two scoped `AppDbContext`s over the same population. Trees are safe (runner lock + re-verify), but both ticks may insert a `WorktreeResidueCandidateCursor` for the same `CandidateKey`; the unique index `IX_WorktreeResidueCandidateCursors_CandidateKey` makes the second `SaveChangesAsync` throw after requests were already sent, leaving that run without `FinishedAt` and its unsaved rows lost (the next tick records `already_absent`). Pre-existing shape since CARD-1677 for preview + scheduled; the route widens it to Execute + Execute. Suggest a process-wide `SemaphoreSlim(1,1)` in `RunTickAsync` or a 409 `tick_in_progress` on the route.
- **A-2 Route runtime.** The execute (and preview) route runs a paced tick of up to `MaxTickMinutes` (20) inside the HTTP request on `RequestAborted`; a client or proxy timeout cancels it mid-tick with the same unsaved-row effect as A-1. Document `curl --max-time` or return the runId early and run detached.
- **A-3 Missing witness.** `MaxAbsentPerTick` (default 200, appsettings 200, validator 0..1000) has no row in `C1677RetentionSettingsTests`, which pins default/appsettings/bounds for `MaxRemovalsPerTick`. A mutant deleting the validator line survives CP-1.
- **A-4 Stop-truncated remainder.** When `StopReason` breaks the loop, the unsent in-bound candidates get only the Deferred stop row, not `queued_next_tick` (only past-bound tasks do). The docs sentence ("every eligible task past a bound") is accurate; the brief's "every eligible leftover" is not met for a stopped tick. Pre-existing shape.
- **A-5 Guard-run residue.** At this branch base `TestClassificationPolicyTests` still leaks `c487-probe-*` dirs (102 -> 108 in /tmp after CP-2, about 290 MB); master `584224f0` carries the `WithTempDirectoryAsync` cleanup, so the rebase at land picks it up. Not a defect of this change.
- **Interpretation note.** On an incomplete inventory nothing is classified gone and nothing goes through the absent bound; the ordinary paced, runner-verified bound (25) still runs as before CARD-1794. A total send halt on an incomplete inventory would be a design change beyond the card: orchestrator's call, not a blocker.
