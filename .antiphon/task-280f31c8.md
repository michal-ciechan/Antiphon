## Brief checks

(a) Timer. `SeatOccupancyHostedService.ExecuteAsync` returns at once when `SeatWatchEnabled` is false; otherwise one sequential loop: sample, then `PeriodicTimer.WaitForNextTickAsync`. Every statement in the loop is inside `try`; non-cancellation exceptions are logged and the previous snapshot stays; `OperationCanceledException` with the stopping token cancelled breaks; an OCE without it falls into the general catch. It cannot overlap itself (single awaiting loop; `PeriodicTimer` coalesces missed ticks). The interval is validated 10..3600 by `AttentionSettingsValidator` with `ValidateOnStart`, so the `PeriodicTimer` constructor outside the `try` cannot see a non-positive period. A failed or slow runner read is bounded per host by `InventoryTimeoutMs` (3 s) through a linked `CancellationTokenSource(TimeSpan, TimeProvider)`; timeout and any non-cancellation exception become `InventoryState=unavailable` with a 256-char bounded reason, desktop counters still sampled, no seats. Hosts are sampled sequentially, so one bad runner delays later hosts by at most its timeout; it never blocks the app.

(b) Writes and calls. The only writes are `HostOccupancySamples.ExecuteDeleteAsync` (retention prune) and the inserted sample rows; every other query is `AsNoTracking`, the scoped `AppDbContext` is fresh per tick, and `HostBudgetService.ListAsync` is a read. The only runner call is `ISessionRunnerDirectory.GetInventoryAsync`, which in `PhoneHomeRunnerDirectory` is a List RPC to a live connection or `Unavailable`; its one side effect is `PhoneHomeLiveConnection.NoteListed`, which sets the diagnostic `ListedNonExited` count and gates nothing. The local host (`LocalRunnerId == "local"`) is sampled from task rows only and never resolves a client, so no Program-boot test can reach the production runner through this path. `RemoteWorkspacePreparer.InFlightCount` is an in-memory count. `SeatOccupancyState.Publish` is an `Interlocked.Exchange`.

(c) Per-minute cost and correctness. One tick is one HostBudgets read, one count for the local host, and per runner host: sessions, pending, dispatched/working counts, the inventory RPC, then the join (sessions, two grouped latest-task passes of two queries each, Blocked events, cards, pooled agents, parks), then one DELETE and one SaveChanges: about 15 statements for local plus one runner. `LatestPerSessionAsync` groups by session and takes `MAX(CreatedAt)` (asserted in SQL by the new test), fetches rows whose CreatedAt is in the set of peaks, then keeps for each session only rows at that session's own peak and tie-breaks on the greater Id, the same `Newer` rule as before. A session with two open tasks is handled by the second pass over the Dispatched/Working subset (`C1079_Join_open_task_is_dispatched_or_working_only`, mixed session); a session with no task has no peak and gets a null `LatestTask`; ties at equal CreatedAt resolve by Id as before. Both sides of the equality come from the database, so timestamp precision cannot split them. Growth is bounded by D-9: `OccupancySampleRetentionDays` (14) with a prune every tick, about 60,000 rows at three hosts.

(d) Slots route. `RunnerSlotService.LoadDesktopAsync` still projects `Live`, `Status`, `OpenTaskId`, `PooledWarm` from the shared join and `OpenTaskId` keeps its Dispatched/Working-only meaning; `RunnerSlotEndpointTests` (8) and `RunnerSlotRulesTests` (2) pass at the tip (CP-21).
