## D-1 Ancestor CLAUDE.md above the owned root now reaches the live lane unseen (guard weakened)
- Where: tests/Shared/LiveClaude/LiveClaudeProfile.cs:93 (`&& LiveClaudeProfilePaths.Within(dir.FullName, Context.OwnedRoot)` in the InstructionDigest walk).
- Failure: put a CLAUDE.md (or AGENTS.md or .mcp.json) in any directory above OwnedRoot, for example `<TEMP>/CLAUDE.md` on Linux, or `%USERPROFILE%\CLAUDE.md` / `%USERPROFILE%\AppData\CLAUDE.md` on the Windows host. At the base the walk enqueued that file and refused `unowned-instructions`. At the tip the loop ends at the root, so the file never enters the digest. The profile is admitted and launches with the cwd under that directory.
- Why it matters: the walk mirrors Claude's own loading, and Claude loads CLAUDE.md from every ancestor of the cwd. The repo's canary tests/Antiphon.Agents.Pty.Tests/OrchestratorWorkspaceLayoutCanaryTests.cs:59 asserts exactly that ("Claude walks ancestors: the parent's CLAUDE.md must be visible"). CLAUDE_CONFIG_DIR redirects only user-level config, not the project-memory walk. The original Windows refusal may have been a true positive: on that host the walk crosses %USERPROFILE%, whose .claude holds the operator's real CLAUDE.md (and possibly rules), and Claude's ancestor walk may read `<ancestor>/.claude/CLAUDE.md`. That last part is plausible but not proven here; a headed canary would settle it.
- Proof (one probe class, Linux, build-slot, scratch worktrees; not committed; probe source is reproduced below):
  - 8cdb8cc45 (red witness, pre-fix code): probe `AncestorClaudeMdAboveOwnedRootRefuses` passed (refuses unowned-instructions).
  - 5053dd18e (tip): the same probe FAILED: `C1545 probe/ancestor-above-root expected typed unowned-instructions refusal`.

- Fix (choice for the Code task): keep walking every ancestor. Above OwnedRoot, refuse `unowned-instructions` when any file Claude loads from an ancestor exists (CLAUDE.md, CLAUDE.local.md, AGENTS.md if imported, .claude/CLAUDE.md, .claude/rules/**). Alternatively, move the Windows live-lane fixture root out of %USERPROFILE% (TEMP sits under it) and keep the full-ancestor refusal. Either way, add this probe as a committed red-first witness: an ancestor CLAUDE.md strictly above the root must refuse. Also add a variant with `<ancestor>/.claude/CLAUDE.md`.

## Advisories (become cards)
- A-1 LiveClaudeProfilePaths.cs Within: the separator is `canonicalRoot.Contains('\\') ? '\\' : '/'`. Take the separator from the rules (Windows shape vs Path.DirectorySeparatorChar).
