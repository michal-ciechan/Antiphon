  `Audit`, `RunWindowsAuditAsync`, the literal rosters, `RemoteFilter`/`RollingFilter`,
  `ExpectedReason`, `RequireNativeLinux` and `[Category("Unit")]` are untouched. origin/master
  (`951e5bf43`, five commits past the base) differs from this file only by the same two lines.
- (c) Checkpoint tooling. The tool decides a row from the TRX counters only: red if failed > 0,
  roster-miss (exit 3) if executed < Min or an Expect token is absent from executed+skipped names,
  else green; the driver's exit 8 is not read when a TRX exists (RowRunner.cs:284-293). A Linux
  row that selects only these two methods now records executed=0 skipped=2: green at Min 0 (CP-3
  above), roster-miss at Min >= 1, where before it was red with 2 failures. Both receipt validators

  as `row_failed`; this already applied to every Linux Unit-lane row because other Windows-only

  them, CP-1/CP-3/CP-5 are Windows rows whose exact-pass floors (4, 2, 4; 0 skipped) are unaffected
  because the skip cannot fire there. The only two-method Linux selections on record were ignored
  diagnostic base checks (task 2a876d8a CP-16, task d5234cdc BASE-UNIT), not plan rows. The Unit
  lane `/*/*/*/*[Category=Unit]` moves from failed=2 to skipped=2; Unit-lane Min cells in plans are
  floors far below the lane count. No manifest, census or validator expects these methods executed

- (d) Who runs them on Windows. Real Windows executions exist only from the CARD-1050 S1/S2 Final
