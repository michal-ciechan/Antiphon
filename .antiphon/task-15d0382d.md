## What changed

- D-1. `Get-CutoverScriptArguments` walks pwsh's own options from argv[1] and returns the tokens
  after the `-File <path>` pair whose `GetFullPath` equals `$PSCommandPath` (any spelling pwsh
  accepts: `-f`, `--File`, `/File`; case-insensitive only on Windows). A `-Command` or
  `-EncodedCommand` switch before that pair (any prefix pwsh accepts, `-c`/`-e` onwards), an implicit
  script path or an in-process call yields no anchor and `-Execute` refuses with exit 2:
  `REFUSED: -Execute requires -ConfirmWindow. The process command line has no -File pair naming this
  script (...). Start it with pwsh -File scripts/cutover-postgres-server2.ps1. Nothing was changed.`
  `Test-ExactNamedSwitch` now takes the anchored tokens, so a `-ConfirmWindow` that is the value of
  `-WorkingDirectory` or `-CustomPipeName`, or sits inside `-Command` text, never counts. A `-File`
  that is the value of another host option names another path and is walked past.
- D-1b (new, found by probing). pwsh `-File` hands the next argv token to a trailing-colon parameter
  as its value: `-Execute -Conf -HoldReason: -ConfirmWindow` binds HoldReason=`-ConfirmWindow` and no
  switch, and the previous scan counted that token. A token ending in `:` now consumes the next token
  as its value. (`-ErrorVariable: -ConfirmWindow` is the same shape and is covered by the same rule.)
- A-1 halves. Half 1 (only a dash token counts) is pinned by `-Execute -Confirm -ErrorVariable
  /ConfirmWindow`: a common parameter the script's own value list does not know, so only the dash
  rule keeps the value out. Half 2 (the value of a value-taking parameter is skipped) is pinned by
  `-HoldReason: -ConfirmWindow`. The name-resolved branch of the skip (exact or unique-prefix name
  without a colon) is unobservable under pwsh 7: `-HoldReason -ConfirmWindow` is a binder error
  (`Missing an argument for parameter 'HoldReason'`) before the script runs. It stays as defence in
  depth for other hosts and is commented as such; a mutation of that branch alone cannot go red.
- Runbook and synopsis say exactly what is checked: the exact token among the arguments after the
  `-File` pair opens the window; an abbreviation, a parameter value, a token before the pair or inside
  `-Command` text does not; a start without the pair refuses with exit 2.
- `Invoke-C1407Cutover` in the harness gained `-HostArguments` (pwsh options before `-File`),
  `-FileSwitch` (`-f` spelling), `-AsCommand` (`-Command '&' '<script>' <args>`, tokens joined by pwsh)
  and `-WorkingDirectory` (Push-Location for the launch). `New-C1407GateCase` builds the table.
