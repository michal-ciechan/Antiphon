## Priority answers

1. **Semantics.** Omitting the row is correct. An `AgentTasks` row disappears in production only through `DataRetentionService.PruneTasksAsync` (server/Application/Services/DataRetentionService.cs:407). That method deletes whole terminal trees older than TaskRetentionDays, and AgentTaskEvents cascade with them. Once the delete commits, the next feed read finds no events, so the row is gone anyway. Skipping it during the window matches the converged state. Nothing can act on the row: its OpenDrawer action points at a task that no longer exists. In tests the same window comes from `Scenario.DisposeAsync` (tests/Antiphon.Tests/Application/AttentionServiceTests.cs:3518-3527), which deletes events and then tasks in separate statements. The sibling `kept` refusal in the witness proves that eligible rows still emit.
2. **The other SingleAsync calls in BuildLandItemsAsync.** None of them is exposed in production. The feed's other partials contain no other SingleAsync/FirstAsync on AgentTasks.
   - AttentionService.cs:1492 (land request -> task): the FK is Restrict, and retention skips trees that have land requests.
   - AttentionService.cs:1521 (note -> task): the TaskId has no FK, and retention skips trees that have notes.
   - AttentionService.cs:1552 (dispatch intent -> task): the FK is Restrict, and retention skips trees that have intents.
   - Each of these lists its rows first and then looks up each task, so a test dispose that deletes the child row and then the task in separate statements can open the same window. Scenario.DisposeAsync does this for notes (3524 then 3527). This is advisory. It is not in the fixed method group, and the brief scoped those lookups out. A follow-up card could make them tolerant or make test dispose atomic.
   - **Behaviour.** Ordering, limits and dedup are unchanged: the Union/OrderBy and ConditionKey grouping are untouched, and the change only skips a group. SingleOrDefaultAsync issues the same single `LIMIT 2` query as SingleAsync, so there is no extra round trip.
