## A-8: per-lane resume in the seed order (`scripts/lib/nightly-stopped-run-seed.ps1`)

The final order contract for `Resolve-NightlyStoppedSeedOrder`:
1. Failed-method chunks (priority 0). This band is unchanged and sorts by known timestamp, oldest first, then canonical order.
2. Every lane's **interrupted** chunks. An interrupted chunk is one with a mapped seed row where started=true and completed=false. Lanes come in canonical lane order. Each lane starts at its first interrupted chunk.
3. Every lane's **untouched** chunks: never started, or a class the seed never saw. Each lane is walked from the same resume point and wraps to earlier holes. A lane with no interrupted chunk resumes after its last passed chunk.
4. Siblings of a placed failure (priority 2), then passed chunks (priority 3). Both bands keep the timestamp-then-ordinal sort.

The seed schedule now returns `lanes` as `{suite, resumeChunk, lastPassedChunk}` (before this it returned `@()`). The reason text keeps the `operator-seed-order` prefix. The seed format, hash and schema are unchanged, so old seeds are accepted as before.

## A-10: skip-only chunks are completed (exporter)

A chunk counts as complete when its only not-executed rows are `NotExecuted` (MTP's encoding of `[Skip]`) or `Skipped`, and the run summary is `Completed`, `Passed` or `Failed`. These cases stay unfinished:
- any other not-executed outcome, such as `Pending`;
- skips under an `Aborted` summary;
- missing rows, which the existing planned-count check catches.

The docs paragraph in `docs/testing-and-build.md#nightly` states the same rules.
