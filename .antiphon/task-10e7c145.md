### D-2: the durable pre-signal write has no time bound, so a slow disk delays or blocks every authorized stop (plan D-8/D-9, "Stop intent", V-13)
- **Where:** the plan requires the requested record to be written before the syscall:
  - `FileOptions.WriteThrough`;
  - `Flush(flushToDisk: true)`;
  - rename;
  - a directory fsync;
  - all inside the serialization gate that the exit observer also takes.

  The plan contains write errors (ENOSPC, unwritable directory, flush or rename failure), but it does not bound
  write latency.
- **Code today:** `PtyAgentRunner.KillAsync` (`PtyAgentRunner.cs:521-528`) calls `_conn.Kill()` synchronously.
  The caller's timeout `Task.Delay(timeout)` starts only after that call. The cgroup path writes inside
  `SealAndObserveCustodyAsync`'s `_writeGate` (`:539ff`).
- **Scenario:**
  1. The runner volume, which agent builds share (`SessionRunnerSettings.cs:6`), is I/O-saturated. A WriteThrough
     plus fsync of the journal and its directory then blocks for tens of seconds. A hung or D-state fsync blocks
     indefinitely.
  2. The CPU-spin watchdog's 5-second `KillTimeout` (`SessionCpuWatchdogService.cs:25`) expires, and so does the
     server's `KillGraceMs` of 5000 (`AgentSessionSettings.cs:9`). The stop is reported failed while SIGKILL is
     still queued behind the fsync.
  3. The same gate holds back the exit observer's publication. Pool release and the CARD-0079 compaction stop then
     see a live process and retry.

  Under D-10 the disk record carries no attribution authority, so a durable write before the signal buys nothing
  except crash diagnostics.
- **Fix:**
  1. Bound the pre-signal record attempt. One option is a short deadline on a worker; on expiry, proceed with
     `durable=false`. Another is to publish `requested` in memory, send the signal, and write or fsync the records
     after the signal and outside the gate.
  2. State the bound in Performance.
  3. Add a V-13 and V-14 arm, `Blocked_record_write_still_signals_within_bound`, using a seam that never completes.
  4. Adjust `Intent_is_durable_before_signal_when_storage_works` to match.

## Advisories
- **A-1 (degraded-path text contradicts D-10):** D-10 makes the live issuer's memory the authority and the disk
  record diagnostic. The table nevertheless drops attribution to `stop sender unknown (intent not durably
  recorded)` whenever the record write fails, even though the issuer's memory proves the issued attempt.
  Recommend `stopped by Antiphon (SIGKILL; stop record not durable); killed by signal 9 (SIGKILL)`. If not, give
  the reason.
- **A-2 (rows missing from the text table, while V-10/V-15 assert exact text):** two combinations have no row:
  - a known signal, plus the server's stored request (`TerminationSource`/`Stopping`, `AgentSessionService.cs:1866-1871,2027-2032`),
    plus no live issuer. This happens on dead-host manifest adoption or with an old host, and it is the commonest
    degraded real case.
  - a runner-issued host-target kill (`KillPidBestEffort`/`KillHostIfStillOurs`/`PtyHostLauncher.cs:229`) whose
    child exit was never observed.

  Specify both texts, for example `Antiphon stop requested; killed by signal 9 (SIGKILL); sender unconfirmed`.

  constant to 1.0.8.0. The contract witness must then fail as well as V-1.

- **A-5 (master port and CARD-1610):** task 00861a7a (`cf80deb58`, base master `698bf1b7`) has three relevant

  - `Porta.Pty.Unix.PtyConnection` is internal and abstract;

- **`ChildWatcherThreadProc` order, on one thread:**

  both writes. The replay is sound.

  plan forbids that and returns null on any contract drift.
- **Trimming and ADR:**

    hits are `false` in test staging.
