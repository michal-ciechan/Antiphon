### D-1 (regression): the nested-custody walk follows directory symlinks out of the root and throws out of SweepOnce

- **Where:** `CheckpointTempRootSweep.Eligible`, lines 227-248 at 1fee5b56. Round 1 replaced
  `ContainedCleanup.SafeTree`, which refused any ReparsePoint, with `AnchoredInventory`, which accepts
  symlinks as leaves. The path-based `EnumerateDirectories`/`Entries` loop that follows is unchanged. It
  uses `File.GetAttributes` and `Directory.EnumerateFileSystemEntries`, so it now descends through a
  symlinked directory. That loop has no try/catch, no MaxDescendantEntries bound and no MaxDuration check.
  The `Eligible(root, started)` call at line 176 sits outside the per-root try at line 186.
- **Failure:** a dead, past-grace root contains `out -> /some/dir`, and the target tree holds an
  unreadable directory (probe P2). `SweepOnce` throws UnauthorizedAccessException. Other failures do the
  same: a directory vanishing mid-walk throws DirectoryNotFound, and ELOOP or EACCES under `/proc` throws.
  The effects:
  - No receipt is produced, and the healthy root behind it is not reclaimed.
  - `WriteState` is skipped, so the cursor and LastSweep never advance. Every later sweep reaches the same
    root and throws again.
  - In `CheckpointTestScope` root creation, `SweepOnce` runs inside the try. Its catch unlinks the new
    root's marker and directory and rethrows. Every checkpoint root allocation on that host therefore fails
    while the dead root exists.
  - With a readable target, the walk instead reads outside the root, unbounded (P3 found `tool/` outside
    the root).

  Base on the same fixture skipped that root as `inventory-incomplete-or-linked` and completed the other.
- **Why:** this breaks the brief's requirement that "one bad root does not abort the sweep of other roots".
  It is also a walk that escapes the root through a path-based call. It is read-only, so no foreign data is
  deleted.
- **Fix:**
  - Drive the nested-custody check from the directories `AnchoredInventory` already listed, which are
    nofollow, mount-checked and counted. Do not re-enumerate by path. At minimum, skip ReparsePoint entries
    in `Entries`.
  - Catch IOException/UnauthorizedAccessException around that walk and return
    `inventory-incomplete-or-linked`, or move the `Eligible` call inside the per-root try.
  - Add a witness that is red at 1fee5b56: a dead root whose dir symlink reaches a mode-000 subdirectory,
    plus a second eligible root. Expect no throw, the bad root retained with its marker, and the good root
    completed.

## Round 1 defects re-verified on the real path (tip code read plus probes)

- **D-1 (backslash or refused name): closed.** On Linux, `EntryNameSafe` refuses only an empty name or one
  containing `/`, which readdir cannot produce. `IncludeListedName` throws `anchored-name-refused` for any
  name still refused, and `.`/`..` are filtered. The throw is caught in two places:
  - in `AnchoredInventory`, as `inventory-incomplete-or-linked`, before any unlink;
  - in `CollectAnchored`, which completes before the first unlink, under the per-root try as
    `delete-IOException`.

  Either way the marker survives and other roots continue.

  Names are passed only to fd-relative `openat`/`statx`/`unlinkat`:
  - A non-UTF-8 name decodes to U+FFFD and statx returns ENOENT, so the root is retained with its marker
    (P4, same as base).
  - Newline and leading dash are harmless, since no shell or argv is involved.
  - Names longer than NAME_MAX cannot come from readdir.
  - The chain walk is per component, so there is no PATH_MAX limit.
- **D-2 (hard link): closed for truncation.** nlink is checked on the opened fd with O_NOFOLLOW and is
  regular-only. A directory or symlink never reaches truncate: the mode check comes first, and O_NOFOLLOW
  plus fstat catch a raced swap.
  - On `AnchoredHardLinkException` the name is unlinked with its listed identity, its bytes are not counted
    and the budget is unchanged.
  - A link count that rises between fstat and ftruncate needs a new link to the root's own file. That
    exposes no foreign bytes.
  - Advisory, same as base (P5): a hard-linked file that is fully unlinked within budget still counts its
    length as reclaimed, although nothing is freed.
- **D-3: closed.** fsync follows ftruncate (an error throws), and Windows calls `Flush(true)` after
  `SetLength`.
- **D-4: closed.** The Windows truncate opens with share 0. A file another process holds open fails with a
  sharing violation (IOException). That is caught per root as `delete-IOException`, with the marker kept,
  which matches base's FileShare.None open. Nothing is swallowed.
- **Identity and mount checks (question 3): no new permanent leak found.**
  - Device encoding is `(major<<32)|minor` from statx on both the `Stat` and `ListAnchored` paths, which is
    consistent. Verified green here on ext4 dm (major 253).
  - The mount-boundary compare covers child directories only, against the root's own device. It never
    compares the root with its parent, so a bind-mounted root or one on a different device is unaffected.
    overlayfs reports the overlay device for every directory, and Docker file st_dev variance is not
    compared.
  - A tmpfs or other mount inside a root returns `mount-boundary`, with the marker kept, before any unlink.
    Base never completed such a root either: its rmdir of the mountpoint failed with EBUSY.
  - An identity mismatch throws before the matching unlink, including for the lock and marker, so the
    marker survives and the next sweep relists.
  - A vanished leaf is tolerated. A vanished directory throws before the lock and marker unlinks.
  - Advisory: a same-device bind mount inside a root is still crossed. That is unchanged from base; kernel
    4.15 has no STATX_MNT_ID.
- **Access-denied mapping:** errno 1, 13 and 30, win32 5, and NTSTATUS 0xC0000022 and 0xC0000121 map to
  UnauthorizedAccessException. The receipt key `delete-UnauthorizedAccessException` therefore matches base.

## Windows (read only, not executed)

- The code is ASCII-clean. The change against round 1 is limited to the share argument, the
  `NumberOfLinks` check, `Flush(true)`, the identity compare (idle, because the Windows listing records
  inode 0 and `Stat` returns 0/0) and the NTSTATUS and win32 mapping.
- Advisory, low confidence, pre-existing from round 1: `NtCreateFile` is called with
  FILE_SYNCHRONOUS_IO_NONALERT (0x20) and a DesiredAccess of GENERIC_READ or GENERIC_READ|GENERIC_WRITE,
  without an explicit SYNCHRONIZE (0x00100000). The unlink open does include SYNCHRONIZE. If the kernel
  validates SYNCHRONIZE before generic mapping, every Windows chain open would fail with
  STATUS_INVALID_PARAMETER. Fail-closed, but nothing would be reclaimed. Confirm this in the pending native
  Windows row.
