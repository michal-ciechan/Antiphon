# Task 0889258e — C1313 harness pipe never closed

C1313_BaselineAuthority hung because a descendant kept the harness pipes open after the root exited. The harness now fails that case inside the cleanup budget and names the holder, and the C1313 git children disable auto-gc and auto-maintenance. Linux verification is green. Tip afb64ae704391c1413c23006a8e15dc4225b0d75.

Verdict: PRODUCT/SCRIPT and the harness. The failing run had already printed every PASS line, with completion root=True and both streams still open. That is a process still holding the redirected pipes after the script left. The script-side cause is a detached git auto-gc or auto-maintenance child. This Linux host did not reproduce a detached git holder; the proof here is a stand-in grandchild that holds stdout after PASS. The Windows qualification clone was left untouched.

## Changes

- ScriptHarnessProcess, after the root leaves, waits only PostExitDrainBudget, which defaults to CleanupBudget (10s in production, 2s in the fixture). The timeout text is "post-exit drain" plus holder=<pid:name>. A flush that reaches EOF still completes. While the root is alive the execution budget still applies. Caller cancellation during the drain stays OperationCanceledException.
- CheckpointProcessRunner.HardenGit and Invoke-ReleaseAuthorityGit pass -c gc.auto=0 and -c maintenance.auto=false, the same pair as ServerGitProcess. C1233_VerifierGit requires both. test-selection.ps1 is part of the selector hash, so its git stays on CheckpointProcessRunner, which now carries the settings. Get-NightlyOriginUrl and Invoke-NightlyGit in nightly-common.ps1 still start native git; they are the same inheritance class and are outside C1313_BaselineAuthority.
