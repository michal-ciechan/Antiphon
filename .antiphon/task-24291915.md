## Change (server/Application/Services/DataRetentionService.cs, AuditService.cs, Settings/RetentionSettings.cs)

- **A-1** `PruneTaskBatchesAsync` loads `LoadOutboundTaskIdsAsync` for every batch attempt (was once per pass). A task referenced after an earlier batch committed is protected for the later batch. A load failure (malformed capture descriptor) still ends the pass; it is not treated as a range fault.
- **A-2** a batch whose eligibility/delete throws is retried immediately; after 3 consecutive failed attempts of the same batch the root range is skipped, logged as `Data retention task prune skipped a failing root range after 3 attempt(s): <exception type chain>` (no ids/row data), the cursor moves past it and the scan continues. After the scan, the last exception is rethrown so the Tasks pass still reports `Failed` with the type chain (C1654_FailingPass behaviour unchanged). Skipped trees are revisited when the scan wraps. Progress: `TaskPrune.FailedAttempts`, `TaskPrune.SkippedRanges`.
- **A-3** SubscriptionUsageSamples, WorktreeResidueHeldRows and AuditArchive each run as bounded single statements (`Where(<unchanged predicate>).OrderBy(..).Take(n).ExecuteDelete/ExecuteUpdate`, each its own implicit transaction) under `RowPruneBatchCommandTimeoutSeconds` (default 60), `RowPruneBatchSize` rows per batch (default 1000), at most `RowPruneMaxBatchesPerSweep` batches per pass per sweep (default 50); a pass ends when a batch comes back short. No cursor needed: touched rows leave the predicate. Cutoffs and keep rules are unchanged. Progress per pass in `DataRetentionPassOutcome.Progress` (Batches, Rows, Complete, BatchMilliseconds); a failed row pass reports committed batches, and the result counts use the tally.
- **AuditArchive confirmed from code**: `AuditService.ArchiveFullContentAsync` is `UPDATE AuditRecords SET FullContent = NULL WHERE CreatedAt < UtcNow - RetentionDays AND FullContent IS NOT NULL`; no copy is written anywhere. Scope unchanged: the sweep now calls `AuditService.ArchiveFullContentBatchAsync(cutoff, n)` with the same predicate and effect, same cutoff (`AuditService.ArchiveCutoff`, DateTime.UtcNow as before). The `DELETE /api/audit/archive` endpoint path is unchanged (still one statement).
- **A-4** per-batch wall time (ms) in `TaskPrune.BatchMilliseconds` and each row pass's `Progress.BatchMilliseconds`, and in the pass log lines. No EXPLAIN captured (no desktop DB access from this lane).
