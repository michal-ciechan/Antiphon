## Defects

### D-1: the witness reads a fixed 25-line window, so an ungated test passes when the next test is gated
- **Where:** `scripts/test-rc-platform.ps1` `Test-RowGated`, class branch (`$slice = Window $lines $def 25`). The method branch has the same problem with `Window $lines $def 30` and helper windows of 20/25 lines.
- **Failure:** I removed `NativeLinuxGate.Require` from `GrokSha256PinTests.Runner_grok_sha_rejects_multiline_pin` (line 27) in a scratch copy of the tip. `every-new-row-has-linux-gate` still **PASSED**. The window from line 25 reaches line 35, the next test's gate. On Windows the class row then drops a test that runs there. That is a hidden Windows-running test, and the witness reports it green.
- **Why:** 25 of the 45 rows exclude whole classes. The witness is the only standing proof that every test in those classes is Linux-gated, and most of them have short tests packed together.
- **Fix:** limit each slice to the method's own body: stop at the next `[Test`, `[Before` or member declaration, or match braces. Add a synthetic red row that puts an ungated test before a gated one, beside `ungated-class-refused`.

### D-2: the witness accepts gates that are present but conditional
- **Where:** `$strict` in `Test-LinuxOnlyWindowsExclusions` (`scripts/test-rc-platform.ps1`).
- **Failure (M2):** I changed `CheckpointRecoveryLinuxTests.Linux()` (line 248) to `if (OperatingSystem.IsLinux()) return true; return File.Exists("C:\\tools\\wsl-sh.exe");` with no skip. The witness **PASSED**: the `if (IsLinux()) return true;` alternative matches by itself, and on Windows those 10 tests would run whenever the tool exists.
- **Failure (M3):** I changed `NightlyProbeSupervisorTests` line 13 to `if (Environment.GetEnvironmentVariable("X") is null) NativeLinuxGate.Require(...)`. The witness **PASSED**, because any occurrence of `NativeLinuxGate.Require` or `Require*Linux(` counts, even when it sits under another condition.
- **Why:** the brief's standard is that every exclusion must be provably Linux-only. A gate that depends on a tool or an environment variable is exactly what the witness was meant to refuse.
- **Fix:** accept the `return true` shape only when the Windows path ends in `Skip.Test` or `throw SkipTestException`. Require the gate call to be an unconditional statement at the top of the method body or `[Before(Test)]`, not nested in an `if`. Add synthetic red rows for both shapes.

Controls that correctly went red: removing `RemoteScriptContractTests` line 1877 (method row) gave FAIL `ungated C1008_Recycle_exact_default_volumes`. Making `CheckpointSourceGitBoundsTests` line 20 a compound condition (`!IsLinux() && !File.Exists(..)`) gave FAIL `ungated@17`. All mutations were made in a scratch `git archive` copy; the subject branch was not touched.

## (3) What an exclusion does

An excluded node is removed from both the required UIDs and the launch plan (`Get-NightlyDiscoveryIndexView`, `Get-NightlyProfileLaunchPlan`, release-authority `Get-ReleaseAuthorityRequiredUids`). `ConvertTo-NightlyCoverageVerdict` (nightly-coverage.ps1:997) does not filter by exclusion. If an excluded identity is ever launched and fails, `failed-row` still fails the gate. An excluded test is simply never run on Windows. That is equivalent to running it only because every gate above is unconditional, which is why D-1 and D-2 matter. Release authority always applies the `windows` rows (release-authority.ps1:231), so these rows lower the release obligation itself.
