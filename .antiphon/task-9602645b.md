## Brief checks

1. **PID reuse, both directions.**
   - Both sides read the same source. The PowerShell client sends `(Get-Process).StartTime.ToUniversalTime().ToString('o')` (`scripts/lib/build-slot.ps1:78`). The checkpoint `LeaseHolder` sends `child.StartTime`, formatted `"O"`. The broker reads `Process.StartTime.ToUniversalTime()` (`ProcessLivenessProbe.cs:94`).
   - If a request carries no start time, the broker records its own reading.
   - On Windows, `'o'` keeps 7 fractional digits, which is the full 100 ns precision of FILETIME. The local-to-UTC round trip happens inside each process, and the DST ambiguity flag survives it. The match is therefore exact.
   - On server2 Linux I measured two separate processes reading pid 1's start time: they differed by 1.4 ms.
   - STJ parses the trailing `Z` as UTC, so there is no timezone shift.
   - Live-looks-recycled (early reap): only possible with a mismatch over 1 s, and that just restores today's TTL reap.
   - Recycled-looks-live (leak): needs a new process on the same pid starting within 1 s of the old holder's start. The old holder must have exited inside that second, after it took its lease. That is negligible.
   - The new rule is stricter than the 2-minute one-sided `IsAlive` tolerance used before the TTL.
2. **Unreadable start time.** `TryGetStartTimeUtc` returns null on any exception, so the lease is reaped at the TTL. A live holder owned by SYSTEM or another user, whose handle the broker is denied, still lives 90 minutes (`IsAlive` returns true on access denied) and is then reaped. That is today's behaviour, not a regression.
3. **New leak risk.** Quantified in A-1. Escape hatches exist, so this is not a D-n.
4. **Lock.** The probe runs under `_gate`. That was already true: `HolderAlive` calls `IsAlive`, which does `GetProcessById`, for every in-TTL lease on every sweep and acquire. A kept lease costs the same single probe per sweep. No new stall class.
5. **Logged-once flag.** `KeptPastTtl` is one bool per lease and goes away with the lease, so it is bounded.
6. **Callers.**
   - `build-slot.ps1` and `run-checkpoint.ps1` (through `lib/build-slot.ps1`) send the full-precision start.
   - The checkpoint tool's `ProcessLeaseHolder` sends `"O"`.
   - `launch-rc.ps1` wraps the whole `nightly-run.ps1` in one `build-slot.ps1` lease (line 64), so the qualification lease is exactly the case this fixes.
   - A client that sends no start gets the broker's own reading, which is an exact match.

## Advisories

- **A-1: no absolute bound, and the escape hatch is undocumented.** The holder for `build-slot.ps1` is the wrapper's own pid, and the wrapper waits on its command with no deadline. Before this change, a hung or orphaned wrapper on the desktop (pid mode) had its slot reaped after 90 minutes. Now it holds the slot until someone acts.
  - Ways out: `DELETE /build-slots/{leaseId}`, which has no auth on the runner loopback; killing the wrapper pid; or restarting the runner, since leases live in memory.
  - Visibility: `GET /build-slots` shows `holderAlive: true` with a past `expiresAtUtc`, and the broker logs `kept past its ttl` once.
  - Checkpoint-tool rows are bounded by their row deadlines, and the hold child dies with its parent.
  - Recommendations (optional, separate card): add a `LeaseMaxHoldHours` setting above the 30-hour qualification run (for example 48, or 0 to disable). Also name the DELETE escape hatch in the Build slots paragraph.
- **A-2: no producer-to-recipient witness of the real start-time path.** Every V-n uses `FakeLiveness`, with the request start equal to the fake's start. No test sends the real client string through JSON to `SystemProcessLivenessProbe` and checks it is within 1 s.
  - A mismatch could only fail in the harmless direction (reaped at the TTL), so this is not a D-n.
  - Suggested cheap witness: `BuildSlotTestHost` with the real probe and a `FakeTimeProvider`, plus one real `build-slot.ps1` wrapper. Advance 91 minutes, sweep and expect the lease kept; then kill the wrapper and expect a reap.
  - No PC can close this gap.
- **A-3: the platform-neutral rule is acceptable.** The server2 runner container's own `/build-slots` is pid mode but has no live clients, because they use the renew broker at `ANTIPHON_BUILD_SLOTS_URL`. On Linux the start time derives from boot time, so drift over hours could exceed 1 s. That fails toward a reap, not a leak.
