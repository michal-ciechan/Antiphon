## (b) Revisited less often, same revision is safe

`StampHeldAttemptAsync` (`BlockedTaskParkingService.cs` lines 165–176) requires a non-empty reason of at most 64 ASCII letters, digits, or underscores, then updates a row matching `Id`, `Revision`, and `State == Held`. It writes `NextAttemptAt`, `ReasonCode`, and `UpdatedAt`. It does not change `State`, `Revision`, `HeldFromState`, or any receipt column, so the write cannot release a row and cannot skip a later check.

`HeldBackoff` (lines 178–184) returns null for `park_workspace_reserved` and when `ReclaimHeldBackoffSeconds` is not positive. Otherwise it returns now plus that many seconds. The default is 600, the existing S3 backoff. The seat gate (lines 84–87) skips prepare only when `State == Held` and `NextAttemptAt` is still in the future. When the due time arrives, prepare runs in full.

While sweeps run, a Held row with a positive backoff is prepared at most once per window and is prepared again after the window. The number of windows is unbounded, so the row is not held forever. This run's C1135 console shows the due refusal wrote (`statementsDue=40`, `statusDue=0`) and the follow-up inside the window did not (`statementsFollow=32`, `statusFollow=0`, `UpdatedAt` unchanged). `park_workspace_reserved` stays immediate (null backoff). That is the existing immediate path.

Keeping the revision is safe for the CAS consumers:

- The stamp matches `State == Held`, so it cannot rewrite a Requested, Released, or Parked row.
- `PersistIntentAsync` (lines 312–320) matches `Id` and `Revision` only, after the task and session lock has reloaded a Requested or Held row with no receipt. A stamp that keeps the revision still lets that update match. Persist then sets Requested, clears `NextAttemptAt`, and bumps `Revision`. Persist wins.
- A stamp after that persist misses, because the revision moved and the state is no longer Held.
- `PersistStateAsync` matches the expected state, checks `Allowed`, and bumps the revision.
- `AcceptAsync` matches `State == Requested`.
- None of those predicates read `NextAttemptAt` or `ReasonCode`. Two stamps at the same revision are last-write-wins on the same three columns.

`HoldAsync` (lines 358–362) stamps when the in-memory state is Held and otherwise calls `PersistStateAsync` from the row's real state to Held. `Allowed` (lines 216–224) admits Requested→Held and Published→Held. The seat-release path already persisted Published→Held. A publication `HoldAsync` that used to pass expected Requested wrote nothing for a Published row; it now holds that row.
