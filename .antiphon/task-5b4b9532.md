## 1. Exit_while_detached_survives_adoption — product race, fixed

A detached host closes the runner pipe and listens again (`NamedPipeServerStream`, max instances 1, pipe `/tmp/antiphon-pty-{sessionId:N}`). `Connect()` can be accepted by the socket that is already closing. The hello read returns null. `PtyHostClient.ConnectAsync` threw `InvalidOperationException` (`Expected helloAck, got EOF`) and did not retry, because that exception was outside the existing retry filter.

`AdoptOrphanedHostsAsync` had already logged the live host. The failed connect then took the exhausted-connect path: `KillPidBestEffort` (SIGKILL; the kill is unbound, so there is no "Host exiting" line), `CreateAdoptedExited` deleted the manifest, and `adopted` stayed 0. `Exit_while_detached_survives_adoption` asserts `ShouldBe(1)`. The pass path is a second connection that reads status `Exited`, increments `adopted`, then takes the shutdown ack.

This is not a false-dead probe, not the 72s linger, and not Adopt's 5s timeout (failures returned in about 0.1s). Sibling PID overlap is not the cause: `ProcessSpawnLimit` serializes spawn tests. CARD-0490 still holds: do not slice `Connect()` into short cancels.

Classification: product race. The bundle makes the EOF common. Solo under CPU load did not.

## 2. Native_exit_reaches_database_and_api(0,23) — test budget, fixed

`Card1619NativeExitFixture.CaptureAsync` wraps the whole start and exit in one `CancellationTokenSource`. It was `TimeSpan.FromSeconds(10)`.

`StartAsync` order: `LaunchDetachedAsync` (product `PtyHostLaunchTimeoutSec` default 30), `ConnectAsync` (`PtyHostConnectTimeoutSec` default 15), launch RPC, then `AttachAsync(0, ct)`. `PtyHostClient.RequestAsync` awaits `_requestGate.WaitAsync(ct)` first (line 169; the qualification stack named the pre-fix line 165). A cancel there means the caller token was already cancelled when attach began: launch + connect + launch RPC had consumed the 10s, and the next await reported `TaskCanceledException`. It is not the following reply wait. The fixture builds `Antiphon.SessionRunner.SessionRunnerSettings` with only `SessionLogPath`, `PtyHostLingerHours = 0.02`, and `CpuWatchdogEnabled = false`, so launch and connect stay 30 and 15. That type is not the server `Application.Settings` type.

Qualification shape (review `6399a4f7`, tip `19cc96020c316bfec21dc000c7f8a807d9726313`): named selection 143 total, 142 passed, 1 failed, 6m 43s. The same test passed 8/8 twice alone. No database work had started.
