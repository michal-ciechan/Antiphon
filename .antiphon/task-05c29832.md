## Defect (verdict)

**D-1. The connection string is put on a child command line.**
- Where: `scripts/cutover-postgres-server2.ps1:230`, `& dotnet user-secrets set 'ConnectionStrings:DefaultConnection' $raw --id ... --project ...`.
- Failure: in phase 4 the full string, including `Password=`, goes into the argv of `dotnet`. Any local process can read it from the process list (Win32_Process CommandLine, /proc). Process-creation auditing, Sysmon or EDR can also log it. `Out-Null` hides only stdout.
- Why: the CARD-1401 design (line 290) says the scripts "do not accept the password as a command-line argument". Brief check (4) lists "placed on a command line" as a leak.
- Fix: give the value to `dotnet user-secrets set --id aspire-antiphon-apphost --project <AppHost csproj>` on stdin as a JSON object `{"ConnectionStrings:DefaultConnection": "..."}`, built with ConvertTo-Json. First confirm that stdin mode merges keys and does not replace the store. Otherwise merge-write the user-secrets `secrets.json` atomically. Add a test that shadows `dotnet` with a fake. The fake records its argv and stdin. The test asserts that the sentinel password never appears in argv.

## Disclosed (not verdict-class; fix in the same Code round where cheap)

- **X-1. The AppHost watchdog is not suppressed during the window.** `-StopOnly` releases the restart lock (correct per brief (2)), so the stack is down with no lock. The cutover never runs `scripts/set-apphost-maintenance.ps1`. "Antiphon AppHost Watchdog" fires every 2 minutes. After three failed rounds, and outside its 15-minute cooldown, it runs a full `restart-apphost.ps1` on the old string. That can happen during the dump, copy, restore or verify phase, or after the desktop container is stopped. Phase 3's live count comparison would probably catch writes made after the dump. Even so, the window is unguarded. `docs/apphost-runbook.md:225` already prescribes maintenance mode before deliberate downtime. Fix: enter maintenance before StopOnly and `-Clear` it after the phase 4/6 restart, or make the cutover hold the restart lock itself.
- **X-2. Stop gate 6 is printed but not evaluated.** The WhatIf text says "if the new database has rows the old desktop volume lacks, the script stops and the operator chooses". `Invoke-CutoverRollback` (lines 301-312) never compares the two databases. It starts desktop postgres, removes the secret and restarts, so any rows written to server2 after phase 4 are silently abandoned. Brief check (6) asks that gates are real. Fix: compare server2 against the desktop volume (the phase 3 queries) before the repoint, and refuse unless an explicit operator flag is given. Or make the WhatIf text say that the operator owns this check.
- **X-3. The plaintext dump goes to server2.** Line 396 copies `$dump` (plaintext) with scp, not `$encrypted`.
