## Advisories (not defects)
- A-1: The guard checks visibility, not this scope. When a child script is invoked in-process with `&` from a parent that already loaded the library, the child skips the load. Its functions then read the child's own script scope, where `$script:TestPhaseVariableNames` is empty, so Remove-TestPhaseVariables strips nothing. A toy probe confirmed this (parent [a,b], child []). No production entry point does this: nightly-tests.ps1 and summarize-test-phases.ps1 run as separate processes. nightly-tests-impl.ps1:8 already had the same pattern at base.
- A-2: If the load throws partway through, `$script:TestPhaseEvidenceLoading` stays true and every later load returns silently. The base had the same effect, because it set the flag at the top of the file.
- A-3: nightly-run now loads the library on every run, including runs that pass -TimingRoot or -SelectionAttemptPath. That is about 2 s once per process on Linux, plus temp warmup files. This is negligible for the overnight run.
- A-4: The master port should be a cherry-pick of 1cad5926b, not a branch merge.
