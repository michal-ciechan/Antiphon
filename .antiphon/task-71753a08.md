## Code review

(a) Authorization and exposure. The route is mapped on the same `/api/hosts` group as `GET /api/hosts` and `PUT /api/hosts/{hostId}/budget`; none of the three carries `RequireAuthorization`, and the server's operator-token protection applies only to the slot release, shutdown and dashboard routes, so the new route sits under exactly its neighbours' exposure. Unknown hosts: `HostBudgetService.EffectiveAsync` -> `RequireKnown` -> `NotFoundException` (404, code `not_found`) before any query; known ids are `local` plus the configured runner ids, which `GET /api/hosts` already lists, so there is no enumeration gain. Body: stored counters, `inventoryState`, timestamps and `inventoryReason` (see disclosure 3); no token, secret or path. Bounds: `limit` omitted is 500, clamped to 2000 and echoed; `limit < 1` is 400 `limit_invalid`; non-numeric or overflowing `limit`/`from`/`to` is a framework 400; default window is 24 hours; a reversed window is 200 with an empty list; `AsNoTracking`, `Take(applied)`, no `SaveChanges`; POST is 405 (tested). The query window itself is unbounded by date but the table is pruned at 14 days (S2) and the result is capped, and `AppDbContext` has the `(HostId, SampledAt)` index.

(b) Settings. `server/appsettings.json` `Attention` block: `SeatWatchEnabled true`, `SeatIdleWarningMinutes 30`, `SeatIdleErrorMinutes 180`, `OccupancySampleIntervalSeconds 60`, `OccupancySampleRetentionDays 14`, `InventoryTimeoutMs 3000`. Each equals the `AttentionSettings` default and sits inside `AttentionSettingsValidator` (warning > 0, error > warning, interval 10..3600, retention 1..365, timeout > 0); options are bound with `ValidateOnStart` (`server/Program.cs:207-210`). `docs/bootstrap.md` lists the same six values and names `SeatWatchEnabled` as the rollback.
