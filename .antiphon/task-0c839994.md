## Residual windows (exact)

A-B-3, Linux. The hash descriptor is fstat'ed before and after the read (size, mtime, ctime, inode, device); the
unlink re-stats the name against the post-hash stat. Remaining:
1. a write landing between the unlink-time `statx` and `unlinkat` — two adjacent syscalls on the same directory
   descriptor, no user code between them (microseconds);
2. a write during the hash that keeps the size and falls in the same coarse clock tick as the file's previous
   change already seen by the pre-hash stat (kernel timestamps use the coarse clock: one jiffy, 1–10 ms; 4 ms at
   HZ=250), so ctime/mtime do not move;
3. a writer that keeps its descriptor across the unlink and writes afterwards writes into an unlinked inode — a write
   after the last check is unavoidable without locking.
Renaming the file into a quarantine first does not close these: an open descriptor writes to the inode whatever its
name (the set-aside rename already fences path opens). What would close 1–3 for writers already open: take
`fcntl(F_SETLEASE, F_RDLCK)` on the hash descriptor — it fails EAGAIN while any writable descriptor exists, and a
later write-open blocks until the lease is released after the unlink. Not implemented here (owner/CAP_LEASE, file
systems without lease support, SIGIO handling).

A-B-3, Windows. The delete-time hash shares no write: an existing writer makes the open fail (sharing violation →
the walk refuses, set-aside held) and none can write while it reads. Residual: a writer opening between the hash
handle's close and `MarkDeleted` (the outer no-follow handle shares write). Not executed natively.

A-B-7. Only files whose raw blob differs go to `git -c core.safecrlf=false hash-object -- <paths>` in the tree (100
per command), so attributes, eol and clean filters apply exactly as `git status` applies them (a configured clean
filter command runs, as it does for status). The raw SHA-256 receipt manifest still binds every deleted byte; a
change between the raw read and hash-object is caught by BindContent's before/after manifest.

B-B-1 mirror. The gate is read after the last await in our code. `PhoneHomeRunnerClient.RemoveWorkspaceAsync` →
`RequestAsync` may still wait on the connection's send path before the frame is written; a flip during that wait is
not re-read, and a sent removal cannot be recalled. The peer witness proves sent/not-sent only.
