## Defects

**D-1 (adequacy). The root-exit composition and its fail-closed rule have no witness.**
- Where: `src/Antiphon.Agents.Pty/PtyAgentRunner.cs` `RootExitedForHangup` (lines 362-371). The tests
  are `Card1681PtyHangupTests` (pure classifiers only) and `LinuxCustodyReleaseHostTests` C1681 x2.
- Failure: three mutants of the method all stay green under `/*/*/LinuxCustodyReleaseHostTests*/*`
  (9/9). The CP-7 unit class does not call this method.
  - M2 drops the /proc signal (`return ProcStatShowsExit(stat)` -> `return false`).
  - M3 drops the runner-exit signal (`_exitTcs.Task.IsCompleted && false`).
  - M5 turns an unreadable stat (IOException/UnauthorizedAccessException) into "exited"
    (`return false` -> `return true`). This fails open: an EIO while the root is alive would read
    as end of output, which is the exact rule the card says must hold.
- Why: in `C1681_Eio_after_root_exit_drains_to_receipt` either signal satisfies the condition, and
  which one does depends on a race. The EIO is raised by exit_files and can win the race against
  Porta's waitpid exit event, so production needs the /proc fallback. A removal would bring
  CARD-1681 back intermittently, and no test would catch it. Nothing exercises the stat-read
  exception mapping (FileNotFound/DirectoryNotFound -> gone, IO/permission -> alive). The worker's
  own handoff flagged this: neither signal is witnessed alone.
- Fix: put the composition behind a seam, for example
  `internal static bool RootExited(bool exitObserved, Func<string?> readStat)`, with the stat reader
  mapping exceptions as today. Add pure tests for each case:
  - observed + live stat -> true;
  - not observed + Z/PF_EXITING stat -> true;
  - not observed + live S stat -> false;
  - not observed + reader throws IOException -> false;
  - reader throws UnauthorizedAccessException -> false;
  - FileNotFound/DirectoryNotFound -> true.

  Commit them red-first against an inert stub. M2, M3 and M5 must each turn red.

## Safety answers (no defect)

(1) S3 EIO-as-EOF:
- Cannot make a receipt claim Exited for a non-empty tree. The drain only changes "drain failed"
  to "drained". Every explicit and ordinary path re-reads `ReadActive` and returns
  Exited/`PersistExited` only when the count is 0 (HostCustodyJournal 147-157 and 243-252).
- The decision applies only on the Linux custody lane (`_custody` and `_containment` set). The
  type must be exactly IOException and HResult must be 5.
- PID reuse needs no start-time check. conn.Pid is the runner's own forked child (the shim execs
  into it), so the pid can be reused only after that root has been reaped, which means it has
  exited. A reused pid reading Z/X/gone therefore states a true fact, and a reused pid reading
  alive only fails closed.
- The stat parse is correct: it parses after the LAST ')'. fields[0] is the state (field 3) and
  fields[6] is the flags (field 9). PF_EXITING is 0x4.
- What the drain feeds: the `OutputDrained` flag and the audit/transcript tail, not per-read child
  accounting. Any tail the kernel buffered arrives before the EIO.

(2) S2 backoff:
- k=1 gives 1 s and k=6 gives 32 s; k>=7 gives 60 s through the ternary before the shift, so the
  shift count is always 0..5 and C# masking cannot occur. k is only ever >=1 when evaluated.
- `int` failure-count overflow would need about 2^31 attempts at 60 s each, so it is not reachable.
- The clock seam is inert: the default is `TimeProvider.System`, the setter refuses once `_conn` is
  set, and only the internal HostSession pass-through calls it.
- After a success the kill never runs again. W1 covers this: 10 reads over 90 min give 1 Terminate,
  Draining every time and no receipt. The receipt carries the last real attempt (W2: error 3).
- Throw or null counts as failed (`finally`, W4).
- Concurrent ticks: Seal/Observe both hold `_writeGate`, a SemaphoreSlim(1,1), so `TerminationDue`
  plus its stamp are serialized and the kill runs at most once per due window.

(3) Windows branch: sha256 of `var modern = (ModernConPtyConnection)_conn!;` through the method's
`finally { _writeGate.Release(); }` is
2fd1ec493d80b8038c32994e9bcae1742057e369498ce7cc0a62db9d2c712e9a at both bcfe77b3d and fc709c938
(10 lines). The read-catch change is gated on `_containment`, which only the Linux branch sets.

## Advisories
- A-1: `/proc` absent or mounted with hidepid (root under another uid) gives
  DirectoryNotFoundException, which is treated as "gone". That fails open toward EOF. The effect is
  limited to OutputDrained, because tree accounting still gates the receipt. Consider requiring
  `/proc/self/stat` to be readable before trusting a missing entry.
- A-2: A root that detaches its stdio and then lives (or whose leader thread exits while other
  threads live) is a liveness gap. The EIO decision is taken once, at EIO time. While the root is
  alive this is a permanent drain failure, so that tree never receipts (it stays Unknown). This
  follows the stated design. A survivor that reopens /dev/pts/N after the EIO would also go
  unread. Neither case affects safety.
- A-3: `PtyAgentRunner.UseCustodyClockForTests` is `public`, matching `UseContainmentForTests`. It
  could be internal.
