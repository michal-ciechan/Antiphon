## Verdict

**The safety core holds, but the plan is not ready for Code. Next: plan.**

These parts are fail-closed in the right places:

- The publication predicate is content-derived and keeps the whole existing location closure: refs,
  reflogs, pseudorefs, stash, annotated tag objects and linked admins (D-2).
- The audit helper runs offline. Credentials stay on the host. A private origin the host
  cannot read refuses. A non-auth error is never treated as authorization (D-6).
- A volume is bound by its whole incarnation tuple and daemon identity, under locks.
- The out-of-protocol privileged-writer race is stated honestly.
- Deletion is an exact-name `docker volume rm` with no force and no Compose `down -v`. Each delete
  has a durable intent and a result, with DryRun, resume and partial states (D-7, D-8).
- Drain, retirement and zero-session checks are kept (D-13).

What blocks Code:

- The checkpoint table does not import.
- The plan predates CARD-1607 landing on master and rc.
- The plan never addresses the real failure modes the brief named.
- It is missing the rollout, rc-port, roster and doc-pin obligations.

- Fix:

**D-5: Transient census failures are unhandled** (D-3 safety row, D-8 step 5, J6).

## Advisories

- **A-1.** D-5 moves runner-tmp to `/tmp` inside the helper. The runner image has `/tmp` content
  that Docker copies into an empty volume on mount (CARD-0827), and the current helper mounts
  (`c590-remote.sh` c1008_audit) do not set `volume-nocopy`. Require `volume-nocopy` on every
  helper volume mount, and have N1 assert that an empty target stays empty. I did not verify
  whether `readonly` alone suppresses the copy.
- **A-2.** In the scripted path, auto-preview then apply runs two full content audits back to back
  (each up to the 10800 s cap). Put a production-phase estimate in the budget.
- **A-3.** The host proof does a fresh blob:none fetch of each origin per phase on the desktop. An
  object cache that only ever receives origin objects is safe to reuse if ref tips always come
  from the fresh advertisement. Measure before adding one.
- **A-4.** Apply `scripts/check-os-witnesses.ps1` if Code adds any OS-selected branch (the Windows
  wrapper and host proof vs the Linux coordinator); the plan does not mention it.
- **A-5.** Plan task `dcbf1d18` shows status Failed on the server, even though its plan is
  complete at `ae1e87f8`.
