## Defects

**D-1: the entrypoint can still exit non-zero and stop the runner.**
- Where: `docker/session-runner-grok/dind-entrypoint.sh:181-183`.
- Failure: after `set -e` is restored, the failure branch runs a bare `rm -f /run/antiphon-custody/namespace`.
- Scenario: a regular marker exists (it persists in the writable layer across a `docker restart`) and cannot be unlinked (EROFS, an immutable file, a ro bind). The inner boot fails, then the outer `rm` fails, so the entrypoint exits 1 before dockerd starts. With `unless-stopped`, the container loops on restart.
- Reproduced by harness case `stalemarker_runro`: `rm: cannot remove ... Read-only file system`, entry_rc=1.
- Why it matters: plan D-17 says a namespace failure must never stop the runner.
- Fix: `rm -f -- /run/antiphon-custody/namespace 2>/dev/null || true`, or move the removal into the guarded child. Add a test that executes the real entrypoint step (see D-3).

**D-2: the managed tree reader is not namespaced, so it reports a fabricated zero.**
- Where: `src/Antiphon.Agents.Pty/IPtyCustodyContainment.cs:178-184` (`TreeProcsPath`), used by `ReadTreePids` at `:121-130`. `ResolveProcsPath` (`:168`) has no production caller.
- Failure: helpers now place trees at `antiphon-custody/<ns>/<id>/tree`, but `ReadTreePids` reads `antiphon-custody/<id>/tree`. Both the file and its directory are absent, so it returns `[]`. `ReadActive()` therefore reports 0 for a live tree.
- The native fixtures (`LinuxCgroupCustodyTests.ActiveHierarchyMembers` and `ReadTreeAsync`) use the same global path. So NP-12 and NP-38 cannot pass on a HEAD image.
- CP-45 (`C1614_Namespace_identity_cannot_cross_container_roots`) only formats strings from an unused static. It cannot go red for production.
- Why it matters: plan §Root isolation and A3b say every helper and managed resolver must agree, with no fallback to the global root. If qualification were turned on, natural finality would certify live descendants.
- Fix: resolve the namespace from `/run/antiphon-custody/namespace` or `linux-namespace.json` in `TreeProcsPath`, and treat a missing or invalid namespace as Unknown or a throw, never `[]`. Point the native fixtures at the same resolver. Re-witness through `ReadTreePids`/`ReadActive`.

**D-3: the boot-failure witness is a stub.**
- Where: `docker/session-runner-grok/antiphon-custody-common.sh:123-127` and `tests/Antiphon.SessionRunner.Tests/CustodyNamespaceBootstrapTests.cs:51-57`.
- Failure: any third argument makes `custody_namespace_boot` print `continued=yes` and return 0. The "failed setup continues" arm asserts exactly that constant. It never runs `dind-entrypoint.sh`, its `set +e`/status/marker handling, or a sentinel runner.
- Deleting `set +e` from the entrypoint, or D-1 itself, stays green.
- Why it matters: plan V-19 asks for "failed setup continues a sentinel runner"; this test cannot go red.
- Fix: extract step 3b into a testable function or script that the entrypoint calls. Drive it with real failing filesystem inputs (as in the harness above) and assert the sentinel continues. Remove the `fail_step` hook from the production library.

**D-4: NP-35's method was never added, and the population and drain fixes have no executing witness.**
- Where: the plan's NP-35 and NP-38 rows name `LinuxCgroupCustodyTests.C1614_Populated_tree_refuses_entry_and_drain_success`, which does not exist.
- No test calls `custody_procs_populated` or `custody_drain`; CustodyHelperContractTests is text-only. Restoring `[ -s ]` in the shared function leaves every committed test green.
- The plan said: "Do not collapse extraction/population repair and lose NP-35". The witness-before-fix ordering is lost, and NP-38 (`--min-executed 7`) cannot pass.
- Fix: add the method as the plan specifies. Add a portable private-filesystem test of the shared reader and drain, with an empty, a populated, a size-0-populated and an unreadable case. The caller rules on how NP-35's RED provenance is recovered, for example by running the new method against `238601a0` helpers.

**D-5: the native namespace-collision witness is a tautology.**
- Where: `tests/Antiphon.SessionRunner.Tests/LinuxRunnerCustodyLifecycleTests.cs:33-52`.
- Failure: it boots two private state directories, then asserts that two strings formatted from two different GUIDs differ. It runs no probe, no helper, no same-GUID launch, no container restart or recreate, and no failed-setup health check.
- Why it matters: plan NP-36/NP-39 require same-GUID probes and launches in two live namespaces, plus a recreate with a reused volume. This cannot go red once boot works.
- Fix: implement the plan's two-container procedure, or mark NP-36/NP-39 explicitly unwitnessed.

**D-6: the kill helper still SIGKILLs an unfrozen tree.**
- Where: `docker/session-runner-grok/antiphon-custody-kill.sh:104-116`.
- Failure: if the freezer write fails, `freeze_failed=1` but the PID sweep still runs. It refuses only afterwards. A missing `freezer.state` skips freezing silently and kills.
- Reproduced in the harness: `freezefail` gives rc 3 with the victim killed; `nofreezer` gives rc 4 with the victim killed.
- Why it matters: plan P-2 says a failed freeze or a missing v1 freezer is a refusal; "never silently fall back to an unfrozen PID sweep". Unfrozen, a PID read from the tree can exit and be reused by an outside process before `kill`.
- Fix: refuse before reading or killing when the freezer is missing or the freeze fails. Keep the owned thaw after a successful freeze.
