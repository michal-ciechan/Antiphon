The two sides read the method name from different sources:

Checked against real formats:

## (3) The missing or empty node list rule

- Confirmed: a missing node list, a `$null` one or an empty `@()` one all mean the whole class. So a chunk of a failed class with no usable node list is priority 0.
  - Code: `hasNodes` is set only by a node that has a non-blank class and method, `nightly-stopped-run-seed.ps1:494-512`.
  - Covered by the committed case `bare` and by 819 empty and 823 null node lists in the property test.
- A node list where every node lacks a method also falls back to the whole class.
- A present but truncated list cannot come from the packer (see the last row of the table in (2)). See A-4.

## (5) Is the sibling band where the operator's rule wants it?

**Yes, in substance.**
- "Failures first" means the failing tests, and that is band 0.
- "Oldest things which have not run" is band 1.
- Siblings come next. They are not failures and, at class level, mostly ran, so placing them before passed chunks is a harmless "affected" preference.
- "Affected lanes only since last rc run" is about lane selection, not this ordering path.

One nuance is advisory A-2.

## Advisories (cards, none blocking)

- **A-1 (test adequacy).** M4 survives all three committed cases.
  - Cause: the `vanished` case in `scripts/test-nightly-stopped-seed.ps1` (FailedMethodBands) has no passed chunk after `r0..r2`, so it cannot tell band 2 (sibling) from band 3 (passed) for a class whose failed method was renamed away.
  - Fix: add a completed `ok` chunk of another class, canonically before `r0` and with the same timestamp. The correct order is then `other,open,ok,r0,r1,r2`; M4 would give `other,open,r0,r1,r2,ok`.
- **A-2 (order nuance).** "Incomplete" is tracked per class, and the sibling band (`nightly-stopped-run-seed.ps1:550`) overrides it.
  - Effect: a sibling chunk of a failed split class that never ran in the stopped run waits behind every other unfinished chunk in all lanes, instead of sorting by age in band 1.
  - The seed has no per-method run record, so the code cannot tell which siblings ran. The cost is a few chunk positions.
- **A-3 (inherited, performance).** `JournalCustodySurvivesInterleaving` takes 163 s alone on server2 against a 180 s budget, and goes red under host load.
  - Its budget should be set to about 2x the measured p95, per `docs/test-performance-standards.md`.
- **A-4 (future guard).** A present but truncated node list that omits a failed method would treat that method as renamed and demote it.
  - No packer path produces one today (verified above).
  - If a future packer emits partial node lists, it should either mark them partial or put the whole class in band 0.
