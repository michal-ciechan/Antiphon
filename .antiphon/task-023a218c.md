## Leak direction

Not a blocker.

- `xxC:secret`, `xc:secret`, a backslash form `xC:\secret`, punctuation (`=C:secret`, `(C:secret`), and quote-prefixed forms are masked.
- Several glued matches on one line mask the whole value (`two xxC:secret and more`).
- Unicode letters plus a colon stay visible. They are not ASCII drive syntax. The preserve tests pin `С:secret`, `Α:secret`, `Ｃ:secret`, and `Å:notes`.
- A glued colon at end of string (`xC:`) and a glued colon followed by a space (`xC: secret`) stay visible, as the card requires.
- A digit after the colon stays visible, including `xC:1` and `build:1`, which the tests pin. `xC:2secret` is the same exception: a drive-relative name whose first character is a digit remains visible when glued. That is the accepted hole, not a new path past the rule.
- `Leaf` still returns an executable basename. A separator-free name such as `xC:secret.exe` is not scanned by `ContainsDrivePrefix`. Directory paths still collapse to the leaf, so the directory is hidden. Unchanged by this commit. Advisory residual.

No regex. `ContainsDrivePrefix` is one forward loop. A verbatim copy of that loop plus the separator/control short-circuit, timed with `dotnet run --file` under the build slot (unlisted; the checkpoint rows do not time it):

- `aC:` repeated to 1,050,000 chars, first match: 0.005 ms
- 1,048,576 chars of non-matching `aC: ` (space): 34.360 ms
- 1,048,576 `a`s: 33.379 ms
- 1,048,576 `x`s plus `C:secret`: 32.993 ms

That is linear. It is not catastrophic backtracking.

Idempotence holds on the samples: the mask constant `[redacted]` has no colon, slash, or control character, and a preserved value is unchanged. There is no separate idempotence test. The projection is pure.
