## (2) A-10 safety

Fresh probe: scratch TUnit 1.44.0 / MTP 2.2.2 project (the repo's versions), `--report-trx`:
- `[Skip]` gives `NotExecuted`.
- A `DependsOn` test whose dependency failed gives `NotExecuted`, but beside a `Failed` row under `ResultSummary outcome="Failed"`, so the chunk still leads (P0). The repo has no `DependsOn`.
- Cancellation writes **no TRX at all**: SIGINT mid-run gives no TRX, SIGTERM gives no TRX (core dump), and `--timeout 6s` gives no TRX (exit 3). A never-started test therefore never appears as a NotExecuted row under a finished summary. The chunk stays unfinished: the TRX is missing and the planned-count check applies.
- `--maximum-failed-tests 1` gives normal rows and summary Failed.
- Summary values seen: `Completed` and `Failed`.

Conclusion: the rule is safe. A failed row and skips still put the failure in `failedTests`, which yields P0; the failure-extraction code is unchanged. Skips under an `Aborted` summary stay unfinished (witnessed).

## Advisories

- **A-1 (precondition for using this on the live restart).** Re-export the stopped-run seed with this exporter before the restart.
  - The old exporter marked every chunk containing an explicit skip as completed=false/started=true. On Windows that includes every chunk that runs `[NativeLinuxOnly]` tests (a `SkipAttribute`, 62 test files).
  - The new resolver reads such rows as **interrupted**. Those passed chunks then go ahead of all untouched work, and each lane "resumes" at its first skip-bearing chunk, not at the real torn one.
