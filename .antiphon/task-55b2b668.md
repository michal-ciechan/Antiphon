## Not-proven item: the new diagnoses and `Test-C1008SafeAuditDiagnosis`

This is not a defect. I read the code and changed nothing.

- `Test-C1008SafeAuditDiagnosis` runs only in `Get-C1008RetireProofExports` (`c590-real.ps1:493`). It reads `inventory-<nonce>/c590-result.json`.
- In the coordinated path, `Invoke-C1609RetirementCoordinator` calls it only after a `C1609_PROOF_REQUEST` line arrives.
- `c1609_prepare_exchange` writes that inventory result only as `{accepted:true,diagnosis:""}`, after the registry export succeeds.
- Every `reason=inventory|registry-*|unapproved-origin detail=…` refusal fires before the proof request. Each one goes through the real `c1008_refuse` → `write_result` into `$CASE_DIR/c590-result.json`.
- The desktop copies that file and rewrites it verbatim at `c590-real.ps1:878`, with no safe filter. `proof-exchange stage=` refusals take the same route.
- So the safe filter never sees these forms, and they carry no URL or `@`: X-8 is now pinned, and `detail` is a `$SERVER2_ROOT` path.
- Pre-existing, unchanged: the uncoordinated `case_retire_temp_inventory` emits `RecycleGitAuditUnknown reason=unapproved-origin`. The safe regex would collapse that to bare `RecycleGitAuditUnknown` at :493. This is CARD-1609 code.
