## Advisories (no Review rerun needed for these alone)
- A-1 `RunnersAsync` matches only the short `WorktreeBranch`, while `PublishedBranchDeletionDependents` accepts four spellings. A task stored with a full or tracking spelling would skip the runner allow-list and the runner ref delete. The worst case is stale runner refs that the CARD-1008 audit counts; origin data is not at risk. Use the same `names[]` in both places.
- A-2 Dependents and `card_not_done` are evaluated before the lease and before a runner step that can take up to 6 minutes. They are not re-checked right before the push. A task queued in that window on `WorktreeBaseBranch=<b>` would fail at dispatch; no data is lost. Re-run `FindAsync` under the lease immediately before saving `Deleting`.
- A-3 The `pending_land_request` term excludes the owner (`r.TaskId != owner`). An owner with a new pending land of the same unchanged branch, for example to another target, would lose its source mid-request. It fails closed, but the term should include the owner unless the request is the op's own.
- A-4 Op 48 returns `Deleted` with "repository absent" when the primary directory is missing (for example, an unmounted volume). That treats "unknown" as absent. Consider `repository_unavailable`.
- A-5 `RunnerRefsDeletedAt` is sticky. After a `delete_push_failed` deferral, a runner that later picks up the branch is not asked again.
- A-6 `card_not_done` treats `Canceled` as not Done, so a canceled card's branches are never deleted. That is the safe direction; record it as an operator note.
- A-7 There is no options validator. Negatives are clamped. A bad cron fails only at startup with the flag on. `.NET` config arrays index-merge across layers: an override of `SourceBranchDeletionRunnerIds` with fewer entries keeps the extra base entries. Document this or validate it.
- A-8 Q-4: there is no revert detection. A reverted land is still deleted after 24 h. Its source commits survive in the desktop land pins, as documented.
