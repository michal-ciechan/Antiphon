## Defects

### D-1 (High): zero-row transcripts are killable, contrary to plan D-10; a live working session can be killed

Where:
- `server/Application/Services/AgentTaskDispatcher.cs:9320-9321` (`missingTurnBoundary`) and `:9433` (recheck).
- `SessionsWithoutTurnBoundaryAsync` `:9559` drops sessions that have no rows.
- The cap arm, `:9229`, has no age floor.
- `docs/session-runtime-invariants.md:249` says "A transcript with no rows ... stays eligible".
- Plan D-10 (`docs/superpowers/plans/2026-10-29-card-1610-failed-task-live-session-plan.md:638`) still says "uncertainty means absent transcript evidence ... cannot prove idle and are also retained".

The code and the plan contradict each other, and the plan was not amended.

Zero rows does not mean idle:
- `src/Antiphon.SessionRunner/TranscriptTailer.cs:607-690`: "Claude creates the file lazily ... a missing transcript is normal".
- The same file has the refusal and no-candidate shapes, including the CARD-0073 "10e30ff7 shape": "a live child that has already been typed at and still has zero cwd-matching candidates".
- In those shapes the tailer stays unbound, possibly for the session's lifetime, and nothing reaches TranscriptEntries.
- Warm Shared delegates share one cwd, which is exactly where candidate refusal happens.
- IsWorkingBatchAsync then reads not-Working.

Concrete scenario:
1. A Shared Claude delegate's tailer is unbound (refused or forked candidates), and the delegate is mid-turn running a long tool.
2. Its agent becomes warm in one of three ways:
   - PoolWarm at settlement (AgentTaskReplyService.cs:2854).
   - MarkIdleForJanitor after a cancel or recovery that did not kill (AgentTaskService.cs:4029, AgentTaskReplyService.cs:2876).
   - A Failed hold released by any later task on the agent (A-1).
3. Then the janitor kills it, either:
   - after PoolIdleRetireMinutes (probe rv-zero-ttl), or
   - as cap surplus with no minimum age (probe rv-zero-cap killed an agent pooled 3 minutes earlier).

The guards do not exclude this:
- StartedAt only proves that a generation exists, not that it is idle.
- The Failed hold covers only a current Failed owner.
- No guard requires positive evidence that no input was delivered.

Why: this is the "unproved idle" class the slice exists to retain ("when unsure RETAIN"). The author's leak argument is a policy trade-off that only Plan can accept.

Fix (recommended):
- Treat a session with zero rows as unproved idle in both passes.
- Bound the leak with detection, not a kill. For example, record the episode the way PooledSessionWorkingPastTtl is recorded, or let positive runner evidence that no input was ever delivered (tailer `awaiting-input`) make the session eligible.
- Keep the six pool tests' intent ("positively idle retires") by seeding a TurnEnd in them: the_janitor_retires_agents_idle_past_the_ttl, the_janitor_enforces_the_per_directory_cap_oldest_first, the_per_directory_cap_skips_a_mid_turn_agent, the_janitor_kills_a_recovered_worktree_delegate_after_the_ttl, the_janitor_keeps_the_row_when_the_kill_did_not_take, and GrokDelegateDispatchTests.the_cap_still_retires_a_surplus_within_one_kind. The last one is outside the S1 CP list, so add it as a row.
- Add arms: zero-row retained at TTL, and zero-row retained under cap pressure.

If the caller instead accepts the author's rule, Plan must amend D-10 explicitly. Exact text:
"uncertainty means a transcript with rows but no turn boundary, an unfinished session (Created/Stopping) outside liveSessionIds, an unavailable fresh runner sample or mismatched generation. A session with no transcript rows is eligible for TTL and cap retirement (accepted risk: a working session whose transcript never bound, CARD-0073 shapes, can be killed at the TTL or as cap surplus)."
