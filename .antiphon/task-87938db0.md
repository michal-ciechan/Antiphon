## Rule now in force (DispatchConcurrencyEditor.tsx)
- **Snapshot identity.** A query cache entry is identified by its data object and its `dataUpdatedAt`. A read of an equal document keeps the same object, so the update time is part of the identity.
- **Which entries are adopted.** Every entry the form has not seen is adopted. The one exception is the `superseded` entry, which is the cache entry present when the PUT reply arrived. It is read from the cache with `getQueryState`, not from props, because observer notifications lag by one macrotask.
- **Why only that entry can predate the Save.** The S1 mutation `onSuccess` invalidation runs before `mutateAsync` resolves. It cancels any read still in flight (`cancelRefetch: true`) and starts a new read after the PUT.
- **Effect.** A failed or held post-save refresh cannot roll back the Save (S2F2). Any later successful read is current, even when its revisions are lower or reused.
- **Revision order.** Revision order (`isOlder`) remains in one place only: between the form's own PUT reply and a read that completed while that PUT was in flight (`late-put-newer-get`).
- **Content changes at the same revision.** `adoptServer` treats a document as changed when its revisions differ, its mode differs, or any cell differs. This covers a reused revision that carries a different document.
- **Dirty draft (D-7).** `rebaseDraft` keeps the cells the operator edited (those that differ from the old saved state) and takes every other cell, plus the mode, from the new document. Raw inputs for non-edited cells are dropped. The banner is shown when there are edits, and its list names the remaining differences. The next PUT therefore never re-sends a value that only the old document held.
- **Conflict reload.** The reload now goes through the same `adoptServer` path, with the banner forced on.
