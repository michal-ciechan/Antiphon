## Why Sequence

`CreatedAt` is when the transcript row was saved. `PhaseStartedAt` is `UtcNow()` when the re-arming prompt's action is processed. A catch-up burst can save the prompt and its `TurnEnd` before that processing, so a `CreatedAt < PhaseStartedAt` guard drops the current turn's `TurnEnd` and the stall scanner kills the idle session 300s later.

A previous turn's `TurnEnd` can also be saved late, so its `CreatedAt` is after the current re-arm while its `Sequence` stays before the re-arming prompt. Dropping the `CreatedAt` guard would let that late save end the current turn. Copying the prompt's `CreatedAt` into `PhaseStartedAt` would move the stall and duration clock and would still treat that late previous-turn save as current. Actions for one session already run in Sequence order, so the current turn is the one whose re-arming prompt Sequence is stored on the real `Transition` (`RearmPromptSequence`). A `TurnEnd` or interrupt marker ends the turn only when `row.Sequence` is greater. The follow-up drop uses the same comparison, so a prompt saved before that `TurnEnd` is processed still re-arms. `PhaseStartedAt` stays the stall and duration clock.

Any stop reason on that current `TurnEnd` returns the attempt to `AwaitingInput`, including `error`, `max_tokens`, `stop_sequence`, `refusal`, and null. The launch `StreamingTurn` has neither the open-wait marker nor an `AwaitingInput` duration, so its `TurnEnd` is still ignored.

Provisional arm writes `OpenInputWait` only when the key is absent. A wait that predates the marker can restore after a slash prompt. An existing marker is left unchanged, so the exact `PhaseDurationsJson` snapshots stay intact. The sequence key is written only on the real `Transition`, not on the provisional arm.
