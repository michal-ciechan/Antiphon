## Diagnosis

The source-level introducing change is d71a4d60fdb1e32ed49e7c6486d2fc49e453a885, `perf(land): one ls-remote for the source recheck and target observation before the push`. Its parent called `RecheckRemoteSourceAsync`, then `RecheckSourceAsync`, then `ObserveAsync`. It now calls `RecheckRemoteSourceAndObserveAsync(..., () => RecheckSourceAsync(...))`.

In `server/Application/Services/AgentTaskLandingProtocol.cs:897`, the combined helper awaits `git.ObserveSourceAndTargetAsync` before calling the local-source `between` callback. That interface's default implementation completes `ObserveAsync` first (`server/Application/Interfaces/ILandingGit.cs:65`); the real implementation completes `PinAndJudgeAsync` before returning (`server/Infrastructure/Git/LandingGit.cs:1510`). Thus target fetch/pinning and ancestry observation occur after a local source/task-coordinate change but before it is refused. Judging the target result later does not preserve the previous observation ordering.

The existing witnesses still reject the source with the expected reason and prevent publication/target advance. They then fail their additional requirement that a source refusal precedes a new publication observation. There is no evidence here of an incorrect push or canonical target mutation. Preserve that distinction in the repair.
