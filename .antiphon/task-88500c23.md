## D-1: the cap proof does not cover failed-test walls or default-priced launches

- **Where:** plan lines 88-92 (S3 budget procedure) and CP-9 `CapFitsAdmittedPlannedCost`.
- **Failure 1: failed-test walls.**
  - A launch whose tests fail at their own deadlines finishes normally with a TRX. Its wall is longer than the healthy model, though.
  - Healthy-only E gives W = 2·E95·P. Example: P = 900 and healthy E95 = Emax = 1. Then the g103 replay (1936 s, which includes a test that failed at 300.0 s) is killed at 1800 s.
  - A small launch shows the same thing. With P = 120, W = 600 s, the floor. Three tests that each fail at a 300 s budget cross 600 s and are killed, which today's 3600 s cap would not do.
  - Either kill turns a precise failure list into timeout/no-TRX "incomplete" and drops the passing siblings' results.
- **Failure 2: unpriced classes.**
  - Classes without a measured row are priced at the 0.5 s/node fallback (1.5 s Slow, ×2 heavy; `nightly-tests-impl.ps1:138-205`). The cost file records a watchdog-killed group 9 running at a 9.2 s/node pace (CARD-1410).
  - The stratum key ("same suite, membership/cost model, source...") is never defined, and neither is a minimum n.
  - So a launch that holds a new unpriced class can get a ratio far above the stratum's Emax and be killed. The alternative reading is that every source change empties every stratum, and S3 never applies.
- **Fix:**
  - (a) Count every complete, non-watchdog wall as an uncensored ratio sample, whatever the test outcome. Or add a failure-tail term derived from the launch's declared per-test deadlines.
  - (b) Define the stratum key and a minimum n. State that any launch containing a default-priced, conservative-bound or unmeasured class, or a membership digest outside a measured stratum, keeps the existing suite watchdog.
  - (c) Add CP-9 cases for the g103-like failed-test replay and for a default-priced class at a 9.2 s/node pace. The rule must not kill either.
  - (d) State where E95/Emax are pinned: the policy/cost file under `policyHash`, not recomputed at run time.

## D-2: the S4 authority integration has no non-release mode boundary

- **Where:** plan lines 100-102 and line 157 (CP-12).
- **Failure:**
  - The integration goes into the shared chain `nightly-run.ps1` -> `nightly-tests.ps1` -> `Invoke-AntiphonNightlyTests`, and it must "refuse incomplete commission/partition before launching".
  - The same chain serves runs with no release intent: the Windmill master nightly, and profile-aware rc Debug/qualification repair runs where `ReleaseIntentPath` is empty (`nightly-tests.ps1:46`, `nightly-tests-impl.ps1:698`).
  - The plan never says which of the following happens:
    - (i) Those runs are refused, which breaks nightly and Debug qualification.
    - (ii) Freezing is silently skipped. A real rc run with a missing or malformed intent could then launch and pack with no authority. That is fail-open, and the error surfaces only at publish time, after a 20 h run.
- **Fix:**
  - Define the boundary explicitly:
    - Release intent present: freeze and write the ledger, or refuse before the first launch.
    - Intent absent: keep the legacy unpacked partition, with no authority and no gate credit.
    - Malformed intent: refuse.
  - Packing must be enabled only when an authority is frozen.
  - Add CP-12 witnesses for both arms, for example `NonReleaseRunKeepsLegacyPlanWithoutCredit` and `MalformedIntentRefusesBeforeFirstLaunch`, and raise the CP-12 floor to match.
