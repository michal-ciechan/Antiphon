## The fix

- **`SessionRunnerSettings`**
  - Null, empty and whitespace-only `PtyHostSocketDir` all mean unset.
  - New `TryResolvePtyHostSocketDir(out dir)` never throws. It returns `GetFullPath` with the trailing separator trimmed. It returns false on `ArgumentException`, `NotSupportedException` or `PathTooLongException`; an embedded NUL is the case that reaches it on Linux.
  - `ResolvedPtyHostSocketDir` now throws `PtyHostSocketDirUnsafeException(pty_host_socket_dir_unsafe)` for an unresolvable value. It used to throw `ArgumentException`.
  - Because the resolved directory has no trailing separator, the launch's `<dir>/<id>` is exactly the path `EnsureSafe` bounds (A-3). The bound counts the UTF-8 bytes of the normalised path plus the NUL.
- **Launch (`StartCoreAsync`).** The `pty_host_socket_dir_unsafe` catch and log now also cover `PtyHostRendezvous.PipeNameFor`. An Owned launch with an unusable setting therefore fails closed before spawn, with the documented code and log line. Legacy never reads the setting, so nothing changes there.
- **Adoption (`AdoptCoreAsync`).** The `pty_host_legacy_socket_path` comparison now resolves through `TryResolvePtyHostSocketDir`. An unresolvable value is treated as "not the legacy comparison" and is not logged. It cannot throw.
- **Client (`PtyHostClient.ConnectAsync`).** The socket-file checks (before connect, and the re-check after connect) and `AcceptPeer(ReadPeer(handle))` (which includes the euid read and the start-time liveness read) now go through `CheckSocketFile` / `AcceptsPeer`. These map any exception to Refused / not accepted, and the result goes through the existing `Unproven`.
  - Under Enforce this is the never-retried `PtyHostPeerRefusedException`. No hello is written, and the sweep's peer arm holds the row as `pty_host_peer_unproven`; the host and its manifest are kept.
  - A proven-hostile peer is still refused without a kill.
  - A null policy (Off) runs none of this code.
- **Doc:** `docs/session-runtime-invariants.md` S2 section (blank means unset, the unresolvable case, proof-step faults are unproven).

**Decisions for Review:**
1. **Observe plus a proof-step fault logs the observe line and connects.** Observe never refuses, and before this change that fault fell to the kill arm.
2. **Exceptions deliberately left to the generic arm** (none of them is a proof step):
   - Connect transport and hello-exchange failures after the retry budget (`TimeoutException`).
   - Faults after a proven peer (the lawful exit path, pinned by `Proven_peer_failure_keeps_the_lawful_exit_path`).
   - The sweep's own cancellation.
   - Custody refusals (I-S2-c; that arm never kills a bound host).
   - Those transport and post-proof cases are today's behaviour; only proof-step faults moved.
3. **The refusal carries no inner exception.** The primary-constructor exception has no inner-exception constructor, so the injected fault's text is not logged. The log keeps the fixed code only.
