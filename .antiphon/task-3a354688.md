## Defects

### D-1. Release and lease destructive git do not prove this slot owns the gitdir

Where: `src/Antiphon.SessionRunner/RunnerWorkspaceSlotPool.cs` `SettleAsync` 350-354 and `ResetForFreeAsync` 461-479; `CheckFreeAsync` 518-521 runs only after that reset (406-406). Lease of an existing slot calls `CheckFreeAsync` (111) then `ResetForLeaseAsync` (249-257) and `ClearWorktreeStateAsync` (491-503). `GitDirectoryAsync` (1142-1147) is `rev-parse --git-dir`. Nothing reads the worktree admin `gitdir` file and requires it to be this slot's `.git`.

Failure: A lessee can replace `<slot>/.git` with `gitdir: <other>`. Release only requires the `.git` file to exist and `rev-parse --git-dir` to succeed, then runs `checkout --force --detach`, `clean` (warm or cold), `update-ref -d` of the task branch, and `File.Delete` of `<gitdir>/logs/HEAD` plus other admin files. Those admin paths are the resolved gitdir, not a path confined to this slot. The parent comparison (`<primary>/.git/worktrees`) runs after that damage on release. It also passes when the pointer names a sibling worktree, because that gitdir's parent is still `<primary>/.git/worktrees`.

Observed on this host, throwaway repos, not product tests:

- Slot A pointed at worktree B's admin directory: `rev-parse --git-dir` returned B. `checkout --force` and `clean` wrote in A's cwd and did not wipe B's dirty tracked file or untracked file. The parent check would pass. `DeleteFile` of `<gitdir>/logs/HEAD` would delete B's reflog, which is what `UnpushedAsync` uses. A later release of B can then miss a reflog-only unpushed commit and wipe B.
- Slot A pointed at the primary `main/.git`, then `checkout --force --detach <sha>`: primary `HEAD` left branch `master` and became detached. Primary dirty tracked and untracked files were not wiped. Deleting `main/.git/logs/HEAD` removed the primary reflog. `update-ref -d refs/heads/taskbranch` from that cwd deleted the branch in the primary repository.

Why: Plan §3.5a (line 319) says a `.git` file pointing elsewhere, during lease, release, reset, cold reset, or retirement, is a broken identity and a quarantine, not a wipe. The only parent comparison cannot go red: with that comparison removed, `/*/*/C0824WorkspaceSlotRe*Tests/*` stayed 21 passed / 0 failed (lease `a4cad690-8376-4b62-b56c-47b38d29784a`, 16.679s). V-34b deletes the `.git` file and is checked at the next lease. V-44 plants sibling directories. Neither retargets `gitdir`.

Fix: Before any `checkout`, `clean`, `update-ref`, or `DeleteFile` in `ResetForFree`, `ResetForLease`, cold reset, retirement remove, and quarantine release, require the resolved gitdir's parent to be `<primary>/.git/worktrees` and the admin `gitdir` file to canonicalize to this slot's `.git`. On failure, quarantine and do not run those commands. Add a witness that goes red when the parent comparison or the back-pointer check is removed.

### D-2. Operator cold reset deletes before the unpushed and free-invariant checks

Where: `ColdResetAsync` 935-945. For a Free slot the code runs `git clean -ffdx` (no keep-list) and only then `CheckFreeAsync`. `UnpushedAsync` is not called on this path.

Failure: Untracked and ignored files outside the keep-list are deleted first. If HEAD is still a published detached tip, `CheckFreeAsync` then passes and the slot stays Free. The same Free slot that `LeaseAsync` would quarantine and preserve (the V-6b late writer) is wiped by an operator or pre-rc `ColdResetAsync`, which reports `cold_reset`. V-28 plants only keep-list native output, so it stays green. This order has no red witness.

Why: Plan §3.12 lines 504-505: a cold reset runs the same unpushed and free-invariant checks; a directory that fails any check is quarantined, never wiped blindly. The leased half is correct: a leased slot only records `ColdResetPending` (V-29; mutant M2 below went red).

Fix: Run `UnpushedAsync` and `CheckFreeAsync` before the cold clean. Quarantine on failure and do not clean. Add a witness that plants a non-keep-list file on a Free slot and expects quarantine with the bytes still present.

### D-3. Drain rebind leaks the slot on the old runner, with no enablement gate

Where: `server/Application/Services/AgentTaskDispatcher.cs` `RebindDrainingAsync` 1166-1195. `RemoteWorkspaceService.RemoveMirrorAsync` 1023-1028 returns null and sends nothing when `RemoteWorkspaceSlotId` is set. `WorkspaceSlotReleaseService.ReconcileAsync` 31-50 then `ReleaseSlotAsync` 227-229 sends `WorkspaceSlotRelease` to `task.RunnerId`. `RunnerWorkspaceSlotPool.ReleaseAsync` 305 throws 409 `slot_unknown` for an unknown id. `RecoverAsync` 1074-1078 does not settle `Leased` when `confirmed` is null; `StartAsync` 1092 calls `RecoverAsync(null)`.

What happens: A queued slot-bound task on a draining runner with an eligible redirect keeps its slot id and generation, clears `RemoteWorktreePath`, and writes `RunnerId` to the new runner. `RemoteWorkspaceSlotReleasedAt` stays null. The reconciler asks the new runner to release a slot it does not have. That 409 is logged and retried every pass. The old runner's slot stays `Leased`. A runner restart does not settle it. A later mirror that overwrites the slot id on the task drops the only server pointer, and the old slot stays leased until the ledger is edited by hand.

Flag-off makes this unreachable today: no slot id is stored, so `RemoveMirrorAsync` takes the legacy path and the reconciler's owed query matches nothing. Enabling either flag does not refuse. `docs/session-runtime-invariants.md` lines 282-315 and `docs/docker-stack.md` lines 685-698 do not say to release the old runner's slot before changing `RunnerId`. The code report's open-question sentence is not a gate or a witness.

Fix: On rebind, release the slot on the old runner id before writing the new `RunnerId`, and only then clear the path. Or refuse `WorkspaceSlotsEnabled` while a drain redirect can move a row that still has a slot id. Add a witness. Do not enable either flag until that lands.
