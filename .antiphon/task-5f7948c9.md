## D-1: an ordinary failing chunk is marked accounting-incomplete, so the Partial sweep refuses its own motivating input

  - `scripts/lib/nightly-failure-history.ps1:395-397`: an accounting-incomplete chunk then adds every class to `unresolved` as `incomplete-chunk`. When membership is unbound, line 400 adds `historical-membership-unavailable` instead.
  - Weakened witnesses in `scripts/test-nightly-failed-first.ps1`:
    - `:88-90`: the 36-failure TRX chunks changed from `exitCode=1` to `exitCode=0`, with the comment "isolates evidence from summary accounting faults".

- **Failure:**
  - The real writer is `nightly-tests-impl.ps1:1457-1460`, plus `:1530` when `testsPassed` is false. It records `result='FAIL'` whenever `ExitCode -ne 0`, and TUnit exits nonzero whenever a test fails.
  - Probe on this tip: a chunk with `exitCode=2`, `result='FAIL'` and a complete TRX (one `Failed` row, one `Passed` row).
    - With a bound plan: the history is `membershipComplete=False` with two `incomplete-chunk` unresolved entries. Full warns UNRESOLVED for both classes and promotes the whole chunk as fallback. Partial throws `prior-failure-sweep-unresolved`.
    - Without a per-suite plan: the history gets `historical-membership-unavailable` and Partial throws again. This is the normal real case, because the writer emits only the singleton `groups-planned.json` (`nightly-tests-impl.ps1:1701`).
    - `exitCode=1` behaves the same way.
  - Mutation check: put the fixture's real shape back (`exitCode=2; result='FAIL'` on the `failed` chunks, a scratch copy of `:90`). Then:
    - EvidenceUnion fails `fallback` and `allSplits`, 8/10 pass.
    - RefusesIncompleteEvidence throws at the valid control `prior-failure-sweep-unresolved`, 0/39.
  - So a real rc history with ordinary failures can never drive a Partial sweep. Full also gets a loud unresolved header for every class of every failed chunk.
- **Why:** this breaks the plan's D-5 and D-6. A complete TRX that records failures is complete evidence. Incompleteness should mean that the accounting disagrees with the evidence. The colleague's fix wording was "nonzero exit with **no failing identity observed**".
- **Fix:**
  - Treat a nonzero exit or a `FAIL`/`TIMEOUT` result as accounting-incomplete only when the TRX and diagnostic observe no failing or in-progress identity, or when the TRX is otherwise incomplete. Keep the `detail`, short-TRX, missing-TRX and timeout checks.
  - Put the real `exitCode`/`result` values back in both fixture rows, at `:90` and `:110`.
  - Add a witness: an ordinary failing chunk (`exitCode=2`, `FAIL`, complete TRX with one `Failed` row) gives a Partial that accepts and selects the failed class, and a Full with no unresolved entry.
  - Keep the crash case (`-1073741819` / `FAIL` / `missing-terminal-accounting` / all-Passed TRX) refused. Mutation: restoring the unconditional exit/result rule must turn the new witness red.

## Advisories

- **A-1:** the resolver detects the platform itself with `DirectorySeparatorChar` (`:468`) instead of calling `Get-NightlyExecutionPlatform`. That skips the host seam, and macOS would map to linux. S4a should use one source.
- **A-2:** an absent `ExclusionContext` is accepted (derived from history). S4a/S5 must always pass it, or a receiving hop cannot detect tampering.
- **A-3:** short-TRX detection compares counts only, not identities. It is inert without a per-suite plan or chunk discovery, which most real chunks lack (singleton plan). A real crash is still caught through exit, result, `coverageComplete` or `detail`.
- **A-4:** a missing TRX with a bound plan is a whole-chunk fallback that Partial accepts (D-5). A crash with a bound plan and an all-Passed TRX is refused. The caller may want these two treated consistently.
- **A-5:** a prerequisite-failed e2e row has no `chunk`, so it is skipped (`:240`) and contributes nothing. This is inherited from earlier rounds.
