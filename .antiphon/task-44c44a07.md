## Questions from the brief

1. **Ordering window.**
   - The window is real. Claude writes one JSONL record per content block, so the sibling's TurnEnd can be stored and handled before the `tool_use` line arrives. If `OnTurnEndAsync` runs in that gap, there is no stored proof, and the nudge goes out (probe confirmed).
   - Nothing retracts an already-enqueued nudge. The card explicitly scopes that out to the stale-nudge follow-up.
   - The dispatcher report sweep calls `SelectAsync` again on every tick. Once the tool row is stored, the boundary is skipped, so there is no repeat nudge and no later wrong settle.
   - A settle in the window would need this task's closing token in a mid-work response. A settle followed by a late ToolCall needs the same, and that behaviour predates this change.
2. **Opposite hole (never settles).**
   - Grok `FromToolCall` writes ToolCall rows without an ApiCallId, and the selector filters `ApiCallId != null`. Codex writes no ToolCall rows. So the guard is Claude-only in practice.
   - For Claude, a genuine final shares its ApiCallId with a ToolCall only if that final message carried `tool_use`. The tool then runs and a new message id ends the turn (the CARD-0282 measurement: every one continued).
   - If a mis-stamped tool-bearing response really was last, the task stays open, where before it was nudged. Session-exit and dead-session reconciliation still apply. This is not a new stuck class.
3. **Span and barriers.**
   - Tools count only when their sequence is greater than the owning raw prompt and less than the next real prompt.
   - A newer real prompt whose end_turn is a phantom stays a barrier, via `SelectionBehindPhantomBarrier`. Its watermark arm cannot be reached, because PreReply already returns earlier. That is harmless dead code.
   - The compacted/resumed case is not covered: see A-1.
