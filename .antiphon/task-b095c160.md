## Behaviour changes

Product commit `8bb811e47ac32e3d18aa0f5156a341ee442b76a5` changes `server/Application/Services/AgentTaskDispatcher.cs` and `server/Application/Services/CapacityRecoveryService.cs`.

1. Claim lock order, when capacity is enabled and an unfinished wait is visible before the task lock: counted-task advisory `antiphon.capacity.counted-tasks` only for a specialist physical id, then the provider advisory for that wait's kind, then the standing-specialist agent `FOR UPDATE`, then the task `FOR UPDATE`. A wait that appears only after the task lock, or whose kind differs from the provider already locked, rolls the claim back as `NotClaimed`. The claim does not take a new provider lock while it holds the task row.

2. Queued reroute (`TryRewalkQueuedChainAsync`) owns its transaction. It refuses to join an ambient transaction. It locks the union of existing wait kinds and the task kind, sorted by `AgentKind`, then the task `FOR UPDATE`. A missing task or a task that is no longer `Queued` returns `RewalkOutcome.ClaimLost`. The tick `continue`s on `ClaimLost`, so it does not ensure a wait for a task that has already left the queue. An early kind/level match still returns `None` before the transaction. The runner-kind block still returns before the transaction. Under the lock, a kind/level that already matches rolls back and returns `None`.

3. `RedeemOnAsync` takes `consume` after the cancellation token. The default remains `true`, so existing callers still spend. `consume: false` on the accept path returns `Accepted` with the current `AdmissionCount` and leaves the grant, the wait state, and the database unchanged. Exhaustion, grant mismatch, a clock that is not due, a disabled feature, and a refusal reason still mutate and save on that early call. The claim's early redemption uses `consume: false`. A refused early redemption still commits with a plain `CommitAsync` so a defer or exhaustion is kept. It does not abandon that wait.

4. Spending happens only on a launch commit. Warm reuse calls `RedeemOnAsync` with `consume: true` before its save. The cold path adds the session, then calls the same consume after `RefuseParallelAsync` returns false and before `Status = Dispatched`. A late consume that is not `Ok` rolls the transaction back, clears the change tracker, and returns `NotClaimed`, which drops the added session. The preparation commit that returns `HeldForRemotePrep` stays a plain commit and keeps the grant.

5. Other non-launch claim commits go through `CommitClaimWithoutLaunchAsync`. That re-locks the provider, cancels the unfinished wait with reason `claim-not-launched`, clears the grant when `GrantedWaitId` matches, does not increment `AdmissionCount`, and then commits. Call sites are the workspace-conflict fail, optional-work expire, interim block, reuse-gate block, warm-reuse expiry, Grok and Claude credential-probe failures, repair-source fail, ambiguous worktree-base block, and progress-capture fail. A parallel hold still rolls back through `FinishParallelHoldAsync`. The stale-claim rollback is before consume and before abandon, so the grant remains. The sign-in lock from `d2d7acc82` is unchanged. `DispatchBaseWarningDeliveryE2ETests` is unchanged. Supervisor and queue redemption, and the post-claim receipt that sets `StartAccepted`, are unchanged. The parallel-tasks advisory stays after the task lock.
