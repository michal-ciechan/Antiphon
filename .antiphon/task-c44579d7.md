## Defects

**D-1: an `@$"` verbatim string can make the comment blanking remove a real marker. This is a regression.**
- Where: `scripts/test-rc-platform.ps1:557`, the literal/comment regex in `Get-C1323LinuxOnlyCensus`.
- Failure: the input below is valid C#. It has a marker and no policy row. At the tip the census returns `Ok=True` with no problems. At base 4282088c9 the same input gives `marker-without-row:antiphon|ZTests|M`.
  ```
  public sealed class ZTests
  {
      static string P(string r) => @$"{r}\" + "**/*.cs";
      [NativeLinuxOnly("x")]
      public void M() { }
      const string H = "a/**/b";
  }
  ```
- Why: the verbatim branch only recognises `@"` (and `$@"`, because its `@"` starts one character later). With `@$"` the match begins at the `"` and uses the regular-string branch. That branch treats `\"` as an escape and closes at the next quote. The glob's `/*` is then read as code and starts a block comment, which runs to the `*/` inside `a/**/b`. The whole marker line is blanked. Windows-path verbatim strings ending in `\` and glob strings are both common in tests.
- Fix:
  - Make the verbatim branch `(?:@\$*|\$+@)"(?:[^"]|"")*"`.
  - Add a C1686 fixture case for `@$"...\"` followed by `/*` and `*/` text.
  - For extra safety, fail closed when a blanked block comment spans a line that matches the canonical marker form in the raw text.

**D-2: a marker split across lines, or reached through a `using` alias, still passes silently. The fix leaves this open.**
- Where: `scripts/test-rc-platform.ps1:565`. The noncanonical scan only matches `NativeLinuxOnly(Attribute)?\s*\(` within a single line.
- Failure: each of these is valid C# with no policy row. Each gives `Ok=True` at the tip, and at the base too.
  - `[NativeLinuxOnly` followed by `    ("x")]` on the next line.
  - `[NativeLinuxOnly // why` followed by `("x")]` on the next line.
  - `using Lin = Antiphon.TestSupport.NativeLinuxOnlyAttribute;` followed by `[Lin("x")]`.
- Why: the docs clause (`docs/release-gates.md:288`) now says that any other non-comment use fails closed. These spellings are the same round-1 D-1 class: a marker without a row that the source census accepts.
- Fix: flag every non-comment `\bNativeLinuxOnly(Attribute)?\b` token outside the canonical form, whether or not a `(` follows. That covers an alias, a line-end name and `typeof`. Exempt the defining file and the witness files in `tests/Shared/` by exact path, not by text shape. Add fixture cases for these spellings.
- Mitigation:
  - None of these spellings exist in the real tree today. In the 76 marker files there are 0 `@$"`, 0 line-end marker names and 0 aliases.
  - The compiled `NativeLinuxPolicyWitnessTests` `reverse-coverage` diagnostic still catches a marked test without a row in the four compiled suites.
  - So both defects are latent today. The source census still does not fail closed as it claims.
