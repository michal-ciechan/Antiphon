## Defect (found)

**DEF-1. A password containing `'`, `"`, whitespace, `<` or `>` prints unmasked.**

- **Where:**
  - `scripts/postgres-cutover-monitor.ps1:174`: the `Hide-CutoverText` userinfo class `[^\s"''<>]*@`.
  - `:136`: `Test-CutoverSecretValue`, which uses the same class.
- **Failure:** .NET reads all of these characters as userinfo.
  - `[uri]'http://u:SENTI''q@h/api/x'` gives host `h` and userinfo `u:SENTI'q`.
  - The apostrophe stays unescaped even in `AbsoluteUri`.
  - `"`, space, `<` and `>` are escaped to `%22`, `%20`, `%3C` and `%3E`.
  - The mask stops at the character and finds no `@`, so it masks nothing.
- **Real output:** I ran the monitor in-process with `-ServerBaseUrl "http://u:SENTAPOS'q@fake.invalid"`, a seam that throws `AbsoluteUri`, and sentinels only.
  - PLAN lines: `PLAN would GET http://u:SENTAPOS'q@fake.invalid/api/agent-tasks/pipeline?projectId=p1 x20 ...`.
  - Result JSON: `"server": "http://u:SENTAPOS'q@fake.invalid"` and `"url": ...`.
  - Result JSON `errorText`: `status=0 request failed for http://u:SENTAPOS'q@fake.invalid/...`.
  - The `"`, space and `<` variants leak the same way in PLAN lines and in the JSON `server`/`url` fields. In the JSON, `"` is written as `\"` and the class stops there too.
  - `Test-CutoverSecretValue` returns False for all of them, so a diagnostics string value of that shape would also be kept.
- **Why it matters:** this is the brief's strict class, a masking miss that prints a credential.
  - It is not a regression: the base class `[^/?#\s"'<>]*@` excluded the same characters.
  - A1 widened the rule for `/`, `?` and `#` but kept these exclusions.
- **Fix (Code owner 173228b3):**
  - Mask userinfo from the parsed URI rather than with a character class alone. For every `scheme://` token, and for each URL parameter before it is used in any line, use `[uri]::TryCreate`. When `UserInfo` is non-empty, replace both the raw and the escaped userinfo with `<redacted>`.
  - At minimum, admit `'` into the class, because `AbsoluteUri` leaves it unescaped.
  - Add a `C1423_*` case per character (`'`, `"`, space, `<`, `>`) over the same surfaces as `Invoke-C1423MaskingForms`.
