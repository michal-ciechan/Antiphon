## Verification of the brief's questions

1. **Safe direction (normaliser).** `NamesBranch` trims the value, cuts at the first `^`, `~`, `:` or `@{`, and then compares
   case-insensitively, either bare or after one prefix (`refs/heads/`, `heads/`, `refs/remotes/origin/`, `remotes/origin/`,
   `origin/`). No real dependent escapes it. I checked these spellings with git 2.x in a scratch repo:
   - Do not resolve to the branch: `refs/heads//b`, `heads//b`, `b//`, `/b`, `b/`, `./b`, `refs/heads/./b`, `b@`, `b..`,
     `refs/heads/b.`.
   - Resolve, and are cut correctly: `b@{0}`, `b@{u}`, `b^{commit}`, `b^0`, `b~0`.
   - Create already refuses leading or trailing whitespace and control characters. Unicode lookalikes are different refs.
     OrdinalIgnoreCase covers NTFS case folding and more.
   - Over-matching (another branch that differs only in case or prefix) only keeps a tree.
2. **Backoff.** `repeats` is capped at 30 before `Math.Pow`, and the result is `Math.Min`'d with 24 h, so the exponent cannot
   overflow. A reset needs a DB fact change (it is fingerprint-voided) and still costs one pre-check under the per-tick
   cap. A tick runs `ActAsync` once per candidate, so `prechecks++` counts a refused filing once. A refused filing writes
   only the check cursor, never the retry cursor, so it can never reach `retry_exhausted`. `NotBefore` is at most 24 h
   ahead, after which the tree is in `due` again. Due trees still sort after never-checked ones (T-D-7, pre-existing).
3. **Settled record.** The key is `CheckCursorKey(task.Id)`, and the fingerprint covers status, attempt, CompletedAt, path
   and branch. A different task has its own key. A settled state only holds a tree, and any fact change voids it.

## Advisories (no Review rerun needed)

- **A-1 (pre-existing, outside the diff).** `WorktreeBaseResolver.Resolve` uses `MergeTargetRef` as the creation base when a
  queued task has no start ref and no base task. `Classify`'s dependents check never consults `MergeTargetRef`, so a
  queued task dispatched with `-MergeTarget <candidate branch>` is not a dependent. If such dispatches occur, it is worth
  a card.
- **A-2.** The candidate's own `BranchName` now strips only `refs/heads/`; it used to strip the origin prefixes as well.
  The difference matters only for a task whose `WorktreeBranch` is literally `origin/<b>` (a local branch with that name).
  For such a task a dependent spelled `<b>` no longer holds the tree. That is correct, because git resolves `<b>` to
  `refs/heads/<b>` and never to `refs/heads/origin/<b>`. A dependent spelled `origin/<b>` or `refs/heads/origin/<b>` still
  matches. No test pins this.
