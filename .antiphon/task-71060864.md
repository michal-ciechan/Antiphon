## Fix

`BuildConfinement.Settle` and `Complete-CheckpointBaseline` split status paths on the baseline index. A path in HEAD is still `git restore --source=<HEAD> --staged --worktree`. A path absent from HEAD is `git restore --staged` only, so the worktree bytes stay. A successful undo, including an index-only addition, is still `refused: tampered`, exit 2, and the receipt stays invalid. The lossless sentence is emitted only on that success path, which does not pass `--worktree` for a path absent from HEAD. The manual command uses `--staged` alone for those paths.

`SafeDelete.RunGit` retries a transient spawn (Unix 4, 11, 12, 26, and 2 or 13 only when the executable exists; Windows 8 or 1450) up to six attempts when the executable exists, then still returns `git-unavailable`. A child that was created and then does not finish, including a wait or kill exception after that start, returns `git-timeout`. A missing executable is `git-unavailable` on the first failure.
