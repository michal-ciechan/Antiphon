## Change

`src/Antiphon.SessionRunner/BuildSlotBroker.cs`:
- `SweepLocked` handles a lease past its TTL as follows. It is reaped as before (`ttl 90m expired`) unless `SameHolderStillRunning(lease)` holds. Otherwise it is kept, and the first time that happens the broker logs `kept past its ttl` once (`Lease.KeptPastTtl`).
- `SameHolderStillRunning` applies only when `HolderLiveness == "pid"`. It requires `IProcessLivenessProbe.TryGetStartTimeUtc(pid)` to be non-null and within `SameHolderStartTolerance` (1 s) of `Lease.ProcessStartUtc`.
- Before the TTL, nothing changes: `HolderAlive` still uses `IsAlive`, which allows 2 minutes of PID-reuse tolerance.
- The broker already recorded the holder pid and its start time at grant: the request's `processStartUtc`, or the OS start time when the request has none. No new data and no new seam were needed. The existing `IProcessLivenessProbe` and `TimeProvider` injection were enough.

`docs/testing-and-build.md` "Build slots": one paragraph says a pid-liveness lease is kept past the TTL. It also says the lease has no absolute bound, that renew mode is unchanged, and that the change reaches the desktop only when its runner restarts.

### No absolute bound: reasoning

- A qualification run lasts 17-30 h. Any fixed cap would reopen the same hole partway through the run.
- A crash cannot hold a slot forever. Once the pid has exited, `TryGetStartTimeUtc` returns null, and the next sweep reaps the lease (every 30 s and on every acquire). If the pid is reused, the start time differs by more than 1 s, so the lease is reaped. If the start time cannot be read (for example, access denied), the lease is reaped too. So a lease is kept only while the original holder process provably exists.
- Nothing is killed, and the wrapper still releases its lease on exit.

## Callers of the reap path (for Full Review)

- `TryAcquire` (POST /build-slots) sweeps before admission. A live same-start holder past the TTL now stays in `_leases`, so `free = MaxConcurrent - _leases.Count` stays lower and a second driver gets 409 busy. That is the intended change. A re-ask by the same holder still returns its own lease, now with a past `expiresAtUtc`. No client reads `expiresAtUtc`: neither `scripts/lib/build-slot.ps1` nor `tools/Antiphon.Checkpoints` does, and only the `c589` shim fixture echoes it.
- `Renew` (POST /build-slots/{id}/renew) sweeps first. In renew mode `SameHolderStillRunning` is false, so the TTL still reaps the lease and a later renew answers 404 as before (V-4).
- `Sweep()` is driven by `BuildSlotSweepService` on its timer (`BuildSlotRoutes.cs:92`). It now keeps a live same-start pid holder.
- `List()` (GET /build-slots) is unchanged code. The kept lease is listed with `holderAlive: true`, counted in `occupied`, and shows its original `expiresAtUtc` (V-5).
- Metrics: a kept lease records no reap. Its held duration is counted at its eventual release or reap.

## Clients' start-time precision

- `scripts/lib/build-slot.ps1:78` sends `(Get-Process).StartTime.ToUniversalTime().ToString('o')`.
- The checkpoint tool's `LeaseHolder` sends `child.StartTime` formatted `"O"`.
- Both come from the same OS source as the broker's `Process.StartTime`, at full precision, so a live holder matches well within 1 s.
- `scripts/qualification/launch-rc.ps1` leases through `build-slot.ps1`.
- A client that sends a coarse or wrong start falls back to today's TTL reap.
