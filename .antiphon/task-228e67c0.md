## Defects

### D-1: a Failed row with an absent, unknown or wrong-case `Setup` becomes INCONCLUSIVE instead of red or invalid

- **Where:** `scripts/lib/live-lane-outcome.ps1:153-155` (any `Setup -cne 'Ready'` goes through `Get-LiveLaneSetupOutcome`) and `:64` (`default` gives 20 `unclassified-skip`).
- **Failure:** I called `Get-LiveLaneOutcome` directly on a valid one-UID terminal with `State='Failed'` and no outage proof:
  - Setup `Ready`: exit 1 RED (correct).
  - Setup absent, `''`, `LegacySkip` or `ready`: exit **20 INCONCLUSIVE `unclassified-skip`**.
  - Setup `AuthMissing`/`QuotaExceeded`/`ReadyTimeout`/`DependencyUnavailable`/`StartupDefaultAbsent` on a row that ran and failed: 20, with no correlated proof.
- **Why:** this breaks the test design's exit table and precedence. Those say "assertion without qualifying outage proof -> 1" and "malformed ... facts -> 2, never 20". The unknown-enum mapping is specified only for skips (`unknown-skip` uses `State='Skipped'`). If a future terminal reader (S1c) omits or mis-cases `Setup`, every genuine assertion failure in the lane reads INCONCLUSIVE, which is the central danger: a code failure turned into INCONCLUSIVE. No test covers it. `unknown-skip` and `setup-contract` both use Skipped rows.
- **Fix:** treat an unrecognised or absent `Setup` as `row-invalid` (2) whatever the state. Let a Failed (executed) row take a setup-table 20 only with correlated outage proof; otherwise keep 1, or 2 as contradictory. Add `TypedSetupOutcomes` cases: Failed + {absent, '', LegacySkip, 'ready'} -> 2, and Failed + AuthMissing without proof -> 1.

### D-2: one post-failure probe, issued for the first failed row, relabels every failed row as a provider outage

- **Where:** `scripts/lib/live-lane-run.ps1:179-186` probes only `$failed[0]`. `scripts/lib/live-lane-outcome.ps1:148` then applies `Test-LiveLaneProbeOutage $row $PostProbe` to every row whose account, endpoint and dependency match, and in one lane they all share one profile.
- **Failure:** two Failed rows (A, B), both `Setup='Ready'`, no transcript proof, and one bounded `Unavailable/ServiceUnavailable` probe give exit **20 provider-outage, A=20/Probe, B=20/Probe**. In practice: a deterministic code red in row B at minute 1 plus a provider blip when the run ends gives an INCONCLUSIVE lane.
- **Why:** the test design says "For the affected failed row alone, qualified outage overrides that row's assertion to 20" and V-7 says "never relabel the unrelated row". The probe also has no time link to B's failure. `mixed-red` only checks transcript proof on B, so this path has no test.
- **Fix:** bind the probe result to the UID it was issued for (carry `Uid` in the probe observation and require a match in `Test-LiveLaneProbeOutage`). Other failed rows stay 1, so independent red wins. Add a `HealthyProviderAssertionStaysRed`/`probe-second-row` case: two failed rows plus a probe-proven outage -> 1, exactly one row at 20.

### D-3: the raw-child-exit guard against a false GREEN has no test (mutant survives)

- **Where:** `scripts/lib/live-lane-outcome.ps1:185` (`$RawChildExit -ne 0 -or $rawOutcome -cne 'Passed'` gives 2 `checkpoint-inconsistent`).
- **Failure:** mutant M7 deletes `$RawChildExit -ne 0 -or`. All 6 `LiveLaneOutcomeTests` methods and 9/9 `ProviderOutcomeIsDistinct` script cases stay green. With the mutant, a checkpoint child that exits 1/2/3/8 while its terminal record says Passed classifies **0 GREEN**.
- **Why:** this line is the only thing stopping a nonzero checkpoint exit becoming green. The `raw-child` case always sets `Build='Failed'` and `Outcome='Failed'`, so the earlier `terminal-invalid` branch decides it and line 185 never runs. That leaves the case unable to go red for this guard, which is a red->green adequacy gap.
- **Fix:** add a `raw-child` variant with a fully consistent passing terminal (Build Succeeded, Outcome Passed, exact passed roster) and raw exit in {1,2,3,8}, expecting 2 `checkpoint-inconsistent`.

- Skip, zero and roster cannot be green: zero, missing, duplicate, unexpected or wrong UID gives 2. Any skip gives 20. Exact count and set equality are enforced.

- Partial or missing receipt: staging then same-directory rename. If the writer throws or the file is missing, `diagnostic.json` is absent and the exit is 20. Exits 1 and 2 are never downgraded by the catch.

- Child environment: `ProcessStartInfo.Environment.Clear()`, then a 7-key allowlist plus 3 selected keys. HOME, provider keys and task tokens are dropped. `Set-AntiphonBuildDriverEnvironment` does nothing on Linux.
- Deadline: stop then join only the owned adapter handles. No name- or pattern-based kill. If the join fails, the lock is kept (no clean release).
- Paid manifest: `schemaVersion: -1545` is refused by the real `ManifestLoader` (checked in C#). No executable row exists.
