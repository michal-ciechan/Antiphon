## Deviations from the plan, stated

1. **Create form.** The pin create is the positional expected-old-zero `update-ref <ref> <sha> <zeros>` (git's
   create-if-absent, already the final step at base), not `update-ref --stdin create`. Same refusal, one process; it keeps
   the `RunAsync` seams (fixture trace, `BeforeCommand` fault hooks that key on a 4-argument `update-ref`
   — `AgentTaskLandBoundaryTests:89`, `AgentTaskLandRemoteSourceRetentionDTests:163` — journal child tag, profile) that
   the stdin runner bypasses.
2. **Reason order kept exactly.** A failed commit check defers its verdict past the read-back, so the base precedence
   (`invalid_recovery_ref` → same-id success / `recovery_ref_collision` → `recovery_ref_query_error` →
   `invalid_recovery_commit` → git's refusal) is unchanged even for double faults.
3. **Branch test name.** The plan names `C1432_missing_branch_reports_source_changed`; at base a deleted branch refuses
   `source_ref_missing` (via `ReadBranchAsync`), not `source_changed`. The brief binds every reason, so the test is
   `C1432_moved_or_missing_branch_keeps_its_reason("moved","source_changed")` / `("missing","source_ref_missing")`:
   the batched path re-reads a branch absent from the batch alone, on that refusal path only.
4. **CP-13 split.** Six `LandingProtocolGuardTests.C475_Task_*` methods are red at base (proof below), so CP-13 ran as
   CP-13a (the other 11 guard methods) + CP-13b (the three other classes) from a hand-split copy of the imported
   manifest (`.antiphon/c1462-s4/s4-manifest.yaml`, ignored), both on CP-12's build (same After group).
