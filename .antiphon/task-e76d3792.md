## Advisories

- **A-1: duplicate ids diverge from the base.**
  - Where: `AgentTaskCostWalk.cs:94`, where `visited` is seeded with `origin.Id`.
  - Base walk: from a second row A2 whose chain passes back through id A, it continues via the first row's parent.
  - New walk: it stops at A.
  - Minimal case: X has cost 100, A1(parent X) 1, A2(parent C) 2, C(parent A) 4. X is 105 new versus 107 base. Fuzz: 1,685 mismatches in 29,503 cases.
  - Unreachable today, because every family is a primary-key-unique DB read.
  - Cheap fix while doing D-1: do not pre-seed `origin.Id`. Stop on a repeat, and skip the cost add only when `parentId == origin.Id`.
- **A-2: worst case is O(n·depth), not O(n).** A 10k-deep chain took 14.8 s. `HashSet.Clear()` is O(capacity) on every origin, so one deep chain also slows every later short walk. MaxDepth bounds this for real data. If hand-edited data matters, use a generation-stamped visited map, or memoised and condensed accumulation.
- **A-3: the cycle test lacks `[Timeout]`.** `AgentTaskSubtreeRollupTests.cs:17`: a guard-free mutant (M3b) hangs the lane instead of going red. Add a timeout of about 2x the measured p95.
- **A-4: wall-clock assertion.** `AgentTaskSubtreeRollupTests.cs:149` asserts `ShouldBeLessThan(100 ms)` with a Stopwatch, and the bound is not derived from p95. Measured work is about 7 ms (14 ms cold), but a GC or JIT stall on loaded server2 could flake it. The chain test's closed form already pins correctness. Prefer a generous bound, or an operation-count witness.
