## Defects

### D-1 (Medium): a same-named helper launders TextWriter.Write and StringBuilder.Append in the real C680 gate

**Where.** `tests/Shared/LiveClaude/LiveClaudeSinkAudit.cs:175-177`, in `IsCallee`, the lower-case receiver arm. The callee table `Callees` is global: it takes every method name declared anywhere in the walked roots. The C680 walk (`LiveLaneEvidenceTests.RawSinks`) walks the whole of `ClaudeDialogCanaryDiagnostics.cs`. That file declares the helpers `Write(string name, string value)`, `Append(object row)`, `Observe(...)` and `Draft(...)`.

**Failure.** Any `x.Write(...)` or `x.Append(...)` call on a lower-case receiver is treated as a walked helper, so it never reaches `Escapes`. I inserted each line below before `LiveClaudeEvidence.Success("c680-native"` in `ClaudeDialogWatchdogCanaryTests.cs`, then walked it with the `RawSinks` roots, using the built audit at ad9bf0c14 through reflection:

| Insert | Result |
|---|---|
| `var output = TestContext.Current!.OutputWriter; output.Write("{0}", snapshot.RenderedScreen);` | every count 0 |
| `using var t = File.CreateText("a.txt"); t.Write("{0}", snapshot.RenderedScreen);` | every count 0 |
| `s_log.Append(snapshot.RenderedScreen);` (static StringBuilder field) | every count 0 |
| Control: the same lines with `WriteLine` or `AppendLine` | Escape = 1 |

The one-argument `output.Write(snapshot.RenderedScreen)` does count, but only by accident. The taint flows into the diagnostics helper's first parameter, `name`, and spreads from there (Escape = 41).

**Why it matters.**
- These are ordinary, honest-looking calls.
- Raw screen text reaches TRX output or a file while the V-7 gate (`RawSinks != 0`) stays green.
- The worker called this residual a theoretical name collision. With `Write` and `Append` in the walk, it is the most common sink verb.
- The residual is not documented in `docs/testing-and-build.md`. The new section there covers only the census.
- None of the 23 D3 witness shapes is applied to the C680 walk.

**Fix.**
- Accept `receiver.Name(...)` as a walked helper only when the receiver is bound to a walked type. That means a local, field or parameter whose declared type or `new` initializer is a type declared in the walked roots, such as `ClaudeDialogCanaryDiagnostics debug`. A name match alone is not enough. Also check arity against the callee's parameter count.
- Make `ReturnsTainted` handle the same receiver form, so that a helper's return value carries taint.
- Add these C680 cycles to `ProveDiagnosticMutants`: `output.Write("{0}", …)` on an OutputWriter alias, `t.Write("{0}", …)` on a `File.CreateText` writer, and `s_log.Append(…)`.
- Document the sink-audit residuals in `docs/testing-and-build.md`.

### D-2 (Medium): lambda parameters over tainted text are never tainted

**Where.** `TaintPass` (`LiveClaudeSinkAudit.cs:345-401`) and `ArgumentCarries` (`:211-221`). A lambda argument counts only when it returns tainted text. Its parameters never receive taint from a tainted receiver or a tainted sibling argument.

**Failure.** I appended each line to `ClaudeSubmitContractLiveTests.Submitting_via_two_writes_completes_a_turn` and walked it with `WithHelpers`, the same way as `CanarySinksCannotBypassSanitizer`:

| Insert | Result |
|---|---|
| `runner.SnapshotScreen().Split('\n').ToList().ForEach(l => throw new InvalidOperationException(l));` | every count 0 |
| `var lines = runner.SnapshotScreen().Split('\n').ToList(); lines.ForEach(l => OtherFile.Log(l));` | every count 0 |
| `runner.SnapshotScreen().Split('\n').Select(l => { OtherFile.Log(l); return 0; }).Sum();` | every count 0 |
| Control: the `foreach (var l in lines) OtherFile.Log(l);` form | Escape = 1 |
| Control: `Array.ForEach(lines, l => …)` | Escape = 1 (the outer call counts) |

**Why it matters.** The first insert puts screen lines into a TRX failure message. Item 3's invariant is that "any tainted value reaching any invocation/creation/throw" counts.

**Fix.**
- In `TaintPass`, taint every parameter of a lambda argument when the call's receiver, or any other argument, carries taint.
- Add these as `raw-any` inserts: `.ForEach(l => throw …)` and `.Select(l => { OtherFile.Log(l); … })`.

### D-3 (Low): a store through a local alias of a non-local object stays "local"

**Where.** `StaysLocal` and `Locals` (`LiveClaudeSinkAudit.cs:280-304`). Any element or member store whose root identifier is a local, a parameter or a catch variable counts as local. That holds even when the identifier aliases a shared object.

**Failure.** Both of these count 0 in the same Pty walk:
- `var bag = TestContext.Current!.ObjectBag; bag["s"] = runner.SnapshotScreen();`. The direct `TestContext.Current!.ObjectBag["s"] = …` form counts 1.
- `catch (Exception ex) { ex.Data["s"] = runner.SnapshotScreen(); throw; }`. The card's item 3 listed `ex.Data` as a survivor, but the witness covers only the `throw ex;` form.

Parameter aliases behave the same way: a helper `void H(Dictionary<string,string> d, string s) { d["k"] = s; }` called with a static dictionary is not counted.

**Fix.**
- Treat a store through an identifier as local only when that identifier is an in-place-created buffer or object (`Buffers`, or a `new` initializer). Count everything else as Escape.
- Add witnesses for the alias store and the `ex.Data` rethrow.
