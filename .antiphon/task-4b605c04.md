## Advisories (no Review rerun needed)

- A-1 The check and the stamp are not atomic (WorkspaceSlotReleaseService.cs:168-206). The service reads a plain tracked entity, and `SaveChanges` updates only `RemoteWorkspaceSlotReleasedAt` and `RemoteWorktreePath` by Id. `AgentTask.ConcurrencyToken` is not an EF concurrency token. A Queued-to-Dispatched claim, or a retry followed by a re-prep, that lands inside the millisecond window would still be stamped. The worst outcome is that the server forgets a live runner lease: the lease leaks, and nothing is deleted because nothing is sent to the runner. This is not practically reachable. It needs an operator action and a millisecond window, and the drain hold or the terminal state blocks a dispatch. A cheap hardening is to use `SELECT ... FOR UPDATE` in a transaction, as `RemoteWorkspaceReadiness.RecordPathAsync` does (RemoteWorkspaceReadiness.cs:26-30), or a conditional `ExecuteUpdate` on Status/Attempt/ReleasedAt IS NULL.
- A-2 The requester is an unauthenticated label, but the audit text `recorded released by the operator 'x'` reads like an identity. Consider `by the operator token holder (requester label 'x')`, or say in docs/ops-http.md that the requester is unverified.
- A-3 "Printable" is implemented as `!char.IsControl`, which rejects only Cc. Format characters (Cf: U+202E, zero-width) and the line and paragraph separators (U+2028/U+2029) pass. This is not CR/LF injection, but it is wider than the documented rule. The witness has no control-character case, so removing the `IsControl` check stays green. Separately, the pre-existing `reason` is only trimmed, so it still lets newlines into both the audit event and the log line.
- A-4 The token check is Ordinal. An uppercased token passes and is recorded, and the stored token is lowercase hex. Use OrdinalIgnoreCase.
- A-5 After a retry that carries the slot fields, the old attempt's stuck lease cannot be recorded until the new attempt's own three slot_unknown tries, which happen only on drain (Queued) or after it is terminal. This refusal is correct, because the lease may belong to the new attempt. Operators should know the new attempt then holds the old slot on the server.
