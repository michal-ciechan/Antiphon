## R2-D1 (defect, S9; not blocking S1)

- **Where:** attempt claims are "keyed by graph digest + node ID + attempt" (l.335). Same-run retention checks "exact graph/output identity and no red attempt" (l.304, l.337). The verdict "comes from it [the frozen graph] and verified execution events" (l.255). Yet l.310 explicitly allows "Moving a target after admission requires a new binding/validation attempt". The target `bindingDigest` is inside the graph, so a rebind gives a new graph digest **within the same runId**.
- **Failure:**
  1. Run R uses graph G1. Chunk X attempt 1 is a bound red.
  2. The operator moves the windows-rc target to a new binding, which creates G2 with a new digest under the same runId.
  3. The claims for G2+X start again at attempt 1, and X passes.
  4. A reducer scoped to "the frozen graph's events", which is the natural reading of l.255, reports X green and the run green.

  V-9 and V-16 exercise red-then-green only within one graph, so CP-9 and CP-16 both stay green. The l.259 phrase "red for the entire run" is prose that no witness reaches across graph digests.
- **Fix:**
  - Key the attempt ledger and the sticky-red reduction by runId plus catalog node identity (node ID plus selection `uidSetDigest`), never by graph digest.
  - A new binding or validation attempt within a run inherits every prior attempt and red.
  - The attempt counter is per run and node.
  - Add a V-9 and V-16 arm: red under G1, rebind, green under G2 with the same runId gives red. The mutant "reduce by graph digest" must turn that arm red.
  - S1 supports this by proving that node IDs do not depend on the target or binding (see the scope below).
