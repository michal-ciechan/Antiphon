### D-2 (blocker): a prefix followed by a single-slash or mixed-slash URL still puts the credential into the request

- **Where:** providerEndpointModel.ts:66-73 (`baseUrlCarriesUserInfo`). The new `//` check looks only for a literal `//`. `rawAuthorityCarriesCredential` cuts the text at its first `/`.
- **Failure:** each value below returns the endpoint, so the PUT or PATCH body carries `u:<password>`:
  - `endpoint: https:/u:pw@h/v1`
  - `x:https:/u:pw@h/v1`
  - `BASE_URL=https:/u:pw@h/v1`
  - `endpoint: https:/\u:pw@h/v1`
  - `endpoint: https:\/u:pw@h/v1`
  - `BASE_URL=https:/\u:pw@h/v1`
  - `endpoint: https:/\u:pw@h`

  Without a prefix the same URLs are refused, because `new URL` reads them as userinfo: `new URL('https:/u:pw@h/v1')` gives `href=https://u:pw@h/v1` with `username=u` and `password=pw`, and likewise for `/\` and `\/`. Proved in vitest: these seven strings added as refusal rows give 7 failed / 53 passed (60) at 1262bc7c1.
- **Why:** this is D-1's class, text before the real scheme hiding the authority, and the brief named this exact form (mixed slashes after a scheme). It was present at 47b55834a and at base 72fada665, so it is not a regression of this diff. The fix for D-1 is still incomplete, and round 1's rule is that any bypass leaking userinfo into a request is a blocker. The server still refuses every one of these values (whitespace or non-http(s) scheme rule, and it never echoes the value). So this is a leak into the request, not a stored secret.
- **Fix (probed):** treat a special scheme anywhere in the value, followed by any run of `/` or `\`, as the start of an authority:

  ```ts
  if (embeddedSpecialAuthorityCarriesCredential(baseUrl)) return true   // after rawAuthorityCarriesCredential

  function embeddedSpecialAuthorityCarriesCredential(value: string): boolean {
    for (const match of value.matchAll(/(?:https?|wss?|ftp|file):[/\\]+/gi)) {
      if (userinfoIsCredential(segmentBeforeDelimiter(value, match.index + match[0].length, true))) return true
    }
    return false
  }
  ```

  With this change, typecheck and lint pass and vitest is 60/60 (the 53 existing rows plus the seven above). The probe shows 0 leaks and 0 regressions over all 57 strings. Add the seven strings as refusal rows, and commit the red before the fix.
