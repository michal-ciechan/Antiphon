## Finding and repair

StartRef: `3fb3c113e8b2554ccd5789e00375dbfd69697981` (`rc/2026-10-27`). The native
`LaunchAsync` cleanup was unchanged from candidate `cde8def41`: handles were collected only
after every assertion, exit waits were after the inner finally, and recursive directory
deletion was unconditional. A body/disposal failure could bypass the explicit waits, while
the delete failure masked the original exception. The newer shared capture helper did not
remove this control-flow defect.

Windows refuses to delete the mapped/running `Antiphon.PtyHost.exe` in this test's own
shadow directory. The supplied stack establishes that cleanup failed, but cannot identify
the earlier exception or establish a product host lifecycle regression. The repair preserves
those earlier failures so the native rerun can identify any remaining cause.

`OwnedProcessDirectoryCleanup` now captures and pins handles for already-attributed owned
processes before stop, checks that the original pinned process remains alive after opening
each handle (preventing PID reuse without comparing wall clocks), and uses cancellable native
exit waits in cleanup even when the body or stop fails. The wait budget is ten seconds shared
across the captured processes, retaining the prior ten-second ceiling without multiplying it
by process count. A survivor diagnostic includes PID, process name, elapsed time and budget.
Unknown capture, failed stop/ownership cleanup or unresolved exit retains the directory.
The existing TestOwnedPtyHost remains the only control authority; the new helper only waits.
Original body, capture, stop and wait errors are preserved through its existing ScopeAsync.

All modern proof remains: owned root/session/generation attribution; ModernConPty and exact
requested backend in the host log; observed OpenConsole/conpty.dll pair and shipped hashes;
the DLL actually loaded in the owned host; runner/host build SHA and file hashes; local and
phone-home capabilities, with no fallback or deprecation.
