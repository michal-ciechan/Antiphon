### 1b. Is the definition legitimate?

- **Test-only and never shipped.** Only `tests/Antiphon.Tests/Antiphon.Tests.csproj` references it, with `ReferenceOutputAssembly=false` and `Private=false`. It is not in `Antiphon.sln`. The product `Dockerfile` copies only `src/`, `server/` and `scripts/lib/*.cs` and publishes `server/`.
- **Does nothing at build time except compile and copy.** It is a plain Exe: no targets, no Imports, no package references. Its only build-time work is compile, apphost creation and the existing `CopyStagedHelpers` copy (`Glob="*"`).
- **No allow-list widening.** `UseAppHost` is already allow-listed (`scripts/audit-land-verification-precheck.ps1:168`). It is not `_PtyHostNativeProps`.
- **`TreatAsLocalProperty="UseAppHost"` is required and correct.** Checkpoint and Linux builds pass `UseAppHost=false` globally. The `CopyStagedHelpers` MSBuild calls create fresh project instances that inherit that global. Only the root attribute forces `true` in every instance, restore included, so CARD-0847's restore-without-apphost-pack failure cannot occur. A ProjectReference `AdditionalProperties` would not reach the `GetTargetPath`/shared `Build` calls.
- **A runtime alternative does not work.** I put a pwsh-staged producer in a scratch copy of the script: this pwsh's absolute path as `FileName`, plus `-NoProfile -File <temp shim.ps1>`. It **fails**. `RunBytes`' git hardening places `-c maintenance.auto=false ...` in front of the injected arguments, so pwsh parses `-c` as `-Command`. The stderr was `'maintenance.auto=false' is not recognized`.
- **No other substitute either.** A PATH git cannot emit invalid UTF-8. On Windows, a `.cmd`/shebang shim is not what `UseShellExecute=false` selects, because .NET resolves only `.exe`. Compiling at test runtime would add per-test compile cost. A native PE is therefore the minimal Windows-correct producer. **Keep the definition change; do not re-do the repair.**
